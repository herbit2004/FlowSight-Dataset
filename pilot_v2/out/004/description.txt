## 图类型与用途
这是一个流程图，描述了可观测性 (Observability) 的概念及其与系统组件之间的关系。它在仓库中的作用是说明如何通过日志 (Logs)、指标 (Metrics) 和追踪 (Traces) 来实现对系统的可观测性。

## 图的整体布局
图整体采用从上到下的布局。顶部是系统组件和可观测性，中间是日志、指标和追踪，底部是它们提供的具体信息。

## 分组/子图/阶段说明
图中包含一个名为 "System" 的子图，该子图代表整个系统，包含三个组件：Application/Service 1, Application/Service 2, Infrastructure。

## 节点逐项说明
- **Observability (O)**：表示可观测性，即从外部了解系统内部状态的能力。
- **Logs (L)**：表示日志，记录系统运行时的事件和信息。
- **Metrics (M)**：表示指标，量化系统性能和健康状况的数据，例如 CPU 使用率、内存占用等。
- **Traces (T)**：表示追踪，记录请求在系统中的完整路径和耗时，用于分析性能瓶颈。
- **Detailed Event Context (LD)**：表示详细事件上下文，由日志提供的信息。
- **Aggregated System Health & Trends (MA)**：表示聚合系统健康和趋势，由指标提供的信息。
- **Request Flow & Bottleneck Analysis (TP)**：表示请求流和瓶颈分析，由追踪提供的信息。
- **System**：表示整个系统，是一个子图。
- **Application/Service 1 (App1)**：表示应用程序/服务 1，是系统中的一个组件。
- **Application/Service 2 (App2)**：表示应用程序/服务 2，是系统中的另一个组件。
- **Infrastructure (App3)**：表示基础设施，例如服务器、网络等。

## 连线、分支与汇聚关系
- `Observability (O) -> Logs (L)`：可观测性依赖于收集日志数据。
- `Observability (O) -> Metrics (M)`：可观测性依赖于收集指标数据。
- `Observability (O) -> Traces (T)`：可观测性依赖于收集追踪数据。
- `Logs (L) --Provides--> Detailed Event Context (LD)`：日志提供详细的事件上下文信息。
- `Metrics (M) --Provides--> Aggregated System Health & Trends (MA)`：指标提供聚合的系统健康状况和趋势信息。
- `Traces (T) --Provides--> Request Flow & Bottleneck Analysis (TP)`：追踪提供请求流的路径和瓶颈分析。
- `Application/Service 1 (App1) -> Logs (L)`：应用程序/服务 1 生成日志数据。
- `Application/Service 1 (App1) -> Metrics (M)`：应用程序/服务 1 生成指标数据。
- `Application/Service 1 (App1) -- Generates Spans For --> Traces (T)`：应用程序/服务 1 生成追踪的 Spans。
- `Application/Service 2 (App2) -> Logs (L)`：应用程序/服务 2 生成日志数据。
- `Application/Service 2 (App2) -> Metrics (M)`：应用程序/服务 2 生成指标数据。
- `Application/Service 2 (App2) -- Generates Spans For --> Traces (T)`：应用程序/服务 2 生成追踪的 Spans。
- `Infrastructure (App3) -> Logs (L)`：基础设施生成日志数据。
- `Infrastructure (App3) -> Metrics (M)`：基础设施生成指标数据。

## 仓库语境与术语解释
- **Observability**：可观测性是指通过系统的外部输出来推断其内部状态的能力。
- **Logs**：日志是记录系统中发生的事件的文本记录，可用于故障排除和审计。
- **Metrics**：指标是衡量系统性能和资源利用率的数值数据。
- **Traces**：追踪是记录请求在系统中传播的路径的数据，用于识别性能瓶颈。
- **Spans**：图中可见，但仓库上下文未进一步说明。
- **Application/Service**：表示在系统中运行的应用程序或服务。参考 README 中的目录，这些服务可能使用 Docker, Kubernetes 等技术部署。
- **Infrastructure**：表示支持应用程序运行的底层硬件和软件资源。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了可观测性的架构，从可观测性出发，依赖于日志、指标和追踪数据的收集。系统中的各个组件（应用程序/服务和基础设施）产生日志、指标和追踪数据。日志提供详细的事件上下文，指标提供聚合的系统健康和趋势信息，追踪提供请求流的路径和瓶颈分析。其中，Application/Service 1 和 Application/Service 2 会生成 Traces 的 Spans。
