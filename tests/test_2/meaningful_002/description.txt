## Diagram Type & Purpose
This is a flowchart diagram depicting the architecture and data flow of a product recommendation system. It illustrates the process from user activity monitoring and catalog ingestion to generating and displaying product recommendations. The diagram serves as a high-level overview of the system's components and their interactions.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is divided into three main subgraphs: User Activity Monitoring, Catalog Ingestion & Enrichment, and Recommendation Service. The process starts with Clickstream Ingestion and Product Data Feed and ends with Frontend Display.

## Edges, Branches & Convergence
- `UA1 --> UA2`: Clickstream data flows from ingestion to real-time processing.
- `UA2 --> UA3`: Processed events update user profiles.
- `UA3 --> RS1`: User profile updates are fed into the recommendation service for query understanding.
- `CI1 --> CI2`: Product data flows from the feed to data validation and cleaning.
- `CI2 --> CI3`: Validated data is used for image feature extraction.
- `CI2 --> CI4`: Validated data is used for textual feature extraction.
- `CI3 & CI4 --> CI5`: Image and textual features are combined to enrich the product catalog.
- `CI5 --> RS1`: The enriched product catalog is fed into the recommendation service for query understanding.
- `RS1 --> RS2`: The understood query and context are used to determine if the query intent is a fuzzy match.
- `RS2 -- Yes --> RS3`: If the query intent is a fuzzy match, keyword expansion and correction are performed.
- `RS2 -- No --> RS4`: If the query intent is not a fuzzy match, semantic similarity search is performed.
- `RS3 --> RS4`: Expanded and corrected keywords are used for semantic similarity search.
- `RS4 --> RS5`: Semantic similarity search results in candidate product retrieval.
- `RS5 --> RS6`: Candidate products are re-ranked and filtered.
- `RS6 --> RS7`: Re-ranked products are passed to the personalization layer.
- `RS7 --> RS8`: Personalized results are aggregated and prioritized.
- `RS8 --> RS9`: Aggregated results generate a product recommendation response.
- `RS9 --> FE1`: The product recommendation response is displayed on the frontend.

## Repository Context & Terminology
- **Clickstream Ingestion**: The process of collecting and storing user interactions (clicks, page views, etc.) on a website or application.
- **Real-Time Event Processing**: Analyzing and reacting to events as they occur, enabling immediate updates and personalized experiences.
- **User Profile**: A collection of data representing a user's preferences, behavior, and attributes.
- **Product Data Feed**: A structured file containing information about products, such as title, description, price, and availability.
- **Data Validation & Cleaning**: Ensuring the accuracy and consistency of data by identifying and correcting errors or inconsistencies.
- **Image Feature Extraction**: The process of extracting meaningful features from images, such as color, texture, and shape.
- **Textual Feature Extraction**: The process of extracting meaningful features from text, such as keywords, entities, and sentiment.
- **Semantic Similarity Search**: A search technique that finds results based on the meaning of the query rather than exact keyword matches.
- **Personalization Layer**: A component that tailors recommendations to individual users based on their preferences and behavior.

## High-Density QA Ground Truth Summary
The product recommendation system begins with two parallel processes: User Activity Monitoring and Catalog Ingestion & Enrichment. User Activity Monitoring starts with Clickstream Ingestion, followed by Real-Time Event Processing, which updates User Profiles. Simultaneously, Catalog Ingestion & Enrichment starts with a Product Data Feed, which undergoes Data Validation & Cleaning, leading to Image Feature Extraction and Textual Feature Extraction. These features enrich the Product Catalog. Both User Profile Updates and the Enriched Product Catalog feed into the Recommendation Service, starting with Query Understanding & Context. If not (No branch), Semantic Similarity Search is performed directly. Semantic Similarity Search leads to Candidate Product Retrieval, followed by Re-Ranking & Filtering, and then the Personalization Layer. The results are then processed by Result Aggregation & Prioritization, generating a Product Recommendation Response. Finally, the recommendations are displayed on the Frontend Display. The Personalization Layer leverages user profile data collected from clickstream events to tailor recommendations, demonstrating the system's ability to adapt to individual user preferences.
