## Repository Context & Terminology
1. **Authentication**: The process of verifying a user's identity. In standard practice, successful authentication would lead to authorization or resource access, not logout. The diagram DEVIATES by routing successful authentication to a "Logout" node.
2. **Authorization**: The process of determining if an authenticated user has permission to access a specific resource. In standard practice, authorization would follow authentication. The diagram DEVIATES by placing authorization *after* logout.
3. **Logout**: The process of terminating a user's session. In standard practice, logout would be a separate action, not part of the core authentication/authorization flow. The diagram DEVIATES by making logout a central step after authentication.
4. **Cache**: A temporary storage area for frequently accessed data. In standard practice, writing to the cache would occur after successful resource access. The diagram DEVIATES by writing to the cache after authorization is granted, which is mislabeled.
5. **Database (DB) Read**: Retrieving data from a database. In standard practice, a DB read might occur if data is not in the cache or if authorization fails. The diagram DEVIATES by initiating a DB read upon authorization failure and looping back to logout.
6. **Access Resource**: The action of allowing a user to use a particular resource. The diagram DEVIATES by allowing direct access to a resource when a user is not authenticated.
7. **User Request**: An action initiated by a user to access a resource or perform a task.
8. **User Response**: The output or feedback provided to the user after processing their request.
