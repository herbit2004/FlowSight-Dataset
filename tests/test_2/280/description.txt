## Repository Context & Terminology
- **KV Cache**: Key-Value cache, a data store that uses key-value pairs to store and retrieve data.
- **AST**: Abstract Syntax Tree, a tree representation of the abstract syntactic structure of source code.
- **ML**: Machine Learning.
- **LLM**: Large Language Model.
- **ContentRouter**: A component that detects the content type and selects an appropriate compressor.
- **Compressor**: A component that compresses data.
- **CCR**: Compress-Cache-Retrieve, a mechanism for compressing, caching, and retrieving data.

## High-Density QA Ground Truth Summary
The transform pipeline begins with the `CacheAligner` stabilizing the prefix for the KV cache. The data then flows to the `ContentRouter`, which detects the content type and picks an appropriate compressor. Based on the content type, the `ContentRouter` dispatches to one of the compressors: `SmartCrusher` for any JSON type, `CodeCompressor` for AST-aware code, or `LLMLingua` for ML-based text. The `SmartCrusher` stores originals and a summary of what's omitted in the `Compressed\nStore`. After `ContentRouter`, the data flows through `IntelligentContext` for score-based token fitting and then to `Query Echo`, which re-injects the user question. The `Query Echo` passes the data to the `LLM Provider`. The `LLM Provider` retrieves data from `headroom_retrieve` when it needs more data. The `headroom_retrieve` interacts with the `Compressed\nStore` to retrieve compressed data. The pipeline's end nodes are the different compressors and the `Compressed\nStore`. The `ContentRouter`'s dispatching logic is crucial for selecting the optimal compression strategy based on the input data's characteristics.
