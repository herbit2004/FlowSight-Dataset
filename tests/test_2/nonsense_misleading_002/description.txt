## Edges, Branches & Convergence
- `User --> Is Validated?`: The user initiates the validation process.
- `Is Validated? -- No --> Redirect to Success Page`: If the user is not validated, redirect to a success page.
- `Is Validated? -- Yes --> Access Protected Resource`: If the user is validated, grant access to the protected resource.
- `Access Protected Resource --> Authorization Check`: After accessing the protected resource, perform an authorization check.
- `Authorization Check -- Denied --> Log Access Attempt`: If authorization is denied, log the access attempt.
- `Log Access Attempt --> Is Validated?`: After logging the access attempt, loop back to the validation check.
- `Authorization Check -- Allowed --> Data Retrieval`: If authorization is allowed, retrieve the data.
- `Data Retrieval --> Write Cache`: After retrieving the data, write it to the cache.
- `Write Cache --> Data Found in Cache?`: After writing to the cache, check if the data is found in the cache.
- `Data Found in Cache? -- Yes --> Return Stale Data`: If the data is found in the cache, return stale data.
- `Data Found in Cache? -- No --> Notify Admin of Cache Miss`: If the data is not found in the cache, notify the administrator of a cache miss.
- `Notify Admin of Cache Miss --> Invalidate Session`: After notifying the administrator, invalidate the session.
- `Invalidate Session --> User`: After invalidating the session, return to the user.
- `Return Stale Data --> User`: After returning stale data, return to the user.

## Repository Context & Terminology
- **User**: A person or system interacting with the application.
- **Validation**: The process of verifying the identity of a user. In standard practice, failure to validate would redirect to a login or error page, not a success page as shown in the diagram.
- **Authorization**: The process of determining if a validated user has permission to access a specific resource.
- **Cache**: A temporary storage location for frequently accessed data. The diagram shows "Write Cache" before checking if data is in the cache, which is counter-intuitive. Typically, one would "Read Cache" first.
- **Cache Miss**: Occurs when requested data is not found in the cache. The diagram shows notifying the admin of a cache miss leading to session invalidation and returning to the user, which is an unusual flow.
- **Stale Data**: Data in the cache that is outdated. The diagram returns stale data to the user without any intermediate steps.
- **Session Invalidation**: The process of terminating a user's active session.

If authorization is denied, the "Log Access Attempt" node is triggered, which then loops back to the "Is Validated?" step, implying that logging causes re-validation. If the data is not found ("No" branch), "Notify Admin of Cache Miss" is triggered, leading to "Invalidate Session", which then returns to the "User". The "Write Cache" step, instead of "Read Cache", is a deviation from standard caching practices. The flow from "Notify Admin of Cache Miss" to "Invalidate Session" and back to the "User" after a cache miss is also an unusual control flow.
