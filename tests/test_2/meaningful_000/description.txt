## Diagram Type & Purpose
This is a flowchart diagram illustrating the user registration and login flow of a typical web application. It outlines the steps involved in creating a new user account, verifying their email address, and authenticating them for login. The diagram serves as a visual representation of the process, aiding in understanding and documenting the user authentication system.

## Overall Layout
The diagram flows from left to right. It starts with user input and proceeds through a series of validation, creation, and authentication steps. The start node is "User Input: Email and Password," and the end nodes are "Return JWT Token to User" and "Return Error: Invalid Credentials."

## Subgraphs / Stages
No explicit subgraphs; logically divided into four stages:
1. Input and Validation: User provides credentials, which are validated.
2. Account Creation: If valid, a new user account is created and email verification is initiated.
3. Authentication: Existing users are authenticated.
4. Token Generation or Error: Upon successful authentication or account activation, a JWT token is generated; otherwise, an error is returned.

## Repository Context & Terminology
- **User Registration**: The process of creating a new user account in the system.
- **Login**: The process of authenticating an existing user to grant access to the system.
- **Email Verification**: A security measure to ensure that the user's email address is valid and belongs to them.
- **Hashing**: A cryptographic function that converts a password into a secure, irreversible string of characters.
- **JWT (JSON Web Token)**: A standard for securely transmitting information between parties as a JSON object. It is commonly used for authentication and authorization.
- **Authentication**: The process of verifying the identity of a user.
- **Credentials**: The information used to authenticate a user, typically a username and password.

## High-Density QA Ground Truth Summary
The user registration and login flow begins with the user providing their email and password (A). The system first checks if the user already exists (B). If the user exists (B -- Yes --> C), the system proceeds to authenticate the user (C). If the user does not exist (B -- No --> D), the system validates the input format (D) and checks if the email is valid (E). If the email is invalid (E -- No --> G), an error is returned (G). If the email is valid (E -- Yes --> F), the password is hashed (F), a user account is created (H), and a verification email is sent (I). The user clicks the verification link (J), the email address is verified (K), and the account is activated (L). After successful authentication (M -- Yes --> N) or account activation (L --> N), a JWT token is generated (N) and returned to the user (P). If authentication fails (M -- No --> O), an error is returned (O). The JWT token is a standard method for securely transmitting user authentication information, allowing the user to access protected resources. The process ends either with the successful return of a JWT token (P) or an error message indicating invalid credentials or email format (G, O).
