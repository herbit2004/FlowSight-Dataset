## Diagram Type & Purpose
This is a flowchart diagram depicting the user registration and login process for a system. It outlines the steps a user takes to either create a new account or log in to an existing one, including validation, authentication, and error handling. The diagram serves as a visual representation of the user authentication flow within the application.

## Overall Layout
The diagram flows from left to right. It starts with the user visiting the login page and branches into registration or login flows based on whether the user is existing or new. The diagram concludes with either a successful login redirecting to the dashboard or a successful registration displaying a verification email message.

## Repository Context & Terminology
- **API Gateway**: A service that acts as a single entry point for all API requests, routing them to the appropriate backend services.
- **User Service**: A service responsible for managing user accounts, including creation, authentication, and authorization.
- **Auth Service**: A service responsible for authenticating users and issuing JWTs.
- **JWT (JSON Web Token)**: A standard for securely transmitting information between parties as a JSON object. It is commonly used for authentication and authorization.
- **HTTP-only cookie**: A cookie that is only accessible by the server and not by client-side scripts, enhancing security.
- **Dashboard**: The main landing page for a logged-in user, providing access to the application's features.
- **Credentials**: The username/email and password used to authenticate a user.

## High-Density QA Ground Truth Summary
The user authentication flow begins when a user visits the login page. The system checks if the user is an existing user. If the user is not an existing user, they are redirected to the registration page, where they fill out a registration form. The system validates the registration form data, and if it's valid, the data is submitted to the API Gateway. The API Gateway routes the request to the User Service, which creates a new user account and sends a verification email. The User Service also stores the email verification token. After successful account creation, the API Gateway receives a success message and displays a "Verification Email Sent" message to the user. If the user is an existing user, they enter their credentials, which are submitted to the API Gateway. The API Gateway authenticates the user via the Auth Service. If the credentials are valid, the Auth Service generates a JWT, which is returned to the API Gateway. The API Gateway sets the JWT as an HTTP-only cookie and redirects the user to the dashboard. If the credentials are invalid, the Auth Service returns an authentication error, and the system displays an "Invalid credentials" error message. The API Gateway acts as a central point for routing requests and handling authentication, while the User Service manages user accounts and the Auth Service handles authentication and JWT generation.
