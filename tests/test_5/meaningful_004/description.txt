## Edges, Branches & Convergence
- `A --> B`: User submits the form.
- `B -- Valid --> C`: Form validation is successful.
- `B -- Invalid --> E`: Form validation fails.
- `C --> D`: Event producer sends the 'form_submission' event to the message queue.
- `D --> F`: Event consumer receives the 'form_submission' event from the message queue.
- `F --> G`: Event consumer triggers campaign identification.

- `I, O --> P`: Paths converge at the Data Warehouse.

## Repository Context & Terminology
- **Marketing Campaign**: A coordinated set of actions designed to promote a product or service.
- **Form Validation**: The process of ensuring that user-submitted data meets predefined criteria.
- **Event Producer**: A component that generates events in response to specific actions.
- **Message Queue**: A system for asynchronous communication between components.
- **Event Consumer**: A component that processes events from a message queue.
- **Data Warehouse**: A central repository for storing and analyzing data.
- **Campaign Metrics**: Quantitative measures used to track the performance of a marketing campaign.

## High-Density QA Ground Truth Summary
The marketing campaign system begins with a user submitting a form, which triggers form validation. If the form is valid, an event producer generates a 'form_submission' event and sends it to the 'CampaignEvents' message queue. If the form is invalid, an error message is displayed to the user. An event consumer, 'campaign_subscriber', then retrieves the event from the queue and attempts to identify the relevant campaign. If a campaign is found, campaign logic applies an offer, and the system checks if the user is eligible for a discount. If eligible, a discount coupon is created and stored in the user's profile; otherwise, a generic thank you message is sent. Both scenarios lead to sending a personalized email. If no campaign is found during the identification step, the unmatched form is logged. Finally, campaign metrics are updated, and all data, including unmatched form logs, is stored in the Data Warehouse. The message queue facilitates asynchronous communication between the form submission and data processing stages, ensuring that the system can handle a high volume of submissions without performance bottlenecks.
