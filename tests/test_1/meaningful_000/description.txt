## Diagram Type & Purpose
This is a flowchart diagram illustrating the user registration and login flow of a typical web application. It outlines the steps involved in both creating a new user account and logging in with existing credentials, including validation checks, error handling, and security measures. The diagram serves as a visual representation of the authentication process.

## Overall Layout
The diagram flows from left to right. It starts with user input and branches into registration and login paths. The end nodes represent successful login (redirect to dashboard) or error states (displaying error messages).

## Edges, Branches & Convergence
- `A --> B`: User input flows to email format validation.
- `B -- Yes --> C`: If the email format is valid, proceed to check if the email is already registered.
- `B -- No --> E`: If the email format is invalid, display an error.
- `C -- No --> D`: If the email is not already registered, create a new user account.
- `C -- Yes --> H`: If the email is already registered, attempt login.
- `D --> F`: After creating a new account, send a verification email.
- `F --> G`: After sending the verification email, await email verification.
- `G -- Verified --> H`: After the email is verified, attempt login.
- `H --> I`: Attempt login flows to credential validation.
- `I -- Yes --> J`: If the credentials are valid, generate a JWT.
- `I -- No --> K`: If the credentials are invalid, check account lockout.
- `K -- Yes --> L`: If the account is locked, display an error.
- `K -- No --> M`: If the account is not locked, increment failed login attempts.
- `M --> N`: After incrementing failed login attempts, display an error.
- `J --> O`: After generating a JWT, set a session cookie.
- `O --> P`: After setting the session cookie, redirect to the user dashboard.

## Repository Context & Terminology
- **Email/Password**: Standard authentication credentials used for user login.
- **Valid Email Format**: A check to ensure the email address conforms to a standard format (e.g., contains an @ symbol and a domain).
- **JWT (JSON Web Token)**: A standard for securely transmitting information between parties as a JSON object. Used here for authentication and authorization.
- **Session Cookie**: A small piece of data stored on the user's computer to maintain session state and track user activity.
- **Account Lockout**: A security measure to prevent brute-force attacks by locking an account after a certain number of failed login attempts.
- **User Dashboard**: The main interface for a logged-in user, providing access to various features and functionalities.
- **Email Verification**: A process to confirm that the email address provided by a user during registration is valid and belongs to them.

## High-Density QA Ground Truth Summary
The user registration and login flow begins with the user providing their email and password. The system first validates the email format. If invalid, an error is displayed. If valid, the system checks if the email is already registered. If not, a new user account is created, and a verification email is sent. After verification, or if the email was already registered, the system attempts login. This involves validating the provided credentials. If valid, a JWT is generated, a session cookie is set, and the user is redirected to their dashboard. If the credentials are invalid, the system checks for account lockout. If the account is locked, an error is displayed. Otherwise, the failed login attempt is incremented, and an invalid credentials error is shown. The JWT is a crucial component, acting as a secure token for subsequent API calls, while the session cookie maintains the user's logged-in state. The account lockout mechanism is a security feature to prevent unauthorized access via brute-force attacks.
