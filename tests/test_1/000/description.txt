## Diagram Type & Purpose
This is a flowchart diagram outlining the process of generating documentation and an interactive DeepWiki for a given code repository. The diagram details the steps involved in analyzing the code structure, creating embeddings, selecting a model provider, generating documentation and visual diagrams, and finally organizing the information into a wiki. It serves as a high-level overview of the documentation generation pipeline.

## Overall Layout
The diagram's layout is top-down (TD). It starts with user input and progresses through a series of steps, branching at the model selection stage, before converging again to organize the output as a wiki. The start node is "User inputs GitHub/GitLab/Bitbucket repo" and the end node is "Interactive DeepWiki".

## Repository Context & Terminology
- **GitHub/GitLab/Bitbucket**: These are popular online platforms for hosting and version controlling code repositories.
- **Private Repo**: A repository with restricted access, requiring authentication (e.g., an access token) to clone or access its contents.
- **Access Token**: A credential used to authenticate and authorize access to a private repository.
- **Code Embeddings**: Vector representations of code snippets, capturing their semantic meaning. These embeddings are used by the models to understand the code and generate relevant documentation.
- **Google Gemini, OpenAI, OpenRouter, Local Ollama, Azure**: These are different model providers that can be used to generate documentation. Each provider offers different models with varying capabilities and pricing.
- **DeepWiki**: An interactive wiki that leverages deep learning techniques to provide enhanced search, navigation, and content understanding.

## High-Density QA Ground Truth Summary
The process begins with the user providing a repository URL from GitHub, GitLab, or Bitbucket. The system then checks if the repository is private. If it is, the user is prompted to add an access token; otherwise, the process proceeds directly to cloning the repository. After cloning, the code structure is analyzed, and code embeddings are created. These embeddings serve as input for the next stage, where a model provider is selected from options like Google Gemini, OpenAI, OpenRouter, Local Ollama, or Azure. Based on the selected provider, documentation is generated. Simultaneously, visual diagrams of the code are created. The generated documentation and visual diagrams are then organized into a wiki. Finally, this wiki is transformed into an interactive DeepWiki. The selection of the model provider determines the specific AI model used for documentation generation, influencing the style, quality, and potential cost of the generated documentation. The final interactive DeepWiki provides a user-friendly interface for exploring and understanding the codebase.
