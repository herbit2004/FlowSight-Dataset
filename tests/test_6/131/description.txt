## Repository Context & Terminology
- **ElatoAI**: The overall project name, encompassing the frontend, backend, and ESP32 client components.
- **Frontend Vercel NextJS**: The frontend is built using Next.js, a React framework, and deployed on Vercel, a platform for serverless functions and static websites.
- **Deno Edge Function**: The backend is implemented as a Deno edge function, allowing for server-side logic to be executed closer to the user for reduced latency.
- **ESP32 Arduino Client**: The client application runs on an ESP32 microcontroller, a low-cost, low-power system-on-a-chip with integrated Wi-Fi and Bluetooth.
- **Supabase DB**: Supabase is an open-source alternative to Firebase, providing a PostgreSQL database, authentication, and real-time subscriptions.
- **Opus Codec**: Opus is a lossy audio codec designed for interactive speech and music transmission over the Internet.
- **ESPAsyncWebServer**: An asynchronous web server library for the ESP32, enabling the device to serve web pages and handle HTTP requests.

## High-Density QA Ground Truth Summary
The ElatoAI system architecture begins with the root node, ElatoAI, which branches out into three primary components: the Frontend Vercel NextJS, the Deno Edge Function, and the ESP32 Arduino Client. The frontend, built with Next.js and deployed on Vercel, interacts with the Supabase DB for data persistence. Similarly, the Deno Edge Function, serving as the backend, also interacts with the Supabase DB. The ESP32 Arduino Client, running on an ESP32 microcontroller, utilizes several libraries for its functionality, including Secure WebSockets for secure communication, Opus Codec for audio encoding/decoding, arduino-audio-tools and arduino-libopus for audio processing, and ESPAsyncWebServer for serving web content. The Supabase DB serves as a central data store accessed by both the frontend and backend. The ESP32 client leverages the Opus codec for efficient audio transmission, a critical aspect for real-time audio applications. The architecture highlights a distributed system with a clear separation of concerns between the frontend, backend, and embedded client.
