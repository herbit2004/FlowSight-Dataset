- `A --> B`: User submits an order, initiating the order processing workflow.
- `B -- Yes --> C`: Payment is received, proceeding to inventory check.
- `B -- No --> H`: Payment is not received, proceeding to cancel the order process.
- `C --> D`: Inventory check is performed.
- `D -- Yes --> F`: Inventory is available, proceeding to determine the shipping method.
- `D -- No --> E`: Inventory is not available, proceeding to notify the user about order cancellation.
- `E --> H`: After notifying the user, the process proceeds to cancel the order process.
- `F --> G`: Shipping method is determined, proceeding to package items for shipping.
- `G --> I`: Items are packaged for shipping.

- `M -- Yes --> N`: User confirms delivery, proceeding to close the order.
- `M -- No --> K`: User does not confirm delivery, looping back to notify user of shipment.
- `H --> N`: Cancel order process merges into close order.

## High-Density QA Ground Truth Summary
The flowchart begins with a "User Submits Order," which leads to a "Payment Received?" check. If payment is received ("Yes"), the process moves to "Inventory Check" and then to "Inventory Available?". If inventory is not available ("No"), the user is notified ("Notify User Order Canceled"), and the process proceeds to "Cancel Order Process," which incorrectly merges into "Close Order." If inventory is available ("Yes"), the system determines the shipping method ("Determine Shipping Method") and packages the items ("Package Items for Shipping"). The diagram then checks "Shipping Label Printed?". If the label is printed ("Yes"), the process loops back to "Package Items for Shipping," which is an error. If the label is not printed ("No"), the order is marked as "Order Shipped," which is also an error, as the label should be printed before shipping. The user is then notified of shipment ("Notify User of Shipment"), and the order is marked as "Order Delivered." The system then checks "User Confirms Delivery?". If the user confirms ("Yes"), the order is closed ("Close Order"). If the user does not confirm ("No"), the system loops back to "Notify User of Shipment," creating an illogical loop. The "Cancel Order Process" incorrectly merges into the "Close Order" node, regardless of the cancellation reason.
