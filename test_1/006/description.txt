## Diagram Type & Purpose
This is an architecture diagram illustrating the data flow and processing pipeline of an issue analysis system. It depicts the stages from data ingestion to analysis and presentation, showcasing the components involved in loading, processing, and visualizing issue data. The diagram serves as a high-level overview of the system's architecture.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is hierarchically structured, starting with the Data Layer at the top, followed by the Analysis Engine, and branching out to Outputs and the TUI Layer at the bottom. The start node is the Data Layer, and the end nodes are the various output formats and TUI views.

## Repository Context & Terminology
- **JSONL**: JSON Lines format, a text format where each line is a valid JSON value.
- **PageRank**: An algorithm used to measure the importance of nodes in a graph.
- **Betweenness Centrality**: A measure of how often a node lies on the shortest path between other nodes.
- **HITS (Hyperlink-Induced Topic Search)**: A link analysis algorithm that rates web pages.
- **Bubble Tea**: A Go framework for building terminal user interfaces.
- **TUI**: Textual User Interface.

## High-Density QA Ground Truth Summary
The architecture diagram begins with the `.beads/beads.jsonl` file, a JSONL Issue Store within the Data Layer, which serves as the initial data source. This data is then ingested by the Loader component within the Analysis Engine. The Loader passes the data to the Graph Builder, which constructs a graph representation suitable for analysis. Subsequently, the 9 Metrics component calculates various graph metrics such as PageRank, Betweenness, and HITS. From the 9 Metrics component, the data branches out in three directions: one path leads to the `--robot-insights` JSON output for AI agents, another to the `--export-md` Markdown Report, and the third to the Bubble Tea Model within the TUI Layer. The Bubble Tea Model then feeds data to the List View, Graph View, Tree View, and Insights Dashboard components of the TUI, providing different ways to visualize the analyzed issue data. The JSONL format is used for storing issue data, and the Bubble Tea framework is employed for building the terminal user interface.
