## Edges, Branches & Convergence
- `GEN --> R`: Generates daily reports.
- `R --> A`: Analyzes the reports.
- `A --> J`: Creates the analysis JSON.
- `J --> B`: Creates a new branch.
- `B --> PRD`: Loads the PRD skill.
- `PRD --> MD`: Loads the PRD markdown file.
- `MD --> TASKS`: Loads the tasks skill.
- `TASKS --> JSON`: Creates the executable tasks JSON.
- `JSON --> LOOP`: Starts the execution loop.
- `LOOP --> PICK`: Picks the next task.
- `PICK --> IMPL`: Implements the task.
- `IMPL --> CHECK`: Performs quality checks.
- `CHECK -- Pass --> COMMIT`: If the quality checks pass, commit the changes.
- `CHECK -- Fail --> FIX`: If the quality checks fail, fix and retry.
- `FIX --> CHECK`: Retries the quality checks after fixing.
- `COMMIT --> UPDATE`: Updates the prd.json file.
- `UPDATE --> DONE`: Checks if all tasks are done.
- `DONE -- No --> PICK`: If not all tasks are done, pick the next task.
- `DONE -- Yes --> EXIT`: If all tasks are done, exit the loop.
- `EXIT --> PUSH`: Pushes the changes.
- `PUSH --> PR`: Creates a pull request.
- The path `FIX --> CHECK` and `UPDATE --> DONE` converge at `CHECK` and `DONE` respectively.

## High-Density QA Ground Truth Summary
The process begins with the "Generate Daily Report" node, which creates reports containing metrics, errors, and feedback. These reports, stored as `reports/*.md`, are then analyzed by the `analyze-report.sh` script using an LLM API. The analysis results in a `analysis.json` file, which includes priority and criteria for subsequent task planning. A new branch is created, and the AI Agent loads the PRD skill from `skills/prd/SKILL.md` and the tasks skill from `skills/tasks/SKILL.md`. These skills are used to generate executable tasks stored in `prd.json`. The `loop.sh` script then executes these tasks in a loop. Inside the loop, the system picks the next task where 'passes' is false, implements it using an AI Agent, and performs quality checks. If the checks pass, the changes are committed via Git, and `prd.json` is updated. If the checks fail, the task is fixed and retried. The loop continues until all tasks are done. Finally, the changes are pushed to Git, and a pull request is created, signaling that the work is ready for review. The quality check outcome determines whether a task is retried or committed, forming a critical decision point in the execution loop.
