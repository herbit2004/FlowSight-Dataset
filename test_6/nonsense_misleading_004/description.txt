## Diagram Type & Purpose
This is a flowchart diagram illustrating the order processing workflow of an e-commerce system. It depicts the sequence of steps from when a user submits an order to when the order is closed, including payment processing, inventory management, shipping, and customer satisfaction. The diagram serves as a visual representation of the order lifecycle, highlighting key decision points and potential failure scenarios.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It starts with the "User Submits Order" node at the top and flows downwards through various stages of order processing, ultimately converging at the "Close Order" node. There is a primary linear flow with several branching decision points that lead to alternative paths.

## Subgraphs / Stages
No explicit subgraphs; logically divided into 6 stages: Order Submission & Payment, Logistics & Inventory, Shipping & Delivery, Issue Resolution, Feedback Collection, and Order Closure.

## Edges, Branches & Convergence
- `A --> B`: User submits an order, initiating the payment process.
- `B -- No --> C`: Payment fails, triggering notification to the user.
- `C --> D`: User is notified of payment failure, leading to automatic order cancellation.
- `B -- Yes --> E`: Payment is successful, triggering logistics assignment.
- `E --> F`: Logistics are assigned, leading to inventory availability check.
- `F -- Yes --> G`: Inventory is available, leading to item shipment.
- `G --> H`: Item is shipped, triggering inventory update.
- `F -- No --> H`: Inventory is unavailable, triggering inventory update.
- `H --> I`: Inventory is updated, leading to shipping confirmation check.
- `I -- No --> J`: Shipping confirmation fails, triggering notification to the warehouse of a shortage.
- `J --> K`: Warehouse is notified of shortage, leading to warehouse restocks.
- `K --> L`: Warehouse restocks, leading to logistics reassignment.
- `L --> G`: Logistics are reassigned, looping back to item shipment.
- `I -- Yes --> M`: Shipping confirmation is sent, leading to order delivery.
- `M --> N`: Order is delivered, leading to user receipt confirmation.
- `N -- No --> O`: User has not received the order, triggering a refund.
- `O --> A`: Refund is issued, looping back to user submitting an order.
- `N -- Yes --> P`: User receives the order, leading to order closure.
- `P --> Q`: Order is closed, triggering sales report generation.
- `Q --> R`: Sales report is generated, leading to order data archiving.
- `R --> S`: Order data is archived, triggering customer satisfaction survey.
- `S --> T`: Customer satisfaction survey is sent, leading to survey completion check.
- `T -- Yes --> U`: Survey is completed, triggering survey result analysis.
- `U --> P`: Survey results are analyzed, looping back to order closure.
- `T -- No --> V`: Survey is not completed, triggering escalation for follow-up.
- `V --> P`: Issue is escalated for follow-up, leading to order closure.

- **Payment Received?**: In standard practice, this is a check to ensure that the customer's payment has been successfully processed. In this diagram, it's a decision point that determines whether the order proceeds or is cancelled.
- **Logistics Assigned**: In standard practice, this refers to the process of assigning a shipping carrier and tracking information to an order. In this diagram, it represents the stage where logistics are handled after payment.
- **Inventory Available?**: In standard practice, this is a check to ensure that the ordered items are in stock. In this diagram, it's a decision point that determines whether the item can be shipped or if inventory needs to be updated.
- **Item Shipped**: In standard practice, this refers to the action of sending the ordered item to the customer. In this diagram, it represents the stage where the item is physically shipped.
- **Update Inventory**: In standard practice, this refers to adjusting the inventory records to reflect the shipped items. In this diagram, it occurs *after* the item is shipped, which is a reversed sequence.
- **Shipping Confirmation Sent?**: In standard practice, this refers to sending a notification to the customer with tracking information. In this diagram, failure to send confirmation triggers a warehouse shortage notification.
- **Close Order**: In standard practice, this refers to the final step of completing the order process. In this diagram, it's the end point of the workflow and a potential loop point after survey analysis or escalation.

## High-Density QA Ground Truth Summary
The order processing workflow begins when a user submits an order (A), which then checks if the payment is received (B). If payment fails (B -- No --> C), the user is notified, and the order is automatically cancelled (D). If payment is successful (B -- Yes --> E), logistics are assigned, and inventory availability is checked (F). If inventory is unavailable (F -- No --> H), the inventory is updated. If inventory is available (F -- Yes --> G), the item is shipped, and the inventory is updated (H). The diagram then checks if a shipping confirmation was sent (I). If not (I -- No --> J), the warehouse is notified of a shortage, restocks (K), and logistics are reassigned (L), looping back to item shipment (G). If shipping confirmation was sent (I -- Yes --> M), the order is delivered, and the system checks if the user received the order (N). If not (N -- No --> O), a refund is issued, and the process loops back to the user submitting a new order (A). If the user received the order (N -- Yes --> P), the order is closed. After closing, a sales report is generated (Q), order data is archived (R), and a customer satisfaction survey is sent (S). The system then checks if the survey was completed (T). If completed (T -- Yes --> U), the survey results are analyzed, and the process loops back to closing the order (P). If the survey is not completed (T -- No --> V), the issue is escalated for follow-up, and the order is closed (P). The final step is closing the order (P), which can be reached through multiple paths. The reversed sequence of updating inventory after shipping (G --> H) and the illogical loop from survey analysis back to closing the order (U --> P) are key deviations from standard e-commerce practices.
