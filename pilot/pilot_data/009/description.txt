## 图类型与用途
这是一个流程图/架构图，描述了 DeepDiagram AI 平台如何将用户请求转换为各种类型的可视化图表。它展示了 DeepDiagram AI 的内部架构和数据处理流程，强调其基于 Agentic AI 和 LangGraph 的多智能体协同工作模式。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户输入节点，中间是智能路由和 LangGraph 编排器，然后是各种专业智能体，底部是前端渲染和展示。

## 分组/子图/阶段说明
图中包含两个 subgraph：
- **Agents**：表示一组专门处理不同类型图表生成的智能体，每个智能体负责生成特定格式的图表代码。
- **Output**：表示流式 XML 标签输出阶段，包括 LLM 生成标签和解析标签。

## 节点逐项说明
- **Input**：用户输入，可以是文本描述、图像、文档等，作为整个流程的起点。
- **Router**：智能路由，接收用户输入后，进行意图分类，决定将请求路由到哪个或哪些 Agent 处理。
- **Graph**：LangGraph 编排器，负责协调和管理各个 Agent 的工作流程，根据意图分类的结果将任务分配给相应的 Agent。
- **AgentMM**：思维导图智能体，生成 Markdown/Markmap 格式的思维导图。
- **AgentFlow**：流程图智能体，生成 React Flow JSON 格式的流程图。
- **AgentChart**：数据图表智能体，生成 ECharts 配置格式的数据图表。
- **AgentDraw**：Draw.io 智能体，生成 mxGraph XML 格式的图表。
- **AgentMermaid**：Mermaid 智能体，生成 Mermaid 语法格式的图表。
- **AgentInfo**：信息图智能体，生成 AntV DSL 格式的信息图。
- **AgentGeneral**：通用智能体，生成纯文本。
- **Tags**：Agent 生成的图表代码被封装在 XML 标签中，例如 `<design_concept>...</design_concept>` 和 `<code>...</code>`。
- **Parser**：流式标签解析器，解析 XML 标签，将 `design_concept` 和 `code` 事件分别提取出来。
- **DC**：`design_concept` 事件流，包含图表的设计概念信息。
- **Code**：`code` 事件流，包含图表的代码信息。
- **Frontend**：React 19 构建的前端界面，负责接收来自后端的数据流，并进行实时渲染。
- **Canvas**：前端提供的交互式画布，用于展示和编辑生成的图表。
- **Trace**：前端提供的执行追踪界面，用于展示整个流程的执行过程。

## 连线、分支与汇聚关系
- `Input -> Router`：用户通过 Input 提交请求后，进入智能路由阶段。
- `Router -- Intent Classification --> Graph`：Router 对用户请求进行意图分类，并将结果传递给 LangGraph Orchestrator。
- `Graph --> Agents`：Graph 根据意图分类结果，将任务路由到相应的 Agents。
- `Agents --> Tags`：Agents 生成对应格式的图表代码，并将其封装在 XML 标签中。
- `Tags --> Parser`：XML 标签被传递给流式标签解析器进行解析。
- `Parser --> DC`：Parser 将解析出的 `design_concept` 事件传递给 Design Concept Stream。
- `Parser --> Code`：Parser 将解析出的 `code` 事件传递给 Code Stream。
- `DC --> Frontend`：Design Concept Stream 通过 SSE (Server-Sent Events) 将数据传递给前端。
- `Code --> Frontend`：Code Stream 通过 SSE 将数据传递给前端，与 Design Concept Stream 形成汇聚关系。
- `Frontend --> Canvas`：前端将数据渲染到交互式画布上。
- `Frontend --> Trace`：前端将执行过程展示在执行追踪 UI 上。

## 仓库语境与术语解释
- **Agentic AI**：DeepDiagram AI 平台利用 Agentic AI 和多智能体编排将自然语言和多模态输入转换为专业图表，如 README 所述。
- **LangGraph**：DeepDiagram 采用 LangGraph 架构，其中专门的代理处理不同的可视化领域，如 README 所述。`backend/app/agents/graph.py` 定义了 LangGraph 状态机。
- **XML Tag Output**：每个 agent 直接输出带有 XML 风格的 `<design_concept>` 和 `<code>` 标签的结构化内容，如 README 所述。
- **SSE (Server-Sent Events)**：后端通过 SSE 将数据流式传输到前端以进行实时预览，如 README 所述。`backend/app/api/routes.py` 定义了 SSE 端点。
- **StreamingTagParser**：`backend/app/api/routes.py` 中定义的类，用于实时解析 XML 风格的标签，并具有状态机以实现强大的多行内容处理。
- **React 19 Frontend**：前端使用 React 19 构建，负责接收来自后端的数据流并进行实时渲染。
- **Intelligent Router**：`backend/app/agents/dispatcher.py` 实现了基于意图的路由，使用显式 `@agent` 标签和 LLM 回退。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 DeepDiagram AI 的核心流程：用户输入请求后，智能路由将其传递给 LangGraph 编排器，编排器根据意图将任务分配给不同的 Agent。Agent 生成包含图表代码的 XML 标签，通过流式标签解析器解析后，分别将设计概念和代码通过 SSE 推送到 React 19 前端，最终在交互式画布上实时渲染，并提供执行追踪 UI。其中，LangGraph 编排器和 XML 标签输出是该流程的关键环节。
