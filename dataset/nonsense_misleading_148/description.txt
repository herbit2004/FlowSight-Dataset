## Diagram Type & Purpose
This is a flowchart diagram illustrating the process of user order placement, order fulfillment, and backend processing in an e-commerce system. It depicts the flow of data and actions from the user's initial browsing to the generation of daily sales reports. The diagram serves as a visual representation of the order processing pipeline, highlighting key decision points and actions performed by the system.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is divided into three subgraphs representing different stages of the order processing pipeline. The start node is "User Browses Products" and the end node is "Generate Daily Sales Report".

## Subgraphs / Stages
The diagram contains three subgraphs:
- **User Order Placement**: This subgraph represents the initial stage where the user interacts with the system to browse products, add items to the cart, and initiate the checkout process.
- **Order Fulfillment**: This subgraph represents the stage where the system processes the order, checks inventory, packages the items, and ships the order to the user.
- **Backend Processing**: This subgraph represents the stage where the system stores order data, performs fraud checks, updates accounting records, generates reporting metrics, and updates the analytics dashboard.

## Edges, Branches & Convergence
- `A --> B`: The user adds items to the cart after browsing products.
- `B --> C`: The user proceeds to checkout after adding items to the cart.
- `C -- Yes --> D`: If the user checks out, the system validates payment information.
- `C -- No --> A`: If the user does not check out, they return to browsing products.
- `D -- Yes --> E`: If the payment information is valid, the payment is processed.
- `D -- No --> B`: If the payment information is invalid, the user is prompted to add items to the cart.
- `E --> F`: After payment is processed, order confirmation is displayed.
- `F -- Yes --> G`: If the order confirmation is displayed, the order is placed.
- `F -- No --> D`: If the order confirmation is not displayed, the system validates payment information again.
- `G --> I`: After the order is placed, the system receives the order.
- `I --> V`: The order data is stored after the system receives the order.
- `V --> J`: After the order data is stored, an inventory check is performed.
- `J --> K`: Inventory check leads to sufficient inventory decision.
- `K -- Yes --> L`: If there is sufficient inventory, the items are pulled from inventory.
- `K -- No --> BB`: If there is insufficient inventory, the system generates a daily sales report.
- `L --> M`: After items are pulled from inventory, the order is packaged.
- `M --> N`: After the order is packaged, a shipping label is printed.
- `N --> O`: After the shipping label is printed, the order is shipped.
- `O --> P`: After the order is shipped, a shipping notification is sent to the user.
- `P --> Q`: After the shipping notification is sent, the order is delivered.
- `Q --> R`: After the order is delivered, a customer satisfaction survey is sent.
- `R --> S`: Customer satisfaction survey leads to customer satisfied decision.
- `S -- Yes --> U`: If the customer is satisfied, the inventory count is updated.
- `S -- No --> T`: If the customer is not satisfied, customer issues are resolved.
- `T --> L`: Customer issues are resolved by pulling items from inventory again.
- `U --> X`: After the inventory count is updated, the order is marked as complete.
- `V --> W`: After the order data is stored, a fraud check is performed.
- `W -- Yes --> Y`: If the fraud check passes, accounting records are updated.
- `W -- No --> T`: If the fraud check fails, customer issues are resolved.
- `Y --> Z`: After accounting records are updated, reporting metrics are generated.
- `Z --> AA`: After reporting metrics are generated, the analytics dashboard is updated.
- `AA --> BB`: After the analytics dashboard is updated, a daily sales report is generated.
- `BB --> AA`: After the daily sales report is generated, the analytics dashboard is updated again.
- `X --> Z`: After the order is marked as complete, reporting metrics are generated.

## Repository Context & Terminology
- **User Order Placement**: The process by which a customer places an order on the e-commerce platform. In this diagram, it encompasses browsing, adding items to the cart, checking out, and payment processing.
- **Order Fulfillment**: The process of preparing and shipping an order to the customer. In this diagram, it includes inventory check, pulling items, packaging, printing shipping labels, shipping, and sending notifications.
- **Backend Processing**: The behind-the-scenes processes that support order management and reporting. In this diagram, it includes data storage, fraud checks, accounting updates, metrics generation, and dashboard updates.
- **Inventory Check**: Verifying the availability of items in stock. In this diagram, it determines whether there is sufficient inventory to fulfill the order.
- **Fraud Check**: Verifying the legitimacy of an order to prevent fraudulent transactions. In this diagram, it determines whether the order is flagged as potentially fraudulent.
- **Analytics Dashboard**: A visual representation of key performance indicators (KPIs) related to sales and orders. In this diagram, it is updated with the latest order data.
- **Daily Sales Report**: A report summarizing the sales activity for a given day. In this diagram, it is generated after the analytics dashboard is updated.
