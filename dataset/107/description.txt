## 图类型与用途
这是一个架构图，展示了 PentAGI 系统的核心组件及其交互方式，用于概览 PentAGI 的系统架构，方便理解其工作原理和数据流向。该系统利用 AI 技术进行自动化渗透测试。

## 图的整体布局
图采用从上到下的布局，将系统划分为五个主要部分，分别是：核心服务、知识图谱、监控、分析和安全工具。数据流从核心服务开始，与其他组件交互，最终可能影响安全工具的执行。

## 分组/子图/阶段说明
图中有五个显式子图，分别代表 PentAGI 系统的五个主要组成部分：
- **Core Services**：包含用户界面、API、数据库、任务队列和 AI 代理等核心组件。
- **Knowledge Graph**：包含知识图谱 API 和图数据库，用于存储和检索知识。
- **Monitoring**：包含用于创建和展示监控仪表盘的组件，以及用于存储监控指标、追踪请求和收集日志的数据库。
- **Analytics**：包含 LLM 分析平台、分析数据库、缓存和对象存储。
- **Security Tools**：包含网络爬虫和安全工具集，用于执行渗透测试任务。

## 节点逐项说明
- **UI (Frontend UI)**：前端用户界面，使用 React 和 TypeScript 构建。
- **API (Backend API)**：后端 API，使用 Go 和 GraphQL 构建，负责处理来自前端的请求，并与数据库、任务队列等其他组件交互。
- **DB (Vector Store)**：向量数据库，使用 PostgreSQL 和 pgvector 扩展，用于存储和检索向量数据，例如嵌入向量。
- **MQ (Task Queue)**：任务队列，用于异步处理任务。
- **Agent (AI Agents)**：AI 代理，一个多代理系统，是 PentAGI 的核心智能部分，负责执行渗透测试任务。
- **Graphiti (Knowledge Graph API)**：知识图谱 API。
- **Neo4j (Graph Database)**：图数据库，用于存储知识图谱。
- **Grafana (Dashboards)**：用于创建和展示监控仪表盘。
- **VictoriaMetrics (Time-series DB)**：时序数据库，用于存储监控指标。
- **Jaeger (Distributed Tracing)**：分布式追踪系统，用于追踪请求在系统中的流向。
- **Loki (Log Aggregation)**：日志聚合系统，用于收集和存储日志。
- **OTEL (OpenTelemetry Data Collection)**：用于收集遥测数据（metrics, traces, logs）。
- **Langfuse (LLM Analytics)**：LLM 分析平台，用于分析 LLM 的性能和行为。
- **ClickHouse (Analytics DB)**：分析数据库，用于存储分析数据。
- **Redis (Cache + Rate Limiter)**：缓存和速率限制器。
- **MinIO (S3 Storage)**：S3 兼容的对象存储，用于存储文件。
- **Scraper (Web Scraper)**：网络爬虫，使用隔离的浏览器环境。
- **PenTest (Security Tools)**：安全工具集，包含 20+ 专业工具，在沙盒环境中执行。

## 连线、分支与汇聚关系
- `UI --> API`：UI 通过 HTTP/WS 协议与 API 进行通信。
- `API --> DB`：API 通过 SQL 查询与 DB 进行交互。
- `API --> MQ`：API 将事件发送到 MQ。
- `MQ --> Agent`：MQ 将任务分发给 Agent。
- `Agent --> PenTest`：Agent 向 PenTest 发送命令以执行安全测试。
- `Agent --> DB`：Agent 查询 DB 以获取信息。
- `Agent --> Graphiti`：Agent 通过 Graphiti 与 Neo4j 知识图谱交互。
- `Graphiti --> Neo4j`：Graphiti 使用 Graph 协议与 Neo4j 交互。
- `API --> OTEL`：API 将遥测数据发送到 OTEL。
- `OTEL --> VictoriaMetrics`：OTEL 将 Metrics 数据发送到 VictoriaMetrics。
- `OTEL --> Jaeger`：OTEL 将 Traces 数据发送到 Jaeger。
- `OTEL --> Loki`：OTEL 将 Logs 数据发送到 Loki。
- `Grafana --> VictoriaMetrics`：Grafana 查询 VictoriaMetrics 获取数据。
- `Grafana --> Jaeger`：Grafana 查询 Jaeger 获取数据。
- `Grafana --> Loki`：Grafana 查询 Loki 获取数据。
- `API --> Langfuse`：API 将 Analytics 数据发送到 Langfuse。
- `Langfuse --> ClickHouse`：Langfuse 将数据存储到 ClickHouse。
- `Langfuse --> Redis`：Langfuse 使用 Redis 作为缓存。
- `Langfuse --> MinIO`：Langfuse 将文件存储到 MinIO。

## 仓库语境与术语解释
- **PentAGI**：Penetration testing Artificial General Intelligence，一个利用 AI 技术进行自动化渗透测试的工具。
- **Core Services**：系统的核心组件，包括 UI、API、数据库、任务队列和 AI 代理。
- **Knowledge Graph**：使用 Graphiti 和 Neo4j 实现，用于存储和检索知识，帮助 AI 代理更好地理解和执行渗透测试任务。
- **Monitoring**：使用 Grafana、VictoriaMetrics、Jaeger 和 Loki 实现，用于监控系统的性能和行为。
- **Analytics**：使用 Langfuse、ClickHouse、Redis 和 MinIO 实现，用于分析 LLM 的性能和行为，并存储分析数据。
- **Security Tools**：包含网络爬虫（Scraper）和安全工具集（PenTest），用于执行渗透测试任务。
- **AI Agents**：多代理系统，是 PentAGI 的核心智能部分，负责执行渗透测试任务。
- **docker-compose.yml**：该文件定义了 PentAGI 系统的各个服务及其依赖关系，方便用户快速部署和运行系统。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 PentAGI 系统的整体架构，从前端 UI 发起请求，通过后端 API 与向量数据库、任务队列交互，AI 代理执行渗透测试任务，并与知识图谱交互。监控组件收集遥测数据，分析组件分析 LLM 性能，安全工具执行实际的渗透测试。核心服务、知识图谱、监控、分析和安全工具是五个主要组成部分，AI 代理是核心智能部分，负责执行渗透测试任务。`docker-compose.yml` 文件用于快速部署系统。
