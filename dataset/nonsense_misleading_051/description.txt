## Edges, Branches & Convergence
- `A --> B`: User places an order, initiating the payment check.
- `B -- No --> C`: If payment is not received, the order is cancelled.
- `B -- Yes --> D`: If payment is received, the order is moved to fulfillment.
- `D --> E`: Order fulfillment leads to an inventory availability check.
- `E -- No --> F`: If inventory is not available, the user is notified of the delay.
- `F --> G`: Notifying the user of a delay leads to refunding the payment.
- `G --> A`: Refund payment loops back to placing a new order.
- `E -- Yes --> H`: If inventory is available, the order is shipped.
- `H --> I`: Shipping the order leads to updating the inventory.
- `I --> J`: Updating inventory leads to checking delivery confirmation.
- `J -- No --> H`: If delivery is not confirmed, the process loops back to shipping the order again.
- `J -- Yes --> K`: If delivery is confirmed, the order is closed.
- `K --> L`: Closing the order leads to sending a confirmation email.
- `L --> C`: Sending a confirmation email leads to cancelling the order.

## High-Density QA Ground Truth Summary
The order processing flowchart begins with a "User Places Order," which then proceeds to a "Payment Received?" check. If payment is not received ("No" branch), the order is immediately "Cancel Order." If payment is received ("Yes" branch), the process moves to "Fulfill Order," followed by an "Inventory Available?" check. If inventory is not available ("No" branch), the "Notify User of Delay" action is triggered, which then leads to "Refund Payment," looping back to "User Places Order." If inventory is available ("Yes" branch), the "Ship Order" action is taken, followed by "Update Inventory." After updating inventory, the process checks "Delivery Confirmed?". If delivery is not confirmed ("No" branch), the process loops back to "Ship Order." If delivery is confirmed ("Yes" branch), the "Close Order" action is taken, followed by "Send Confirmation Email," which then leads to "Cancel Order." The diagram contains several errors, including updating inventory before shipping, looping back to shipping if delivery is not confirmed, and cancelling the order after sending a confirmation email. The "Refund Payment" action also incorrectly loops back to the beginning, allowing the user to place a new order.
