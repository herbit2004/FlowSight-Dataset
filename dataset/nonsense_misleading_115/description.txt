## Diagram Type & Purpose
This is a flowchart diagram depicting the process of order fulfillment. It outlines the steps from when a user places an order to when the order is completed or cancelled. The diagram serves as a visual representation of the order processing workflow, including payment verification, item availability, shipping, and delivery.

## Overall Layout
The diagram has a top-down (TD) layout. It starts with the "Start: User Places Order" node at the top and flows downwards through a series of decision points and actions, ultimately leading to "Order Completed" or "Order Cancelled" nodes. The diagram contains loops and branches, indicating different paths based on conditions.

## Subgraphs / Stages
No explicit subgraphs; logically divided into 6 stages: Order Placement & Payment, Item Processing, Shipping, Delivery, Completion/Return, and Cancellation.

## Edges, Branches & Convergence
- `A --> B`: User places an order, initiating the payment verification process.
- `B -- No --> C`: If payment is not received, the order is cancelled.
- `B -- Yes --> D`: If payment is received, the items are packaged.
- `D --> E`: After packaging, the system checks for item availability.
- `E -- No --> F`: If items are not available, the payment is refunded.
- `E --> G`: If items are available, a shipping label is printed.
- `G --> H`: After printing the label, the package is shipped.
- `H --> I`: After shipping, the system checks for successful delivery.
- `I -- Yes --> J`: If delivery is successful, the order is completed.
- `I -- No --> K`: If delivery is not successful, a return label is created.
- `K --> L`: After creating a return label, a claim is filed with the carrier.
- `L --> M`: After filing a claim, the order is completed.
- `F --> A`: After refunding payment, the process loops back to the start (User Places Order).
- `J --> C`: After order completion, the order is cancelled.

## High-Density QA Ground Truth Summary
The process begins with the "Start: User Places Order" node, immediately followed by a "Payment Received?" check. If payment is not received ("No" branch), the "Order Cancelled" node is reached, terminating the process. If payment is received ("Yes" branch), the process moves to "Package Items." The next decision point is "Items Available?". If items are not available ("No" branch), "Refund Payment" is triggered, which then loops back to "Start: User Places Order," restarting the entire process. If items are available ("Yes" branch), "Shipping Label Printed" is executed, followed by "Package Shipped." The process then proceeds to "Delivery Successful?". If delivery is successful ("Yes" branch), the "Order Completed" node is reached, which counterfactually leads to "Order Cancelled." If delivery is unsuccessful ("No" branch), "Create Return Label" is executed, followed by "File Claim to Carrier," which then leads to "Order Completed." The standard practice of verifying payment authorization is represented by the "Payment Received?" node, but the subsequent flow deviates from typical order processing.
