## 图类型与用途
这是一个架构图，展示了 NestJS Monorepo 模板中客户端、服务、后台任务和数据库之间的交互关系。它描述了微服务架构中不同组件如何协同工作，以及数据如何在它们之间流动。该图在 README.md 中作为架构概览的一部分，帮助开发者理解项目的整体结构。

## 图的整体布局
图采用从左到右的布局。左侧是客户端和后台任务，中间是各种服务，右侧是数据库。数据流从客户端和服务流向数据库。

## 分组/子图/阶段说明
图中包含四个显式子图：
- **Client**：表示客户端，包括浏览器、移动应用和管理界面。
- **Services**：表示不同的服务，包括 API 服务、WebSocket 服务和管理服务。
- **Worker**：表示后台任务处理服务。
- **Database**：表示数据库，包括 MongoDB、PostgreSQL 和 MySQL。

## 节点逐项说明
- **Browser**：表示通过浏览器访问应用的用户。
- **Mobile App**：表示通过移动应用访问应用的用户。
- **Admin UI**：表示管理员使用的管理界面。
- **api-server :3001**：主要的 REST API 服务，端口号为 3001。根据 README.md 和 apps/api-server/src/main.ts，它处理 HTTP 请求，提供 Swagger 文档，并负责认证和授权。
- **websocket-service :3002**：WebSocket 服务，用于实时连接，端口号为 3002。根据 README.md 和 apps/websocket-service/src/main.ts，它处理 WebSocket 连接，提供实时事件和房间广播。
- **admin :3003**：管理服务，提供管理界面，端口号为 3003。根据 README.md 和 apps/admin/src/main.ts，它提供管理面板、Swagger 文档、用户管理和系统配置功能。
- **worker (No Port)**：后台工作服务，没有端口号，用于执行后台任务和计划任务。根据 README.md 和 apps/worker/src/main.ts，它运行在后台，执行计划任务和处理队列。
- **MongoDB**：MongoDB 数据库。
- **PostgreSQL**：PostgreSQL 数据库。
- **MySQL**：MySQL 数据库。

## 连线、分支与汇聚关系
- `Browser -> api-server :3001`：浏览器通过 HTTP/REST 协议与 API 服务进行通信。
- `Mobile App -> api-server :3001`：移动应用通过 HTTP/REST 协议与 API 服务进行通信。
- `Browser -> websocket-service :3002`：浏览器通过 WebSocket 协议与 WebSocket 服务进行通信。
- `Admin UI -> admin :3003`：管理界面通过 HTTP/REST 协议与 Admin 服务进行通信。
- `api-server :3001 -> Database`：API 服务对数据库进行读写操作。
- `websocket-service :3002 -> Database`：WebSocket 服务对数据库进行读写操作。
- `admin :3003 -> Database`：Admin 服务对数据库进行读写操作。
- `worker (No Port) -> Database`：后台工作服务对数据库进行读写操作。
- `api-server :3001 -.-> websocket-service :3002`：API 服务会触发事件，并通知 WebSocket 服务。
- `worker (No Port) -.-> api-server :3001`：后台工作服务处理完成后，会通知 API 服务。

## 仓库语境与术语解释
- **Monorepo**：指在一个代码仓库中管理多个项目。该项目采用 Monorepo 架构，将多个 NestJS 应用放在同一个仓库中。
- **Microservices Architecture**：一种软件架构模式，将应用拆分成多个小型、独立的服务。该项目采用微服务架构，每个应用都是一个独立的服务。
- **NestJS**：一个用于构建高效、可扩展的 Node.js 服务器端应用的框架。
- **API Server**：提供 REST API 接口的服务，端口为 3001，负责处理客户端的 HTTP 请求。
- **WebSocket Service**：提供 WebSocket 连接的服务，端口为 3002，用于实时通信。
- **Admin Service**：提供管理界面的服务，端口为 3003，用于管理应用。
- **Worker Service**：在后台运行的服务，没有端口，用于执行计划任务和处理队列。
- **Database Abstraction**：通过 `libs/db` 库实现数据库抽象，可以方便地切换 MongoDB、PostgreSQL 和 MySQL 数据库，无需修改代码。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个基于 NestJS 的 Monorepo 微服务架构。客户端（浏览器、移动应用、管理界面）通过 HTTP/REST 或 WebSocket 协议与 API 服务、WebSocket 服务和管理服务进行交互。API 服务和管理服务通过 HTTP/REST 协议与客户端通信，浏览器还通过 WebSocket 协议与 WebSocket 服务通信。后台工作服务在后台运行，执行计划任务。所有服务都与数据库进行读写操作，API 服务还会触发事件通知 WebSocket 服务，后台工作服务处理完成后也会通知 API 服务。该架构支持 MongoDB、PostgreSQL 和 MySQL 数据库，并提供了数据库抽象层。核心服务包括 api-server (3001), websocket-service (3002), admin (3003) 和 worker (No Port)。
