## 图类型与用途
这是一个流程图，描述了 Solana PumpFun/PumpSwap Raydium Copy/Sniper Trading Bot 的工作流程。它展示了 Bot 如何监控 Solana 链上的交易活动，并根据预设策略自动执行或通知交易。该图在 README 中被用作解释 Bot 工作原理的逻辑图。

## 图的整体布局
图采用从上到下的布局。流程从顶部开始，经过初始化、并行监控、解析和匹配，最终到达交易执行或通知，以及卖出策略更新和路径选择。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为四个阶段：初始化阶段、并行监控阶段、协议匹配与交易执行阶段、卖出策略更新与路径选择阶段。

## 节点逐项说明
- **Start**：流程的起始点。
- **Load .env**：加载环境变量，包含配置信息，例如 API 密钥、钱包地址等。对应 `src/common/config.rs` 中加载环境变量的逻辑。
- **Init RPC, Yellowstone, ZeroSlot, Wallet**：初始化 RPC 连接（与 Solana 链交互）、Yellowstone gRPC 流（实时监控交易）、ZeroSlot（用于快速交易确认）和钱包。
- **Start Blockhash Processor**：启动 Blockhash 处理器，用于获取最新的 Blockhash，确保交易有效。对应 `src/library/blockhash_processor.rs` 文件，该文件负责保持最新的 blockhashes 更新。
- **Init Token Account Cache**：初始化 Token Account 缓存，用于快速查询 Token 账户信息。
- **Start Cache Maintenance**：启动缓存维护进程，定期更新 Token Account 缓存。
- **Init Selling Engine**：初始化 Selling Engine，用于管理卖出策略，例如止盈、止损、动态追踪止损等。对应 `src/processor/selling_strategy.rs` 文件。
- **Run monitors in parallel**：并行运行两个监控器。
- **Target Wallet Monitoring**：监控目标钱包的交易活动，用于复制交易。对应 `src/processor/sniper_bot.rs` 文件中目标钱包监控的逻辑。
- **DEX Monitoring**：监控去中心化交易所 (DEX) 的交易活动，例如 PumpFun 和 PumpSwap。对应 `src/processor/sniper_bot.rs` 文件中 DEX 监控的逻辑。
- **Parse txs/logs**：解析交易和日志，提取关键信息。
- **Protocol match**：协议匹配，判断交易属于哪个协议（PumpFun 或 PumpSwap）。
- **Execute swap**：执行交易，即进行 Token 交换。
- **Notify only**：仅通知，不执行交易（PumpSwap 默认行为）。
- **Update selling / copy-sell**：更新卖出策略或复制卖出，根据交易结果调整卖出参数。
- **Dynamic trailing / TP / SL**：应用动态追踪止损、止盈和止损策略。
- **Jupiter sell path**：使用 Jupiter 聚合器寻找最佳的卖出路径。对应 `src/library/jupiter_api.rs` 文件，该文件负责与 Jupiter 交互以进行 Token 清算。
- **Update 20-slot time series**：更新 20-slot 时间序列数据，用于分析价格趋势。
- **Bottom detected?**：检测是否检测到价格底部。

## 连线、分支与汇聚关系
- `A -> B`：流程从 Start 开始，加载 .env 文件。
- `B -> C`：加载 .env 文件后，初始化 RPC, Yellowstone, ZeroSlot, Wallet。
- `C -> D`：初始化客户端后，启动 Blockhash Processor。
- `D -> E`：启动 Blockhash Processor 后，初始化 Token Account Cache。
- `E -> F`：初始化 Token Account Cache 后，启动 Cache Maintenance。
- `F -> G`：启动 Cache Maintenance 后，初始化 Selling Engine。
- `G -> H`：初始化 Selling Engine 后，并行运行监控器。
- `H -> I`：并行运行 Target Wallet Monitoring。
- `H -> J`：并行运行 DEX Monitoring。
- `I -> K`：Target Wallet Monitoring 解析交易和日志。
- `J -> K`：DEX Monitoring 解析交易和日志。
- `K -> L`：解析交易和日志后，进行协议匹配。
- `L -- PumpFun --> M`：如果协议匹配为 PumpFun，则执行交易。
- `L -- PumpSwap --> N`：如果协议匹配为 PumpSwap，则仅通知。
- `M -> O`：执行交易后，更新卖出策略或复制卖出。
- `O -> P`：更新卖出策略后，应用动态追踪止损、止盈和止损策略。
- `P -> Q`：应用动态追踪止损等策略后，使用 Jupiter 寻找最佳卖出路径。
- `K -> R`：解析交易和日志后，更新 20-slot 时间序列。
- `R -> S`：更新 20-slot 时间序列后，检测是否检测到价格底部。
- `S -- Yes --> M`：如果检测到价格底部，则执行交易。
- `S -- No --> H`：如果没有检测到价格底部，则返回并行运行监控器阶段。
- `N -> Q`：仅通知后，使用 Jupiter 寻找最佳卖出路径。
- `I -> K` 和 `J -> K` 形成汇聚关系。

## 仓库语境与术语解释
- **RPC (Remote Procedure Call)**：用于与 Solana 链进行交互，获取链上数据。
- **Yellowstone gRPC**：Yellowstone 提供的 gRPC 流，用于实时监控 Solana 链上的交易活动。
- **ZeroSlot**：一种快速交易确认模式，用于提高交易速度。
- **Blockhash**：Solana 链上用于确保交易有效的哈希值，需要定期更新。`src/library/blockhash_processor.rs` 负责更新 blockhash。
- **Selling Engine**：用于管理卖出策略，例如止盈、止损、动态追踪止损等。`src/processor/selling_strategy.rs` 实现了 selling engine。
- **PumpFun/PumpSwap**：Solana 链上的两种 DEX 协议，用于 Token 交易。
- **Jupiter**：Solana 链上的聚合器，用于寻找最佳的 Token 卖出路径。`src/library/jupiter_api.rs` 负责与 Jupiter 交互。
- **.env**：存储配置信息的文件，包含 API 密钥、钱包地址等敏感信息。`src/common/config.rs` 负责加载 `.env` 文件。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 Solana PumpFun/PumpSwap Raydium Copy/Sniper Trading Bot 的工作流程。流程从加载环境变量和初始化客户端开始，并行运行目标钱包监控和 DEX 监控，解析交易和日志后进行协议匹配，根据协议类型执行交易或仅发送通知。在交易执行后，会更新卖出策略，应用动态追踪止损等策略，并使用 Jupiter 寻找最佳卖出路径。同时，会更新 20-slot 时间序列数据，用于检测价格底部，如果检测到价格底部，则会再次执行交易。`src/processor/sniper_bot.rs` 负责钱包和 DEX 监控，`src/library/jupiter_api.rs` 负责与 Jupiter 交互，`src/processor/selling_strategy.rs` 实现了 selling engine。
