## Edges, Branches & Convergence
- `User prompt --> Rate limit check`: The user's input is checked against the rate limit.
- `Rate limit check -- ok --> START`: If the rate limit is not exceeded, the process starts.
- `Rate limit check -- 429 --> Backoff and retry`: If the rate limit is exceeded, the process backs off and retries.
- `START --> PLAN create plan`: The process starts by creating a plan.
- `PLAN create plan --> DECIDE next action`: The plan is used to decide the next action.
- `DECIDE next action --> ACT bind tool emit call`: Based on the decision, a tool is selected and a call is emitted. (Multiple edges: search, fetch, kb_search, calculate, write_file, draft_email)
- `ACT bind tool emit call --> ToolNode executes call`: The tool call is executed.
- `ToolNode executes call --> REFLECT briefing or next`: The results of the tool call are reflected upon.
- `REFLECT briefing or next -- done --> FINALIZE result`: If the process is complete, the result is finalized.
- `REFLECT briefing or next -- not done --> DECIDE next action`: If the process is not complete, the next action is decided.
- `PLAN -. use kb hits .-> Chroma vector KB`: The plan uses knowledge base hits from the Chroma vector KB.
- `ToolNode executes call --> web search`: The tool node executes a web search. (Multiple edges: query, url, semantic, ingest, expr, path content, to subject body)
- `web search --> web fetch`: Web search results are used to fetch web content.
- `web fetch --> PLAN create plan`: Fetched web content is used to create a plan.
- `web fetch --> Citations store`: Fetched web content is stored in the citations store.
- `FINALIZE result --> SQLite messages`: The finalized result is saved to SQLite messages.
- `Feedback API --> SQLite messages`: Feedback is saved to SQLite messages.

## High-Density QA Ground Truth Summary
The process begins with a `User prompt` that undergoes a `Rate limit check`. If the rate limit is exceeded (429), the system enters a `Backoff and retry` state; otherwise, the process proceeds to `START`. From `START`, the system `PLAN create plan`, which then feeds into `DECIDE next action`. This decision node branches based on several criteria: `search`, `fetch`, `kb_search`, `calculate`, `write_file`, and `draft_email`, each triggering an `ACT bind tool emit call`. The selected tool call is then executed by `ToolNode executes call`. The `ToolNode executes call` node then branches to different tools in the `Tool and API Layer` based on the type of call: `web search`, `web fetch`, `kb search`, `kb add`, `calculator`, `file write`, and `emailer`. The results of the tool execution are then passed to `REFLECT briefing or next`. This reflection node determines whether the process is `done`, leading to `FINALIZE result`, or `not done`, looping back to `DECIDE next action`. The `FINALIZE result` node represents the end of the process. The system uses `Chroma vector KB` for knowledge base searches, with `web fetch` populating the `Citations store`. The `Experience Layer FastAPI SSE` handles user interaction and streams tokens using Server-Sent Events.
