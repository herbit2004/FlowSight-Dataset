## 图类型与用途
该图是一个流程图，描述了用户请求的处理流程。该流程涉及数据库、缓存、API网关、认证、鉴权和支付等环节。图中的流程包含分支和循环。

## 图的整体布局
该图的布局方向是从上到下。整体流程从用户请求开始，经过一系列处理后，最终返回结果或重试支付，或登出，或回到用户请求。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. 缓存检查阶段：检查缓存是否命中。
2. 用户认证阶段：检查用户是否登出，进行认证。
3. 支付阶段：进行鉴权，检查支付是否成功。

## 节点逐项说明
- **A**：用户请求的起始节点。
- **B**：数据库节点。
- **C**：判断缓存是否命中的节点。
- **D**：API 网关节点。
- **E**：写缓存节点。
- **F**：判断用户是否登出的节点。
- **G**：登出节点。
- **H**：认证节点。
- **I**：消息队列节点。
- **J**：鉴权节点。
- **K**：判断支付是否成功的节点。
- **L**：返回结果节点。
- **M**：重试支付节点。

## 连线、分支与汇聚关系
- A -> B：用户请求发送到数据库。
- B -> C：数据库将数据发送到缓存命中判断节点。
- C -- Yes --> D：缓存命中，数据发送到 API 网关。
- C -- No --> E：缓存未命中，数据发送到写缓存节点。
- E -> B：写缓存后，数据返回到数据库。
- D -> F：API 网关将数据发送到用户是否登出判断节点。
- F -- Yes --> G：用户已登出，进入登出流程。
- F -- No --> H：用户未登出，进行认证。
- H -> I：认证后，数据发送到消息队列。
- I -> J：消息队列将数据发送到鉴权节点。
- J -> K：鉴权后，进入支付是否成功判断节点。
- K -- Yes --> L：支付成功，返回结果。
- K -- No --> M：支付失败，进入重试支付流程。
- M -> J：重试支付流程返回到鉴权节点。
- L -> A：返回结果后，流程回到用户请求。
- G -> A：登出后，流程回到用户请求。

## 仓库语境与术语解释
- **用户请求**：用户发起的对系统的访问或操作。
- **数据库**：用于存储和管理数据的系统。
- **缓存**：用于临时存储数据，以提高访问速度。
- **API 网关**：系统的入口，负责请求路由、认证和授权等功能。
- **认证**：验证用户身份的过程。
- **鉴权**：验证用户是否有权限访问特定资源的过程。
- **消息队列**：用于在不同系统或组件之间传递消息的中间件。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先到达数据库，然后判断缓存是否命中。如果缓存命中，则经过 API 网关，判断用户是否登出，如果登出则直接返回用户请求，否则进行认证，经过消息队列和鉴权，判断支付是否成功，成功则返回结果并回到用户请求，否则重试支付，直到支付成功或达到重试次数上限。如果缓存未命中，则写入缓存后回到数据库。
