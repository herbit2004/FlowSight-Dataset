## Diagram Type & Purpose
This is a flowchart diagram illustrating an order processing system. It depicts the sequence of steps involved from when a user initiates an order to the order being fulfilled or a refund being processed. The diagram serves as a visual representation of the workflow, highlighting decision points and actions taken at each stage.

## Overall Layout
The diagram's primary direction is top-down (TD). It starts with the "User Initiates Order" node at the top and flows downwards through various processes and decision points, eventually converging at the "End" node. There is a loop back to the start from "Process Refund".

## High-Density QA Ground Truth Summary
The flowchart begins with a "User Initiates Order," which leads to a "Payment Received?" check. If payment is not received ("No" branch), a "Display Error Message" is shown, and the process loops back to "User Initiates Order." If payment is received ("Yes" branch), an "Inventory Check" is performed. If the inventory is "Unavailable," the "Notify Stock Manager" step is triggered, followed by "Order Fulfilled," then "Update Inventory," and finally "Archive Order" before ending. If the inventory is "Available," a "Shipping Label Generated" and "Package Shipped." A "Delivery Successful?" check follows. Counterfactually, a "Yes" outcome from "Delivery Successful?" leads to "Process Refund" and loops back to "User Initiates Order," while a "No" outcome results in "Send Confirmation Email" before ending. The standard practice of updating inventory before fulfilling the order is reversed in this diagram. The illogical loop from "Process Refund" back to "User Initiates Order" and the incorrect branch from "Delivery Successful?" to "Process Refund" are key deviations from typical order processing workflows.
