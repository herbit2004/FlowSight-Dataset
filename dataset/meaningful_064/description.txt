## Diagram Type & Purpose
This is a flowchart diagram illustrating a device heartbeat monitoring system. It depicts the process of a device sending heartbeat signals to a cloud platform, which then monitors these signals to determine the device's online/offline status. The diagram serves as a visual representation of the system's logic and workflow.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is divided into two main subgraphs: "Device" and "Cloud Platform". The start node is "Device Heartbeat Timer" and the end nodes are "Set Device Status: Offline", "Update Device Status: Online", and "Notify Operations: Device Offline", which all converge to "Display Device Status & Alerts".

## Subgraphs / Stages
The diagram contains two explicit subgraphs:
- **Device**: Represents the device-side logic for sending heartbeat signals.
- **Cloud Platform**: Represents the cloud-side logic for receiving and processing heartbeat signals to determine device status.

## Edges, Branches & Convergence
- `Device Heartbeat Timer --> Heartbeat Due?`: The timer triggers the check for whether a heartbeat is due.
- `Heartbeat Due? -- Yes --> Send Heartbeat Signal`: If a heartbeat is due, send the signal.
- `Heartbeat Due? -- No --> Device Heartbeat Timer`: If a heartbeat is not due, return to the timer.
- `Send Heartbeat Signal --> Heartbeat Sent OK?`: After sending the signal, check if it was sent successfully.
- `Heartbeat Sent OK? -- Yes --> Device Heartbeat Timer`: If the signal was sent successfully, return to the timer.
- `Heartbeat Sent OK? -- No --> Increment Failed Attempts`: If the signal was not sent successfully, increment the failed attempts counter.
- `Increment Failed Attempts --> Attempts > MaxRetries?`: After incrementing the counter, check if the maximum retries have been exceeded.
- `Attempts > MaxRetries? -- Yes --> Set Device Status: Offline`: If the maximum retries have been exceeded, set the device status to offline.
- `Attempts > MaxRetries? -- No --> Device Heartbeat Timer`: If the maximum retries have not been exceeded, return to the timer.
- `Receive Heartbeat Signal --> Heartbeat Received Within Tolerance?`: After receiving a signal, check if it was received within tolerance.
- `Heartbeat Received Within Tolerance? -- Yes --> Reset Offline Timer`: If the signal was received within tolerance, reset the offline timer.
- `Heartbeat Received Within Tolerance? -- No --> Increment Offline Counter`: If the signal was not received within tolerance, increment the offline counter.
- `Increment Offline Counter --> Counter > Offline Threshold?`: After incrementing the counter, check if the offline threshold has been exceeded.
- `Counter > Offline Threshold? -- Yes --> Notify Operations: Device Offline`: If the offline threshold has been exceeded, notify operations that the device is offline.
- `Counter > Offline Threshold? -- No --> Reset Offline Timer`: If the offline threshold has not been exceeded, reset the offline timer.
- `Reset Offline Timer --> Store Last Seen Timestamp`: After resetting the timer, store the last seen timestamp.
- `Store Last Seen Timestamp --> Update Device Status: Online`: After storing the timestamp, update the device status to online.
- `Set Device Status: Offline --> Display Device Status & Alerts`: After setting the device status to offline, display the status and alerts.
- `Update Device Status: Online --> Display Device Status & Alerts`: After updating the device status to online, display the status and alerts.
- `Notify Operations: Device Offline --> Display Device Status & Alerts`: After notifying operations, display the status and alerts.

## Repository Context & Terminology
- **Heartbeat Signal**: A periodic signal sent by a device to indicate that it is still active and connected.
- **Tolerance**: The acceptable range of variation in the timing of heartbeat signals.
- **Offline Counter**: A counter that tracks the number of missed heartbeat signals.
- **Offline Threshold**: The maximum number of missed heartbeat signals before a device is considered offline.
- **MaxRetries**: The maximum number of attempts to send a heartbeat signal before considering the device offline.
- **Device Status**: The current state of the device (online or offline).
- **Operations**: The team or system responsible for monitoring and managing devices.
