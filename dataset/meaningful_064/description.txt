## 图类型与用途
该图是一个流程图，描述了设备端与心跳服务之间进行心跳检测的流程。该流程用于检测设备是否在线，如果设备长时间没有发送心跳包，则认为设备离线。

## 图的整体布局
该图采用从上到下的布局，分为“设备端”和“心跳服务”两个子图。流程从设备启动开始，最终到业务系统处理离线事件结束。

## 分组/子图/阶段说明
图中包含两个子图：
- **设备端**：描述设备端发送心跳包并处理心跳失败的流程。
- **心跳服务**：描述心跳服务接收心跳包并判断设备是否离线的流程。

## 节点逐项说明
- **A[设备启动]**：设备启动后，开始心跳检测流程。
- **B{心跳间隔到达?}**：判断心跳间隔是否到达，到达则构造心跳包。
- **C[构造心跳包]**：构造心跳包，准备发送。
- **D[发送心跳包至心跳服务]**：将心跳包发送至心跳服务。
- **E{心跳成功?}**：判断心跳是否成功。
- **F[重试心跳]**：如果心跳失败，则重试心跳。
- **G{重试次数超限?}**：判断重试次数是否超过限制。
- **H[进入离线状态]**：如果重试次数超过限制，则进入离线状态。
- **I(停止心跳)**：停止心跳流程。
- **J[接收心跳包]**：心跳服务接收设备端发送的心跳包。
- **K[更新设备最后活跃时间]**：更新设备最后活跃时间。
- **L{最后活跃时间 > 阈值?}**：判断设备最后活跃时间是否超过阈值。
- **M[标记设备为离线]**：如果设备最后活跃时间超过阈值，则标记设备为离线。
- **N(等待下一个心跳包)**：等待下一个心跳包。
- **O[上报设备离线事件]**：上报设备离线事件。
- **P[业务系统处理离线事件]**：业务系统处理设备离线事件。

## 连线、分支与汇聚关系
- A -> B：设备启动后，进入心跳间隔判断。
- B -- 是 --> C：心跳间隔到达，构造心跳包。
- B -- 否 --> B：心跳间隔未到达，继续等待。
- C -> D：构造心跳包后，发送心跳包至心跳服务。
- D -> E：发送心跳包后，判断心跳是否成功。
- E -- 是 --> B：心跳成功，回到心跳间隔判断。
- E -- 否 --> F：心跳失败，重试心跳。
- F -> G：重试心跳后，判断重试次数是否超限。
- G -- 是 --> H：重试次数超限，进入离线状态。
- G -- 否 --> E：重试次数未超限，回到心跳成功判断。
- H -> I：进入离线状态后，停止心跳。
- I -> O：停止心跳后，上报设备离线事件。
- J -> K：接收心跳包后，更新设备最后活跃时间。
- K -> L：更新最后活跃时间后，判断最后活跃时间是否大于阈值。
- L -- 是 --> M：最后活跃时间大于阈值，标记设备为离线。
- L -- 否 --> N：最后活跃时间小于阈值，等待下一个心跳包。
- N -> J：等待下一个心跳包，回到接收心跳包。
- M -> O：标记设备为离线后，上报设备离线事件。
- O -> P：上报设备离线事件后，业务系统处理离线事件。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **心跳**：设备定时向服务器发送的信号，用于表明设备在线。
- **心跳间隔**：设备发送心跳包的时间间隔。
- **最后活跃时间**：设备最后一次发送心跳包的时间。
- **阈值**：判断设备是否离线的最后活跃时间的最大值。
- **离线状态**：设备与服务器断开连接的状态。
- **离线事件**：设备进入离线状态的事件。

## 可作为 QA Ground Truth 的高信息密度摘要
设备启动后，进入心跳检测流程，判断心跳间隔是否到达。如果到达，则构造心跳包并发送至心跳服务。心跳服务接收心跳包并更新设备最后活跃时间，判断最后活跃时间是否超过阈值。如果超过阈值，则标记设备为离线并上报离线事件，最终由业务系统处理离线事件。如果心跳失败，设备会重试心跳，如果重试次数超过限制，则进入离线状态并停止心跳。
