## 图类型与用途
这是一个流程图，描述了将 COBOL 代码迁移到 Java 或 C# 的架构流程。它展示了从 COBOL 文件输入，经过处理流水线，存储到混合存储，最终输出 Java/C# 代码和可视化门户的完整过程。该图在仓库中的作用是概括代码迁移的主流程。

## 图的整体布局
图整体采用从上到下的布局。顶部是输入节点，中间是处理流水线和混合存储阶段，底部是输出节点。数据流从 COBOL 文件开始，经过各个处理阶段，最终输出到 Java/C# 代码和 Web 门户。

## 分组/子图/阶段说明
图中包含四个显式子图：
- **INPUT**：表示 COBOL 代码迁移的输入部分。
- **PROCESS**：表示代码迁移的处理流水线，包含多个 AI Agents。
- **STORAGE**：表示混合存储，用于存储迁移过程中的数据和结果。
- **OUTPUT**：表示代码迁移的输出结果，包括生成的代码和 Web 门户。

## 节点逐项说明
- **COBOL Files source/*.cbl, *.cpy**：包含 COBOL 源代码文件（`.cbl`）和拷贝文件（`.cpy`），作为迁移过程的初始输入。
- **Regex / Syntax Parsing (Deep SQL/Variable Extraction)**：使用正则表达式和语法分析技术，从 COBOL 代码中提取深层的 SQL 语句和变量信息。
- **AI Agents (MS Agent Framework)**：核心处理组件，使用 Microsoft Agent Framework，包含多个 AI Agent。
- **CobolAnalyzerAgent**：用于分析 COBOL 代码，提取程序结构、变量、段落和逻辑流等信息。
- **BusinessLogicExtractor**：用于提取 COBOL 代码中的业务逻辑。
- **Java/C# Converter**：将 COBOL 代码转换为 Java 或 C# 代码。
- **DependencyMapper**：用于分析 COBOL 代码的依赖关系。
- **SQLite Data/migration.db**：一个 SQLite 数据库，用于存储运行元数据、文件内容、原始 AI 分析结果和生成的代码。
- **Neo4j bolt://localhost:7687**：一个 Neo4j 图数据库，用于存储依赖关系、关系图和影响分析数据。
- **Java/C# Code output/java or output/csharp**：生成的 Java 或 C# 代码，位于 `output/java` 或 `output/csharp` 目录下。
- **Web Portal & MCP Server localhost:5028**：一个 Web 门户，运行在 `localhost:5028`，用于可视化迁移进度、依赖关系图，并提供 AI 驱动的问答功能。

## 连线、分支与汇聚关系
- `COBOL Files -> Regex / Syntax Parsing`：COBOL 文件首先经过正则表达式和语法分析进行信息提取。
- `Regex / Syntax Parsing -> AI Agents`：语法分析的输出作为 AI Agents 的输入。
- `AI Agents -> CobolAnalyzerAgent`：AI Agents 将任务分发给 CobolAnalyzerAgent。
- `AI Agents -> BusinessLogicExtractor`：AI Agents 将任务分发给 BusinessLogicExtractor。
- `AI Agents -> Java/C# Converter`：AI Agents 将任务分发给 Java/C# Converter。
- `AI Agents -> DependencyMapper`：AI Agents 将任务分发给 DependencyMapper。
- `CobolAnalyzerAgent -> SQLite`：CobolAnalyzerAgent 的结果存储在 SQLite 数据库中。
- `BusinessLogicExtractor -> SQLite`：BusinessLogicExtractor 的结果存储在 SQLite 数据库中。
- `Java/C# Converter -> SQLite`：Java/C# Converter 的结果存储在 SQLite 数据库中。
- `Java/C# Converter -> Java/C# Code`：Java/C# Converter 将生成的代码输出到代码目录。
- `DependencyMapper -> Neo4j`：DependencyMapper 的结果存储在 Neo4j 图数据库中。
- `SQLite -> Web Portal & MCP Server`：SQLite 中的数据被用于构建 Web 门户。
- `Neo4j -> Web Portal & MCP Server`：Neo4j 中的数据被用于构建 Web 门户。

## 仓库语境与术语解释
- **COBOL Files**：指包含 COBOL 源代码的文件，通常以 `.cbl` 和 `.cpy` 为扩展名。
- **Microsoft Agent Framework**：该项目使用 Microsoft Agent Framework (`Microsoft.Agents.AI.*`)，而不是 Semantic Kernel。README 中提到，Agent Framework 提供了更简单的 `IChatClient` 抽象，并原生支持 Responses API 和 Chat Completions API。
- **Responses API / Chat Completions API**：项目支持两种 Azure OpenAI API 类型。Responses API 用于代码生成（agents），Chat Completions API 用于报告和门户聊天。
- **SQLite**：一个轻量级的数据库，用于存储迁移过程中的元数据、文件内容、AI 分析结果和生成的代码。根据 `Config/appsettings.json`，数据库文件位于 `Data/migration.db`。
- **Neo4j**：一个图数据库，用于存储 COBOL 代码的依赖关系、关系图和影响分析数据。根据 `Config/appsettings.json`，Neo4j 的连接地址为 `bolt://localhost:7687`。
- **Web Portal & MCP Server**：一个 Web 门户，用于可视化迁移进度、依赖关系图，并提供 AI 驱动的问答功能。README 中提到，该门户运行在 `localhost:5028`。
- **doctor.sh**：一个 shell 脚本，用于运行代码迁移流程。README 中提到，应该始终使用 `./doctor.sh run` 来运行迁移，而不是直接使用 `dotnet run`。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 COBOL 代码迁移到 Java/C# 的整体架构流程。流程从 COBOL 文件输入开始，经过 Regex 语法分析后，由多个 AI Agents（CobolAnalyzerAgent、BusinessLogicExtractor、Java/C# Converter、DependencyMapper）进行处理。处理结果存储在 SQLite 和 Neo4j 数据库中，最终生成 Java/C# 代码，并通过 Web Portal & MCP Server 提供可视化界面。其中，AI Agents 和混合存储是核心中间环节，Microsoft Agent Framework 和 `doctor.sh` 脚本是重要的仓库语境锚点。
