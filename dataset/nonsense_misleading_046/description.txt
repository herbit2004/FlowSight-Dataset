## Diagram Type & Purpose
This is a flowchart diagram illustrating the order processing workflow for an e-commerce system. It depicts the steps involved from when a user places an order to when a refund is processed, including inventory management, shipping, and delivery confirmation. The diagram serves as a visual representation of the order fulfillment process.

## Overall Layout
The diagram's layout is top-down (TD). The flow starts with "User Places Order" at the top and progresses downwards through decision points and actions. The end nodes are "Send Order Cancellation", "Investigate Delivery Issue", and "Process Refund", with "Process Refund" looping back to "User Places Order".

## Subgraphs / Stages
No explicit subgraphs; logically divided into 6 stages: Order Placement & Payment, Inventory Check, Order Fulfillment, Shipping, Delivery Confirmation, and Issue Resolution/Refund.

## Edges, Branches & Convergence
- `A --> B`: The user placing an order leads to a payment check.
- `B -- No --> C`: If payment is not received, the order is canceled.
- `B -- Yes --> D`: If payment is received, the inventory is updated.
- `D --> E`: Updating inventory leads to checking if inventory is sufficient.
- `E -- No --> F`: If inventory is insufficient, the order is backordered.
- `E -- Yes --> G`: If inventory is sufficient, the order is packaged.
- `F --> D`: Backordering the order leads back to updating inventory.
- `G --> H`: Packaging the order leads to generating a shipping label.
- `H --> I`: Generating a shipping label leads to shipping the order.
- `I --> J`: Shipping the order leads to checking for delivery confirmation.
- `J -- No --> K`: If delivery confirmation is not received, the delivery issue is investigated.
- `J -- Yes --> L`: If delivery confirmation is received, a refund is processed.
- `L --> A`: Processing a refund leads back to the user placing a new order.
- `K --> I`: Investigating the delivery issue leads back to the order being shipped.
- `C --> L`: Sending order cancellation leads to processing a refund.

## Repository Context & Terminology
- **User Places Order**: Standard meaning is a customer initiating a purchase. In this diagram, it's the starting point of the workflow.
- **Payment Received?**: Standard meaning is verifying successful payment. In this diagram, it's a decision point determining whether to proceed with the order.
- **Update Inventory**: Standard meaning is adjusting stock levels. In this diagram, it's an action performed after payment is received, and also after backordering.
- **Inventory Sufficient?**: Standard meaning is checking if enough stock is available. In this diagram, it's a decision point determining whether to package the order or backorder it.
- **Order Backordered**: Standard meaning is placing an order on hold due to insufficient stock. In this diagram, it leads back to updating inventory, which is illogical.
- **Package Order**: Standard meaning is preparing the order for shipment. In this diagram, it follows a check for sufficient inventory.
- **Delivery Confirmation Received?**: Standard meaning is verifying that the customer received the order. In this diagram, it determines whether to investigate delivery issues or process a refund.
- **Process Refund**: Standard meaning is returning money to the customer. In this diagram, it loops back to the user placing a new order, which is unusual.
