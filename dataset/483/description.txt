## 图类型与用途
这是一个架构图，用于展示 `zeromd` 如何在不同设备之间同步 Obsidian vault 的数据。它通过 iCloud 实现 macOS 和 iOS 设备的快速同步，并通过 Git/GitHub 实现更频繁的同步，同时支持 Windows 设备的可选同步。该图在 README 中用于概括 `zeromd` 的核心架构。

## 图的整体布局
图采用从左到右的布局，展示了 iCloud 和 Git 两种同步方式。左侧是 iCloud 同步，中间是 Git 同步，右侧是可选的 Windows 设备。

## 分组/子图/阶段说明
- **icloud ("☁️ iCloud — seconds") 子图**：代表使用 iCloud 进行同步的部分，同步频率为秒级。
- **git ("🍀 Git — every 5 min") 子图**：代表使用 Git/GitHub 进行同步的部分，同步频率为每 5 分钟。

## 节点逐项说明
- **iPhone ("📱<br/>iPhone")**：代表 iPhone 设备，通过 iCloud 与 macOS 设备同步 Obsidian vault。
- **Mac ("💻<br/>macOS")**：代表 macOS 设备，通过 iCloud 与 iPhone 设备同步，并通过 Git/GitHub 进行备份和版本控制。
- **GitHub ("🍀<br/>GitHub")**：代表 GitHub 仓库，用于存储 Obsidian vault 的 Git 仓库，实现版本控制和备份。
- **Windows ("🖥️<br/>Windows")**：代表 Windows 设备，可以通过 Git 从 GitHub 仓库拉取 Obsidian vault 的数据，是可选的同步方式。

## 连线、分支与汇聚关系
- `iPhone <--> Mac`：iPhone 和 Mac 之间通过 iCloud 进行双向同步。
- `Mac <--> GitHub`：Mac 和 GitHub 之间通过 Git 进行双向同步。
- `GitHub -.-> Windows`：GitHub 和 Windows 之间是可选的单向同步，Windows 可以从 GitHub 拉取更改。

## 仓库语境与术语解释
- **iCloud**：苹果提供的云同步服务，用于在 macOS 和 iOS 设备之间快速同步 Obsidian vault。根据 README，vault 存储在 `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/<vault>/`。
- **Git/GitHub**：Git 是一种版本控制系统，GitHub 是一个基于 Git 的代码托管平台。`zeromd` 使用 Git/GitHub 进行 Obsidian vault 的版本控制和备份。
- **Obsidian**：一个本地优先的知识库应用，使用 Markdown 文件存储数据。`zeromd` 旨在同步 Obsidian vault 在不同设备上的数据。
- **sync.sh**：`zeromd` 的同步脚本，负责将 macOS 上的 Obsidian vault 的变更同步到 Git 远程仓库。该脚本由 launchd 定时执行，具体配置见 `com.zeromd.sync.plist`。
- **com.zeromd.sync.plist**：launchd 的配置文件，用于定时执行 `sync.sh` 脚本。根据该文件，同步间隔默认为 300 秒（5 分钟）。
- **install.sh**：安装脚本，用于设置 `zeromd` 的运行环境。该脚本实际上会调用 `setup.sh` 完成安装过程。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 `zeromd` 如何同步 Obsidian vault 在不同设备上的数据。iPhone 和 Mac 通过 iCloud 进行秒级同步，Mac 通过 Git 定时（每 5 分钟）将数据同步到 GitHub，Windows 设备可以选择从 GitHub 拉取数据。核心流程是“iCloud 实现 macOS/iOS 快速同步，Git/GitHub 实现跨平台备份和版本控制”，其中 `sync.sh` 脚本和 `com.zeromd.sync.plist` 文件是实现 Git 同步的关键组件。
