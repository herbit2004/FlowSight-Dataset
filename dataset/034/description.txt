## 图类型与用途
这是一个流程图，描述了 NioPD 系统中产品经理与 Nio（虚拟产品负责人）以及子代理之间的交互流程。该图展示了从产品经理提出想法或问题开始，到任务被执行并交付的过程，以及如何根据任务的重复性来动态创建新的子代理。

## 图的整体布局
图整体采用从上到下的布局，从产品经理提出想法开始，经过 Nio 的评估和任务分配，最终到任务执行和交付。图中存在一个“Direct Command”子图，表示产品经理可以绕过 Nio 直接与子代理交互。

## 分组/子图/阶段说明
图中包含一个名为 "Direct Command" 的子图，表示产品经理可以直接委派任务给子代理，绕过 Nio。
此外，逻辑上可分为三个阶段：
1. **需求提出与评估阶段**：产品经理提出想法，Nio 评估任务性质。
2. **任务执行阶段**：任务被委派给子代理或由 Nio 自己执行。
3. **子代理动态创建阶段**：Nio 检测重复性任务，并提议创建新的子代理。

## 节点逐项说明
- **A (Product Manager (User) has new idea/problem)**：产品经理，作为系统的用户，提出新的想法或问题。根据 README，产品经理是组织的领导者和决策者，负责审查和批准所有交付物。
- **B (Nio - Virtual Head of Product)**：Nio，虚拟产品负责人，负责接收产品经理的需求，评估任务性质，并协调子代理的工作。根据 README 和 `core/agents/niopd/nio.md`，Nio 的核心职责是通过苏格拉底式提问和指导，帮助产品经理理清思路，而不是直接提供答案。
- **C (Is there a suitable Sub-agent?)**：判断是否存在合适的子代理来处理当前任务的决策节点。
- **D (Delegates task to Sub-agent)**：将任务委派给合适的子代理。
- **E (Sub-agent executes single task)**：子代理执行单个任务。根据 README，子代理是特定领域的专家，负责高效地完成分配给他们的单个任务。
- **F (Nio executes task itself)**：如果没有合适的子代理，Nio 自己执行任务。
- **G (Deliverable)**：任务的交付物，例如报告、分析结果等。
- **H (Detects high-frequency repetitive tasks)**：检测到高频重复性任务。
- **I (Proposes creating new expert to PM)**：向产品经理提议创建新的专家（子代理）。
- **J (PM approves creation?)**：产品经理是否批准创建新的子代理的决策节点。
- **K (Creates new Sub-agent capability definition)**：创建新的子代理能力定义。
- **L (Maintains current structure)**：维持当前的组织结构，不创建新的子代理。
- **M (New Sub-agent joins organization)**：新的子代理加入组织。

## 连线、分支与汇聚关系
- `A -> B`：产品经理发起与 Nio 的联系，阐明需求和目标。
- `B <--> A`：Nio 与产品经理进行引导式对话，以明确上下文和目标。
- `B -> C`：Nio 评估任务的性质，判断是否存在合适的子代理。
- `C -- Yes --> D`：如果存在合适的子代理，Nio 将任务委派给子代理。
- `D -> E`：子代理执行单个任务。
- `C -- No --> F`：如果不存在合适的子代理，Nio 自己执行任务。
- `E -> G`：子代理完成任务后，生成交付物。
- `F -> G`：Nio 完成任务后，生成交付物。
- `G -> A`：交付物返回给产品经理进行审查。
- `A -.-> E`：产品经理绕过 Nio，直接将任务委派给子代理（Direct Command）。
- `B -> H`：Nio 检测高频重复性任务。
- `H -> I`：Nio 向产品经理提议创建新的专家。
- `I -> J`：产品经理决定是否批准创建新的子代理。
- `J -- Yes --> K`：如果产品经理批准创建，则创建新的子代理能力定义。
- `J -- No --> L`：如果产品经理不批准创建，则维持当前的组织结构。
- `K -> M`：创建新的子代理能力定义后，新的子代理加入组织。
- `M -> C`：新的子代理加入组织后，可以被 Nio 委派任务。
- `A -> I`：产品经理主动请求创建新的专家。

## 仓库语境与术语解释
- **NioPD (Nio Product Director)**：是一个 AI 驱动的下一代产品管理工具包，旨在为产品经理提供一个虚拟产品专家团队。
- **Nio**：是虚拟产品负责人，负责接收产品经理的需求，评估任务性质，并协调子代理的工作。`core/agents/niopd/nio.md` 中定义了 Nio 的角色和职责。
- **Sub-agent**：是特定领域的专家，负责高效地完成分配给他们的单个任务。`core/agents/README.md` 中列出了可用的子代理，例如 `competitor-analyzer`、`data-analyst` 等。
- **Direct Command**：指产品经理可以绕过 Nio，直接将任务委派给子代理。
- **Initiative**：根据 `COMMANDS.md`，initiative 是一个高层次的产品战略。
- **PRD (Product Requirements Document)**：根据 `COMMANDS.md`，PRD 是产品需求文档。
- **niopd-workspace/**：根据 README，这是 NioPD 的工作空间，用于存储所有数据文件，例如 initiatives、PRDs、reports 等。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 NioPD 系统中产品经理与 Nio 之间的交互流程。产品经理提出想法或问题，Nio 评估任务性质并委派给合适的子代理或自己执行。产品经理也可以绕过 Nio 直接委派任务给子代理。Nio 还会检测高频重复性任务，并提议创建新的子代理。整个流程从产品经理提出想法开始，到任务被执行并交付结束，其中 Nio 的任务评估和子代理的动态创建是关键环节。`COMMANDS.md` 和 `AGENTS.md` 文件提供了关于 NioPD 命令和代理的详细信息。
