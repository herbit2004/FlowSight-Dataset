## High-Density QA Ground Truth Summary
The architecture begins with a User initiating a request, which is first intercepted by the Nginx Router acting as an ingress point. The Nginx Router then forwards the request to the OAuth2 Proxy for authentication. If the user is not authenticated, the OAuth2 Proxy redirects them to an External Identity Provider. Upon successful authentication, the External Identity Provider redirects the user back to the OAuth2 Proxy, which then forwards the authenticated request to the High Performance Rust Web Server. The Rust Web Server orchestrates the core logic, interacting with the High Performance RAG Engine for information retrieval, the LLM Provider (such as Ollama, OpenAI, or Anthropic) for generating responses, and the Postgres Relational DB & PgVector for data storage and retrieval. The RAG Engine further interacts with the Rust Document Engine for document processing and indexing, and queries the Postgres database for relevant information. The LLM Provider may also access data stored in S3-Compatible Object Storage. The system is deployed on Kubernetes, potentially using EKS, AKS, GKE, or k3s distributions, leveraging PgVector for efficient vector-based similarity searches within the Postgres database to enhance the RAG process.
