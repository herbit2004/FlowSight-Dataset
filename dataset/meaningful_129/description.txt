## 图类型与用途
该图是一个流程图，用于描述用户参与活动的流程。它展示了从用户行为触发到完成活动参与的各个步骤，以及中间的条件判断和分支。该图可以用于理解和优化活动参与流程。

## 图的整体布局
该图采用从上到下的布局方式。流程从“用户行为触发”子图开始，经过一系列判断和处理，最终到达“完成流程”。整体上呈现一个线性的流程，带有条件分支。

## 分组/子图/阶段说明
图中包含一个名为“用户行为触发”的子图，该子图描述了活动触发的起始阶段。后续流程可以分为：
1. **活动资格检查阶段**：包括判断是否满足活动触发条件，以及检查用户是否已参与活动。
2. **活动参与限制阶段**：判断是否允许重复参与。
3. **活动权益生成阶段**：包括应用活动规则、生成活动权益和记录活动参与日志。

## 节点逐项说明
- **A[用户行为发生: 浏览商品/点击广告等]**: 用户执行特定行为，例如浏览商品或点击广告，触发活动流程。
- **B{是否满足活动触发条件?}**: 判断用户行为是否满足活动设定的触发条件。
- **C[检查用户是否已参与活动]**: 检查用户是否已经参与过该活动。
- **E{是否允许重复参与?}**: 判断活动是否允许用户重复参与。
- **F[应用活动规则: 计算折扣/赠品]**: 根据活动规则，计算折扣或赠品等活动权益。
- **G[生成活动权益]**: 生成用户参与活动所获得的权益。
- **H[记录活动参与日志]**: 记录用户参与活动的日志信息。
- **I[完成流程]**: 活动参与流程结束。
- **D[结束流程]**: 由于不满足条件，流程提前结束。

## 连线、分支与汇聚关系
- A -> B：用户行为触发后，进入条件判断。
- B -- 是 --> C：如果满足活动触发条件，则检查用户是否已参与活动。
- B -- 否 --> D：如果不满足活动触发条件，则结束流程。
- C -- 是 --> E：如果用户已参与活动，则判断是否允许重复参与。
- C -- 否 --> D：如果用户未参与活动，则进入判断是否允许重复参与。
- E -- 是 --> F：如果允许重复参与，则应用活动规则。
- E -- 否 --> D：如果不允许重复参与，则结束流程。
- F -> G：应用活动规则后，生成活动权益。
- G -> H：生成活动权益后，记录活动参与日志。
- H -> I：记录活动参与日志后，完成流程。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **用户行为**：用户在系统中的操作，例如浏览商品、点击广告等。
- **活动触发条件**：活动设定的启动条件，例如用户浏览特定商品达到一定次数。
- **活动权益**：用户参与活动所获得的利益，例如折扣、赠品等。
- **活动规则**：活动设定的具体规则，例如折扣比例、赠品数量等。
- **活动参与日志**：记录用户参与活动的详细信息，例如参与时间、获得的权益等。
- **重复参与**：用户多次参与同一活动的行为。

## 可作为 QA Ground Truth 的高信息密度摘要
用户行为发生后，系统判断是否满足活动触发条件。如果满足，则检查用户是否已参与活动。如果用户已参与，则判断是否允许重复参与。如果允许，则应用活动规则，计算折扣或赠品，生成活动权益，并记录活动参与日志，最终完成流程。如果不满足活动触发条件，或者用户不允许重复参与，则流程结束。
