## 图类型与用途
该图是一个流程图，描述了消息中心处理消息的流程。它展示了消息如何被接收、分类、处理，以及如何通过不同的通知通道发送给用户，最终记录消息发送报告。

## 图的整体布局
该图从左到右布局，整体呈现一个消息处理和通知的流程。起点是消息接收，终点是消息记录数据库。

## 分组/子图/阶段说明
图中有一个名为“消息中心”的子图，包含了整个消息处理的流程。

## 节点逐项说明
- **消息接收**：接收来自外部系统的消息。
- **消息分类**：对接收到的消息进行分类，区分业务消息和系统消息。
- **业务处理模块**：处理业务相关的消息。
- **系统通知服务**：处理系统相关的消息，用于发送系统通知。
- **业务数据存储**：存储业务处理后的数据。
- **用户通知通道**：选择合适的通道（短信、APP推送、站内信）发送通知。
- **短信网关**：发送短信的网关服务。
- **推送服务器**：用于APP推送的服务。
- **站内信存储**：存储站内信消息。
- **是否需要通知**：判断业务数据变更后是否需要发送通知。
- **结束**：流程结束。
- **短信发送成功**：短信发送成功状态。
- **推送成功**：APP推送成功状态。
- **存储成功**：站内信存储成功状态。
- **消息发送报告**：汇总消息发送的状态报告。
- **消息记录数据库**：存储消息发送的记录。

## 连线、分支与汇聚关系
- 消息接收 -> 消息分类：接收到的消息进入分类环节。
- 消息分类 -- 业务消息 --> 业务处理模块：业务消息进入业务处理模块。
- 消息分类 -- 系统消息 --> 系统通知服务：系统消息进入系统通知服务。
- 业务处理模块 -> 业务数据存储：业务处理模块将数据存储。
- 系统通知服务 -> 用户通知通道：系统通知服务选择用户通知通道。
- 用户通知通道 -- 短信 --> 短信网关：通过短信通道发送消息。
- 用户通知通道 -- APP推送 --> 推送服务器：通过APP推送通道发送消息。
- 用户通知通道 -- 站内信 --> 站内信存储：通过站内信通道发送消息。
- 业务数据存储 -> 是否需要通知：判断是否需要发送通知。
- 是否需要通知 -- 是 --> 系统通知服务：如果需要通知，则进入系统通知服务。
- 是否需要通知 -- 否 --> 结束：如果不需要通知，则流程结束。
- 短信网关 -> 短信发送成功：短信发送成功。
- 推送服务器 -> 推送成功：APP推送成功。
- 站内信存储 -> 存储成功：站内信存储成功。
- 短信发送成功 -> 消息发送报告：短信发送报告。
- 推送成功 -> 消息发送报告：APP推送发送报告。
- 存储成功 -> 消息发送报告：站内信发送报告。
- 消息发送报告 -> 消息记录数据库：消息发送报告存储到数据库。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **消息中心**：负责接收、处理和发送消息的系统组件。
- **业务消息**：与具体业务逻辑相关的消息。
- **系统消息**：与系统状态或通知相关的消息。
- **用户通知通道**：用于向用户发送通知的各种渠道，如短信、APP推送、站内信。
- **短信网关**：用于发送短信的外部服务接口。
- **APP推送**：通过移动应用程序向用户发送通知的方式。
- **站内信**：在系统内部发送和接收的消息。
- **消息记录数据库**：用于存储消息发送记录的数据库。

## 可作为 QA Ground Truth 的高信息密度摘要
消息中心接收消息后，进行消息分类，分为业务消息和系统消息。业务消息进入业务处理模块，进行业务数据存储，并判断是否需要通知，若需要则进入系统通知服务；系统消息直接进入系统通知服务。系统通知服务选择用户通知通道，通过短信网关、推送服务器或站内信存储发送消息，最终汇总消息发送报告，并存储到消息记录数据库。
