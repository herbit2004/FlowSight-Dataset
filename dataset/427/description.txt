## 图类型与用途
这是一个架构图，展示了一个企业级电子商务平台的多活多区域（Active-Active Multi-Region）架构。它用于说明如何构建一个具有高可用性和容错能力的系统，能够应对区域性的故障，并为全球用户提供服务，目标是达到 99.99% 的可用性。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户，然后是流量管理，接着是两个活跃区域（Region A 和 Region B），每个区域包含负载均衡器、EKS 集群和数据库。

## 分组/子图/阶段说明
- **Traffic Management**：处理用户流量的组件，包括 Route 53 和 CloudFront CDN。
- **Region A (Active)**：代表一个活跃的 AWS 区域，包含负载均衡器、EKS 集群和 Aurora Primary 数据库。
- **Region B (Active)**：代表另一个活跃的 AWS 区域，包含负载均衡器、EKS 集群和 Aurora Secondary 数据库。

## 节点逐项说明
- **Global Users**：代表全球范围内的用户。
- **Route 53 Latency-Based Routing**：AWS 的 DNS 服务，使用基于延迟的路由策略，将用户请求路由到延迟最低的区域。
- **CloudFront CDN**：AWS 的内容分发网络，用于缓存静态内容，加速用户访问，并减轻后端服务器的负载。
- **Load Balancer (ALB1)**：区域 A 的负载均衡器，将流量分发到 EKS 集群中的微服务。
- **EKS Cluster Microservices (EKS1)**：区域 A 的 Kubernetes 容器服务，运行着平台的微服务。
- **Aurora Primary (DB1)**：区域 A 的 AWS Aurora 数据库的主实例。
- **Load Balancer (ALB2)**：区域 B 的负载均衡器，将流量分发到 EKS 集群中的微服务。
- **EKS Cluster Microservices (EKS2)**：区域 B 的 Kubernetes 容器服务，运行着平台的微服务。
- **Aurora Secondary (DB2)**：区域 B 的 AWS Aurora 数据库的辅助实例。

## 连线、分支与汇聚关系
- `Global Users -> Route 53 Latency-Based Routing`：用户的请求通过 DNS 服务进行路由。
- `Global Users -> CloudFront CDN`：用户也可以直接通过 CDN 访问静态资源。
- `Route 53 Latency-Based Routing -> Load Balancer (ALB1)`：DNS 根据延迟将用户请求路由到区域 A 的负载均衡器。
- `Route 53 Latency-Based Routing -> Load Balancer (ALB2)`：DNS 根据延迟将用户请求路由到区域 B 的负载均衡器。
- `Load Balancer (ALB1) -> EKS Cluster Microservices (EKS1)`：区域 A 的负载均衡器将流量分发到 EKS 集群。
- `Load Balancer (ALB2) -> EKS Cluster Microservices (EKS2)`：区域 B 的负载均衡器将流量分发到 EKS 集群。
- `EKS Cluster Microservices (EKS1) -> Aurora Primary (DB1)`：区域 A 的 EKS 集群访问 Aurora Primary 数据库。
- `EKS Cluster Microservices (EKS2) -> Aurora Secondary (DB2)`：区域 B 的 EKS 集群访问 Aurora Secondary 数据库。
- `Aurora Primary (DB1) <--> Aurora Secondary (DB2)`：Aurora Primary 和 Aurora Secondary 之间通过全局复制和写转发进行数据同步。

## 仓库语境与术语解释
- **Active-Active Multi-Region Architecture**：一种高可用性架构，在多个地理区域同时运行应用程序，以提高可用性和容错能力。
- **Route 53**：AWS 的 DNS 服务，用于将用户请求路由到最近的区域，提高用户体验。
- **CloudFront CDN**：AWS 的内容分发网络，用于缓存静态内容，加速用户访问。
- **EKS Cluster**：AWS 的 Kubernetes 容器服务，用于运行平台的微服务。
- **Aurora Global Database**：跨多个 AWS 区域复制数据的数据库服务，提供低延迟的全局读取和快速的灾难恢复。
- **Global Replication & Write Forwarding**：Aurora 数据库之间的数据同步机制，确保数据一致性。
- **Digital Resilience**: 根据 `docs/README.md`，该项目通过多个架构维度（视角）和质量属性（视角）来实现数字弹性。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个多活多区域的电商平台架构，从全球用户发起请求开始，通过 Route 53 的延迟路由或 CloudFront CDN 将流量分发到 Region A 或 Region B。每个区域都包含 Load Balancer、EKS Cluster 和 Aurora 数据库。两个区域的 Aurora 数据库之间通过全局复制和写转发保持数据同步，实现高可用性和容错能力。该架构旨在实现 99.99% 的可用性，是 `README.md` 中“Production-Grade Resilience”的体现。
