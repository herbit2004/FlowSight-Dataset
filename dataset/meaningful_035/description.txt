## Edges, Branches & Convergence
- `A --> B`: The client request is sent to check if a tier check is required.
- `B -- Yes --> C`: If a tier check is required, the flow proceeds to the Tier Eligibility Service.
- `B -- No --> H`: If a tier check is not required, the flow proceeds to the Points Processor.
- `C --> D`: The Tier Eligibility Service determines if the client is eligible for a higher tier.
- `D -- Yes --> E`: If the client is eligible for a higher tier, the tier status is updated.
- `D -- No --> F`: If the client is not eligible for a higher tier, the tier eligibility check is logged.
- `E --> G`: After updating the tier status, a tier change notification is sent.
- `F --> K`: After logging the tier eligibility check, the flow proceeds to the Activity Log: Points Earned.
- `G --> H`: After sending the tier change notification, the flow proceeds to the Points Processor.
- `H --> I`: The Points Processor updates the points ledger.
- `I --> J`: The Points Ledger Update updates the points balance.
- `J --> K`: The Points Balance Update logs the activity of points earned.
- `K --> L`: The Activity Log sends a notification about the points earned.
- `L --> M`: The Notification Service updates the reward points data store.
- `M --> N`: The Reward Points Data Store checks if the client has sufficient points for a reward.
- `N -- Yes --> O`: If the client has sufficient points for a reward, the flow proceeds to the Reward Redemption Service.
- `N -- No --> R`: If the client does not have sufficient points for a reward, the flow proceeds to the Transaction Log.
- `O --> P`: The Reward Redemption Service initiates the reward fulfillment process.
- `P --> Q`: The Reward Fulfillment Process interacts with the Inventory Management System.
- `Q --> R`: The Inventory Management System logs the transaction of the reward redeemed.

## Repository Context & Terminology
- **Loyalty System**: A system designed to reward customers for their continued patronage.
- **Tier**: A level within the loyalty program, often associated with different benefits.
- **Points**: A unit of value earned within the loyalty system, redeemable for rewards.
- **Ledger**: A record of all points transactions within the system.
- **Redemption**: The process of exchanging points for rewards.
- **Inventory Management**: The process of tracking and managing the available rewards.
- **Transaction Log**: A record of all transactions within the system, including points earned and rewards redeemed.

## High-Density QA Ground Truth Summary
The loyalty system workflow begins with a "Client Request: Earn Points," triggering a "Tier Check Required?" decision. If a tier check is needed ("Yes" branch), the "Tier Eligibility Service" determines if the client qualifies for a higher tier. A "Yes" outcome leads to "Update Tier Status" and "Tier Change Notification," while a "No" outcome results in "Log Tier Eligibility Check." Both paths eventually converge at "Activity Log: Points Earned." If no tier check is required ("No" branch from "Tier Check Required?"), the flow proceeds directly to "Points Processor." The "Points Processor" updates the "Points Ledger," which in turn updates the "Points Balance." The "Points Balance Update" feeds into "Activity Log: Points Earned," which then triggers a "Notification Service: Points Earned" and updates the "Reward Points Data Store." A "Sufficient Points for Reward?" decision determines if the client can redeem a reward. If sufficient points exist ("Yes" branch), the "Reward Redemption Service" initiates the "Reward Fulfillment Process," interacting with the "Inventory Management System." Regardless of whether points were sufficient or not ("No" branch), the final step is to update the "Transaction Log: Reward Redeemed," recording the outcome of the process. The "Transaction Log" serves as a permanent record of all loyalty-related activities.
