## Edges, Branches & Convergence
- `Web Browser --> REST API + WebSocket`: User interaction triggers a request to the backend.
- `REST API + WebSocket --> Authentication CSRF Protection`: The backend authenticates the request and protects against CSRF attacks.
- `Authentication CSRF Protection --> Research Routes`: Validated requests are routed to the research routes.
- `Research Routes --> Strategy Selector`: Research routes trigger the strategy selection process.
- `Strategy Selector --> Question Generator`: The selected strategy initiates the question generation process.
- `Question Generator --> Search Executor`: The generated questions are passed to the search executor.
- `Search Executor --> Ollama, LM Studio, OpenAI, Anthropic, Google Gemini, OpenRouter, SearXNG, Elasticsearch, Document Library, Tavily, Brave, DuckDuckGo, ArXiv, PubMed, Semantic Scholar`: The search executor queries various LLM providers and search engines.
- `Search Executor --> Report Synthesizer`: Search results are passed to the report synthesizer.
- `Report Synthesizer --> SQLCipher DB`: The report synthesizer stores data in the SQLCipher database.
- `Document Library --> Vector Store`: The document library stores vector embeddings.
- `Document Library --> File Storage`: The document library stores PDFs and Docs.
- `Report Synthesizer --> Markdown, PDF Export, LaTeX, Quarto, RIS/BibTeX`: The report synthesizer generates output in various formats.

## Repository Context & Terminology
- **Flask Backend**: The backend is implemented using the Flask framework, a Python web framework.
- **REST API**: The backend exposes a RESTful API for communication with the frontend.
- **WebSocket**: The backend uses WebSockets for real-time communication.
- **CSRF Protection**: Cross-Site Request Forgery (CSRF) protection is implemented to prevent malicious attacks.
- **SQLCipher**: SQLCipher is an extension to SQLite that provides AES-256 encryption.
- **Vector Store**: A database or storage system optimized for storing and querying vector embeddings.
- **Ollama**: Ollama is a tool for running large language models locally.

## High-Density QA Ground Truth Summary
The process begins with a user interacting with the Web Browser at localhost:5000, which sends a request to the Flask Backend via REST API and WebSocket. The backend then performs Authentication and CSRF Protection. Upon successful authentication, the request is routed to the Research Routes. The Research Routes trigger the Strategy Selector, which selects from 20+ strategies to initiate the Question Generator. The generated questions are then passed to the Search Executor. The Search Executor queries a variety of LLM Providers including local LLMs like Ollama and LM Studio, and cloud LLMs like OpenAI, Anthropic, Google Gemini, and OpenRouter. It also queries various Search Engines including SearXNG, Elasticsearch, Document Library, Tavily, Brave, DuckDuckGo, ArXiv, PubMed, and Semantic Scholar. The Document Library stores Vector Store Embeddings and PDFs & Docs in File Storage. The search results are then passed to the Report Synthesizer, which stores data in the SQLCipher DB (AES-256 Encrypted) and generates output in various formats: Markdown, PDF Export, LaTeX, Quarto, and RIS/BibTeX. The SQLCipher DB provides encrypted storage for sensitive research data.
