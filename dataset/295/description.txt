## 图类型与用途
这是一个流程图，描述了基于ESP32的AI语音助手如何处理用户语音指令并生成回复。它展示了从对话开始到完成一轮对话，并判断是否继续进行连续对话的完整流程。

## 图的整体布局
图采用从左到右的布局。流程从左侧的“开始对话”节点开始，经过语音识别、指令判断、大模型处理等阶段，最终到达右侧的“一轮对话完成”节点。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为三个阶段：对话发起与语音识别、指令处理与大模型交互、语音合成与对话完成。

## 节点逐项说明
- **开始对话**：流程的起点，表示用户开始与系统交互。
- **语音唤醒**：系统通过语音识别技术检测预设的唤醒词，例如“你好九歌”。
- **按下BOOT键**：用户通过按下开发板上的BOOT键来触发录音。
- **通过串口发送消息**：用户可以通过串口直接发送文本消息给系统。
- **系统进入录音状态**：系统开始录音，准备接收用户的语音输入。
- **INMP441麦克风录音**：使用INMP441麦克风模块采集用户的语音。根据 README，INMP441 麦克风模块通过特定引脚连接到 ESP32 或 ESP32-S3 开发板。
- **讯飞STT服务**：将录音的语音数据发送到讯飞的语音转文字（STT）服务，将语音转换为文本。根据 README，需要注册讯飞开放平台并开通 STT 语音转文字服务。
- **识别结果**：判断语音识别的结果是否有效。
- **是否为指令**：判断识别出的文本是否为预定义的指令，例如控制硬件设备或执行特定操作。
- **提示重新说话**：如果语音识别无效，提示用户重新说话。
- **发送至大模型**：如果识别结果不是指令，则将文本发送到预设的大语言模型（例如 ChatGPT、Claude 等）。
- **接收大模型回复**：接收大语言模型生成的回复文本。
- **回复内容分段**：将大模型回复的文本进行分段处理，以便进行语音合成。
- **本地函数处理**：如果识别结果是指令，则调用本地函数执行相应的操作。
- **百度TTS服务**：使用百度文本转语音（TTS）服务将文本转换为语音。
- **语音输出**：通过扬声器播放合成的语音。
- **一轮对话完成**：完成一轮对话。
- **是否连续对话**：判断用户是否希望进行连续对话。

## 连线、分支与汇聚关系
- `开始对话 -> 语音唤醒`：用户可以通过语音唤醒开始对话。
- `开始对话 -> 按下BOOT键`：用户可以通过按下BOOT键开始对话。
- `开始对话 -> 通过串口发送消息`：用户可以通过串口发送消息开始对话。
- `语音唤醒 -> 系统进入录音状态`：语音唤醒后，系统进入录音状态。
- `按下BOOT键 -> 系统进入录音状态`：按下BOOT键后，系统进入录音状态。
- `系统进入录音状态 -> INMP441麦克风录音`：系统进入录音状态后，使用麦克风录音。
- `INMP441麦克风录音 -> 讯飞STT服务`：麦克风录音后，将语音数据发送到讯飞STT服务。
- `讯飞STT服务 -> 识别结果`：讯飞STT服务将语音转换为文本后，判断识别结果是否有效。
- `识别结果 -- 有效 --> 是否为指令`：如果识别结果有效，则判断是否为指令。
- `识别结果 -- 无效 --> 提示重新说话`：如果识别结果无效，则提示用户重新说话。
- `提示重新说话 -> 系统进入录音状态`：提示用户重新说话后，系统重新进入录音状态。
- `是否为指令 -- 否 --> 发送至大模型`：如果识别结果不是指令，则将文本发送到大模型。
- `是否为指令 -- 是 --> 本地函数处理`：如果识别结果是指令，则调用本地函数处理。
- `发送至大模型 -> 接收大模型回复`：将文本发送到大模型后，接收大模型回复。
- `接收大模型回复 -> 回复内容分段`：接收到大模型回复后，将回复内容分段。
- `回复内容分段 -> 百度TTS服务`：将回复内容分段后，使用百度TTS服务将文本转换为语音。
- `百度TTS服务 -> 语音输出`：使用百度TTS服务将文本转换为语音后，进行语音输出。
- `本地函数处理 -> 语音输出`：本地函数处理后，进行语音输出。
- `语音输出 -> 一轮对话完成`：语音输出后，完成一轮对话。
- `一轮对话完成 -> 是否连续对话`：完成一轮对话后，判断是否进行连续对话。
- `是否连续对话 -- 是 --> 系统进入录音状态`：如果进行连续对话，则系统重新进入录音状态。
- `是否连续对话 -- 否 --> 开始对话`：如果不进行连续对话，则流程结束，回到开始对话状态。
- `通过串口发送消息 -> 是否为指令`：通过串口发送消息后，判断是否为指令。

## 仓库语境与术语解释
- **ESP32**：一种低功耗、低成本的微控制器，常用于物联网设备。该项目基于 ESP32 实现智能语音助手。
- **INMP441**：一种全向麦克风模块，用于采集用户的语音。根据 README，需要正确连接 INMP441 麦克风模块的引脚到 ESP32 开发板。
- **讯飞STT服务**：讯飞提供的语音转文字服务，用于将用户的语音转换为文本。根据 README，需要在讯飞开放平台注册并开通 STT 服务。
- **百度TTS服务**：百度提供的文本转语音服务，用于将文本转换为语音。
- **ASRPRO**：一个语音识别模块，可以用于离线语音唤醒。根据 README，需要下载天问Block软件配置 ASRPRO 模块。
- **main.cpp**：项目的主要代码文件，包含了程序的主要逻辑和功能实现。根据 README，需要查看 main.cpp 顶部的注意事项，并填写讯飞账号参数和大模型的相关参数。
- **User_Setup.h**：TFT_eSPI 库的配置文件，用于配置屏幕的驱动类型和引脚。根据 README，需要将 esp32AI_vscode 文件夹下的 User_Setup.h 文件替换为对应的版本。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 ESP32 AI 语音助手的核心对话流程。流程从“开始对话”节点出发，用户可以通过语音唤醒、按下 BOOT 键或通过串口发送消息来启动对话。系统进入录音状态后，使用 INMP441 麦克风采集语音，并通过讯飞 STT 服务将语音转换为文本。如果识别结果有效，则判断是否为指令，如果是指令则调用本地函数处理，否则将文本发送至大模型获取回复。最后，使用百度 TTS 服务将回复转换为语音输出，完成一轮对话。用户可以选择进行连续对话，或者结束对话流程。其中，讯飞 STT 服务和大模型是实现语音助手功能的核心组件。
