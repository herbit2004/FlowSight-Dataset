## 图类型与用途
这是一个分层架构图，展示了 FSharp.Azure.Quantum 库中，如何使用量子算法解决组合优化问题的架构。该图描述了从高层问题构建器，经过量子求解器，最终到达量子后端的流程，用于概括库的整体架构。

## 图的整体布局
图采用从上到下的分层布局，分为三个主要层次：高层构建器、量子求解器和量子后端。数据/流程从顶层开始，逐层向下传递。

## 分组/子图/阶段说明
图中包含三个显式子图，分别对应三个层次：
- **Layer 1: High-Level Builders**：包含各种问题构建器，用于定义需要解决的组合优化问题。
- **Layer 2: Quantum Solvers**：包含各种量子求解器，它们使用量子近似优化算法 (QAOA) 来解决由第一层构建的问题。
- **Layer 3: Quantum Backends**：包含不同的量子计算后端，用于实际运行量子算法。

## 节点逐项说明
- **GC (GraphColoring Builder)**：图着色问题构建器，使用 `graphColoring { }` 表达式。
- **MC (MaxCut Builder)**：最大割问题构建器，使用 `MaxCut.createProblem` 函数。
- **KS (Knapsack Builder)**：背包问题 (0/1) 构建器，使用 `Knapsack.createProblem` 函数。
- **TS (TSP Builder)**：旅行商问题构建器，使用 `TSP.createProblem` 函数。
- **PO (Portfolio Builder)**：投资组合优化问题构建器，使用 `Portfolio.createProblem` 函数。
- **NF (NetworkFlow Builder)**：网络流问题构建器，使用 `NetworkFlow module`。
- **SCHED (TaskScheduling Builder)**：任务调度问题构建器，使用 `scheduledTask { }` 表达式。
- **QGC (QuantumGraphColoringSolver)**：图着色问题的量子求解器 (QAOA)。
- **QMC (QuantumMaxCutSolver)**：最大割问题的量子求解器 (QAOA)。
- **QKS (QuantumKnapsackSolver)**：背包问题的量子求解器 (QAOA)。
- **QTS (QuantumTspSolver)**：旅行商问题的量子求解器 (QAOA)。
- **QPO (QuantumPortfolioSolver)**：投资组合优化问题的量子求解器 (QAOA)。
- **QNF (QuantumNetworkFlowSolver)**：网络流问题的量子求解器 (QAOA)。
- **QSCHED (QuantumSchedulingSolver)**：任务调度问题的量子求解器 (QAOA)。
- **LOCAL (LocalBackend)**：本地后端，适用于小规模问题 (≤20 qubits)。根据 `src/FSharp.Azure.Quantum/Backends/LocalBackend.fs`，它使用 StateVector 进行门操作的量子模拟。
- **IONQ (IonQBackend)**：IonQ 提供的量子后端，通过 Azure Quantum 平台访问。根据 `src/FSharp.Azure.Quantum/Backends/IonQBackend.fs`，它将电路序列化为 IonQ 格式的 JSON。
- **RIGETTI (RigettiBackend)**：Rigetti 提供的量子后端，通过 Azure Quantum 平台访问。根据 `src/FSharp.Azure.Quantum/Backends/RigettiBackend.fs`，它将电路序列化为 Quil 汇编语言。
- **ATOM (AtomComputingBackend)**：Atom Computing 提供的量子后端，通过 Azure Quantum 平台访问，拥有 100+ qubits。根据 `src/FSharp.Azure.Quantum/Backends/AtomComputingBackend.fs`，它接受 OpenQASM 2.0 字符串。
- **QUANTINUUM (QuantinuumBackend)**：Quantinuum 提供的量子后端，通过 Azure Quantum 平台访问，具有 99.9%+ 的 fidelity。图中可见，但仓库上下文未进一步说明。

## 连线、分支与汇聚关系
- `GC -> QGC`：图着色问题构建器连接到图着色问题的量子求解器。
- `MC -> QMC`：最大割问题构建器连接到最大割问题的量子求解器。
- `KS -> QKS`：背包问题构建器连接到背包问题的量子求解器。
- `TS -> QTS`：旅行商问题构建器连接到旅行商问题的量子求解器。
- `PO -> QPO`：投资组合优化问题构建器连接到投资组合优化问题的量子求解器。
- `NF -> QNF`：网络流问题构建器连接到网络流问题的量子求解器。
- `SCHED -> QSCHED`：任务调度问题构建器连接到任务调度问题的量子求解器。
- `QGC -> LOCAL`，`QMC -> LOCAL`，`QKS -> LOCAL`，`QTS -> LOCAL`，`QPO -> LOCAL`，`QNF -> LOCAL`，`QSCHED -> LOCAL`：所有量子求解器都连接到本地后端。形成汇聚关系。
- `QGC -.-> IONQ`，`QMC -.-> IONQ`，`QKS -.-> IONQ`，`QTS -.-> IONQ`，`QPO -.-> IONQ`，`QNF -.-> IONQ`，`QSCHED -.-> IONQ`：所有量子求解器都虚线连接到 IonQ 后端。
- `QGC -.-> RIGETTI`，`QMC -.-> RIGETTI`，`QKS -.-> RIGETTI`，`QTS -.-> RIGETTI`，`QPO -.-> RIGETTI`，`QNF -.-> RIGETTI`，`QSCHED -.-> RIGETTI`：所有量子求解器都虚线连接到 Rigetti 后端。
- `QGC -.-> ATOM`，`QMC -.-> ATOM`，`QKS -.-> ATOM`，`QTS -.-> ATOM`，`QPO -.-> ATOM`，`QNF -.-> ATOM`，`QSCHED -.-> ATOM`：所有量子求解器都虚线连接到 Atom Computing 后端。
- `QGC -.-> QUANTINUUM`，`QMC -.-> QUANTINUUM`，`QKS -.-> QUANTINUUM`，`QTS -.-> QUANTINUUM`，`QPO -.-> QUANTINUUM`，`QNF -.-> QUANTINUUM`，`QSCHED -.-> QUANTINUUM`：所有量子求解器都虚线连接到 Quantinuum 后端。

## 仓库语境与术语解释
- **QAOA (Quantum Approximate Optimization Algorithm)**：量子近似优化算法，用于解决组合优化问题。`src/FSharp.Azure.Quantum/Core/QaoaCircuit.fs` 实现了 QAOA 电路构建。
- **QUBO (Quadratic Unconstrained Binary Optimization)**：二次无约束二进制优化，是一种用于表示组合优化问题的数学模型。
- **Azure Quantum**：微软的量子计算云平台，提供对不同量子硬件的访问。
- **LocalBackend**：本地量子模拟器，用于在本地计算机上模拟量子电路。
- **IonQBackend, RigettiBackend, AtomComputingBackend, QuantinuumBackend**：分别对应 IonQ、Rigetti、Atom Computing 和 Quantinuum 提供的量子计算后端。
- **OpenQASM 2.0**：一种用于描述量子电路的开放标准语言。AtomComputingBackend 接受 OpenQASM 2.0 字符串作为输入。
- **Graph Coloring, MaxCut, Knapsack, TSP, Portfolio Optimization, Network Flow, Task Scheduling**：常见的组合优化问题，该库提供了相应的构建器和求解器。
- **Qubit**：量子比特，量子计算中的基本信息单位。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 FSharp.Azure.Quantum 库的架构，从 Layer 1 的高层问题构建器（如 GraphColoring Builder, MaxCut Builder 等）开始，通过 Layer 2 的量子求解器（如 QuantumGraphColoringSolver, QuantumMaxCutSolver 等），最终到达 Layer 3 的量子后端（如 LocalBackend, IonQBackend, RigettiBackend, AtomComputingBackend, QuantinuumBackend）。其中，量子求解器使用 QAOA 算法，并且可以选择不同的量子后端执行计算。LocalBackend 用于本地模拟，而 IonQ, Rigetti, Atom Computing 和 Quantinuum 通过 Azure Quantum 提供云端量子计算资源。该架构支持多种组合优化问题，并提供了从问题定义到量子计算的完整流程。
