## 图类型与用途
这是一个流程图，描述了 XingRin 攻击面管理平台中任务调度和分发的架构。其用途是展示如何将扫描任务高效地分配到不同的 Worker 节点上，并利用 Redis 缓存负载信息，实现负载均衡，提高扫描效率和稳定性。

## 图的整体布局
图整体采用从上到下的布局。顶部是主服务器，包含任务调度器和 Redis 负载缓存，底部是 Worker 节点集群。任务从任务调度器分发到 Worker 节点。

## 分组/子图/阶段说明
图中包含两个子图：
- **MASTER (主服务器)**：包含任务调度器和 Redis 负载缓存，负责接收、调度和分发扫描任务。
- **WORKERS (Worker 节点集群)**：包含多个 Worker 节点，负责执行实际的扫描任务。

任务调度器内部又分为三个阶段：
- **SUBMIT (接收扫描任务)**：接收用户提交的扫描任务。
- **SELECT (负载感知选择)**：根据 Redis 中缓存的负载数据，选择合适的 Worker 节点。
- **DISPATCH (智能分发)**：将扫描任务分发到选定的 Worker 节点。

## 节点逐项说明
- **MASTER (主服务器)**：整个系统的核心控制中心，负责接收、调度和分发扫描任务。
- **REDIS (Redis 负载缓存)**：用于存储和缓存各个 Worker 节点的负载数据（CPU 和内存使用率），供任务调度器使用。
- **SCHEDULER (任务调度器)**：负责接收扫描任务，并根据 Worker 节点的负载情况进行智能分发。
- **SUBMIT (接收扫描任务)**：接收用户提交的扫描任务。
- **SELECT (负载感知选择)**：根据 Redis 中缓存的负载数据，选择合适的 Worker 节点。
- **DISPATCH (智能分发)**：将扫描任务分发到选定的 Worker 节点。
- **W1 (Worker 1 (本地) CPU: 45% | MEM: 60%)**：本地 Worker 节点，显示 CPU 和内存使用率。
- **W2 (Worker 2 (远程) CPU: 30% | MEM: 40%)**：远程 Worker 节点，显示 CPU 和内存使用率。
- **W3 (Worker N (远程) CPU: 90% | MEM: 85%)**：远程 Worker 节点，显示 CPU 和内存使用率，负载较高。

## 连线、分支与汇聚关系
- `REDIS -.负载数据.-> SELECT`：Redis 将负载数据传递给负载感知选择节点。
- `SUBMIT --> SELECT`：接收扫描任务后传递给负载感知选择节点。
- `SELECT --> DISPATCH`：负载感知选择节点将选择结果传递给智能分发节点。
- `DISPATCH --> W1`：智能分发节点将任务分发到 Worker 1。
- `DISPATCH --> W2`：智能分发节点将任务分发到 Worker 2。
- `DISPATCH --> W3`：智能分发节点由于 W3 负载过高，跳过该节点。
- `W1 -.心跳上报.-> REDIS`：Worker 1 定期向 Redis 上报心跳和负载数据。
- `W2 -.心跳上报.-> REDIS`：Worker 2 定期向 Redis 上报心跳和负载数据。
- `W3 -.心跳上报.-> REDIS`：Worker 3 定期向 Redis 上报心跳和负载数据。

## 仓库语境与术语解释
- **ASM (攻击面管理)**：XingRin 是一个攻击面管理平台，旨在自动化资产发现与漏洞扫描。
- **Worker 节点**：分布式扫描的执行器，负责实际的扫描任务。根据 `backend/apps/engine/models/engine.py` 中的 `WorkerNode` 模型定义，Worker 节点可以是本地节点（Docker 容器内）或远程节点。
- **Redis**：用于缓存 Worker 节点的负载数据，任务调度器根据这些数据进行智能分发。
- **负载感知调度**：根据 Worker 节点的实时负载情况，自动将任务分发到最优节点，避免某些节点过载。`backend/apps/engine/services/task_distributor.py` 实现了负载感知任务分发器。
- **心跳上报**：Worker 节点定期向 Redis 上报心跳和负载数据，用于监控节点状态和负载情况。
- **TASK_EXECUTOR_IMAGE**：Docker 镜像，用于执行扫描任务。根据 `backend/apps/engine/services/task_distributor.py`，该镜像的版本需要与 server 版本一致。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 XingRin 平台的任务调度架构，采用主从模式。MASTER 服务器负责接收扫描任务，通过 SCHEDULER 中的 SUBMIT 节点接收任务，SELECT 节点从 REDIS 获取 Worker 节点的负载数据，DISPATCH 节点根据负载情况将任务分发到 WORKERS 节点集群。WORKERS 节点定期向 REDIS 上报心跳和负载数据。任务调度器会跳过高负载节点，保证系统的稳定性和性能。该架构实现了负载感知调度，提高了整体扫描效率和稳定性。`backend/apps/engine/services/task_distributor.py` 实现了负载感知任务分发器，`backend/apps/engine/models/engine.py` 定义了 WorkerNode 模型。
