## 图类型与用途
该图是一个流程图，用于描述用户注册与登录的流程。它详细展示了新用户注册、老用户登录以及忘记密码的各种情况，并处理无效请求。

## 图的整体布局
该图采用从上到下的布局。整体流程从用户发起请求开始，经过一系列判断和处理，最终跳转至用户中心或返回错误。

## 分组/子图/阶段说明
图中包含四个子图：
- **用户注册与登录流程**：总览流程的起点和登录状态判断。
- **新用户注册**：描述新用户注册的详细步骤。
- **老用户登录**：描述老用户登录的详细步骤，包括二次验证。
- **忘记密码流程**：描述用户找回密码的流程。

## 节点逐项说明
- **A[用户发起请求]**：用户发起注册或登录请求。
- **B{判断：已登录？}**：判断用户是否已经登录。
- **C[跳转至用户中心]**：如果用户已登录，则跳转至用户中心。
- **D{判断：请求类型？}**：判断用户请求的类型（注册、登录、忘记密码等）。
- **E[显示注册页面]**：显示注册页面给用户填写信息。
- **F[用户填写注册信息]**：用户在注册页面填写个人信息。
- **G{验证：信息有效？}**：验证用户填写的注册信息是否有效。
- **H[返回注册页面，提示错误]**：如果注册信息无效，则返回注册页面并提示错误。
- **I[提交注册信息]**：用户提交注册信息。
- **J[创建用户账户]**：创建新的用户账户。
- **K[发送验证邮件/短信]**：向用户发送验证邮件或短信。
- **L{验证：验证成功？}**：验证用户是否成功验证邮件/短信。
- **M[账户冻结/锁定]**：如果验证失败，则冻结或锁定账户。
- **N[注册成功]**：用户注册成功。
- **O[自动登录]**：注册成功后自动登录。
- **P[显示登录页面]**：显示登录页面给用户填写信息。
- **Q[用户填写登录信息]**：用户在登录页面填写用户名和密码。
- **R{验证：用户名密码正确？}**：验证用户输入的用户名和密码是否正确。
- **S[返回登录页面，提示错误]**：如果用户名或密码错误，则返回登录页面并提示错误。
- **T{验证：是否需要二次验证？}**：判断用户是否需要进行二次验证。
- **U[发送二次验证码]**：向用户发送二次验证码。
- **V[用户输入二次验证码]**：用户输入收到的二次验证码。
- **W{验证：验证码正确？}**：验证用户输入的二次验证码是否正确。
- **X[返回二次验证页面，提示错误]**：如果二次验证码错误，则返回二次验证页面并提示错误。
- **Y[登录成功]**：用户登录成功。
- **AA[显示找回密码页面]**：显示找回密码页面给用户填写信息。
- **BB[用户填写邮箱/手机号]**：用户填写用于找回密码的邮箱或手机号。
- **CC{验证：账号存在？}**：验证用户填写的邮箱或手机号对应的账号是否存在。
- **DD[提示账号不存在]**：如果账号不存在，则提示用户账号不存在。
- **EE[发送重置密码链接/验证码]**：向用户发送重置密码链接或验证码。
- **FF[用户重置密码]**：用户重置密码。
- **GG[密码重置成功]**：密码重置成功。
- **ZZ[无效请求，返回错误]**：处理无效请求，返回错误信息。

## 连线、分支与汇聚关系
- A -> B：用户发起请求后，进入登录状态判断。
- B -- 是 --> C：如果已登录，则跳转至用户中心。
- B -- 否 --> D：如果未登录，则判断请求类型。
- D -- 注册 --> E：如果是注册请求，则显示注册页面。
- D -- 登录 --> P：如果是登录请求，则显示登录页面。
- D -- 忘记密码 --> AA：如果是忘记密码请求，则显示找回密码页面。
- D -- 其他 --> ZZ：如果是其他请求，则返回错误。
- E -> F：用户填写注册信息。
- F -> G：验证注册信息。
- G -- 否 --> H：如果注册信息无效，则返回注册页面。
- H -.-> E：返回注册页面，提示错误后重新显示注册页面。
- G -- 是 --> I：如果注册信息有效，则提交注册信息。
- I -> J：创建用户账户。
- J -> K：发送验证邮件/短信。
- K -> L：验证邮件/短信。
- L -- 否 --> M：如果验证失败，则冻结/锁定账户。
- L -- 是 --> N：如果验证成功，则注册成功。
- N -> O：注册成功后自动登录。
- O -> C：自动登录后跳转至用户中心。
- P -> Q：用户填写登录信息。
- Q -> R：验证用户名密码。
- R -- 否 --> S：如果用户名密码错误，则返回登录页面。
- S -.-> P：返回登录页面，提示错误后重新显示登录页面。
- R -- 是 --> T：如果用户名密码正确，则判断是否需要二次验证。
- T -- 是 --> U：如果需要二次验证，则发送二次验证码。
- U -> V：用户输入二次验证码。
- V -> W：验证二次验证码。
- W -- 否 --> X：如果二次验证码错误，则返回二次验证页面。
- X -.-> U：返回二次验证页面，提示错误后重新发送二次验证码。
- W -- 是 --> Y：如果二次验证码正确，则登录成功。
- T -- 否 --> Y：如果不需要二次验证，则登录成功。
- Y -> C：登录成功后跳转至用户中心。
- AA -> BB：用户填写邮箱/手机号。
- BB -> CC：验证账号是否存在。
- CC -- 否 --> DD：如果账号不存在，则提示账号不存在。
- DD -.-> AA：返回找回密码页面，提示账号不存在后重新显示找回密码页面。
- CC -- 是 --> EE：如果账号存在，则发送重置密码链接/验证码。
- EE -> FF：用户重置密码。
- FF -> GG：密码重置成功。
- GG -> P：密码重置成功后返回登录页面。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **用户中心**：用户登录后可以访问的个人信息管理页面。
- **二次验证**：在用户名密码验证之外，增加的一种安全验证方式，例如短信验证码。
- **注册信息**：用户在注册时填写的个人信息，例如用户名、密码、邮箱等。
- **登录信息**：用户在登录时填写的用户名和密码。
- **验证码**：用于验证用户身份的随机数字或字母组合，通常通过短信或邮件发送。
- **账户冻结/锁定**：为了安全起见，暂时或永久禁止用户访问账户。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起请求后，系统首先判断用户是否已登录，若已登录则跳转至用户中心。否则，系统根据请求类型进入不同流程：若为注册请求，则显示注册页面，用户填写信息并验证，验证成功后创建账户并发送验证信息，验证成功则注册成功并自动登录至用户中心；若为登录请求，则显示登录页面，用户填写信息并验证，验证成功后根据是否需要二次验证，完成登录并跳转至用户中心；若为忘记密码请求，则显示找回密码页面，用户填写信息并验证账号存在，验证成功后发送重置密码链接，用户重置密码后返回登录页面。如果请求类型无效，则返回错误。
