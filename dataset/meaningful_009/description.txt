## Diagram Type & Purpose

## Edges, Branches & Convergence
- `Metric Ingestion API --> Kafka Topic: raw_metrics`: Metrics are ingested and sent to the `raw_metrics` Kafka topic.
- `Kafka Topic: raw_metrics --> Metric Parser\n& Validator`: Raw metrics are sent to the Metric Parser & Validator.
- `Metric Parser\n& Validator -- Invalid Metrics --> Dead Letter Queue`: Invalid metrics are sent to the Dead Letter Queue.
- `Metric Parser\n& Validator -- Valid Metrics --> Kafka Topic: validated_metrics`: Valid metrics are sent to the `validated_metrics` Kafka topic.
- `Kafka Topic: validated_metrics --> Aggregation Engine`: Validated metrics are sent to the Aggregation Engine.
- `Aggregation Engine --> Time-series Database`: Aggregated metrics are stored in the Time-series Database.
- `Time-series Database --> Query API`: The Alerting System queries the Time-series Database via the Query API.
- `Query API --> Alerting Rules Engine`: The query is sent to the Alerting Rules Engine.
- `Alerting Rules Engine -- Rule Triggered --> Threshold Check`: If a rule is triggered, the system proceeds to the Threshold Check.
- `Threshold Check -- Threshold Exceeded --> Alert Generation`: If the threshold is exceeded, an alert is generated.
- `Threshold Check -- Threshold Not Exceeded --> No Action`: If the threshold is not exceeded, no action is taken.
- `Alert Generation --> Notification Service`: The generated alert is sent to the Notification Service.
- `No Action` is a terminal state.
- `Notification Service --> Email Service`: Notifications are sent via Email Service.
- `Notification Service --> Slack Integration`: Notifications are sent via Slack Integration.
- `Notification Service --> PagerDuty Escalation`: Notifications are sent via PagerDuty Escalation.

## High-Density QA Ground Truth Summary
The data pipeline begins with the Metric Ingestion API, which receives incoming metrics. These metrics are then published to the `raw_metrics` Kafka topic. The Metric Parser & Validator consumes these raw metrics, validating them. Invalid metrics are routed to the Dead Letter Queue, while valid metrics are published to the `validated_metrics` Kafka topic. The Aggregation Engine then processes these validated metrics, and the aggregated data is stored in the Time-series Database. The Alerting System queries this database via the Query API, passing the results to the Alerting Rules Engine. If a rule is triggered, a Threshold Check is performed. If the threshold is exceeded, Alert Generation creates an alert, which is then sent to the Notification Service. If the threshold is not exceeded, No Action is taken. The Notification Service then distributes the alert via multiple channels: Email Service, Slack Integration, and PagerDuty Escalation. Kafka is used as a message broker for the raw and validated metrics, ensuring reliable data delivery between components.
