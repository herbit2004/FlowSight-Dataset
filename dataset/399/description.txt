## 图类型与用途
这是一个架构图，展示了一个基于 Google Cloud Platform 和 Google Gemini 模型的智能、多代理内容创作系统。它在仓库中的作用是描绘该系统的各个组件及其交互方式，是 `diagrams/architecture.mmd` 中提到的系统架构图。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户界面，中间是 Google Cloud Run 和 Google Cloud Platform，底部是 AI 模型。数据流从用户界面开始，经过各个组件，最终到达 AI 模型。

## 分组/子图/阶段说明
图中包含多个子图，分别代表不同的组件或环境：
- **User Interface**：用户与系统交互的入口。
- **Google Cloud Run**：运行组合服务（前端和后端）的平台。
- **Google Cloud Platform**：包含 Vertex AI Agent Engine 和基础设施服务。
- **Vertex AI Agent Engine**：运行 Master Orchestrator、Content Creation Coordinator 和 Content Analyzer 等代理的平台。
- **Infrastructure**：包含 Artifact Registry、Cloud Storage 和 Cloud Logging 等基础设施服务。
- **AI Models**：使用 Google Gemini 2.5 Flash 模型进行内容创作和分析。

## 节点逐项说明
- **Web Browser**：用户与系统交互的入口。
- **React Frontend**：使用 React 框架构建的前端界面，提供静态文件服务，基于 Vite 和 React 18。
- **FastAPI Backend**：使用 FastAPI 框架构建的 API 服务器，处理来自前端的请求，基于 Python 3.11 和 Uvicorn。
- **Master Orchestrator**：负责协调和管理其他代理的代理，使用 gemini-2.5-flash 模型。
- **Content Creation Coordinator**：负责协调内容创作流程的代理，使用 gemini-2.5-flash 模型。
- **Content Analyzer**：负责分析内容的代理，使用 gemini-2.5-flash 模型。
- **Artifact Registry**：存储 Docker 镜像。
- **Cloud Storage**：存储临时文件和数据。
- **Cloud Logging**：用于记录和监控系统的日志。
- **Google Gemini 2.5 Flash**：通过 Vertex AI 提供的 Google Gemini 模型。

## 连线、分支与汇聚关系
- `Web Browser -> React Frontend`：用户通过 HTTPS 请求访问 React 前端。
- `React Frontend -> FastAPI Backend`：React 前端通过 `/api/*` 路径将请求发送到 FastAPI 后端。
- `Frontend -.served by.-> Backend`：图中可见，React Frontend 由 FastAPI Backend 提供静态文件服务。
- `FastAPI Backend -> Master Orchestrator`：FastAPI 后端通过 RemoteRunner 调用 Vertex AI Agent Engine 中的 Master Orchestrator。
- `Master Orchestrator -> Content Creation Coordinator`：Master Orchestrator 将任务分配给 Content Creation Coordinator。
- `Master Orchestrator -> Content Analyzer`：Master Orchestrator 将任务分配给 Content Analyzer。
- `Content Creation Coordinator -> Google Gemini 2.5 Flash`：Content Creation Coordinator 通过 API Calls 调用 Google Gemini 2.5 Flash 模型。
- `Content Analyzer -> Google Gemini 2.5 Flash`：Content Analyzer 通过 API Calls 调用 Google Gemini 2.5 Flash 模型。
- `FastAPI Backend -.logs.-> Cloud Logging`：FastAPI 后端将日志信息发送到 Cloud Logging。
- `Artifact Registry -.deploys.-> FastAPI Backend`：Artifact Registry 部署 Docker 镜像到 FastAPI 后端。
- `Content Creation Coordinator -.stores.-> Cloud Storage`：Content Creation Coordinator 将数据存储到 Cloud Storage。

## 仓库语境与术语解释
- **React Frontend**：使用 Vite 和 React 18 构建，代码位于 `frontend/` 目录下，如 `frontend/src/App.jsx`。
- **FastAPI Backend**：使用 Python 3.11 和 Uvicorn 构建，代码位于 `backend/` 目录下，如 `backend/api_server.py`。
- **Vertex AI Agent Engine**：Google Cloud Platform 提供的服务，用于部署和管理 AI Agent。
- **Master Orchestrator**：负责协调和管理其他 Agent，代码位于 `content_creation_studio/agent.py`。
- **Google Gemini 2.5 Flash**：通过 Vertex AI 提供的 Google Gemini 模型，用于内容创作和分析。
- **Artifact Registry**：用于存储 Docker 镜像，方便部署。
- **Cloud Storage**：用于存储临时文件和数据，例如 Content Creation Coordinator 存储的数据。
- **Cloud Logging**：用于记录和监控系统的日志，方便调试和问题排查。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了内容创作工作室的整体架构，用户通过 Web Browser 发起请求，经过 React Frontend 和 FastAPI Backend，到达 Google Cloud Platform 的 Vertex AI Agent Engine。Master Orchestrator 协调 Content Creation Coordinator 和 Content Analyzer，它们通过 API Calls 调用 Google Gemini 2.5 Flash 模型。Artifact Registry 部署 Docker 镜像到 FastAPI Backend，Content Creation Coordinator 将数据存储到 Cloud Storage，FastAPI Backend 将日志信息发送到 Cloud Logging。该架构利用 Google Cloud Platform 和 Google Gemini 模型，实现智能、多代理的内容创作系统。
