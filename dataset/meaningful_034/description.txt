## 图类型与用途
该图是一个流程图，描述了用户领取和使用优惠券的完整流程。它展示了用户行为、优惠券核销流程以及系统模块之间的交互关系。该图可以用于理解优惠券系统的运作方式和优化流程。

## 图的整体布局
该图采用从左到右的布局，分为三个主要部分：用户行为、优惠券核销流程和系统模块。流程从用户触发优惠券领取事件开始，到结算完成结束。

图中包含三个子图：

## 连线、分支与汇聚关系
- A -> B：用户触发优惠券领取事件后，进入条件判断。
- B -- 符合 --> C：如果用户符合领取条件，则生成优惠券。
- B -- 不符合 --> D：如果用户不符合领取条件，则提示用户。
- C -> E：生成优惠券后，保存到用户账户。
- E -> F：保存优惠券后，用户获得优惠券。
- G -> H：用户发起结算请求后，检查用户是否有可用优惠券。
- H -- 有可用 --> I：如果有可用优惠券，则选择优惠券。
- H -- 无可用 --> J：如果没有可用优惠券，则按原价结算。
- I -> K：选择优惠券后，计算优惠金额。
- K -> L：计算优惠金额后，应用优惠。
- L -> M：应用优惠后，生成支付单。
- M -> N：生成支付单后，用户完成支付。
- N -> O：用户完成支付后，更新优惠券状态为已使用。
- O -> P：更新优惠券状态后，结算完成。
- J -> P：按原价结算后，结算完成。
- S1 -> B：用户服务提供用户是否符合领取条件的判断。
- S2 -> C：优惠券服务负责生成优惠券。
- S2 -> H：优惠券服务提供检查用户是否有可用优惠券的功能。
- S3 -> G：结算服务接收用户发起的结算请求。
- S3 -> K：结算服务负责计算优惠金额。
- S4 -> M：支付服务负责生成支付单。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **优惠券**：一种电子凭证，用户可以在购物或消费时使用以享受折扣或优惠。
- **结算**：计算商品或服务的总价，并进行支付的过程。
- **支付单**：记录支付信息的单据，用于确认支付行为。
- **用户账户**：存储用户个人信息、优惠券、积分等数据的账户。
- **结算请求**：用户发起的结算操作，包含购买的商品或服务信息。
- **核销**：将优惠券标记为已使用，防止重复使用。

## 可作为 QA Ground Truth 的高信息密度摘要
用户触发优惠券领取事件，系统判断用户是否符合条件，符合则生成优惠券并保存到用户账户，用户获得优惠券；用户发起结算请求，系统检查用户是否有可用优惠券，有则选择优惠券并计算优惠金额，应用优惠后生成支付单，用户完成支付，更新优惠券状态为已使用，结算完成；若用户不符合领取条件，则提示用户；若用户没有可用优惠券，则按原价结算，结算完成。
