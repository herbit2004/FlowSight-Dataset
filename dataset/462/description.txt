## Diagram Type & Purpose
This is a flowchart diagram. It illustrates a decision-making process for selecting the appropriate messaging strategy based on the sender's and receiver's relevance and the message's intent. The diagram serves as a guide for determining whether to use targeted, untargeted, or broadcast messaging.

## Overall Layout
The diagram's primary direction is top-down (TD). It starts with a single start node and branches based on a series of questions, leading to one of three end nodes.

## Subgraphs / Stages
No explicit subgraphs; logically divided into three stages:
1. Sender Relevance Check
2. Receiver Relevance Check / Intent Check
3. Messaging Strategy Selection

## Node-by-Node Description
- **Start / I need to send a message**: Represents the initial state where a message needs to be sent. visible in diagram; no further repository context available.
- **Q1 / Does it matter WHO sent it?**: A decision node that checks if the sender's identity is relevant to the message. visible in diagram; no further repository context available.
- **Q2 / Does it matter WHO receives it?**: A decision node that checks if the receiver's identity is relevant to the message. visible in diagram; no further repository context available.
- **Untargeted / Use UNTARGETED Global announcement**: Represents the messaging strategy where the message is a global announcement and the sender and receiver are irrelevant. visible in diagram; no further repository context available.
- **Q3 / Am I commanding someone to act?**: A decision node that checks if the message is a command. visible in diagram; no further repository context available.
- **Targeted / Use TARGETED Directed command**: Represents the messaging strategy where the message is a directed command and the sender or receiver is relevant. visible in diagram; no further repository context available.
- **Broadcast / Use BROADCAST Observable fact**: Represents the messaging strategy where the message is an observable fact and the sender is relevant, but the message is not a command. visible in diagram; no further repository context available.

## Edges, Branches & Convergence
- `Start --> Q1`: Indicates the start of the decision-making process.
- `Q1 -- No --> Q2`: If the sender's identity is irrelevant, proceed to check the receiver's relevance.
- `Q2 -- No --> Untargeted`: If the receiver's identity is also irrelevant, use the UNTARGETED messaging strategy.
- `Q2 -- Yes --> Targeted`: If the receiver's identity is relevant, use the TARGETED messaging strategy.
- `Q1 -- Yes --> Q3`: If the sender's identity is relevant, proceed to check if the message is a command.
- `Q3 -- Yes --> Targeted`: If the message is a command, use the TARGETED messaging strategy.
- `Q3 -- No --> Broadcast`: If the message is not a command, use the BROADCAST messaging strategy.
- `Q2 -- Yes --> Targeted` and `Q3 -- Yes --> Targeted`: The paths converge at the "Targeted" node.

## Repository Context & Terminology
- **UNTARGETED**: A messaging strategy where the message is a global announcement, and the sender and receiver are irrelevant.
- **TARGETED**: A messaging strategy where the message is a directed command, and the sender or receiver is relevant.
- **BROADCAST**: A messaging strategy where the message is an observable fact, and the sender is relevant, but the message is not a command.

## High-Density QA Ground Truth Summary
The flowchart begins with the user needing to send a message, initiating the decision process. The first question is whether the sender's identity matters. If the answer is "No," the flow proceeds to the question of whether the receiver's identity matters. If the receiver's identity also doesn't matter ("No"), the "UNTARGETED" messaging strategy is selected, characterized as a global announcement. However, if the receiver's identity does matter ("Yes"), the "TARGETED" messaging strategy is chosen, representing a directed command. Returning to the initial question, if the sender's identity does matter ("Yes"), the flow moves to the question of whether the message is a command. If it is a command ("Yes"), the "TARGETED" messaging strategy is selected. If it is not a command ("No"), the "BROADCAST" messaging strategy is selected, representing an observable fact. The "TARGETED" strategy is reached via two distinct paths, converging after different decision branches. The flowchart provides a structured approach to selecting the appropriate messaging strategy based on the context of the message and the relevance of the sender and receiver.
