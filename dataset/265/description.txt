## Diagram Type & Purpose
This is a flowchart diagram illustrating the flow of an HTTP request through a proxy server. It depicts the routing and processing of requests based on defined locations and plugins, showing how requests are handled by different upstream servers and response plugins before a final HTTP response is generated and logged. The diagram serves as a high-level overview of the request processing pipeline.

## Overall Layout
The diagram's primary direction is top-to-bottom (TD). It starts with a "New Request" node, flows through an HTTP server, branches based on request path, and converges at an "HTTP Response" node before ending at a "Logging" node.

## Repository Context & Terminology
- **HTTP Server**: A server that handles HTTP requests.
- **Location**: A specific route or configuration within the proxy server, defining how requests are handled based on host and path.
- **Proxy Plugin**: A module that intercepts and modifies requests before they are sent to the upstream server.
- **Upstream Server**: A backend server to which the proxy forwards requests.
- **Response Plugin**: A module that intercepts and modifies responses received from the upstream server.
- **Proxy Pass**: A directive that specifies the address of the upstream server to which requests should be proxied.
- **Logging**: The process of recording information about requests and responses for monitoring and debugging purposes.

## High-Density QA Ground Truth Summary
The process begins with a "New Request" entering the system and being received by the "HTTP Server". The server then routes the request based on its path. If the request's host is `HostA` and the path matches `/api/*`, it's routed to "Location A"; otherwise, if the path matches `/rest/*`, it's routed to "Location B". Each location then executes a list of proxy plugins ("Proxy Plugin List A" or "Proxy Plugin List B"). These plugins can proxy the request to one of several upstream servers. For Location A, the options are "Upstream A1" (`10.0.0.1:8001`) and "Upstream A2" (`10.0.0.2:8001`). For Location B, the options are "Upstream B1" (`10.0.0.1:8002`) and "Upstream B2" (`10.0.0.2:8002`). After receiving a response from an upstream server, response plugins ("Response Plugin List A" or "Response Plugin List B") are executed. Finally, the modified response is sent as the "HTTP Response" and then "Logging" occurs. If no upstream server is selected by the proxy plugins, the request proceeds directly to the "HTTP Response" stage. The "proxy pass" directives determine the target upstream server based on the configuration of the proxy plugins.
