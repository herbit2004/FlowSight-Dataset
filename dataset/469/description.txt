## 图类型与用途
这是一个流程图，展示了 GUARDRAIL 框架在大型语言模型（LLM）应用中的安全架构。该图描述了 MCP 客户端环境、GUARDRAIL 框架本身以及 MCP 服务端环境之间的关系和数据流，用于说明 GUARDRAIL 如何通过分层安全机制保护 LLM 应用。

## 图的整体布局
图采用从上到下的布局。顶部是 MCP 客户端环境，中间是 GUARDRAIL 框架的各个安全层，底部是 MCP 服务端环境。数据流从 MCP 客户端开始，经过 GUARDRAIL 的各个层，最终到达 MCP 服务端。

## 分组/子图/阶段说明
图中包含三个子图：
- **MCP Client Environment**：表示 MCP 客户端所在的运行环境。
- **GUARDRAIL**：表示整个安全框架，包含多个安全层。
- **MCP Server Environment**：表示 MCP 服务端所在的运行环境。

## 节点逐项说明
- **MC (MCP Client)**：MCP 客户端，代表发起请求的应用程序或用户。位于 "MCP Client Environment" 子图中。
- **IGL (Information Gateway Layer)**：信息网关层，负责接收来自 MCP 客户端的请求，并进行初步处理。
- **CVL (Context Verification Layer)**：上下文验证层，负责验证请求的上下文信息，确保其符合预期。
- **RCL (Request Control Layer)**：请求控制层，负责根据验证结果控制请求的访问权限和执行策略。
- **ECL (Execution Containment Layer)**：执行容器层，负责在受控环境中执行请求，防止恶意代码或操作对系统造成损害。
- **AML (Audit & Monitoring Layer)**：审计与监控层，负责记录和监控整个请求处理过程，以便进行安全分析和事件响应。
- **MS (MCP Server)**：MCP 服务端，代表实际处理请求的服务或资源。位于 "MCP Server Environment" 子图中。

## 连线、分支与汇聚关系
- `MC -- "MCP Protocol" --> IGL`：MCP 客户端通过 MCP 协议向信息网关层发送请求。
- `IGL --> CVL`：信息网关层将请求传递给上下文验证层。
- `CVL --> RCL`：上下文验证层将验证后的请求传递给请求控制层。
- `RCL --> ECL`：请求控制层将控制后的请求传递给执行容器层。
- `ECL -- "Contained Execution" --> MS`：执行容器层在受控环境中执行请求，并将执行结果传递给 MCP 服务端。
- `ECL --> AML`：执行容器层同时将执行过程中的审计信息传递给审计与监控层。

## 仓库语境与术语解释
- **GUARDRAIL**：根据 README 和 `2-technical-spec.md`，GUARDRAIL 是一个用于保护 LLM 应用的安全框架，通过分层安全机制对请求进行多重验证和控制。
- **MCP (Model Context Protocol)**：根据 `2-technical-spec.md`，MCP 是 GUARDRAIL 框架所应用的环境，用于在 LLM 应用生态系统中进行信息流控制。
- **Information Gateway Layer (IGL)**：根据 `2-technical-spec.md`，IGL 是 GUARDRAIL 的第一层，负责接收和初步处理来自 MCP 客户端的请求，执行流量策略、分类和传输安全。
- **Context Verification Layer (CVL)**：根据 `2-technical-spec.md`，CVL 负责验证请求的上下文信息，包括验证 attestation、trust scoring 和策略发现。
- **Request Control Layer (RCL)**：根据 `2-technical-spec.md`，RCL 根据验证结果控制请求的访问权限和执行策略，包括请求过滤、资源保护和行为控制。
- **Execution Containment Layer (ECL)**：根据 `2-technical-spec.md`，ECL 在受控环境中执行请求，防止恶意代码或操作对系统造成损害。
- **Audit & Monitoring Layer (AML)**：根据 `2-technical-spec.md`，AML 负责记录和监控整个请求处理过程，以便进行安全分析和事件响应。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 GUARDRAIL 框架如何保护 LLM 应用。MCP 客户端通过 MCP 协议发起请求，请求首先进入 Information Gateway Layer (IGL) 进行初步处理，然后依次经过 Context Verification Layer (CVL)、Request Control Layer (RCL) 和 Execution Containment Layer (ECL)，最终到达 MCP Server。同时，Execution Containment Layer (ECL) 会将执行过程中的审计信息传递给 Audit & Monitoring Layer (AML)。GUARDRAIL 通过分层安全机制，对来自 MCP 客户端的请求进行多重验证和控制，确保 LLM 应用的安全。
