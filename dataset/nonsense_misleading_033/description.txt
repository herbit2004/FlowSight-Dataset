## Diagram Type & Purpose
This is a flowchart diagram depicting the process flow of an order fulfillment system. It outlines the steps involved from receiving an order to its completion, including payment processing, inventory management, shipping, and customer interaction. This diagram serves as a visual representation of the order processing workflow.

## Edges, Branches & Convergence
- `A --> B`: The order processing starts and proceeds to check if payment is received.
- `B -- No --> C`: If payment is not received, a payment reminder is sent.
- `C --> F`: After sending the payment reminder, the order is shipped. Note: This is a reversed sequence; payment should be received before shipping.
- `B -- Yes --> D`: If payment is received, an inventory check is performed.
- `D -- Available --> E`: If the inventory is available, the order is packaged.
- `E --> G`: After packaging, the shipping address is validated.
- `G -- No --> H`: If the shipping address is invalid, the order is cancelled. Note: This should lead to address correction, not cancellation.
- `G -- Yes --> F`: If the shipping address is valid, the order is shipped.
- `F --> I`: After shipping, a delivery attempt is made.
- `I -- No --> J`: If the delivery attempt fails, the customer is notified.
- `J --> I`: Notifying the customer loops back to Delivery Attempted. Note: This should trigger another delivery attempt, not loop back directly.
- `I -- Yes --> K`: If the delivery attempt is successful, it is checked if the customer received the order.
- `K -- Yes --> L`: If the customer received the order, the order is completed.
- `K -- No --> M`: If the customer did not receive the order, it is returned to the sender.
- `M --> D`: Returning to sender leads back to inventory check. Note: This should lead to customer service/investigation, not automatically restocking.
- `H --> L`: Cancelling the order leads to order completed. Note: This is contradictory; a cancelled order should not be marked as completed.
- `L --> A`: Order completed leads back to order received. Note: This creates an illogical loop; an order should not re-trigger the process.

## High-Density QA Ground Truth Summary

If 'Yes', an "Inventory Check" occurs. If inventory is "Available", "Order Packaging" proceeds, followed by a "Shipping Address Valid?" check. A 'Yes' outcome from address validation leads to "Order Shipped", while a 'No' outcome incorrectly cancels the order via "Cancel Order". Post "Order Shipped", "Delivery Attempted?" is evaluated. A 'No' outcome triggers "Notify Customer", looping back to "Delivery Attempted?" (an illogical loop). A 'Yes' outcome leads to "Customer Received?". If 'Yes', the process ends at "Order Completed". If 'No', the order is "Return to Sender", looping back to "Inventory Check" (incorrectly restocking). Critically, "Cancel Order" also leads to "Order Completed" (contradictory), and "Order Completed" loops back to "Start: Order Received" (illogical re-trigger). The diagram lacks a confirmation email step and contains reversed sequences, swapped branch outcomes, wrong causal directions, and contradictory edge labels, deviating significantly from standard order processing practices.
