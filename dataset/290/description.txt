## Repository Context & Terminology
- **franken_agent_detection**: The component responsible for automatically discovering, scanning, normalizing, and deduplicating data from various sources.
- **frankensqlite**: A SQLite database used as the source of truth for the system, employing Write-Ahead Logging (WAL) for improved performance and concurrency.
- **frankensearch**: A search engine component utilizing BM25, Semantic RRF, and Fusion Reranking to provide relevant search results.
- **BM25**: A ranking function used by frankensearch to determine the relevance of documents to a given search query.
- **Semantic RRF (Reciprocal Rank Fusion)**: A technique used in frankensearch to combine the results of multiple search algorithms, improving the overall ranking quality.
- **TUI (FrankenTUI)**: A Textual User Interface built with Elm, providing a user-friendly way to interact with the system.
- **sources.toml**: A configuration file that specifies the remote data sources to be synchronized.

## High-Density QA Ground Truth Summary
The diagram illustrates a data pipeline that begins with multiple local sources (Codex, Cline, Gemini, Claude, OpenCode, Amp, Cursor, ChatGPT, Aider, Pi-Agent, Factory) and remote sources configured via `sources.toml` and synchronized using an SSH/rsync engine into a `remotes/Synced Data` directory. All these sources converge at the `franken_agent_detection` component, which automatically discovers, scans, normalizes, and deduplicates the data. The processed data is then persisted into a `frankensqlite` database, serving as the source of truth, and indexed by `frankensearch`. The `frankensearch` component utilizes BM25 for initial ranking, followed by Semantic RRF and Fusion Reranking to refine the search results. The `frankensqlite` database can be used to rebuild the `frankensearch` index. Finally, the system presents the data through two interfaces: a TUI (FrankenTUI) built with Elm for interactive analytics and a CLI/Robot interface that outputs JSON for automation. Queries from both the TUI and CLI are directed to the `frankensearch` component. The use of `frankensqlite` with WAL ensures data integrity and concurrency, while `frankensearch` provides efficient and relevant search capabilities.
