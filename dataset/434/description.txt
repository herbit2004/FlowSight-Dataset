## 图类型与用途
这是一个流程图，描述了 Knowledge-Assistant 应用中，用户消息如何从客户端传递到服务器，经过知识加载和 AI 处理，最终返回给客户端。它在仓库中的作用是展示数据流的架构。

## 图的整体布局
图整体采用从左到右的布局。左侧是客户端，中间是服务器，右侧是知识库。数据流从客户端开始，经过服务器处理，最终返回客户端。

## 分组/子图/阶段说明
图中包含三个子图：Client（客户端）、Server（服务器）和 Knowledge（知识库）。这些子图代表了应用的不同组成部分。

## 节点逐项说明
- **Chat Interface**：客户端的聊天界面，用户在此输入消息。
- **Next.js API**：服务器端的 Next.js API 接口，接收用户消息并处理。根据 `app/api/chat/stream/route.ts` 和 `app/api/chat/route.ts`，该 API 负责与 OpenRouter API 交互。
- **Knowledge Loader**：服务器端的知识加载器，负责从知识库读取文件。
- **OpenRouter API**：用于访问 AI 模型的 OpenRouter API。根据 README，该应用使用 OpenRouter 的免费模型。
- **content/*.md**：存储知识库的 Markdown 文件。根据 README，这些文件位于 `content/` 目录下。

## 连线、分支与汇聚关系
- `A --> B`：用户消息从聊天界面发送到 Next.js API。
- `B --> C`：Next.js API 将请求传递给 Knowledge Loader。
- `C --> E`：Knowledge Loader 读取 `content/*.md` 文件。
- `C --> D`：Knowledge Loader 将上下文和消息发送到 OpenRouter API。
- `D --> B`：OpenRouter API 返回流式响应给 Next.js API。
- `B --> A`：Next.js API 将 SSE 流发送回聊天界面。

## 仓库语境与术语解释
- **Knowledge-Assistant**：README 中描述的轻量级、基于文件的聊天助手，用于回答用户基于自定义知识文件的问题。
- **OpenRouter API**：一个用于访问多个 AI 模型的 API。该项目使用它来利用免费的 LLM 模型，如 Llama, Mimo, DeepSeek。相关代码见 `app/api/chat/stream/route.ts` 和 `app/api/chat/route.ts`。
- **content/*.md**：存储知识库的 Markdown 文件。这些文件被 Knowledge Loader 读取，作为 AI 模型的上下文。
- **Next.js API**：使用 Next.js 构建的 API 接口，负责处理客户端请求和与 OpenRouter API 交互。
- **SSE Stream**：服务器发送事件（Server-Sent Events），用于将 AI 生成的响应以流的形式发送回客户端。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Knowledge-Assistant 应用的数据流。用户在 Chat Interface 发送消息，消息传递到 Server 端的 Next.js API，然后 Knowledge Loader 从 `content/*.md` 读取知识文件，并将上下文和消息发送到 OpenRouter API。OpenRouter API 返回流式响应，Next.js API 将其作为 SSE Stream 发送回 Chat Interface。核心流程是“用户消息 -> Next.js API -> Knowledge Loader -> OpenRouter API -> Next.js API -> 用户界面”，其中 Knowledge Loader 读取 `content/*.md` 文件是关键环节。
