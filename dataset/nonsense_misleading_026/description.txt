## Diagram Type & Purpose

The diagram serves as a visual representation of the order processing logic, including payment verification, inventory management, shipping, and feedback collection.

The diagram has a top-down (TD) layout. It starts with the "Start: User Places Order" node at the top and flows downwards through a series of process and decision nodes, eventually leading to the "End: Order Completed" node at the bottom. ## Edges, Branches & Convergence
- `A --> B`: The order processing workflow starts by checking if payment has been received.
- `B -- No --> C`: If payment has not been received, send an order confirmation.
- `B -- Yes --> D`: If payment has been received, update the inventory.
- `D --> E`: After updating inventory, check if the inventory is sufficient.
- `E -- No --> F`: If inventory is not sufficient, notify the user of the delay.
- `F --> G`: After notifying the user, cancel the order.
- `E -- Yes --> H`: If inventory is sufficient, package the order.
- `H --> I`: After packaging the order, check if the shipping address is valid.
- `I -- Yes --> L`: If the shipping address is valid, contact customer service.
- `I -- No --> J`: If the shipping address is not valid, send a shipping notification.
- `J --> K`: After sending the shipping notification, deliver the order.
- `K --> N`: After delivering the order, check if the order has been received.
- `N -- No --> O`: If the order has not been received, investigate the non-delivery.
- `O --> N`: After investigating non-delivery, loop back to check if the order has been received.
- `N -- Yes --> P`: If the order has been received, send a feedback request.
- `P --> Q`: After sending the feedback request, check if feedback has been received.
- `Q -- No --> R`: If feedback has not been received, close the order.
- `Q -- Yes --> S`: If feedback has been received, process the feedback.
- `S --> R`: After processing feedback, close the order.
- `G --> T`: After cancelling the order, refund the payment.
- `T --> U`: After refunding the payment, close the order.
- `U --> B`: After closing the order, loop back to check if payment has been received.
- `L --> M`: After contacting customer service, resolve the address issue.
- `M --> H`: After resolving the address issue, loop back to package the order.
- `R --> End`: After closing the order, the order processing is completed.

## Repository Context & Terminology
- **Order**: A request from a user to purchase goods or services. In this diagram, the order is the central object being processed.
- **Payment**: The act of transferring money in exchange for goods or services. In this diagram, payment verification is a critical step.
- **Inventory**: The stock of goods available for sale. In this diagram, inventory is updated after payment and checked for sufficiency.
- **Shipping Address**: The address to which the order will be delivered. In this diagram, the validity of the shipping address is checked.
- **Feedback**: Information provided by the user about their experience with the order. In this diagram, feedback is collected and processed.
- **Order Confirmation**: A notification sent to the user confirming their order. In this diagram, the order confirmation is sent before payment verification.
- **Shipping Notification**: A notification sent to the user when their order has been shipped. In this diagram, the shipping notification is sent if the shipping address is invalid.

## High-Density QA Ground Truth Summary
The order processing workflow begins with a user placing an order (A), which immediately proceeds to sending an order confirmation (C) before checking for payment (B). If payment is received (B -- Yes --> D), the inventory is updated (D), otherwise the process ends. The system then checks if the inventory is sufficient (E). If not (E -- No --> F), the user is notified of a delay (F), the order is cancelled (G), payment is refunded (T), and the order is closed (U), looping back to the payment check (B). If inventory is sufficient (E -- Yes --> H), the order is packaged (H). The system then checks if the shipping address is valid (I). If it is valid (I -- Yes --> L), customer service is contacted (L), the address issue is resolved (M), and the process loops back to packaging the order (H). If the shipping address is not valid (I -- No --> J), a shipping notification is sent (J), and the order is delivered (K). The system then checks if the order has been received (N). If not (N -- No --> O), non-delivery is investigated (O), looping back to the order received check (N). If the order has been received (N -- Yes --> P), a feedback request is sent (P). The system then checks if feedback has been received (Q). If not (Q -- No --> R), the order is closed (R). If feedback has been received (Q -- Yes --> S), the feedback is processed (S), and the order is closed (R), leading to the end of the workflow (End). The diagram contains several illogical flows, such as sending an order confirmation before payment and looping back to packaging after resolving address issues.
