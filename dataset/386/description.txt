## High-Density QA Ground Truth Summary
The process begins with a client request originating from either Cherry Studio, NextChat WebUI, an HTML5 UI, or a standard API client. These requests are routed by the `/v1/*` dispatcher to the IdentityForge module for identity spoofing. From IdentityForge, requests are forwarded to either the image generation API (`/v1/images/generations`) or the chat adapter (`/v1/chat/completions`). The image generation API submits tasks to the server-side polling engine and returns task IDs to the client-side polling mode. The chat adapter sends data to the TransformStream for real-time SSE streaming, which provides progress feedback to Cherry Studio and triggers asynchronous polling. The polling engine and status query endpoint (`/v1/query/status`) interact with the Z-Image original interface to retrieve image URLs. Finally, the OpenAI Format module standardizes responses and sends them back to the client applications in various formats (Markdown/JSON, HTML, structured data). The system relies on a combination of REST APIs, WebSocket/HTTP connections, and SSE streaming to handle requests and deliver results.
