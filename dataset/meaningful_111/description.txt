## 图类型与用途
这是一个流程图，描述了API的身份验证流程。该图展示了用户请求API后，系统如何验证token，校验用户角色权限，并根据验证结果执行API操作或返回错误信息。

## 图的整体布局
该图采用从上到下的布局。流程从用户请求API开始，经过一系列验证和权限检查，最终返回数据或错误信息，到达结束节点。

## 分组/子图/阶段说明
图中包含一个名为“身份验证流程”的子图，该子图包含了token有效性检查和获取用户角色两个步骤。

## 节点逐项说明
- **A**：用户请求API的起始节点。
- **B**：检查token有效性的判断节点。
- **C**：获取用户角色的节点。
- **D**：角色权限校验的判断节点。
- **E**：返回401错误信息的节点，表示token无效。
- **F**：执行API操作的节点，表示用户有权限。
- **G**：返回403错误信息的节点，表示用户无权限。
- **H**：返回数据的节点，表示API操作成功。
- **I**：返回错误信息的节点，对应token无效的情况。
- **J**：返回错误信息的节点，对应用户无权限的情况。
- **K**：流程结束节点。

## 连线、分支与汇聚关系
- A -> B：用户请求API后，进入token有效性检查。
- B -- 有效 --> C：token有效，获取用户角色。
- B -- 无效 --> E：token无效，返回401错误。
- C -> D：获取用户角色后，进行角色权限校验。
- D -- 有权限 --> F：用户有权限，执行API操作。
- D -- 无权限 --> G：用户无权限，返回403错误。
- F -> H：API操作执行成功，返回数据。
- E -> I：返回401错误后，返回错误信息。
- G -> J：返回403错误后，返回错误信息。
- H -> K：返回数据后，流程结束。
- I -> K：返回错误信息后，流程结束。
- J -> K：返回错误信息后，流程结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **API**：应用程序编程接口，允许不同的软件系统相互通信。
- **Token**：令牌，用于身份验证和授权的字符串。
- **401**：HTTP状态码，表示未授权。
- **403**：HTTP状态码，表示禁止访问。
- **角色权限校验**：验证用户是否具有执行特定操作的权限。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求API，系统检查token有效性。若token有效，则获取用户角色并进行角色权限校验；若token无效，则返回401错误信息。若用户有权限，则执行API操作并返回数据；若用户无权限，则返回403错误信息。最终，流程结束，返回数据或错误信息。
