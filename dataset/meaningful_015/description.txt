## Diagram Type & Purpose
This is a flowchart diagram illustrating a user authentication and authorization process. It outlines the steps involved in verifying a user's identity, validating their roles, checking permissions, and granting access to a resource. The diagram serves as a visual representation of the authentication and authorization logic within a system.

## Overall Layout
The diagram flows from top to bottom (TD). It is hierarchically structured into two subgraphs: "User Authentication" and "Resource Server." The process starts with "User Login" and can end with either "Display Authentication Error," "Display Unauthorized Role Error," "Display Access Denied Error," or "Serve Resource."

## Subgraphs / Stages
The diagram contains two explicit subgraphs:
- **User Authentication**: This subgraph encompasses the initial steps of user login, authentication, and role retrieval.
- **Resource Server**: This subgraph represents the final stage where access is granted and the resource is served.

## Edges, Branches & Convergence
- `A --> B`: User login attempt triggers authentication.
- `B -- Yes --> C`: If authentication is successful, retrieve user roles.
- `B -- No --> X`: If authentication fails, display an authentication error.
- `C --> D`: After retrieving user roles, perform a user role lookup.
- `D --> E`: The user role lookup triggers the role validation service.
- `E --> F`: The role validation service leads to a check of role validity against the request.
- `F -- Yes --> G`: If the role is valid, proceed to permission validation.
- `F -- No --> Z`: If the role is not valid, display an unauthorized role error.
- `G --> H`: Permission validation service triggers a permission check.
- `H --> I`: The permission check leads to a decision on whether permission is allowed.
- `I -- Yes --> J`: If permission is allowed, record an audit log.
- `I -- No --> AA`: If permission is not allowed, display an access denied error.
- `J --> K`: Recording the audit log leads to granting access.
- `K --> L`: Granting access leads to serving the resource.

## Repository Context & Terminology
- **User Authentication**: The process of verifying a user's identity.
- **User Role Lookup**: The process of retrieving the roles associated with a user.
- **Role Validation Service**: A service that validates whether a user's role is authorized to access a specific resource.
- **Permission Validation Service**: A service that validates whether a user has the necessary permissions to perform a specific action on a resource.
- **Audit Log**: A record of events that occur within a system, used for security and compliance purposes.
- **Grant Access**: The process of allowing a user to access a resource.
- **Serve Resource**: The process of providing a resource to a user.
