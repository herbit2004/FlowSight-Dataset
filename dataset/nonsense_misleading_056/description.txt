## Edges, Branches & Convergence
- `A --> B`: User submits an order, initiating the payment process.
- `B -- No --> C`: If payment is unsuccessful, the flow proceeds to cancel the order.
- `B -- Yes --> D`: If payment is successful, the flow proceeds to ship the order.
- `D --> E`: The order is shipped, leading to a check for delivery status.
- `E -- Yes --> F`: If the order is delivered, an invoice is issued.
- `E -- No --> G`: If the order is not delivered, the delay is investigated.
- `G --> D`: After investigating the delay, the flow returns to shipping the order.

## High-Density QA Ground Truth Summary
The flowchart begins with a "User Submits Order," which then proceeds to a "Payment Successful?" decision. If the payment fails ("No" branch), the order is canceled, and the inventory is restocked. If the payment is successful ("Yes" branch), the order is shipped. After shipping, the flowchart checks "Order Delivered?". If not delivered ("No" branch), the system investigates the delay and then loops back to shipping the order again. If delivered ("Yes" branch), an invoice is issued, and then customer satisfaction is assessed. If the customer is satisfied ("Yes" branch), the order is closed; if not ("No" branch), a refund is processed, which then loops back to the user submitting a new order. After the order is closed, the inventory is restocked. Restocking then triggers generating a sales report, notifying logistics, and archiving order data, which then leads to closing the order again. The diagram contains several errors, including an illogical loop from refund processing back to order submission, restocking inventory after closing the order, and notifying logistics before archiving data. The "Ship Order" node lacks a packing stage, and the "Investigate Delay" node loops back to shipping without addressing the root cause of the delay.
