## 图类型与用途
这是一个流程图，描述了 AgentDock 框架中 AI Agent 处理用户查询的流程。它展示了用户输入如何被 Agent 处理，以及 Agent 如何通过 LLM 推理选择不同的工具来生成最终响应。该图在 README.md 中作为框架介绍的一部分。

## 图的整体布局
图采用从上到下的布局。流程从用户查询开始，经过 Agent 节点和工具选择，最终汇聚到最终响应。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为三个阶段：用户输入、Agent 处理与工具选择、工具执行与响应生成。

## 节点逐项说明
- **Input (User Query)**：用户输入的查询，是整个流程的起点。
- **Agent (AgentNode)**：代表 AgentDock 框架中的核心 Agent 组件，负责接收用户查询并进行处理。根据 `agentdock-core/src/nodes/agent-node.ts`，AgentNode 具有工具调用支持和编排功能。
- **ToolChoice (Tool Selection)**：代表工具选择环节，Agent 基于 LLM 的推理，决定使用哪个工具来处理用户查询。
- **ToolA (Deep Research Tool)**：一种工具，用于进行深度研究。
- **ToolB (Data Analysis Tool)**：另一种工具，用于进行数据分析。
- **ToolC (Direct Response)**：第三种工具，用于直接生成响应。
- **Response (Final Response)**：最终的响应，是 Agent 处理用户查询后生成的输出。

## 连线、分支与汇聚关系
- `Input -> Agent`：用户查询进入 Agent 节点。
- `Agent -> ToolChoice`：Agent 使用 LLM 进行推理，并根据推理结果选择合适的工具。
- `ToolChoice -- Option A --> ToolA`：如果选择 Option A，则使用 Deep Research Tool。
- `ToolChoice -- Option B --> ToolB`：如果选择 Option B，则使用 Data Analysis Tool。
- `ToolChoice -- Option C --> ToolC`：如果选择 Option C，则使用 Direct Response 工具。
- `ToolA -> Response`：Deep Research Tool 的输出作为最终响应的一部分。
- `ToolB -> Response`：Data Analysis Tool 的输出也作为最终响应的一部分，形成汇聚关系。
- `ToolC -> Response`：Direct Response 工具的输出也作为最终响应的一部分，形成汇聚关系。

## 仓库语境与术语解释
- **AgentDock Core**：根据 README.md，AgentDock Core 是一个开源的、后端优先的框架，用于构建和部署 AI Agent。
- **AgentNode**：根据 `agentdock-core/src/nodes/agent-node.ts`，AgentNode 是 AgentDock 框架中的核心组件，负责处理用户查询和选择合适的工具。
- **LLM Reasoning (Non-Deterministic)**：图中可见，但仓库上下文未进一步说明。表示 LLM 的推理过程具有非确定性，Agent 的行为也具有一定的灵活性和不确定性。
- **Tool**：根据 `agentdock-core/src/nodes/tool/index.ts`，Tool 是 Agent 可以使用的各种工具，用于执行不同的任务。
- **Configurable determinism**: README.md 提到，AgentDock 强调可配置的确定性，允许开发者控制 Agent 行为的可预测性。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 AgentDock 框架中 AI Agent 处理用户查询的流程。用户查询首先进入 Agent 节点，Agent 通过 LLM 推理选择合适的工具（Deep Research Tool、Data Analysis Tool 或 Direct Response）。最终，所有工具的输出都汇聚到最终响应。该流程的关键在于 LLM 的推理过程，它决定了使用哪个工具，也决定了最终响应的质量。AgentDock 框架强调可配置的确定性，允许开发者控制 Agent 行为的可预测性。
