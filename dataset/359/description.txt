## 图类型与用途
这是一个分层架构图，用于展示ServiceNow Helper的系统架构，包括前端、认证、后端服务、多供应商AI层以及ServiceNow集成。该图旨在展示各个组件之间的关系以及数据流向，在 `docs/ARCHITECTURE.md` 中作为系统概览的一部分。

## 图的整体布局
图采用从左到右的布局，分为五个主要层级：Frontend Layer、Authentication Layer、Backend Services、Multi-Provider AI Layer 和 ServiceNow Integration。数据流从左侧的 Frontend Layer 开始，经过各个层级，最终到达右侧的 ServiceNow Instance。

## 分组/子图/阶段说明
图中有五个显式子图，分别对应不同的层级：
- **Frontend Layer**：表示用户界面和前端逻辑。
- **Authentication Layer**：表示身份验证和会话管理。
- **Backend Services**：表示后端 API 和数据处理服务。
- **Multi-Provider AI Layer**：表示多供应商 AI 模型的管理和编排。
- **ServiceNow Integration**：表示与 ServiceNow 实例的集成。

## 节点逐项说明
- **Next.js 15 App**：使用 Next.js 框架构建的应用程序，是用户交互的入口。
- **React Components**：使用 React 构建的 UI 组件。
- **TailwindCSS**：CSS 框架，用于样式设计。
- **TypeScript**：编程语言，用于类型安全和代码维护。
- **JWT Middleware**：使用 JWT (JSON Web Token) 进行身份验证的中间件。
- **Session Management**：会话管理组件，用于跟踪用户状态。
- **API Routes**：后端 API 路由，处理来自前端的请求。
- **n8n Workflows**：使用 n8n 进行工作流自动化，根据 `n8n/init/workflow-template.json` 可知，n8n 用于处理不同类型的请求，例如 recommendation, documentation, script 等。
- **Streaming SSE**：使用服务器发送事件（SSE）进行实时数据流传输。
- **PostgreSQL**：数据库，用于存储数据。
- **AI Processing**：AI 处理模块，负责调用和处理 AI 模型。
- **Provider Manager**：供应商管理器，负责管理和选择不同的 AI 供应商。
- **OpenRouter**：AI 供应商 OpenRouter，根据 `src/app/api/providers/route.ts` 可知，该模块负责获取 active providers。
- **Hugging Face**：AI 供应商 Hugging Face。
- **Extensible Providers**：可扩展的 AI 供应商，允许添加其他供应商。
- **Orchestration Agent**：编排代理，负责协调其他代理的工作。
- **Planner Agent L/S**：规划代理，负责制定计划 (L/S 表示 Large/Small 两种变体)。
- **Coder Agent L/S**：编码代理，负责生成代码 (L/S 表示 Large/Small 两种变体)。
- **Architect Agent L/S**：架构代理，负责设计系统架构 (L/S 表示 Large/Small 两种变体)。
- **Process SME L/S**：流程专家代理，负责提供流程方面的专业知识 (L/S 表示 Large/Small 两种变体)。
- **ServiceNow Helper Companion App**：ServiceNow Helper 的配套应用，用于与 ServiceNow 实例交互。
- **Staging Tables**：临时表，用于在 ServiceNow Helper 和 ServiceNow 实例之间传输数据。
- **ServiceNow Instance**：ServiceNow 实例，是目标集成平台。

## 连线、分支与汇聚关系
- `Next.js 15 App -> React Components`：Next.js 应用使用 React 组件构建用户界面。
- `React Components -> TailwindCSS`：React 组件使用 TailwindCSS 进行样式设计。
- `React Components -> TypeScript`：React 组件使用 TypeScript 进行类型安全和代码维护。
- `JWT Middleware -> Session Management`：JWT 中间件用于管理用户会话。
- `API Routes -> n8n Workflows`：API 路由将请求传递给 n8n 工作流进行处理。
- `API Routes -> Streaming SSE`：API 路由使用 SSE 进行实时数据流传输。
- `n8n Workflows -> AI Processing`：n8n 工作流调用 AI 处理模块。
- `Streaming SSE -> n8n Workflows`：SSE 数据流传输到 n8n 工作流。
- `API Routes -> PostgreSQL`：API 路由与 PostgreSQL 数据库交互。
- `AI Processing -> PostgreSQL`：AI 处理模块将数据存储到 PostgreSQL 数据库。
- `Provider Manager -> OpenRouter`：供应商管理器管理 OpenRouter 供应商。
- `Provider Manager -> Hugging Face`：供应商管理器管理 Hugging Face 供应商。
- `Provider Manager -> Extensible Providers`：供应商管理器管理可扩展的供应商。
- `OpenRouter -> Orchestration Agent`：OpenRouter 供应商与编排代理交互。
- `Hugging Face -> Planner Agent L/S`：Hugging Face 供应商与规划代理交互。
- `OpenRouter -> Coder Agent L/S`：OpenRouter 供应商与编码代理交互。
- `Hugging Face -> Architect Agent L/S`：Hugging Face 供应商与架构代理交互。
- `OpenRouter -> Process SME L/S`：OpenRouter 供应商与流程专家代理交互。
- `ServiceNow Helper Companion App -> Staging Tables`：ServiceNow Helper 应用使用临时表进行数据传输。
- `Staging Tables -> ServiceNow Instance`：临时表将数据传输到 ServiceNow 实例。
- `n8n Workflows -> ServiceNow Helper Companion App`：n8n 工作流与 ServiceNow Helper 应用交互。
- `A -> E`：Frontend Layer 的 Next.js 15 App 连接到 Authentication Layer 的 JWT Middleware。
- `H -> L`：Backend Services 的 API Routes 连接到 Multi-Provider AI Layer 的 Provider Manager。
- `J -> K`：Backend Services 的 AI Processing 连接到 PostgreSQL 数据库。

## 仓库语境与术语解释
- **Next.js**：一个 React 框架，用于构建用户界面。该项目使用 Next.js 16.1.1，如 `README.md` 所示。
- **n8n**：一个工作流自动化平台，用于编排 AI 处理和 ServiceNow 集成。该项目使用 n8n 1.118.2，如 `README.md` 所示。
- **PostgreSQL**：一个关系型数据库，用于存储数据。该项目使用 PostgreSQL 15.x，如 `README.md` 所示。
- **JWT (JSON Web Token)**：一种用于身份验证的令牌格式。
- **SSE (Server-Sent Events)**：一种服务器推送技术，用于实时数据流传输。
- **Multi-Agent AI Architecture**：一种使用多个 AI 代理协同工作的架构，如 `README.md` 中所述。
- **Multi-Provider Support**：支持多个 AI 供应商，例如 OpenRouter 和 Hugging Face，如 `README.md` 中所述。
- **ServiceNow Instance**：目标集成平台，即 ServiceNow 实例。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 ServiceNow Helper 的系统架构，从 Frontend Layer 的 Next.js 15 App 开始，经过 Authentication Layer 的 JWT Middleware 进行身份验证，然后通过 Backend Services 的 API Routes 将请求传递给 n8n Workflows 进行处理。n8n Workflows 调用 Multi-Provider AI Layer 的 AI 供应商（如 OpenRouter 和 Hugging Face）进行 AI 处理，并将结果存储到 PostgreSQL 数据库。最后，通过 ServiceNow Integration 将数据传输到 ServiceNow Instance。该架构支持 Multi-Agent AI Architecture 和 Multi-Provider Support，以实现智能辅助功能。
