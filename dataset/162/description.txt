## 图类型与用途
这是一个流程图，用于展示 Cyber-AutoAgent 的核心架构，描述了用户输入如何驱动 Cyber-AutoAgent，以及 Cyber-AutoAgent 内部各个组件之间的交互关系。该图在 `docs/architecture.md` 中，用于解释系统的设计理念和组件间的协作方式。

## 图的整体布局
图采用从上到下的布局。顶部是用户输入，随后是 Cyber-AutoAgent 和 Agent 的核心处理流程，底部是各种工具和资源。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可以分为四个阶段：用户输入、核心处理、工具选择与执行、安全工具调用。

## 节点逐项说明
- **User Input**：用户输入，代表用户提供给 Cyber-AutoAgent 的指令或信息。
- **Cyber-AutoAgent**：Cyber-AutoAgent 的核心组件，是整个系统的入口点，负责接收用户输入并协调其他组件的工作。
- **Agent**：代理，是 Cyber-AutoAgent 的一个核心模块，负责根据用户输入和 AI 模型的决策，调用工具、访问内存系统，并执行相应的操作。
- **Tool Registry**：工具注册表，存储了 Cyber-AutoAgent 可以使用的各种工具的信息。
- **Memory System**：内存系统，用于存储和检索信息，供 Agent 使用。
- **AI Models**：AI 模型，用于做出决策，例如选择要使用的工具、确定要执行的操作等。
- **shell**：shell 命令执行工具，用于执行系统命令，例如调用安全工具。
- **editor**：文本编辑器，用于创建或修改文件和自定义工具。
- **swarm**：集群管理工具，用于部署并行 agents 以执行复杂任务。
- **load_tool**：工具加载器，用于动态加载新的工具。
- **http_request**：HTTP 请求工具，用于发送 HTTP 请求。
- **mem0_memory**：内存管理工具，用于存储和检索信息。
- **stop**：停止命令，用于终止执行。
- **Security Tools**：安全工具，代表实际执行安全任务的工具集合。
- **nmap, sqlmap, etc.**：具体安全工具的示例，例如 nmap（网络扫描器）和 sqlmap（SQL 注入工具）。
- **self install package**：自安装包，可能指可以自动安装的安全工具。

## 连线、分支与汇聚关系
- `User Input -> Cyber-AutoAgent`：用户输入被传递给 Cyber-AutoAgent。
- `Cyber-AutoAgent -> Agent`：Cyber-AutoAgent 将用户输入传递给 Agent 进行处理。
- `Agent -> Tool Registry`：Agent 根据需要从 Tool Registry 中选择合适的工具。
- `Agent -> Memory System`：Agent 可以访问 Memory System 来存储和检索信息。
- `Agent -> AI Models`：Agent 使用 AI Models 来辅助决策。
- `Tool Registry -> shell`：Tool Registry 包含 shell 工具。
- `Tool Registry -> editor`：Tool Registry 包含 editor 工具。
- `Tool Registry -> swarm`：Tool Registry 包含 swarm 工具。
- `Tool Registry -> load_tool`：Tool Registry 包含 load_tool 工具。
- `Tool Registry -> http_request`：Tool Registry 包含 http_request 工具。
- `Tool Registry -> mem0_memory`：Tool Registry 包含 mem0_memory 工具。
- `Tool Registry -> stop`：Tool Registry 包含 stop 工具。
- `shell -> Security Tools`：shell 工具可以调用 Security Tools。
- `Security Tools -> nmap, sqlmap, etc.`：Security Tools 包含具体的安全工具，例如 nmap 和 sqlmap。
- `Security Tools -> self install package`：安全工具可能包含自安装包。

## 仓库语境与术语解释
- **Cyber-AutoAgent**：一个自主的网络安全评估工具，使用 Strands 框架进行智能渗透测试。
- **Agent**：在 `src/modules/agents/cyber_autoagent.py` 中定义，负责协调工具、访问内存系统和使用 AI 模型。
- **Tool Registry**：存储了 Cyber-AutoAgent 可以使用的各种工具的信息，工具通过 `shell` 命令访问，如 `nmap` 和 `sqlmap`。
- **Memory System**：使用 Mem0 作为后端，用于存储和检索信息，相关代码在 `src/modules/tools/memory.py` 中。
- **AI Models**：可以使用 AWS Bedrock、Ollama 或 LiteLLM 作为模型提供商，配置在 `src/modules/config/manager.py` 中。
- **Strands framework**: Cyber-AutoAgent 使用 Strands 框架进行自主渗透测试，该框架支持元认知架构。
- **Meta-Everything Architecture**: Cyber-AutoAgent 采用的架构，允许系统通过元操作动态扩展其能力。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Cyber-AutoAgent 的核心架构，从用户输入开始，经过 Cyber-AutoAgent 和 Agent 的处理，Agent 根据 AI 模型的决策，从 Tool Registry 中选择合适的工具，并访问 Memory System 存储和检索信息。其中，Tool Registry 包含了 shell、editor、swarm 等工具，shell 工具可以调用 Security Tools，例如 nmap 和 sqlmap。该架构支持动态工具创建和子 agent 部署，并采用元认知评估来优化工具选择和策略。
