## 图类型与用途
该图是一个流程图，描述了一个分布式事务处理流程，涉及支付服务、库存服务和订单服务。它展示了在正常情况下完成订单的流程，以及在出现异常情况时进行补偿回滚的流程。

## 图的整体布局
该图采用从上到下的布局。整体上分为三个主要服务（PaymentService、InventoryService、OrderService）和一个补偿流程（Compensation）。起点是发起支付请求，终点是事务提交或补偿完成。

## 分组/子图/阶段说明
图中包含多个子图，分别代表不同的服务：
- **PaymentService**: 处理支付相关的操作，包括检查余额、扣减余额和记录流水。
- **InventoryService**: 处理库存相关的操作，包括预占库存、锁定库存。
- **OrderService**: 处理订单创建相关的操作。
- **Compensation**: 处理事务失败后的补偿流程，包括回滚库存预占、回滚订单创建和回滚支付。

## 节点逐项说明
- **A[发起支付请求]**: 流程的起始节点，表示用户发起支付请求。
- **B{检查账户余额足够?}**: 判断节点，检查用户账户余额是否足够支付。
- **C[扣减账户余额]**: 如果余额足够，则扣减用户账户余额。
- **D[记录支付流水]**: 记录支付流水信息。
- **E[预占库存]**: 预先占用库存，防止超卖。
- **F{库存预占成功?}**: 判断节点，检查库存预占是否成功。
- **G[锁定库存]**: 如果库存预占成功，则锁定库存。
- **I[创建订单]**: 创建订单记录。
- **J{订单创建成功?}**: 判断节点，检查订单是否创建成功。
- **K[事务提交]**: 如果所有操作都成功，则提交事务。
- **M[发送成功消息]**: 发送订单创建成功的消息。
- **Z[支付失败: 余额不足]**: 支付失败，因为余额不足。
- **H[库存不足]**: 库存不足，无法完成预占。
- **L[订单创建失败]**: 订单创建失败。
- **N[尝试回滚库存预占]**: 尝试回滚之前预占的库存。
- **O[尝试回滚订单创建]**: 尝试回滚订单创建操作。
- **P[通知PaymentService回滚支付]**: 通知支付服务回滚支付操作。
- **Q[PaymentService: 增加账户余额]**: 支付服务增加账户余额，回滚支付。
- **R[记录补偿流水]**: 记录补偿流水信息。
- **S[补偿完成]**: 补偿流程完成。

## 连线、分支与汇聚关系
- A -> B：发起支付请求后，检查账户余额是否足够。
- B -- 是 --> C：如果余额足够，则扣减账户余额。
- B -- 否 --> Z：如果余额不足，则支付失败。
- C -> D：扣减账户余额后，记录支付流水。
- D -> E：记录支付流水后，预占库存。
- E -> F：预占库存后，检查库存预占是否成功。
- F -- 是 --> G：如果库存预占成功，则锁定库存。
- F -- 否 --> H：如果库存预占失败，则库存不足。
- G -> I：锁定库存后，创建订单。
- I -> J：创建订单后，检查订单是否创建成功。
- J -- 是 --> K：如果订单创建成功，则提交事务。
- J -- 否 --> L：如果订单创建失败，则订单创建失败。
- K -> M：事务提交后，发送成功消息。
- H -> N：库存不足时，尝试回滚库存预占。
- L -> O：订单创建失败时，尝试回滚订单创建。
- O -> P：回滚订单创建后，通知PaymentService回滚支付。
- P -> Q：通知PaymentService回滚支付后，增加账户余额。
- Q -> R：增加账户余额后，记录补偿流水。
- R -> S：记录补偿流水后，补偿完成。
- N -> S：回滚库存预占后，补偿完成。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **分布式事务**: 涉及多个服务或数据库的事务，保证数据一致性。
- **支付服务 (PaymentService)**: 负责处理支付相关的业务逻辑，如余额检查、扣款等。
- **库存服务 (InventoryService)**: 负责处理库存相关的业务逻辑，如库存预占、锁定等。
- **订单服务 (OrderService)**: 负责处理订单相关的业务逻辑，如创建订单等。
- **预占库存**: 暂时占用库存，防止超卖，但未真正扣减。
- **锁定库存**: 确认订单后，真正扣减库存。
- **补偿**: 在事务失败后，通过回滚操作恢复到事务开始前的状态。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起支付请求，PaymentService检查账户余额，若余额足够则扣减余额并记录流水。InventoryService预占库存，若预占成功则锁定库存。OrderService创建订单，若订单创建成功则事务提交并发送成功消息。若余额不足，则支付失败；若库存不足，则尝试回滚库存预占；若订单创建失败，则尝试回滚订单创建，并通知PaymentService回滚支付，最终完成补偿。
