## Edges, Branches & Convergence
- `A --> B`: Real-time sensor data is fed into the time-based rolling window.
- `B -- Window Full --> C`: When the time-based rolling window is full, the data is passed to the pre-aggregated stats calculation.
- `B -- Window Open --> B`: If the time-based rolling window is not full, it continues to collect data.
- `C --> D`: Pre-aggregated stats are passed to the geo-partitioning stage.
- `D -- Region 1 --> E`: Data for Region 1 is passed to the average temperature calculation.
- `D -- Region 2 --> F`: Data for Region 2 is passed to the anomaly detection module.
- `E --> G`: The calculated average temperature is passed to the alert threshold check.
- `F -- Anomaly Found --> H`: If an anomaly is detected, the event is passed to the escalation service.
- `F -- No Anomaly --> I`: If no anomaly is detected, the data is used to store the baseline.
- `G --> J`: If the average temperature is above the threshold, an alert is generated and pushed to the dashboard.

## Repository Context & Terminology
- **Real-Time Sensor Data**: Data collected from physical sensors in real-time, such as temperature, pressure, or humidity sensors.
- **Time-Based Rolling Window**: A technique for aggregating data over a sliding time window, used for smoothing and trend analysis.
- **Pre-Aggregated Stats**: Statistical summaries calculated from the data within the rolling window, such as average, min, max, and standard deviation.
- **Geo-Partitioning**: Dividing data based on geographical regions, allowing for region-specific analysis and anomaly detection.
- **Anomaly Detection Module**: A system or algorithm that identifies data points that deviate significantly from the expected behavior.
- **Escalation Service**: A service that handles the escalation of detected anomalies, potentially triggering alerts or automated responses.
- **Baseline**: A reference point or set of data used to compare against current data to identify anomalies.
