## Diagram Type & Purpose
This is a flowchart diagram illustrating a software release process. It depicts the flow of code changes and tagging operations through different stages of development, staging, and production environments. The diagram serves as a visual representation of the release pipeline, outlining the steps involved in deploying code to various clusters.

## Overall Layout

## Edges, Branches & Convergence
- `D --> S`: Code changes flow from the development branch to the staging environment.
- `S --> P`: A stable tag is created from the staging environment for production.
- `S --> R`: An optional release branch is created from the staging environment.
- `S --> R`: Fixes are merged from staging to the release branch.
- `R --> P`: A stable tag is created from the release branch for production.
- `R --> P`: The release branch is tagged as stable.
- `D --> C1`: The development branch is deployed to the development cluster.
- `S --> C2`: The staging environment is deployed to the staging cluster.
- `P --> C3`: The production stable tag is deployed to the production cluster.
- `P --> C4`: The production stable tag is deployed to the operations cluster.

## Repository Context & Terminology
- **dev branch**: The primary branch for active development, where new features and bug fixes are implemented.
- **staging branch**: A branch used for integration and testing of code before it is released to production.
- **Soak testing**: A type of software testing where a system is subjected to a continuous, expected load for a long period of time to identify performance issues or memory leaks.
- **release/x.y branch**: An optional branch created for a specific release version (x.y), allowing for focused bug fixes and stabilization.
- **Production stable tag**: A tag applied to a specific commit in the repository, indicating that it is a stable and tested version suitable for production deployment.
- **Clusters**: Represent different environments (dev, staging, production, ops) where the application is deployed.
- **dev-01, stag-01, prod-01, ops-01**: Naming conventions for specific cluster instances.
