## 图类型与用途
这是一个流程图，展示了 Unity 游戏中使用 `DxMessaging` 系统进行消息传递的流程。它描述了一个消息（例如，敌人受到伤害）如何被多个监听者接收，体现了 `DxMessaging` 如何实现解耦的消息传递。

## 图的整体布局
图采用从左到右的布局。消息的发送者位于左侧，消息总线位于中间，多个消息监听者位于右侧。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：消息产生、消息广播、消息处理。

## 节点逐项说明
- **Source[Enemy]**：消息的发送者，代表游戏中的一个敌人实体。
- **"I took damage!"**：表示敌人发送的消息内容，表明敌人受到了伤害。
- **Radio[📻 Message Bus]**：`DxMessaging` 系统的核心组件，充当消息的中心枢纽，负责接收消息并将其分发给所有订阅者。根据 README，`DxMessaging` 旨在取代全局静态事件总线。
- **L1[Damage Numbers UI]**：代表一个监听者，负责显示敌人受到的伤害数值的 UI 界面。
- **L2[Achievement Tracker]**：代表一个监听者，负责追踪与敌人受到伤害相关的成就。
- **L3[Analytics]**：代表一个监听者，负责收集与敌人受到伤害相关的数据，用于游戏分析。
- **L4[Combat Log]**：代表一个监听者，负责记录战斗事件，包括敌人受到伤害的信息。

## 连线、分支与汇聚关系
- `Source[Enemy] -> Radio[📻 Message Bus]`：敌人发送一条消息 "I took damage!" 到消息总线。
- `Radio[📻 Message Bus] -> L1[Damage Numbers UI]`：消息总线将消息广播给伤害数值 UI。
- `Radio[📻 Message Bus] -> L2[Achievement Tracker]`：消息总线将消息广播给成就追踪器。
- `Radio[📻 Message Bus] -> L3[Analytics]`：消息总线将消息广播给分析模块。
- `Radio[📻 Message Bus] -> L4[Combat Log]`：消息总线将消息广播给战斗日志，形成分支关系。

## 仓库语境与术语解释
- **DxMessaging**：一个类型安全的消息传递系统，旨在取代 C# 事件和 UnityEvents，提供可观察和生命周期管理的消息传递模式。根据 README，它适用于解耦游戏系统。
- **Broadcast Message**：一种消息类型，由特定来源发出，任何监听者都可以使用。根据 `docs/concepts/message-types.md`，广播消息用于反应关于特定来源的“事实”。
- **Message Bus**：`DxMessaging` 的核心组件，负责消息的路由和分发。`Runtime/Core/MessageBus/MessageBus.cs` 定义了 `MessageBus` 类，它实现了 `IMessageBus` 接口。
- **MessagingComponent**：`Runtime/Unity/MessagingComponent.cs` 定义了 `MessagingComponent` 类，它是 Unity 的桥梁，为 `UnityEngine.GameObject` 托管 `Core.MessageHandler`。
- **MessageRegistrationToken**：用于启用和禁用消息注册。
- **DxBroadcastMessageAttribute**：`Runtime/Core/Attributes/DxBroadcastMessageAttribute.cs` 定义了该 Attribute，用于标记一个类型为广播消息。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 `DxMessaging` 系统中广播消息的传递流程。从 `Source[Enemy]` 发出 "I took damage!" 消息开始，该消息被发送到 `Radio[📻 Message Bus]`，然后消息总线将该消息广播给多个监听者，包括 `L1[Damage Numbers UI]`、`L2[Achievement Tracker]`、`L3[Analytics]` 和 `L4[Combat Log]`。该图体现了 `DxMessaging` 如何通过消息总线实现消息的解耦传递，使得消息发送者不需要知道哪些组件需要接收消息。`DxMessaging` 旨在取代传统的 C# 事件和 UnityEvents，提供更灵活和可维护的消息传递机制。
