## Repository Context & Terminology
- **Pulumi CLI**: The command-line interface is the primary way users interact with Pulumi.
- **SDKs (Go, Node.js, Python)**: These SDKs allow users to define infrastructure as code in their preferred programming languages.
- **Engine**: The core of Pulumi, responsible for orchestrating deployments and managing resources.
- **State**: Pulumi stores the state of your infrastructure to track changes and manage deployments. This state is typically stored in a cloud storage service like S3 or Azure Blob Storage.
- **Providers**: Pulumi Providers are plugins that interact with specific cloud providers or services.
- **Plugins**: Pulumi uses plugins to extend its functionality and support different languages and providers.
- **Go**: The Go programming language is used for the core components of the Pulumi system, such as the Engine, State Manager, and API Server.
- **Infrastructure as Code (IaC)**: Pulumi enables Infrastructure as Code, allowing users to define and manage infrastructure using code.

## High-Density QA Ground Truth Summary
The Pulumi architecture begins with a User interacting with the Pulumi CLI (written in Go). The CLI then interfaces with various SDKs (Go, Node.js, Python) depending on the user's chosen language. The CLI also communicates with the core Pulumi Engine (Go), which orchestrates deployments. The Engine interacts with the Resource Manager (Go), State Manager (Go), and Config Manager (Go) to manage resources, state, and configuration respectively. The Resource Manager utilizes Provider Plugins (written in various languages) to interact with external Cloud Providers like AWS, Azure, and GCP. The Engine also uses Language Plugins (various languages) to support different programming languages. The State Manager relies on the Storage Service (Go) to persist infrastructure state in Data Storage, such as S3 or Azure Blob. The Engine also interacts with the API Server (Go). The CLI interacts with Version Control systems like GitHub or GitLab. The end points of the diagram are the Cloud Providers and Version Control systems, representing the external systems that Pulumi interacts with. The Pulumi Engine, written in Go, is central to the entire process, managing the lifecycle of cloud resources and ensuring that the desired state of the infrastructure is achieved.
