## 图类型与用途
这是一个流程图，对比了两种方法来回答用户关于代码库依赖关系的问题：传统的图 RAG (Retrieval Augmented Generation) 方法和 GitNexus 的智能工具方法。它在仓库中的作用是展示 GitNexus 的智能工具在效率和准确性方面优于传统的图 RAG 方法。

## 图的整体布局
图整体采用从上到下的布局，左右并列展示两种方法。两种方法都从用户问题开始，最终给出答案。

## 分组/子图/阶段说明
图中包含两个子图，分别代表两种方法：
- **Traditional Graph RAG**：代表使用传统图 RAG 方法的流程。
- **GitNexus Smart Tools**：代表使用 GitNexus 智能工具的流程。

## 节点逐项说明
- **U1 (User)**：用户提出的问题，例如 "What depends on UserService?"。
- **LLM1 (LLM receives raw graph)**：大语言模型接收原始的图数据。
- **Q1 (Query 1: Find callers)**：代表一系列查询中的第一个查询，用于从图中提取相关信息，例如查找调用者。
- **Q2 (Query 2: What files?)**：代表一系列查询中的第二个查询，用于从图中提取相关信息，例如查找哪些文件。
- **Q3 (Query 3: Filter tests?)**：代表一系列查询中的第三个查询，用于从图中提取相关信息，例如过滤测试。
- **Q4 (Query 4: High-risk?)**：代表一系列查询中的第四个查询，用于从图中提取相关信息，例如查找高风险项。
- **OUT1 (Answer after 4+ queries)**：经过多次查询后，最终给出的答案。
- **U2 (User)**：用户提出的问题，与 U1 相同。
- **TOOL (impact UserService upstream)**：代表 GitNexus 的智能工具，用于分析 UserService 的上游依赖关系。根据 README，GitNexus 通过索引代码库并构建知识图谱，暴露智能工具给 AI agents。
- **PRECOMP (Pre-structured response: 8 callers, 3 clusters, all 90%+ confidence)**：代表预先结构化的响应，包含了关键信息，例如调用者数量、集群数量以及置信度。
- **OUT2 (Complete answer, 1 query)**：通过一次查询即可获得完整的答案。

## 连线、分支与汇聚关系
- `U1 -> LLM1`：用户问题传递给 LLM。
- `LLM1 -> Q1`：LLM 接收原始图数据后，进行第一次查询。
- `Q1 -> Q2`：第一次查询后，进行第二次查询。
- `Q2 -> Q3`：第二次查询后，进行第三次查询。
- `Q3 -> Q4`：第三次查询后，进行第四次查询。
- `Q4 -> OUT1`：经过多次查询后，生成最终答案。
- `U2 -> TOOL`：用户问题直接传递给 GitNexus 的智能工具。
- `TOOL -> PRECOMP`：GitNexus 的智能工具生成预先结构化的响应。
- `PRECOMP -> OUT2`：预先结构化的响应直接给出完整的答案。

## 仓库语境与术语解释
- **Graph RAG (Retrieval Augmented Generation)**：一种利用图结构进行信息检索和生成的方法。
- **LLM (Large Language Model)**：大型语言模型，用于处理和理解自然语言。
- **GitNexus Smart Tools**：GitNexus 提供的智能工具，用于代码库分析和依赖关系查询。根据 README，GitNexus 通过索引代码库并构建知识图谱，暴露智能工具给 AI agents。
- **UserService**：图中示例中用户查询的对象，代表代码库中的一个服务。
- **MCP (Message passing)**：根据 README，MCP 是 GitNexus 连接 AI agents 的方式。
- **KuzuDB**：根据 README，GitNexus 使用 KuzuDB 作为存储，用于存储索引后的代码仓库数据。

## 可作为 QA Ground Truth 的高信息密度摘要
该图对比了传统图 RAG 方法和 GitNexus 智能工具在回答代码库依赖关系问题上的流程。传统方法需要多次查询 LLM 才能得到答案，而 GitNexus 通过预先结构化的响应，只需一次查询即可给出完整答案。GitNexus 的流程是：用户提问，通过智能工具分析，生成预结构化响应，最终给出答案。传统 RAG 的流程是：用户提问，LLM 接收图数据，多次查询，最终给出答案。GitNexus 通过预计算和结构化数据，减少了 LLM 的查询次数，从而提高了效率。
