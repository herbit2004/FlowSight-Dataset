## Edges, Branches & Convergence
- `Q --> E`: The user query is passed to the embedding process.
- `E --> V`: The embedded query is used to perform a vector search in Pinecone.
- `V --> K`: The results of the vector search are filtered to the top K most relevant.
- `K --> G`: The top K results are enriched using a Neo4j graph database.
- `G --> M`: The enriched results are merged and deduplicated.
- `M --> LLM`: The merged and deduplicated results are used to create an augmented prompt.

## Repository Context & Terminology
- **User Query**: The initial input provided by the user, which can be a question, a statement, or any other form of text.
- **Embed Query**: The process of converting the user query into a vector representation, typically using a pre-trained language model. This vector representation captures the semantic meaning of the query.
- **Pinecone**: A managed vector database service that allows for efficient similarity search on high-dimensional vectors.
- **Vector Search**: The process of finding vectors in a vector database that are similar to a given query vector. Similarity is typically measured using cosine similarity or other distance metrics.
- **Top-K Results**: The K most similar vectors returned by the vector search.
- **Neo4j**: A graph database management system that stores data in the form of nodes and relationships.
- **Graph Enrichment**: The process of adding information to the search results by querying a graph database. This can involve finding related entities, properties, or relationships.
- **Merge + Dedupe**: The process of combining information from different sources and removing duplicate entries.
- **Augmented Prompt**: A modified or enhanced version of the original user query, typically created by adding relevant context or information. This augmented prompt is then used as input to a language model.

## High-Density QA Ground Truth Summary
The process begins with a "User Query" which is then transformed into a vector embedding via the "Embed Query" stage. This embedding is then used to perform a "Pinecone Vector Search," retrieving the "Top-K Results" based on similarity. These results are subsequently enriched using a "Neo4j Graph Enrichment" process, leveraging the relationships and data stored in the graph database to add context and relevant information. The enriched data is then processed through a "Merge + Dedupe" stage to consolidate information and remove redundancies. Finally, the resulting data is used to generate an "Augmented Prompt." This augmented prompt is designed to provide a more comprehensive and informative input for a downstream application, such as a language model. The use of Pinecone allows for efficient similarity search, while Neo4j provides a structured way to incorporate relational knowledge into the prompt. The final "Augmented Prompt" is the culmination of these steps, representing a refined and contextually enriched version of the original user query.
