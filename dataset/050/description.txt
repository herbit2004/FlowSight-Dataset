## 图类型与用途
这是一个流程图，描述了用户访问 GitHub 时的登录和数据加载流程。它用于说明用户是否已登录，以及根据登录状态展示不同的操作流程。

## 图的整体布局
图采用从上到下的布局。流程从顶部的起始节点开始，经过判断和处理，最终到达底部的结束节点。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：初始状态判断、登录/仪表盘显示、数据加载与结束。

## 节点逐项说明
- **A (Inicio)**：流程的起始点，表示用户开始访问 GitHub。
- **B (¿Es usuario?)**：判断节点，询问用户是否已登录。
- **C (Mostrar dashboard)**：如果用户已登录，则显示用户的仪表盘。
- **D (Mostrar login)**：如果用户未登录，则显示登录页面。
- **E (Cargar datos)**：加载用户仪表盘所需的数据。
- **F (Verificar credenciales)**：验证用户在登录页面输入的用户名和密码是否正确。
- **G (Mostrar error)**：如果用户输入的用户名和密码不正确，则显示错误信息。
- **H (Fin)**：流程的结束点，表示数据加载完成。

## 连线、分支与汇聚关系
- `A -> B`：流程从起始点进入用户判断阶段。
- `B -- Sí --> C`：如果用户已登录，则显示仪表盘。
- `B -- No --> D`：如果用户未登录，则显示登录页面。
- `C -> E`：显示仪表盘后，加载数据。
- `D -> F`：显示登录页面后，验证用户凭据。
- `F -- Válidas --> C`：如果凭据有效，则显示仪表盘。
- `F -- Inválidas --> G`：如果凭据无效，则显示错误信息。
- `G -> D`：显示错误信息后，返回登录页面。
- `E -> H`：加载数据完成后，流程结束。

## 仓库语境与术语解释
- **GitHub**: README 介绍了 GitHub 是一个允许存储、共享和协作代码的平台。
- **Repositorio**: README 提到仓库是 GitHub 上代码的集中存储位置，用于管理和跟踪更改。
- **Dashboard**: 图中指用户登录后看到的个性化信息和功能界面，图中可见，但仓库上下文未进一步说明。
- **Git**: README 提到 GitHub 基于 Git，一个用于跟踪文件更改的开源版本控制系统。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了用户访问 GitHub 的登录和数据加载流程。流程从判断用户是否已登录开始，如果已登录则显示仪表盘并加载数据，否则显示登录页面并验证用户凭据。验证成功后显示仪表盘并加载数据，验证失败则显示错误信息并返回登录页面。核心流程是“判断用户 -> 显示仪表盘/登录页面 -> 验证凭据 -> 加载数据”，最终确保只有已登录用户才能访问其个性化的仪表盘和数据。
