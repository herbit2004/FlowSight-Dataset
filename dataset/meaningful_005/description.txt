## 图类型与用途
该图是一个流程图，描述了业务请求处理过程中缓存的使用策略。它展示了请求如何通过缓存层和持久层获取数据，以及缓存的淘汰和清理机制。该图可以帮助理解缓存系统的工作原理和数据流向。

## 图的整体布局
该图采用从上到下的布局。整体上分为应用服务、缓存层、持久层和缓存清理服务四个部分。流程从业务请求入口开始，最终返回业务响应。

## 分组/子图/阶段说明
图中包含四个子图：
- **应用服务**：处理业务请求的入口。
- **缓存层**：包含分布式缓存集群，用于缓存数据。
- **持久层**：数据存储服务，用于存储原始数据。
- **缓存清理服务**：监听数据变更事件，并清理缓存。

## 连线、分支与汇聚关系
- A -> B：业务请求进入缓存查询。
- B -- 是 --> E：缓存命中。
- E -> F：返回缓存数据。
- F -> G：业务响应。
- B -- 否 --> H：缓存未命中。
- H -> I：请求数据存储服务。
- I -> D：请求发送到数据存储服务。
- D -> J：返回数据。
- J -> K：构建缓存数据。
- K -> L：写入缓存。
- L -> C：写入缓存到分布式缓存集群。
- L -> M：设置过期时间。
- M -> N：返回数据。
- N -> G：业务响应。
- C -> P：缓存淘汰策略判断。
- P -- 达到上限 --> Q：触发缓存淘汰。
- Q -> R：选择淘汰数据。
- R -> S：移除缓存数据。
- T -> U：数据变更事件传递到接收事件节点。
- U -> V：判断是否需要清理缓存。
- V -- 是 --> W：删除缓存。
- W -> C：删除缓存数据。
- V -- 否 --> X：忽略事件。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **缓存**：一种高速数据存储层，用于存储频繁访问的数据，以减少访问底层存储的延迟。
- **缓存命中**：当请求的数据存在于缓存中时，称为缓存命中。
- **缓存未命中**：当请求的数据不存在于缓存中时，称为缓存未命中。
- **缓存淘汰**：当缓存空间不足时，需要移除部分缓存数据，这个过程称为缓存淘汰。
- **过期时间**：缓存数据在缓存中存储的时间限制，超过该时间后，缓存数据会被自动移除。
- **数据存储服务**：用于持久化存储数据的服务，例如数据库。
- **数据变更事件**：当数据存储服务中的数据发生变化时，会触发数据变更事件。

## 可作为 QA Ground Truth 的高信息密度摘要
业务请求首先进入缓存查询，如果缓存命中，则直接返回缓存数据并响应业务；如果缓存未命中，则请求数据存储服务，获取数据后构建缓存数据并写入缓存，同时设置过期时间，最终返回数据并响应业务。缓存层会根据缓存淘汰策略移除缓存数据。缓存清理服务监听数据变更事件，并根据事件判断是否需要清理缓存。
