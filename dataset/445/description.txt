## Repository Context & Terminology
- **Presentation Layer**: The outermost layer responsible for handling user interaction and displaying data.
- **Application Layer**: The layer that contains the application's business logic and orchestrates the execution of use cases.
- **Domain Layer**: The layer that represents the core business domain and contains entities, value objects, and domain services.
- **Infrastructure Layer**: The layer that provides access to external resources such as databases, file systems, and external APIs.
- **Services**: Components that encapsulate business logic and provide specific functionalities.
- **Use Cases**: Specific scenarios or interactions that users have with the system.
- **DTOs**: Data Transfer Objects, used to transfer data between layers.
- **Entities**: Objects that represent real-world concepts in the domain.
- **Value Objects**: Immutable objects that represent a value.
- **Domain Services**: Services specific to the domain logic.
- **Business Rules**: Rules that govern the system's behavior.

## High-Density QA Ground Truth Summary
The architecture diagram illustrates a layered application design. The process starts from the Presentation Layer, specifically the MCP Tools API and CLI Interface, which initiate actions within the Application Layer's Services and Use Cases. These Application Layer components then interact with the Domain Layer, accessing Entities, Value Objects, Domain Services, and Business Rules to implement core business logic. Simultaneously, the Application Layer interacts with the Infrastructure Layer, utilizing the File System, Database, External APIs, and Logging for data persistence, integration, and monitoring. Domain Services also directly interact with the File System. The diagram highlights the separation of concerns, with the Presentation Layer focused on user interaction, the Application Layer on business logic orchestration, the Domain Layer on core business concepts, and the Infrastructure Layer on external resource access. DTOs are used for data transfer between layers, ensuring loose coupling. The architecture supports modularity and maintainability by isolating different aspects of the system into distinct layers.
