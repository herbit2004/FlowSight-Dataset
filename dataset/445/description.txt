## 图类型与用途
这是一个分层架构图，展示了 MCP SDD Server 的四层架构：Presentation Layer, Application Layer, Domain Layer, Infrastructure Layer。它在仓库中的作用是概括系统的整体架构和模块之间的关系，对应 `ARCHITECTURE.md` 中的 Layered Architecture 章节。

## 图的整体布局
图整体采用从左到右的布局。最左侧是 Presentation Layer，然后依次是 Application Layer, Domain Layer, Infrastructure Layer。数据流从 Presentation Layer 开始，经过 Application Layer 和 Domain Layer，最终到达 Infrastructure Layer。

## 分组/子图/阶段说明
图中显式地分为四个子图，分别对应四层架构：
- **Presentation Layer**：负责处理用户交互和 MCP 协议。
- **Application Layer**：负责协调领域服务和基础设施，实现用例。
- **Domain Layer**：包含核心业务逻辑和领域模型。
- **Infrastructure Layer**：提供对外部服务的访问和框架集成。

## 节点逐项说明
- **P1[MCP Tools API]**：表示 MCP Tools 的 API 接口，属于 Presentation Layer。
- **P2[CLI Interface]**：表示命令行接口，属于 Presentation Layer。
- **A1[Services]**：表示应用层服务，负责协调领域服务和基础设施。根据 `ARCHITECTURE.md`，关键服务包括 `RequirementsClarificationService`, `WorkflowEngineService`, `SteeringDocumentService`, `ProjectInitializationService`。
- **A2[Use Cases]**：表示用例，属于 Application Layer。
- **A3[DTOs]**：表示数据传输对象，属于 Application Layer。
- **D1[Entities]**：表示领域实体，属于 Domain Layer。
- **D2[Value Objects]**：表示值对象，属于 Domain Layer。
- **D3[Domain Services]**：表示领域服务，属于 Domain Layer。
- **D4[Business Rules]**：表示业务规则，属于 Domain Layer。
- **I1[File System]**：表示文件系统，属于 Infrastructure Layer。
- **I2[Database]**：表示数据库，属于 Infrastructure Layer。
- **I3[External APIs]**：表示外部 API 接口，属于 Infrastructure Layer。
- **I4[Logging]**：表示日志记录，属于 Infrastructure Layer。

## 连线、分支与汇聚关系
- `P1 & P2 --> A1 & A2`：MCP Tools API 和 CLI Interface 都与 Application Layer 的 Services 和 Use Cases 交互。
- `A1 & A2 --> D1 & D2 & D3 & D4`：Application Layer 的 Services 和 Use Cases 与 Domain Layer 的 Entities, Value Objects, Domain Services, Business Rules 交互。
- `A1 & A2 --> I1 & I2 & I3 & I4`：Application Layer 的 Services 和 Use Cases 与 Infrastructure Layer 的 File System, Database, External APIs, Logging 交互。
- `D3 --> I1`：Domain Services 与 File System 交互。

## 仓库语境与术语解释
- **MCP (Model Context Protocol)**：一种协议，用于 AI 客户端与服务器之间的通信，`README.md` 中提到 "A Model Context Protocol (MCP) server implementing Spec-Driven Development (SDD) workflows"。
- **SDD (Spec-Driven Development)**：一种软件开发方法，通过规范驱动开发过程，`README.md` 中提到 "SDD now uses a **hybrid architecture** for better token efficiency"。
- **Presentation Layer**：负责处理用户交互和 MCP 协议，对应 `/src/infrastructure/mcp` 和 `/src/adapters` 目录。
- **Application Layer**：负责协调领域服务和基础设施，实现用例，对应 `/src/application/services` 目录。
- **Domain Layer**：包含核心业务逻辑和领域模型，对应 `/src/domain` 目录。
- **Infrastructure Layer**：提供对外部服务的访问和框架集成，对应 `/src/infrastructure` 目录。
- **Entities, Value Objects, Domain Services, Business Rules**：这些是 Domain-Driven Design (DDD) 的核心概念，用于组织和表达业务逻辑。`ARCHITECTURE.md` 中提到 "Domain-Driven Design (DDD): Clear separation between domain logic, application services, and infrastructure"。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 MCP SDD Server 的四层架构，从 Presentation Layer 的 MCP Tools API 和 CLI Interface 开始，经过 Application Layer 的 Services 和 Use Cases，与 Domain Layer 的 Entities, Value Objects, Domain Services, Business Rules 交互，最终到达 Infrastructure Layer 的 File System, Database, External APIs, Logging。数据流从用户界面到数据存储，体现了分层架构的设计原则。`ARCHITECTURE.md` 描述了每一层的职责，例如 Application Layer 负责协调领域服务和基础设施，而 Domain Layer 包含核心业务逻辑。
