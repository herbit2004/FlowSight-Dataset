- `AI Agent / LLM --> Registry API`: AI Agent executes tools via the Registry API.

## Repository Context & Terminology
- **Registry API**: The central API for interacting with the registry, providing endpoints for searching, executing, and managing tools.
- **OAuth Proxy**: Handles authentication and authorization, ensuring secure access to the registry's resources.
- **Meilisearch**: A fast and relevant search engine used for indexing and querying the registry's metadata.
- **Runtime Environment**: The environment where tools are executed, providing isolation and resource management.
- **Secure Sandbox**: A secure execution environment that isolates tools from the host system, preventing malicious code from causing harm.
- **MCP Server**: The server responsible for managing and controlling the execution of tools within the runtime environment.

## High-Density QA Ground Truth Summary
The diagram illustrates the architecture of a self-hosted registry system. The process begins with either a User/Developer searching for tools via the Registry API or an AI Agent/LLM executing tools via the Registry API after authenticating through the OAuth Proxy. The Registry API then interacts with several core components. It queries the Meilisearch index for search results and reads metadata from the Registry Data store. The Registry API can also trigger the execution of tools in either the Local Exec environment or the Secure Sandbox. Both Local Exec and Secure Sandbox environments ultimately execute processes on the MCP Server. The choice between Local Exec and Secure Sandbox depends on the tool's security requirements. The OAuth Proxy handles authentication flows initiated by the AI Agent/LLM, ensuring secure access to the registry. The Registry API serves as the central point of interaction, coordinating search, data retrieval, and tool execution within the self-hosted environment. The MCP Server represents the final stage where tools are executed, completing the workflow.
