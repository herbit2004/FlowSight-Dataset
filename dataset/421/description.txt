## 图类型与用途
这是一个流程图，描述了规范驱动开发（SDD）的流程，从用户需求开始，经过规范制定和技术方案设计，最终到代码实现和一致性校验。它在仓库中的作用是展示 SDD 的整体架构和流程，强调规范的重要性。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户需求，中间是规范制定和技术方案设计阶段，底部是代码实现和一致性校验环节。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分成三个阶段：需求与规范制定、技术方案设计、代码实现与验证。

## 节点逐项说明
- **用户需求**：代表用户最初提出的需求，通常是模糊的、不明确的。
- **SpecMaster 需求规范智能体 (SpecMasterSystemPrompts.md)**：代表 SpecMaster 智能体，其作用是将用户需求转化为详细的、可执行的规范文档。对应于 `SpecMasterSystemPrompts.md` 文件，该文件是 SpecMaster 智能体的系统提示词。
- **Spec 规范文档 (可执行规范)**：代表由 SpecMaster 生成的规范文档，强调其是“可执行规范”，意味着它不仅是文档，还可以用于验证和测试。
- **TechPlan 技术方案智能体 (TechPlanSystemPrompts.md)**：代表 TechPlan 智能体，其作用是基于 Spec 规范文档生成详细的技术方案。对应于 `TechPlanSystemPrompts.md` 文件，该文件是 TechPlan 智能体的系统提示词。
- **技术方案文档**：代表由 TechPlan 生成的技术方案文档，详细描述了如何实现 Spec 规范。
- **代码实现**：代表最终的代码实现，它是基于技术方案文档编写的。
- **一致性校验**：代表一致性校验环节，用于确保 Spec 规范文档、技术方案文档和代码实现之间的一致性。
- **规范作为通用语言**：标注 Spec 规范文档作为业务、产品、技术团队沟通的统一语言。
- **持续精化 验证**：标注一致性校验环节可以持续精化和验证规范、方案、代码的一致性。

## 连线、分支与汇聚关系
- `用户需求 -> SpecMaster 需求规范智能体 (SpecMasterSystemPrompts.md)`：用户需求流向 SpecMaster 智能体。
- `SpecMaster 需求规范智能体 (SpecMasterSystemPrompts.md) -> Spec 规范文档 (可执行规范)`：SpecMaster 智能体生成 Spec 规范文档。
- `Spec 规范文档 (可执行规范) -> TechPlan 技术方案智能体 (TechPlanSystemPrompts.md)`：Spec 规范文档流向 TechPlan 智能体。
- `TechPlan 技术方案智能体 (TechPlanSystemPrompts.md) -> 技术方案文档`：TechPlan 智能体生成技术方案文档。
- `技术方案文档 -> 代码实现`：技术方案文档指导代码实现。
- `Spec 规范文档 (可执行规范) -.-> 一致性校验`：Spec 规范文档参与一致性校验。
- `技术方案文档 -.-> 一致性校验`：技术方案文档参与一致性校验。
- `代码实现 -.-> 一致性校验`：代码实现参与一致性校验，形成汇聚关系。
- `一致性校验 -.-> Spec 规范文档 (可执行规范)`：一致性校验的结果可以反馈到 Spec 规范文档，进行修正和改进。
- `一致性校验 -.-> 技术方案文档`：一致性校验的结果可以反馈到技术方案文档，进行修正和改进。
- `代码实现 -.-> 技术方案文档`：代码实现也可以反馈到技术方案文档，进行修正和改进。
- `Spec 规范文档 (可执行规范) -.-> 规范作为通用语言`：强调规范作为通用语言。
- `一致性校验 -.-> 持续精化 验证`：强调持续精化和验证。

## 仓库语境与术语解释
- **SpecMaster**：一个专业的规范驱动开发（SDD）智能助手，旨在引导用户按照 SDD 核心原则，完成从"模糊需求→Spec规范→技术方案"的全流程落地。
- **TechPlan**：一个专业的技术方案制定智能助手，其核心使命是基于已完成的 Spec 规范文档，制定完整的技术实现方案。
- **SDD (Specification-Driven Development)**：规范驱动开发，一种以规范为中心的开发方法，强调规范的可执行性和可追溯性。
- **Spec 规范文档**：由 SpecMaster 生成的规范文档，是可执行的，可以用于验证和测试。
- **技术方案文档**：由 TechPlan 生成的技术方案文档，详细描述了如何实现 Spec 规范。
- **一致性校验**：确保 Spec 规范文档、技术方案文档和代码实现之间的一致性。
- **`SpecMasterSystemPrompts.md`**：SpecMaster 智能体的系统提示词文件，定义了 SpecMaster 的行为和职责。
- **`TechPlanSystemPrompts.md`**：TechPlan 智能体的系统提示词文件，定义了 TechPlan 的行为和职责。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了规范驱动开发（SDD）的流程。从用户需求开始，SpecMaster 智能体将需求转化为可执行的 Spec 规范文档。然后，TechPlan 智能体基于 Spec 规范生成技术方案文档，最终指导代码实现。通过一致性校验环节，确保规范、方案和代码的一致性，并通过反馈循环进行持续精化和验证。其中，`SpecMasterSystemPrompts.md` 和 `TechPlanSystemPrompts.md` 分别定义了 SpecMaster 和 TechPlan 智能体的行为和职责。
