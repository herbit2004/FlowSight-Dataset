## Diagram Type & Purpose
This is a flowchart diagram illustrating the indexing pipeline and search serving process for a search engine. It depicts the flow of data and operations from a user search query to the point where search nodes are ready to serve results. The diagram serves as a high-level overview of the indexing and search serving architecture.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is divided into three subgraphs representing different stages of the process. The start node is "User Search Query" and the end node is "Search Nodes Ready to Serve."

## Subgraphs / Stages
The diagram is divided into three subgraphs:
- **Client Request**: Represents the initial stage where a user submits a search query.
- **Indexing Pipeline**: Represents the core indexing process, including incremental updates, schema validation, and index segment creation.
- **Index Serving**: Represents the process of pushing index segments to search nodes and making them available for serving search queries.

## Edges, Branches & Convergence
- `A --> B`: A user search query is sent to the query router.
- `B --> C`: The query router sends the query to the indexing pipeline to determine if an incremental update is needed.
- `C -- Yes --> D`: If an incremental update is needed, parse the delta feed.
- `C -- No --> E`: If a full index build is needed, trigger a full index build.
- `E --> F`: Snapshot data from the source for a full index build.
- `D --> G`: Transform delta records after parsing the delta feed.
- `F --> G`: Transform delta records after snapshotting data from the source.
- `G --> H`: Apply schema and validation to the transformed delta records.
- `H -- Valid --> I`: If the data is valid, apply the delta to the inverted index.
- `H -- Invalid --> J`: If the data is invalid, write it to the error queue.
- `I --> K`: Update bloom filters after applying the delta to the inverted index.
- `K --> L`: Commit index segments after updating bloom filters.
- `L --> M`: Push segments to search nodes after committing index segments.
- `M --> N`: Check if replication is complete.
- `N -- Yes --> O`: If replication is complete, rollout new segments.
- `N -- No --> P`: If replication is not complete, retry the push.
- `P --> M`: Retry pushing segments to search nodes.
- `O --> Q`: Invalidate cache and load new data after rolling out new segments.
- `Q --> R`: The index is ready after invalidating the cache and loading new data.
- `R --> S`: Search nodes are ready to serve after the index is ready.

## Repository Context & Terminology
- **Inverted Index**: A data structure that maps content (e.g., words) to its locations in a document or set of documents. Used for efficient search.
- **Delta Feed**: A stream of changes or updates to the data source, used for incremental indexing.
- **Bloom Filter**: A space-efficient probabilistic data structure used to test whether an element is a member of a set. Used to reduce unnecessary disk lookups.
- **Index Segments**: Smaller, self-contained parts of the overall index. Committing segments allows for incremental updates and faster search.
- **Search Nodes**: Servers or instances responsible for serving search queries.
- **Replication**: The process of copying index segments to multiple search nodes for redundancy and load balancing.
- **Cache Invalidation**: The process of removing old data from the cache to ensure that the search nodes serve the most up-to-date results.
