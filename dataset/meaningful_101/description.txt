## 图类型与用途
该图是一个流程图，描述了用户请求处理以及缓存失效的完整流程。它展示了请求如何在边缘缓存和应用层之间传递，以及缓存失效后如何更新缓存。该图旨在说明缓存机制在系统中的作用。

## 图的整体布局
该图从上到下布局，分为“用户请求”、“应用层处理”和“缓存失效流程”三个主要部分。用户请求作为起点，最终数据返回至边缘缓存，缓存失效流程则独立运行，影响缓存状态。

## 分组/子图/阶段说明
图中包含三个子图：
- **用户请求**：描述用户请求的初始处理，包括边缘缓存的命中判断。
- **应用层处理**：描述应用层如何处理未命中边缘缓存的请求，包括本地缓存的命中判断、数据存储查询和缓存更新。
- **缓存失效流程**：描述数据变更事件如何触发缓存失效，以及缓存消费者如何处理失效消息。

## 连线、分支与汇聚关系
- A -> B：用户请求到达边缘缓存。
- B -- 是 --> C：边缘缓存命中，返回数据。
- B -- 否 --> D：边缘缓存未命中，请求转发至应用层。
- D -> E：请求到达应用层，判断本地缓存是否命中。
- E -- 是 --> F：本地缓存命中，返回数据。
- E -- 否 --> G：本地缓存未命中，查询数据存储。
- G -> H：查询数据存储返回数据。
- H -> I：更新本地缓存。
- I -> J：返回数据。
- F -> J：本地缓存返回数据。

- K -> C：边缘缓存返回数据。
- L -> M：数据变更事件触发缓存失效流程。
- M -- 是 --> N：数据变更涉及缓存，生成失效消息。
- M -- 否 --> O：数据变更不涉及缓存，忽略。

- P -> Q：缓存消费者从消息队列消费失效消息。

- R -- 否 --> T：不需要使边缘缓存失效，判断是否需要使本地缓存失效。
- T -- 是 --> U：需要使本地缓存失效。
- T -- 否 --> V：不需要使本地缓存失效，忽略。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **边缘缓存**：位于网络边缘的缓存，用于加速用户请求的响应速度。
- **本地缓存**：位于应用服务器上的缓存，用于减少对数据存储的访问。
- **数据存储**：存储实际数据的数据库或其他存储系统。
- **缓存失效**：使缓存中的数据过期，强制从数据存储中重新获取数据。
- **消息队列**：用于异步传递消息的中间件，用于解耦数据变更事件和缓存失效操作。
- **缓存消费者**：监听消息队列，并根据失效消息执行缓存失效操作的组件。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先到达边缘缓存，如果命中则直接返回数据；否则，请求转发至应用层。应用层首先检查本地缓存，如果命中则返回数据；否则，查询数据存储，更新本地缓存并返回数据至边缘缓存。当数据发生变更时，系统会生成失效消息并推送到消息队列，缓存消费者监听消息队列，并根据失效消息使边缘缓存或本地缓存失效，最终保证数据一致性。
