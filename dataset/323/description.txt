## 图类型与用途
这是一个云原生微服务架构图，展示了一个基于 Amazon EKS 的咖啡店应用的部署架构。它描述了用户如何通过负载均衡器访问应用，开发者如何将容器镜像推送到容器镜像仓库，以及微服务之间如何通过事件驱动架构进行通信，并展示了整体的监控和 CI/CD 流程。该图在 README 中作为“Modern Cloud-Native Architecture on Amazon EKS”的示例。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户和开发者，中间是网络层、EKS 集群和 Lambda 函数，底部是数据层、事件驱动架构和 API 层。

## 分组/子图/阶段说明
- **VPC (Virtual Private Cloud)**：提供隔离的网络环境，包含 Public Subnet 和 Private Subnet。
- **Public Subnet**：包含可以从互联网访问的资源，如 ALB 和 NAT 网关。
- **Private Subnet**：包含不能直接从互联网访问的资源，如 EKS 集群和 Lambda 函数。
- **EKS Cluster (Kubernetes Cluster)**：托管的 Kubernetes 集群，用于运行容器化的微服务。
- **coffeeshop namespace**：Kubernetes 命名空间，用于隔离咖啡店应用的资源。
- **System Components (SystemPods)**：Kubernetes 集群的系统组件。
- **Lambda (AWS Lambda)**：无服务器计算服务，用于运行事件驱动的代码。
- **Data Layer**：包含 DynamoDB 数据库表。
- **Event-Driven Architecture**：使用 Amazon EventBridge 实现事件驱动的架构。
- **API Layer**：使用 Amazon API Gateway 提供 REST API。
- **Monitoring & Observability**：使用 Amazon CloudWatch 进行监控和告警。
- **CI/CD Pipeline**：使用 EKS Pipeline Stack 实现自动化部署。

## 节点逐项说明
- **User (👤 Users)**：最终用户，通过浏览器或应用程序访问咖啡店应用。
- **Application Load Balancer (ALB)**：应用程序负载均衡器，负责将用户请求路由到不同的微服务。
- **Orders Web (OrdersPod)**：订单微服务，负责处理订单相关的业务逻辑。
- **Coffee Web (CoffeePod)**：咖啡微服务，负责处理咖啡相关的业务逻辑。
- **Inventory Web (InventoryPod)**：库存微服务，负责处理库存相关的业务逻辑。
- **Coffee Order Handler**：Lambda 函数，用于处理咖啡订单相关的业务逻辑。
- **Inventory Handler**：Lambda 函数，用于处理库存相关的业务逻辑。
- **Order Table**：订单表，用于存储订单数据。
- **Coffee Table**：咖啡表，用于存储咖啡数据。
- **Inventory Table**：库存表，用于存储库存数据。
- **Amazon EventBridge (Event Bus)**：事件总线，用于实现事件驱动的架构。
- **Amazon API Gateway (REST API)**：API 网关，用于创建、发布和管理 API。
- **Amazon CloudWatch (Metrics & Logs)**：用于收集和提供指标数据。
- **Amazon SNS (Alarm Notifications)**：用于发送告警通知。
- **EKS Pipeline Stack (Automated Deployment)**：用于自动化部署 EKS 集群。
- **Developer (👨‍💻 Developers)**：负责开发、构建和部署应用程序的开发人员。
- **Amazon ECR (Container Registry)**：Amazon Elastic Container Registry，用于存储和管理容器镜像。
- **NAT Gateway**：网络地址转换网关，允许私有子网中的实例访问互联网。
- **AWS Load Balancer Controller**：Kubernetes 控制器，用于管理 ALB。
- **Cluster Autoscaler**：Kubernetes 控制器，用于自动调整集群规模。
- **Metrics Server**：Kubernetes 组件，用于收集和提供指标数据。
- **EBS CSI Driver**：Kubernetes 组件，用于管理 EBS 卷。
- **CloudWatch Dashboard**：CloudWatch 的可视化面板。

## 连线、分支与汇聚关系
- `User -> ALB`：用户通过 ALB 访问应用。
- `ALB -> OrdersPod`：ALB 将请求路由到 Orders Web 微服务。
- `ALB -> CoffeePod`：ALB 将请求路由到 Coffee Web 微服务。
- `ALB -> InventoryPod`：ALB 将请求路由到 Inventory Web 微服务。
- `OrdersPod -> DynamoOrder`：Orders Web 微服务访问 Order Table。
- `OrdersPod -> EventBridge`：Orders Web 微服务发送事件到 EventBridge。
- `CoffeePod -> DynamoCoffee`：Coffee Web 微服务访问 Coffee Table。
- `InventoryPod -> DynamoInventory`：Inventory Web 微服务访问 Inventory Table。
- `APIGateway -> CoffeeOrderHandler`：API Gateway 将请求路由到 Coffee Order Handler Lambda 函数。
- `APIGateway -> InventoryHandler`：API Gateway 将请求路由到 Inventory Handler Lambda 函数。
- `CoffeeOrderHandler -> DynamoOrder`：Coffee Order Handler Lambda 函数访问 Order Table。
- `CoffeeOrderHandler -> DynamoCoffee`：Coffee Order Handler Lambda 函数访问 Coffee Table。
- `InventoryHandler -> DynamoCoffee`：Inventory Handler Lambda 函数访问 Coffee Table。
- `EventBridge -> CoffeeOrderHandler`：EventBridge 将事件发送到 Coffee Order Handler Lambda 函数。
- `OrdersPod -.-> EventBridge`：Orders Web 微服务发送事件到 EventBridge。
- `ECR -> OrdersPod`：ECR 中的镜像被部署到 Orders Web 微服务。
- `ECR -> CoffeePod`：ECR 中的镜像被部署到 Coffee Web 微服务。
- `ECR -> InventoryPod`：ECR 中的镜像被部署到 Inventory Web 微服务。
- `OrdersPod -> CloudWatch`：Orders Web 微服务发送指标到 CloudWatch。
- `CoffeePod -> CloudWatch`：Coffee Web 微服务发送指标到 CloudWatch。
- `InventoryPod -> CloudWatch`：Inventory Web 微服务发送指标到 CloudWatch。
- `CoffeeOrderHandler -> CloudWatch`：Coffee Order Handler Lambda 函数发送指标到 CloudWatch。
- `InventoryHandler -> CloudWatch`：Inventory Handler Lambda 函数发送指标到 CloudWatch。
- `EKS -> CloudWatch`：EKS 集群发送指标到 CloudWatch。
- `CloudWatch -> Dashboard`：CloudWatch 指标显示在 Dashboard 上。
- `CloudWatch -> SNS`：CloudWatch 触发 SNS 告警。
- `Pipeline -> ECR`：CI/CD Pipeline 将镜像推送到 ECR。
- `Pipeline -> EKS`：CI/CD Pipeline 部署到 EKS 集群。
- `MetricsServer -> OrdersPod`：Metrics Server 收集 Orders Web 微服务的指标。
- `MetricsServer -> CoffeePod`：Metrics Server 收集 Coffee Web 微服务的指标。
- `MetricsServer -> InventoryPod`：Metrics Server 收集 Inventory Web 微服务的指标。
- `ClusterAutoscaler -> EKS`：Cluster Autoscaler 根据指标自动调整 EKS 集群规模。

## 仓库语境与术语解释
- **Amazon EKS (Elastic Kubernetes Service)**：托管的 Kubernetes 服务，用于运行容器化的应用程序。在 `deployment/coffeeshop-cdk-v2/lib/stacks/eks-stack.js` 中定义了 EKS 集群的配置。
- **Amazon ECR (Elastic Container Registry)**：用于存储和管理 Docker 容器镜像的容器镜像仓库。
- **Amazon VPC (Virtual Private Cloud)**：在 AWS 云中预置一个逻辑隔离的部分，可以在自己定义的虚拟网络中启动 AWS 资源。在 `deployment/coffeeshop-cdk-v2/lib/stacks/network-stack.js` 中定义了 VPC 的配置。
- **AWS Lambda**：无服务器计算服务，允许您无需预置或管理服务器即可运行代码。
- **Amazon EventBridge**：无服务器事件总线服务，可以轻松地将应用程序与来自各种来源的数据连接起来。
- **Domain Driven Design (DDD)**：一种软件开发方法，侧重于将软件的设计与业务领域的概念相匹配。README 提到使用 DDD 方法来构建应用程序。
- **Event Storming**：一种团队协作方法，用于快速探索复杂的业务领域。README 提到使用 Event Storming 来理解业务领域模型。
- **Spring Boot**：一个 Java 框架，用于构建独立的、生产级别的、基于 Spring 的应用程序。图中的 Orders Web, Coffee Web, Inventory Web 都是基于 Spring Boot 3.4.1 构建的。
- **Java 21**：该项目使用的 Java 运行时版本。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个基于 Amazon EKS 的咖啡店应用的云原生微服务架构。用户通过 ALB 访问 Orders Web、Coffee Web 和 Inventory Web 微服务。开发者将容器镜像推送到 ECR。微服务之间通过 Amazon EventBridge 进行事件驱动通信。Lambda 函数处理咖啡订单和库存。数据存储在 DynamoDB 中。Amazon CloudWatch 用于监控和告警。EKS Pipeline Stack 用于自动化部署。该架构的关键组件包括 EKS 集群、微服务、Lambda 函数、DynamoDB 数据库和 EventBridge 事件总线。该架构利用了 AWS 的云原生服务，实现了高可用性、可伸缩性和弹性。
