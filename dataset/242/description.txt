## 图类型与用途
这是一个流程图，描述了 GLaDOS 如何构建发送给 LLM 的上下文。该图展示了上下文来源如何被合并，最终形成 LLM 请求，在仓库中用于概括 GLaDOS 的上下文构建流程。

## 图的整体布局
图整体采用从上到下的布局。顶部是上下文来源，中间是上下文构建器，底部是 LLM 请求。流程从各种信息源开始，经过合并，最终形成 LLM 请求。

## 分组/子图/阶段说明
图中包含三个子图：
- **Sources (上下文来源)**：包含所有为 GLaDOS 提供上下文信息的来源。
- **Builder (上下文构建器)**：负责将来自不同来源的信息合并成一个统一的上下文。
- **Final (LLM 请求)**：表示最终发送给 LLM 的请求。

## 节点逐项说明
- **sys (系统提示/个性)**：包含 GLaDOS 的系统提示，定义了其核心个性和行为方式。
- **slots (任务槽/天气, 新闻, etc.)**：包含与当前任务相关的动态信息，例如天气、新闻等。根据 `src/glados/autonomy/slots.py`，任务槽存储了任务的状态、摘要和报告。
- **prefs (用户偏好)**：包含用户的个人偏好设置，用于个性化交互。
- **const (宪法修正/约束)**：包含对 GLaDOS 行为的约束或规则，例如道德准则。
- **mcp (MCP 资源)**：MCP (Master Control Program) 资源，可能包含系统状态、资源信息等。根据 `src/glados/mcp/manager.py`，MCP Manager 管理 MCP 服务器和工具。
- **vision (视觉状态)**：包含视觉信息，例如摄像头捕捉到的图像或视频分析结果。根据 `src/glados/vision/vision_state.py`，VisionState 存储了最新的视觉描述。
- **merge (优先级排序合并)**：负责按照优先级对来自不同来源的信息进行排序和合并，以确保最重要的信息优先被 LLM 使用。
- **messages (系统消息)**：包含由上下文构建器生成的系统消息，为 LLM 提供背景信息和指令。
- **history (对话历史)**：包含之前的对话记录，用于保持对话的连贯性。
- **user (用户消息)**：包含用户当前输入的消息。

## 连线、分支与汇聚关系
- `Sources --> merge`：所有上下文来源（sys, slots, prefs, const, mcp, vision）都将信息传递给上下文构建器中的 "merge" 节点。
- `merge --> messages`： "merge" 节点将合并后的上下文信息传递给 "messages" 节点，形成系统消息。
- `messages --> history`：系统消息与对话历史结合。
- `history --> user`：对话历史与用户消息结合，形成完整的 LLM 请求。

## 仓库语境与术语解释
- **LLM (大型语言模型)**：GLaDOS 使用的大型语言模型，用于生成响应。
- **ContextBuilder**：根据 `src/glados/core/context.py`，ContextBuilder 用于构建 LLM 上下文，从注册的来源构建系统消息。
- **MCP (Master Control Program)**：根据 README 和 `docs/mcp.md`，MCP 是一个可扩展的工具系统，用于家庭自动化、系统信息等。
- **Vision State**：根据 `src/glados/vision/vision_state.py`，VisionState 存储了最新的视觉描述，GLaDOS 可以通过摄像头观察环境。
- **Task Slots**：根据 `src/glados/autonomy/slots.py`，TaskSlotStore 存储了任务的状态、摘要和报告，用于自主行为。
- **configs/glados_config.yaml**：该文件包含了 GLaDOS 的配置信息，例如 LLM 模型、API 密钥、语音等。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 GLaDOS 如何构建 LLM 请求的上下文。流程从多个上下文来源（系统提示、任务槽、用户偏好、约束条件、MCP 资源和视觉状态）开始，这些信息被优先级排序合并，形成系统消息。系统消息与对话历史和用户消息结合，最终形成完整的 LLM 请求。其中，MCP 资源和视觉状态是两个重要的上下文来源，它们分别提供了系统状态和视觉信息。`configs/glados_config.yaml` 文件定义了 GLaDOS 的配置，包括 LLM 模型和 API 密钥。
