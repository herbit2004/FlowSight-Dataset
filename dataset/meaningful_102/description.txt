## Edges, Branches & Convergence
- `A --> B`: Log data flows from the application server to the log forwarder.
- `B --> C`: Log forwarder sends data to the resource monitor.
- `C -- Yes --> D`: If CPU usage is high, logs are dynamically sampled to reduce verbosity.
- `C -- No --> E`: If CPU usage is not high, default sampling is used.
- `D --> F`: Dynamically sampled logs are sent to the Kafka topic.
- `E --> F`: Default sampled logs are sent to the Kafka topic.
- `F --> G`: Logs are aggregated from Kafka by Apache Flume.
- `G --> H`: Aggregated logs are evaluated for data enrichment.
- `H -- Needs GeoIP? --> I`: If GeoIP enrichment is needed, logs are sent to the GeoIP Lookup Service.
- `H -- No --> J`: If GeoIP enrichment is not needed, logs are sent to the parsing and normalization stage.
- `I --> J`: GeoIP enriched logs are sent to the parsing and normalization stage.
- `J --> K`: Parsed and normalized logs are sent to the Elasticsearch indexer.
- `K --> L`: Indexed logs are stored in the Elasticsearch cluster.
- `L --> M`: Logs in Elasticsearch are evaluated against alerting rules.
- `L --> Q`: Logs in Elasticsearch are sent to the Kibana Dashboard.
- `M -- Threshold Breached --> N`: If alerting rules are met (threshold breached), a PagerDuty alert is triggered.
- `M -- OK --> O`: If alerting rules are not met (OK), the system remains idle.
- `N --> P`: A PagerDuty alert triggers the incident management system.

## Repository Context & Terminology

- **Apache Flume**: A distributed, reliable, and available service for efficiently collecting, aggregating, and moving large amounts of log data.
- **GeoIP Lookup**: The process of determining the geographic location of an IP address.

- **Kibana**: A data visualization dashboard for Elasticsearch.
- **PagerDuty**: An incident management platform that provides alerting and on-call scheduling.

## High-Density QA Ground Truth Summary
The log processing pipeline begins with the Application Server (MyApp) generating logs, which are then forwarded by Fluentd. A Resource Monitor checks for high CPU usage. If CPU usage is high (`Yes` branch), Dynamic Sampling reduces log verbosity; otherwise (`No` branch), Default Sampling is applied. Both sampling paths converge at the Kafka Topic (app-logs), where logs are stored. Apache Flume aggregates logs from Kafka. A Data Enrichment decision point determines if GeoIP enrichment is needed. If so (`Needs GeoIP?` branch), the GeoIP Lookup Service enriches the logs; otherwise (`No` branch), logs proceed directly to parsing and normalization. Enriched or non-enriched logs are then parsed and normalized before being indexed by the Elasticsearch Indexer and stored in the Elasticsearch Cluster. The Elasticsearch Cluster data is visualized via a Kibana Dashboard. Alerting Rules are then evaluated. If a threshold is breached, a PagerDuty Alert is triggered, activating the Incident Management System. Otherwise, the system remains Idle. Fluentd acts as the initial log forwarder, collecting and routing logs based on configured rules, which may include dynamic sampling to manage verbosity under high CPU load.
