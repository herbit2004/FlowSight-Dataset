## 图类型与用途
这是一个流程图，描述了 `antissh.sh` 脚本在 Linux 系统上配置反重力 Agent 代理的流程。该脚本旨在解决网络连接问题，特别是针对 IDE 升级后可能出现的代理失效情况。它在仓库中的作用是展示脚本的执行流程，以及在不同情况下可能出现的分支和退出点。

## 图的整体布局
图整体采用从上到下的布局。顶部是脚本执行的起点，中间是代理配置和 graftcp 编译安装过程，底部是配置完成或失败的终点。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分成以下几个阶段：
- 系统检测与代理配置询问
- 代理地址解析与 graftcp-local 端口配置
- graftcp 编译与 language_server 查找
- 最终配置完成或失败退出

## 节点逐项说明
- **A[开始]**：脚本执行的起点。
- **B{检测系统}**：检查当前操作系统类型。
- **C[询问代理配置]**：询问用户是否需要配置代理。
- **Z1[显示替代方案提示并退出]**：在 macOS/Windows 系统上，显示替代方案提示并退出脚本。README 提到 macOS/Windows 推荐使用 Proxifier 或 TUN 模式。
- **D{用户输入代理地址}**：提示用户输入代理地址。
- **Z2[退出脚本]**：用户选择跳过代理配置时，退出脚本。
- **E[解析并校验代理格式]**：验证用户输入的代理地址格式是否正确。
- **E1{检测到上次端口}**：检测是否检测到上次使用的端口。
- **E1A{是否复用上次端口}**：询问用户是否复用上次使用的端口。
- **E1B[校验上次端口并复用]**：校验上次端口并复用。
- **E1C[手动输入端口 默认 2233]**：提示用户手动输入端口号，默认端口为 2233。
- **E1D[校验端口占用并确定端口]**：校验端口是否被占用，并确定最终使用的端口。
- **E2[选择 DNS 解析策略]**：选择 DNS 解析策略。
- **F[轻量级代理探测]**：尝试使用代理进行轻量级探测，判断代理是否可用。
- **G1[导出 HTTP_PROXY 等环境变量]**：如果代理探测成功，则导出 HTTP_PROXY 等环境变量。
- **G2[使用镜像下载策略]**：如果代理探测失败或超时，则继续使用镜像下载策略。
- **H[检查/安装依赖]**：检查并安装脚本运行所需的依赖，例如 Go, Git, Make, GCC。
- **I{GRAFTCP_DIR 环境变量?}**：检查是否设置了 GRAFTCP_DIR 环境变量。
- **J1[跳过编译，使用现有 graftcp]**：如果 GRAFTCP_DIR 环境变量已设置且有效，则跳过编译，直接使用现有的 graftcp。
- **J2{本地已有 graftcp?}**：检查本地是否已存在 graftcp。
- **K[克隆 graftcp 仓库]**：克隆 graftcp 仓库到本地。
- **L[编译 graftcp]**：编译 graftcp。
- **Z3[显示手动安装指引并退出]**：graftcp 编译失败时，显示手动安装指引并退出脚本。
- **M[查找 language_server]**：查找 language_server。
- **N[备份原始文件并生成 wrapper]**：备份原始文件，并生成 wrapper 脚本。
- **N1[清理残留 language_server]**：清理残留的 language_server 进程。
- **N2[清理旧 graftcp-local 保留当前端口实例]**：清理旧的 graftcp-local 进程，但保留当前端口对应的实例。
- **O[测试代理连通性]**：测试代理的连通性。
- **P[配置完成 🎉]**：脚本配置完成。

## 连线、分支与汇聚关系
- `A -> B`：脚本开始后，首先检测系统类型。
- `B -- Linux --> C`：如果系统是 Linux，则询问是否配置代理。
- `B -- macOS/Windows --> Z1`：如果系统是 macOS/Windows，则显示替代方案提示并退出。
- `C -> D`：询问是否配置代理后，提示用户输入代理地址。
- `D -- 跳过 --> Z2`：如果用户选择跳过，则退出脚本。
- `D -- 输入代理 --> E`：如果用户输入代理地址，则解析并校验代理格式。
- `E -> E1`：解析并校验代理格式后，检测是否检测到上次使用的端口。
- `E1 -- 是 --> E1A`：如果检测到上次使用的端口，则询问用户是否复用上次使用的端口。
- `E1 -- 否 --> E1C`：如果没有检测到上次使用的端口，则提示用户手动输入端口号。
- `E1A -- Y/回车 --> E1B`：如果用户选择复用上次使用的端口，则校验上次端口并复用。
- `E1A -- N --> E1C`：如果用户选择不复用上次使用的端口，则提示用户手动输入端口号。
- `E1B -> E2`：校验上次端口并复用后，选择 DNS 解析策略。
- `E1C -> E1D`：手动输入端口后，校验端口是否被占用，并确定最终使用的端口。
- `E1D -> E2`：校验端口占用并确定端口后，选择 DNS 解析策略。
- `E2 -> F`：选择 DNS 解析策略后，进行轻量级代理探测。
- `F -- 成功 --> G1`：如果代理探测成功，则导出 HTTP_PROXY 等环境变量。
- `F -- 失败/超时 --> G2`：如果代理探测失败或超时，则继续使用镜像下载策略。
- `G1 -> H`：导出 HTTP_PROXY 等环境变量后，检查/安装依赖。
- `G2 -> H`：使用镜像下载策略后，检查/安装依赖。
- `H -> I`：检查/安装依赖后，检查 GRAFTCP_DIR 环境变量。
- `I -- 已设置且有效 --> J1`：如果 GRAFTCP_DIR 环境变量已设置且有效，则跳过编译，使用现有 graftcp。
- `I -- 未设置 --> J2`：如果 GRAFTCP_DIR 环境变量未设置，则检查本地是否已有 graftcp。
- `J2 -- 是 --> J1`：如果本地已有 graftcp，则跳过编译，使用现有 graftcp。
- `J2 -- 否 --> K`：如果本地没有 graftcp，则克隆 graftcp 仓库。
- `K -> L`：克隆 graftcp 仓库后，编译 graftcp。
- `L -- 成功 --> M`：如果编译 graftcp 成功，则查找 language_server。
- `L -- 失败 --> Z3`：如果编译 graftcp 失败，则显示手动安装指引并退出。
- `J1 -> M`：跳过编译，使用现有 graftcp 后，查找 language_server。
- `M -> N`：查找 language_server 后，备份原始文件并生成 wrapper。
- `N -> N1`：备份原始文件并生成 wrapper 后，清理残留 language_server。
- `N1 -> N2`：清理残留 language_server 后，清理旧 graftcp-local，保留当前端口实例。
- `N2 -> O`：清理旧 graftcp-local 后，测试代理连通性。
- `O -> P`：测试代理连通性后，配置完成。

## 仓库语境与术语解释
- **antissh.sh**：是用于配置反重力 Agent 代理的 Bash 脚本，解决网络连接问题。
- **graftcp**：是一个用于透明代理 TCP 连接的工具，`antissh.sh` 脚本会自动安装和配置 graftcp。
- **language_server**：是 Antigravity Agent 使用的语言服务器，`antissh.sh` 脚本会自动查找并配置 language_server。
- **GRAFTCP_DIR**：是一个环境变量，用于指定 graftcp 的安装目录。如果设置了该环境变量，脚本会跳过编译 graftcp 的步骤。
- **HTTP_PROXY**：是一个环境变量，用于指定 HTTP 代理服务器的地址。
- **HTTPS_PROXY**：是一个环境变量，用于指定 HTTPS 代理服务器的地址。
- **~/.graftcp-antigravity/last_graftcp_local_port**：该文件用于记录上次使用的 graftcp-local 端口，以便下次运行时提示用户是否复用。
- **installAntigravity.sh**：是用于手动安装 Antigravity Server 的脚本，如果远程服务器无法自动下载 Antigravity Server，可以使用该脚本手动安装。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 `antissh.sh` 脚本的执行流程，从开始检测系统类型，到最终配置完成或失败退出。脚本首先询问用户是否需要配置代理，如果需要，则解析并校验代理地址，然后配置 graftcp-local 端口和 DNS 解析策略。接着，脚本会检查并安装依赖，编译 graftcp，查找 language_server，备份原始文件并生成 wrapper 脚本，最后测试代理连通性。如果 graftcp 编译失败，则显示手动安装指引并退出。该脚本的核心功能是自动配置 graftcp，以便为 Antigravity Agent 提供代理服务。`antissh.sh` 脚本会自动查找并配置 language_server，并清理残留进程，以确保代理配置生效。
