## 图类型与用途
该图是一个流程图，描述了支付回调、对账以及差异处理的完整流程。它展示了用户支付后，支付平台如何回调通知，以及支付系统如何进行对账和处理差异。该图旨在帮助理解支付系统的内部运作机制。

## 图的整体布局
该图采用从上到下的布局，分为三个主要的子图：支付回调流程、对账流程和差异处理流程。整个流程从用户发起支付开始，最终到对账结果的存储。

## 分组/子图/阶段说明
图中包含三个子图：
- **支付回调流程**：描述了支付平台回调通知支付系统的过程，包括签名校验、订单状态更新和业务系统通知。
- **对账流程**：描述了支付系统如何定期拉取账单和交易记录，进行数据比对，并生成对账报告。
- **差异处理流程**：描述了当对账出现差异时，如何判断差异类型并进行相应的处理。

## 节点逐项说明
- **A (用户发起支付)**：用户在业务系统或应用中发起支付请求。
- **B (支付平台)**：接收用户支付请求的第三方支付平台。
- **C (支付平台处理)**：支付平台处理用户的支付请求。
- **D (支付回调通知)**：支付平台支付成功后，向支付系统发送回调通知。
- **E (回调处理服务)**：支付系统接收到支付平台的回调通知后，进行处理的服务。
- **F (签名/参数校验)**：对支付平台回调通知的签名和参数进行校验，确保数据的安全性。
- **G (更新订单状态为已支付)**：如果签名和参数校验成功，则更新订单状态为已支付。
- **H (记录异常/告警)**：如果签名和参数校验失败，则记录异常信息并进行告警。
- **I (通知业务系统)**：订单状态更新后，通知业务系统进行后续处理。
- **J (业务系统处理)**：业务系统接收到支付成功的通知后，进行相应的业务处理。
- **K (返回处理结果)**：业务系统处理完成后，返回处理结果给回调处理服务。
- **L (每日定时任务)**：每天定时执行的任务，用于启动对账流程。
- **M (拉取支付平台账单)**：从支付平台拉取账单数据。
- **N (拉取支付系统交易记录)**：从支付系统拉取交易记录数据。
- **O (数据比对)**：将支付平台账单数据和支付系统交易记录数据进行比对。
- **P (生成对账报告)**：根据数据比对的结果，生成对账报告。
- **Q (生成差异报告)**：如果数据比对发现不一致，则生成差异报告。
- **R (人工介入/异常处理)**：对于无法自动处理的差异，需要人工介入进行处理。
- **S (发送对账结果通知)**：将对账结果通知相关人员。
- **T (存储对账报告)**：将生成的对账报告存储起来，以备后续查询。
- **U (差异类型判断)**：判断差异的类型，例如金额差异或订单差异。
- **V (财务复核)**：如果差异类型是金额差异，则需要财务人员进行复核。
- **W (技术排查)**：如果差异类型是订单差异，则需要技术人员进行排查。

## 连线、分支与汇聚关系
- A -> B：用户发起支付请求到支付平台。
- B -- 发起支付请求 --> C：支付平台发起支付请求进行处理。
- C -- 支付成功 --> D：支付平台处理成功后发送支付回调通知。
- D -- 通知支付系统 --> E：支付回调通知发送到回调处理服务。
- E -- 验证签名/参数 --> F：回调处理服务验证签名和参数。
- F -- 校验成功 --> G：签名/参数校验成功。
- F -- 校验失败 --> H：签名/参数校验失败。
- G -> I：更新订单状态后通知业务系统。
- I -> J：业务系统进行处理。
- J -> K：业务系统返回处理结果。
- K -> E：处理结果返回给回调处理服务。
- D -- 通知失败 (重试) --> D：回调通知失败后进行重试。
- L -> M：每日定时任务触发拉取支付平台账单。
- M -> N：拉取支付平台账单后，拉取支付系统交易记录。
- N -> O：拉取交易记录后进行数据比对。
- O -- 一致 --> P：数据比对一致，生成对账报告。
- O -- 不一致 --> Q：数据比对不一致，生成差异报告。
- Q -> R：生成差异报告后，人工介入/异常处理。
- R -> P：人工处理后，生成对账报告。
- P -> S：生成对账报告后，发送对账结果通知。
- S -> T：发送对账结果通知后，存储对账报告。
- Q -> U：生成差异报告后，判断差异类型。
- U -- 金额差异 --> V：差异类型为金额差异，进行财务复核。
- U -- 订单差异 --> W：差异类型为订单差异，进行技术排查。
- V -> R：财务复核后，人工介入/异常处理。
- W -> R：技术排查后，人工介入/异常处理。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **支付回调**：支付平台在完成支付后，主动通知支付系统的过程。
- **对账**：核对支付平台账单数据和支付系统交易记录数据，确保数据一致性的过程。
- **差异报告**：在对账过程中，如果发现支付平台账单数据和支付系统交易记录数据不一致，则生成差异报告。
- **签名校验**：验证支付平台回调请求的签名，确保请求的合法性和数据的完整性。
- **订单状态**：订单在支付系统中的状态，例如待支付、已支付、已退款等。
- **业务系统**：与支付系统对接的业务系统，例如电商平台、游戏平台等。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起支付后，支付平台处理支付请求并发送支付回调通知给支付系统。回调处理服务验证签名和参数，校验成功则更新订单状态为已支付并通知业务系统，校验失败则记录异常。每日定时任务拉取支付平台账单和支付系统交易记录进行数据比对，一致则生成对账报告并发送通知，不一致则生成差异报告。差异报告根据差异类型判断，金额差异进行财务复核，订单差异进行技术排查，最终都需要人工介入处理，并生成对账报告。最终，对账报告会被存储。
