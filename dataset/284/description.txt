- `A --> B`: The `documents.json` file is passed to the `docfind` process.
- `B --> C`: The `docfind` process initiates keyword extraction using RAKE.
- `B --> E`: The `docfind` process initiates FSST compression of document strings.
- `C --> D`: The extracted keywords are used to create an FST map.
- `D --> F`: The FST map is used to create the index.
- `E --> F`: The compressed document strings are used to create the index.
- `D, E --> F`: The outputs of FST Map and FSST Compression converge at the Index node.

## Repository Context & Terminology
- **docfind**: The name of the tool or library being used for indexing.
- **documents.json**: A JSON file containing the documents to be indexed.
- **RAKE**: Rapid Automatic Keyword Extraction, an algorithm for extracting keywords from text.
- **FST**: Finite State Transducer, a type of finite-state machine used for mapping keywords to documents.
- **FSST**: Finite State String Transducer, a type of FST used for compressing strings.
- **docfind_bg.wasm**: A WebAssembly module generated by `docfind`.
- **docfind.js**: A JavaScript file that provides an interface to the `docfind_bg.wasm` module.

## High-Density QA Ground Truth Summary
The diagram illustrates the `docfind` indexing pipeline, starting with a `documents.json` file containing the documents to be indexed. The `docfind` process then branches into two parallel paths: keyword extraction using the RAKE algorithm and FSST compression of document strings. The RAKE algorithm extracts keywords, which are then used to create an FST map, mapping keywords to documents. Simultaneously, the document strings are compressed using FSST. The outputs of both the FST map and FSST compression converge at the `Index` node, where the final index is created. This index is then output as two files: `docfind_bg.wasm`, a WebAssembly module, and `docfind.js`, a JavaScript file that interfaces with the WebAssembly module. The use of RAKE for keyword extraction and FSST for compression are key components of the `docfind` indexing process, aiming to create a compact and efficient index for searching. The final output, `docfind_bg.wasm` and `docfind.js`, represents the deployable index ready for use in a web application.
