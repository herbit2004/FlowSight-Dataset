## Repository Context & Terminology
- **GitHub Actions**: A CI/CD platform that allows you to automate your build, test, and deployment pipeline.
- **Terraform**: An infrastructure-as-code tool that allows you to define and provision infrastructure using declarative configuration files.
- **AWS ECS (Elastic Container Service)**: A container orchestration service that allows you to run and manage Docker containers on AWS.
- **ECR (Elastic Container Registry)**: A fully-managed Docker container registry that makes it easy to store, manage, and deploy Docker container images.
- **IMAGE_URI**: An environment variable that stores the URI of the Docker image in ECR.
- **variables.tf**: A Terraform file that defines the input variables for the Terraform configuration.
- **container_definitions.json.tpl**: A template file used by Terraform to generate the `container_definitions.json` file, which defines the configuration for the containers in the ECS task definition.
- **outputs.tf**: A Terraform file that defines the output values for the Terraform configuration.

## High-Density QA Ground Truth Summary
The deployment pipeline begins with a "GitHub Push to main", triggering a "GitHub Actions Workflow". This workflow first "Builds a Docker Image" and then "Tags the Docker Image with the Commit SHA" for version control. The tagged image is then "Pushed to ECR", AWS's container registry. Subsequently, the "IMAGE_URI Environment Variable" is set, providing the location of the image for later steps. Terraform is then initialized, and a Terraform plan is run using the `IMAGE_URI`. The Terraform plan is applied, which initializes the Terraform backend using S3 and DynamoDB for state management. Terraform then loads variables from `variables.tf` and uses the `container_definitions.json.tpl` template to configure the ECS task definition. The ECS task definition is then created or updated, triggering ECS to pull the image from ECR. Finally, the ECS service is updated with the new containers, and information is output from `outputs.tf`. The `container_definitions.json.tpl` file is crucial as it allows dynamic configuration of the ECS task definition based on the newly built Docker image. The pipeline culminates in the "ECS Service Updated with New Containers" node, signifying a successful deployment.
