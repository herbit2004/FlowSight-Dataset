## Repository Context & Terminology
- **GitHub Actions**: A CI/CD platform that allows you to automate your build, test, and deployment pipeline.
- **Docker Images**: A lightweight, standalone, executable package that includes everything needed to run a piece of software, including the code, runtime, system tools, system libraries, and settings.
- **Amazon ECR (Elastic Container Registry)**: A fully managed container registry that makes it easy to store, manage, share, and deploy your container images.
- **Terraform**: An infrastructure-as-code (IaC) tool that enables you to define and provision infrastructure using a declarative configuration language.
- **ECS (Elastic Container Service)**: A fully managed container orchestration service that makes it easy to run, stop, and manage Docker containers on a cluster.
- **CloudWatch Logs**: A monitoring and logging service that collects and monitors log data from your applications and infrastructure.
- **VPC (Virtual Private Cloud)**: A logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define.

## High-Density QA Ground Truth Summary
The deployment process starts with GitHub Actions, which triggers the building of Docker images. These images are then pushed to Amazon ECR for storage and versioning. The presence of images in ECR initiates the Terraform deployment stage. Within the Terraform deployment, several parallel actions occur: an ECS cluster is provisioned, containers are deployed to the ECS cluster, CloudWatch logs are configured for monitoring, and VPC and network resources are created to provide the necessary network infrastructure. All these Terraform-managed resources ultimately contribute to the final AWS Infrastructure. Terraform, as an infrastructure-as-code tool, ensures that the AWS resources are provisioned and configured in a consistent and repeatable manner. The end result is a fully deployed application running on AWS, with monitoring and logging enabled via CloudWatch. The AWS Infrastructure is the final destination for all the resources created and configured during the Terraform deployment.
