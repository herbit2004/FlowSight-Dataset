## 图类型与用途
这是一个流程图，描述了 `coding-agent-search (cass)` 应用的运行时架构和用户交互流程。它展示了用户输入如何驱动应用状态的更新，以及如何将更新后的状态渲染到终端。该图在仓库中的作用是概括应用程序的整体架构和数据流。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户输入，经过运行时环境和模型更新，最终渲染到终端。后台线程异步更新运行时状态。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为四个阶段：用户输入、模型更新、视图渲染和后台任务处理。

## 节点逐项说明
- **User Input**：代表用户通过键盘、鼠标或定时器触发的输入事件，是整个流程的起点。
- **Runtime**：代表应用程序的运行时环境，负责接收输入、调度任务和管理状态。
- **Model::update**：代表模型更新函数，根据接收到的 `CassMsg` 消息更新应用程序的状态。根据 `docs/FRANKENTUI_UX_ARCHITECTURE.md`，`CassApp::update()` 是一个纯状态转换，返回 `Cmd` 值用于副作用。
- **Model::view**：代表视图渲染函数，根据当前应用程序的状态生成用户界面。根据 `docs/FRANKENTUI_UX_ARCHITECTURE.md`，`view()` 读取模型并发出渲染指令，没有 ad-hoc 突变。
- **Bayesian Diff**：代表差异引擎，用于比较新旧视图，并计算出需要更新的最小写入集合。图中可见，但仓库上下文未进一步说明。
- **Terminal**：代表终端，最终显示用户界面的地方。
- **Background Thread**：代表后台线程，用于执行耗时任务，避免阻塞主线程。

## 连线、分支与汇聚关系
- `User Input -> Runtime`：用户输入通过键盘、鼠标或定时器触发事件，传递给运行时环境。
- `Runtime -> Model::update`：运行时环境将输入转换为 `CassMsg` 消息，传递给模型更新函数。
- `Model::update -> Runtime`：模型更新函数产生需要执行的命令（`Cmd`），传递给运行时环境，由运行时环境负责执行。
- `Model::update -> Model::view`：应用程序状态发生改变，传递给视图渲染函数。
- `Model::view -> Bayesian Diff`：视图渲染函数根据新的应用程序状态生成用户界面（`Frame`），传递给差异引擎。
- `Bayesian Diff -> Terminal`：差异引擎比较新旧视图，计算出需要更新的最小写入集合，传递给终端进行渲染。
- `Model::update -> Background Thread`：模型更新函数还可以产生 `Cmd::Task` 命令，表示需要执行后台任务，这些任务被发送到后台线程。
- `Background Thread -> Runtime`：后台线程执行任务完成后，将结果封装成 `Result Msg` 消息，传递给运行时环境，以便更新应用程序的状态，形成汇聚关系。

## 仓库语境与术语解释
- **CassMsg**：应用程序内部的消息类型，用于在不同组件之间传递数据和事件。
- **Model::update**：根据 `docs/FRANKENTUI_UX_ARCHITECTURE.md`，`CassApp` 是单一 Model，`update()` 是纯状态转换，返回 `Cmd` 值用于副作用。
- **Model::view**：根据 `docs/FRANKENTUI_UX_ARCHITECTURE.md`，`view()` 读取模型并发出渲染指令，没有 ad-hoc 突变。
- **FrankenTUI (ftui)**：根据 `docs/FRANKENTUI_UX_ARCHITECTURE.md`，`cass` 的 TUI 遵循 Elm 架构模式，由 ftui 实现。
- **Robot Mode**：根据 `docs/ROBOT_MODE.md`，`cass` 可以在非交互式的 "robot mode" 下运行，用于自动化任务。
- **Cmd**：表示需要执行的命令，例如异步 I/O、持久化或子进程调用。
- **Background Thread**：用于执行耗时任务，避免阻塞主线程，保证用户界面的流畅性。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 `coding-agent-search (cass)` 应用的运行时架构。用户输入首先传递给 `Runtime`，然后通过 `Model::update` 更新应用状态。状态变化会触发 `Model::view` 渲染视图，并通过 `Bayesian Diff` 优化终端写入。`Model::update` 还可以将任务发送到 `Background Thread` 异步执行，结果最终反馈给 `Runtime`。整个流程基于 Elm 架构，如 `docs/FRANKENTUI_UX_ARCHITECTURE.md` 所述，并且支持在 `docs/ROBOT_MODE.md` 中描述的 Robot Mode 下运行。
