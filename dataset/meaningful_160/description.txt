## 图类型与用途
该图是一个流程图，描述了设备端心跳任务的执行流程。它展示了设备如何定期发送心跳包，并根据服务端响应情况判断设备是否在线。该流程用于监控设备状态，及时发现设备离线情况。

## 图的整体布局
该图采用从上到下的布局。流程从“设备端心跳任务”开始，经过一系列判断和操作，最终可能到达“上报设备离线事件”。整体流程是一个循环，大部分情况下会回到“设备端心跳任务”重新开始。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. **心跳周期检查阶段**：判断心跳周期是否到达。
2. **心跳包发送与响应等待阶段**：发送心跳包并等待服务端响应。
3. **超时判断阶段**：判断服务端响应是否超时。
4. **离线上报阶段**：如果服务端响应超时，则上报设备离线事件。

## 节点逐项说明
- **设备端心跳任务**：设备端启动的心跳任务，是整个流程的起点。
- **心跳周期到达?**：判断当前是否到达心跳周期的时间点。
- **发送心跳包**：设备端向服务端发送心跳包。
- **等待服务端响应**：设备端等待服务端对心跳包的响应。
- **服务端响应超时?**：判断是否在规定时间内收到服务端响应。
- **上报设备离线事件**：如果服务端响应超时，则上报设备离线事件。

## 连线、分支与汇聚关系
- 设备端心跳任务 -> 心跳周期到达?: 启动心跳任务后，进入心跳周期判断。
- 心跳周期到达? -- 是 --> 发送心跳包：如果心跳周期到达，则发送心跳包。
- 心跳周期到达? -- 否 --> 设备端心跳任务：如果心跳周期未到达，则回到心跳任务起点。
- 发送心跳包 -> 等待服务端响应：发送心跳包后，等待服务端响应。
- 等待服务端响应 -- 是 --> 设备端心跳任务：如果收到服务端响应，则回到心跳任务起点。
- 等待服务端响应 -- 否 --> 服务端响应超时?: 如果未收到服务端响应，则进入超时判断。
- 服务端响应超时? -- 是 --> 上报设备离线事件：如果服务端响应超时，则上报设备离线事件。
- 服务端响应超时? -- 否 --> 设备端心跳任务：如果服务端响应未超时，则回到心跳任务起点。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **设备端**：指需要被监控状态的客户端设备。
- **服务端**：指接收设备端心跳包并进行响应的服务器。
- **心跳任务**：设备端定时发送心跳包的任务，用于保持与服务端的连接并表明设备在线。
- **心跳周期**：设备端发送心跳包的时间间隔。
- **心跳包**：设备端发送给服务端的数据包，用于表明设备在线。
- **服务端响应**：服务端收到心跳包后，返回给设备端的确认信息。
- **设备离线事件**：当设备端无法与服务端正常通信时，上报的事件。

## 可作为 QA Ground Truth 的高信息密度摘要
设备端心跳任务启动后，会定期检查心跳周期是否到达。如果到达，则发送心跳包并等待服务端响应。如果收到响应，则重新开始心跳任务。如果等待超时，则判断服务端响应是否超时。如果超时，则上报设备离线事件，否则重新开始心跳任务。
