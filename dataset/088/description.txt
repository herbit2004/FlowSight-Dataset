## 图类型与用途
这是一个流程图，描述了 Claude Code Audio Hooks 系统的架构和数据流。该系统的目的是在 Claude Code 完成任务或需要用户注意时，通过音频、桌面通知和文本转语音等方式通知用户。该图在仓库中用于展示系统的整体架构。

## 图的整体布局
图整体采用从上到下的布局。顶部是 Claude Code CLI，中间是 Hook System，底部是 Output Channels 和 User Terminal。数据流从 Claude Code CLI 开始，经过 Hook System 的处理，最终通过不同的输出渠道到达 User Terminal。

## 分组/子图/阶段说明
图中包含四个子图：
- **Claude Code**：表示 Claude Code 命令行界面，是整个流程的起点。
- **Hook System**：表示 Hook 运行器和上下文解析器，负责接收 Claude Code CLI 的触发信号和 JSON 数据，并进行解析。
- **Output Channels**：表示音频文件、桌面通知和文本转语音等输出渠道，用于提醒用户。
- **User**：表示用户的终端，用户在这里与 Claude Code 交互，并接收来自系统的通知。

## 节点逐项说明
- **Claude Code CLI (CC)**：Claude Code 的命令行界面，负责执行代码任务。
- **Hook Runner (HS)**：用 Python 编写的 Hook 运行器，负责接收 Claude Code CLI 发送的触发信号和 JSON 数据。根据 `docs/ARCHITECTURE.md`，该组件读取项目路径和用户配置，判断 Hook 是否启用，并选择合适的音频文件播放。
- **Context Parser (CTX)**：上下文解析器，接收来自 Hook Runner 的标准输入 JSON 数据，并解析其中的信息，以便后续处理。
- **Audio Files (AF)**：音频文件，存储 MP3 格式的音频文件，用于播放声音提醒。
- **Desktop Notifications (DN)**：桌面通知，使用 `osascript` (macOS) 或 `notify-send` (Linux) 等工具显示桌面通知。
- **Text-to-Speech (TTS)**：文本转语音，使用 `say` (macOS), `espeak` (Linux), 或 SAPI (Windows) 等工具将文本转换为语音。
- **User Terminal (U)**：用户的终端，用户在这里与 Claude Code 交互，并接收来自系统的通知。

## 连线、分支与汇聚关系
- `Claude Code CLI (CC) -> Hook Runner (HS)`：Claude Code CLI 在特定事件发生时，会触发 Hook Runner，并向其发送包含 JSON 数据的触发信号。
- `Hook Runner (HS) -> Context Parser (CTX)`：Hook Runner 将接收到的 JSON 数据传递给 Context Parser 进行解析。
- `Context Parser (CTX) -> Audio Files (AF)`：Context Parser 根据解析结果，触发播放相应的音频文件。
- `Context Parser (CTX) -> Desktop Notifications (DN)`：Context Parser 根据解析结果，显示相应的桌面通知。
- `Context Parser (CTX) -> Text-to-Speech (TTS)`：Context Parser 根据解析结果，将文本转换为语音并播放。
- `Audio Files (AF) -> User Terminal (U)`：播放的音频文件提醒用户。
- `Desktop Notifications (DN) -> User Terminal (U)`：桌面通知提醒用户。
- `Text-to-Speech (TTS) -> User Terminal (U)`：语音提醒用户。
- `Audio Files (AF)`、`Desktop Notifications (DN)`、`Text-to-Speech (TTS)` 汇聚到 `User Terminal (U)`，形成汇聚关系。

## 仓库语境与术语解释
- **Claude Code CLI**：Claude Code 的命令行界面，是整个系统的核心。用户通过 CLI 与 Claude Code 交互。
- **Hook Runner**：根据 `docs/ARCHITECTURE.md`，Hook Runner 是一个 Python 脚本 (`hook_runner.py`)，负责接收 Claude Code 的事件触发，并根据用户配置执行相应的操作。
- **Context Parser**：负责解析从 Claude Code 传递过来的 JSON 数据，提取关键信息用于后续处理。
- **Audio Files**：存储在 `audio/` 目录下，包含默认和自定义的音频文件，用于声音提醒。
- **Desktop Notifications**：通过系统自带的通知机制，向用户发送桌面通知。在 macOS 上使用 `osascript`，在 Linux 上使用 `notify-send`，在 Windows 上使用 PowerShell。
- **Text-to-Speech (TTS)**：将文本转换为语音，通过系统自带的 TTS 引擎播放。在 macOS 上使用 `say`，在 Linux 上使用 `espeak`，在 Windows 上使用 SAPI。
- **User Terminal**：用户与 Claude Code 交互的界面，也是接收通知的最终渠道。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Claude Code Audio Hooks 系统的架构。Claude Code CLI 触发事件并传递 JSON 数据给 Hook Runner，Hook Runner 将数据交给 Context Parser 解析。Context Parser 根据解析结果，选择性地触发音频播放（Audio Files）、桌面通知（Desktop Notifications）和文本转语音（Text-to-Speech），最终通过 User Terminal 提醒用户。Hook Runner 是系统的核心组件，负责执行 Hook 并播放音频。该系统通过多种通知渠道，确保用户能够及时了解 Claude Code 的运行情况。`docs/ARCHITECTURE.md` 描述了该架构的更多细节。
