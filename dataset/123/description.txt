## 图类型与用途
这是一个流程图，描述了 TrendRadar 项目的用户配置和运行流程，旨在帮助用户快速部署和使用该热点助手，获取自己真正关心的新闻资讯。它在仓库中的作用是指导用户如何配置和使用该项目。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户开始节点，经过一系列配置和运行步骤，最终到达持续接收精准推送的节点。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：用户配置阶段、系统运行阶段、效果评估与反馈阶段。

- **👤 用户开始**：流程的起点，代表用户想要使用 TrendRadar。
- **🍴 Fork 项目**：用户需要 Fork TrendRadar 的 GitHub 仓库到自己的账号下。
- **⚙️ 选择通知方式**：用户选择接收热点信息的通知方式。
- **📱 企业微信群机器人<br/>最简单快速**：使用企业微信群机器人接收通知，特点是配置简单快速。
- **💬 飞书机器人<br/>显示效果最佳**：使用飞书机器人接收通知，特点是显示效果最佳。

- **📱 推送到你的手机**：系统将筛选后的热点信息推送到用户的手机。

## 仓库语境与术语解释
- **Fork 项目**：将 GitHub 仓库复制到自己的账号下，是使用 TrendRadar 的第一步。
- **GitHub Secrets**：用于存储敏感信息，如机器人 Webhook 地址，避免直接暴露在代码中。
- **config/frequency_words.txt**：用于配置用户关心的关键词，系统会根据这些关键词筛选热点信息。
- **config/config.yaml**：主配置文件，用于配置应用设置、爬虫配置、通知配置、平台配置等。
- **daily/current/incremental**：`config/config.yaml` 中 `report.mode` 的可选值，分别代表每日汇总、当前榜单和增量监控三种运行模式。
- **Webhooks**：用于将消息从 TrendRadar 推送到企业微信、飞书、钉钉或 Telegram 等平台的 URL。
- **GitHub Actions**：用于自动化运行 TrendRadar 的任务，例如定时爬取和推送热点信息。
- **Silent Push**：静默推送模式，允许用户设定推送时间范围，避免非工作时间的消息打扰，配置在 `config/config.yaml` 的 `notification.silent_push` 中。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 TrendRadar 的配置和使用流程，从用户 Fork 项目开始，选择通知方式（企业微信、飞书、钉钉、Telegram），配置 GitHub Secrets，编辑关键词配置文件 `config/frequency_words.txt`，选择运行模式（daily/current/incremental），配置完成后系统自动运行，爬取各大平台热点，根据关键词筛选后推送到用户手机，用户查看推送结果，如果满意则持续接收精准推送，否则返回编辑关键词配置。其中，`config/config.yaml` 用于配置应用设置、爬虫配置、通知配置等，GitHub Actions 用于自动化运行该流程。
