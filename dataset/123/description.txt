## Repository Context & Terminology
- **config/frequency_words.txt**: This file contains the keywords that the user is interested in, used for filtering relevant information.
- **config/config.yaml**: This file contains the configuration settings for the system, including the run mode (daily, current, or incremental).
- **GitHub Secrets**: A secure way to store sensitive information, such as bot webhook addresses, used to authenticate and authorize the notification system.
- **Webhook**: A URL that the notification system uses to send messages to the selected bot platform (WeChat, Feishu, DingTalk, Telegram).
- **Run Mode (daily/current/incremental)**: Defines how the system processes data. Daily likely processes data from the current day, current processes the most recent data, and incremental processes data that has changed since the last run.

## High-Density QA Ground Truth Summary
The flowchart begins with the user starting the process and forking the project. The user then selects a notification method from options like WeChat, Feishu, DingTalk, or Telegram bots. Each bot selection leads to configuring GitHub Secrets by entering the bot's webhook address. Following this, the user edits the `config/frequency_words.txt` file to add keywords of interest, which are used to filter the scraped data. The user then selects a run mode (daily, current, or incremental) from the `config/config.yaml` file. After configuration, the system automatically runs, scraping hot topics from various platforms and filtering them based on the configured keywords. Notifications are then pushed to the user's phone, and the user reviews the results. If the user is not satisfied with the notifications, the flow loops back to editing the keyword configuration. If the user is satisfied, they continue to receive personalized notifications. The `config/frequency_words.txt` file allows users to customize the notifications based on their specific interests.
