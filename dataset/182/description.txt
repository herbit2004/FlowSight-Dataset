## Diagram Type & Purpose
This is a flowchart diagram depicting a CI/CD (Continuous Integration/Continuous Deployment) pipeline. It illustrates the steps involved in making changes to an application, building and testing it, deploying it, and verifying the deployment. The diagram serves as a visual representation of the automated process for software release.

## Overall Layout
The diagram flows from left to right. It starts with making changes to the application and ends with the application updates being live or a system health check. The diagram includes decision diamonds to represent success checks at various stages.

## Edges, Branches & Convergence
- `nv --> n7`: Committing changes triggers the build and test of the frontend and backend.
- `n7 --> nf`: After building and testing, a success check is performed.
- `nf -- Yes --> n2`: If the build and test are successful, the Docker image is built and tested.
- `nf -- No --> n4`: If the build and test fail, the pipeline is canceled.
- `n2 --> n5`: After building and testing the Docker image, a success check is performed.
- `n5 -- Yes --> nx`: If the Docker image build and test are successful, the image is published to GitHub packages.
- `n5 -- No --> n4`: If the Docker image build and test fail, the pipeline is canceled.
- `nx --> nj`: After publishing the Docker image, a success check is performed.
- `nj -- Yes --> nd`: If publishing the Docker image is successful, the deployment stage is initiated.
- `nj -- No --> n4`: If publishing the Docker image fails, the pipeline is canceled.
- `nd --> nc`: The deployment stage involves logging into a VM and copying the Docker Compose file.
- `nc --> n6`: After logging in and copying the Docker Compose file, a success check is performed.
- `n6 -- Yes --> no`: If logging in and copying the Docker Compose file are successful, the previously pushed Docker image is pulled and the Docker Compose file is executed.
- `n6 -- No --> n4`: If logging in and copying the Docker Compose file fail, the pipeline is canceled.
- `no --> na`: After pulling the Docker image and executing the Docker Compose file, a success check is performed.
- `na -- Yes --> nk`: If pulling the Docker image and executing the Docker Compose file are successful, the updates are live.
- `na -- No --> ng`: If pulling the Docker image and executing the Docker Compose file fail, the system's health is checked.
- Multiple paths converge at `n4`: The "Cancel pipeline" node is reached if any of the success checks (nf, n5, nj, n6) fail.

## Repository Context & Terminology
- **Docker Image**: A lightweight, standalone, executable package that includes everything needed to run a piece of software, including the code, runtime, system tools, system libraries, and settings.
- **Docker Compose**: A tool for defining and running multi-container Docker applications. A Compose file is used to configure the application's services.
- **GitHub Packages**: A package hosting service, integrated with GitHub, that allows you to host your software packages privately or publicly.
- **VM (Virtual Machine)**: An emulation of a computer system. Virtual machines are based on computer architectures and provide functionality of a physical computer.
- **CI/CD Pipeline**: A process that automates the software release process, from code changes to deployment.
- **Docker Compose File**: A YAML file defining services, networks, and volumes for a Docker application.
