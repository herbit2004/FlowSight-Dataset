## 图类型与用途
该图是一个流程图，描述了工单处理过程中服务级别协议（SLA）的管理流程。它展示了工单从创建到解决或升级的整个生命周期，以及SLA对工单处理的影响。该流程图用于可视化和理解工单处理的SLA管理机制。

## 图的整体布局
该图采用从上到下的布局方式。整体流程从“工单创建”开始，经过SLA匹配和处理，最终到达“关闭工单”。图中存在循环，例如优先级重新评估后会重新进行SLA匹配。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. **工单创建与SLA匹配阶段**：包括工单创建、SLA匹配和优先级评估。
2. **SLA执行与监控阶段**：包括启动SLA时钟、SLA倒计时和等待解决。
3. **SLA超时处理阶段**：包括SLA超时判断、不同级别的升级和通知。
4. **工单解决与关闭阶段**：包括工单解决、停止SLA时钟、记录SLA信息和关闭工单。

## 节点逐项说明
- **工单创建**：流程的起始节点，表示创建一个新的工单。
- **SLA 匹配**：判断工单是否匹配现有的SLA规则。
- **SLA 规则引擎**：用于匹配工单和SLA规则的系统或模块。
- **SLA 已命中**：表示工单成功匹配到SLA规则。
- **启动 SLA 时钟**：开始计算工单处理的剩余时间。
- **SLA 倒计时**：SLA时钟持续倒计时，监控工单是否超时。
- **SLA 超时**：判断工单是否超过SLA规定的解决时间。
- **一级升级**：将工单升级到技术支持团队处理。
- **二级升级**：将工单升级到业务支持团队处理。
- **通知值班经理**：当工单超时达到更高等级时，通知值班经理。
- **自动分配**：系统自动将工单分配给合适的处理人员。
- **工单解决**：工单问题得到解决。
- **SLA 时钟停止**：停止SLA时钟的计时。
- **记录 SLA 信息**：记录工单的SLA相关信息，如是否超时、升级情况等。
- **关闭工单**：流程的结束节点，表示工单已完成处理。
- **重新评估优先级**：重新评估工单的优先级。
- **更新工单信息**：更新工单的相关信息。
- **等待解决**：工单等待被解决的状态。
- **技术支持团队**：负责处理一级升级的工单。
- **业务支持团队**：负责处理二级升级的工单。

## 连线、分支与汇聚关系
- `A --> B`：工单创建后进行SLA匹配。
- `B -- 是 --> D`：如果SLA匹配成功，则SLA已命中。
- `B -- 否 --> P`：如果SLA匹配失败，则重新评估优先级。
- `P --> Q`：重新评估优先级后，更新工单信息。
- `Q --> B`：更新工单信息后，重新进行SLA匹配。
- `D --> E`：SLA已命中后，启动SLA时钟。
- `E --> F`：启动SLA时钟后，进行SLA倒计时。
- `F --> R`：SLA倒计时后，工单进入等待解决状态。
- `R -- 超时 --> G`：如果工单超时，则判断SLA是否超时。
- `R -- 解决 --> L`：如果工单解决，则进入工单解决流程。
- `G -- 一级超时 --> H`：如果一级超时，则进行一级升级。
- `H --> S`：一级升级后，交给技术支持团队处理。
- `S --> R`：技术支持团队处理后，工单重新进入等待解决状态。
- `G -- 二级超时 --> I`：如果二级超时，则进行二级升级。
- `I --> T`：二级升级后，交给业务支持团队处理。
- `T --> R`：业务支持团队处理后，工单重新进入等待解决状态。
- `G -- 更高级别超时 --> J`：如果更高级别超时，则通知值班经理。
- `J --> K`：通知值班经理后，进行自动分配。
- `K --> R`：自动分配后，工单重新进入等待解决状态。
- `L --> M`：工单解决后，停止SLA时钟。
- `M --> N`：停止SLA时钟后，记录SLA信息。
- `N --> O`：记录SLA信息后，关闭工单。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **工单**：用户提交的需要处理的任务或请求。
- **SLA (Service Level Agreement)**：服务级别协议，定义了服务提供商与用户之间的服务质量标准。
- **SLA 规则引擎**：用于匹配工单和SLA规则的系统或模块。
- **优先级**：工单处理的紧急程度或重要性。
- **超时**：超过SLA规定的解决时间。
- **升级**：将工单转交给更高级别的支持团队处理。
- **值班经理**：负责监控和协调工单处理的高级管理人员。

## 可作为 QA Ground Truth 的高信息密度摘要
工单创建后，系统进行SLA匹配，如果匹配成功则启动SLA时钟并开始倒计时，工单进入等待解决状态。如果工单在SLA规定时间内解决，则停止SLA时钟，记录SLA信息并关闭工单。如果工单超时，则根据超时级别进行升级，可能升级到技术支持团队、业务支持团队，或者通知值班经理并自动分配。升级后工单重新进入等待解决状态，直到工单解决并关闭。如果SLA匹配失败，则重新评估优先级并更新工单信息，然后再次进行SLA匹配。
