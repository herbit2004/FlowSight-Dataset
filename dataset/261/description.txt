## 图类型与用途
这是一个流程图，描述了无梯度优化器如何与搜索空间、目标函数和搜索数据交互以进行优化。该图旨在展示优化过程中数据在不同组件之间的流动和依赖关系，是理解该优化框架的核心概念图。

## 图的整体布局
图采用中心辐射型布局，优化器位于左侧，搜索空间位于顶部，目标函数位于右侧，搜索数据位于底部中心。箭头指示了数据在这些组件之间的流动方向。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为参数提议、目标评估、结果反馈和数据存储四个阶段。

## 节点逐项说明
- **Optimizer**：代表优化器，包含21种不同的算法，用于提出新的参数组合。根据 README，该库提供了21种优化算法的统一接口。
- **Search Space**：代表搜索空间，参数以NumPy数组的形式存在。优化器在这个空间中寻找最佳参数。根据 `docs/source/user_guide/search_spaces.rst`，搜索空间定义了参数的取值范围和类型，可以是连续的（tuple）、离散的（NumPy array）或分类的（Python list）。
- **Objective**：代表目标函数，接受参数作为输入，并返回一个分数（score）。这个分数用于评估参数组合的优劣。根据 `docs/source/user_guide/objective_functions.rst`，目标函数是优化的核心，它接收参数字典并返回一个数值评分，默认情况下，GFO 尝试最大化这个评分。
- **Search Data**：代表搜索数据，包含优化过程的历史记录。图中可见，但仓库上下文未进一步说明。

## 连线、分支与汇聚关系
- `Optimizer -> Search Space`：优化器通过 `propose` 操作向搜索空间提出新的参数组合。
- `Search Space -> Objective`：搜索空间将参数（`params`）传递给目标函数。
- `Objective -> Optimizer`：目标函数计算出分数（`score`）并返回给优化器，用于评估参数组合的优劣。
- `Optimizer -.-> Search Data`：优化器将搜索过程中的数据存储到搜索数据中。
- `Search Data -.-> Optimizer`：搜索数据可以作为优化器的 `warm start`，用于初始化或指导后续的搜索过程。

## 仓库语境与术语解释
- **Optimizer (O)**：实现了搜索策略，该库提供了21种算法，涵盖局部搜索、全局搜索、基于种群和序列模型等类别。
- **Search Space (S)**：定义了有效的参数组合，使用NumPy数组表示。每个键是参数名，每个值是允许值的数组。
- **Objective Function (F)**：需要最大化的函数。它接受一个参数字典，并返回一个分数。可以使用取反来实现最小化。
- **Search Data (D)**：包含了所有评估的完整历史记录，可以通过 `opt.search_data` 访问，用于分析和热启动未来的搜索。
- **Gradient-Free Optimization**：一种优化黑盒函数的方法，不需要计算梯度。
- **NumPy arrays**：用于定义离散搜索空间，指定参数可以取哪些数值。
- **Warm start**：使用之前的搜索数据来初始化或指导后续的搜索过程，可以加速优化过程。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了无梯度优化算法框架的核心流程：优化器首先在搜索空间中提出参数组合，然后目标函数评估这些参数的性能并返回评分，优化器根据评分调整搜索策略，并将搜索数据存储起来用于后续的 warm start。整个流程形成一个闭环，优化器通过与搜索空间和目标函数交互，并利用历史数据，不断改进参数以获得更好的结果。其中，搜索空间定义了参数的取值范围，目标函数用于评估参数组合的优劣，而搜索数据则记录了优化过程的历史信息。
