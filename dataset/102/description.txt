## 图类型与用途
这是一个流程图，描述了 `mermaid-fixer` 工具处理 Markdown 文件中 Mermaid 图表的核心流程。它展示了该工具如何扫描目录、解析 Markdown 文件、提取 Mermaid 代码块、验证语法、使用 AI 修复错误，并最终保存文件。

## 图的整体布局
图采用从上到下的布局。顶部是扫描和解析阶段，中间是验证和修复阶段，底部是循环处理和保存阶段。流程从目录扫描开始，到保存文件结束。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为四个阶段：
- **扫描与提取阶段**：包括 "Directory Scanner"、"Markdown Parser" 和 "Mermaid Extractor" 节点，负责从 Markdown 文件中提取 Mermaid 代码块。
- **语法验证阶段**：包括 "Syntax Validator" 和 "Valid?" 节点，用于验证提取出的 Mermaid 代码块的语法是否正确。
- **AI 修复阶段**：包括 "AI Fixer"、"Re-validate" 和 "Fixed?" 节点，用于使用 AI 模型尝试自动修复语法错误。
- **循环与保存阶段**：包括 "Skip Block"、"Update Content"、"Log Error"、"Next Block"、"More Blocks?" 和 "Save File" 节点，用于处理每个 Mermaid 代码块，并在处理完所有代码块后保存文件。

## 节点逐项说明
- **A [Directory Scanner]**：负责扫描指定的目录，寻找需要处理的 Markdown 文件。根据 `README.md` 和 `src/markdown_scanner.rs`，该模块递归扫描目录，并过滤 `.git`、`node_modules` 等无关路径。
- **B [Markdown Parser]**：解析扫描到的 Markdown 文件，将其结构化。
- **C [Mermaid Extractor]**：从解析后的 Markdown 文件中提取出 Mermaid 代码块。根据 `src/utils.rs`，该模块提取所有 ` ```mermaid ` 代码块及其在文件中的位置信息。
- **D [Syntax Validator]**：验证提取出的 Mermaid 代码块的语法是否正确。根据 `src/mermaid_validator.rs`，该模块使用 `mermaid-rs` 引擎进行语法校验，并返回结构化错误类型。
- **E {Valid?}**：一个判断节点，根据语法验证器的结果判断 Mermaid 代码块是否有效。
- **F [Skip Block]**：如果 Mermaid 代码块语法有效，则跳过该代码块，不再进行后续处理。
- **G [AI Fixer]**：如果 Mermaid 代码块语法无效，则使用 AI 模型尝试自动修复语法错误。根据 `src/ai_fixer.rs`，该模块调用远程 LLM API（如 Mistral）请求修复。
- **H [Re-validate]**：对 AI 修复后的 Mermaid 代码块再次进行语法验证。
- **I {Fixed?}**：一个判断节点，根据重新验证的结果判断 Mermaid 代码块是否已被成功修复。
- **J [Update Content]**：如果 Mermaid 代码块已被成功修复，则将 Markdown 文件中对应的 Mermaid 代码块替换为修复后的代码。
- **K [Log Error]**：如果 Mermaid 代码块无法被修复，则记录错误信息，方便后续排查。
- **L [Next Block]**：处理完当前 Mermaid 代码块后，开始处理下一个代码块。
- **M {More Blocks?}**：一个判断节点，判断 Markdown 文件中是否还有未处理的 Mermaid 代码块。
- **N [Save File]**：处理完所有 Mermaid 代码块后，保存修改后的 Markdown 文件。

## 连线、分支与汇聚关系
- `A [Directory Scanner] -> B [Markdown Parser]`：目录扫描器将扫描到的文件传递给 Markdown 解析器。
- `B [Markdown Parser] -> C [Mermaid Extractor]`：Markdown 解析器将解析后的文件传递给 Mermaid 提取器。
- `C [Mermaid Extractor] -> D [Syntax Validator]`：Mermaid 提取器将提取出的代码块传递给语法验证器。
- `D [Syntax Validator] -> E {Valid?}`：语法验证器将验证结果传递给判断节点。
- `E {Valid?} -- Yes --> F [Skip Block]`：如果代码块有效，则跳过该代码块。
- `E {Valid?} -- No --> G [AI Fixer]`：如果代码块无效，则使用 AI 修复器。
- `G [AI Fixer] -> H [Re-validate]`：AI 修复器将修复后的代码传递给重新验证节点。
- `H [Re-validate] -> I {Fixed?}`：重新验证节点将验证结果传递给判断节点。
- `I {Fixed?} -- Yes --> J [Update Content]`：如果代码块已修复，则更新内容。
- `I {Fixed?} -- No --> K [Log Error]`：如果代码块未修复，则记录错误。
- `F [Skip Block] -> L [Next Block]`：跳过代码块后，进入下一个代码块的处理。
- `J [Update Content] -> L [Next Block]`：更新内容后，进入下一个代码块的处理。
- `K [Log Error] -> L [Next Block]`：记录错误后，进入下一个代码块的处理。
- `L [Next Block] -> M {More Blocks?}`：处理完当前代码块后，判断是否还有更多代码块。
- `M {More Blocks?} -- Yes --> D [Syntax Validator]`：如果还有更多代码块，则返回语法验证器。
- `M {More Blocks?} -- No --> N [Save File]`：如果没有更多代码块，则保存文件。

## 仓库语境与术语解释
- **Mermaid Fixer**：一个用 Rust 构建的工具，用于自动检测和修复 Markdown 文件中的 Mermaid 图表语法错误。
- **Markdown Scanner**：负责扫描指定目录下的所有 Markdown 文件。
- **Mermaid Extractor**：负责从 Markdown 文件中提取 Mermaid 代码块。
- **Syntax Validator**：使用 `mermaid-rs` 引擎验证 Mermaid 代码块的语法是否正确。
- **AI Fixer**：使用 AI 模型（如 LLM API）尝试自动修复语法错误。根据 `README.md`，该工具集成了大型语言模型 (LLMs) 来智能修复损坏的图表，同时保留其原始意图和结构。
- **config.toml**：配置文件，用于配置 LLM API 密钥、模型、超时时间等参数。根据 `README.md`，可以通过配置文件或命令行参数指定 LLM API 密钥。
- **Dry-run mode**：一种模式，只检测问题，不执行修复。根据 `README.md`，该模式用于安全测试。
