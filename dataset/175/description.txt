## Diagram Type & Purpose
This is a flowchart diagram depicting the vulnerability scanning and policy enforcement process for uploaded artifacts. It illustrates the steps involved in identifying vulnerabilities in artifacts, scoring them, and determining whether they should be stored or quarantined based on policy evaluation. The diagram serves as a visual representation of the artifact security pipeline.

## Overall Layout
The diagram flows from left to right. It starts with "Artifact Upload" and ends with either "Stored" or "Quarantined." The core process involves deduplication, scanning for vulnerabilities using multiple tools, scoring the vulnerabilities, and then applying a policy engine.

## Edges, Branches & Convergence
- `Artifact Upload --> SHA-256 Dedup`: An artifact is uploaded and passed to the deduplication process.
- `SHA-256 Dedup --> Trivy FS Scanner`: If the artifact is new, it is sent to the Trivy FS Scanner.
- `SHA-256 Dedup --> Grype Dependency Scanner`: If the artifact is new, it is sent to the Grype Dependency Scanner.
- `SHA-256 Dedup --> Cached Results`: If the artifact has already been scanned, the cached results are retrieved.
- `Trivy FS Scanner --> Vulnerability Score A-F`: Trivy FS Scanner results are fed into the vulnerability scoring process.
- `Grype Dependency Scanner --> Vulnerability Score A-F`: Grype Dependency Scanner results are fed into the vulnerability scoring process.
- `Cached Results --> Vulnerability Score A-F`: Cached results are fed into the vulnerability scoring process.
- `Vulnerability Score A-F --> Policy Engine`: The vulnerability score is passed to the policy engine for evaluation.
- `Policy Engine -- Pass --> Stored`: If the policy engine evaluation passes, the artifact is stored.
- `Policy Engine -- Fail --> Quarantined`: If the policy engine evaluation fails, the artifact is quarantined.
- Trivy FS Scanner, Grype Dependency Scanner, and Cached Results all converge at Vulnerability Score A-F.

## Repository Context & Terminology
- **SHA-256**: A cryptographic hash function used for deduplication, ensuring that identical artifacts are not scanned multiple times.
- **Trivy**: A comprehensive and easy-to-use security scanner. Trivy scans for vulnerabilities in container images, file systems, and Git repositories, as well as secrets, misconfigurations, and SBOM.
- **Grype**: A vulnerability scanner for container images and file systems. More specifically, Grype will scan a software artifact and produce a Software Bill of Materials (SBOM). Grype will then cross-reference the discovered packages and versions against its vulnerability database.
- **Vulnerability Score**: A numerical or categorical representation of the severity of identified vulnerabilities, often using scales like A-F or CVSS scores.
- **Policy Engine**: A component that evaluates artifacts against predefined security policies, determining whether they meet the required standards for storage or require quarantine.
