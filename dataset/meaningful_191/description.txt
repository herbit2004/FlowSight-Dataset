## Diagram Type & Purpose
This is a flowchart diagram illustrating the workflow of an inventory system. It depicts the process from receiving an order request to handling successful order fulfillment or managing failures, including inventory recovery and customer notification. The diagram serves as a visual representation of the order processing logic and error handling mechanisms within the inventory system.

## Overall Layout
The diagram is laid out from left to right (LR). It has a hierarchical structure with an overall "Inventory System" subgraph containing nested subgraphs for "Event Queue" and "Order Management". The start node is "Receive Order Request", and the end nodes include "Update Order History: Recovery Logged", "Create Incident Ticket", and "Create Refund Request".

## Subgraphs / Stages
The diagram contains three explicit subgraphs:

- **Event Queue**: Handles asynchronous events related to inventory deduction failures.
- **Order Management**: Manages order history updates and incident creation.

## Edges, Branches & Convergence
- `A --> B`: The order request is passed to the validation process.
- `B -- Valid --> C`: If the order is valid, reserve the inventory.
- `B -- Invalid --> I`: If the order is invalid, reject the order due to inventory unavailability.
- `C --> D`: The inventory reservation process leads to a success check.
- `D -- Yes --> E`: If inventory reservation is successful, deduct the inventory.
- `D -- No (Partial Failure) --> F`: If inventory reservation fails partially, rollback the reservation.
- `E --> G`: After deducting inventory, update the order status to processing.
- `E -- Inventory Deduction Error --> M`: If there's an inventory deduction error, trigger the "Inventory Deduction Failure Event".
- `F --> I`: After rolling back the inventory reservation, reject the order due to inventory unavailability.
- `G --> H`: After updating the order status to processing, ship the order.
- `H --> J`: After shipping the order, update the order status to shipped.
- `K --> L`: When an order is rejected, notify the customer of the rejection.
- `L --> T`: After notifying the customer of rejection, send a rejection email.
- `M --> N`: When an inventory deduction fails, start inventory recovery.
- `N --> O`: After starting inventory recovery, identify the failed deduction.
- `O --> P`: After identifying the failed deduction, compensate inventory levels.
- `P --> Q`: After compensating inventory levels, check if compensation was successful.
- `Q -- Yes --> R`: If compensation is successful, log the recovery success.
- `Q -- No --> S`: If compensation fails, alert the operations team for manual intervention.
- `R --> V`: After logging recovery success, update the order history to reflect the recovery.
- `S --> W`: If manual intervention is required, create an incident ticket.
- `T --> U`: After sending a rejection email, create a refund request.

## Repository Context & Terminology
- **Inventory System**: A system responsible for managing and tracking the quantity and availability of products.
- **Order**: A request from a customer to purchase goods or services.
- **Inventory Reservation**: The process of temporarily allocating inventory to fulfill an order.
- **Inventory Deduction**: The process of reducing the available inventory count after an order is shipped.
- **Event Queue**: A message queue used for asynchronous communication between different parts of the system, often used for handling errors or failures.
- **Compensation**: Actions taken to correct errors or failures, such as restoring inventory levels.
- **Incident Ticket**: A record of an issue or problem that requires investigation and resolution.

## High-Density QA Ground Truth Summary
The inventory system process begins with "Receive Order Request", followed by "Validate Order". If the order is valid, the system proceeds to "Reserve Inventory"; otherwise, the flow branches to "Reject Order: Inventory Unavailable". Upon successful inventory reservation, the system attempts to "Deduct Inventory". An "Inventory Deduction Error" triggers the "Inventory Deduction Failure Event" within the "Event Queue", initiating "Start Inventory Recovery". The system then attempts to "Identify Failed Deduction" and "Compensate Inventory Levels". The success of compensation is evaluated at "Compensation Successful?". If successful, the system "Log Recovery Success" and "Update Order History: Recovery Logged" within the "Order Management" subgraph. If compensation fails, the system "Alert Operations Team: Manual Intervention" and "Create Incident Ticket". If the initial inventory reservation fails partially, the system executes "Rollback Inventory Reservation" and subsequently "Reject Order: Inventory Unavailable". Order rejection leads to "Notify Customer of Rejection" and "Send Rejection Email", culminating in "Create Refund Request". The "Event Queue" and "Order Management" subgraphs handle asynchronous error recovery and logging, respectively, ensuring system resilience and auditability.
