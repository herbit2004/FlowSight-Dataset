## Diagram Type & Purpose

It depicts the sequence of steps involved from when a user initiates an order to when the order is either fulfilled or cancelled. This diagram serves as a visual representation of the order processing logic.

## Edges, Branches & Convergence
- `A --> B`: User initiates the order, leading to a stock check.
- `B -- No --> C`: If the item is not in stock, notify the user.
- `B -- Yes --> D`: If the item is in stock, check if payment is received.
- `C --> F`: Notifying the user of out-of-stock status leads to the end of the process.
- `D -- No --> E`: If payment is not received, cancel the order.
- `D -- Yes --> G`: If payment is received, send a shipping confirmation.
- `E --> F`: Cancelling the order leads to the end of the process.
- `G --> H`: After sending shipping confirmation, prepare the shipment.
- `H --> I`: After preparing the shipment, check if the address is valid.
- `I -- No --> K`: If the address is NOT valid, ship the order (incorrect path).
- `I -- Yes --> J`: If the address IS valid, update the inventory.
- `J --> K`: After updating inventory, ship the order.
- `K --> L`: After shipping the order, check if the order is delivered.
- `L -- No --> H`: If the order is not delivered, go back to preparing the shipment (incorrect retry trigger).
- `L -- Yes --> M`: If the order is delivered, archive the order data.
- `M --> F`: Archiving the order data leads to the end of the process.

## High-Density QA Ground Truth Summary
The order processing flowchart begins with a "User Initiates Order," which immediately leads to checking "Item in Stock?". If the item is not in stock, the user is notified, and the process ends. If the item is in stock, the system checks "Payment Received?". If payment is not received, the order is cancelled, and the process ends. If payment is received, a "Shipping Confirmation Sent" is triggered *before* "Prepare Shipment," a reversed sequence. The system then proceeds to "Address Valid?". A 'No' on address validity incorrectly leads to "Ship Order" without correction. A 'Yes' on address validity triggers "Update Inventory" before "Ship Order." After shipping, the system checks "Order Delivered?". If the order is delivered, "Archive Order Data" is performed, and the process ends. If the order is not delivered, the process loops back to "Prepare Shipment," an illogical retry trigger. The process terminates at the "End" node, reached either after archiving order data or after notifying the user of out-of-stock status or cancelling the order. The "Shipping Confirmation Sent" node represents an email notification to the user, while "Archive Order Data" might correspond to database updates for record-keeping.
