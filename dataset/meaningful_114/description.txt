## 图类型与用途
这是一个流程图，用于描述一个规则引擎的工作流程。该图展示了数据从接入到最终决策执行的整个过程，包括数据清洗、规则匹配、决策制定以及监控反馈等环节。该流程图可以帮助理解规则引擎的内部运作机制。

## 图的整体布局
该图采用从上到下的布局方式。整体上分为数据接入层、规则引擎核心和策略执行层三个主要层次。流程从实时数据流和离线数据仓库开始，最终到阻断/放行结束。

## 分组/子图/阶段说明
图中包含三个子图：
- **数据接入层**：负责接入实时数据流和离线数据仓库的数据，并进行清洗和转换。
- **规则引擎核心**：负责决策预处理、特征计算、规则匹配和风险决策。
- **策略执行层**：负责执行最终的决策，并进行监控和报警。

## 节点逐项说明
- **实时数据流**：实时产生的数据流，作为规则引擎的输入。
- **离线数据仓库**：存储历史数据的仓库，作为规则引擎的输入。
- **数据清洗与转换**：对接入的数据进行清洗和转换，使其符合规则引擎的要求。
- **规则引擎核心**：规则引擎的核心模块，负责规则的匹配和决策的制定。
- **决策预处理**：对数据进行预处理，为后续的规则匹配做准备。
- **预热特征**：预先计算好的特征，用于规则匹配。
- **实时特征计算**：实时计算的特征，用于规则匹配。
- **规则匹配**：将数据与规则进行匹配，判断是否命中规则。
- **风险决策**：根据命中的规则，制定风险决策。
- **默认决策**：如果没有命中任何规则，则采用默认的决策。
- **策略执行层**：执行最终的决策，例如阻断或放行。
- **阻断/放行**：根据决策结果，对请求进行阻断或放行。
- **监控与报警**：对决策执行的结果进行监控，并进行报警。
- **规则优化反馈**：根据监控结果，对规则进行优化。
- **规则配置管理**：对规则进行配置和管理。

## 连线、分支与汇聚关系
- 实时数据流 -> 数据清洗与转换：实时数据流经过数据清洗与转换。
- 离线数据仓库 -> 数据清洗与转换：离线数据仓库的数据经过数据清洗与转换。
- 数据清洗与转换 -> 规则引擎核心：清洗后的数据进入规则引擎核心。
- 规则引擎核心 -> 决策预处理：规则引擎核心进行决策预处理。
- 决策预处理 -- 命中预热规则 --> 预热特征：如果命中预热规则，则使用预热特征。
- 决策预处理 -- 未命中预热规则 --> 实时特征计算：如果没有命中预热规则，则进行实时特征计算。
- 预热特征 -> 规则匹配：预热特征用于规则匹配。
- 实时特征计算 -> 规则匹配：实时特征用于规则匹配。
- 规则匹配 -- 命中规则 --> 风险决策：如果命中规则，则进行风险决策。
- 规则匹配 -- 未命中规则 --> 默认决策：如果没有命中规则，则采用默认决策。
- 风险决策 -> 策略执行层：风险决策进入策略执行层。
- 默认决策 -> 策略执行层：默认决策进入策略执行层。
- 策略执行层 -> 阻断/放行：策略执行层执行阻断或放行操作。
- 阻断/放行 -> 监控与报警：阻断/放行的结果进入监控与报警模块。
- 监控与报警 -> 规则优化反馈：监控与报警的结果用于规则优化反馈。
- 规则优化反馈 -> 规则配置管理：规则优化反馈的结果用于规则配置管理。
- 规则配置管理 -> 规则引擎核心：规则配置管理的结果反馈给规则引擎核心。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **规则引擎**：一种用于自动化决策的系统，它根据预定义的规则对输入数据进行评估，并输出相应的决策结果。
- **特征**：用于描述数据的属性或指标，是规则引擎进行决策的依据。
- **规则**：一种条件-动作语句，用于定义在特定条件下应该执行的操作。
- **决策**：规则引擎根据输入数据和规则做出的判断或选择。
- **策略**：一系列规则和决策的组合，用于实现特定的业务目标。
- **阻断/放行**：一种常见的策略执行方式，用于控制对资源的访问。

## 可作为 QA Ground Truth 的高信息密度摘要
流程从实时数据流和离线数据仓库接入数据，经过数据清洗与转换后进入规则引擎核心。在规则引擎核心中，首先进行决策预处理，根据是否命中预热规则，选择使用预热特征或进行实时特征计算。然后，通过规则匹配，如果命中规则则进行风险决策，否则采用默认决策。最终，决策结果进入策略执行层，执行阻断或放行操作，并将结果反馈给监控与报警模块，用于规则优化反馈和规则配置管理，形成闭环。
