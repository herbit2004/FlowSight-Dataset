## 图类型与用途
这是一个流程图，描述了 MCP SuperAssistant Chrome 扩展如何处理 AI 聊天界面生成的工具调用，并将其与 MCP 服务器连接，最终将结果返回到聊天界面。它展示了数据在不同组件之间的流动和交互。

## 图的整体布局
图采用从上到下的布局。流程从 AI 聊天界面开始，经过一系列处理步骤，最终将结果添加回聊天界面。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：工具调用生成与检测、MCP 服务器交互、结果返回与插入。

## 节点逐项说明
- **AI Chat Interface**：代表 AI 聊天界面，例如 ChatGPT、Perplexity 等，用户在此与 AI 交互。根据 README，MCP SuperAssistant 支持多种 AI 平台。
- **Tool Calls**：代表 AI 聊天界面生成的工具调用请求。这些请求指示 AI 需要使用外部工具来完成特定任务。
- **Extension Detects Tool Calls**：代表 MCP SuperAssistant 扩展，它负责检测 AI 聊天界面生成的工具调用。
- **MCP Local Proxy Server**：代表 MCP 本地代理服务器，它作为扩展和实际 MCP 服务器之间的中介。README 中提到可以通过 `npx` 启动本地代理服务器。
- **Actual MCP Server**：代表实际的 MCP 服务器，它处理工具调用请求并返回结果。
- **Add Results Back to Chat**：代表将 MCP 服务器返回的结果插入回 AI 聊天界面。

## 连线、分支与汇聚关系
- `AI Chat Interface -> Tool Calls`：AI 聊天界面生成工具调用。
- `Tool Calls -> Extension Detects Tool Calls`：MCP SuperAssistant 扩展检测到这些工具调用。
- `Extension Detects Tool Calls -> MCP Local Proxy Server`：扩展通过 Server-Sent Events (SSE) 将工具调用发送到 MCP 本地代理服务器。
- `MCP Local Proxy Server -> Actual MCP Server`：本地代理服务器将工具调用转发到实际的 MCP 服务器。
- `Actual MCP Server -> MCP Local Proxy Server`：MCP 服务器处理工具调用并返回结果给本地代理服务器。
- `MCP Local Proxy Server -> Extension Detects Tool Calls`：本地代理服务器将结果返回给扩展。形成汇聚关系。
- `Extension Detects Tool Calls -> Add Results Back to Chat`：扩展将结果插入回 AI 聊天界面。

## 仓库语境与术语解释
- **MCP (Model Context Protocol)**：是由 Anthropic 开发的开放标准，用于连接 AI 助手和数据系统。
- **MCP SuperAssistant Chrome Extension**：一个 Chrome 扩展，集成了 MCP 工具与 AI 平台，允许用户直接从这些平台执行 MCP 工具。
- **Tool Calls**：AI 聊天界面生成的工具调用请求，指示 AI 需要使用外部工具来完成特定任务。
- **SSE (Server-Sent Events)**：一种服务器推送技术，用于将数据从 MCP SuperAssistant 扩展发送到 MCP 本地代理服务器。`chrome-extension/src/mcpclient/plugins/sse/SSEPlugin.ts` 文件中定义了 SSE 插件。
- **MCP Local Proxy Server**：本地代理服务器，作为扩展和实际 MCP 服务器之间的中介。
- **config.json**：用于配置 MCP 服务器详细信息的文件，例如 Desktop Commander 的配置。README 中有提到。
- **Supported AI Platforms**：包括 ChatGPT, Perplexity, Google Gemini, Grok, Google AI Studio 等。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 MCP SuperAssistant 扩展如何处理 AI 聊天界面的工具调用。流程从 AI 聊天界面生成工具调用开始，扩展检测到这些调用后，通过 SSE 发送到 MCP 本地代理服务器，再转发到实际的 MCP 服务器进行处理。处理结果通过代理服务器返回给扩展，最终插入回聊天界面。MCP 作为连接 AI 助手和数据系统的协议，是该流程的核心。
