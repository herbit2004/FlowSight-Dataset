## 图类型与用途
该图是一个流程图，描述了用户签到与任务系统的流程。它展示了用户签到请求的处理过程，以及每日任务的发布和完成流程。该图可以帮助理解用户签到和任务系统的运作机制。

## 图的整体布局
该图从左到右布局，分为两个主要的子图：用户签到与任务系统、每日任务流程。用户签到流程从用户发起签到请求开始，到记录签到日志结束。每日任务流程从每日凌晨重置任务状态开始，到发放任务奖励结束。

## 分组/子图/阶段说明
图中有两个显式的子图：
- **用户签到与任务系统**：描述用户签到的完整流程，包括签到状态检查、经验/积分增加、签到任务处理等。
- **每日任务流程**：描述每日任务的发布、完成和奖励发放流程。

## 节点逐项说明
- **A[用户发起签到请求]**：用户向系统发送签到请求。
- **B{检查今日是否已签到}**：系统检查用户今天是否已经签到。
- **C[返回已签到信息]**：如果用户已签到，系统返回已签到信息。
- **D[更新用户签到记录]**：如果用户未签到，系统更新用户的签到记录。
- **E[增加用户经验值/积分]**：系统增加用户的经验值或积分。
- **F[检查是否有待完成的签到任务]**：系统检查用户是否有待完成的签到任务。
- **G[返回签到成功信息]**：系统返回签到成功信息。
- **H[更新签到任务进度]**：系统更新签到任务的进度。
- **I{签到任务已完成?}**：系统判断签到任务是否已完成。
- **J[发放签到任务奖励]**：如果签到任务已完成，系统发放签到任务奖励。
- **K[触发其他事件/通知]**：系统触发其他事件或发送通知。
- **L[记录签到日志]**：系统记录签到日志。
- **M[每日凌晨重置任务状态]**：系统在每日凌晨重置任务状态。
- **N[查询所有可发布的每日任务]**：系统查询所有可发布的每日任务。
- **O{用户是否满足任务发布条件?}**：系统判断用户是否满足任务发布条件。
- **P[发布每日任务给用户]**：如果用户满足条件，系统发布每日任务给用户。
- **Q[忽略该任务]**：如果用户不满足条件，系统忽略该任务。
- **R[用户完成每日任务]**：用户完成每日任务。
- **S[校验任务完成条件]**：系统校验任务完成条件。
- **T[发放任务奖励]**：如果任务完成条件满足，系统发放任务奖励。

## 连线、分支与汇聚关系
- A -> B：用户发起签到请求后，系统检查是否已签到。
- B -- 是 --> C：如果已签到，返回已签到信息。
- B -- 否 --> D：如果未签到，更新用户签到记录。
- D -> E：更新签到记录后，增加用户经验值/积分。
- E -> F：增加经验值/积分后，检查是否有待完成的签到任务。
- F -- 无签到任务 --> G：如果没有签到任务，返回签到成功信息。
- F -- 有签到任务 --> H：如果有签到任务，更新签到任务进度。
- H -> I：更新任务进度后，判断签到任务是否已完成。
- I -- 是 --> J：如果任务已完成，发放签到任务奖励。
- J -> G：发放奖励后，返回签到成功信息。
- I -- 否 --> G：如果任务未完成，返回签到成功信息。
- G -> K：返回签到成功信息后，触发其他事件/通知。
- K -> L：触发事件/通知后，记录签到日志。
- M -> N：每日凌晨重置任务状态后，查询所有可发布的每日任务。
- N -> O：查询任务后，判断用户是否满足任务发布条件。
- O -- 是 --> P：如果满足条件，发布每日任务给用户。
- O -- 否 --> Q：如果不满足条件，忽略该任务。
- Q -> N：忽略任务后，重新查询任务。
- P -> R：发布任务后，用户完成每日任务。
- R -> S：用户完成任务后，校验任务完成条件。
- S -- 满足 --> T：如果满足条件，发放任务奖励。
- S -- 不满足 --> R：如果不满足条件，重新完成任务。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **签到**：用户通过系统进行每日登记的行为，通常可以获得奖励。
- **经验值/积分**：用户在系统中积累的数值，可以用于提升等级或兑换奖励。
- **签到任务**：与签到行为相关的任务，例如连续签到多少天。
- **每日任务**：每天都会重置的任务，用户可以通过完成这些任务获得奖励。
- **任务发布条件**：用户需要满足的条件才能接收到每日任务，例如等级限制。
- **任务完成条件**：用户需要满足的条件才能算作完成每日任务。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起签到请求，系统检查是否已签到。如果已签到，返回已签到信息；否则，更新用户签到记录，增加经验值/积分，并检查是否有待完成的签到任务。如果有签到任务，更新任务进度，判断任务是否完成，完成则发放奖励，最后返回签到成功信息，触发其他事件/通知，并记录签到日志。同时，每日凌晨重置任务状态，查询可发布的每日任务，根据用户是否满足任务发布条件来发布任务，用户完成任务后，校验任务完成条件，满足则发放任务奖励。
