## 图类型与用途
这是一个架构图，描述了 IsoBridge 项目的整体架构，展示了各个组件之间的关系和数据流。IsoBridge 是一个用于解析、构建和转发 ISO 8583 消息的 .NET 6 应用，旨在桥接传统的金融交换系统和现代系统。该图在仓库中用于概览系统的模块化分层架构。

## 图的整体布局
图整体采用从上到下的分层布局，从顶部的 UI 层开始，依次是 Web/API 层、核心域、ISO8583 引擎、基础设施层和适配器层，最后是外部系统。数据流从 UI 层经过各层处理，最终到达外部系统。

## 分组/子图/阶段说明
图中包含多个子图，分别代表不同的层或模块：
- **UI Layer**：包含用户界面组件，是系统的入口。
- **IsoBridge.Web (ASP.NET Core)**：包含 ASP.NET Core Web API 组件，负责处理 HTTP 请求。
- **IsoBridge.Core**：包含核心业务逻辑组件，定义了领域模型和接口。
- **IsoBridge.ISO8583**：包含 ISO 8583 消息处理引擎的组件，负责消息的解析和构建。
- **IsoBridge.Infrastructure (Audit)**：包含基础设施组件，主要负责审计功能。
- **IsoBridge.Adapters**：包含消息转发适配器，负责将消息转发到外部系统。
- **External Upstream Hosts**：代表外部系统，是消息的最终目的地。

## 节点逐项说明
- **ISO Preview UI**：用于预览 ISO 8583 消息的 UI。
- **Admin Audit UI**：用于管理和审计交易记录的 UI。
- **Swagger UI**：用于浏览和测试 API 的 Swagger 界面。
- **IsoController (Parse • Build • Forward)**：处理 ISO 8583 消息的解析、构建和转发，对应 `IsoBridge.Web/Controllers/IsoController.cs`。
- **AdminAuditController (View • Verify • Export)**：处理审计数据的查看、验证和导出。
- **Service Registration & Routing**：负责服务注册和请求路由。
- **IIsoParser**：定义 ISO 8583 消息解析器的接口，对应 `IsoBridge.Core/ISO/IsoParserAbstraction.cs`。
- **IsoMessage • ParseResult**：表示 ISO 8583 消息和解析结果的数据结构。
- **AuditLoggingService**：负责审计日志记录。
- **Audit Interfaces IAuditStore • IAuditHasher**：定义审计存储和哈希的接口。
- **DefaultIsoParser**：`IIsoParser` 接口的默认实现，对应 `IsoBridge.ISO8583/DefaultIsoParser.cs`。
- **TemplateLoader**：负责加载 ISO 8583 消息模板。
- **Field Codec**：负责 ISO 8583 字段的编码和解码。
- **Bitmap Utils**：提供位图相关的工具函数。
- **iso8583-templates.json**：包含 ISO 8583 消息模板的 JSON 文件，对应 `IsoBridge.ISO8583/Config/iso8583-templates.json`。
- **AuditRepository**：负责审计数据的存储和检索，对应 `IsoBridge.Infrastructure/Audit/AuditRepository.cs`。
- **SHA256 Hasher**：使用 SHA256 算法进行哈希处理。
- **audit.db • SQLite**：用于存储审计数据的 SQLite 数据库。
- **ForwardingService**：负责将消息转发到外部系统，对应 `IsoBridge.Adapters/Forwarding/ForwardingService.cs`。
- **IForwarder**：定义消息转发器的接口。
- **RestForwarder**：使用 REST 协议转发消息。
- **SoapForwarder**：使用 SOAP 协议转发消息。
- **REST Payment Host**：REST 支付主机。
- **SOAP Switch Host**：SOAP 交换主机。

## 连线、分支与汇聚关系
- `ISO Preview UI -> IsoController`：ISO 预览 UI 将请求发送到 IsoController。
- `Admin Audit UI -> AdminAuditController`：Admin Audit UI 将请求发送到 AdminAuditController。
- `Swagger UI -> IsoController`：Swagger UI 将请求发送到 IsoController。
- `IsoController -> ForwardingService`：IsoController 将消息转发到 ForwardingService。
- `IsoController -> IIsoParser`：IsoController 使用 IIsoParser 解析和构建消息。
- `IsoController -> AuditLoggingService`：IsoController 使用 AuditLoggingService 记录审计日志。
- `AdminAuditController -> AuditRepository`：AdminAuditController 使用 AuditRepository 查询审计数据。
- `AuditLoggingService -> Audit Interfaces IAuditStore • IAuditHasher`：AuditLoggingService 使用审计接口进行审计。
- `DefaultIsoParser -.implements.-> IIsoParser`：DefaultIsoParser 实现了 IIsoParser 接口。
- `DefaultIsoParser -> TemplateLoader -> iso8583-templates.json`：DefaultIsoParser 使用 TemplateLoader 加载 iso8583-templates.json 中的模板。
- `DefaultIsoParser -> Field Codec`：DefaultIsoParser 使用 Field Codec 进行字段的编码和解码。
- `DefaultIsoParser -> Bitmap Utils`：DefaultIsoParser 使用 Bitmap Utils 处理位图。
- `AuditRepository -> audit.db • SQLite`：AuditRepository 将审计数据存储到 SQLite 数据库。
- `SHA256 Hasher -> Audit Interfaces IAuditStore • IAuditHasher`：SHA256 Hasher 实现了审计哈希接口。
- `ForwardingService -> IForwarder`：ForwardingService 使用 IForwarder 转发消息。
- `IForwarder -.REST.-> RestForwarder`：IForwarder 通过 REST 协议使用 RestForwarder。
- `IForwarder -.SOAP.-> SoapForwarder`：IForwarder 通过 SOAP 协议使用 SoapForwarder。
- `RestForwarder -> REST Payment Host`：RestForwarder 将消息发送到 REST 支付主机。
- `SoapForwarder -> SOAP Switch Host`：SoapForwarder 将消息发送到 SOAP 交换主机。

## 仓库语境与术语解释
- **ISO 8583**：一种国际标准的银行间交易报文格式，用于金融支付领域的报文交换。
- **MTI (Message Type Indicator)**：消息类型指示符，ISO 8583 消息的第一个字段，用于标识消息的类型。
- **Bitmap**：位图，用于指示 ISO 8583 消息中哪些字段存在。
- **Field Codec**：字段编解码器，负责 ISO 8583 字段的编码和解码。
- **audit.db**：SQLite 数据库文件，用于存储审计日志，记录每次消息解析、构建和转发操作。
- **Swagger UI**：用于浏览和测试 API 的 Swagger 界面，可以通过 `http://localhost:5000/swagger` 访问。
- **iso8583-templates.json**：JSON 格式的 ISO 8583 消息模板文件，定义了不同 MTI 消息的字段结构，位于 `IsoBridge.ISO8583/Config/iso8583-templates.json`。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 IsoBridge 的整体架构，从顶层的 UI 层（包括 ISO Preview UI、Admin Audit UI 和 Swagger UI）发起请求，经过 IsoBridge.Web 层的 IsoController 处理，IsoController 负责消息的解析、构建和转发，其中消息的解析和构建依赖于 IsoBridge.ISO8583 层的 DefaultIsoParser，该解析器使用 iso8583-templates.json 文件中的模板。消息转发通过 IsoBridge.Adapters 层的 ForwardingService 实现，最终将消息发送到外部的 REST Payment Host 或 SOAP Switch Host。所有操作都会被记录到 IsoBridge.Infrastructure 层的 audit.db 数据库中，实现审计功能。
