## High-Density QA Ground Truth Summary
The IsoBridge system's architecture begins with the UI layer, comprising the Admin Audit UI, Swagger UI, and ISO Preview UI. User interactions with these UIs trigger requests to the IsoBridge.Web layer, specifically the AdminAuditController and IsoController. The AdminAuditController handles requests related to admin audit functions, interacting with the AuditRepository to manage audit data stored in the audit.db SQLite database. The IsoController, responsible for parsing, building, and forwarding ISO messages, utilizes the IIsoParser interface, implemented by DefaultIsoParser in the IsoBridge.ISO8583 module. DefaultIsoParser relies on TemplateLoader to load message templates from iso8583-templates.json, and also uses Field Codec and Bitmap Utils for message encoding/decoding. The IsoController also interacts with the AuditLoggingService to log audit events, which in turn uses Audit Interfaces (IAuditStore, IAuditHasher). The IsoController forwards requests to the ForwardingService, which uses the IForwarder interface to delegate to either RestForwarder or SoapForwarder based on the protocol (REST or SOAP). Finally, RestForwarder and SoapForwarder forward requests to the external REST Payment Host and SOAP Switch Host, respectively. The SHA256 Hasher is used for data integrity, implementing the IAuditHasher interface.
