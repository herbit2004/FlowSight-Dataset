## Repository Context & Terminology
- **Frontend (UI)**: The user interface component of the application, responsible for presenting data and handling user interactions.
- **Controllers**: Components that receive requests from the UI, orchestrate the application logic, and return responses.
- **Casos de Uso (Use Cases)**: Specific functionalities or scenarios that the application supports.
- **Modelos (Models)**: Data structures representing the domain entities.
- **Repositórios (Repositories)**: Abstractions over data access, providing a consistent interface for interacting with databases or other data sources.
- **Interfaces das Portas (Gateways)**: Interfaces that define how the application interacts with external systems or services.
- **Clientes HTTP (HTTP Clients)**: Components responsible for making HTTP requests to external APIs.
- **Bancos de Dados SQL (SQL Databases)**: Relational databases used for storing application data.
- **APIs REST de IA (AI REST APIs)**: RESTful APIs providing access to AI-related functionalities.

## High-Density QA Ground Truth Summary
The diagram illustrates a layered architecture, starting with the Frontend (UI) which interacts directly with Controllers. The Controllers then communicate bidirectionally with Casos de Uso (Use Cases), which in turn interact bidirectionally with Modelos (Models). The diagram also shows external infrastructure components, Bancos de Dados SQL (SQL Databases) and APIs REST de IA (AI REST APIs). The layered architecture promotes separation of concerns, allowing for independent development and maintenance of each layer.
