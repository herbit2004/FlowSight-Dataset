## 图类型与用途
这是一个架构图，展示了一个 REST API 的分层架构，该 API 允许用户与 League of Legends (LOL) 英雄进行对话。该图在 README.md 中被用作项目架构的概览，强调了各层之间的职责分离和依赖关系。

## 图的整体布局
图采用从上到下的分层布局，从基础设施层开始，依次经过适配器层、应用层，最后到达实体层。数据流从顶部的 UI 开始，贯穿各层，最终与外部系统交互。

## 分组/子图/阶段说明
图中有三个显式子图：layer-infra (Infraestrutura)、layer-adpaters (Adaptadores) 和 layer-app (Aplicação)，以及一个嵌套在 layer-app 中的 layer-entities (Entidades (Domínio))。
- **layer-infra (Infraestrutura)**：基础设施层，包含 UI、数据库和外部 API。
- **layer-adpaters (Adaptadores)**：适配器层，负责应用与外部系统之间的交互。
- **layer-app (Aplicação)**：应用层，包含用例和实体。
- **layer-entities (Entidades (Domínio))**：实体层，定义了应用程序中使用的数据结构和实体。

## 节点逐项说明
- **UI ("Frontend (UI)")**：前端用户界面，负责与用户交互。
- **Controller ("Controllers")**：控制器层，接收来自前端的请求，并将其转发给应用层处理。对应 `src/main/java/me/dio/sdw24/adapters/in/AskChampionRestController.java`。
- **UC ("Casos de Uso")**：用例层/应用层，包含具体的业务逻辑，例如处理用户请求、调用 AI API、从数据库获取数据等。
- **Model ("Modelos")**：模型层，定义了应用程序中使用的数据结构和实体，例如 `src/main/java/me/dio/sdw24/domain/model/Champion.java`。
- **IPort ("Interfaces das Portas (Gateways)")**：端口接口层，定义了应用层与外部系统（如数据库、AI API）交互的接口。
- **Repo ("Repositórios")**：仓库层，负责与数据库进行交互，实现数据的持久化存储和读取。
- **HTTP ("Clientes HTTP")**：HTTP 客户端，负责与外部 REST API（特别是 AI API）进行通信。
- **BD ("Bancos de Dados SQL")**：SQL 数据库，用于存储应用程序的数据。
- **EXT ("APIs REST de IA")**：外部的 AI REST API，用于生成 LOL 英雄的对话内容。

## 连线、分支与汇聚关系
- `UI ---> Controller`：前端用户界面将请求发送到控制器。
- `Controller <--> UC`：控制器与用例层之间进行双向通信，控制器调用用例，用例返回结果给控制器。
- `UC <--> layer-entities`：用例层与实体层之间进行双向通信，用例层使用实体层定义的数据模型。
- `Repo -..-> |implementam| IPort`：仓库层实现了端口接口，即仓库层提供了端口接口的具体实现。
- `HTTP -..-> |implementam| IPort`：HTTP 客户端实现了端口接口，即 HTTP 客户端提供了端口接口的具体实现。
- `BD --- Repo`：数据库与仓库层进行交互，仓库层负责数据的读写操作。
- `EXT --- HTTP`：AI REST API 与 HTTP 客户端进行交互，HTTP 客户端负责发送请求并接收响应。

## 仓库语境与术语解释
- **REST API**：一种软件架构风格，用于构建基于 HTTP 协议的网络应用程序。
- **Frontend (UI)**：使用 HTML, CSS 和 JavaScript 构建的用户界面，用于与 API 交互。
- **Spring Boot**：一个 Java 框架，用于简化 Spring 应用程序的创建和部署。README 提到项目使用 Java 21 和 Spring Boot 3 构建。
- **Clean Architecture**：一种软件设计原则，旨在将业务逻辑与技术实现细节分离，提高代码的可维护性和可测试性。README 提到该项目架构与 Clean Architecture 原则对齐。
- **League of Legends (LOL)**：一款多人在线竞技游戏，该 API 旨在模拟 LOL 英雄的对话。
- **Inteligências Artificiais (IAs) Generativas**：用于生成 LOL 英雄对话内容的 AI 模型，例如 OpenAI (GPT) 和 Google (Gemini)。README 提到项目使用了这些 AI 模型。
- **AWS Elastic Beanstalk**：AWS 提供的 PaaS 服务，用于部署和管理 Web 应用程序。README 提到可以使用该服务部署 API。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 REST API 的分层结构，从前端 UI 发起请求，经过 Controller 传递到 UC (用例层)，UC 与 Model (模型) 交互，并通过 Repo 和 HTTP 客户端与数据库和外部 AI API 进行交互。该架构基于 Clean Architecture 原则，旨在实现与 League of Legends (LOL) 英雄进行对话的功能，并使用了 Spring Boot 框架和 AI 模型（如 OpenAI 和 Gemini）。关键路径是 UI -> Controller -> UC -> Model，以及 UC 通过 Repo 和 HTTP 与数据库和 AI API 的交互。
