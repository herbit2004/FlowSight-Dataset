## High-Density QA Ground Truth Summary
The architecture begins with the Client Layer, where either the CLI Interface (`packages/agent-client/src/cli.js`) or the API Server (`packages/api-server`) initiates a request to the MultiAgentDecisionExecutor in the Decision & Optimization Layer. The MultiAgentDecisionExecutor then coordinates agents and loads necessary schemas and context. It passes control to the CoordinatorAgent within the Multi-Agent System, which orchestrates the workflow by delegating tasks to PlannerAgent, ExecutorAgent, and AnalyzerAgent. The PlannerAgent handles intent analysis and plan generation, while the ExecutorAgent executes tasks using tools managed by the MCP Server. The AnalyzerAgent synthesizes results and ensures quality. Both PlannerAgent, ExecutorAgent, and AnalyzerAgent use the LLMFactory to create instances of different LLMs (ClaudeLLM, OpenAILLM, GeminiLLM, GroqLLM) for various tasks. The Tool Manager, part of the MCP Server Layer, interacts with TaskPlanner, SequentialThinker, and LoopDetector to manage tool execution. The Tool Manager also interacts with DuckDB for local analytics, File Providers for accessing files, and Neo4j Knowledge Graph for knowledge management. The MultiAgentDecisionExecutor also provides the DecisionContext, which is stored in both Neo4j Knowledge Graph and MongoDB for persistence. The system concludes with data persistence in the Data & Storage Layer, utilizing Neo4j Knowledge Graph, MongoDB, DuckDB, and File Providers. The AgentContext, a Supporting Component, provides session management and file tracking, while the PerformanceLogger tracks latency and pipeline stages.
