## Repository Context & Terminology
- **Flask**: A micro web framework written in Python. It is used to build the REST API in the application layer.
- **REST API**: An architectural style for designing networked applications. It relies on a stateless, client-server communication protocol, typically HTTP.
- **RFNoC**: Radio Frequency Network on Chip. A framework for building high-performance SDR applications on FPGAs.
- **FPGA**: Field-Programmable Gate Array. An integrated circuit that can be configured by the user after manufacturing.
- **USRP X310**: A software-defined radio (SDR) platform manufactured by Ettus Research. It is used for transmitting and receiving radio signals.
- **GSCN**: Global System Cell Network.
- **Bootstrap**: A popular CSS framework for developing responsive and mobile-first websites.

## High-Density QA Ground Truth Summary
The system architecture begins with the `index.html` file in the User Interface Layer, which interacts with JavaScript for real-time updates. Bootstrap CSS provides responsive design. The JavaScript communicates with the `app.py` Flask application via a REST API. The Flask application then interacts with several modules: `config.py` for settings management, which reads from and writes to `config.json`; `gscn_calculator.py` for frequency calculation, which writes to `detected_frequencies.json`; and `usrp_controller.py` for hardware control. The `usrp_controller.py` module interacts with the Data Layer, reading and writing `detected_frequencies.json` and `*.dat` files containing signal data. It also initiates the `init_ssb_block` RFNoC application in the Hardware Layer. The RFNoC application loads the `FPGA Bitstream` for custom processing, which configures the `USRP X310` SDR hardware. The USRP X310 is the final hardware component. The `config.py` file manages settings, demonstrating a key aspect of the application layer's role in configuring the system's behavior.
