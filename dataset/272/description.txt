## 图类型与用途
这是一个流程图，描述了 Self-Refine 框架通过迭代和自我反馈来改进输出的过程。它在仓库中的作用是展示 Self-Refine 框架的核心工作流程。

## 图的整体布局
图整体采用从左到右的布局。流程从生成器开始，经过多次迭代改进，最终输出精炼的输出结果。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：初始生成阶段、反馈与提炼阶段、迭代改进阶段。

## 节点逐项说明
- **Generator**：生成初始输出，作为整个流程的起点。
- **Unrefined (Output to Refine)**：表示需要改进的初始输出，是迭代过程中的中间状态，接收来自生成器的初始输出以及来自批评者的反馈。
- **Critic_1, ..., Critic_k**：代表一个或多个批评者，负责对当前的未提炼输出进行评估，并生成反馈。省略号表示可以有多个批评者。
- **Critique_fb**：代表由批评者们产生的反馈信息，这些反馈信息会被用来指导后续的改进过程。
- **Refiner**：负责根据未提炼的输出和批评反馈，生成改进后的输出。
- **Refined_Output**：代表经过提炼器改进后的输出结果。

## 连线、分支与汇聚关系
- `Generator -- Initializes --> Unrefined`：生成器初始化未提炼的输出。
- `Critic_1 --> Critique_fb`：批评者1对未提炼的输出进行评估，并将评估结果汇总为批评反馈。
- `... --> Critique_fb`：其他批评者对未提炼的输出进行评估，并将评估结果汇总为批评反馈。
- `Critic_k --> Critique_fb`：批评者k对未提炼的输出进行评估，并将评估结果汇总为批评反馈。
- `Critic_1, ..., Critic_k` 汇聚到 `Critique_fb`，形成汇聚关系。
- `Critique_fb --> Unrefined`：批评反馈被送回未提炼的输出，用于指导下一步的改进。
- `Unrefined --> Refiner`：未提炼的输出和批评反馈一起被送入提炼器。
- `Refiner --> Refined_Output`：提炼器根据未提炼的输出和批评反馈，生成精炼的输出，提炼器接收的输入是：R: y_t, x, fb，其中 y_t 代表未提炼的输出，x 代表输入，fb 代表反馈。
- `Refined_Output -- Stopping Criteria Not Met --> Unrefined`：如果未满足停止条件，则流程结束，输出精炼的输出被送回未提炼的输出，开始新一轮的迭代改进。

## 仓库语境与术语解释
- **Self-Refine**：根据 README，Self-Refine 允许 LLM 对其工作生成反馈，使用该反馈来改进输出，并重复此过程。
- **Generator**：根据 README 的 "General setup"，每个任务都有三种不同类型的 prompt，其中 `Init` 用于初始化任务，生成初始输出。
- **Feedback**：根据 README 的 "General setup"，每个任务都有三种不同类型的 prompt，其中 `Feedback` 用于从模型获取关于中间结果的反馈。
- **Iterate**：根据 README 的 "General setup"，每个任务都有三种不同类型的 prompt，其中 `Iterate` 用于从模型获取基于反馈的下一次迭代。
- **Stopping Criteria**：图中可见，但仓库上下文未进一步说明，表示停止迭代的条件，例如达到最大迭代次数或输出质量达到阈值。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Self-Refine 框架的核心迭代改进流程。流程从 Generator 生成初始输出开始，多个 Critic 对输出进行评估并产生反馈 Critique_fb，反馈被送回 Unrefined 输出。Refiner 接收 Unrefined 输出和 Critique_fb，生成 Refined_Output。如果未满足 Stopping Criteria，Refined_Output 会被送回 Unrefined 进行下一轮迭代，直到满足停止条件。该流程通过自我反馈机制，迭代地改进初始输出，最终得到精炼的输出结果。
