## Diagram Type & Purpose
This is a flowchart diagram illustrating the customer order flow and payment processing within an e-commerce system. It outlines the steps involved in creating an order, validating details, processing payment, and handling post-payment execution, including error scenarios. The diagram serves as a visual representation of the order processing logic.

## Overall Layout
The diagram is laid out from top to bottom (TB), with three main subgraphs representing distinct stages of the order processing: Customer Order Flow, Payment Processing, and Post-Payment Execution. ## Repository Context & Terminology
- **Customer Order Creation**: The initial step where a customer places an order, typically involving adding items to a cart and providing shipping information.
- **Validate Order Details**: Verifying the accuracy and completeness of the order information, such as address, payment details, and item availability.
- **Inventory Check & Reservation**: Checking if the requested items are in stock and reserving them to prevent overselling.
- **Payment Gateway**: A service that processes credit card payments securely.
- **PayPal API**: An interface for integrating PayPal payments into the system.
- **Authorization Request**: A request to the payment provider to verify the customer's payment method and authorize the transaction.
- **Payment Capture**: The process of collecting the authorized funds from the customer's account.
- **Rollback Inventory Reservation**: Releasing the reserved inventory back into the available stock if the payment fails.

## High-Density QA Ground Truth Summary
The customer order flow begins with "Customer Order Creation," which leads to "Validate Order Details." If the order details are invalid, the process branches to "Display Error to Customer," terminating the flow. If the details are valid, the flow proceeds to "Inventory Check & Reservation." If there is insufficient inventory, the flow branches to "Display Error to Customer." With sufficient inventory, the system calculates the order total and generates an order ID before presenting payment options to the customer. The customer selects a payment method (Credit Card, PayPal, or Store Credit), triggering an "Authorization Request." If the authorization is approved, "Payment Capture" occurs, followed by "Order Confirmation." If declined, a "Payment Declined Notification" is sent. Post-payment, the system updates inventory levels and sends a shipping notification, culminating in "Order Completion." In case of payment failure, the system rolls back the inventory reservation and notifies the customer, ultimately displaying an error. The "Payment Gateway" and "PayPal API" are external services used for processing payments, ensuring secure transactions.
