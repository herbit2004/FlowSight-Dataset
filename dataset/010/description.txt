## 图类型与用途
这是一个流程图，用于指导开发者在 MoAI-ADK 项目中选择合适的开发方法。它根据项目是否为新项目以及测试覆盖率来决定采用测试驱动开发（TDD）还是领域驱动设计（DDD）。

## 图的整体布局
图整体采用从上到下的布局。流程从项目分析开始，经过两个决策节点，分别导向 TDD 或 DDD 流程，最终到达各自的开发步骤。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：项目分析、开发方法选择、以及具体的开发流程。

## 节点逐项说明
- **🔍 Project Analysis**：项目分析，是流程的起点，表示对项目进行初步的评估和了解。
- **New Project or 10%+ Test Coverage?**：决策节点，判断项目是新项目还是已有项目，并且测试覆盖率是否达到10%以上。
- **TDD (default)**：测试驱动开发（Test-Driven Development），如果项目是新项目或者测试覆盖率达到10%以上，则默认推荐使用TDD。根据 README，MoAI-ADK 默认对新项目应用 TDD。
- **Existing Project < 10% Coverage?**：决策节点，判断项目是已有项目，并且测试覆盖率是否低于10%。
- **DDD**：领域驱动设计（Domain-Driven Design），如果项目是已有项目且测试覆盖率低于10%，则推荐使用DDD。
- **RED → GREEN → REFACTOR**：TDD 的核心流程，即先编写失败的测试（RED），然后编写代码使其通过测试（GREEN），最后重构代码（REFACTOR）。
- **ANALYZE → PRESERVE → IMPROVE**：DDD 的核心流程，即分析现有代码（ANALYZE），保留现有功能（PRESERVE），然后逐步改进代码（IMPROVE）。

## 连线、分支与汇聚关系
- `🔍 Project Analysis -> New Project or 10%+ Test Coverage?`：项目分析后，进入开发方法选择阶段。
- `New Project or 10%+ Test Coverage? -- Yes --> TDD (default)`：如果项目是新项目或者测试覆盖率达到10%以上，则进入 TDD 流程。
- `New Project or 10%+ Test Coverage? -- No --> Existing Project < 10% Coverage?`：如果项目不是新项目且测试覆盖率低于10%，则进入下一个判断节点。
- `Existing Project < 10% Coverage? -- Yes --> DDD`：如果项目是已有项目且测试覆盖率低于10%，则进入 DDD 流程。
- `TDD (default) -> RED → GREEN → REFACTOR`：选择 TDD 后，遵循 TDD 的核心流程。
- `DDD -> ANALYZE → PRESERVE → IMPROVE`：选择 DDD 后，遵循 DDD 的核心流程。

## 仓库语境与术语解释
- **MoAI-ADK**：一个高性能 AI 开发环境，用于 Claude Code。
- **TDD (Test-Driven Development)**：测试驱动开发，一种先编写测试用例，再编写代码使其通过测试的开发方法。`.claude/skills/moai-workflow-tdd/SKILL.md` 文件描述了 TDD 的使用场景。
- **DDD (Domain-Driven Design)**：领域驱动设计，一种用于处理复杂领域的软件开发方法，强调对领域知识的理解和建模。`.claude/skills/moai-workflow-ddd/SKILL.md` 文件描述了 DDD 的使用场景。
- **Test Coverage**：测试覆盖率，衡量测试用例覆盖代码的程度。
- **Claude Code**：README 提到，MoAI-ADK 是一个为 Claude Code 设计的 AI 开发环境。
- **RED → GREEN → REFACTOR**：TDD 的三个阶段，分别表示编写失败的测试、编写代码使其通过测试、以及重构代码。
- **ANALYZE → PRESERVE → IMPROVE**：DDD 的三个阶段，分别表示分析现有代码、保留现有功能、以及逐步改进代码。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图从项目分析开始，根据项目是否为新项目以及测试覆盖率，选择 TDD 或 DDD 开发方法。对于新项目或高测试覆盖率项目，推荐 TDD，其流程为 RED -> GREEN -> REFACTOR；对于已有项目且低测试覆盖率项目，推荐 DDD，其流程为 ANALYZE -> PRESERVE -> IMPROVE。该图旨在指导开发者在 MoAI-ADK 项目中选择合适的开发方法，提高开发效率和代码质量。
