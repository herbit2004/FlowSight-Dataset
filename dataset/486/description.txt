## 图类型与用途
这是一个流程图，描述了从最初的 Feature Idea 到最终 Merge 的软件开发流程，并展示了使用 AI Agent 进行协作和自动化的环节。它在 README.md 中被用作 Issue-Driven Development 方法的示例。

## 图的整体布局
图整体采用从左到右的布局。起点是 Feature Idea，终点是 Merge。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为需求提出、任务分解、AI 协作、代码合并四个阶段。

## 节点逐项说明
- **Feature Idea**：表示一个功能的想法或需求，是整个流程的起点。
- **Epic + Sub-Issues**：表示将 Feature Idea 细化为 Epic（史诗级任务）以及更小的 Sub-Issues（子任务）。Epic 是一个大型的用户故事，可以分解成多个更小的、可管理的子任务。
- **Agent Orchestration**：代表 AI Agent 的编排和协作。在这个阶段，多个 AI Agent 协同工作，完成 Epic 和 Sub-Issues 中定义的任务。这可能包括代码生成、测试、文档编写等。
- **Pull Request**：表示 AI Agent 完成任务后，提交的 Pull Request（合并请求）。这是将代码变更合并到主分支之前的请求。
- **Merge**：表示代码经过评审后，被合并到主分支。这是流程的终点。

## 连线、分支与汇聚关系
- `A -> B`：Feature Idea 通过 `/issue` 命令转化为 Epic 和 Sub-Issues。
- `B -> C`：Epic 和 Sub-Issues 通过 `/task` 命令触发 AI Agent 的编排和协作，开始执行具体的开发任务。
- `C -> D`：AI Agent 完成任务后，通过 `/pr` 命令提交 Pull Request。
- `D -> E`：Pull Request 经过人工 Review（评审）后，被 Merge 到主分支。

## 仓库语境与术语解释
- **Feature Idea**：软件开发流程的起点，代表一个待实现的功能或需求。
- **/issue**：一个 Slash Command，用于将 Feature Idea 转化为 Epic 和 Sub-Issues。参见 `commands/issue.md`，该文件定义了创建 GitHub issue 的模板。
- **Epic + Sub-Issues**：Epic 是一个大型的用户故事，可以分解成多个更小的、可管理的子任务。
- **/task**：一个 Slash Command，用于触发 AI Agent 的编排和协作，开始执行具体的开发任务。参见 `commands/task.md`，该文件描述了如何使用 Agent Orchestration 解决 Issue。
- **Agent Orchestration**：AI Agent 的编排和协作，用于完成 Epic 和 Sub-Issues 中定义的任务。
- **/pr**：一个 Slash Command，用于提交 Pull Request。参见 `commands/pr.md`，该文件描述了如何创建 GitHub Pull Request。
- **Pull Request**：将代码变更合并到主分支之前的请求。
- **Merge**：代码经过评审后，被合并到主分支。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个基于 AI Agent 协作的软件开发流程。从 Feature Idea 开始，通过 `/issue` 命令分解为 Epic 和 Sub-Issues，然后通过 `/task` 命令触发 AI Agent 的编排和协作来完成任务，生成代码。最后，通过 `/pr` 命令提交 Pull Request，经过人工 Review 后，将代码合并到主分支。其中 `/issue`、`/task`、`/pr` 等命令暗示了流程与 GitHub 工作流集成。
