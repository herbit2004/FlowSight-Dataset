## 图类型与用途
这是一个流程图，描述了 RepoMind 如何扫描代码仓库并生成安全报告的架构。它在仓库中的作用是展示 RepoMind 的代码安全扫描流程，从用户发起扫描请求开始，到最终生成安全报告。

## 图的整体布局
图整体采用从上到下的布局。顶部是起始节点，中间是代码分析阶段，底部是结果生成节点。

## 分组/子图/阶段说明
图中包含两个子图，分别是 "Pattern Engine (Fast)" 和 "AI Engine (Deep)"，分别代表快速模式匹配引擎和深度AI分析引擎。

## 节点逐项说明
- **Start (User Requests Scan)**：用户发起扫描请求的起始点。
- **Select (Select Code Files)**：选择需要扫描的代码文件。
- **Fetch (Fetch Content)**：获取选定代码文件的内容。
- **Secrets (Detect Secrets)**：检测代码中的敏感信息，如密钥、密码等。对应 `src/lib/security-scanner.ts` 中的 `detectSecrets` 函数，该函数使用正则表达式来查找硬编码的密钥。
- **Patterns (Code Patterns)**：检测代码中存在的特定代码模式，可能包括潜在的安全漏洞。
- **Deps (Check Dependencies)**：检查代码的依赖关系，例如使用的库和框架，以识别潜在的依赖漏洞。
- **AI (Gemini 3 Analysis)**：使用 Gemini 3 模型对代码进行分析。根据 `src/lib/ai-client.ts`，RepoMind 使用 Gemini 模型进行代码分析。
- **AIFindings (AI Findings)**：AI 分析的结果，包含潜在的安全问题或改进建议。
- **Dedup (Deduplicate & Aggregate)**：对来自不同引擎的分析结果进行去重和聚合。
- **Report (Generate Security Report)**：生成最终的安全报告。

## 连线、分支与汇聚关系
- `Start -> Select`：用户发起扫描请求后，进入代码文件选择阶段。
- `Select -> Fetch`：选择代码文件后，获取文件内容。
- `Fetch -> Secrets`：获取的代码内容进入 Pattern Engine 的 Secrets 检测模块。
- `Fetch -> Patterns`：获取的代码内容进入 Pattern Engine 的 Patterns 检测模块。
- `Fetch -> Deps`：获取的代码内容进入 Pattern Engine 的 Dependencies 检测模块。
- `Fetch -- High Risk Files --> AI`：高风险文件被送入 AI Engine 进行分析。
- `AI -- Context Aware --> AIFindings`：AI 分析生成 Findings。
- `Secrets -> Dedup`：Secrets 检测结果进入去重和聚合阶段。
- `Patterns -> Dedup`：Patterns 检测结果进入去重和聚合阶段。
- `Deps -> Dedup`：Dependencies 检测结果进入去重和聚合阶段。
- `AIFindings -> Dedup`：AI Findings 进入去重和聚合阶段。
- `Secrets`、`Patterns`、`Deps`、`AIFindings` 汇聚到 `Dedup` 节点，形成汇聚关系。
- `Dedup -> Report`：去重和聚合后的结果生成安全报告。

## 仓库语境与术语解释
- **RepoMind**：一个使用 Agentic CAG 的 AI 应用，用于分析 GitHub 仓库和开发者信息，如 README 所示。
- **Gemini 3**：RepoMind 使用的 AI 模型，用于代码分析和漏洞检测，如 README 所示。
- **Pattern Engine (Fast)**：快速分析引擎，用于检测代码中的已知模式和依赖关系，对应 `src/lib/security-scanner.ts`。
- **AI Engine (Deep)**：深度分析引擎，使用 Gemini 3 模型进行更深入的分析，对应 `src/lib/gemini-security.ts`。
- **Security Report**：包含代码安全分析结果的报告，用于帮助用户发现和修复潜在的安全问题。
- **Agentic CAG (Context Augmented Generation)**：RepoMind 使用的架构，与传统的 RAG 不同，它将完整的文件加载到模型的长上下文中，以便更好地理解代码。
- **Vulnerability Scanning**: 零配置安全审计功能，用于检测 SQL 注入、XSS 和身份验证缺陷，无需设置 CI/CD 管道，如 README 所示。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 RepoMind 的代码安全扫描流程。流程从用户发起扫描请求开始，选择代码文件并获取文件内容。文件内容同时进入 Pattern Engine 和 AI Engine 进行分析。Pattern Engine 并行执行 Secrets 检测、Patterns 检测和 Dependencies 检测。AI Engine 对高风险文件进行 Gemini 3 分析，生成 AI Findings。所有分析结果经过 Dedup 阶段后，最终生成安全报告。其中，Gemini 3 模型和快速模式匹配是 RepoMind 的核心组成部分。
