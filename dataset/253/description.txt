## 图类型与用途
这是一个流程图/架构图，用于展示 RedAmon 工具在漏洞扫描、利用和后渗透测试时，各种数据实体之间的关系，以及攻击链的构建过程。它描绘了从域名到最终漏洞发现和利用的整个流程，并关联了漏洞信息到 MITRE 知识库。

## 图的整体布局
图整体采用从上到下的布局。从顶部的 Domain 和 AttackChain 开始，向下延伸到 IP 地址、端口、服务等，最终关联到 CVE 和 MitreData。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为以下几个阶段：
- **目标识别与信息收集阶段**：从 Domain 到 BaseURL，涉及子域名、IP 地址、端口和服务等信息的收集。
- **漏洞发现与分析阶段**：从 BaseURL 到 Vulnerability 和 CVE，涉及端点、参数、技术和已知漏洞的关联。
- **攻击链构建与利用阶段**：AttackChain、ChainStep 和 ChainFinding 描述了攻击链的构建和利用过程。
- **MITRE 知识库关联阶段**：从 CVE 到 Capec，将漏洞与 MITRE 知识库中的 CWE 和 CAPEC 信息关联。

## 节点逐项说明
- **Domain**：目标系统的域名。
- **Subdomain**：目标域名的子域名。
- **IP**：子域名解析到的 IP 地址。
- **Port**：IP 地址上开放的端口。
- **Service**：在特定端口上运行的服务。
- **BaseURL**：服务的根 URL。
- **Endpoint**：BaseURL 下的特定 URL 路径。
- **Parameter**：Endpoint 接收的参数。
- **Technology**：BaseURL 使用的技术栈。
- **Header**：HTTP 响应头。
- **CVE**：已知的漏洞标识符，与 Technology 关联。
- **Vulnerability**：在系统中发现的漏洞实例，与 Endpoint 和 Parameter 关联。
- **MitreData**：关于漏洞的 MITRE 相关信息，包括 CWE（Common Weakness Enumeration）。
- **Capec**：常见攻击模式枚举与分类，与 MitreData 关联。
- **AttackChain**：一系列攻击步骤的集合，用于实现特定目标。
- **ChainStep**：攻击链中的单个步骤。
- **ChainFinding**：在攻击链步骤中发现的结果或信息。

## 连线、分支与汇聚关系
- `Domain -- HAS_SUBDOMAIN --> Subdomain`：域名包含子域名。
- `Subdomain -- RESOLVES_TO --> IP`：子域名解析到 IP 地址。
- `IP -- HAS_PORT --> Port`：IP 地址包含端口。
- `Port -- RUNS_SERVICE --> Service`：端口运行服务。
- `Service -- POWERED_BY --> BaseURL`：服务由 BaseURL 提供支持。
- `Port -- SERVES_URL --> BaseURL`：端口提供 BaseURL。
- `BaseURL -- HAS_ENDPOINT --> Endpoint`：BaseURL 包含端点。
- `BaseURL -- USES_TECHNOLOGY --> Technology`：BaseURL 使用技术。
- `BaseURL -- HAS_HEADER --> Header`：BaseURL 包含 HTTP 头部。
- `Endpoint -- HAS_PARAMETER --> Parameter`：端点包含参数。
- `Technology -- HAS_KNOWN_CVE --> CVE`：技术存在已知的 CVE 漏洞。
- `CVE -- HAS_CWE --> MitreData`：CVE 关联到 MITRE 的 CWE 信息。
- `MitreData -- HAS_CAPEC --> Capec`：MitreData 关联到 CAPEC 攻击模式。
- `Vulnerability -- FOUND_AT --> Endpoint`：漏洞在端点被发现。
- `Vulnerability -- AFFECTS_PARAMETER --> Parameter`：漏洞影响参数。
- `AttackChain -- HAS_STEP --> ChainStep`：攻击链包含步骤。
- `ChainStep -- PRODUCED --> ChainFinding`：链步骤产生发现。
- `AttackChain -.-> CHAIN_TARGETS IP`：攻击链的目标是 IP 地址。
- `ChainStep -.-> STEP_TARGETED IP`：链步骤的目标是 IP 地址。
- `ChainStep -.-> STEP_EXPLOITED CVE`：链步骤利用 CVE 漏洞。
- `ChainFinding -.-> FOUND_ON IP`：发现位于 IP 地址上。
- `ChainFinding -.-> FINDING_RELATES_CVE CVE`：发现与 CVE 漏洞相关。

## 仓库语境与术语解释
- **Domain Recon**：`recon/domain_recon.py` 文件实现了子域名发现和 DNS 解析功能，是信息收集阶段的关键模块。
- **CVE**：通用漏洞披露，是公开披露的安全漏洞的唯一标识符。RedAmon 使用 CVE 信息来识别和利用系统中的漏洞。
- **CWE**：通用弱点枚举，是 MITRE 维护的软件和硬件弱点类型列表。`recon/readmes/README.MITRE.md` 说明了 RedAmon 如何使用 CWE 来丰富漏洞信息。
- **CAPEC**：常见攻击模式枚举与分类，是 MITRE 维护的攻击模式列表。RedAmon 使用 CAPEC 来理解漏洞的利用方式。
- **AttackChain**：攻击链，是指攻击者为了达到特定目标而采取的一系列攻击步骤。RedAmon 旨在自动化攻击链的构建和利用。
- **Neo4j Graph Schema**：`graph_db/readmes/GRAPH.SCHEMA.md` 定义了 RedAmon 使用的 Neo4j 图数据库的模式，用于存储和查询漏洞信息和攻击链。
- **MitreData**：指的是与漏洞相关的 MITRE 知识库信息，包括 CWE 和 CAPEC。`recon/add_mitre.py` 模块负责将 CVE 数据与 MITRE 知识库关联。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 RedAmon 工具从域名开始，通过子域名解析、端口扫描、服务识别等步骤，最终发现漏洞并构建攻击链的完整流程。其中，域名是整个流程的起点，IP 地址、端口和服务是关键的中间节点，CVE 和 Vulnerability 是漏洞发现的结果，AttackChain 描述了攻击链的构建过程。该图还展示了如何将漏洞信息与 MITRE 知识库中的 CWE 和 CAPEC 信息关联，从而提供更全面的漏洞分析和利用能力。`recon/domain_recon.py` 负责子域名发现，`graph_db/readmes/GRAPH.SCHEMA.md` 定义了数据存储模式，`recon/readmes/README.MITRE.md` 解释了 MITRE 知识库的集成。
