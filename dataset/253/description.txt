## Diagram Type & Purpose
This is a flowchart diagram depicting the relationships between different elements in a cyber attack chain. It illustrates how vulnerabilities, exploits, and other components are connected to form a complete attack path. The diagram serves as a visual representation of the attack surface and can be used for threat modeling and security analysis.

## Overall Layout
The diagram's layout is top-down (TD). It shows a hierarchical structure starting from the `AttackChain` node at the top and branching down to various components like `Domain`, `IP`, `Service`, `Vulnerability`, and ultimately `Capec` at the bottom. There is no single end node, but `Capec` represents a final stage in the chain.

## Edges, Branches & Convergence
- `Domain --> Subdomain`: Represents the relationship where a domain has subdomains (HAS_SUBDOMAIN).
- `Subdomain --> IP`: Represents the resolution of a subdomain to an IP address (RESOLVES_TO).
- `IP --> Port`: Represents the relationship where an IP address has open ports (HAS_PORT).
- `Port --> Service`: Represents a service running on a port (RUNS_SERVICE).
- `Service --> BaseURL`: Represents a service powering a base URL (POWERED_BY).
- `Port --> BaseURL`: Represents a service serving a base URL (SERVES_URL).
- `BaseURL --> Endpoint`: Represents a base URL having endpoints (HAS_ENDPOINT).
- `BaseURL --> Technology`: Represents a base URL using a technology (USES_TECHNOLOGY).
- `BaseURL --> Header`: Represents a base URL having headers (HAS_HEADER).
- `Endpoint --> Parameter`: Represents an endpoint having parameters (HAS_PARAMETER).
- `Technology --> CVE`: Represents a technology having known CVEs (HAS_KNOWN_CVE).
- `CVE --> MitreData`: Represents a CVE relating to MITRE data (HAS_CWE).
- `MitreData --> Capec`: Represents MITRE data relating to CAPEC (HAS_CAPEC).
- `Vulnerability --> Endpoint`: Represents a vulnerability found at an endpoint (FOUND_AT).
- `Vulnerability --> Parameter`: Represents a vulnerability affecting a parameter (AFFECTS_PARAMETER).
- `AttackChain --> ChainStep`: Represents an attack chain having steps (HAS_STEP).
- `ChainStep --> ChainFinding`: Represents a chain step producing a finding (PRODUCED).
- `AttackChain -.-> IP`: Represents an attack chain targeting an IP (CHAIN_TARGETS).
- `ChainStep -.-> IP`: Represents a chain step targeting an IP (STEP_TARGETED).
- `ChainStep -.-> CVE`: Represents a chain step exploiting a CVE (STEP_EXPLOITED).
- `ChainFinding -.-> IP`: Represents a chain finding found on an IP (FOUND_ON).
- `ChainFinding -.-> CVE`: Represents a chain finding relating to a CVE (FINDING_RELATES_CVE).

## Repository Context & Terminology
- **AttackChain**: A sequence of actions or events that constitute an attack.
- **ChainStep**: An individual action or event within an attack chain.
- **ChainFinding**: A piece of information discovered during an attack chain, such as a vulnerability or misconfiguration.
- **CVE (Common Vulnerabilities and Exposures)**: A dictionary of publicly known information security vulnerabilities and exposures.
- **MitreData**: Data related to the MITRE ATT&CK framework, which is a knowledge base of adversary tactics and techniques.
- **Capec (Common Attack Pattern Enumeration and Classification)**: A catalog of common attack patterns used by adversaries.
- **Domain/Subdomain**: A domain name or its subdomain, used to identify a network or resource.
- **IP/Port**: An IP address and port number, used to identify a specific network service.
