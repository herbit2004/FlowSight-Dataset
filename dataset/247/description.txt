## 图类型与用途
这是一个流程图，描述了 Acontext 系统如何将会话消息转化为可复用的技能代理。该图在仓库中用于概括 Acontext 的核心工作流程，即从用户交互中学习并将知识转化为可复用的技能。

## 图的整体布局
图采用从左到右的布局。流程从会话消息开始，经过任务提取、任务完成/失败判断、提炼，最终生成技能代理并存储为 Markdown 文件。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：任务提取、任务处理与提炼、技能代理生成与存储。

## 节点逐项说明
- **Session messages**：表示用户与系统或代理之间的交互信息，是整个流程的起点。
- **Task extraction**：表示从会话消息中识别并提取出需要执行的任务。
- **Task complete/failed**：表示任务完成或失败的状态。任务提取后，系统会尝试执行任务，并根据执行结果进入此状态。
- **Distillation**：表示提炼阶段，将已完成的任务及其结果进行提炼，提取出关键信息和模式，形成可复用的知识。
- **Skill Agent**：表示技能代理，是提炼后的知识的载体，可以理解为一个封装了特定技能的智能体，可以被重复调用来完成类似的任务。
- **Markdown files**：表示技能代理的存储形式，这里使用 Markdown 文件来存储技能代理的定义和相关信息。根据 README，技能代理以 Markdown 格式存储，方便阅读、编辑和共享。

## 连线、分支与汇聚关系
- `Session messages -> Task extraction`：会话消息作为输入，被用于提取任务。
- `Task extraction -> Task complete/failed`：提取出的任务会被执行，并进入完成或失败状态。
- `Task complete/failed -> Distillation`：已完成的任务及其结果会被提炼，提取出关键信息和模式。
- `Distillation -> Skill Agent`：提炼后的知识被用于构建技能代理。
- `Skill Agent -> Markdown files`：技能代理被存储为 Markdown 文件。

## 仓库语境与术语解释
- **Acontext**：是一个开源的 Agent Skills 记忆层，能够自动捕获 Agent 运行中的学习成果，并将知识存储为 Markdown 文件。
- **Session messages**：指的是用户与 Agent 之间的对话和交互，Acontext 从这些消息中提取信息。
- **Skill Agent**：是 Acontext 的核心概念，代表着从会话中学习并构建的可复用技能。
- **Markdown files**：Acontext 使用 Markdown 文件存储技能代理，方便用户阅读、编辑和共享。
- **SKILL.md**：根据 README，`SKILL.md` 定义了技能的 schema、命名和文件布局。
- **get_skill / get_skill_file**：根据 README，Agent 使用 `get_skill` 和 `get_skill_file` 工具来获取所需的技能内容。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 Acontext 如何从会话消息开始，经过任务提取、完成状态判断和知识提炼，最终生成 Skill Agent 并存储为 Markdown 文件。核心流程是“会话消息 -> 任务提取 -> 任务完成/失败 -> 知识提炼 -> Skill Agent -> Markdown 文件”，体现了 Acontext 从用户交互中学习并将知识转化为可复用技能的核心功能。根据 README，Skill Agent 以 Markdown 格式存储，方便阅读、编辑和共享，并且可以通过 `get_skill` 和 `get_skill_file` 工具被 Agent 调用。
