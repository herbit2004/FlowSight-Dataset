## 图类型与用途
这是一个流程图，描述了 `DeepResearch` 系统如何通过迭代的搜索、阅读和推理来回答用户提出的问题。它在仓库中的作用是可视化核心工作流程，展示了系统如何不断地搜索、阅读网页并进行推理，直到找到答案或超出 token 预算。

## 图的整体布局
图整体采用从上到下的布局。流程从顶部的 "Start" 节点开始，经过一系列处理和判断步骤，最终到达底部的 "End" 节点。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为以下几个阶段：
- **初始化阶段**：包括 "Start" 和 "Initialize context & variables" 节点，负责启动流程和设置初始状态。
- **迭代搜索与推理阶段**：这是流程的核心部分，包括 "Get current question from gaps"、"Generate prompt"、"Generate response using Gemini"、"Check action type" 等节点，以及根据动作类型进行搜索、访问 URL、反思等分支。
- **答案评估与存储阶段**：包括 "AnswerCheck"、"Evaluate answer"、"Is answer definitive?"、"Has references?" 等节点，负责评估生成的答案，并根据评估结果进行存储或重新开始。
- **最终答案生成阶段**：当 token 预算超出时，进入 "Beast Mode"，生成最终答案。

## 节点逐项说明
- **Start**：流程的起始点。
- **Initialize context & variables**：初始化搜索过程所需的上下文信息和变量，例如已访问的 URL、已知信息、token 预算等。
- **Token budget exceeded?**：检查是否超过了预定的 token 预算。如果超过，则进入 "Beast Mode"。
- **Get current question from gaps**：从待解决问题队列（gaps）中获取当前要处理的问题。
- **Generate prompt**：根据当前问题和已知的上下文信息，生成用于驱动 Gemini 模型进行推理的提示。
- **Generate response using Gemini**：使用 Gemini 模型根据生成的提示生成响应。根据 README，这里使用了 Gemini (latest `gemini-2.0-flash`) / OpenAI / [LocalLLM](#use-local-llm) for reasoning。
- **Check action type**：分析 Gemini 模型生成的响应，判断其建议采取的动作类型。可能的动作类型包括 "answer"、"reflect"、"search"、"visit"。
- **AnswerCheck**：检查当前答案是否是针对原始问题的回答。
- **Is original question?**：判断当前回答是否针对原始问题。
- **Evaluate answer**：评估生成的答案的质量。
- **Is answer definitive?**：判断答案是否足够明确和完整。
- **Has references?**：检查答案是否包含引用来源。
- **Store bad attempt Reset context**：如果答案不好，则存储这次尝试，并重置上下文，以便重新开始。
- **Store as intermediate knowledge**：如果答案不是最终答案，但包含有用的信息，则将其存储为中间知识，供后续推理使用。
- **Process new sub-questions**：处理 Gemini 模型提出的新的子问题。
- **New unique questions?**：检查新提出的子问题是否是之前未提出的。
- **Add to gaps queue**：将新的唯一子问题添加到待解决问题队列（gaps）中。
- **Disable reflect for next step**：如果没有新的子问题，则禁用下一步的反思动作。
- **Execute search**：执行搜索查询，以查找与当前问题相关的网页。
- **New URLs found?**：检查搜索结果中是否包含之前未访问过的 URL。
- **Store URLs for future visits**：存储搜索结果中新的 URL，以便后续访问。
- **Disable search for next step**：如果没有找到新的 URL，则禁用下一步的搜索动作。
- **Visit URLs**：访问之前存储的 URL。
- **New content found?**：检查访问的 URL 中是否包含新的内容。
- **Store content as knowledge**：将新的内容存储为知识，供后续推理使用。
- **Disable visit for next step**：如果没有找到新的内容，则禁用下一步的访问动作。
- **Beast Mode**：当 token 预算超出时，进入该模式，图中可见，但仓库上下文未进一步说明。
- **Generate final answer**：生成最终答案。
- **End**：流程的结束点。

## 连线、分支与汇聚关系
- `Start -> Initialize context & variables`：流程开始后，初始化上下文和变量。
- `Initialize context & variables -> Token budget exceeded?`：初始化完成后，检查 token 预算。
- `Token budget exceeded? -- No --> Get current question from gaps`：如果 token 预算未超出，则从 gaps 中获取当前问题。
- `Token budget exceeded? -- Yes --> BeastMode`：如果 token 预算超出，则进入 Beast Mode。
- `Get current question from gaps -> Generate prompt`：获取当前问题后，生成提示。
- `Generate prompt -> Generate response using Gemini`：生成提示后，使用 Gemini 生成响应。
- `Generate response using Gemini -> Check action type`：生成响应后，检查动作类型。
- `Check action type -- answer --> AnswerCheck`：如果动作类型是 answer，则进行答案检查。
- `Check action type -- reflect --> Process new sub-questions`：如果动作类型是 reflect，则处理新的子问题。
- `Check action type -- search --> Execute search`：如果动作类型是 search，则执行搜索。
- `Check action type -- visit --> Visit URLs`：如果动作类型是 visit，则访问 URL。
- `AnswerCheck -- Yes --> Evaluate answer`：如果答案是针对原始问题的回答，则评估答案。
- `AnswerCheck -- No --> Store as intermediate knowledge`：如果答案不是针对原始问题的回答，则存储为中间知识，并形成汇聚关系。
- `Evaluate answer -> Is answer definitive?`：评估答案后，判断答案是否是确定的。
- `Is answer definitive? -- Yes --> Has references?`：如果答案是确定的，则检查是否有引用。
- `Is answer definitive? -- No --> Store bad attempt Reset context`：如果答案不是确定的，则存储不良尝试并重置上下文，并形成汇聚关系。
- `Has references? -- Yes --> End`：如果有引用，则流程结束。
- `Has references? -- No --> GetQuestion`：如果没有引用，则回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Process new sub-questions -> New unique questions?`：处理新的子问题后，检查是否有新的唯一问题。
- `New unique questions? -- Yes --> Add to gaps queue`：如果有新的唯一问题，则添加到 gaps 队列。
- `New unique questions? -- No --> Disable reflect for next step`：如果没有新的唯一问题，则禁用下一步的反思，并形成汇聚关系。
- `Add to gaps queue -> GetQuestion`：添加到 gaps 队列后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Disable reflect for next step -> GetQuestion`：禁用下一步的反思后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Execute search -> New URLs found?`：执行搜索后，检查是否有新的 URL。
- `New URLs found? -- Yes --> Store URLs for future visits`：如果有新的 URL，则存储 URL，并形成汇聚关系。
- `New URLs found? -- No --> Disable search for next step`：如果没有新的 URL，则禁用下一步的搜索，并形成汇聚关系。
- `Store URLs for future visits -> GetQuestion`：存储 URL 后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Disable search for next step -> GetQuestion`：禁用下一步的搜索后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Visit URLs -> New content found?`：访问 URL 后，检查是否有新的内容。
- `New content found? -- Yes --> Store content as knowledge`：如果有新的内容，则存储内容，并形成汇聚关系。
- `New content found? -- No --> Disable visit for next step`：如果没有新的内容，则禁用下一步的访问，并形成汇聚关系。
- `Store content as knowledge -> GetQuestion`：存储内容后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Disable visit for next step -> GetQuestion`：禁用下一步的访问后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Store as intermediate knowledge -> GetQuestion`：存储为中间知识后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `Store bad attempt Reset context -> GetQuestion`：存储不良尝试并重置上下文后，回到 "Get current question from gaps" 节点，形成汇聚关系。
- `BeastMode -> FinalAnswer`：进入 Beast Mode 后，生成最终答案。
- `FinalAnswer -> End`：生成最终答案后，流程结束。

## 仓库语境与术语解释
- **DeepResearch**：该项目旨在通过迭代的搜索、阅读和推理来回答用户提出的问题。根据 README，它专注于通过迭代过程找到正确的答案，而不是生成长篇文章。
- **Gemini / OpenAI / LocalLLM**：用于推理的大语言模型。根据 README，该系统可以使用 Gemini (latest `gemini-2.0-flash`)、OpenAI 或本地 LLM 进行推理。`src/config.ts` 文件中定义了 LLM 提供者的相关配置。
- **Jina Reader**：用于搜索和阅读网页的工具。根据 README，可以使用 Jina Reader 搜索和阅读网页。`src/tools/read.ts` 文件中定义了如何使用 Jina Reader API。
- **Token budget**：预定的 token 预算，用于限制搜索和推理过程的资源消耗。
