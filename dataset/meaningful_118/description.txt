## 图类型与用途
该图是一个流程图，描述了订单服务和支付服务之间的交互流程。它展示了订单请求的处理、支付流程以及错误处理和重试机制。该图可以用于理解订单支付的整体架构和流程。

## 图的整体布局
该图采用从上到下的布局。整体上分为订单服务和支付服务两个子图，订单服务是流程的起点，返回成功是流程的终点。

## 分组/子图/阶段说明
图中包含两个显式子图：
- **订单服务**：负责接收订单请求、参数校验、生成订单记录、调用支付服务以及发布订单支付成功事件。
- **支付服务**：负责处理支付请求，包括首次支付尝试、支付网关交互、重试机制和熔断机制。

## 节点逐项说明
- **A[接收订单请求]**: 接收来自用户的订单请求。
- **B{订单参数校验}**: 校验订单参数的有效性。
- **C[生成订单记录]**: 在数据库中生成订单记录。
- **D[调用支付服务]**: 调用支付服务进行支付处理。
- **E{首次支付尝试}**: 首次尝试进行支付。
- **F{支付网关}**: 与支付网关进行交互。
- **G[更新订单状态为已支付]**: 支付成功后，更新订单状态为已支付。
- **H[返回错误]**: 返回错误信息给用户。
- **I[重试计数器+1]**: 支付失败时，重试计数器加1。
- **J{重试次数 < 最大重试次数}**: 判断重试次数是否小于最大重试次数。
- **K[等待策略]**: 根据等待策略进行等待。
- **L{熔断器开启}**: 当重试次数超过最大值时，开启熔断器。
- **M[触发告警]**: 触发告警，通知相关人员。
- **N[发布订单支付成功事件]**: 发布订单支付成功的事件。
- **O[返回成功]**: 返回成功信息给用户。

## 连线、分支与汇聚关系
- A -> B：接收订单请求后进行订单参数校验。
- B -- 成功 --> C：订单参数校验成功后生成订单记录。
- B -- 失败 --> H：订单参数校验失败后返回错误。
- C -> D：生成订单记录后调用支付服务。
- D -- 请求 --> E：订单服务请求支付服务进行首次支付尝试。
- E -> F：首次支付尝试通过支付网关。
- F -- 成功 --> G：支付网关支付成功后更新订单状态为已支付。
- F -- 失败 --> I：支付网关支付失败后重试计数器+1。
- I -> J：重试计数器+1后判断重试次数是否小于最大重试次数。
- J -- 是 --> K：重试次数小于最大重试次数，执行等待策略。
- K -> F：等待策略后重新尝试支付网关。
- J -- 否 --> L：重试次数大于等于最大重试次数，开启熔断器。
- L -> M：开启熔断器后触发告警。
- G -> N：更新订单状态为已支付后发布订单支付成功事件。
- N -> O：发布订单支付成功事件后返回成功。
- H -> O：返回错误后返回成功。
- M -> H：触发告警后返回错误。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **订单服务**：负责处理订单相关业务的微服务。
- **支付服务**：负责处理支付相关业务的微服务。
- **支付网关**：第三方支付平台提供的接口，用于完成支付操作。
- **熔断器**：一种保护机制，当服务出现故障时，防止故障蔓延。
- **重试机制**：当支付失败时，自动重新尝试支付的过程。
- **告警**：当系统出现异常时，通知相关人员的机制。

## 可作为 QA Ground Truth 的高信息密度摘要
订单服务接收订单请求，进行参数校验，成功后生成订单记录并调用支付服务。支付服务进行首次支付尝试，通过支付网关，若成功则更新订单状态为已支付并发布订单支付成功事件，最终返回成功；若支付失败，则进行重试，若超过最大重试次数则开启熔断器并触发告警，最终返回错误。订单参数校验失败也会直接返回错误。
