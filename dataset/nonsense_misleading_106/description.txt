## Diagram Type & Purpose
This is a flowchart diagram illustrating the order processing workflow of an e-commerce system. It outlines the steps involved from when a user submits an order to when the order details are archived, including payment processing, shipping, and customer support interactions. The diagram serves as a visual representation of the order fulfillment process.

## Overall Layout
The diagram's primary direction is top-down (TD). It starts with the "User Submits Order" node at the top and flows downwards through a series of processes and decision points, eventually converging at the "Archive Order Details" node at the bottom. The start node is "User Submits Order" and the end node is "Archive Order Details".

## Edges, Branches & Convergence
- `A --> B`: User submits an order, triggering the payment check.
- `B -- No --> C`: If payment is not received, cancel the order and notify the user.
- `B -- Yes --> D`: If payment is received, ship the order.
- `D --> E`: Shipping the order leads to a check for shipping success.
- `E -- No --> F`: If shipping is not successful, contact customer support.
- `E -- Yes --> G`: If shipping is successful, the order is delivered.
- `G --> H`: Order delivered triggers sending a delivery confirmation email.
- `H --> I`: Sending a delivery confirmation email leads to checking if the user confirms receipt.
- `I -- No --> J`: If the user does not confirm receipt, mark the order as delivered.
- `I -- Yes --> K`: If the user confirms receipt, update the inventory.
- `K --> A`: After updating inventory, the process loops back to the user submitting another order.
- `F --> L`: Contacting customer support leads to refunding the payment.
- `L --> M`: Refunding the payment leads to updating the inventory.
- `M --> N`: Updating the inventory after a refund leads to archiving order details.
- `C --> N`: Canceling the order and notifying the user leads to archiving order details.
- `J --> N`: Marking the order as delivered leads to archiving order details.

## Repository Context & Terminology
- **User Submits Order**: The initial action where a customer places an order through the system's interface. In this diagram, it starts the entire order processing workflow.
- **Payment Received?**: A check to verify if the payment for the order has been successfully processed. In this diagram, it determines whether the order proceeds to fulfillment or is canceled.
- **Ship Order**: The process of preparing and sending the order to the customer. In this diagram, it occurs *before* payment is confirmed, which is an error.
- **Shipping Successful?**: A check to verify if the order was successfully delivered to the customer. In this diagram, it determines whether to proceed with delivery confirmation or contact customer support.
- **Contact Customer Support**: The action of reaching out to customer support for assistance, typically when shipping fails. In this diagram, it leads to a refund *before* any resolution.
- **Refund Payment**: The process of returning the payment to the customer, usually when an order cannot be fulfilled. In this diagram, it happens *after* contacting customer support due to shipping failure.
- **Update Inventory**: The process of adjusting the stock levels based on the order. In this diagram, it happens both after successful delivery confirmation and after a refund, and also loops back to the start.
- **Archive Order Details**: The final step of storing the order information for record-keeping. In this diagram, it represents the end of the order processing workflow.

If shipping fails (E -- No --> F), customer support is contacted, and then a refund is issued (F --> L). The inventory is then updated (L --> M) before archiving the order details (M --> N). If the user does not confirm receipt (I -- No --> J), the order is marked as delivered (J) and archived (J --> N). If the user confirms receipt (I -- Yes --> K), the inventory is updated (K), and the process loops back to the "User Submits Order" node (K --> A), creating an illogical loop. The final step for all paths (except the illogical loop) is to "Archive Order Details" (N), representing the end of the order processing workflow. The diagram contains several errors, including shipping before payment, refunding before attempting to resolve shipping issues, and looping back to the start after updating inventory.
