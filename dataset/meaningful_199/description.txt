## 图类型与用途
该图是一个流程图，描述了订单创建过程中订单服务和库存服务之间的交互流程。它展示了订单服务如何验证订单信息并请求库存服务扣减库存，以及库存服务如何处理库存扣减请求并返回结果。该图用于说明分布式系统中服务间的协作。

## 图的整体布局
该图采用从上到下的布局。整体分为两个主要服务模块：订单服务和库存服务。流程从订单服务接收订单创建请求开始，最终订单创建成功结束。

## 分组/子图/阶段说明
图中包含两个子图：
- **服务A - 订单服务**：负责接收订单创建请求、验证订单信息以及请求库存服务。
- **服务B - 库存服务**：负责接收库存扣减请求、检查库存、扣减库存以及返回扣减结果。

## 节点逐项说明
- **A**：接收订单创建请求。
- **B**：验证订单信息。
- **C**：请求库存服务。
- **D**：接收库存扣减请求。
- **E**：检查库存。
- **F**：库存充足？，判断库存是否充足的决策节点。
- **G**：扣减库存。
- **H**：返回扣减结果。
- **I**：返回库存不足。
- **J**：订单创建成功。

## 连线、分支与汇聚关系
- A -> B：接收订单创建请求后，验证订单信息。
- B -> C：验证订单信息后，请求库存服务。
- C -- gRPC --> D：订单服务通过 gRPC 调用库存服务。
- D -> E：接收库存扣减请求后，检查库存。
- E -> F：检查库存后，判断库存是否充足。
- F -- 是 --> G：如果库存充足，则扣减库存。
- G -> H：扣减库存后，返回扣减结果。
- F -- 否 --> I：如果库存不足，则返回库存不足。
- I -> C：库存不足时，返回订单服务。
- H -> B：库存扣减成功后，返回订单服务。
- B -> J：订单创建成功。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **订单服务**：负责处理订单创建、查询等业务逻辑的服务。
- **库存服务**：负责管理商品库存的服务。
- **gRPC**：一种高性能、开源的通用 RPC 框架。
- **库存扣减**：减少商品库存数量的操作。
- **订单创建**：生成新订单的过程。
- **库存充足**：库存数量满足订单需求。

## 可作为 QA Ground Truth 的高信息密度摘要
订单创建流程开始于订单服务接收订单创建请求，然后验证订单信息并请求库存服务扣减库存。库存服务接收到扣减请求后，检查库存是否充足。如果库存充足，则扣减库存并返回扣减结果，订单服务最终创建订单成功；如果库存不足，则返回库存不足信息给订单服务，流程结束。
