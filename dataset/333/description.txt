## 图类型与用途
这是一个流程图，描述了华中科技大学狼牙战队2022赛季步兵自瞄程序的数据处理流程。该图展示了数据从相机和 STM32 微控制器获取，经过图像处理、姿态估计、状态估计等步骤，最终将数据发送回 STM32 的过程。该图在 README.md 中被提及，用于概括程序框图。

## 图的整体布局
图整体采用从上到下的布局。顶部是线程（thread）分组，中间是数据源（source）分组，底部是队列（queue）分组。数据流从相机和 STM32 开始，经过队列缓冲，再到检测线程处理，最终回到 STM32。

## 分组/子图/阶段说明
- **source**：数据源，包含 Camera (相机) 和 stm32 (STM32 微控制器)。
- **queue**：队列，包含 D1 (picture queue - 图像队列) 和 D2 (serial data queue - 串口数据队列)。
- **thread**：线程，包含 detector (检测线程)、camera (相机线程) 和 serial (串口线程)。
- **detector**：检测线程，负责图像处理、目标检测、姿态估计和状态估计，并将结果发送给 STM32。
- **camera**：相机线程，负责从相机获取图像，并将图像放入图像队列。
- **serial**：串口线程，负责接收 STM32 发送的串口数据，并将数据放入串口数据队列。

## 节点逐项说明
- **Camera**：负责采集图像数据。根据 README.md，硬件配置使用了大恒相机。
- **stm32**：负责发送串口数据，可能包含目标位置信息或其他控制指令。
- **D1 (picture queue)**：存储相机采集的图像数据，供图像处理线程使用。
- **D2 (serial data queue)**：存储 STM32 发送的串口数据，供状态估计线程使用。
- **A (detector start)**：检测线程的起始点。
- **A2 (wait for a picture)**：等待图像队列中的图像数据。
- **A3 (wait for a serial data)**：等待串口数据队列中的串口数据。
- **A4 (image process)**：对图像进行预处理，例如滤波、二值化等。
- **A5 (posture estimate)**：根据图像中的目标特征，估计目标的姿态（位置和角度）。
- **A6 (state estimate)**：结合姿态估计和串口数据，对目标的状态进行估计，例如速度、加速度等。
- **A7 (send data to stm32)**：将估计的目标状态数据发送给 STM32。
- **A8 (end a loop)**：检测线程循环的结束点。
- **B (camera start)**：相机线程的起始点。
- **B1 (wait for image from camera)**：等待相机采集的图像数据。
- **B2 (send data to queue)**：将图像数据放入图像队列。
- **B3 (end a loop)**：相机线程循环的结束点。
- **C (serial start)**：串口线程的起始点。
- **C1 (wait for serial data)**：等待串口数据。
- **C2 (send data to queue)**：将串口数据放入串口数据队列。
- **C3 (end a loop)**：串口线程循环的结束点。

## 连线、分支与汇聚关系
- `Camera -> B1`：相机采集图像数据后，发送给相机线程的等待图像节点。
- `B1 -> B2`：相机线程等待到图像后，将数据发送到队列。
- `B2 -> D1`：相机线程将图像数据发送到图像队列。
- `B2 -> B3`：相机线程发送数据到队列后，结束本次循环。
- `stm32 -> C1`：STM32 发送串口数据到串口线程的等待串口数据节点。
- `C1 -> C2`：串口线程接收到串口数据后，将数据发送到队列。
- `C2 -> D2`：串口线程将串口数据发送到串口数据队列。
- `C2 -> C3`：串口线程发送数据到队列后，结束本次循环。
- `D1 -> A2`：图像队列中的数据被发送到检测线程的等待图像节点。
- `D2 -> A3`：串口数据队列中的数据被发送到检测线程的等待串口数据节点。
- `A(detector start) -> A2`：检测线程启动后，等待图像数据。
- `A2 -> A3`：检测线程接收到图像数据后，等待串口数据。
- `A3 -> A4`：检测线程接收到串口数据后，进行图像处理。
- `A4 -> A5`：图像处理后，进行姿态估计。
- `A5 -> A6`：姿态估计后，进行状态估计。
- `A6 -> A7`：状态估计后，将数据发送到 STM32。
- `A7 -> stm32`：检测线程将数据发送给 STM32。
- `A7 -> A8`：检测线程发送数据到 STM32 后，结束本次循环。
- `A8 -> A2`：检测线程循环结束，重新等待图像数据。

## 仓库语境与术语解释
- **Camera**：根据 README.md，项目使用了大恒相机，相关驱动代码位于 `src/driver/GxCamera.cpp` 和 `src/driver/include/GxCamera.h`。
- **stm32**：STM32 微控制器，负责发送串口数据。
- **SerialPort**：串口通信类，用于接收 STM32 发送的串口数据，相关代码位于 `src/driver/SerialPort.cpp` 和 `src/driver/include/SerialPort.h`。
- **picture queue / serial data queue**：图像队列和串口数据队列，用于缓冲数据，实现生产者-消费者模式，在 README.md 中被提及。
- **detector thread**：检测线程，负责图像处理、姿态估计和状态估计，并将结果发送给 STM32。
- **AutoAim.cpp / AutoAim.h**：主程序文件，生成子线程，在 README.md 的文件结构中有提及。
- **init.json**：配置文件，在 `src/AutoAim.h` 中定义了其路径，用于配置系统参数。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了步兵自瞄程序的数据处理流程，从 Camera 和 STM32 获取数据开始，Camera 数据进入图像队列，STM32 数据进入串口数据队列。检测线程从两个队列中获取数据，依次进行图像处理、姿态估计和状态估计，最终将结果发送回 STM32。其中，相机使用大恒相机，串口通信通过 `src/driver/SerialPort.cpp` 实现，整体流程体现了生产者-消费者模式。
