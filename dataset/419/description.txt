## 图类型与用途
这是一个分层架构图，展示了 `arolariu.ro` 项目后端服务的五层架构，描述了请求在不同服务层级间的流转过程。该图体现了“The Standard”架构原则，旨在说明各层之间的依赖关系和职责划分。

## 图的整体布局
图采用从上到下的垂直布局。顶部是暴露端点层，底部是代理层，数据流从上至下传递。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为五个阶段，对应五层架构：
- **Endpoints (Exposers)**：暴露端点层，处理 HTTP 请求映射。
- **Processing Services**：处理服务层，负责繁重的计算，例如 AI/ML 任务。
- **Orchestration Services**：编排服务层，负责协调不同服务，处理横切关注点。
- **Foundation Services**：基础服务层，负责 CRUD 操作、数据验证等。
- **Brokers**：代理层，负责对外部服务进行抽象，提供轻量级的封装。

## 节点逐项说明
- **🔌 Endpoints (Exposers) <br/><i>HTTP mapping, 1 Processing service</i>**：暴露端点，负责处理 HTTP 请求映射，每个端点对应一个处理服务。根据 `knowledge/insights/endpoints-expose-only-processing-services-following-the-standard-exposer-pattern.md`，Minimal API handlers inject only `IProcessingService`。
- **⚡ Processing Services <br/><i>Heavy computation, AI/ML, 1-2 Orchestration services</i>**：处理服务，负责进行繁重的计算，例如 AI/ML 任务。每个处理服务对应 1-2 个编排服务。
- **🔄 Orchestration Services <br/><i>Coordination, cross-cutting, 2-3 Foundation services</i>**：编排服务，负责协调不同服务，处理横切关注点。每个编排服务对应 2-3 个基础服务。
- **🏗️ Foundation Services <br/><i>CRUD, validation, 1-2 Brokers</i>**：基础服务，负责 CRUD 操作（创建、读取、更新、删除），数据验证等。每个基础服务对应 1-2 个代理。
- **📦 Brokers <br/><i>External abstraction, thin wrappers, NO business logic</i>**：代理，负责对外部服务进行抽象，提供轻量级的封装，不包含任何业务逻辑。根据 `knowledge/insights/brokers-are-thin-wrappers-with-zero-business-logic.md`，代理层不包含任何业务逻辑。

## 连线、分支与汇聚关系
- `EP --> PS`：端点服务调用处理服务。
- `PS --> OS`：处理服务调用编排服务。
- `OS --> FS`：编排服务调用基础服务。
- `FS --> BR`：基础服务调用代理。

## 仓库语境与术语解释
- **The Standard**：Hassan Habib 提出的软件工程标准，用于构建企业级系统。`docs/rfc/2003-the-standard-implementation.md` 详细描述了 `arolariu.ro` 后端如何实现该标准。
- **Domain-Driven Design (DDD)**：一种软件开发方法，侧重于将业务领域知识融入到软件设计中。`docs/rfc/2001-domain-driven-design-architecture.md` 描述了 DDD 在 `arolariu.ro` 后端 API 中的应用。
- **Brokers**：根据 `knowledge/insights/tri-nature-theory-grounds-the-standard-in-dependencies-purpose-and-exposure.md`，代理层代表依赖关系（Dependencies），是 Tri-Nature 理论的一部分。
- **Endpoints (Exposers)**：根据 `knowledge/insights/tri-nature-theory-grounds-the-standard-in-dependencies-purpose-and-exposure.md`，暴露端点层代表暴露（Exposure），是 Tri-Nature 理论的一部分。
- **Florance Pattern**：一种依赖管理模式，限制每个服务最多依赖 2-3 个其他服务。`knowledge/insights/the-florance-pattern-limits-each-service-to-two-or-three-dependencies.md` 详细描述了该模式。
- **CRUD**：创建（Create）、读取（Read）、更新（Update）、删除（Delete）操作的缩写，是基础服务层的主要职责之一。
- **Monorepo**：根据 README.md，`arolariu.ro` 项目采用 Monorepo 架构。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 `arolariu.ro` 项目后端服务的五层架构，遵循 "The Standard" 架构原则。请求从暴露端点（Endpoints）进入，依次经过处理服务（Processing Services）、编排服务（Orchestration Services）、基础服务（Foundation Services），最终到达代理层（Brokers）。每一层都依赖于下一层提供的服务，形成清晰的依赖关系链。该架构采用分层设计，有助于解耦不同服务，提高系统的可维护性和可扩展性。其中，Brokers 代表依赖关系，Endpoints 代表暴露，而中间三层则代表目的。
