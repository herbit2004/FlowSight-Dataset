## Diagram Type & Purpose

It outlines the steps involved from the initial user request to the final payment confirmation, including validation, calculation, generation, and payment processing. The diagram serves as a visual representation of the invoice lifecycle within the system.

## High-Density QA Ground Truth Summary
The process begins with the user initiating an invoice request via the UI (A). The system then checks if the request is valid (B). If the request is not valid (B -- No --> E), an error is returned to the UI. If the request is valid (B -- Yes --> C), the Invoice Request Service receives the request (C) and checks if the customer account is active (D). If the account is inactive (D -- No --> G), an error is returned. If the account is active (D -- Yes --> F), the Billing Engine calculates invoice details (F), followed by the Tax Service calculating applicable taxes (H) and the Discount Engine applying eligible discounts (I). The Invoice Generation Service then creates the invoice document (J), which is persisted to the database (K). The system checks if a payment method is on file (L). If not (L -- No --> N), an invoice notification is sent, and the invoice status is updated to awaiting payment (Q). If a payment method is on file (L -- Yes --> M), the Payment Service attempts automated payment (M). If payment is successful (M -- Payment Successful --> O), the invoice status is updated to paid, and a payment confirmation is sent (R). If payment fails (M -- Payment Failed --> P), a payment reminder is sent, and the invoice status is updated to awaiting payment (Q). The Notification Service is used to send invoice notifications, payment reminders, and payment confirmations.
