## 图类型与用途
该图是一个流程图，描述了一个电商系统中创建订单并完成支付的完整流程。它展示了订单服务、库存服务和支付服务之间的交互关系。该图可以帮助理解订单创建和支付过程中的关键步骤和状态转换。

## 图的整体布局
该图采用从上到下的布局。整体上分为订单服务、库存服务和支付服务三个子流程。流程从“收到创建订单请求”开始，到“更新订单状态为已支付”或“释放已锁定库存”结束。

## 分组/子图/阶段说明
图中包含三个子图：
- **订单服务**：处理订单创建请求，进行参数校验，并根据库存情况决定是否锁定库存。
- **库存服务**：接收锁定库存请求，更新库存，并返回锁定结果。
- **支付服务**：接收支付请求，创建支付订单，并返回支付订单信息。

## 节点逐项说明
- **收到创建订单请求**：订单服务接收到用户发起的创建订单请求。
- **参数校验**：订单服务对接收到的订单参数进行校验。
- **库存是否充足?**：判断当前库存是否满足订单需求。
- **锁定库存**：如果库存充足，则锁定相应数量的库存。
- **返回库存不足**：如果库存不足，则返回库存不足的错误信息。
- **接收锁定库存请求**：库存服务接收到订单服务发起的锁定库存请求。
- **更新库存**：库存服务更新库存数量。
- **返回锁定结果**：库存服务返回库存锁定结果。
- **发起支付请求**：订单服务发起支付请求。
- **接收发起支付请求**：支付服务接收到订单服务发起的支付请求。
- **创建支付订单**：支付服务创建一个支付订单。
- **返回支付订单信息**：支付服务返回支付订单的相关信息。
- **返回支付成功**：支付服务返回支付成功的消息。
- **返回支付失败**：支付服务返回支付失败的消息。
- **通知订单服务**：支付服务通知订单服务支付结果。
- **更新订单状态为已支付**：订单服务更新订单状态为已支付。
- **更新订单状态为待支付**：订单服务更新订单状态为待支付。
- **释放已锁定库存**：释放之前锁定的库存。
- **返回订单创建失败**：订单服务返回订单创建失败的消息。

## 连线、分支与汇聚关系
- A -> B：收到创建订单请求后，进行参数校验。
- B -- 校验通过 --> C：参数校验通过后，判断库存是否充足。
- C -- 是 --> D：库存充足，锁定库存。
- C -- 否 --> E：库存不足，返回库存不足。
- F -> G：接收锁定库存请求后，更新库存。
- G -> H：更新库存后，返回锁定结果。
- D -- 锁定成功 --> L：锁定库存成功后，发起支付请求。
- L -> I：发起支付请求到支付服务。
- I -> J：接收发起支付请求后，创建支付订单。
- J -> K：创建支付订单后，返回支付订单信息。
- I -- 支付成功 --> M：支付成功，返回支付成功。
- I -- 支付失败 --> N：支付失败，返回支付失败。
- M -> O：支付成功后，通知订单服务。
- N -> P：支付失败后，通知订单服务。
- O -> Q：收到支付成功通知后，更新订单状态为已支付。
- P -> R：收到支付失败通知后，更新订单状态为待支付。
- R -> S：订单状态为待支付时，释放已锁定库存。
- E -> T：返回库存不足时，返回订单创建失败。
- N -> S：支付失败后，释放已锁定库存。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **订单服务**：负责处理订单相关的业务逻辑，包括创建订单、修改订单状态等。
- **库存服务**：负责管理商品库存，提供库存查询、锁定、释放等功能。
- **支付服务**：负责处理支付相关的业务逻辑，包括发起支付、接收支付结果等。
- **锁定库存**：在用户下单后，暂时将商品库存锁定，防止超卖。
- **释放库存**：在订单取消或支付失败后，将锁定的库存释放，供其他用户购买。
- **支付订单**：支付服务中用于记录支付信息的订单。

## 可作为 QA Ground Truth 的高信息密度摘要
订单服务收到创建订单请求后，进行参数校验，校验通过后，判断库存是否充足。如果库存充足，则锁定库存，并向支付服务发起支付请求。支付服务接收到支付请求后，创建支付订单，并返回支付订单信息。如果支付成功，则通知订单服务更新订单状态为已支付；如果支付失败，则通知订单服务更新订单状态为待支付，并释放已锁定库存。如果库存不足，则返回订单创建失败。
