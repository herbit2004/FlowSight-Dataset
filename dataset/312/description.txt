## 图类型与用途
这是一个流程图/架构图，描述了 MCP 客户端如何通过 `revit-mcp` 服务器与 Revit 软件进行通信。该图展示了客户端（如 ClaudeDesktop）发送命令到 Revit，以及 Revit 执行命令后返回结果的整体流程。

## 图的整体布局
图采用从左到右的布局。左侧是 MCP 客户端，中间是 `revit-mcp` 服务器，右侧是 Revit 及其插件。数据流从左向右流动，最终返回到中间的服务器和左侧的客户端。

## 分组/子图/阶段说明
图中包含三个子图，分别代表 MCPClient、MCPServer 和 Revit。Revit 子图中又包含一个子图 `revit-mcp-plugin`。

## 节点逐项说明
- **ClaudeDesktop**：代表使用 MCP 协议的 AI 客户端，例如 Claude。README 提到支持 Claude 等 MCP 客户端。
- **revit-mcp**：代表 `revit-mcp` 服务器，它是 AI 客户端和 Revit 之间的桥梁。README 提到该项目是服务器端，为 AI 提供工具。
- **SocketService**：`revit-mcp-plugin` 的一部分，负责建立和维护客户端与 Revit 之间的 Socket 连接，接收命令并发送执行结果。
- **CommandSet**：`revit-mcp-plugin` 的一部分，用于管理和组织各种命令。它接收来自 SocketService 的 `commandName`，并根据名称找到对应的 `command`。
- **CommandManager**：`revit-mcp-plugin` 的一部分，负责管理和注册不同的命令项目（CommandProject1, CommandProject2, CommandProject...）。
- **CommandExecute**：`revit-mcp-plugin` 的一部分，负责实际执行从 CommandSet 获取的命令。
- **CommandProject1, CommandProject2, CommandProject...**：表示不同的命令项目，图中可见，但仓库上下文未进一步说明。

## 连线、分支与汇聚关系
- `ClaudeDesktop -> revit-mcp`：ClaudeDesktop 向 revit-mcp 服务器发送请求。
- `revit-mcp -> SocketService`：revit-mcp 服务器将请求转发给 Revit 插件的 SocketService。
- `SocketService --commandName--> CommandSet`：SocketService 根据命令名称将命令发送给 CommandSet。
- `CommandManager -> CommandSet`：CommandManager 管理 CommandSet 中的命令。
- `CommandSet --command--> CommandExecute`：CommandSet 将命令发送给 CommandExecute 执行。
- `CommandExecute --executeResult--> SocketService`：CommandExecute 执行命令后将结果返回给 SocketService。
- `CommandProject1 -> CommandManager`：CommandProject1 向 CommandManager 注册命令。
- `CommandProject2 -> CommandManager`：CommandProject2 向 CommandManager 注册命令。
- `CommandProject... -> CommandManager`：更多的 CommandProject 向 CommandManager 注册命令，形成汇聚关系。

## 仓库语境与术语解释
- **MCP (Model Context Protocol)**：一种允许 AI 客户端与软件进行交互的协议。README 提到 `revit-mcp` 允许使用 MCP 协议与 Revit 交互。
- **revit-mcp-plugin**：一个 Revit 插件，用于驱动 Revit 执行命令。README 提到需要与 `revit-mcp-plugin` 结合使用。
- **SocketService**：负责建立和维护客户端与 Revit 之间的 Socket 连接。`src/utils/SocketClient.ts` 文件中定义了 `RevitClientConnection` 类，用于处理 Socket 连接。
- **CommandSet/CommandManager/CommandExecute**：这些组件共同负责命令的管理、查找和执行。`src/tools/register.ts` 文件负责注册工具，这些工具最终会被 CommandExecute 执行。
- **Tools 目录**：`src/tools` 目录下包含了各种工具，例如 `get_current_view_info`、`create_point_based_element` 等，这些工具可以通过 MCP 协议被 AI 客户端调用。
- **registerTools 函数**：`src/tools/register.ts` 中定义的函数，用于动态注册工具到 MCP 服务器。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 ClaudeDesktop 等 MCP 客户端如何通过 `revit-mcp` 服务器与 Revit 软件进行交互。客户端发送请求到服务器，服务器将命令转发给 Revit 插件的 SocketService，SocketService 根据命令名称将命令发送给 CommandSet，最终由 CommandExecute 执行。CommandManager 负责管理命令项目，并将命令注册到 CommandSet 中。整体流程是从客户端发起请求，经过服务器中转，最终在 Revit 中执行，并将结果返回。`revit-mcp-plugin` 是驱动 Revit 的关键组件，而 `src/tools/register.ts` 负责注册可被 AI 客户端调用的工具。
