## 图类型与用途
该图是一个流程图，描述了服务器数据的备份与恢复流程。它展示了从服务器数据变更开始，经过备份流程，最终完成数据恢复的过程。该图可以用于理解和优化数据备份与恢复策略。

## 图的整体布局
该图采用从上到下的布局。整体分为四个层次：初始状态、备份流程、恢复流程和最终状态。流程从“服务器数据变更”开始，到“服务器数据恢复完成”结束。

## 分组/子图/阶段说明
图中包含三个显式子图：
- **初始状态**：描述服务器数据变更的初始状态。
- **备份流程**：描述数据备份的详细步骤。
- **恢复流程**：描述数据恢复的详细步骤。

## 节点逐项说明
- **服务器数据变更**：表示服务器上的数据发生了变化，需要进行备份。
- **检查备份策略**：检查当前的数据变更是否满足备份策略的条件。
- **触发备份任务**：根据备份策略，触发备份任务的执行。
- **应用一致性快照**：创建数据的一致性快照，保证备份数据的一致性。
- **数据增量备份**：只备份自上次备份以来发生变化的数据，提高备份效率。
- **数据压缩**：对备份数据进行压缩，减少存储空间。
- **备份数据加密**：对备份数据进行加密，保护数据的安全性。
- **上传至备份仓库**：将备份数据上传到备份仓库进行存储。
- **验证备份完整性**：验证备份数据的完整性，确保数据可用。
- **选择恢复点**：选择要恢复到的备份时间点。
- **下载备份数据**：从备份仓库下载选定的备份数据。
- **解密备份数据**：对备份数据进行解密，恢复数据的可读性。
- **数据解压**：对备份数据进行解压缩，恢复数据的原始大小。
- **数据校验**：对解压后的数据进行校验，确保数据完整性。
- **数据恢复至目标**：将备份数据恢复到目标服务器或存储位置。
- **启动后校验**：在数据恢复完成后，进行启动后的校验，确保数据可用。
- **服务器数据恢复完成**：表示服务器数据已经成功恢复。

## 连线、分支与汇聚关系
- `服务器数据变更 -> 检查备份策略`：服务器数据变更后，需要检查是否满足备份策略。
- `检查备份策略 -- 满足条件 --> 触发备份任务`：如果满足备份策略，则触发备份任务。
- `检查备份策略 -- 不满足 --> 服务器数据变更`：如果不满足备份策略，则回到服务器数据变更状态，等待下次检查。
- `触发备份任务 -> 应用一致性快照`：触发备份任务后，首先应用一致性快照。
- `应用一致性快照 -> 数据增量备份`：应用一致性快照后，进行数据增量备份。
- `数据增量备份 -> 数据压缩`：数据增量备份完成后，进行数据压缩。
- `数据压缩 -> 备份数据加密`：数据压缩完成后，进行备份数据加密。
- `备份数据加密 -> 上传至备份仓库`：备份数据加密完成后，上传至备份仓库。
- `上传至备份仓库 -> 验证备份完整性`：上传至备份仓库后，验证备份完整性。
- `验证备份完整性 -- 成功 --> 选择恢复点`：如果备份完整性验证成功，则进入恢复流程，选择恢复点。
- `验证备份完整性 -- 失败 --> 触发备份任务`：如果备份完整性验证失败，则重新触发备份任务。
- `选择恢复点 -> 下载备份数据`：选择恢复点后，下载备份数据。
- `下载备份数据 -> 解密备份数据`：下载备份数据后，解密备份数据。
- `解密备份数据 -> 数据解压`：解密备份数据后，进行数据解压。
- `数据解压 -> 数据校验`：数据解压后，进行数据校验。
- `数据校验 -> 数据恢复至目标`：数据校验完成后，将数据恢复至目标。
- `数据恢复至目标 -> 启动后校验`：数据恢复至目标后，进行启动后校验。
- `启动后校验 -> 服务器数据恢复完成`：启动后校验完成后，服务器数据恢复完成。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **备份策略**：定义了何时、何种数据需要备份的规则和流程。
- **一致性快照**：在某个特定时间点创建的数据副本，用于保证备份数据的一致性。
- **增量备份**：只备份自上次备份以来发生变化的数据。
- **备份仓库**：用于存储备份数据的存储系统或位置。
- **恢复点**：备份数据的时间点，用于选择要恢复到的数据状态。
- **数据校验**：验证数据完整性和准确性的过程。

## 可作为 QA Ground Truth 的高信息密度摘要
服务器数据变更后，系统检查备份策略。如果满足策略，则触发备份任务，应用一致性快照，进行数据增量备份、压缩和加密，然后上传至备份仓库并验证完整性。备份成功后，可以选择恢复点，下载、解密、解压备份数据，进行数据校验，恢复至目标服务器，并进行启动后校验，最终完成服务器数据恢复。如果备份完整性验证失败，则重新触发备份任务。
