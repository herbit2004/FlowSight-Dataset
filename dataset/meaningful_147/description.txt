## 图类型与用途
该图是一个流程图，描述了一个分布式系统的请求处理流程，包括前端服务、后端服务集群和链路追踪系统。它展示了用户请求如何经过 API 网关、路由转发到不同的后端服务，以及链路追踪系统如何收集和展示请求的调用链信息。该图旨在帮助理解分布式系统的架构和请求处理过程。

## 图的整体布局
该图采用从上到下的布局，分为三个主要层次：前端服务、后端服务集群和链路追踪系统。用户请求是起点，链路追踪系统的可视化界面是终点。

## 分组/子图/阶段说明
图中包含三个子图：
- **前端服务**：处理用户请求的入口，包括 API 网关、认证授权、流量控制和路由转发。
- **后端服务集群**：包含多个后端服务，如用户画像、订单管理和库存管理，以及它们对应的数据存储。
- **链路追踪系统**：收集、存储和展示请求的调用链信息，包括 Agent、Collector、Storage、Query 和 UI。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **API Gateway**：API 网关，是系统的入口，负责请求的路由、认证、授权和流量控制等功能。
- **SpanContext**：用于在分布式系统中传递调用链信息的上下文数据。
- **TraceId**：用于标识一次请求的唯一ID，贯穿整个调用链。
- **Span**：表示一次调用过程，包含调用的开始时间、结束时间、调用的服务等信息。
- **Agent**：链路追踪 Agent，负责收集请求的调用链信息。
- **Collector**：链路追踪 Collector，负责收集 Agent 上报的调用链数据。
- **UI**：链路追踪 UI，展示调用链信息的可视化界面。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先到达 API Gateway，经过认证授权和流量控制后，路由转发到不同的后端服务，例如用户画像服务、订单管理服务和库存管理服务。这些服务分别查询或操作对应的数据库。在整个过程中，链路追踪 Agent 收集调用链信息，上报给 Collector，Collector 将数据存储到 Storage 中，最终通过 Query 服务和 UI 可视化界面展示调用链信息。每个服务都会上报Span到Agent。
