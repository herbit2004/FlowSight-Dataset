## 图类型与用途
该图是一个流程图，描述了数据变更后触发备份任务的流程。它展示了数据异动判断、备份目标选择以及备份完成的整个过程。该流程图用于说明数据备份策略和流程。

## 图的整体布局
该图从上到下布局，整体呈现线性流程。流程从“数据变更事件”开始，最终到达“备份任务完成”或“流程结束”。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. 数据变更与异动判断阶段（A -> B）
2. 备份任务触发阶段（B -> C）
3. 备份数据准备与目标选择阶段（C -> E -> F）
4. 数据写入与验证阶段（G/H -> I -> J）
5. 任务完成阶段（J -> K）

## 节点逐项说明
- **A**：数据变更事件，表示数据发生了变化，触发后续流程。
- **B**：数据异动判断，判断数据变更是否需要备份。
- **C**：增量备份任务触发，当数据需要备份时，触发增量备份任务。
- **D**：流程结束，当数据无需备份时，流程结束。
- **E**：备份数据准备，准备需要备份的数据。
- **F**：备份目标选择，根据优先级选择备份目标。
- **G**：在线热备库，优先级高的备份目标，用于快速恢复数据。
- **H**：离线冷备存储，优先级低的备份目标，用于长期存储数据。
- **I**：备份数据写入，将数据写入到选定的备份目标。
- **J**：备份结果验证，验证备份数据是否正确。
- **K**：备份任务完成，表示备份任务成功完成。

## 连线、分支与汇聚关系
- A -> B：数据变更事件触发数据异动判断。
- B -- 需要备份 --> C：如果数据需要备份，则触发增量备份任务。
- B -- 无需备份 --> D：如果数据无需备份，则流程结束。
- C -> E：增量备份任务触发后，进行备份数据准备。
- E -> F：备份数据准备完成后，选择备份目标。
- F -- 优先级高 --> G：如果优先级高，则选择在线热备库。
- F -- 优先级低 --> H：如果优先级低，则选择离线冷备存储。
- G -> I：将数据写入在线热备库。
- H -> I：将数据写入离线冷备存储。
- I -> J：备份数据写入完成后，进行备份结果验证。
- J -> K：备份结果验证通过后，备份任务完成。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **数据变更事件**：指数据库中数据发生了修改、删除或新增等变化。
- **增量备份**：仅备份自上次完全备份以来发生变化的数据。
- **在线热备库**：一种高可用性的备份存储，允许快速数据恢复。
- **离线冷备存储**：一种低成本的备份存储，通常用于长期归档。
- **备份数据写入**：将备份数据传输并存储到指定的备份介质或存储位置的过程。
- **备份结果验证**：对备份数据的完整性和可用性进行检查，确保备份的有效性。

## 可作为 QA Ground Truth 的高信息密度摘要
数据变更事件触发后，系统判断数据是否需要备份。如果需要备份，则触发增量备份任务，并准备备份数据。根据优先级选择备份目标，优先级高则写入在线热备库，优先级低则写入离线冷备存储。备份数据写入完成后，进行备份结果验证，验证通过则备份任务完成。如果数据不需要备份，则流程直接结束。
