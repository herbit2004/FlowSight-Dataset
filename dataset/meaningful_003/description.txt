## 图类型与用途
该图是流程图，描述了库存扣减和库存回滚的两种流程。它展示了用户请求发起后，库存扣减的完整过程，以及扣减失败后库存回滚的流程。该图可以帮助理解库存管理系统的运作机制。

## 图的整体布局
该图采用从左到右的布局。整体上分为上下两个子图，分别代表库存扣减流程和库存回滚流程。两个流程的起点分别是“用户请求”和“接收回滚请求”，终点都是流程结束。

## 分组/子图/阶段说明
图中包含两个子图：
- **库存扣减流程**：描述了从用户请求到库存扣减完成或预占释放的完整流程。
- **库存回滚流程**：描述了接收到回滚请求后，查询待扣减记录状态并进行库存回滚的流程。

## 节点逐项说明
- **A (用户请求)**：用户发起库存扣减的请求。
- **B (校验请求参数)**：对用户请求的参数进行校验。
- **C (预占库存)**：尝试预先占用库存。
- **D (生成待扣减记录)**：生成一条待扣减的库存记录。
- **E (返回库存不足)**：如果预占库存失败，则返回库存不足的提示。
- **F (发送库存扣减消息)**：发送库存扣减的消息到消息队列。
- **G (MQ: 库存扣减消费者)**：消息队列中的库存扣减消费者，负责处理扣减消息。
- **H (实际扣减库存)**：实际执行库存扣减操作。
- **I (更新扣减记录状态为成功)**：如果扣减成功，则更新扣减记录的状态为成功。
- **J (更新扣减记录状态为失败)**：如果扣减失败，则更新扣减记录的状态为失败。
- **K (释放预占库存)**：释放之前预占的库存。
- **L (流程结束: 库存已扣减/预占已释放)**：库存扣减流程的最终状态。
- **M (返回参数错误)**：如果参数校验失败，则返回参数错误的提示。
- **N (接收回滚请求)**：接收到库存回滚的请求。
- **O (查询待扣减记录状态)**：查询待扣减记录的当前状态。
- **P (释放预占库存)**：释放预占的库存。
- **Q (记录状态异常)**：如果记录状态不是失败，则标记为异常状态。
- **R (更新扣减记录状态为已回滚)**：更新扣减记录的状态为已回滚。
- **S (流程结束: 库存已回滚)**：库存回滚流程的最终状态。

## 连线、分支与汇聚关系
- A -> B：用户请求发送到参数校验环节。
- B -- 参数有效 --> C：参数校验通过，进入预占库存环节。
- B -- 参数无效 --> M：参数校验失败，返回参数错误。
- C -- 预占成功 --> D：预占库存成功，生成待扣减记录。
- C -- 预占失败 --> E：预占库存失败，返回库存不足。
- D -> F：生成待扣减记录后，发送库存扣减消息。
- F -> G：发送消息到消息队列的库存扣减消费者。
- G -- 收到消息 --> H：消费者收到消息，开始实际扣减库存。
- H -- 扣减成功 --> I：扣减成功，更新扣减记录状态为成功。
- H -- 扣减失败 --> J：扣减失败，更新扣减记录状态为失败。
- I -> K：扣减成功后，释放预占库存。
- J -> K：扣减失败后，释放预占库存。
- K -> L：释放预占库存后，流程结束。
- M -> L：返回参数错误后，流程结束。
- E -> L：返回库存不足后，流程结束。
- N -> O：接收回滚请求后，查询待扣减记录状态。
- O -- 状态为失败 --> P：记录状态为失败，释放预占库存。
- O -- 其他状态 --> Q：记录状态为其他状态，标记记录状态异常。
- P -> R：释放预占库存后，更新扣减记录状态为已回滚。
- R -> S：更新扣减记录状态后，流程结束。
- Q -> S：标记记录状态异常后，流程结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **库存**：指可以被销售或使用的商品数量。
- **预占库存**：指暂时锁定一部分库存，防止被其他请求使用。
- **库存扣减**：指实际减少库存数量的操作。
- **库存回滚**：指将已经扣减的库存恢复到之前的状态。
- **MQ (消息队列)**：一种异步通信机制，用于在不同的系统或组件之间传递消息。
- **消费者**：指从消息队列中接收并处理消息的应用程序或组件。
- **待扣减记录**：记录了需要进行库存扣减的信息。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求发起库存扣减，首先校验请求参数，参数有效则预占库存，预占成功则生成待扣减记录并发送库存扣减消息到MQ，MQ消费者收到消息后实际扣减库存，扣减成功则更新扣减记录状态为成功并释放预占库存，扣减失败则更新扣减记录状态为失败并释放预占库存，最终流程结束。若预占库存失败，则返回库存不足并结束流程。若参数校验失败，则返回参数错误并结束流程。如果接收到回滚请求，则查询待扣减记录状态，状态为失败则释放预占库存并更新扣减记录状态为已回滚，流程结束。
