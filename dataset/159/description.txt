## Edges, Branches & Convergence
- `A --> B`: The SQL query input is passed to the Parser Module.
- `B --> C`: The Parser Module generates an AST.
- `C --> D`: The AST is passed to the Converter Module.
- `K --> D`: The Schema System provides schema information to the Converter Module.
- `D --> E`: The Converter Module passes the converted representation to Semantic Analysis.
- `E --> F`: Semantic Analysis passes the analyzed representation to Code Generation.
- `F --> G`: Code Generation passes the generated code to the Evaluator Module.
- `K --> G`: The Schema System provides schema information to the Evaluator Module.
- `L --> K`: The Plugin System interacts with the Schema System.
- `L --> G`: The Plugin System interacts with the Evaluator Module.
- `G --> H`: The Evaluator Module passes the evaluated code to Compilation.
- `H --> I`: The compiled code is passed to Execution.
- `I --> J`: The executed code produces the Results Output.

## Repository Context & Terminology
- **SQL Query**: A structured query language statement used to interact with databases.
- **Parser Module**: A software component that transforms input data (in this case, an SQL query) into a data structure suitable for further processing.
- **AST (Abstract Syntax Tree)**: A tree representation of the abstract syntactic structure of source code written in a programming language.
- **Schema System**: A system that defines the structure and constraints of the data stored in a database.
- **Plugin System**: A system that allows adding new features or functionalities to an existing software application without altering the core code.
- **Evaluator Module**: A component that evaluates the generated code against the schema and data.
- **Compilation**: The process of translating source code into machine code or another lower-level form.
