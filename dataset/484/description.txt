## Edges, Branches & Convergence
- `check -- No --> skip`: If there are no changes detected, the process goes to sleep.
- `check -- Yes --> stage`: If there are changes detected, the process proceeds to the synchronization pipeline.
- `stage --> commit`: After staging changes, the process commits them.
- `commit --> pull`: After committing, the process pulls and rebases from the remote repository.
- `pull --> push`: After successfully pulling and rebasing, the process pushes the changes to the remote repository.
- `push --> done`: After successfully pushing, the process is complete.
- `pull -- conflict --> err`: If a conflict occurs during the pull and rebase operation, the process goes to the manual fix state.

## Repository Context & Terminology
- **launchd**: A system service management framework in macOS used to manage daemons, applications, processes, and scripts. The diagram indicates that `launchd` is used to schedule the synchronization task every 5 minutes.
- **git add -A**: A Git command that stages all changes (new, modified, and deleted) in the repository for the next commit.
- **git commit**: A Git command that records the staged changes in the repository's history.
- **git pull --rebase**: A Git command that fetches changes from a remote repository and integrates them into the current branch by rebasing the local commits on top of the remote commits. This helps maintain a cleaner commit history.
- **git push**: A Git command that uploads the local repository's commits to a remote repository.
- **gmd doctor**: A diagnostic tool (likely specific to the project) used to diagnose and resolve issues, particularly conflicts arising during the `git pull --rebase` operation.
