## 图类型与用途
这是一个流程图，展示了 Parlant 系统的核心架构和信息流，描述了 Parlant 如何利用各种输入信息来生成最终的消息。根据 README，Parlant 的目标是为面向客户的 AI 代理提供会话控制层。

## 图的整体布局
图整体采用从左到右的布局。左侧是各种输入信息，中间是核心处理引擎和工具调用器，右侧是消息生成器。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：信息输入阶段、上下文匹配与工具调用阶段、消息生成阶段。

## 节点逐项说明
- **Observations (O)**：观察结果，代表系统接收到的事件或用户输入。
- **Guidelines (G)**：指导方针，代表系统遵循的规则或策略。根据 `docs/concepts/customization/guidelines.md`，Guidelines 是以 condition-action 对的形式存在的行为规则，用于在特定情况下引导 agent 的行为。
- **Journeys (SOPs) (J)**：流程（标准操作程序），代表系统执行的预定义步骤。根据 `docs/concepts/customization/journeys.md`，Journeys 用于定义 agent 需要遵循的特定对话流程。
- **Retrievers (R)**：检索器，代表系统用于访问领域知识的模块。根据 `docs/concepts/customization/retrievers.md`，Retrievers 用于获取上下文信息，以增强 agent 的知识并使其与当前对话状态保持一致。
- **Glossary (GL)**：词汇表，代表系统使用的领域术语。根据 `docs/concepts/customization/glossary.md`，Glossary 用于定义 agent 需要理解的特定领域的术语。
- **Variables (V)**：变量，代表系统存储的记忆或状态信息。根据 `docs/concepts/customization/variables.md`，Variables 用于丰富 agent 所看到的关于客户的上下文信息，以便 agent 可以根据客户的具体情况定制其响应。
- **Contextual Matching Engine (E)**：上下文匹配引擎，是系统的核心组件，负责整合所有输入信息。
- **Tool Caller (T)**：工具调用器，负责调用外部工具来执行特定任务。
- **Message Generation (M)**：消息生成器，负责根据上下文生成最终的消息。

## 连线、分支与汇聚关系
- `Observations (O) -> Contextual Matching Engine (E)`：Observations 通过 "Events" 流向 Contextual Matching Engine。
- `Guidelines (G) -> Contextual Matching Engine (E)`：Guidelines 通过 "Instructions" 流向 Contextual Matching Engine。
- `Journeys (SOPs) (J) -> Contextual Matching Engine (E)`：Journeys 通过 "Current Steps" 流向 Contextual Matching Engine。
- `Retrievers (R) -> Contextual Matching Engine (E)`：Retrievers 通过 "Domain Knowledge" 流向 Contextual Matching Engine。
- `Glossary (GL) -> Contextual Matching Engine (E)`：Glossary 通过 "Domain Terms" 流向 Contextual Matching Engine。
- `Variables (V) -> Contextual Matching Engine (E)`：Variables 通过 "Memories" 流向 Contextual Matching Engine。
- `Contextual Matching Engine (E) -> Tool Caller (T)`：Contextual Matching Engine 通过 "Tool Requests" 流向 Tool Caller。
- `Tool Caller (T) -.-> Contextual Matching Engine (E)`：Tool Caller 通过 "Results + Optional Extra Matching Iterations" 虚线箭头返回到 Contextual Matching Engine，表示可选的反馈循环。
- `Tool Caller (T) -> Message Generation (M)`：Tool Caller 通过 "**Key Result:** Focused Context Window" 流向 Message Generation。

## 仓库语境与术语解释
- **Observations**：代表系统接收到的事件或用户输入，是系统了解用户意图的基础。
- **Guidelines**：用于规范 agent 行为的规则，确保 agent 在特定情况下采取正确的行动。
- **Journeys**：用于定义 agent 需要遵循的特定对话流程，确保对话按照预期的步骤进行。
- **Retrievers**：用于从外部知识库中检索信息，增强 agent 的知识并使其与当前对话状态保持一致。
- **Glossary**：用于定义 agent 需要理解的特定领域的术语，确保 agent 能够正确理解用户的意图。
- **Variables**：用于存储客户的个性化信息，使 agent 能够根据客户的具体情况定制其响应。
- **Contextual Matching Engine**：系统的核心组件，负责整合所有输入信息，并根据这些信息确定 agent 的下一步行动。
- **Tool Caller**：用于调用外部工具来执行特定任务，例如查询数据库或调用 API。
- **Message Generation**：用于根据上下文生成最终的消息，确保消息内容准确、流畅、符合用户需求。

## 可作为 QA Ground Truth 的高信息密度摘要
这张图展示了 Parlant 系统的核心架构，从 Observations、Guidelines、Journeys、Retrievers、Glossary 和 Variables 等多个来源获取信息，这些信息汇聚到 Contextual Matching Engine 中进行处理。Contextual Matching Engine 决定是否需要调用 Tool Caller 来执行外部工具，并将结果反馈回 Contextual Matching Engine 进行可选的额外匹配迭代。最终，Tool Caller 将关键结果（Focused Context Window）传递给 Message Generation 模块，生成最终的消息。整个流程体现了 Parlant 如何通过整合多方信息，并利用外部工具来生成高质量的对话消息。其中 Guidelines 和 Journeys 用于控制 agent 的行为，Retrievers 和 Glossary 用于增强 agent 的知识，Variables 用于个性化 agent 的响应。
