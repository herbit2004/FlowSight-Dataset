## 图类型与用途
这是一个架构图，展示了 Gas Town 系统的核心组件及其关系。Gas Town 是一个多智能体编排系统，旨在解决 Claude Code 智能体在重启后丢失上下文的问题。该图用于概览 Gas Town 的整体架构和工作原理。

## 图的整体布局
图整体采用从上到下的布局。顶部是 Town Workspace，向下分叉到 Mayor 和多个 Rigs。每个 Rig 又进一步连接到 Crew Members、Hooks 和 Polecats。Git Repository 位于图的底部，通过虚线连接到 Hooks。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为 Town 级别、Rig 级别和数据存储三个阶段。Town 级别包含 Mayor，Rig 级别包含 Crew Members、Hooks 和 Polecats，数据存储阶段是 Git Repository。

## 节点逐项说明
- **Town Workspace ~/gt/**：工作区目录，包含所有项目、智能体和配置。根据 README，它是整个系统的根目录。
- **The Mayor AI Coordinator**：主要的 AI 协调器，是一个 Claude Code 实例，拥有关于工作区、项目和智能体的完整上下文。根据 README，它是整个系统的入口点，负责协调和管理其他组件。
- **Rig: Project A / Rig: Project B**：项目容器，封装一个 Git 仓库并管理与其关联的智能体。根据 README，每个 Rig 代表一个独立的开发项目。
- **Crew Member Your workspace / Crew Member**：在 Rig 中的个人工作区，用于进行实际的开发工作。
- **Hooks Persistent storage / Hooks**：持久化存储，用于保存工作状态，即使智能体重启也不会丢失上下文。
- **Polecats Worker agents / Polecats**：工作智能体，具有持久的身份，但生命周期较短。根据 README，它们执行具体的任务，并受 Mayor 的协调。
- **Git Repository / Git Repository**：实际存储代码的 Git 仓库，每个 Rig 对应一个 Git 仓库。

## 连线、分支与汇聚关系
- `Town --> Mayor`：Town 包含 Mayor。
- `Town --> Rig1`：Town 包含 Rig1 (Project A)。
- `Town --> Rig2`：Town 包含 Rig2 (Project B)。
- `Rig1 --> Crew1`：Rig1 包含 Crew1。
- `Rig1 --> Hooks1`：Rig1 包含 Hooks1。
- `Rig1 --> Polecats1`：Rig1 包含 Polecats1。
- `Rig2 --> Crew2`：Rig2 包含 Crew2。
- `Rig2 --> Hooks2`：Rig2 包含 Hooks2。
- `Rig2 --> Polecats2`：Rig2 包含 Polecats2。
- `Hooks1 -.git worktree.-> GitRepo1`：Hooks1 使用 Git worktree 技术与 GitRepo1 进行交互，实现持久化存储。
- `Hooks2 -.git worktree.-> GitRepo2`：Hooks2 使用 Git worktree 技术与 GitRepo2 进行交互，实现持久化存储。

## 仓库语境与术语解释
- **Mayor**：主要的 AI 协调器，负责协调和管理其他组件。根据 `internal/config/roles/mayor.toml`，Mayor 的 scope 是 town 级别。
- **Rig**：项目容器，封装一个 Git 仓库并管理与其关联的智能体。`internal/cmd/rig.go` 文件定义了 rig 相关的命令。
- **Polecats**：工作智能体，具有持久的身份，但生命周期较短。根据 `internal/config/roles/polecat.toml`，Polecat 的 scope 是 rig 级别。
- **Hooks**：Git worktree-based persistent storage for agent work。
- **Town**：工作区目录，包含所有项目、智能体和配置。
- **Crew Member**：在 Rig 中的个人工作区。
- **Git worktree**：一种 Git 技术，允许在同一个仓库中同时检出多个工作目录。
- **Beads**：Git-backed issue tracking system that stores work state as structured data。

## 可作为 QA Ground Truth 的高信息密度摘要
这张图展示了 Gas Town 系统的核心架构。Town Workspace 作为根节点，包含 Mayor 和多个 Rigs。每个 Rig 又包含 Crew Members、Hooks 和 Polecats。Hooks 通过 Git worktree 技术与 Git Repository 交互，实现持久化存储。Mayor 负责协调各个 Rig 中的智能体，实现多智能体协同工作。Gas Town 的核心思想是围绕一个中心化的 AI 协调器（Mayor）组织多个项目（Rig），通过 Git worktree 技术，Hooks 将工作状态持久化到 Git 仓库中。
