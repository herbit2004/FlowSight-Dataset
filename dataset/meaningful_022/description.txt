## Edges, Branches & Convergence
- `Order Received --> Validate Order`: The flow starts with the receipt of an order.
- `Validate Order -- Valid --> Process Payment`: If the order is valid, proceed to payment processing.
- `Validate Order -- Invalid --> Reject Order`: If the order is invalid, reject it.
- `Process Payment --> Payment Successful?`: After processing the payment, check if it was successful.
- `Payment Successful? -- Yes --> Fulfill Order`: If the payment was successful, fulfill the order.
- `Payment Successful? -- No --> Payment Retry Logic`: If the payment failed, initiate the payment retry logic.
- `Fulfill Order --> Order Completed`: After fulfilling the order, mark it as completed.
- `Payment Retry Logic --> Retry Attempt Limit Reached?`: After initiating the payment retry logic, check if the retry limit has been reached.
- `Retry Attempt Limit Reached? -- Yes --> Reject Order`: If the retry limit has been reached, reject the order.
- `Retry Attempt Limit Reached? -- No --> Increment Retry Count`: If the retry limit has not been reached, increment the retry count.
- `Increment Retry Count --> Circuit Breaker Open?`: After incrementing the retry count, check if the circuit breaker is open.
- `Circuit Breaker Open? -- Yes --> Reject Order`: If the circuit breaker is open, reject the order.
- `Circuit Breaker Open? -- No --> Attempt Payment Retry`: If the circuit breaker is closed, attempt the payment retry.
- `Attempt Payment Retry --> Payment Successful?`: After attempting the payment retry, return to the "Payment Successful?" decision point.
- `Order Completed --> Post-Processing Tasks`: After the order is completed, perform post-processing tasks.
- `Post-Processing Tasks --> Inventory Update`: After post-processing tasks, update the inventory.
- `Inventory Update --> Reject Order`: If the inventory update fails, reject the order.
- `Reject Order --> Order Failed - Notify Support`: After rejecting the order, notify support.

## Repository Context & Terminology
- **Order Validation**: The process of verifying that the order details are correct and complete before processing the payment.
- **Payment Processing**: The process of collecting payment from the customer for the order.
- **Payment Retry Logic**: A mechanism to automatically retry payment processing in case of temporary failures.
- **Circuit Breaker**: A design pattern used to prevent an application from repeatedly trying to execute an operation that is likely to fail.
- **Order Fulfillment**: The process of preparing the order for shipment, including picking, packing, and labeling.
- **Post-Processing Tasks**: Tasks performed after the order is completed, such as sending confirmation emails and updating order status.
- **Inventory Update**: The process of adjusting the inventory levels to reflect the items sold in the order.

## High-Density QA Ground Truth Summary
The order submission flow begins with "Order Received," which triggers "Validate Order." If the order is deemed "Invalid," the flow immediately branches to "Reject Order" and then to "Order Failed - Notify Support," the terminal failure state. If the order is "Valid," the process moves to "Process Payment" and then to the decision point "Payment Successful?". A "Yes" branch leads to "Fulfill Order," "Order Completed," "Post-Processing Tasks," and "Inventory Update," representing a successful order. A "No" branch initiates "Payment Retry Logic," followed by a check: "Retry Attempt Limit Reached?". If "Yes," the order is rejected; if "No," the "Retry Count" is incremented. A "Circuit Breaker Open?" check then determines whether to attempt another payment retry or reject the order. If the circuit breaker is open, the order is rejected. If the circuit breaker is closed, the system attempts payment again. The "Payment Retry Logic" and "Circuit Breaker" are examples of resilience patterns implemented to handle transient payment failures, preventing cascading failures and improving the overall system stability. The flow converges at "Reject Order" from multiple failure points, ultimately leading to "Order Failed - Notify Support."
