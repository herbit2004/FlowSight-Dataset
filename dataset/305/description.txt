## 图类型与用途
这是一个流程图，描述了 Voxtype 语音转文本工具的整体架构和数据处理流程。它展示了从用户输入语音到最终文本输出的各个环节，以及不同组件之间的交互关系，用于概括 Voxtype 的核心工作流程。

## 图的整体布局
图整体采用从左到右的布局，分为 Input（输入）、Transcription（转录）和 Output（输出）三个主要阶段。流程从左侧的输入开始，经过中间的转录处理，最终到达右侧的输出。

## 分组/子图/阶段说明
图中包含三个显式子图：
- **Input**：负责接收用户的语音输入，包括热键触发和音频捕获。
- **Transcription**：负责将音频数据转换为文本，支持多种转录引擎和后端。
- **Output**：负责将转录后的文本输出到指定位置，并进行可选的后处理和与合成器的交互。

## 节点逐项说明
- **Hotkey (compositor/evdev)**：用户按下热键触发语音录制。根据 README，Voxtype 支持 compositor keybindings (Hyprland, Sway, River) 和 evdev fallback。
- **Audio (cpal)**：通过 cpal 库获取的音频数据。
- **Engine?**：决定使用哪种转录引擎。
- **WhisperBackend?**：决定使用哪种 Whisper 后端。
- **Whisper (whisper-rs)**：使用 whisper-rs 库进行本地转录。
- **CLI (subprocess)**：调用 whisper-cli 子进程进行转录。
- **Remote Server (HTTP API)**：通过 HTTP API 调用远程服务器进行转录。
- **ONNX Engine (Parakeet, Moonshine, SenseVoice, Paraformer, Dolphin, Omnilingual)**：使用 ONNX 引擎进行转录，支持多种模型。README 中提到 Voxtype 支持 7 种转录引擎，包括 Whisper 和多种 ONNX 模型。
- **Post-Process (optional)**：对转录结果进行可选的后处理。
- **Pre-Output Hook**：在文本输出前执行的自定义脚本或操作。
- **TextOutput (wtype/dotool/ydotool)**：将文本输出到光标位置，优先使用 wtype，其次是 dotool 和 ydotool。README 中提到 Voxtype 使用 fallback chain 进行类型输出。
- **Post-Output Hook**：在文本输出后执行的自定义脚本或操作。
- **Compositor (submap/mode)**：与合成器（如 Hyprland, Sway, River）交互，可能用于子映射或模式切换。

## 连线、分支与汇聚关系
- `Hotkey -> Audio`：用户按下热键后，系统捕获音频。
- `Audio -> Engine?`：音频数据传递给转录引擎。
- `Engine? -- whisper --> WhisperBackend?`：选择 Whisper 引擎。
- `Engine? -- onnx --> ONNX Engine`：选择 ONNX 引擎。
- `WhisperBackend? -- local --> Whisper`：选择本地 Whisper 后端。
- `WhisperBackend? -- cli --> CLI`：选择命令行 Whisper 后端。
- `WhisperBackend? -- remote --> Remote Server`：选择远程服务器 Whisper 后端。
- `Whisper -> PostProcess`：本地 Whisper 转录结果传递给后处理模块。
- `CLI -> PostProcess`：命令行 Whisper 转录结果传递给后处理模块。
- `Remote Server -> PostProcess`：远程服务器 Whisper 转录结果传递给后处理模块。
- `ONNX Engine -> PostProcess`：ONNX 引擎转录结果传递给后处理模块。
- `PostProcess -> Pre-Output Hook`：后处理后的文本传递给预输出钩子。
- `Pre-Output Hook -> TextOutput`：预输出钩子执行后，文本通过 TextOutput 组件输出。
- `TextOutput -> Post-Output Hook`：文本输出后，执行后输出钩子。
- `Pre-Output Hook -.-> Compositor`：预输出钩子可以与合成器进行交互。
- `Post-Output Hook -.-> Compositor`：后输出钩子可以与合成器进行交互。

## 仓库语境与术语解释
- **Hotkey**：用户按下以触发录音的按键。可在 `config/default.toml` 中配置，默认为 ScrollLock。
- **cpal**：一个跨平台的音频 I/O 库，用于捕获音频数据。
- **Whisper**：OpenAI 开发的语音识别模型，Voxtype 支持通过 whisper.cpp 进行本地推理。
- **ONNX**：开放神经网络交换格式，Voxtype 支持多种基于 ONNX 的语音识别模型，如 Parakeet, Moonshine, SenseVoice, Paraformer, Dolphin, Omnilingual。
- **wtype/dotool/ydotool**：用于将文本输出到光标位置的工具。Voxtype 优先使用 wtype，然后是 dotool 和 ydotool 作为 fallback。
- **Compositor**：Wayland 合成器，如 Hyprland, Sway, River。Voxtype 可以与合成器交互，实现子映射或模式切换。
- **Post-Process**：对转录文本进行后处理，例如通过 `config/default.toml` 中的 word replacements 和 spoken punctuation 功能进行修正。

## 可作为 QA Ground Truth 的高信息密度摘要
Voxtype 的核心流程从用户按下热键开始，通过 cpal 捕获音频，然后选择 Whisper 或 ONNX 引擎进行转录。Whisper 引擎可以选择本地、命令行或远程后端。转录结果经过可选的后处理后，通过 wtype/dotool/ydotool 输出到光标位置。预输出和后输出钩子可以与 Compositor 交互。`config/default.toml` 文件用于配置热键、音频设备、转录引擎和输出方式。
