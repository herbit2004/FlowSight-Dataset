## 图类型与用途
这是一个流程图，展示了 GoClaw 项目中多 Agent 团队如何协作处理用户请求。它描述了用户发起“Research competitor pricing”请求后，如何在不同 Agent 之间进行任务分配、信息传递和结果汇总，最终将答案返回给用户。该图在仓库中的作用是概括 Agent 团队协作处理用户请求的架构。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户节点，中间是 Agent 团队的子图，底部是各个 Agent 节点。流程从用户发起请求开始，经过 Agent 团队的处理，最终返回答案给用户。

## 分组/子图/阶段说明
图中包含一个名为 "Agent Team" 的子图，该子图包含四个 Agent 节点：Support Bot、Research Bot、Content Writer 和 Billing Bot。

## 节点逐项说明
- **USER (用户)**：代表发起请求的用户，是整个流程的起点和终点。
- **TEAM (Agent 团队)**：一个包含多个 Agent 的子图，代表一个协作完成任务的 Agent 群体。根据 `docs/11-agent-teams.md`，Agent 团队由一个 lead agent 和多个 member agent 组成，通过共享任务版和邮箱进行协作。
- **SUPPORT (Support Bot)**：支持机器人，使用 Claude Haiku 模型，作为整个流程的入口和出口，负责接收用户请求、协调其他 Agent 的工作，并将最终答案返回给用户。
- **RESEARCH (Research Bot)**：研究机器人，使用 GPT-4 模型，负责进行竞争对手定价的研究工作。
- **WRITER (Content Writer)**：内容撰写机器人，使用 Claude Sonnet 模型，负责根据研究结果撰写相关内容。
- **BILLING (Billing Bot)**：账单机器人，使用 Gemini 模型，可能负责处理与账单相关的任务，但在此流程中与其它 Agent 没有直接关联。

## 连线、分支与汇聚关系
- `USER -> SUPPORT`：用户发起 "Research competitor pricing" 的请求，该请求首先到达支持机器人。
- `SUPPORT -> RESEARCH`：支持机器人将研究任务同步（sync）地委托给研究机器人，需要等待研究机器人完成任务并返回结果。
- `RESEARCH -> SUPPORT`：研究机器人完成研究后，将 "result" 返回给支持机器人。
- `SUPPORT -> WRITER`：支持机器人将内容撰写任务异步（async）地委托给内容撰写机器人，不需要等待内容撰写机器人完成任务。
- `WRITER -.-> SUPPORT`：内容撰写机器人完成撰写后，"announce when done"（通知完成）给支持机器人。
- `SUPPORT -> USER`：支持机器人将 "final answer"（最终答案）返回给用户。
- `SUPPORT -.-x BILLING`：账单机器人与其它 Agent 没有直接的连接。

## 仓库语境与术语解释
- **Agent Team**：根据 `docs/11-agent-teams.md`，Agent 团队由一个 lead agent 和多个 member agent 组成，通过共享任务版和邮箱进行协作。
- **LLM Providers**：GoClaw 支持多种 LLM 提供商，包括 Anthropic、OpenAI、Gemini 等。`README.md` 中提到支持 13+ LLM Providers。
- **Claude Haiku / GPT-4 / Claude Sonnet / Gemini**：这些是不同的 LLM 模型，分别由 Anthropic 和 Google 提供。`README.md` 中提到了 GoClaw 支持这些 LLM 提供商。
- **sync / async**：表示 Agent 之间任务委托的同步和异步方式。同步委托需要等待被委托 Agent 完成任务并返回结果，而异步委托不需要等待。
- **Delegation**：`internal/tools/delegate.go` 定义了 DelegationTask 结构体，用于跟踪 active delegation 的并发控制和取消。
- **Agent**: `internal/agent/types.go` 定义了 Agent 接口，是 AI agent 执行循环的核心抽象。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起 "Research competitor pricing" 请求，Support Bot 接收请求并同步委托给 Research Bot，Research Bot 返回结果给 Support Bot，Support Bot 异步委托给 Content Writer，Content Writer 完成后通知 Support Bot，Support Bot 将最终答案返回给用户。其中，Support Bot 使用 Claude Haiku 模型，Research Bot 使用 GPT-4 模型，Content Writer 使用 Claude Sonnet 模型，Billing Bot 使用 Gemini 模型，但 Billing Bot 在此流程中没有直接关联。整个流程展示了 Agent 团队如何通过协作完成复杂的任务。`docs/11-agent-teams.md` 描述了 Agent 团队的协作模式。
