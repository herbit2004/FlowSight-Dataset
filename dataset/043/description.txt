## Diagram Type & Purpose
This is a flowchart diagram illustrating the end-to-end flow of an e-commerce application, from user login to order processing and error handling. It depicts the sequence of user interactions, API calls, service layer operations, and database interactions involved in the application. The diagram serves as a high-level overview of the system architecture and the flow of data between different components.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is hierarchically structured, with distinct subgraphs representing different stages of the e-commerce flow. The start node is "User Opens App," and the end nodes include "Order Confirmation," "Out of Stock Error," "Payment Failed," "Error Logs," and "Error Toast Notification."

## Subgraphs / Stages
The diagram contains the following subgraphs:
- **Authentication System**: Handles user login and authentication.
- **E-Commerce Flow**: Covers product browsing, adding to cart, and checkout.
- **Checkout Processing**: Manages order creation, inventory check, payment processing, and order confirmation.
- **Error Management**: Deals with error handling and logging.
- **Product Search**: Implements the product search functionality.

## Edges, Branches & Convergence
- `APP_Start --> AUTH_Check`: User opens the app, initiating the authentication check.
- `AUTH_Check -- No --> UI_LoginPage`: If the user is not logged in, redirect to the login page.
- `UI_LoginPage --> UI_LoginForm`: The login page displays the login form.
- `UI_LoginForm --> API_Login`: User submits the login form, triggering the login API call.
- `API_Login --> SVC_AuthValidator`: The login API call invokes the authentication validator service.
- `SVC_AuthValidator --> DB_Users`: The authentication validator service queries the users database.
- `DB_Users --> LoginResult`: The users database returns the user credentials for validation.
- `LoginResult -- No --> UI_LoginError`: If the credentials are invalid, display a login error.
- `LoginResult -- Yes --> SVC_TokenGenerator`: If the credentials are valid, generate an authentication token.
- `SVC_TokenGenerator --> API_Login`: The token generator returns the token to the login API.
- `API_Login -- Success --> STATE_UserSession`: Upon successful login, store the user session.
- `AUTH_Check -- Yes --> UI_Dashboard`: If the user is already logged in, redirect to the dashboard.
- `STATE_UserSession --> UI_Dashboard`: After storing the user session, redirect to the dashboard.
- `UI_Dashboard --> UI_ProductGrid`: The dashboard displays the product grid.
- `UI_ProductGrid --> UI_ProductCard`: The product grid displays individual product cards.
- `UI_ProductCard --> UI_ProductModal`: User selects "View Details" on a product card, opening the product details modal.
- `UI_ProductCard --> STATE_CartManager`: User selects "Quick Add" on a product card, adding the product to the cart.
- `UI_ProductModal --> STATE_CartManager`: User selects "Add to Cart" on the product details modal, adding the product to the cart.
- `STATE_CartManager --> UI_CartIcon`: The cart state manager updates the cart icon badge.
- `UI_CartIcon --> UI_CartDrawer`: User clicks on the cart icon badge, opening the shopping cart drawer.
- `UI_CartDrawer --> UI_CheckoutFlow`: User selects "Checkout" in the shopping cart drawer, navigating to the checkout page.
- `UI_CheckoutFlow --> API_CreateOrder`: User submits the checkout form, triggering the order creation API call.
- `API_CreateOrder --> SVC_OrderProcessor`: The order creation API call invokes the order processor service.
- `SVC_OrderProcessor --> SVC_InventoryCheck`: The order processor service invokes the inventory check service.
- `SVC_InventoryCheck --> DB_Inventory`: The inventory check service queries the inventory database.
- `DB_Inventory --> StockCheck`: The inventory database returns the inventory information.
- `StockCheck -- No --> UI_StockError`: If the items are out of stock, display an out-of-stock error.
- `StockCheck -- Yes --> SVC_PaymentGateway`: If the items are in stock, invoke the payment gateway service.
- `SVC_PaymentGateway --> EXT_Stripe`: The payment gateway service calls the Stripe API.
- `EXT_Stripe --> PaymentResult`: The Stripe API returns the payment result.
- `PaymentResult -- No --> UI_PaymentError`: If the payment fails, display a payment failure message.
- `PaymentResult -- Yes --> DB_Orders`: If the payment is successful, store the order in the orders database.
- `DB_Orders --> SVC_EmailService`: After storing the order, invoke the email service.
- `SVC_EmailService --> EXT_SendGrid`: The email service calls the SendGrid API.
- `DB_Orders --> UI_OrderSuccess`: After storing the order, display an order confirmation message.
- `API_Login --> UI_ErrorToast`: If an error occurs during login, display an error toast notification.
- `API_CreateOrder --> UI_ErrorToast`: If an error occurs during order creation, display an error toast notification.
- `EXT_Stripe --> UI_ErrorToast`: If an error occurs during payment processing, display an error toast notification.
- `EXT_SendGrid --> SVC_ErrorLogger`: If an error occurs during email sending, log the error.
- `SVC_ErrorLogger --> DB_ErrorLogs`: The error logger service stores the error logs in the error logs database.
- `UI_Dashboard --> UI_SearchBar`: The dashboard displays the search bar.
- `UI_SearchBar --> SVC_SearchDebounce`: User types in the search bar, triggering the debounce service.
- `SVC_SearchDebounce --> API_Search`: After a 300ms debounce, call the search API.
- `API_Search --> SVC_SearchEngine`: The search API invokes the search engine service.
- `SVC_SearchEngine --> DB_Products`: The search engine service queries the products database.
- `DB_Products --> UI_SearchResults`: The products database returns the search results.
- `UI_SearchResults --> UI_ProductModal`: User selects a search result, opening the product details modal.
