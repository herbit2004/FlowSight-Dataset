## 图类型与用途
这是一个流程图，描述了基于 Git 的代码仓库中，代码提交（Push）、拉取请求（Pull Request）和分支删除（Delete Branch）如何触发不同的部署流程。它展示了这些操作与生产环境、预发布环境（Staging）和临时环境（Ephemeral Deployment）之间的关系。

## 图的整体布局
图整体采用从左到右的布局，分为三个主要流程，分别用 subgraph 框出：Push, Pull Request, Cleanup。每个流程内部采用从上到下的布局。

## 分组/子图/阶段说明
- **Push**：表示代码推送事件的处理流程，从判断是否为受保护分支开始，根据不同分支类型进行不同的部署操作。
- **Pull Request**：表示拉取请求事件的处理流程，触发临时环境部署。
- **Cleanup**：表示分支删除事件的处理流程，销毁与该分支相关的临时环境。

## 节点逐项说明
- **A (Push)**：代码推送事件，表示开发者将本地代码推送到远程仓库。
- **D (Is Protected Branch?)**：判断是否为受保护分支的决策节点。受保护分支通常是 `main` 或 `master` 等重要分支。
- **H (Is it the 'main' branch?)**：判断是否为 `main` 分支的决策节点。
- **F1 (Offer Manual Ephemeral Deployment)**：提供手动触发临时环境部署的选项。
- **I1 (Deploy to Production)**：部署到生产环境。
- **I2 (Deploy to Staging)**：部署到预发布环境。
- **J1 (Create GitHub Release)**：创建 GitHub 发布版本。
- **J2 (Deploy Storybook)**：部署 Storybook（UI 组件库）。
- **B (Pull Request)**：拉取请求事件，表示开发者发起合并代码的请求。
- **F (Ephemeral Deployment)**：临时环境部署，用于在拉取请求期间进行代码测试和预览。
- **C (Delete Branch)**：分支删除事件，表示开发者删除一个分支。
- **X (Destroy Deployment Stack)**：销毁部署栈，通常指销毁临时环境。

## 连线、分支与汇聚关系
- `A -> D`：代码推送后，判断是否为受保护分支。
- `D -- Yes --> H`：如果是受保护分支，则判断是否为 `main` 分支。
- `D -- No --> F1`：如果不是受保护分支，则提供手动触发临时环境部署的选项。
- `F1 -.-> F`：手动触发临时环境部署。
- `H -- Yes --> I1`：如果是 `main` 分支，则部署到生产环境。
- `H -- Yes --> J2`：如果是 `main` 分支，则部署 Storybook。
- `H -- No --> I2`：如果不是 `main` 分支，则部署到预发布环境。
- `I1 -> J1`：部署到生产环境后，创建 GitHub 发布版本。
- `I2 -> J1`：部署到预发布环境后，创建 GitHub 发布版本。
- `B -> F`：发起拉取请求时，触发临时环境部署。
- `C -> X`：删除分支时，销毁部署栈。

## 仓库语境与术语解释
- **Ephemeral Deployment**：根据 README 和 `.github/workflows/deploy.yml`，临时环境部署使用 AWS Lambda + Api Gateway。
- **Production / Staging**：根据 `.github/workflows/deploy.yml`，生产环境和预发布环境的部署通过 GitHub Actions 触发 AWS CDK 部署流程。
- **Storybook**：根据 README，该项目使用 Storybook v7 进行组件开发。
- **GitHub Release**：根据 README，该项目使用 semantic-release 实现自动发布管理。
- **AWS CDK**：根据 README，该项目使用 AWS CDK 进行 AWS 部署。
- **RemixDeployment**：根据 `deployment/stacks/EphemeralStack.ts` 和 `deployment/stacks/ProductionStack.ts`，这是一个自定义的 CDK Construct，用于部署 Remix 应用。
- **RemixApiGateway**：根据 `deployment/stacks/EphemeralStack.ts` 和 `deployment/stacks/ProductionStack.ts`，这是一个自定义的 CDK Construct，用于创建 Remix 应用的 API Gateway。
- **Destroy Deployment Stack**：根据 `.github/workflows/ephemeralDestroy.yml`，销毁临时环境通过 GitHub Actions 触发 AWS CDK 销毁流程。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 Trance Stack 项目中，代码变更如何触发不同的部署流程。当代码被推送时，系统会判断是否为受保护分支以及是否为 `main` 分支，从而决定部署到生产环境、预发布环境或提供手动触发临时环境部署的选项。拉取请求会触发临时环境部署，而删除分支则会销毁相应的部署栈。其中，生产环境和预发布环境的部署都涉及到 GitHub Release 的创建，而 `Ephemeral Deployment` 和 `Destroy Deployment Stack` 流程则与临时环境的生命周期管理密切相关。该项目使用 AWS CDK 和 GitHub Actions 实现自动化部署流程。
