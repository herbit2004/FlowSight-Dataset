## 图类型与用途
这是一个流程图，描述了 `vibe-log-cli` 工具如何分析 Claude Code 会话中的用户提示，并提供反馈以改进提示质量。它展示了从用户输入提示到在状态栏显示反馈的整个流程。

## 图的整体布局
图整体采用从左到右的布局。从左侧的“Input”子图开始，经过中间的“Analysis”子图，最终到达右侧的“Display”子图，展示了数据流动的方向。

## 分组/子图/阶段说明
- **Input**：表示用户在 Claude Code 环境中输入和提交提示的阶段。
- **Analysis**：表示使用 Claude Code SDK 在本地进行提示分析的过程，包括检查是否为新会话、注入教练性格、以及使用 SDK 分析提示质量。
- **Personality**：表示注入教练性格的模块，用于影响分析结果的呈现方式，包括 Gordon、Vibe-log 和 Custom 三种性格。
- **Display**：表示将分析结果显示给用户的过程，包括保存分析结果到本地文件，以及在状态栏显示评分和建议。

## 节点逐项说明
- **User**：用户在 Claude Code 中输入提示的地方。
- **Submit**：用户提交提示的操作。
- **Hook**：`UserPromptSubmit` 钩子，在用户提交提示时被触发，用于启动分析流程。
- **CLI**：`Vibe-log CLI` 命令行工具，接收到用户提示。
- **Check**：一个判断节点，检查当前是否是一个新的聊天会话。
- **Context**：如果不是新会话，则包含之前的对话上下文。
- **Direct**：如果是新会话，则直接分析当前提示。
- **Gordon**：一种严厉的教练性格。
- **Vibe**：一种鼓励性的教练性格。
- **Custom**：用户自定义的教练性格。
- **SDK**：Claude SDK，用于分析提示质量的组件。
- **Score**：生成提示的评分和改进建议。
- **Save**：将分析结果保存到本地文件 `~/.vibe-log/analysis`。
- **Status**：状态栏读取分析结果。
- **Show**：在状态栏显示评分和教练性格的建议。
- **Improve**：通过改进提示来获得更好的结果。

## 连线、分支与汇聚关系
- `User -> Submit`：用户输入提示后提交。
- `Submit -> Hook`：提交提示后触发 `UserPromptSubmit` 钩子。
- `Hook -> CLI`：钩子触发后，`Vibe-log CLI` 接收到提示。
- `CLI -> Check`：CLI 接收到提示后，检查是否为新会话。
- `Check -- No --> Context`：如果不是新会话，则包含之前的对话上下文。
- `Check -- Yes --> Direct`：如果是新会话，则直接分析当前提示。
- `Context -> SDK`：包含上下文后，使用 Claude SDK 分析提示质量。
- `Direct -> SDK`：直接分析提示后，使用 Claude SDK 分析提示质量。
- `Gordon -.-> SDK`：Gordon 教练性格影响 Claude SDK 的分析。
- `Vibe -.-> SDK`：Vibe 教练性格影响 Claude SDK 的分析。
- `Custom -.-> SDK`：Custom 教练性格影响 Claude SDK 的分析。
- `SDK -> Score`：Claude SDK 分析后，生成评分和改进建议。
- `Score -> Save`：生成评分和建议后，保存到本地文件。
- `Save -> Status`：保存后，状态栏读取分析结果。
- `Status -> Show`：状态栏显示分析结果。
- `Show -> Improve`：显示结果后，鼓励用户改进提示。

## 仓库语境与术语解释
- **vibe-log-cli**：一个开源命令行工具，用于分析 Claude Code 会话，提取生产力见解并生成报告。
- **Claude Code SDK**：用于在本地分析提示质量的 SDK。
- **UserPromptSubmit hook**：一个钩子，在用户提交提示时被触发，用于启动分析流程。
- **Coach Personality**：影响分析结果呈现方式的教练性格，包括 Gordon（严厉）、Vibe-log（鼓励性）和 Custom（用户自定义）。参考 `src/lib/personality-manager.ts`。
- **Status Line**：Claude Code 的状态栏，用于显示分析结果和建议。参考 `src/commands/statusline.ts`。
- **~/.vibe-log/analysis**：分析结果保存到的本地文件路径。
- **Promotional Tip**：图中未显示，但 `src/lib/prompt-analyzer.ts` 提到会生成一个预生成的推广提示（10% 概率）。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 `vibe-log-cli` 工具分析 Claude Code 提示的流程。用户在 Claude Code 中输入提示并提交后，`UserPromptSubmit` 钩子触发，`vibe-log-cli` 接收提示。工具检查是否为新会话，并选择是否包含之前的对话上下文。然后，根据选择的教练性格（Gordon、Vibe-log 或 Custom），Claude SDK 分析提示质量，生成评分和改进建议，并保存到 `~/.vibe-log/analysis`。最终，分析结果显示在 Claude Code 的状态栏中，鼓励用户改进提示。其中，教练性格的选择和 Claude SDK 的分析是关键环节。
