## Repository Context & Terminology

- **Postgres**: A relational database used for storing structured data.
- **Redis**: An in-memory data structure store, used as a cache and message broker.
- **Schema Composition**: The process of combining multiple GraphQL schemas into a single schema.
- **Schema Validation**: The process of verifying that a GraphQL schema is valid and conforms to the GraphQL specification.

## High-Density QA Ground Truth Summary
The diagram illustrates the flow of GraphQL queries and schema updates within a schema registry system. The process begins with the `federated-gateway`, which receives incoming queries and routes them to either `service A` or `service B`. The gateway also polls the `schema registry` every 10 seconds using a POST request to `/schema/compose`. Both `service A` and `service B` register their schemas in runtime with the central `schema registry`. `Service B` also validates its schema on commit/cli/CI. The `schema registry` then stores these schemas in a `postgres` database and caches queries and logs in `redis`. A `query analyzer` consumes queries from the `graphql-queries topic` and stores update schema hits in the `postgres` database. Schema changes are published to the `graphql-schema-updates topic` via Kafka, and the `federated-gateway` listens for these updates. The system uses Kafka topics for asynchronous communication of queries and schema updates, ensuring loose coupling between components. The `federated-gateway` acts as the central entry point and also as a consumer of schema updates, completing the cycle. The `postgres` and `redis` databases serve as persistent storage for schema information and query data.
