## 图类型与用途
这是一个流程图，描述了工单处理过程中服务级别协议（SLA）的管理流程。该流程图展示了从工单创建到关闭，SLA 规则匹配、计时、超时处理以及升级的各个环节。通过该图可以清晰地了解工单在不同SLA状态下的处理方式。

## 图的整体布局
该图采用从上到下的布局方式。整体流程从“工单创建”开始，经过一系列判断和处理步骤，最终到达“工单关闭”。图中的流程分支和汇聚反映了工单处理的不同路径。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. **SLA 初始化阶段**：包括工单创建、SLA规则匹配、SLA目标设置或默认SLA设置。
2. **SLA 计时与处理阶段**：包括SLA计时开始、判断SLA是否超时、等待处理、判断处理是否完成。
3. **SLA 超时处理与升级阶段**：包括SLA超时处理、判断自动升级规则、自动升级或通知负责人、手动升级判断。

## 节点逐项说明
- **工单创建**：流程的起始节点，表示创建一个新的工单。
- **SLA 规则匹配?**：判断是否存在与该工单匹配的SLA规则。
- **设置 SLA 目标**：如果存在匹配的SLA规则，则设置相应的SLA目标。
- **默认 SLA 设置**：如果没有匹配的SLA规则，则使用默认的SLA设置。
- **SLA 计时开始**：开始对工单的处理时间进行计时。
- **SLA 是否超时?**：判断工单的处理是否超过了设定的SLA时间。
- **等待处理**：工单在处理过程中，等待相关人员进行处理。
- **处理完成?**：判断工单是否已经完成处理。
- **SLA 计时停止**：当工单处理完成后，停止SLA计时。
- **工单关闭**：流程的结束节点，表示工单已完成处理并关闭。
- **SLA 超时处理**：如果SLA超时，则进入超时处理流程。
- **自动升级规则?**：判断是否存在自动升级规则。
- **自动升级**：根据自动升级规则，自动提升工单的优先级或分配给更高级别的处理人员。
- **通知升级后负责人**：通知升级后的负责人，告知工单已升级。
- **通知当前负责人**：通知当前负责人，告知工单SLA已超时。
- **手动升级判断**：由当前负责人手动判断是否需要升级工单。
- **是否升级?**：判断是否需要手动升级工单。
- **继续等待处理**：如果不需要升级，则继续等待处理。

## 连线、分支与汇聚关系
- A -> B：工单创建后，进入SLA规则匹配判断。
- B -- 是 --> C：如果SLA规则匹配，则设置SLA目标。
- B -- 否 --> D：如果SLA规则不匹配，则使用默认SLA设置。
- C -> E：设置SLA目标后，SLA计时开始。
- D -> E：使用默认SLA设置后，SLA计时开始。
- E -> F：SLA计时开始后，判断SLA是否超时。
- F -- 否 --> G：如果SLA未超时，则进入等待处理状态。
- G -> H：等待处理后，判断处理是否完成。
- H -- 是 --> I：如果处理完成，则SLA计时停止。
- I -> J：SLA计时停止后，工单关闭。
- H -- 否 --> F：如果处理未完成，则返回判断SLA是否超时。
- F -- 是 --> K：如果SLA超时，则进入SLA超时处理。
- K -> L：SLA超时处理后，判断是否存在自动升级规则。
- L -- 是 --> M：如果存在自动升级规则，则自动升级。
- M -> N：自动升级后，通知升级后负责人。
- L -- 否 --> O：如果不存在自动升级规则，则通知当前负责人。
- O -> P：通知当前负责人后，进行手动升级判断。
- P -> Q：手动升级判断后，判断是否升级。
- Q -- 是 --> M：如果需要升级，则自动升级。
- Q -- 否 --> R：如果不需要升级，则继续等待处理。
- N -> H：通知升级后负责人后，返回判断处理是否完成。
- R -> H：继续等待处理后，返回判断处理是否完成。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **工单**：指用户提交的问题或请求，需要在系统中进行处理的任务。
- **SLA（Service Level Agreement）**：服务级别协议，定义了服务提供商对客户提供的服务质量和可用性的承诺。
- **SLA 目标**：SLA中规定的具体服务指标，例如响应时间、解决时间等。
- **SLA 超时**：指工单的处理时间超过了SLA规定的时间。
- **自动升级**：指根据预设规则，自动提升工单的优先级或分配给更高级别的处理人员。
- **手动升级**：指由人工判断并决定是否需要提升工单的优先级或分配给更高级别的处理人员。

## 可作为 QA Ground Truth 的高信息密度摘要
工单创建后，系统判断是否存在匹配的SLA规则，若有则设置SLA目标，否则使用默认SLA设置。SLA计时开始后，系统判断SLA是否超时。若未超时，则进入等待处理状态，直到处理完成或SLA超时。若SLA超时，则进行超时处理，判断是否存在自动升级规则，若有则自动升级并通知升级后负责人，否则通知当前负责人进行手动升级判断。最终，工单处理完成后，SLA计时停止，工单关闭。
