## High-Density QA Ground Truth Summary
The transform pipeline begins with the CacheAligner stabilizing the prefix for the KV cache. This is followed by the ContentRouter, which detects the content type and selects a compressor. Based on the content type, the ContentRouter dispatches to either the SmartCrusher for JSON data, the CodeCompressor for AST-aware code, or LLMLingua for ML-based text. The IntelligentContext then performs score-based token fitting, and the Query Echo re-injects the user question. The user question is then passed to the LLM Provider. If the LLM Provider requires additional information, it retrieves data from the Compress-Cache-Retrieve (CCR) component using the headroom_retrieve tool. The SmartCrusher stores the original data and a summary of what's omitted in the Compressed Store. The CCR component acts as a cache, providing compressed data to the LLM Provider when needed, optimizing performance and reducing the amount of data that needs to be processed by the LLM. The pipeline concludes with the LLM Provider having the necessary information to fulfill the user's request.
