## 图类型与用途
该图是一个流程图，描述了微服务架构中的服务注册与发现以及服务调用的两个主要流程。它展示了服务实例如何注册到注册中心，以及客户端如何发现并调用服务。该图有助于理解微服务架构中的服务治理机制。

## 图的整体布局
该图采用从左到右的布局，分为上下两个子图。上半部分描述服务注册与发现流程，下半部分描述服务调用流程。整体流程从服务实例启动或客户端发起请求开始，最终返回结果或错误。

## 分组/子图/阶段说明
图中包含两个子图：
- **服务注册与发现**：描述服务实例如何注册到注册中心，并保持心跳，以便注册中心能够监控服务实例的健康状态。
- **服务调用**：描述客户端如何通过服务发现找到可用的服务实例，并进行负载均衡选择，最终发起调用并处理调用结果。

## 节点逐项说明
- **A[服务实例启动]**：服务实例启动的起始节点。
- **B{是否已注册?}**：判断服务实例是否已经注册的决策节点。
- **C[心跳保活]**：服务实例定期向注册中心发送心跳，保持注册状态。
- **D[请求注册中心]**：服务实例向注册中心发起注册请求。
- **E[注册成功]**：服务实例成功注册到注册中心。
- **F{心跳正常?}**：判断服务实例心跳是否正常的决策节点。
- **G[上报异常]**：服务实例心跳异常，向注册中心上报异常。
- **H[触发熔断/降级]**：注册中心根据服务实例的异常状态，触发熔断或降级策略。
- **I[客户端发起请求]**：客户端发起服务调用请求的起始节点。
- **J[服务发现]**：客户端通过服务发现机制查找可用的服务实例。
- **K{可用实例列表?}**：判断是否存在可用服务实例的决策节点。
- **L[返回错误]**：没有可用服务实例，返回错误信息。
- **M[负载均衡选择实例]**：从可用的服务实例列表中选择一个实例进行调用。
- **N[发起调用]**：客户端向选择的服务实例发起调用。
- **O{调用成功?}**：判断服务调用是否成功的决策节点。
- **P[返回结果]**：服务调用成功，返回结果。
- **Q[重试/降级]**：服务调用失败，进行重试或降级处理。
- **R[返回错误]**：服务调用失败，返回错误信息。

## 连线、分支与汇聚关系
- A -> B：服务实例启动后，进入是否已注册的判断。
- B -- 是 --> C：如果已注册，则进行心跳保活。
- B -- 否 --> D：如果未注册，则请求注册中心。
- D -> E：请求注册中心后，注册成功。
- E -> C：注册成功后，进行心跳保活。
- C -> F：心跳保活后，进入心跳是否正常的判断。
- F -- 是 --> C：心跳正常，继续心跳保活。
- F -- 否 --> G：心跳异常，上报异常。
- G -> H：上报异常后，触发熔断/降级。
- I -> J：客户端发起请求后，进行服务发现。
- J -> K：服务发现后，进入可用实例列表的判断。
- K -- 否 --> L：没有可用实例，返回错误。
- K -- 是 --> M：有可用实例，进行负载均衡选择实例。
- M -> N：负载均衡选择实例后，发起调用。
- N -> O：发起调用后，进入调用是否成功的判断。
- O -- 是 --> P：调用成功，返回结果。
- O -- 否 --> Q：调用失败，进行重试/降级。
- Q -> R：重试/降级后，返回错误。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **服务注册**：服务实例向注册中心注册自己的信息，包括IP地址、端口号等。
- **服务发现**：客户端通过注册中心查找可用的服务实例。
- **心跳保活**：服务实例定期向注册中心发送心跳，表明自己仍然可用。
- **熔断**：当服务实例出现故障时，停止向该实例发送请求，避免雪崩效应。
- **降级**：当服务实例出现故障时，提供备用方案，保证服务可用性。
- **负载均衡**：将请求分发到多个服务实例上，提高系统的吞吐量和可用性。
- **重试**：当服务调用失败时，重新发起调用，提高调用成功率。

## 可作为 QA Ground Truth 的高信息密度摘要
服务实例启动后，首先判断是否已注册。若未注册，则向注册中心请求注册，注册成功后进行心跳保活。若已注册，则直接进行心跳保活。心跳正常则继续保活，否则上报异常，触发熔断/降级。客户端发起请求后，进行服务发现，若有可用实例，则通过负载均衡选择实例并发起调用。调用成功则返回结果，否则进行重试/降级，最终返回错误。若服务发现没有可用实例，则直接返回错误。
