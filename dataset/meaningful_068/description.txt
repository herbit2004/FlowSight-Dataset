## 图类型与用途
这是一个流程图，描述了用户填写表单后，客户端和服务器端对表单数据进行校验，最终完成数据持久化的过程。该图展示了表单校验的完整流程，包括客户端校验、服务器端校验以及错误处理机制。

## 图的整体布局
该图采用从上到下的布局方式。流程从用户填写表单开始，经过客户端和服务端校验，最终完成数据持久化并结束。

## 连线、分支与汇聚关系
- A -> B: 用户填写表单后，进入客户端校验判断。
- B -- 是 --> C: 如果需要客户端校验，则进入客户端校验器。
- B -- 否 --> D: 如果不需要客户端校验，则跳过客户端校验。
- C -> E: 客户端校验器执行校验后，进入校验成功判断。
- E -- 是 --> F: 如果客户端校验成功，则进行表单数据预处理。
- E -- 否 --> G: 如果客户端校验失败，则显示客户端错误信息。
- G -> A: 显示客户端错误信息后，返回用户填写表单。
- F -> H: 表单数据预处理后，提交请求至服务器。
- D -> H: 跳过客户端校验后，提交请求至服务器。
- H -> I: 提交请求至服务器后，进入服务器端校验判断。
- I -- 是 --> J: 如果需要服务器端校验，则进入服务器端校验器。
- I -- 否 --> K: 如果不需要服务器端校验，则跳过服务器端校验。
- J -> L: 服务器端校验器执行校验后，进入校验成功判断。
- L -- 是 --> M: 如果服务器端校验成功，则进行数据持久化。
- L -- 否 --> N: 如果服务器端校验失败，则返回服务器端错误信息。
- N -> A: 返回服务器端错误信息后，返回用户填写表单。
- K -> M: 跳过服务器端校验后，进行数据持久化。
- M -> O: 数据持久化后，发送成功通知。
- O -> P: 发送成功通知后，流程结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **客户端校验**: 在用户浏览器端进行的表单数据验证，可以快速反馈错误，提升用户体验。
- **服务器端校验**: 在服务器端进行的表单数据验证，可以确保数据的安全性和完整性。
- **数据持久化**: 将数据保存到数据库或文件系统中，以便长期存储和使用。
- **表单数据预处理**: 在提交到服务器之前，对表单数据进行格式化、清洗等操作。
- **错误信息**: 指校验失败时返回给用户的提示信息，用于指导用户修改输入。

## 可作为 QA Ground Truth 的高信息密度摘要
用户填写表单后，系统判断是否需要进行客户端校验。如果需要，则执行客户端校验，校验成功后进行表单数据预处理，否则跳过客户端校验直接进行表单数据预处理。预处理后，提交请求至服务器，服务器判断是否需要进行服务器端校验。如果需要，则执行服务器端校验，校验成功后进行数据持久化，否则跳过服务器端校验直接进行数据持久化。数据持久化后，发送成功通知，流程结束。如果客户端或服务器端校验失败，则返回相应的错误信息给用户，用户重新填写表单。
