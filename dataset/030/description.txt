## 图类型与用途
这是一个流程图，描述了 AI 驱动的游戏开发团队的工作流程，从用户提出游戏想法开始，经过市场分析、不同开发模式的选择、团队协作开发、数据分析与优化，最终到游戏发布和持续优化的整个过程。该图在仓库中用于概括整个 AI 辅助游戏开发系统的工作流程。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户输入和项目初始化阶段，中间是开发模式选择和并行开发阶段，底部是游戏发布和持续优化阶段。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分成以下几个阶段：
- **市场分析阶段**：评估游戏创意的可行性，由 Market Analyst Agent 负责。
- **项目初始化阶段**：由 Master Orchestrator 负责，选择开发模式。
- **并行开发阶段**：由不同的开发团队和 Agent 协作完成。
- **持续优化阶段**：收集数据并进行分析，最终发布游戏并进行持续优化。

## 节点逐项说明
- **A (User: Game Idea)**：用户提出的游戏创意，是整个流程的起点。
- **B (Initialize Project)**：初始化项目，为后续开发做准备。
- **C (Market Analysis Phase)**：市场分析阶段，评估游戏创意的可行性。
- **D (Market Analyst Agent)**：市场分析师 Agent，负责市场分析工作。根据 `agents/market_analyst.md`，该 Agent 负责提供市场洞察、竞品分析和数据驱动的建议。
- **E (Competitive Research)**：竞品研究，分析市场上类似游戏的优劣势。
- **F (Market Sizing)**：市场规模评估，预测游戏潜在的市场容量。
- **G (Target Audience Analysis)**：目标受众分析，了解目标玩家的喜好和需求。
- **H (Go/No-Go Decision)**：根据市场分析结果，决定是否继续进行项目。
- **I (Pivot or Stop)**：如果市场分析结果不理想，则调整游戏创意或停止项目。
- **J (Master Orchestrator)**：主协调者，负责协调整个开发流程。根据 `agents/master_orchestrator.md`，该 Agent 负责项目初始化、Agent 管理和工作流编排。
- **K (Development Mode?)**：选择开发模式，包括设计模式、原型模式和完整开发模式。
- **L (Design Team)**：设计团队，负责游戏的设计工作。
- **M (Prototype Team)**：原型团队，负责制作游戏原型。
- **N (Full Team)**：完整团队，负责游戏的完整开发。
- **O (Producer Agent Coordination)**：制片人 Agent 协调，协调不同团队的工作。根据 `agents/producer_agent.md`，该 Agent 负责项目初始化和生产管理。
- **P (Data Scientist Setup)**：数据科学家设置，为后续的数据分析做准备。
- **Q (Analytics Framework)**：分析框架，用于收集和分析游戏数据。
- **R (Telemetry Planning)**：遥测规划，规划需要收集的游戏数据。
- **S (A/B Testing Design)**：A/B 测试设计，设计用于优化游戏体验的 A/B 测试。
- **T (Parallel Development)**：并行开发，多个角色同时进行开发工作。
- **U (Sr Game Designer)**：高级游戏设计师。
- **V (Mid Game Designer)**：中级游戏设计师。
- **W (Mechanics Developer)**：机制开发者。
- **X (Game Feel Developer)**：游戏感觉开发者。
- **Y (Sr Game Artist)**：高级游戏美术师。
- **Z (Technical Artist)**：技术美术师。
- **AA (UI/UX Agent)**：UI/UX Agent。
- **BB (QA Agent)**：QA Agent。根据 `agents/qa_agent.md`，该 Agent 负责质量保证和测试。
- **CC (Continuous Data Collection)**：持续数据收集，收集游戏数据。
- **DD (Data Scientist Analysis)**：数据科学家分析，分析收集到的游戏数据。根据 `agents/data_scientist.md`，该 Agent 负责分析、指标和预测建模。
- **EE (Market Analyst Validation)**：市场分析师验证，验证数据分析结果。
- **FF (Producer Agent Optimization)**：制片人 Agent 优化，根据数据分析结果优化游戏。
- **GG (Milestone Complete?)**：里程碑是否完成的判断节点。
- **HH (Next Phase)**：进入下一个阶段。
- **II (Final Release?)**：是否最终发布的判断节点。
- **JJ (Launch with Data Monitoring)**：发布游戏并进行数据监控。
- **KK (Post-Launch Analytics)**：发布后分析。
- **LL (Continuous Optimization)**：持续优化。

## 连线、分支与汇聚关系
- `A -> B`：用户提出游戏创意后，初始化项目。
- `B -> C`：项目初始化后，进入市场分析阶段。
- `C -> D`：市场分析阶段由 Market Analyst Agent 负责。
- `D -> E`：Market Analyst Agent 进行竞品研究。
- `D -> F`：Market Analyst Agent 进行市场规模评估。
- `D -> G`：Market Analyst Agent 进行目标受众分析。
- `E -> H`：竞品研究的结果影响 Go/No-Go Decision。
- `F -> H`：市场规模评估的结果影响 Go/No-Go Decision。
- `G -> H`：目标受众分析的结果影响 Go/No-Go Decision。
- `H -- No Go --> I`：如果市场分析结果不理想，则调整游戏创意或停止项目。
- `H -- Go --> J`：如果市场分析结果理想，则由 Master Orchestrator 负责后续流程。
- `J -> K`：Master Orchestrator 根据项目需求选择开发模式。
- `K -- Design Mode --> L`：选择设计模式，由 Design Team 负责。
- `K -- Prototype Mode --> M`：选择原型模式，由 Prototype Team 负责。
- `K -- Development Mode --> N`：选择完整开发模式，由 Full Team 负责。
- `L -> O`：Design Team 的工作由 Producer Agent Coordination 协调。
- `M -> O`：Prototype Team 的工作由 Producer Agent Coordination 协调。
- `N -> O`：Full Team 的工作由 Producer Agent Coordination 协调。
- `O -> P`：Producer Agent Coordination 后，进行 Data Scientist Setup。
- `P -> Q`：Data Scientist Setup 后，建立 Analytics Framework。
- `P -> R`：Data Scientist Setup 后，进行 Telemetry Planning。
- `P -> S`：Data Scientist Setup 后，进行 A/B Testing Design。
- `Q -> T`：Analytics Framework 为 Parallel Development 提供支持。
- `R -> T`：Telemetry Planning 为 Parallel Development 提供支持。
- `S -> T`：A/B Testing Design 为 Parallel Development 提供支持。
- `T -> U`：Parallel Development 阶段，Sr Game Designer 参与开发。
- `T -> V`：Parallel Development 阶段，Mid Game Designer 参与开发。
- `T -> W`：Parallel Development 阶段，Mechanics Developer 参与开发。
- `T -> X`：Parallel Development 阶段，Game Feel Developer 参与开发。
- `T -> Y`：Parallel Development 阶段，Sr Game Artist 参与开发。
- `T -> Z`：Parallel Development 阶段，Technical Artist 参与开发。
- `T -> AA`：Parallel Development 阶段，UI/UX Agent 参与开发。
- `T -> BB`：Parallel Development 阶段，QA Agent 参与开发。
- `U -> CC`：Sr Game Designer 的工作产生 Continuous Data Collection。
- `V -> CC`：Mid Game Designer 的工作产生 Continuous Data Collection。
- `W -> CC`：Mechanics Developer 的工作产生 Continuous Data Collection。
- `X -> CC`：Game Feel Developer 的工作产生 Continuous Data Collection。
- `Y -> CC`：Sr Game Artist 的工作产生 Continuous Data Collection。
- `Z -> CC`：Technical Artist 的工作产生 Continuous Data Collection。
- `AA -> CC`：UI/UX Agent 的工作产生 Continuous Data Collection。
- `BB -> CC`：QA Agent 的工作产生 Continuous Data Collection。
- `CC -> DD`：Continuous Data Collection 后，进行 Data Scientist Analysis。
- `DD -> EE`：Data Scientist Analysis 后，进行 Market Analyst Validation。
- `EE -> FF`：Market Analyst Validation 后，进行 Producer Agent Optimization。
- `FF -> GG`：Producer Agent Optimization 后，判断 Milestone Complete?
- `GG -- No --> T`：如果里程碑未完成，则返回 Parallel Development 阶段。
- `GG -- Yes --> HH`：如果里程碑已完成，则进入 Next Phase。
- `HH -> II`：进入 Next Phase 后，判断 Final Release?
- `II -- No --> T`：如果未最终发布，则返回 Parallel Development 阶段。
- `II -- Yes --> JJ`：如果最终发布，则 Launch with Data Monitoring。
- `JJ -> KK`：Launch with Data Monitoring 后，进行 Post-Launch Analytics。
- `KK -> LL`：Post-Launch Analytics 后，进行 Continuous Optimization。

## 仓库语境与术语解释
- **Agent**：指 AI 驱动的游戏开发团队中的各个角色，例如 Market Analyst Agent、Producer Agent 等。每个 Agent 负责特定的任务和职责。
- **Master Orchestrator**：系统协调者和项目初始化者，负责整个 Agent 生态系统的初始化、协调和管理。
- **Producer Agent**：项目经理，负责管理项目执行、验证交付物，并确保游戏开发成功。
- **Market Analyst Agent**：负责提供市场洞察、竞品分析和数据驱动的建议，以确保项目可行性和成功。
