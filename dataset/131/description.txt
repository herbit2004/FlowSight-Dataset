## 节点逐项说明
- **ElatoAI (repo)**：代表整个 ElatoAI 项目的仓库或核心。它是整个架构的起点。
- **Frontend Vercel NextJS (frontend)**：表示使用 Vercel 部署的 Next.js 前端应用程序。它是用户与系统交互的界面。
- **Deno Edge Function (deno)**：表示使用 Deno 编写的边缘函数。边缘函数通常用于处理请求、验证和路由，靠近用户以减少延迟。
- **ESP32 Arduino Client (esp32)**：表示运行在 ESP32 微控制器上的 Arduino 客户端。这可能是嵌入式设备或物联网设备，负责采集数据或执行某些操作。
- **Supabase DB (supabase)**：表示 Supabase 数据库。用于存储和管理应用程序的数据。
- **Secure WebSockets (websockets)**：表示安全 WebSockets 连接，用于 ESP32 和后端之间的实时通信。
- **Opus Codec (opus)**：表示 Opus 音频编解码器，用于压缩和解压缩音频数据。
- **arduino-audio-tools (audio_tools)**：表示 Arduino 音频工具库，用于处理音频相关的任务。
- **arduino-libopus (libopus)**：表示 Arduino 的 libopus 库，用于在 Arduino 环境中使用 Opus 编解码器。
- **ESPAsyncWebServer (ESPAsyncWebServer)**：表示 ESP32 上的异步 Web 服务器库，用于处理 HTTP 请求。

## 仓库语境与术语解释
- **ElatoAI**: 这是一个使用 ESP32 和 Deno Edge Functions 实现实时语音 AI 模型的项目，支持 OpenAI, Gemini, Grok, Eleven Labs 和 Hume AI 等多种 AI 语音模型。
- **Frontend Vercel NextJS**: 前端客户端，使用 Next.js 框架，托管在 Vercel 上，用于创建和与 AI agents 交互，并将指令发送到 ESP32 设备。
- **Deno Edge Function**: 边缘服务器功能，使用 Deno 编写，运行在 Deno/Supabase Edge 上，用于处理来自 ESP32 设备的 WebSocket 连接以及 LLM Provider API 调用。
- **ESP32 Arduino Client**: 物联网客户端，使用 PlatformIO/Arduino 框架，运行在 ESP32-S3 上，用于接收来自边缘服务器功能的 WebSocket 连接，并将音频发送到 LLM Provider。
- **Supabase DB**: 用于存储用户数据、设备信息、对话历史记录等。
- **Secure WebSockets**: 用于 ESP32 客户端和 Deno Edge Function 之间的安全通信，保证数据传输的加密和可靠性。
- **Opus Codec**: 用于压缩和解压缩音频数据，以减少带宽占用并提高音频传输效率。
- **arduino-audio-tools & arduino-libopus**: Arduino 的音频处理库，用于在 ESP32 上进行音频相关的任务，例如音频采集、处理和播放。
- **ESPAsyncWebServer**: ESP32 上的异步 Web 服务器库，用于处理 HTTP 请求，例如 OTA 更新和设备配置。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 ElatoAI 项目的核心组件及其关系。项目从 ElatoAI 仓库开始，分为三个主要分支：Frontend Vercel NextJS 前端应用，Deno Edge Function 边缘函数，以及 ESP32 Arduino Client 客户端。前端和边缘函数都与 Supabase DB 数据库交互。ESP32 客户端通过 Secure WebSockets 与边缘函数通信，并使用 Opus Codec 进行音频编解码，同时依赖 arduino-audio-tools 和 arduino-libopus 进行音频处理，以及 ESPAsyncWebServer 处理 HTTP 请求。整体架构体现了“云-边-端”协同的特点，其中 Deno Edge Function 负责连接云端 AI 模型和设备端，实现实时语音交互。
