## Edges, Branches & Convergence
- `Telemetry Sensor --> Data Formatting`: Telemetry data flows from the sensor to the data formatting component.
- `Data Formatting --> API Gateway`: Formatted telemetry data is sent to the API Gateway.
- `API Gateway --> Authentication`: API Gateway forwards the request to the Authentication service.
- `Authentication -- Valid User --> Traffic Shaping`: If the user is authenticated, the request is passed to traffic shaping.
- `Authentication -- Invalid User --> Reject Request`: If the user is not authenticated, the request is rejected.
- `Traffic Shaping --> Message Queue`: Traffic shaping forwards the request to the message queue.
- `Message Queue --> Telemetry Ingestion`: The message queue forwards the request to telemetry ingestion.
- `Telemetry Ingestion --> Data Store`: Telemetry data is stored in the data store.
- `Telemetry Ingestion -- Threshold Exceeded --> Alerting Engine`: If a threshold is exceeded, an alert is triggered.
- `Alerting Engine --> Escalation Policy`: The alerting engine triggers the escalation policy.
- `Escalation Policy -- Notify Ops --> PagerDuty`: If the escalation policy requires notification, PagerDuty is notified.
- `Escalation Policy -- Log Only --> Data Store`: If the escalation policy requires logging only, the event is logged to the data store.
- `API Gateway --> Command Dispatch`: API Gateway forwards the command to the Command Dispatch.
- `Command Dispatch --> Command Type`: Command Dispatch forwards the command to the Command Type decision point.
- `Command Type -- Config Change --> Param Validation`: If the command is a config change, it is passed to parameter validation.
- `Command Type -- Reboot --> Reboot Command`: If the command is a reboot command, it is passed to the reboot command handler.
- `Param Validation -- Valid Param --> Reboot Command`: If the parameters are valid, the command is passed to the reboot command handler.
- `Param Validation -- Invalid Param --> Reject w/ Error`: If the parameters are invalid, the command is rejected with an error.
- `Reboot Command --> Cmd Queue`: The reboot command is added to the command queue.
- `Cmd Queue --> Cmd Router`: The command queue forwards the command to the command router.
- `Cmd Router --> Device Type`: The command router forwards the command to the device type decision point.
- `Device Type -- Sensor --> Device Specific Cmd`: If the device is a sensor, the command is passed to the sensor-specific command handler.
- `Device Type -- Actuator --> Device Specific Cmd`: If the device is an actuator, the command is passed to the actuator-specific command handler.
- `Device Specific Cmd --> Msg Format`: The device-specific command is formatted.
- `Msg Format --> Encrypt & Sign`: The message is encrypted and signed.
- `Encrypt & Sign --> Send to Device`: The message is sent to the device.
- `Send to Device --> Cmd Receive`: The device receives the command.

## High-Density QA Ground Truth Summary
The process begins with either the "Telemetry Sensor" sending data to "Data Formatting" on the IoT Device, or the "API Gateway" receiving a command on the Cloud Platform. For telemetry, formatted data is sent to the API Gateway, then proceeds through "Authentication," "Traffic Shaping," "Message Queue," and "Telemetry Ingestion" before being stored in the "Data Store." If "Threshold Exceeded" is triggered during telemetry ingestion, the "Alerting Engine" initiates an "Escalation Policy," potentially leading to "Notify Ops" via "PagerDuty" or simply logging the event to the "Data Store." For commands, the "API Gateway" forwards the request to "Command Dispatch," which determines the "Command Type." A "Config Change" command proceeds to "Param Validation"; invalid parameters lead to "Reject w/ Error," while valid parameters and "Reboot" commands are enqueued in "Cmd Queue." The "Cmd Router" then determines the "Device Type" (Sensor or Actuator), routing to the appropriate "Device Specific Cmd" handler. The command is then formatted ("Msg Format"), encrypted and signed ("Encrypt & Sign"), and sent ("Send to Device") to the IoT Device, ultimately reaching "Cmd Receive." Authentication failures at the API Gateway result in "Reject Request." The system handles both telemetry data ingestion and command dispatch to IoT devices, with error handling and alerting mechanisms in place.
