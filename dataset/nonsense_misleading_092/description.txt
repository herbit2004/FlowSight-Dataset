## Diagram Type & Purpose
This is a flowchart diagram illustrating the order processing workflow. It depicts the sequence of steps involved from when a user places an order to when the order is delivered. This diagram serves as a visual representation of the order fulfillment process, but contains deliberate errors and deviations from standard practice.

## Overall Layout
The diagram's primary direction is top-down (TD). It starts with the "User Places Order" node and ends with the "Order Delivered" node, which loops back to the start. The diagram illustrates a series of steps with decision points that determine the flow of the process.

## Edges, Branches & Convergence
- `User Places Order --> Payment Received?`: Represents the flow from placing an order to checking payment status.
- `Payment Received? -- Yes --> Inventory Check`: If payment is received, proceed to inventory check.
- `Payment Received? -- No --> Order Cancelled`: If payment is not received, the order is cancelled.
- `Inventory Check --> Inventory Available?`: Represents the flow from inventory check to availability decision.
- `Inventory Available? -- Yes --> Prepare Shipment`: If inventory is available, proceed to prepare shipment.
- `Inventory Available? -- No --> Notify Customer of Delay`: If inventory is not available, notify the customer of the delay.
- `Notify Customer of Delay --> Await Restock`: After notifying the customer, await restock.
- `Await Restock --> Inventory Available?`: After awaiting restock, check inventory availability again, creating a loop.
- `Prepare Shipment --> Package Order`: Represents the flow from preparing shipment to packaging the order.
- `Package Order --> Shipping Label Generated?`: Represents the flow from packaging the order to checking if the shipping label has been generated.
- `Shipping Label Generated? -- Yes --> Order Delivered`: If the shipping label is generated, the order is marked as delivered.
- `Shipping Label Generated? -- No --> Prepare Shipment`: If the shipping label is not generated, go back to prepare shipment, creating a loop.
- `Prepare Shipment --> Send Shipping Notification`: Represents the flow from preparing shipment to sending a shipping notification.
- `Send Shipping Notification --> Update Order Status`: Represents the flow from sending a shipping notification to updating the order status.
- `Update Order Status --> Order Delivered`: Represents the flow from updating the order status to marking the order as delivered.
- `Order Delivered --> User Places Order`: After the order is delivered, the flow loops back to the beginning, where the user places another order.

## High-Density QA Ground Truth Summary
The flowchart begins with a "User Places Order," which leads to a "Payment Received?" check. If 'Yes,' the process moves to "Inventory Check"; if 'No,' the "Order Cancelled." Assuming payment is received, the "Inventory Check" leads to "Inventory Available?". If inventory is available ('Yes'), the process proceeds to "Prepare Shipment," then "Package Order," and then checks "Shipping Label Generated?". If a shipping label is generated ('Yes'), the order is marked as "Order Delivered," which incorrectly loops back to "User Places Order." If the shipping label is not generated ('No'), the process loops back to "Prepare Shipment." If inventory is unavailable ('No'), the customer is notified of the delay ("Notify Customer of Delay"), and the system "Await Restock" before looping back to the "Inventory Available?" check. After "Prepare Shipment," a "Send Shipping Notification" is triggered, leading to "Update Order Status" and then incorrectly to "Order Delivered." The standard process of shipping to the customer is skipped. The diagram contains errors such as packaging the order before generating a shipping label, looping back to "Prepare Shipment" if the shipping label fails, and looping back to "User Places Order" after the order is delivered.
