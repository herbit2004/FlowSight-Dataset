## 图类型与用途
这是一个流程图，描述了 UnityHFSM 中状态转换的逻辑，特别是当当前状态需要退出时间 (Exit Time) 时，状态转换是如何处理的。它用于解释状态机如何判断是否可以立即切换状态，以及如何处理需要延迟切换状态的情况。

## 图的整体布局
图整体采用从上到下的布局。顶部是状态转换的起点，中间是判断和处理退出时间的阶段，底部是状态切换的终点。

## 分组/子图/阶段说明
图中包含一个名为 "Delayed State Change" 的子图，用于描述延迟状态切换的流程。主流程逻辑上可分为三个阶段：状态转换请求、退出时间判断与处理、状态切换。

## 节点逐项说明
- **Transition**：状态转换的起点，表示状态机接收到一个状态转换的请求。
- **Does active state need exit time?**：一个判断节点，检查当前激活状态是否需要退出时间。退出时间通常用于确保状态在切换之前完成某些动画或逻辑。
- **FSM calls activeState.OnExitRequest()**：状态机调用当前激活状态的 `OnExitRequest()` 方法。这个方法是状态用来处理退出请求的。根据 `src/Base/StateBase.cs`，`OnExitRequest()` 在 `needsExitTime` 为 true 时被调用。
- **Does the active state call fsm.StateCanExit()?**：一个判断节点，检查当前激活状态是否调用了 `fsm.StateCanExit()` 方法。这个方法是状态用来通知状态机它是否可以安全退出的。
- **Later in OnLogic / an event / ...**：表示状态机将在稍后的时间点（例如在 `OnLogic` 函数中，或者在某个事件触发时）再次尝试状态切换。
- **fsm.StateCanExit()**：在稍后的时间点，状态机再次调用 `fsm.StateCanExit()` 方法，以检查状态是否可以退出。
- **Change State**：状态转换的终点。表示状态机成功切换到新状态。

## 连线、分支与汇聚关系
- `Transition -> Does active state need exit time?`：状态转换开始时，首先判断当前状态是否需要退出时间。
- `Does active state need exit time? -- No --> Change State`：如果当前状态不需要退出时间，则直接进入状态切换。
- `Does active state need exit time? -- Yes --> FSM calls activeState.OnExitRequest()`：如果当前状态需要退出时间，则进入 `OnExitRequest` 节点，状态机调用当前状态的 `OnExitRequest()` 方法。
- `FSM calls activeState.OnExitRequest() -> Does the active state call fsm.StateCanExit()?`：调用 `OnExitRequest()` 后，判断状态是否调用了 `fsm.StateCanExit()` 方法。
- `Does the active state call fsm.StateCanExit()? -- Yes --> Change State`：如果状态调用了 `fsm.StateCanExit()` 并且返回 `true`，则状态机可以切换到新状态。
- `Does the active state call fsm.StateCanExit()? -- No --> Later in OnLogic / an event / ...`：如果状态没有调用 `fsm.StateCanExit()` 或者返回 `false`，则状态机需要延迟状态切换，进入 "Delayed State Change" 子图。
- `Later in OnLogic / an event / ... -> fsm.StateCanExit()`：在 "Delayed State Change" 子图中，稍后再次调用 `fsm.StateCanExit()` 方法。
- `fsm.StateCanExit() -> Change State`：最终，状态机切换到新状态，形成汇聚关系。

## 仓库语境与术语解释
- **UnityHFSM**：仓库名，表示 Unity 的分层有限状态机。README 描述其为 "A simple yet powerful hierarchical finite state machine for the Unity game engine"。
- **State Machine**：一种用于组织和控制游戏逻辑的方式，尤其适用于具有多种状态的对象。README 提到 "State machines are an amazingly easy way to write and organise game logic"。
- **StateBase**：所有状态的基类。`src/Base/StateBase.cs` 定义了状态的基本属性和方法，例如 `OnEnter`、`OnLogic`、`OnExit` 和 `OnExitRequest`。
- **TransitionBase**：所有转换的基类。`src/Base/TransitionBase.cs` 定义了转换的基本属性和方法，例如 `ShouldTransition`、`BeforeTransition` 和 `AfterTransition`。
- **Exit Time**：状态在切换之前需要完成某些动画或逻辑的时间。
- **OnExitRequest()**：当状态机要从当前状态切换到另一个状态时，会调用当前状态的 `OnExitRequest()` 方法。
- **fsm.StateCanExit()**：状态用来通知状态机它是否可以安全退出的方法。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 UnityHFSM 中状态转换的处理流程，从 `Transition` 开始，首先判断当前状态是否需要退出时间。如果不需要，则直接切换到 `Change State`。如果需要，则调用 `activeState.OnExitRequest()`，然后判断状态是否调用了 `fsm.StateCanExit()`。如果调用了，则切换到 `Change State`；否则，进入 "Delayed State Change" 子图，稍后再次调用 `fsm.StateCanExit()`，最终切换到 `Change State`。其中，`needsExitTime` 和 `fsm.StateCanExit()` 是两个关键的判断条件。该流程与 `src/Base/StateBase.cs` 中 `OnExitRequest()` 的定义相关。
