## 图类型与用途
这是一个流程图/架构图，展示了 SpecMind 项目中用户认证的架构。它描述了客户端应用如何通过不同的认证方式来获取访问权限，是系统架构设计的一部分。

## 图的整体布局
图采用从上到下的布局。顶部是客户端应用，中间是认证相关的 API 和服务，底部是数据存储和 OAuth 认证提供方。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：认证请求发起、认证服务处理、以及 Token 生成与存储。

## 节点逐项说明
- **Client App**：发起认证请求的客户端应用程序，例如网页应用或移动应用。
- **Auth API**：接收客户端认证请求的 API 网关或服务入口。
- **Auth Service**：负责处理认证逻辑的核心服务，包括用户验证、Token 生成等。
- **User Database**：存储用户账户信息（用户名、密码等）的数据库。
- **JWT Token Service**：负责生成和验证 JSON Web Tokens (JWT)，用于安全地传递用户身份信息。
- **OAuth Service**：负责处理 OAuth 认证流程的服务，允许用户通过第三方平台（如 Google 或 GitHub）进行认证。
- **Google OAuth**：Google 提供的 OAuth 认证服务。
- **GitHub OAuth**：GitHub 提供的 OAuth 认证服务。
- **Redis Cache**：用于缓存 JWT Token，提高认证效率。

## 连线、分支与汇聚关系
- `Client App -> Auth API`：客户端应用通过 `POST /auth/login` 请求发送认证信息到认证 API。
- `Auth API -> Auth Service`：认证 API 将请求转发给认证服务。
- `Auth Service -> User Database`：认证服务使用用户名/密码认证时，从用户数据库中验证用户信息。
- `Auth Service -> JWT Token Service`：认证服务在成功认证后，使用 JWT Token 服务生成 JWT Token。
- `Auth Service -> OAuth Service`：认证服务使用 OAuth 认证时，将请求转发给 OAuth 服务。
- `OAuth Service -> Google OAuth`：OAuth 服务与 Google OAuth 进行交互，完成 OAuth 流程。
- `OAuth Service -> GitHub OAuth`：OAuth 服务与 GitHub OAuth 进行交互，完成 OAuth 流程。
- `JWT Token Service -> Redis Cache`：JWT Token 服务将生成的 Token 存储到 Redis 缓存中。

## 仓库语境与术语解释
- **SpecMind**：是一个开源开发者工具，用于支持架构驱动的开发流程，确保架构和实现同步。
- **`.sm` 文件**：SpecMind 使用 Markdown + Mermaid diagrams 的 `.sm` 文件来描述系统架构和特性。参考 `packages/format/src/schemas.ts`。
- **`/analyze` 命令**：SpecMind 提供的命令，用于分析代码库并生成系统架构图，包括服务、数据库和外部集成。
- **`/design <feature>` 命令**：SpecMind 提供的命令，用于规划新特性如何更新系统架构。
- **JWT (JSON Web Token)**：一种行业标准的、自包含的、用于在各方之间安全地传输信息的 JSON 对象。
- **OAuth**：一种开放标准，允许用户授权第三方应用访问其存储在另一个服务提供商上的信息，而无需共享其密码。
- **Redis Cache**：一种内存数据结构存储，用作数据库、缓存和消息代理。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 SpecMind 项目中的用户认证架构，从客户端应用发起认证请求开始，经过 Auth API 转发到 Auth Service。Auth Service 根据认证方式选择 User Database 或 OAuth Service 进行认证，认证成功后，通过 JWT Token Service 生成 Token 并缓存到 Redis 中。该架构支持用户名/密码认证和 OAuth 认证，并使用 JWT 和 Redis 缓存提高安全性和性能。
