## 图类型与用途
该图是一个流程图，描述了外部请求如何被路由到不同的租户（TenantA 和 TenantB）并最终访问各自的数据库。它展示了一个多租户架构中请求处理的流程。

## 图的整体布局
图的布局是从上到下。整体上分为两个并行的租户处理流程，起点是外部请求，终点是各自租户的数据库。

## 分组/子图/阶段说明
图中包含两个子图，分别代表租户A和租户B。每个子图内部代表了请求处理的不同阶段。

## 节点逐项说明
- **API**：代表外部请求的入口。
- **A1 (API Gateway)**：租户A的API网关，接收外部请求。
- **A2 (请求路由)**：租户A的请求路由组件，负责将请求路由到相应的计算集群。
- **A3 (租户A计算集群)**：租户A的计算资源集群，处理业务逻辑。
- **A4 (租户A数据库)**：租户A的数据库，存储租户A的数据。
- **B1 (API Gateway)**：租户B的API网关，接收外部请求。
- **B2 (请求路由)**：租户B的请求路由组件，负责将请求路由到相应的计算集群。
- **B3 (租户B计算集群)**：租户B的计算资源集群，处理业务逻辑。
- **B4 (租户B数据库)**：租户B的数据库，存储租户B的数据。

## 连线、分支与汇聚关系
- API -> A1：外部请求发送到租户A的API网关。
- API -> B1：外部请求发送到租户B的API网关。
- A1 -> A2：租户A的API网关将请求转发到请求路由。
- B1 -> B2：租户B的API网关将请求转发到请求路由。
- A2 -- 租户A标识 --> A3：租户A的请求路由根据租户A的标识将请求路由到租户A的计算集群。
- B2 -- 租户B标识 --> B3：租户B的请求路由根据租户B的标识将请求路由到租户B的计算集群。
- A3 -> A4：租户A的计算集群访问租户A的数据库。
- B3 -> B4：租户B的计算集群访问租户B的数据库。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **API Gateway**：API网关，作为系统的入口点，负责请求的接收、路由和鉴权等功能。
- **请求路由**：根据请求的特征（如租户ID）将请求转发到相应的后端服务。
- **计算集群**：一组计算资源的集合，用于执行应用程序的业务逻辑。
- **数据库**：用于存储和管理数据的系统。
- **租户**：使用同一套软件系统的不同用户或组织，彼此隔离。

## 可作为 QA Ground Truth 的高信息密度摘要
外部请求首先到达API网关，根据请求的目标租户（A或B）被路由到相应的租户的计算集群。租户A的请求通过A1 API Gateway到达A2请求路由，根据租户A标识到达A3计算集群，最终访问A4数据库。租户B的请求通过B1 API Gateway到达B2请求路由，根据租户B标识到达B3计算集群，最终访问B4数据库。每个租户的数据存储在各自的数据库中，实现了数据隔离。
