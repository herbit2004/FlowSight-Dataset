## High-Density QA Ground Truth Summary
The `spec-gen` process begins with either CLI commands (`spec-gen commands`) or a programmatic API call (`specGenRun`). CLI commands can directly invoke `specGenInit`, `specGenAnalyze`, `specGenGenerate`, `specGenVerify`, or `specGenDrift`. The `specGenRun` API call triggers `specGenInit`, `specGenAnalyze`, and `specGenGenerate` in sequence. `specGenInit` initializes the project by using `Project Detector` and `Config Manager`. `specGenAnalyze` performs static analysis, walking files (`File Walker`), scoring significance (`Significance Scorer`), parsing imports (`Import Parser`), building a dependency graph (`Dependency Graph`), mapping the repository (`Repository Mapper`), and generating artifacts (`Artifact Generator`). The `Artifact Generator` produces analysis artifacts consumed by both the `Spec Pipeline` (in the `Generate` stage, requiring an API key) and the `Verification Engine` (in the `Verify` stage, also requiring an API key). The `Spec Pipeline` formats specifications (`OpenSpec Formatter`) and writes them (`OpenSpec Writer`) to `openspec/specs/*.md`, and also generates ADRs (`ADR Generator`) written to `openspec/decisions/*.md`. The `Drift` stage (no API key required) analyzes the Git repository (`Git Analyzer`), maps specifications (`Spec Mapper`), and detects drift (`Drift Detector`), optionally using an `LLM Enhancer`. The `LLM Service` is used by the `Generate` and `Verify` stages, and optionally by the `LLM Enhancer`. The process culminates in the generation of specification files, ADR files, analysis artifacts in `.spec-gen/analysis/`, and a `Drift Report`. The `OpenSpec` format is used for the generated specifications.
