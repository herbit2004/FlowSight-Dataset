## 图类型与用途
这是一个流程图，描述了将 COBOL 代码迁移到 Java 或 C# 的自动化流程。它展示了代码迁移过程中的各个阶段和组件，以及它们之间的依赖关系，用于概括迁移流程的架构。

## 图的整体布局
图整体采用从上到下的布局。顶部是流程的入口点 CLI，中间是深度分析、依赖分析和转换三个主要阶段，底部是最终的输出文件。

## 分组/子图/阶段说明
图中包含三个显式子图，分别对应迁移流程的三个阶段：
- **ANALYZE_PHASE (PHASE 1: Deep Analysis)**：深度分析阶段，用于分析 COBOL 代码的结构和逻辑。
- **DEPENDENCY_PHASE (PHASE 2: Dependencies)**：依赖分析阶段，用于构建 COBOL 代码的依赖关系图。
- **CONVERT_PHASE (PHASE 3: Conversion)**：转换阶段，用于将 COBOL 代码转换为 Java 或 C# 代码。

## 节点逐项说明
- **CLI / doctor.sh\n- Loads AI config\n- Selects target language**：命令行界面，是流程的入口点。负责加载 AI 配置，并允许用户选择目标语言（Java 或 C#）。根据 `doctor.sh` 脚本，它也负责启动整个迁移流程。
- **REGEX["Regex Parsing\n(Fast SQL/Variable Extraction)"]**：使用正则表达式进行快速解析，主要用于提取 SQL 语句和变量信息。
- **ANALYZER["CobolAnalyzerAgent\n(Structure & Logic)"]**：COBOL 分析代理，负责分析 COBOL 代码的结构和逻辑。根据 `Agents/CobolAnalyzerAgent.cs`，它使用 AI 模型来分析 COBOL 文件。
- **SQLITE[("SQLite Storage")]**：SQLite 数据库，用于存储 REGEX 和 CobolAnalyzerAgent 的分析结果。根据 `Persistence/SqliteMigrationRepository.cs`，它用于持久化存储分析结果。
- **MAPPER["DependencyMapperAgent\n(Builds Graph)"]**：依赖关系映射代理，负责构建 COBOL 代码的依赖关系图。根据 `Agents/DependencyMapperAgent.cs`，它使用 AI 模型分析 COBOL 文件的依赖关系。
- **NEO4J[("Neo4j Graph DB")]**：Neo4j 图数据库，用于存储 DependencyMapperAgent 构建的依赖关系图。
- **FETCHER["Context Fetcher\n(Aggregates Dependencies)"]**：上下文获取器，负责从 SQLite 和 Neo4j 中聚合依赖关系信息，为代码转换提供上下文。
- **CONVERTER["CodeConverterAgent\n(Java/C# Generation)"]**：代码转换代理，负责将 COBOL 代码转换为 Java 或 C# 代码。根据 `Agents/CSharpConverterAgent.cs`，它使用 AI 模型将 COBOL 代码转换为 C# 代码。
- **OUTPUT["Output Files"]**：输出文件，存储转换后的 Java 或 C# 代码。

## 连线、分支与汇聚关系
- `CLI --> REGEX`：CLI 启动流程，并将 COBOL 代码传递给 REGEX 进行初步解析。
- `REGEX --> SQLITE`：REGEX 将提取的 SQL 语句和变量信息存储到 SQLite 数据库中。
- `REGEX --> ANALYZE_PHASE`：REGEX 将 COBOL 代码传递给深度分析阶段。
- `ANALYZER --> SQLITE`：CobolAnalyzerAgent 将分析结果存储到 SQLite 数据库中。
- `SQLITE --> MAPPER`：DependencyMapperAgent 从 SQLite 数据库中读取分析结果，用于构建依赖关系图。
- `MAPPER --> NEO4J`：DependencyMapperAgent 将构建的依赖关系图存储到 Neo4j 图数据库中。
- `SQLITE --> FETCHER`：Context Fetcher 从 SQLite 数据库中读取分析结果。
- `NEO4J --> FETCHER`：Context Fetcher 从 Neo4j 图数据库中读取依赖关系图。
- `FETCHER --> CONVERTER`：Context Fetcher 将聚合的依赖关系信息传递给 CodeConverterAgent。
- `CONVERTER --> OUTPUT`：CodeConverterAgent 将转换后的代码存储到输出文件中。

## 仓库语境与术语解释
- **doctor.sh**：一个 Bash 脚本，用于管理 COBOL 到 Java/C# 的迁移流程。它封装了配置、测试、运行和诊断等功能。
- **CobolAnalyzerAgent**：一个 AI Agent，用于分析 COBOL 源代码的结构和逻辑。它使用 Microsoft Agent Framework 和 Azure OpenAI 服务。
- **DependencyMapperAgent**：一个 AI Agent，用于构建 COBOL 代码的依赖关系图。它分析 copybook 的使用情况和程序调用关系。
- **CodeConverterAgent**：一个 AI Agent，用于将 COBOL 代码转换为 Java 或 C# 代码。它根据选择的目标语言使用不同的转换逻辑。
- **SQLite**：一个轻量级的数据库，用于存储 COBOL 代码分析的中间结果。
- **Neo4j**：一个图数据库，用于存储 COBOL 代码的依赖关系图。
- **AI config**：指的是 AI 模型的配置，包括 endpoint、API key 和 model ID，这些配置存储在 `Config/ai-config.env.example` 文件中。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 COBOL 代码迁移到 Java 或 C# 的自动化流程。流程从 CLI 启动，通过 `doctor.sh` 脚本加载 AI 配置并选择目标语言。然后，COBOL 代码经过深度分析（REGEX 和 CobolAnalyzerAgent）和依赖分析（DependencyMapperAgent），结果分别存储在 SQLite 和 Neo4j 中。Context Fetcher 聚合这些信息，CodeConverterAgent 将 COBOL 代码转换为目标语言，并输出到文件中。其中，CobolAnalyzerAgent、DependencyMapperAgent 和 CodeConverterAgent 是核心的 AI Agent 组件，SQLite 和 Neo4j 用于持久化存储分析结果。
