## Edges, Branches & Convergence
- `CLI --> Hubble`: The CLI provides input to the Flow Parsing module, indicated by the "learn" label.
- `CLI --> Synth`: The CLI proposes policies to the Policy Synthesis module.
- `CLI --> Verify`: The CLI triggers policy verification in the Policy Validation module.
- `CLI --> Explain`: The CLI triggers report generation in the Report Generation module.
- `HubbleJSON --> Hubble`: Hubble flow data from JSON files is fed into the Flow Parsing module.
- `HubbleCLI -.-> Hubble`: The Hubble CLI (future API) provides input to the Flow Parsing module.
- `Hubble --> Synth`: Parsed flows are passed from the Flow Parsing module to the Policy Synthesis module.
- `Synth --> Verify`: Synthesized policies are passed to the Policy Validation module.
- `Synth --> Explain`: Synthesized policies are passed to the Report Generation module.
- `Hubble --> Explain`: Flows are passed from the Flow Parsing module to the Report Generation module.
- `Validate --> Hubble`: Input Validation provides data to Flow Parsing.
- `Validate --> Synth`: Input Validation provides data to Policy Synthesis.
- `Validate --> Verify`: Input Validation provides data to Policy Validation.
- `Validate --> Explain`: Input Validation provides data to Report Generation.
- `Synth --> Policies`: Synthesized policies are output as CiliumNetworkPolicy YAML.
- `Explain --> Graph`: The Report Generation module feeds data to the Network Graph module.
- `Explain --> Report`: The Report Generation module generates an HTML Report with Graph.

## High-Density QA Ground Truth Summary
The process begins with the `cmd/cpp/main.go` Cobra CLI in the CLI Layer, which serves as the entry point for user interaction. The CLI can trigger several actions: learning flows, proposing policies, verifying policies, and explaining network behavior. These actions initiate data flows to the internal packages. Data sources, including Hubble Flows from JSON files and the Hubble CLI (future API), feed into the `internal/hubble/ Flow Parsing` module. The `internal/validate/ Input Validation` module provides validation data to `internal/hubble/ Flow Parsing`, `internal/synth/ Policy Synthesis`, `internal/verify/ Policy Validation`, and `internal/explain/ Report Generation`. Parsed flows from Hubble are then passed to `internal/synth/ Policy Synthesis`. The Policy Synthesis module generates policies that are used by both `internal/verify/ Policy Validation` and `internal/explain/ Report Generation`. Flows are also passed directly from `internal/hubble/ Flow Parsing` to `internal/explain/ Report Generation`. The `internal/explain/ Report Generation` module generates reports and feeds data to `internal/graph/ Network Graph`. Finally, the system outputs `CiliumNetworkPolicy YAML` and an `HTML Report with Graph`, representing the synthesized policies and a visual representation of the network. The Cobra CLI framework facilitates user interaction, while Hubble provides the network observability data that drives policy generation.
