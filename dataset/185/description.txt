## 图类型与用途
这是一个流程图，描述了坚果量化交易系统的架构，展示了系统内各个组件之间的交互关系和数据流向。该图在 `README.md` 中被用作架构说明。

## 图的整体布局
图采用从上到下的布局。顶部是交易所，中间是 API 和策略引擎，底部是机器人控制台。数据和指令在这些组件之间流动。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为数据源（交易所）、核心处理（API 和策略引擎）、用户交互（机器人控制台）三个阶段。

## 节点逐项说明
- **Exchange (数字货币交易所)**：代表实际的数字货币交易所，例如 Binance、OKX 等。它是交易数据和执行交易的场所。`yufuquant/exchanges/models.py` 定义了 Exchange 模型，包含 code, name, logo 等字段。
- **Bot (机器人控制台)**：代表用户使用的控制界面，用于监控和管理交易策略。用户可以通过控制台查看策略运行状态、调整参数等。
- **API (坚果API)**：代表坚果量化系统提供的应用程序编程接口。它是连接各个组件的桥梁，负责处理数据请求和指令传递。
- **Strategy (策略引擎)**：代表量化交易策略的执行引擎。它根据预设的策略规则，分析市场数据，并生成交易指令。`yufuquant/strategies/models.py` 定义了 Strategy 模型，包含 name, brief, description, specification 等字段。

## 连线、分支与汇聚关系
- `Exchange ---> API`：数字货币交易所向坚果API提供市场数据。
- `API ---> Exchange`：坚果API向数字货币交易所发送交易指令。
- `Bot ---> API`：机器人控制台向坚果API发送用户指令。
- `API ---> Bot`：坚果API向机器人控制台返回策略运行状态、交易结果等信息。
- `API ---> Strategy`：坚果API向策略引擎提供市场数据和用户配置。
- `Strategy ---> API`：策略引擎向坚果API发送交易指令。
- `Exchange ---> Strategy`：数字货币交易所直接向策略引擎提供数据。
- `Strategy ---> Bot`：策略引擎直接向机器人控制台发送信息。

## 仓库语境与术语解释
- **Exchange**：数字货币交易所，是量化交易的数据来源和执行场所。
- **Bot**：机器人控制台，是用户与量化交易系统交互的界面。
- **API**：坚果API，是连接各个组件的桥梁，负责数据请求和指令传递。
- **Strategy**：策略引擎，根据预设的策略规则分析市场数据并生成交易指令。`docs/specification.md` 描述了策略规范。
- **robots**: `yufuquant/robots/models.py` 定义了 Robot 模型，表示自动交易机器人。
- `config/api_router.py` 定义了 API 的路由，包括 users, robots, strategies, exchanges, credentials 等。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了坚果量化交易系统的架构。交易所提供数据给 API 和策略引擎，API 接收来自机器人控制台的指令，并将数据传递给策略引擎。策略引擎根据策略生成交易指令，通过 API 发送到交易所执行。同时，交易所的数据和策略引擎的状态也会反馈到控制台。核心在于策略引擎，它接收来自交易所的市场数据和来自控制台的用户配置，然后根据预设的策略生成交易指令。
