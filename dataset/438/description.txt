## 图类型与用途
这是一个流程图/架构图，描述了 Vibe Coder MCP Server 的核心架构、请求处理流程、工具生态系统、支持服务以及配置与安全机制。它在仓库中的作用是展示该服务器如何处理来自客户端的请求，并利用各种工具和支持服务来完成任务，最终将结果返回给客户端。

## 图的整体布局
图整体采用从左到右的布局，分为五个主要部分：核心架构、请求处理、工具生态系统、支持服务、配置与安全。请求处理位于中部，核心架构在右侧，工具生态系统、支持服务、配置与安全位于左侧。

## 分组/子图/阶段说明
图中包含五个显式子图：
- **Core Architecture**：描述服务器的初始化和配置加载过程，以及传输类型的选择。
- **Request Processing**：描述客户端请求的处理流程，包括会话管理、路由选择、语义匹配和工具执行。
- **Tool Ecosystem**：展示了服务器支持的各种工具，例如研究工具、任务管理器、代码地图工具等。
- **Support Services**：描述了支持请求处理的各种服务，例如异步任务处理、文件操作、LLM 集成等。
- **Configuration & Security**：描述了服务器的配置加载和安全机制，包括 LLM 配置、MCP 工具配置、环境变量和安全边界。

## 节点逐项说明
- **Init (index.ts)**：程序的入口点，初始化模块。根据仓库目录树，该节点对应 `src/index.ts` 文件。
- **Configuration Loader**：负责加载和解析服务器的配置信息。
- **Transport Type**：决定服务器使用哪种传输协议与客户端通信。
- **Stdio Transport**：使用标准输入/输出流进行通信。
- **SSE Transport**：使用服务器发送事件 (Server-Sent Events) 进行通信。
- **MCP Server**：核心服务器组件，接收和处理客户端请求。
- **Tool Registry**：维护所有可用工具的列表。
- **Initialize Embeddings**：初始化用于语义匹配的嵌入向量。
- **Server Ready**：表示服务器已成功启动并准备好接收请求。
- **Client Request**：来自客户端的请求。
- **Session Manager**：管理客户端会话。
- **Hybrid Router**：根据请求内容选择合适的处理方式。
- **Semantic Matcher**：使用语义分析来确定请求应该使用哪个工具。
- **Sequential Thinking**：使用顺序推理来处理请求。
- **Tool Execution**：执行选定的工具来处理请求。
- **Job Manager**：管理工具执行的任务。
- **Response to Client**：将处理结果返回给客户端。
- **Research Tool**：用于进行研究和信息收集。
- **Vibe Task Manager**：用于管理任务和工作流程。
- **Code Map Tool**：用于生成代码地图。
- **Fullstack Generator**：用于生成全栈应用程序。
- **PRD Generator**：用于生成产品需求文档。
- **User Stories Generator**：用于生成用户故事。
- **Task List Generator**：用于生成任务列表。
- **Rules Generator**：用于生成规则。
- **Workflow Runner**：用于运行工作流程。
- **Async Job Processing**：异步处理任务。
- **File Operations**：执行文件操作。
- **LLM Integration**：与 LLM 集成。
- **Error Handling**：处理错误。
- **Session State**：管理会话状态。
- **LLM Config Mapping**：LLM 配置映射。

## 连线、分支与汇聚关系
- `Init (index.ts) -> Configuration Loader`：程序初始化后加载配置。
- `Configuration Loader -> Transport Type`：加载配置后确定传输类型。
- `Transport Type -- stdio --> Stdio Transport`：选择标准输入/输出流传输。
- `Transport Type -- sse --> SSE Transport`：选择服务器发送事件传输。
- `Stdio Transport -> MCP Server`：标准输入/输出流传输到 MCP 服务器。
- `SSE Transport -> MCP Server`：服务器发送事件传输到 MCP 服务器，形成汇聚关系。
- `MCP Server -> Tool Registry`：MCP 服务器使用工具注册表。
- `Tool Registry -> Initialize Embeddings`：工具注册表初始化嵌入。
- `Initialize Embeddings -> Server Ready`：初始化嵌入后服务器准备就绪。
- `Client Request -> Session Manager`：客户端请求进入会话管理器。
- `Session Manager -> Hybrid Router`：会话管理器将请求传递给混合路由器。
- `Hybrid Router -> Semantic Matcher`：混合路由器将请求传递给语义匹配器。
- `Hybrid Router -> Sequential Thinking`：混合路由器将请求传递给顺序思考模块。
- `Semantic Matcher -- High Confidence --> Tool Execution`：语义匹配器高置信度地选择工具执行。
- `Sequential Thinking -- Fallback --> Tool Execution`：顺序思考模块作为备选方案选择工具执行。
- `Tool Execution -> Job Manager`：工具执行交给任务管理器。
- `Job Manager -> Response to Client`：任务管理器将响应返回给客户端。
- `Tool Execution -> Research Tool`：工具执行可能调用研究工具。
- `Tool Execution -> Vibe Task Manager`：工具执行可能调用 Vibe 任务管理器。
- `Tool Execution -> Code Map Tool`：工具执行可能调用代码地图工具。
- `Tool Execution -> Fullstack Generator`：工具执行可能调用全栈生成器。
- `Tool Execution -> PRD Generator`：工具执行可能调用 PRD 生成器。
- `Tool Execution -> User Stories Generator`：工具执行可能调用用户故事生成器。
- `Tool Execution -> Task List Generator`：工具执行可能调用任务列表生成器。
- `Tool Execution -> Rules Generator`：工具执行可能调用规则生成器。
- `Tool Execution -> Workflow Runner`：工具执行可能调用工作流运行器。
- `Job Manager -> Async Job Processing`：任务管理器使用异步任务处理。
- `Tool Execution -> File Operations`：工具执行可能需要文件操作。
- `Tool Execution -> LLM Integration`：工具执行可能需要 LLM 集成。
- `Tool Execution -> Error Handling`：工具执行可能需要错误处理。
- `Tool Execution -> Session State`：工具执行可能需要会话状态。
- `Configuration Loader -> LLM Config Mapping`：配置加载器加载 LLM 配置映射。
- `Configuration Loader -> MCP Tool Config`：配置加载器加载 MCP 工具配置。
- `Configuration Loader -> Environment Variables`：配置加载器加载环境变量。

## 仓库语境与术语解释
- **MCP (Model Context Protocol)**：一种协议，用于 AI 助手与外部工具之间的通信。Vibe Coder MCP Server 旨在通过该协议增强 AI 助手的能力。
- **Tool Registry**：`src/services/routing/toolRegistry.ts` 文件定义了 `ToolRegistry` 类，用于管理和注册工具，包括工具的元数据、输入验证模式和执行逻辑。
- **index.ts**：`src/index.ts` 是程序的入口点，负责初始化服务器、加载配置和启动传输服务。
- **llm_config.json**：该文件定义了 LLM 的配置映射，用于指定不同任务使用的 LLM 模型。
- **mcp-config.json**：该文件定义了 MCP 工具的配置，包括工具的描述、用例和输入模式。
- **OpenRouter API Key**：使用 Vibe Coder MCP 需要 OpenRouter API 密钥，用于访问 LLM 服务。
- **VIBE_PROJECT_ROOT**：环境变量，用于指定项目根目录，简化了 CLI 用户和 MCP 客户端的配置。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 Vibe Coder MCP Server 的架构和请求处理流程。从 `index.ts` 初始化开始，加载配置并选择传输类型（Stdio 或 SSE），然后启动 MCP Server。客户端请求经过会话管理和混合路由，通过语义匹配或顺序思考选择合适的工具执行。工具执行由任务管理器管理，并最终将响应返回给客户端。其中，`llm_config.json` 和 `mcp-config.json` 文件用于配置 LLM 和 MCP 工具，`VIBE_PROJECT_ROOT` 环境变量用于指定项目根目录。
