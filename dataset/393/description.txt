## 图类型与用途
这是一个架构图，展示了 OpenFactory 平台的整体架构，包括前端、后端、数据库、实时协作、IDE 集成以及与外部服务的集成。该图在 README 中作为架构概览出现，帮助理解 OpenFactory 的组件及其交互方式。

## 图的整体布局
图采用从上到下的布局。顶部是客户端入口，中间是核心服务层，底部是数据存储和异步任务处理。数据流主要从上到下，通过 API Server 连接各个组件。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可以分为以下几个阶段：
- **用户交互层**：包括 Web Browser 和 Coding Agent / IDE，是用户与 OpenFactory 平台交互的入口。
- **前端层**：Next.js Frontend 负责用户界面和交互逻辑。
- **后端核心服务层**：Fastify API Server 作为后端核心，处理来自前端、IDE 和其他服务的请求。
- **数据存储层**：PostgreSQL + pgvector 数据库用于存储数据，Redis 用于缓存和消息队列。
- **外部集成层**：GitHub App、Slack Webhooks 和 Jira API 用于与外部服务集成。
- **异步任务处理层**：BullMQ Jobs 队列用于处理异步任务，Codebase Indexer 和 Drift Detection 模块处理队列中的任务。

## 节点逐项说明
- **Client (Web Browser)**：用户的 Web 浏览器，是用户与 OpenFactory 交互的入口。
- **Web (Next.js Frontend)**：使用 Next.js 构建的前端应用，负责用户界面和用户交互。根据 `packages/web/next.config.ts`，该应用使用 Next.js。
- **IDE (Coding Agent / IDE)**：集成开发环境，包含编码代理，允许开发者直接与 OpenFactory 交互。
- **MCP (MCP Server)**：模型上下文协议（Model Context Protocol）服务器，用于 IDE 和 API 之间的通信。
- **API (Fastify API Server)**：使用 Fastify 构建的 API 服务器，是后端的核心组件，处理来自前端、IDE 和其他服务的请求。根据 `packages/api/src/app.ts`，该服务使用 Fastify 框架。
- **DB (PostgreSQL + pgvector)**：使用 PostgreSQL 数据库，并使用 pgvector 扩展存储向量数据，用于 AI 相关的功能。根据 README，后端使用 PostgreSQL + pgvector。
- **Redis (Redis)**：Redis 缓存数据库，用于缓存数据和消息队列。
- **Hocus (Hocuspocus Collab Server)**：Hocuspocus 协作服务器，用于支持实时协作功能。根据 README，实时协作功能基于 Yjs + Hocuspocus。
- **GH (GitHub App)**：GitHub 应用，用于与 GitHub 集成，例如创建 issue。
- **Slack (Slack Webhooks)**：Slack Webhooks，用于向 Slack 发送通知。
- **Jira (Jira API)**：Jira API，用于与 Jira 集成，例如创建 issue。
- **BullMQ (BullMQ Jobs)**：BullMQ 任务队列，用于处理异步任务。根据 README，AI 相关技术栈包含 BullMQ。
- **Indexer (Codebase Indexer)**：代码库索引器，用于索引代码库，支持代码搜索和分析。
- **Drift (Drift Detection)**：漂移检测模块，用于检测代码和架构之间的差异。

## 连线、分支与汇聚关系
- `Client -> Web`：用户通过 Web Browser 访问 Next.js Frontend。
- `Web -> API`：Next.js Frontend 通过 Fastify API Server 与后端进行交互。
- `IDE -> MCP`：Coding Agent / IDE 通过 MCP Server 与 API Server 进行交互。
- `MCP -> API`：MCP Server 将 IDE 的请求转发到 Fastify API Server。
- `API -> DB`：Fastify API Server 与 PostgreSQL + pgvector 数据库进行数据交互。
- `API -> Redis`：Fastify API Server 使用 Redis 作为缓存和消息队列。
- `API -> Hocus`：Fastify API Server 使用 Hocuspocus Collab Server 实现实时协作功能。
- `API -> GH`：Fastify API Server 通过 GitHub App 与 GitHub 集成。
- `API -> Slack`：Fastify API Server 通过 Slack Webhooks 与 Slack 集成。
- `API -> Jira`：Fastify API Server 通过 Jira API 与 Jira 集成。
- `Redis -> BullMQ`：Redis 将消息发送到 BullMQ 任务队列。
- `BullMQ -> Indexer`：BullMQ 队列中的任务由 Codebase Indexer 处理。
- `BullMQ -> Drift`：BullMQ 队列中的任务由 Drift Detection 模块处理。

## 仓库语境与术语解释
- **Next.js Frontend**：使用 Next.js 框架构建的前端应用，位于 `packages/web` 目录。
- **Fastify API Server**：使用 Fastify 框架构建的后端 API 服务器，位于 `packages/api` 目录。根据 `packages/api/src/app.ts`，它处理所有 API 路由。
- **PostgreSQL + pgvector**：PostgreSQL 数据库，使用 pgvector 扩展存储向量数据，用于 AI 相关功能。`packages/api/src/db/connection.ts` 文件定义了数据库连接。
- **MCP (Model Context Protocol)**：一种用于 IDE 集成的协议，`packages/mcp-server` 目录包含 MCP 服务器的实现。
- **BullMQ**：一个基于 Redis 的任务队列，用于处理异步任务。
- **Codebase Indexer**：用于索引代码库，支持代码搜索和分析。
- **Drift Detection**：用于检测代码和架构之间的差异，是 Foundry 模块的关键能力之一，如 README 所示。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 OpenFactory 平台的整体架构，从 Web Browser 和 IDE 发起的请求，分别通过 Next.js Frontend 和 MCP Server 到达核心的 Fastify API Server。API Server 负责与 PostgreSQL 数据库、Redis 缓存、Hocuspocus 协作服务器以及 GitHub、Slack、Jira 等外部服务集成。异步任务通过 Redis 传递给 BullMQ 队列，由 Codebase Indexer 和 Drift Detection 模块处理。该架构体现了 OpenFactory 作为 AI 原生 SDLC 编排平台的特性，通过 MCP 实现 IDE 集成，并利用 BullMQ 处理异步任务。
