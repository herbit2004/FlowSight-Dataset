## 图类型与用途
这是一个流程图，描述了 `AutoQA-Agent` 工具中 "Plan Commands" 的架构，展示了如何从用户输入开始，经过探索和生成阶段，最终生成测试计划和相关文件。它在仓库中的作用是概括 Plan 命令的结构，特别是 `autoqa plan-explore` 和 `autoqa plan-generate` 命令的流程，如 README 中 "Plan Command Structure" 章节所述。

## 图的整体布局
图整体采用从上到下的布局。顶部是 "Plan Commands" 的总括，其下分为 "Input Selection"、"Exploration Phase"、"Generation Phase" 和 "Output Artifacts" 四个主要部分，数据流从 "Input Selection" 开始，经过 "Exploration Phase" 和 "Generation Phase"，最终到达 "Output Artifacts"。

## 分组/子图/阶段说明
- **Exploration Phase**：负责探索 Web 应用的结构和元素，包括起始 URL、探索深度、最大页面数、导航图和元素发现。
- **Generation Phase**：负责根据探索阶段的结果生成测试计划，包括测试类型、测试计划和 Markdown 规范。
- **Output Artifacts**：流程最终生成的各种文件，包括导航图 JSON 文件、元素信息 JSON 文件、交互记录 JSON Lines 文件、测试计划 JSON 文件和 Markdown 格式的测试用例规范文件。

## 节点逐项说明
- **Input Selection**：用户输入选择，代表用户提供的指令或配置，是整个流程的起点。
- **Start URL**：探索的起始 URL，是 "Exploration Phase" 的起点。
- **Depth: 1-10**：探索的深度，即递归遍历链接的层数，是 "Exploration Phase" 的参数之一。
- **Max Pages**：探索的最大页面数量，是 "Exploration Phase" 的参数之一。
- **Navigation Graph**：记录页面之间导航关系的图，是 "Exploration Phase" 的输出之一。
- **Element Discovery**：发现页面上的元素（如按钮、链接、文本框等），是 "Exploration Phase" 的输出之一。
- **Test Types**：指定要生成的测试类型（例如，功能测试、回归测试），是 "Generation Phase" 的输入。
- **Test Plan**：生成的测试计划，包含一系列测试用例，是 "Generation Phase" 的输出之一。
- **Markdown Specs**：以 Markdown 格式编写的测试用例规范，是 "Generation Phase" 的输出之一。
- **navigation-graph.json**：导航图的 JSON 文件，是 "Output Artifacts" 之一。
- **elements.json**：页面元素信息的 JSON 文件，是 "Output Artifacts" 之一。
- **transcript.jsonl**：交互记录的 JSON Lines 文件，是 "Output Artifacts" 之一。
- **test-plan.json**：测试计划的 JSON 文件，是 "Output Artifacts" 之一。
- **specs/\*.md**：Markdown 格式的测试用例规范文件，是 "Output Artifacts" 之一。

## 连线、分支与汇聚关系
- `Input Selection -> Exploration Phase`：用户输入驱动探索阶段的开始。
- `Input Selection -> Generation Phase`：用户输入也直接影响测试计划的生成方式。
- `Exploration Phase -> Output Artifacts`：探索阶段的结果（导航图、元素信息等）被保存为文件。
- `Generation Phase -> Output Artifacts`：生成阶段的结果（测试计划、Markdown 规范）被保存为文件。

## 仓库语境与术语解释
- **Plan Commands**：指的是 `autoqa plan` 命令及其子命令，用于自动化测试计划的生成。
- **Exploration Phase**：对应 `autoqa plan-explore` 命令，用于探索 Web 应用的结构和元素。
- **Generation Phase**：对应 `autoqa plan-generate` 命令，用于根据探索阶段的结果生成测试计划。
- **Output Artifacts**：指的是由 Plan 命令生成的各种文件，例如导航图、元素信息、测试计划和 Markdown 规范。
- **Markdown Specs**：指的是以 Markdown 格式编写的测试用例规范，是 `AutoQA-Agent` 的核心特性之一，允许非技术人员参与测试编写，如 README 中 "Docs as Tests" 所述。
- **Explore Scope**：在 `src/plan/types.ts` 中定义，控制 URL 过滤行为，包括 'site'、'focused' 和 'single_page' 三种模式。
- **GuardrailConfig**：在 `src/plan/types.ts` 中定义，用于配置探索会话的护栏，例如最大 Agent 轮数、最大快照数等。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 `AutoQA-Agent` 工具中 "Plan Commands" 的执行流程。流程从 "Input Selection" 开始，用户输入驱动 "Exploration Phase" 和 "Generation Phase"。 "Exploration Phase" 探索 Web 应用的结构和元素，生成导航图和元素信息。"Generation Phase" 根据探索结果和用户指定的测试类型，生成测试计划和 Markdown 规范。最终，所有结果作为 "Output Artifacts" 被保存为文件。该流程体现了 `AutoQA-Agent` 的核心功能，即根据用户输入自动探索 Web 应用并生成测试计划，如 README 中 "How It Works" 章节所述。
