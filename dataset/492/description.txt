## 图类型与用途
这是一个流程图，描述了本地邮件代理（Local Email Agent）处理用户输入并生成最终答案的流程。该图展示了数据如何在 LangChain 代理、Phi-4 模型和自定义中间件之间流动，以执行工具调用并最终生成回复。

## 图的整体布局
图采用从左到右的布局。流程从用户输入开始，经过一系列处理步骤，最终生成最终答案。Phi-4 模型在流程中占据核心位置，并与两个中间件组件交互。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可以分为四个阶段：输入与代理处理、模型生成与格式转换、工具执行、结果处理与反馈。

## 节点逐项说明
- **Input (User Input)**：用户输入，代表用户向系统发出的请求或指令。
- **Agent (LangChain Agent)**：LangChain 代理，负责接收用户输入，并将其传递给 Phi-4 模型。根据 `agent_graph.py`，该代理使用 Foundry Local 连接。
- **Phi (Phi-4-generic-gpu)**：Phi-4 模型，运行在 GPU 上，是系统的核心语言模型，用于生成 JSON 格式的工具调用指令。根据 `foundry_service.py`，该模型通过 Foundry Local 进行管理。
- **JSON (JSON Output)**：Phi 模型输出的 JSON 格式数据，包含模型生成的工具调用指令。
- **MW1 (PhiJSONToToolCallMiddleware)**：PhiJSONToToolCall 中间件，负责将 Phi 模型输出的 JSON 格式数据转换为 `tool_calls` 格式，以便后续工具调用。根据 `ARCHITECTURE.md`，该中间件将 JSON 转换为 LangChain 的 `tool_calls` 格式。
- **ToolCall (tool_calls Format)**：`tool_calls` 格式的数据，指定了需要调用的工具及其参数。
- **Execute (Execute Tool)**：执行工具，根据 `tool_calls` 格式的数据，调用相应的工具来完成特定的任务，例如发送邮件、查询信息等。
- **ToolResult (Tool Results)**：工具执行的结果，包含工具返回的数据或状态信息。
- **MW2 (PhiToolResultMiddleware)**：PhiToolResult 中间件，负责处理工具执行的结果，并对其进行裁剪和添加提醒信息，以便更好地引导 Phi 模型生成最终答案。根据 `ARCHITECTURE.md`，该中间件用于防止上下文溢出，并提示 Phi 模型综合答案。
- **Trim (Trimmed + Reminder)**：对工具结果进行裁剪和添加提醒信息，以便更好地引导 Phi 模型生成最终答案。
- **Answer (Final Answer)**：最终答案，是系统根据用户输入和工具执行结果生成的最终回复。

## 连线、分支与汇聚关系
- `Input -> Agent`：用户输入被传递给 LangChain 代理。
- `Agent -> Phi`：LangChain 代理将输入传递给 Phi 模型。
- `Phi -> JSON`：Phi 模型输出 JSON 格式的数据。
- `JSON -> MW1`：PhiJSONToToolCall 中间件将 JSON 数据转换为 `tool_calls` 格式。
- `MW1 -> ToolCall`：中间件将转换后的数据传递给 ToolCall 节点。
- `ToolCall -> Execute`：执行工具根据 `tool_calls` 格式的数据调用相应的工具。
- `Execute -> ToolResult`：工具执行的结果被传递给 ToolResult 节点。
- `ToolResult -> MW2`：PhiToolResult 中间件处理工具执行的结果。
- `MW2 -> Trim`：PhiToolResult 中间件对结果进行裁剪和添加提醒。
- `Trim -> Phi`：裁剪后的结果被反馈给 Phi 模型，形成一个反馈循环。
- `Phi -> Answer`：Phi 模型根据所有信息生成最终答案。

## 仓库语境与术语解释
- **LangChain Agent**：`agent_graph.py` 中定义了使用 LangGraph 构建的代理，用于编排整个流程。
- **Phi-4-generic-gpu**：根据 `foundry_service.py`，这是 Foundry Local 提供的本地模型，用于生成文本和理解用户意图。
- **Foundry Local**：根据 README 和 `foundry_service.py`，这是一个在本地运行 LLM 的工具，本项目使用它来运行 Phi-4 模型。
- **Middleware (MW1, MW2)**：根据 `ARCHITECTURE.md`，这些是自定义中间件组件，用于在 Phi-4 模型前后处理数据，以弥补其工具调用方面的不足。
- **tool_calls Format**：LangChain 定义的一种标准格式，用于指定要调用的工具及其参数。
- **HITL (Human-in-the-Loop)**：根据 README 和 `hitl_schemas.py`，该机制允许用户在敏感操作（如发送邮件）执行前进行审批。
- **MCP (Model Context Protocol)**：根据 README，这是一个用于连接 Microsoft 365 服务的协议，用于执行邮件和日历操作。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了本地邮件代理处理用户输入的流程。流程从用户输入开始，经过 LangChain 代理传递给 Phi-4 模型。Phi-4 模型生成 JSON 输出，然后通过 `PhiJSONToToolCallMiddleware` 转换为 `tool_calls` 格式。接着，系统执行相应的工具，并将结果通过 `PhiToolResultMiddleware` 处理后反馈给 Phi-4 模型，最终生成最终答案。其中，`PhiJSONToToolCallMiddleware` 和 `PhiToolResultMiddleware` 是关键的中间件组件，用于弥补 Phi-4 模型在工具调用方面的不足，并实现 Human-in-the-Loop 审批。
