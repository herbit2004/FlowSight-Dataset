## Edges, Branches & Convergence
- `Browser --> App`: HTTP/WebSocket requests from the web browser are sent to the Flask application.
- `App --> Routes`: The Flask application routes requests to the appropriate route handlers.
- `App --> SocketIO`: The Flask application uses Flask-SocketIO for WebSocket communication.
- `Routes --> Scanner`: Route handlers trigger the scanner engine.
- `Routes --> Reporter`: Route handlers trigger the PDF reporter.
- `SocketIO --> Browser`: Real-time events are sent from the Flask-SocketIO server to the web browser.
- `Scanner --> Socket`: The scanner engine uses the Python Socket API for network communication.
- `Scanner --> DNS`: The scanner engine uses DNS resolution for resolving domain names.
- `Scanner --> IPv4`: The scanner engine uses IPv4 support for network communication.
- `Scanner --> IPv6`: The scanner engine uses IPv6 support for network communication.
- `App --> Gemini`: The Flask application interacts with the Google Gemini API for AI analysis.
- `App --> History`: The Flask application stores scan history in the JSON history file.
- `App --> State`: The Flask application stores the latest scan results in the global state.
- `Reporter --> History`: The PDF reporter stores data in the JSON history file.

## Repository Context & Terminology

- **app.py**: The main file for the Flask application, containing the application logic and route definitions.
- **core/scanner.py**: A Python file containing the implementation of the scanner engine.
- **core/reporter.py**: A Python file containing the implementation of the PDF reporter.
- **scan_history.json**: A JSON file used to store the history of scans performed by the application.

## High-Density QA Ground Truth Summary
The architecture begins with the user interacting with the **Web Browser**, which communicates with the **Flask Application (app.py)** via HTTP/WebSocket. The Flask application then routes requests to specific **Route Handlers** such as `/`, `/dashboard`, `/history`, and `/subdomain`. These route handlers can trigger the **Scanner Engine (core/scanner.py)** or the **PDF Reporter (core/reporter.py)**. The Scanner Engine utilizes the **Python Socket API**, **DNS Resolution**, **IPv4 Support (AF_INET)**, and **IPv6 Support (AF_INET6)** for network scanning. The Flask application also interacts with the **Google Gemini API** for AI analysis. The Flask application and PDF Reporter store data in the **JSON History File (scan_history.json)**, while the Flask application also updates the **Global State (latest_results)**. The **Flask-SocketIO WebSocket Server** enables real-time events to be sent back to the **Web Browser**. The `core/scanner.py` and `core/reporter.py` files represent key modules within the application responsible for scanning and report generation respectively, highlighting the modular design of the system. The `scan_history.json` file serves as a persistent record of past scans, enabling users to review previous activity.
