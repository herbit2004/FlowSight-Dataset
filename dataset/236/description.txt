## 图类型与用途
这是一个流程图，展示了 Dayflow 应用中三种不同的 AI 处理流程，用于从视频数据生成时间线卡片。该图旨在对比不同 AI 模型（Gemini, 本地模型, ChatGPT/Claude）在视频处理流程中的差异和 LLM 调用次数。

## 图的整体布局
图采用从左到右的布局，每个流程都独立成一个子图，从视频输入开始，经过一系列处理步骤，最终到达“Done”节点。三个子图从上到下依次是 ChatGPT/Claude Flow, Local Flow, Gemini Flow。

## 分组/子图/阶段说明
图中有三个显式子图，分别对应三种不同的 AI 处理流程：
- **Gemini Flow**：使用 Google Gemini 模型的流程，标注为 "Gemini Flow: 2 LLM Calls"。
- **Local Flow**：使用本地模型的流程，标注为 "Local Flow: 33+ LLM Calls"。
- **ChatCLI Flow**：使用 ChatGPT 或 Claude 模型的流程，标注为 "ChatGPT/Claude Flow: 4-6 LLM Calls"。

## 节点逐项说明
- **GV (Video)**：Gemini Flow 的输入视频文件。
- **GU (Upload + Transcribe)**：Gemini Flow 中上传视频并进行转录的步骤，需要调用一次 LLM。
- **GC (Generate Cards)**：Gemini Flow 中根据转录结果生成时间线卡片的步骤，需要调用一次 LLM。
- **GD (Done)**：Gemini Flow 流程结束，生成卡片。
- **LV (Video)**：Local Flow 的输入视频文件。
- **LE (Extract 30 frames)**：Local Flow 中从视频中提取 30 帧的步骤。
- **LD (30 descriptions)**：Local Flow 中使用本地 LLM 模型为每帧图像生成描述的步骤，需要调用 30 次 LLM。
- **LM (Merge)**：Local Flow 中将 30 个描述合并的步骤，需要调用一次 LLM。
- **LT (Title)**：Local Flow 中生成标题的步骤，需要调用一次 LLM。
- **LC (Merge Check)**：Local Flow 中检查合并结果的步骤，需要调用一次 LLM。
- **LMC (Merge Cards)**：Local Flow 中合并卡片的步骤，需要调用一次 LLM。
- **LD2 (Done)**：Local Flow 流程结束，生成卡片。
- **CV (Video)**：ChatCLI Flow 的输入视频文件。
- **CE (Extract frames every 60s)**：ChatCLI Flow 中每 60 秒提取一帧图像的步骤。
- **CB (Batch describe 10 frames/call)**：ChatCLI Flow 中将 10 帧图像打包，并使用 LLM 模型生成描述的步骤，每次调用处理 10 帧。
- **CM (Merge segments)**：ChatCLI Flow 中合并图像片段的步骤，需要调用一次 LLM。
- **CC (Generate Cards)**：ChatCLI Flow 中根据合并结果生成时间线卡片的步骤，需要调用一次 LLM。
- **CD (Done)**：ChatCLI Flow 流程结束，生成卡片。

## 连线、分支与汇聚关系
- `GV -> GU`：Gemini Flow 中，视频文件上传并转录。
- `GU -> GC`：Gemini Flow 中，转录结果用于生成卡片。
- `GC -> GD`：Gemini Flow 中，生成卡片后流程结束。
- `LV -> LE`：Local Flow 中，视频文件提取 30 帧。
- `LE -> LD`：Local Flow 中，为每帧图像生成描述。
- `LD -> LM`：Local Flow 中，合并 30 个描述。
- `LM -> LT`：Local Flow 中，生成标题。
- `LT -> LC`：Local Flow 中，检查合并结果。
- `LC -> LMC`：Local Flow 中，合并卡片。
- `LMC -> LD2`：Local Flow 中，生成卡片后流程结束。
- `CV -> CE`：ChatCLI Flow 中，视频文件提取帧。
- `CE -> CB`：ChatCLI Flow 中，批量描述提取的帧。
- `CB -> CM`：ChatCLI Flow 中，合并图像片段。
- `CM -> CC`：ChatCLI Flow 中，根据合并结果生成卡片。
- `CC -> CD`：ChatCLI Flow 中，生成卡片后流程结束。

## 仓库语境与术语解释
- **Dayflow**：一个 macOS 应用程序，通过分析屏幕活动自动生成时间线，如 README 所述。
- **LLM (Large Language Model)**：用于生成视频描述和时间线卡片的人工智能模型。Dayflow 支持 Gemini, 本地模型 (Ollama / LM Studio), 和 ChatGPT/Claude，如 README 所述。
- **Gemini**：Google 提供的 LLM，Dayflow 允许用户使用自己的 API 密钥进行集成，如 README 和 `Dayflow/Dayflow/Core/AI/GeminiDirectProvider.swift` 中所述。
- **Local models (Ollama / LM Studio)**：用户可以在本地运行的 LLM，例如 Ollama 或 LM Studio，用于处理视频数据，如 README 和 `Dayflow/Dayflow/Core/AI/OllamaProvider.swift` 中所述。
- **ChatGPT/Claude**：OpenAI 的 ChatGPT 或 Anthropic 的 Claude，需要付费订阅才能使用，Dayflow 通过 CLI 工具批量处理提取的帧，如 README 和 `Dayflow/Dayflow/Core/AI/ChatCLIProvider.swift` 中所述。
- **Timeline Card**：Dayflow 应用中用于表示用户活动时间线的卡片，包含时间、类别、标题和摘要等信息。
- **Screenshot Interval**：截屏间隔，由 `Dayflow/Dayflow/Core/Recording/ScreenRecorder.swift` 中的 `ScreenshotConfig.interval` 定义，用于控制截屏频率。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Dayflow 应用中三种不同的视频处理流程，分别使用 Gemini, 本地模型 (Ollama / LM Studio), 和 ChatGPT/Claude。Gemini Flow 流程简洁，只需要两次 LLM 调用；Local Flow 需要 33+ 次 LLM 调用，主要用于生成帧描述；ChatCLI Flow 需要 4-6 次 LLM 调用，用于批量描述帧和合并片段。每个流程都以视频文件作为输入，最终生成时间线卡片。Dayflow 允许用户选择不同的 AI 提供商，以平衡质量和效率。
