## 图类型与用途
这是一个架构图，展示了 Unmute 系统的主要组件及其交互方式，描述了用户语音输入到系统，再到系统输出语音回复的整体流程。该图在 README 中用于概括 Unmute 系统的工作原理。

## 图的整体布局
图采用从左到右的布局。用户浏览器是流程的起点，后端是核心处理中心，语音转文本、大语言模型和文本转语音是三个关键组件，前端与用户浏览器并行。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：用户交互（User browser 和 Frontend）、核心处理（Backend）、以及语音和文本处理（STT、LLM、TTS）。

## 节点逐项说明
- **User browser**：用户的浏览器，是用户与 Unmute 系统交互的入口。
- **Frontend**：前端，负责提供用户界面，处理用户输入，并与后端进行通信。根据 `frontend/README.md`，前端使用 Next.js 构建。
- **Backend**：后端，系统的核心逻辑处理部分，负责协调 STT、LLM 和 TTS 组件。
- **Speech-to-text (STT)**：语音转文本模块，负责将用户的语音输入转换为文本。
- **LLM**：大语言模型，负责根据用户的文本输入生成回复文本。README 提到可以使用 OpenRouter 或 VLLM 作为 LLM 服务。
- **Text-to-speech (TTS)**：文本转语音模块，负责将 LLM 生成的回复文本转换为语音输出。

## 连线、分支与汇聚关系
- `User browser -> Backend`：用户浏览器直接与后端建立连接，例如通过 WebSocket。
- `User browser -> Frontend`：用户通过浏览器与前端进行交互。
- `Backend -> Speech-to-text`：后端与语音转文本模块进行通信，接收语音转录的文本。
- `Backend -> LLM`：后端与大语言模型进行通信，获取回复文本。
- `Backend -> Text-to-speech`：后端与文本转语音模块进行通信，将回复文本转换为语音。

## 仓库语境与术语解释
- **Unmute**：一个允许文本 LLM 听和说的系统，通过 Kyutai 的文本转语音 (TTS) 和语音转文本 (STT) 模型封装 LLM。
- **Frontend**：使用 Next.js 构建，负责用户界面和与后端的通信。
- **Backend**：使用 Python 和 FastAPI 构建，负责协调各个模块，完成语音输入到语音输出的整个流程。
- **STT (Speech-to-text)**：将用户的语音输入转换为文本，仓库中使用了 Kyutai 的 STT 模型。
- **LLM (LLM)**：根据用户的文本输入生成回复文本，可以使用 OpenRouter 或 VLLM。
- **TTS (Text-to-speech)**：将 LLM 生成的回复文本转换为语音输出，仓库中使用了 Kyutai 的 TTS 模型。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Unmute 系统的核心架构。用户通过浏览器与前端和后端交互，语音输入被发送到后端，后端将语音发送给 STT 模块进行转录，然后将转录后的文本发送给 LLM 生成回复。最后，后端将回复文本发送给 TTS 模块，将回复转换为语音输出给用户。其中，Backend 作为核心枢纽，连接了 User browser, Frontend, STT, LLM 和 TTS 各个模块。Unmute 系统通过 Kyutai 的 TTS 和 STT 模型封装 LLM，实现了文本 LLM 的听和说能力。
