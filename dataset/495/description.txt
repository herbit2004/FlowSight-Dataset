## Repository Context & Terminology
- **Gremlin**: A graph traversal language commonly used with graph databases.
- **TinkerPop**: An Apache project providing a graph computing framework.
- **Cypher**: A declarative graph query language.

- **Raft**: A consensus algorithm used for distributed systems.
- **RocksDB**: A high-performance embedded database for key-value data.

## High-Density QA Ground Truth Summary
The diagram illustrates the architecture of the HugeGraph system, starting with client applications in the Client Layer (Gremlin Console, REST Client, Cypher Client, SDK/Tools) which interact with the HugeGraph Server. The server layer, running on port 8080, comprises a REST API (Jersey 3), a Gremlin Server (TinkerPop 3.5), and a Cypher Engine (OpenCypher), all feeding into the core Graph Engine (hugegraph-core). The Graph Engine then directs data to different storage backends based on the deployment mode. In standalone mode, it connects directly to an embedded RocksDB instance. In distributed mode, it interacts with a HugeGraph-PD Raft Cluster (ports 8620/8686), which in turn communicates with the HugeGraph-Store (Raft + RocksDB, port 8520). The Graph Engine also supports interaction with legacy backends (MySQL, PostgreSQL, Cassandra, HBase ≤v1.7), although this is represented as a dashed line, indicating a less direct or potentially deprecated path. The use of TinkerPop for the Gremlin Server indicates support for graph traversal and manipulation using the Gremlin language.
