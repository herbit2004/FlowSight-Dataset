## Diagram Type & Purpose
This is a flowchart diagram illustrating a cluster membership and failover process. It depicts how nodes in a distributed system maintain cluster membership through heartbeats, how failover is initiated upon heartbeat loss, and how a new active node is selected. The diagram serves as a visual representation of the system's fault tolerance mechanism.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is divided into three main subgraphs: Cluster Membership, Failover Process, and Active/Passive Role Assignment. The process starts with nodes sending heartbeats and ends with data replication to passives or maintaining a passive state.

## Repository Context & Terminology
- **Heartbeat**: A periodic signal sent by a node to indicate its availability and health.
- **Cluster Membership**: The state of nodes being part of a distributed system, maintained through heartbeat mechanisms.
- **Failover**: The process of automatically transferring control to a redundant or standby system upon the failure of the primary system.
- **Election Manager**: A component responsible for managing the election process to select a new active node.
- **Quorum**: The minimum number of nodes required to be available for the system to operate correctly.
- **Active Node**: The node currently responsible for handling requests and managing the system.
- **Passive Node**: A node that is in standby mode, ready to take over if the active node fails.

## High-Density QA Ground Truth Summary
The cluster membership process begins with Node A, Node B, and Node C sending heartbeats to each other to maintain awareness of their availability. If a node detects a loss of heartbeat from the active node, such as Node B detecting a loss from Node A, it proposes a failover. These proposals converge at the Election Manager, which initiates a Quorum Size Check to ensure enough nodes are available. If a quorum is achieved ("Yes" branch), the process proceeds to designate a primary node and then selects an active node. The active node is assigned the "Active Role" and begins handling requests, while other nodes are assigned the "Passive Role" and enter "Standby for Failover." The new active node then replicates data to the passive nodes. If a quorum is not achieved ("No" branch), the node maintains a passive state. The heartbeat mechanism and quorum check are crucial for ensuring fault tolerance and data consistency in the distributed system. The failover process ensures that the system can continue to operate even if one or more nodes fail.
