## Edges, Branches & Convergence
- `S0 --> S1`: Transition from strategy to specification, driven by the "Business Case".
- `S1 --> Ambiguity`: Transition from specification to ambiguity check, driven by "PRD Draft".
- `Ambiguity -- Yes --> Clarify`: If the PRD is ambiguous, clarify questions.
- `Clarify --> S1`: After clarifying questions, return to the specification stage.
- `Ambiguity -- No --> S2`: If the PRD is not ambiguous, proceed to the planning stage.
- `S2 --> Review1`: Transition from planning to design approval, driven by "PLAN.md + C4".
- `Review1 -- No --> S2`: If the design is not approved, return to the planning stage.
- `Review1 -- Yes --> S3`: If the design is approved, proceed to the tasks stage.
- `S3 --> Decomp`: Transition from tasks to task decomposition, driven by "project/TASKS.md".
- `Decomp -- No --> S3`: If a task is not less than 15 minutes, return to the tasks stage.
- `Decomp -- Yes --> S4`: If a task is less than 15 minutes, proceed to the implementation stage.
- `S4 --> TDD`: Transition from implementation to the TDD cycle.
- `TDD --> RARV`: Transition from the TDD cycle to the RARV cycle.
- `RARV --> Audit`: Transition from the RARV cycle to the audit log.
- `Audit --> Done`: Transition from the audit log to feature completion.

## Repository Context & Terminology
- **PRD (Product Requirements Document)**: A document outlining the purpose, features, functionality, and behavior of a product.
- **PLAN.md**: A markdown file containing the plan for the feature.
- **C4 Model**: A set of diagrams used to describe the architecture of a software system.
- **project/TASKS.md**: A markdown file containing the tasks for the project.
- **TDD (Test-Driven Development)**: A software development process where tests are written before the code.
- **RARV (Reason/Act/Reflect/Verify)**: A cycle of reasoning, acting, reflecting, and verifying, used for continuous improvement.
- **Audit Log**: A record of events that occur during the feature development process.
