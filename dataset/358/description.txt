## 图类型与用途
这是一个流程图，描述了 GABBE (Generative Architectural Brain Base Engine) 中 Agentic Software R&D 工程套件的开发流程。该图展示了软件开发的迭代过程，以及如何通过一系列步骤和检查点来确保代码质量和项目目标的达成。

## 图的整体布局
图整体采用从上到下的布局。顶部是流程的起点，底部是流程的终点，中间是迭代开发过程中的各个阶段。

## 分组/子图/阶段说明
图中包含三个显式子图，分别代表软件开发的不同阶段：
- **Definition**：定义阶段，主要进行需求规范和计划制定。
- **Design**：设计阶段，主要进行开发计划的制定和审查。
- **Execution**：执行阶段，主要进行任务分解、代码实现、测试和验证。

## 节点逐项说明
- **S0: Strategy**：代表项目或功能的初始策略阶段，确定业务案例。
- **S1: Specify**：代表需求规范阶段，根据策略制定产品需求文档 (PRD) 草案。
- **Ambiguous?**：一个决策节点，用于判断 PRD 草案是否存在歧义。
- **Clarify Questions**：如果 PRD 存在歧义，则需要澄清问题，并返回 S1 重新规范。
- **S2: Plan**：代表计划阶段，基于规范制定详细的开发计划 (PLAN.md) 和 C4 模型。
- **Approved?**：一个审查节点，用于判断开发计划是否获得批准。
- **S3: Tasks**：代表任务分解阶段，将开发计划分解为具体的任务，并记录在 TASKS.md 文件中。
- **Task < 15m?**：一个决策节点，用于判断任务是否足够小（小于 15 分钟）。
- **S4: Implement**：代表实现阶段，根据分解的任务进行代码实现。
- **TDD Cycle**：代表测试驱动开发 (TDD) 循环，即先编写测试用例，再编写代码使其通过测试。
- **RARV: Reason/Act/Reflect/Verify**：代表一个循环，用于在开发过程中进行推理、行动、反思和验证，以确保代码质量和正确性。
- **Audit Log**：记录开发过程中的所有活动，用于审计和追踪。
- **Feature Complete**：代表功能开发完成。

## 连线、分支与汇聚关系
- `S0 -> S1`：从策略阶段进入需求规范阶段。
- `S1 -> Ambiguous?`：生成 PRD 草案后，判断是否存在歧义。
- `Ambiguous? -- Yes --> Clarify Questions`：如果存在歧义，则进入澄清问题阶段。
- `Clarify Questions -> S1`：澄清问题后返回 S1 重新规范。
- `Ambiguous? -- No --> S2`：如果没有歧义，则进入计划阶段。
- `S2 -> Approved?`：制定开发计划后，进行审查。
- `Approved? -- No --> S2`：如果计划未获得批准，则返回 S2 重新制定。
- `Approved? -- Yes --> S3`：如果计划获得批准，则进入任务分解阶段。
- `S3 -> Task < 15m?`：将开发计划分解为任务后，判断任务是否足够小。
- `Task < 15m? -- No --> S3`：如果任务不够小，则返回 S3 重新分解。
- `Task < 15m? -- Yes --> S4`：如果任务足够小，则进入实现阶段。
- `S4 -> TDD Cycle`：进入测试驱动开发循环。
- `TDD Cycle -> RARV`：进行推理、行动、反思和验证。
- `RARV -> Audit Log`：记录审计日志。
- `Audit Log -> Feature Complete`：功能开发完成。

## 仓库语境与术语解释
- **GABBE**：Generative Architectural Brain Base Engine，一个用于软件和 AI 编码代理的通用工具包，参见 README.md。
- **Agentic Software R&D Engineering Kit**：基于软件工程和架构实践和程序的工具包，用于将任何 AI 编码代理转变为受管理的工程团队，参见 README.md。
- **PRD**：Product Requirements Document，产品需求文档，用于详细描述产品的功能和需求，参见 agents/skills/product/spec-writer.skill.md 和 agents/templates/product/PRD_TEMPLATE.md。
- **PLAN.md**：开发计划文档，用于详细描述开发过程中的各个阶段和任务，参见 agents/templates/core/PLAN_TEMPLATE.md。
- **C4 模型**：一种软件架构可视化方法，用于描述软件系统的结构和组成。
- **TASKS.md**：任务分解文档，用于详细描述开发过程中需要完成的各个任务，参见 agents/templates/core/TASKS_TEMPLATE.md。
- **TDD Cycle**：Test-Driven Development Cycle，测试驱动开发循环，一种先编写测试用例，再编写代码使其通过测试的开发方法，参见 agents/skills/coding/tdd-cycle.skill.md。
- **RARV**：Reason/Act/Reflect/Verify，推理/行动/反思/验证，一个用于在开发过程中进行推理、行动、反思和验证的循环，以确保代码质量和正确性，参见 agents/guides/processes/RARV_CYCLE.md。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 GABBE 中 Agentic Software R&D 工程套件的开发流程，从策略制定开始，经过需求规范、计划制定、任务分解、代码实现、测试和验证，最终完成功能开发。其中，PRD 的歧义澄清、开发计划的审批、任务分解的粒度控制、TDD 循环和 RARV 过程是保证代码质量的关键环节。该流程涉及的关键文档包括 PLAN.md 和 TASKS.md。
