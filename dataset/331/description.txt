## 图类型与用途
这是一个流程图，描述了 `cc-devflow` 项目中从项目启动到发布完成的开发流程。它展示了如何使用 `harness:*` 命令链驱动开发，并突出了各个阶段的关键操作和产物。

## 图的整体布局
图采用从上到下的布局。流程从顶部的“Start Project”节点开始，经过项目级别配置和需求级别开发，最终到达底部的“Release Complete”节点。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：项目级别配置、需求级别开发，以及流程执行阶段。

## 节点逐项说明
- **Start Project**：流程的起点，表示项目启动。
- **Project-Level Setup**：项目级别配置阶段，进行全局配置，例如生成路线图、架构文档和风格指南。
- **/core-roadmap ROADMAP.md & BACKLOG.md**：项目核心路线图和待办事项，由 `/core-roadmap` 命令生成，包含项目的长期规划和需求优先级。
- **/core-architecture ARCHITECTURE.md**：项目核心架构文档，由 `/core-architecture` 命令生成，描述项目的整体设计。
- **/core-guidelines frontend/backend guidelines**：前端和后端开发指南，规范开发标准，图中可见，但仓库上下文未进一步说明。
- **/core-style STYLE.md**：项目风格指南，定义代码风格和用户界面风格，由 `/core-style` 命令生成。
- **Requirement-Level Development**：基于具体需求进行开发工作的阶段。
- **/flow:init harness:init + harness:pack**：初始化流程，执行 `harness:init` 和 `harness:pack` 命令，用于初始化需求目录结构和打包运行时上下文。
- **/flow:spec harness:plan task-manifest**：需求规格说明流程，执行 `harness:plan` 命令，生成任务清单。
- **/flow:dev harness:dispatch/resume runtime-events**：开发流程，执行 `harness:dispatch` 或 `harness:resume` 命令，处理运行时事件。
- **/flow:verify harness:verify report-card**：验证流程，执行 `harness:verify` 命令，生成报告卡。
- **/flow:release harness:release/janitor release-note**：发布流程，执行 `harness:release` 和 `harness:janitor` 命令，生成发布说明。
- **Release Complete**：流程的终点，代表项目发布完成。

## 连线、分支与汇聚关系
- `Start Project -> ProjectLevel Setup`：项目启动后进入项目级别配置阶段。
- `ProjectLevel Setup -> /core-roadmap ROADMAP.md & BACKLOG.md`：项目级别配置阶段生成核心路线图。
- `ProjectLevel Setup -> /core-architecture ARCHITECTURE.md`：项目级别配置阶段生成核心架构文档。
- `ProjectLevel Setup -> /core-guidelines frontend/backend guidelines`：项目级别配置阶段生成开发指南。
- `ProjectLevel Setup -> /core-style STYLE.md`：项目级别配置阶段生成风格指南。
- `/core-roadmap ROADMAP.md & BACKLOG.md -> Requirement-Level Development`：核心路线图作为需求级别开发的输入。
- `/core-architecture ARCHITECTURE.md -> Requirement-Level Development`：核心架构文档作为需求级别开发的输入。
- `/core-guidelines frontend/backend guidelines -> Requirement-Level Development`：开发指南作为需求级别开发的输入。
- `/core-style STYLE.md -> Requirement-Level Development`：风格指南作为需求级别开发的输入。
- `Requirement-Level Development -> /flow:init harness:init + harness:pack`：需求级别开发后，执行初始化流程。
- `/flow:init harness:init + harness:pack -> /flow:spec harness:plan task-manifest`：初始化流程后，执行需求规格说明流程。
- `/flow:spec harness:plan task-manifest -> /flow:dev harness:dispatch/resume runtime-events`：需求规格说明流程后，进入开发流程。
- `/flow:dev harness:dispatch/resume runtime-events -> /flow:verify harness:verify report-card`：开发流程后，执行验证流程。
- `/flow:verify harness:verify report-card -> /flow:release harness:release/janitor release-note`：验证流程后，执行发布流程。
- `/flow:release harness:release/janitor release-note -> Release Complete`：发布流程完成后，项目发布完成。
- `/flow:verify harness:verify report-card -.-> Requirement-Level Development`：验证流程可以重新回到需求级别开发阶段，允许在任何阶段重新验证。

## 仓库语境与术语解释
- **Harness-First**：README 提到，该项目采用“Harness-First”的开发流程，即以 `harness:*` 命令链驱动开发。
- **/flow:init**：用于初始化需求目录结构和打包运行时上下文，是 canonical mainline 的第一步。
- **/flow:spec**：用于构建任务清单，是 canonical mainline 的第二步。
- **/flow:dev**：用于分发和执行任务，是 canonical mainline 的第三步。
- **/flow:verify**：用于运行报告卡门禁，是 canonical mainline 的第四步。
- **/flow:release**：用于发布，是 canonical mainline 的最后一步。
- **ROADMAP.md & BACKLOG.md**：由 `/core-roadmap` 命令生成，包含产品愿景、目标、季度规划和里程碑定义。
- **STYLE.md**：由 `/core-style` 命令生成，作为项目级别的设计 Single Source of Truth (SSOT)。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 `cc-devflow` 项目的开发流程，从“Start Project”开始，经过“Project-Level Setup”生成核心文档，进入“Requirement-Level Development”阶段，然后依次执行 `/flow:init`、`/flow:spec`、`/flow:dev`、`/flow:verify` 和 `/flow:release` 命令，最终到达“Release Complete”。其中，`/core-roadmap` 命令用于生成 `ROADMAP.md` 和 `BACKLOG.md`，而 `/flow:init` 命令用于初始化需求结构，是整个流程的关键步骤。验证阶段可以重新回到需求级别开发，形成迭代。
