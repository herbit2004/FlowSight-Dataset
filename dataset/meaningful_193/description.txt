## 图类型与用途
该图是一个流程图，描述了用户发起订单到完成支付的完整流程。它展示了订单创建、库存和优惠验证、支付方式选择以及支付结果通知等关键步骤。该图可以帮助理解电商平台或类似系统的订单支付逻辑。

## 图的整体布局
该图采用从左到右的布局方式。流程从“用户发起订单”开始，经过一系列处理和判断，最终到达“结束”节点。整体呈现一个线性的流程，包含多个分支。

## 分组/子图/阶段说明
图中有一个名为“订单创建与支付流程”的子图，包含了整个流程的所有节点和连线。

## 节点逐项说明
- **用户发起订单**：用户在系统前端发起一个订单。
- **验证库存与优惠**：系统验证订单中商品的库存是否充足，以及用户是否使用了有效的优惠券。
- **生成待支付订单**：如果库存充足且优惠有效，系统生成一个待支付的订单。
- **选择支付方式**：用户选择使用微信支付或支付宝支付。
- **微信支付网关**：微信支付的接口网关。
- **支付宝支付网关**：支付宝支付的接口网关。
- **拉起微信支付**：调用微信支付接口，拉起微信支付页面。
- **拉起支付宝支付**：调用支付宝支付接口，拉起支付宝支付页面。
- **用户完成支付**：用户在微信或支付宝页面完成支付操作。
- **订单状态更新为已支付**：如果支付成功，系统将订单状态更新为已支付。
- **订单状态更新为待支付**：如果支付失败，系统将订单状态更新为待支付。
- **发送支付成功通知**：系统向用户发送支付成功的通知。
- **发送支付失败通知**：系统向用户发送支付失败的通知。
- **提示库存不足**：如果库存不足，系统提示用户库存不足。
- **提示优惠已失效**：如果优惠已失效，系统提示用户优惠已失效。
- **结束**：流程结束。

## 连线、分支与汇聚关系
- 用户发起订单 -> 验证库存与优惠：发起订单后，进入库存和优惠验证环节。
- 验证库存与优惠 -- 库存充足 & 优惠有效 --> 生成待支付订单：如果库存充足且优惠有效，则生成待支付订单。
- 验证库存与优惠 -- 库存不足 --> 提示库存不足：如果库存不足，则提示库存不足。
- 验证库存与优惠 -- 优惠失效 --> 提示优惠已失效：如果优惠失效，则提示优惠已失效。
- 生成待支付订单 -> 选择支付方式：生成待支付订单后，进入支付方式选择环节。
- 选择支付方式 -- 微信支付 --> 微信支付网关：选择微信支付，进入微信支付网关。
- 选择支付方式 -- 支付宝支付 --> 支付宝支付网关：选择支付宝支付，进入支付宝支付网关。
- 微信支付网关 -> 拉起微信支付：通过微信支付网关拉起微信支付。
- 支付宝支付网关 -> 拉起支付宝支付：通过支付宝支付网关拉起支付宝支付。
- 拉起微信支付 -> 用户完成支付：用户在微信支付页面完成支付。
- 拉起支付宝支付 -> 用户完成支付：用户在支付宝支付页面完成支付。
- 用户完成支付 -- 支付成功 --> 订单状态更新为已支付：如果支付成功，则更新订单状态为已支付。
- 用户完成支付 -- 支付失败 --> 订单状态更新为待支付：如果支付失败，则更新订单状态为待支付。
- 订单状态更新为已支付 -> 发送支付成功通知：支付成功后，发送支付成功通知。
- 订单状态更新为待支付 -> 发送支付失败通知：支付失败后，发送支付失败通知。
- 发送支付成功通知 -> 结束：发送支付成功通知后，流程结束。
- 发送支付失败通知 -> 结束：发送支付失败通知后，流程结束。
- 提示库存不足 -> 结束：提示库存不足后，流程结束。
- 提示优惠已失效 -> 结束：提示优惠已失效后，流程结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **订单**：用户在电商平台或类似系统中购买商品的请求。
- **库存**：系统中可供销售的商品数量。
- **优惠**：用户可以享受的折扣或促销活动。
- **支付网关**：连接电商平台和支付渠道（如微信支付、支付宝）的接口。
- **支付成功通知**：系统向用户发送的支付成功的消息。
- **支付失败通知**：系统向用户发送的支付失败的消息。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起订单，系统验证库存和优惠。如果库存充足且优惠有效，则生成待支付订单，用户选择微信或支付宝支付，系统拉起相应的支付页面。用户完成支付后，如果支付成功，订单状态更新为已支付，并发送支付成功通知；如果支付失败，订单状态更新为待支付，并发送支付失败通知。如果库存不足或优惠失效，系统会提示相应的错误信息，流程结束。
