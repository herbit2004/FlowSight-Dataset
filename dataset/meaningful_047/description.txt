## Diagram Type & Purpose
This is a flowchart diagram illustrating the data masking and encryption flow within a system. It outlines the steps involved in processing incoming data, identifying personally identifiable information (PII), and applying appropriate masking or encryption techniques before storing the data. The diagram serves as a visual representation of the data security process.

## Overall Layout
The diagram has a left-to-right (LR) flow. It starts with an "Incoming Data Feed" node and ends with a "Data Storage" node. The diagram depicts a linear flow with branching based on the presence of PII and the application of masking or encryption rules.

## Edges, Branches & Convergence
- `A --> B`: Data flows from the incoming feed to the PII check.
- `B -- Yes --> C`: If PII is present, the data is sent to the PII Identification Module.
- `B -- No --> F`: If PII is not present, the data is directly sent to Data Storage.
- `C --> D`: Identified PII data flows to the Masking/Encryption Rule Engine.
- `D -- Apply Masking --> E`: The Masking/Encryption Rule Engine triggers the Data Masking Module.
- `D -- Apply Encryption --> G`: The Masking/Encryption Rule Engine triggers the Data Encryption Module.
- `E --> F`: Masked data flows to Data Storage.
- `G --> F`: Encrypted data flows to Data Storage.
- Paths `E` and `G` converge at `F`.

## Repository Context & Terminology
- **PII (Personally Identifiable Information)**: Data that can be used to identify an individual, such as name, address, or social security number.
- **Data Masking**: A technique to hide sensitive data by replacing it with modified or fabricated data.
- **Data Encryption**: A technique to convert data into a coded form to prevent unauthorized access.
- **Rule Engine**: A software system that executes rules to automate decision-making processes.
- **Module**: A self-contained component of a larger system.
- **Data Storage**: The location where data is stored, such as a database or file system.
