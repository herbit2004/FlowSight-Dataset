## 图类型与用途
该图是一个流程图，描述了从交易数据准备到最终清算的完整对账结算流程。它展示了数据准备、对账处理和结算清算三个主要阶段，以及每个阶段中的关键步骤和决策点。该图可以用于理解和优化对账结算流程。

## 图的整体布局
该图采用从上到下的布局，整体呈现出层次分明的结构。流程从“数据准备”子图开始，依次经过“对账处理”和“结算与清算”子图，最终到达“执行清算”或“结算单修改”节点。

## 分组/子图/阶段说明
图中包含三个子图，分别代表对账结算流程的三个主要阶段：
- **数据准备**：包括提取交易数据、转换数据格式、数据校验和生成对账文件等步骤。
- **对账处理**：包括获取三方对账文件、判断文件格式是否一致、执行对账和差异分析与调整等步骤。
- **结算与清算**：包括提交结算单、财务审核、执行清算和结算单修改等步骤。

## 节点逐项说明
- **提取交易数据**：从系统中提取需要进行对账的交易数据。
- **转换数据格式**：将提取的交易数据转换为统一的格式，方便后续处理。
- **数据校验**：对转换后的数据进行校验，确保数据的准确性和完整性。
- **生成对账文件**：根据校验通过的数据生成对账文件。
- **异常处理**：当数据校验失败时，进行异常处理，例如记录错误日志或通知相关人员。
- **获取三方对账文件**：获取来自第三方的对账文件。
- **文件格式一致?**：判断三方对账文件格式是否与系统要求的格式一致。
- **执行对账**：将系统生成的对账文件与三方对账文件进行比对，查找差异。
- **格式转换或人工介入**：当文件格式不一致时，进行格式转换或人工介入处理。
- **对账结果一致?**：判断对账结果是否一致。
- **生成结算单**：如果对账结果一致，则生成结算单。
- **差异分析与调整**：如果对账结果不一致，则进行差异分析与调整，找出差异原因并进行相应处理。
- **提交结算单**：将生成的结算单提交给财务部门进行审核。
- **财务审核**：财务部门对结算单进行审核。
- **审核通过?**：判断财务审核是否通过。
- **执行清算**：如果财务审核通过，则执行清算操作。
- **结算单修改**：如果财务审核未通过，则修改结算单。

## 连线、分支与汇聚关系
- A -> B：提取交易数据后，转换数据格式。
- B -> C：转换数据格式后，进行数据校验。
- C -- 校验通过 --> D：数据校验通过后，生成对账文件。
- C -- 校验失败 --> E：数据校验失败后，进行异常处理。
- D -> F：生成对账文件后，获取三方对账文件。
- F -> G：获取三方对账文件后，判断文件格式是否一致。
- G -- Yes --> H：文件格式一致，执行对账。
- G -- No --> I：文件格式不一致，进行格式转换或人工介入。
- I -> H：格式转换或人工介入后，执行对账。
- H -> J：执行对账后，判断对账结果是否一致。
- J -- Yes --> K：对账结果一致，生成结算单。
- J -- No --> L：对账结果不一致，进行差异分析与调整。
- L -> H：差异分析与调整后，重新执行对账。
- K -> M：生成结算单后，提交结算单。
- M -> N：提交结算单后，进行财务审核。
- N -> O：财务审核后，判断审核是否通过。
- O -- Yes --> P：审核通过，执行清算。
- O -- No --> Q：审核未通过，修改结算单。
- Q -> N：修改结算单后，重新进行财务审核。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **对账**：核对账目，确保账目记录与实际情况相符。
- **结算**：根据对账结果，计算应收或应付的金额。
- **清算**：根据结算结果，进行资金的划拨和支付。
- **结算单**：记录结算金额和相关信息的单据。
- **三方对账文件**：由第三方提供的对账文件，用于与系统内部数据进行核对。
- **差异分析**：对对账结果不一致的情况进行分析，找出差异的原因。
- **财务审核**：财务部门对结算单进行审核，确保其准确性和合规性。

## 可作为 QA Ground Truth 的高信息密度摘要
流程开始于提取交易数据并转换格式，随后进行数据校验。若校验通过，则生成对账文件，并与获取的三方对账文件进行对账。若文件格式不一致，则进行格式转换或人工介入。对账结果一致则生成结算单，否则进行差异分析与调整后重新对账。结算单提交后经过财务审核，审核通过则执行清算，否则修改结算单后重新审核。
