## 图类型与用途
这是一个流程图，用于描述用户请求的分流和实验分组过程。该图展示了根据用户画像和实验配置，将用户分配到不同实验组的逻辑。该流程旨在实现个性化分流和实验效果评估。

## 图的整体布局
该图采用从上到下的布局。整体上分为“用户请求分流”和“实验配置校验”两个主要阶段。流程从“用户请求”开始，到“记录分流日志”结束。

## 分组/子图/阶段说明
图中包含两个子图：
- **用户请求分流**：描述了根据用户画像和个性化策略对用户请求进行分流的过程。
- **实验配置校验**：描述了校验实验配置，并根据配置有效性将用户分配到实验组或对照组的过程。

## 节点逐项说明
- **A[用户请求]**: 流程的起始节点，表示接收到的用户请求。
- **B{用户画像可用?}**: 判断用户画像是否可用的决策节点。
- **C[画像服务]**: 提供用户画像的服务。
- **D[默认分流配置]**: 使用默认的分流配置。
- **E[计算分流策略]**: 根据用户画像计算分流策略。
- **F{存在个性化策略?}**: 判断是否存在个性化策略的决策节点。
- **G[个性化分组]**: 根据个性化策略进行分组。
- **H[基于人群分组]**: 基于人群特征进行分组。
- **I[校验实验配置]**: 校验实验配置是否有效。
- **J{配置有效?}**: 判断实验配置是否有效的决策节点。
- **K[分配实验组]**: 将用户分配到实验组。
- **L[默认对照组]**: 将用户分配到默认对照组。
- **M[返回实验组]**: 返回用户所属的实验组。
- **N[记录分流日志]**: 记录用户的分流日志。

## 连线、分支与汇聚关系
- A -> B：用户请求进入用户画像可用性判断。
- B -- 是 --> C：如果用户画像可用，则使用画像服务。
- B -- 否 --> D：如果用户画像不可用，则使用默认分流配置。
- C -> E：画像服务输出到计算分流策略。
- E -> F：计算分流策略后判断是否存在个性化策略。
- F -- 是 --> G：如果存在个性化策略，则进行个性化分组。
- F -- 否 --> D：如果不存在个性化策略，则使用默认分流配置。
- D -> H：默认分流配置后进行基于人群分组。
- H -> I：基于人群分组后校验实验配置。
- I -> J：校验实验配置后判断配置是否有效。
- J -- 是 --> K：如果配置有效，则分配实验组。
- J -- 否 --> L：如果配置无效，则分配默认对照组。
- K -> M：分配实验组后返回实验组。
- L -> M：分配默认对照组后返回实验组。
- M -> N：返回实验组后记录分流日志。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **用户画像**：对用户特征的抽象描述，用于个性化推荐和分流。
- **分流策略**：将用户分配到不同实验组的规则或算法。
- **实验组**：接受特定实验处理的用户群体。
- **对照组**：不接受实验处理，作为参照的用户群体。
- **实验配置**：实验相关的参数和设置，如流量比例、目标人群等。
- **分流日志**：记录用户分流信息的日志，用于后续分析。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先判断用户画像是否可用，可用则通过画像服务计算分流策略，并判断是否存在个性化策略，存在则进行个性化分组，否则使用默认分流配置；用户画像不可用则直接使用默认分流配置，然后基于人群分组。分组后校验实验配置，配置有效则分配实验组，否则分配默认对照组。最后返回实验组并记录分流日志。
