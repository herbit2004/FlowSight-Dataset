## 图类型与用途
这是一个系统架构图，描述了基于BBOT的OSINT（开源情报）持续监控系统的架构。该系统通过FastAPI服务自动化目标扫描，并将数据存储在Neo4j数据库中，同时提供API接口和监控仪表盘，Caddy作为反向代理。

## 图的整体布局
图整体采用从上到下的布局，分为客户端层、VPS服务器层和外部服务层三个主要部分。客户端层位于顶部，外部服务层位于底部。

## 分组/子图/阶段说明
图中包含三个显式子图：
- **Client Layer（客户端层）**：包含与系统交互的客户端组件。
- **VPS Server（VPS服务器）**：包含Caddy反向代理和内部网络，内部网络又包含FastAPI服务和Neo4j数据库。
- **External Services（外部服务）**：包含BBOT模块和Telegram Bot API。

## 节点逐项说明
- **A (Cursor IDE MCP Query Only)**：使用Cursor IDE进行MCP查询的客户端，仅用于查询操作。
- **B (Monitoring Dashboard)**：监控仪表盘，用于可视化展示扫描结果和系统状态。
- **C (API Client/Script)**：API客户端或脚本，用于通过API接口与系统交互。
- **D (Caddy Reverse Proxy Port 80/443 Let's Encrypt TLS)**：Caddy反向代理服务器，监听80和443端口，使用Let's Encrypt提供TLS加密，负责将客户端请求转发到内部网络的服务。根据`reverse-proxy/Caddyfile`，Caddy配置了反向代理到`osint:8000`，并设置了X-Forwarded-Proto等header。
- **E (FastAPI Service Port 8000 + Continuous Scanner)**：FastAPI服务，监听8000端口，包含持续扫描器。它是系统的核心组件，负责接收请求、启动扫描、处理数据和通知。根据`services/osint/app/main.py`，FastAPI服务启动时会加载`init_config.json`，并启动持续扫描器。
- **F (Neo4j Database Port 7687)**：Neo4j图数据库，监听7687端口，用于存储扫描结果。
- **G (BBOT Modules SecurityTrails, Shodan, VirusTotal, etc.)**：BBOT模块，包含SecurityTrails、Shodan、VirusTotal等外部服务，用于执行实际的OSINT扫描。`init_config.json.example`中列出了可配置的BBOT模块及其API密钥。
- **H (Telegram Bot API)**：Telegram Bot API，用于发送周期性扫描完成的通知。

## 连线、分支与汇聚关系
- `A -> D`：Cursor IDE通过MCP查询HTTPS请求发送到Caddy反向代理。
- `B -> D`：监控仪表盘通过HTTPS API请求发送到Caddy反向代理。
- `C -> D`：API客户端/脚本通过HTTPS API请求发送到Caddy反向代理。
- `D -> E`：Caddy反向代理将请求转发到FastAPI服务。
- `E -> F`：FastAPI服务将扫描数据摄取（Ingest Data）到Neo4j数据库。
- `E -> E`：FastAPI服务内部存在一个自动扫描循环（Auto Scan Loop），实现持续扫描。
- `E -> G`：FastAPI服务通过持续扫描（Continuous Scan）调用BBOT模块。
- `E -> H`：FastAPI服务在扫描周期完成后，通过Telegram Bot API发送通知（Cycle Complete Notify）。

## 仓库语境与术语解释
- **BBOT**：是一个开源情报（OSINT）框架，用于自动化信息收集。
- **FastAPI**：是一个现代、快速（高性能）的Web框架，用于构建API。
- **Neo4j**：是一个图数据库，用于存储和查询关联数据。`docs/DATA_MODEL.md`描述了Neo4j的数据模型。
- **Caddy**：是一个快速、易于使用的Web服务器，具有自动HTTPS功能。
- **MCP (Cursor IDE MCP Query Only)**：Cursor IDE 使用的查询协议，用于从系统中检索数据。
- **init_config.json**：是系统的配置文件，包含目标、API密钥、扫描参数等。`docs/INIT_CONFIG_GUIDE.md`提供了编写`init_config.json`的指南。
- **Continuous Scanner**：持续扫描器，根据`services/osint/app/scheduler.py`，它会定期扫描目标，并将结果存储到Neo4j数据库中。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个基于BBOT的OSINT持续监控系统架构。客户端（Cursor IDE、监控仪表盘、API客户端）通过HTTPS请求与Caddy反向代理交互，Caddy将请求转发到FastAPI服务。FastAPI服务是核心，它启动持续扫描器，调用BBOT模块进行扫描，并将扫描数据摄取到Neo4j数据库。扫描周期完成后，系统通过Telegram Bot API发送通知。`init_config.json`用于配置扫描目标和API密钥，Caddy根据`reverse-proxy/Caddyfile`进行反向代理配置。
