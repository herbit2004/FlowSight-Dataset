## 图类型与用途
这是一个流程图，描述了扫描和利用 Fast Pair 设备漏洞的流程。它在仓库中的作用是展示如何检测设备是否存在 CVE-2025-36911 (WhisperPair) 漏洞并进行利用，如 README 所述，该工具旨在帮助安全研究人员、设备制造商和终端用户识别需要固件更新的易受攻击设备。

## 图的整体布局
图整体采用从左到右的布局。起点是扫描设备，终点是访问麦克风。流程主要分为扫描、漏洞测试、利用和连接四个阶段。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为四个阶段：设备扫描与识别、漏洞测试、漏洞利用（如果存在）和连接与访问。

## 节点逐项说明
- **Scan**：扫描周围的设备，寻找支持 Fast Pair 的设备。根据 README，该步骤对应于发现广播 0xFE2C 服务 UUID 的 Fast Pair 设备。
- **Fast Pair Device?**：判断扫描到的设备是否是 Fast Pair 设备。
- **Test Vulnerability**：如果设备是 Fast Pair 设备，则对其进行漏洞测试，检测是否存在 CVE-2025-36911 漏洞。README 提到这是一种非侵入式检查，用于确定设备是否已针对 CVE-2025-36911 打了补丁。
- **Vulnerable?**：判断漏洞测试的结果，确定设备是否存在漏洞。
- **Exploit**：如果设备存在漏洞，则尝试利用该漏洞。README 指出，这是为了演示完整的利用链，包括基于密钥的配对绕过、BR/EDR 地址提取、蓝牙经典绑定和帐户密钥持久性。
- **Patched ✓**：如果设备不存在漏洞，则表示设备已打补丁。
- **Pair Device**：利用漏洞成功后，尝试与设备配对。
- **Connect HFP**：配对成功后，尝试连接设备的 HFP (Hands-Free Profile)。
- **Access Microphone**：连接 HFP 后，尝试访问设备的麦克风。README 说明这用于演示利用后的麦克风访问。

## 连线、分支与汇聚关系
- `A (Scan) -> B (Fast Pair Device?)`：扫描设备后，判断是否为 Fast Pair 设备。
- `B (Fast Pair Device?) -- Yes --> C (Test Vulnerability)`：如果是 Fast Pair 设备，则进行漏洞测试。
- `B (Fast Pair Device?) -- No --> A (Scan)`：如果不是 Fast Pair 设备，则返回扫描阶段。
- `C (Test Vulnerability) -> D (Vulnerable?)`：漏洞测试后，判断是否存在漏洞。
- `D (Vulnerable?) -- Yes --> E (Exploit)`：如果存在漏洞，则进行漏洞利用。
- `D (Vulnerable?) -- No --> F (Patched ✓)`：如果不存在漏洞，则认为设备已打补丁。
- `E (Exploit) -> G (Pair Device)`：漏洞利用成功后，尝试与设备配对。
- `G (Pair Device) -> H (Connect HFP)`：配对成功后，连接 HFP。
- `H (Connect HFP) -> I (Access Microphone)`：连接 HFP 后，访问麦克风。

## 仓库语境与术语解释
- **Fast Pair**：Google 的快速配对协议，存在 CVE-2025-36911 漏洞，允许未经授权的配对和潜在的麦克风访问。
- **CVE-2025-36911 (WhisperPair)**：一个影响 Google Fast Pair 协议的漏洞，允许攻击者在未经用户同意的情况下与受害者的耳机配对。
- **HFP (Hands-Free Profile)**：蓝牙协议中的免提配置文件，用于音频设备。
- **Account Key**：用于持久设备跟踪的密钥，该工具不包含 FMDN 配置功能，因此不涉及 Account Key 写入。
- **BLE Scanner**：用于发现广播 0xFE2C 服务 UUID 的 Fast Pair 设备的组件，如 README 的 Features 表格中所述。
- **Vulnerability Tester**：用于非侵入式地检查设备是否已针对 CVE-2025-36911 打补丁的组件，如 README 的 Features 表格中所述。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 WPair 工具如何扫描 Fast Pair 设备，检测 CVE-2025-36911 漏洞，并在漏洞存在时进行利用。流程从扫描设备开始，判断是否为 Fast Pair 设备，如果是，则进行漏洞测试。如果设备存在漏洞，则尝试利用漏洞进行配对，连接 HFP 并访问麦克风。如果设备不存在漏洞，则认为设备已打补丁。该流程的关键分支在于漏洞测试的结果，决定了是否进入漏洞利用阶段。该工具旨在帮助识别需要固件更新的易受攻击设备。
