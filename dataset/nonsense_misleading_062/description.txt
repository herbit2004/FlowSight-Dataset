## Edges, Branches & Convergence
- `A --> B`: User places an order, initiating the payment verification process.
- `B -- No --> C`: If payment is not received, the order is cancelled.
- `B -- Yes --> D`: If payment is received, fulfillment begins.
- `D --> E`: Fulfillment begins, leading to an inventory check.
- `E -- No --> F`: If inventory is not available, a backorder is placed.
- `F --> D`: Backorder placed loops back to Fulfillment Begins (illogical loop).
- `E -- Yes --> G`: If inventory is available, the order is packed.
- `G --> H`: Order packed, leading to shipping label creation.
- `H --> I`: Shipping label created, leading to package shipment.
- `I --> J`: Package shipped, leading to a delivery success check.
- `J -- No --> K`: If delivery is not successful, a refund is processed.
- `K --> L`: Refund processed, leading to order completion.
- `J -- Yes --> M`: If delivery is successful, the customer is notified (incorrect branch).
- `M --> C`: Customer notified leads back to order cancellation (wrong causal direction).
- `C --> L`: Order cancelled leads to order completion (reversed sequence).

If payment is not received, the "Order Cancelled" node is reached, which then proceeds to "Order Completed." If payment is received, "Fulfillment Begins," leading to an "Inventory Available?" decision.
