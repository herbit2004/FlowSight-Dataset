## 图类型与用途
这是一个流程图，描述 Kubernetes Reloader 组件如何监听 Secret 和 ConfigMap 的变化，并触发工作负载的滚动更新。它在仓库中的作用是展示 Reloader 的核心工作流程。

## 图的整体布局
图整体采用从左到右的布局。左侧是 Secret 和 ConfigMap 的来源，中间是 Reloader 组件，右侧是被触发滚动更新的工作负载类型和通知渠道。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：配置来源、Reloader 监听与触发、工作负载更新与通知。

## 节点逐项说明
- **ExternalSecret**：表示外部 Secret 管理系统，负责创建和管理 Secret。
- **SealedSecret**：表示 SealedSecret，一种加密的 Secret，负责创建和管理 Secret。
- **Certificate**：表示证书管理系统，负责创建和管理 Secret (通常用于存储证书)。
- **Secret**：Kubernetes Secret 对象，用于存储敏感信息，例如密码、令牌等。
- **ConfigMap**：Kubernetes ConfigMap 对象，用于存储非敏感的配置信息。
- **Reloader**：核心组件，即 Reloader 控制器，负责监听 Secret 和 ConfigMap 的变化，并触发工作负载的滚动更新。README 提到 Reloader 会 watch 这些资源。
- **Deployment**：Kubernetes Deployment 对象，用于管理无状态应用的部署。
- **DeploymentConfig**：OpenShift DeploymentConfig 对象，类似于 Deployment，用于管理无状态应用的部署。
- **Daemonset**：Kubernetes DaemonSet 对象，用于在每个节点上运行一个 Pod。
- **Statefulset**：Kubernetes StatefulSet 对象，用于管理有状态应用的部署。
- **ArgoRollout**：Argo Rollouts 对象，用于实现更高级的部署策略，如蓝绿部署、金丝雀发布等。
- **CronJob**：Kubernetes CronJob 对象，用于定时执行任务。
- **Slack,Teams,Webhook**：通知渠道，Reloader 可以通过这些渠道发送通知，告知用户工作负载已滚动更新。

## 连线、分支与汇聚关系
- `ExternalSecret -> Secret`：ExternalSecret 创建 Secret。
- `SealedSecret -> Secret`：SealedSecret 创建 Secret。
- `Certificate -> Secret`：Certificate 创建 Secret。
- `Secret -> Reloader`：Reloader 监听 Secret 的变化。
- `ConfigMap -> Reloader`：Reloader 监听 ConfigMap 的变化。
- `Reloader -> Deployment`：Reloader 触发 Deployment 的滚动更新。
- `Reloader -> DeploymentConfig`：Reloader 触发 DeploymentConfig 的滚动更新。
- `Reloader -> Daemonset`：Reloader 触发 Daemonset 的滚动更新。
- `Reloader -> Statefulset`：Reloader 触发 Statefulset 的滚动更新。
- `Reloader -> ArgoRollout`：Reloader 触发 ArgoRollout 的滚动更新。
- `Reloader -> CronJob`：Reloader 触发 CronJob 的 Job 创建。
- `Reloader -> Slack,Teams,Webhook`：Reloader 通过这些渠道发送通知。

## 仓库语境与术语解释
- **Reloader**: Kubernetes 控制器，用于监听 ConfigMap 和 Secret 的变化，并自动触发相关工作负载的滚动更新。
- **Secret**: Kubernetes 对象，用于存储敏感信息。
- **ConfigMap**: Kubernetes 对象，用于存储非敏感的配置信息。
- **Deployment, StatefulSet, DaemonSet, ArgoRollout, CronJob**: Kubernetes 工作负载类型，Reloader 可以触发这些工作负载的滚动更新。
- **Rolling Upgrade**: 一种部署策略，用于在不中断服务的情况下更新应用程序。`internal/pkg/handler/upgrade.go` 文件定义了不同类型 workload 的 rolling upgrade 函数。
- **Annotation**: Kubernetes 的一种元数据，用于为对象添加额外的配置信息。Reloader 使用 annotation 来指定需要监听的 ConfigMap 和 Secret。
- **CSI-mounted secrets**: README 提到 Reloader 可以监听 CSI 挂载的 secrets。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Reloader 的核心工作流程：ExternalSecret、SealedSecret 和 Certificate 等组件创建 Secret，Reloader 监听 Secret 和 ConfigMap 的变化，当这些资源发生变化时，Reloader 触发 Deployment、DeploymentConfig、Daemonset、Statefulset、ArgoRollout 和 CronJob 等工作负载的滚动更新，并通过 Slack、Teams 或 Webhook 发送通知。Reloader 的主要作用是自动化 Kubernetes 工作负载的滚动更新，确保应用程序能够及时应用最新的配置和密钥。`pkg/common/reload_source.go` 定义了 ReloadSource 结构体，用于描述触发 reload 的资源。
