## 图类型与用途
该图是一个流程图，描述了风控系统的整体架构和工作流程。它展示了数据接入、规则引擎、策略决策、监控反馈以及异常流程等关键环节。该图可以帮助理解风控系统的运作机制，以及各个模块之间的依赖关系。

## 图的整体布局
该图采用从上到下的布局，分为五个主要部分：数据接入与预处理、规则引擎核心、策略决策与执行、监控与反馈、异常流程。流程从用户行为事件和外部数据源开始，最终形成风控拦截/放行决策，并生成事件报告。

## 分组/子图/阶段说明
图中包含五个子图，分别代表风控系统的不同阶段：
- **数据接入与预处理**：负责收集和清洗数据，并进行特征工程。
- **规则引擎核心**：负责加载和管理规则，执行规则并计算风险评分。
- **策略决策与执行**：负责编排策略，根据优先级执行策略，并进行风控拦截或放行。
- **监控与反馈**：负责实时监控指标，评估模型效果，并进行规则优化和调整。
- **异常流程**：负责检测可疑交易，并进行人工介入。

## 节点逐项说明
- **A 用户行为事件**：用户在系统中的各种行为事件，例如登录、浏览、购买等。
- **B 外部数据源**：来自外部的数据，例如征信数据、黑名单数据等。
- **C 数据清洗与转换**：对原始数据进行清洗和转换，使其符合后续处理的要求。
- **D 特征工程**：从清洗后的数据中提取有用的特征，用于风险评估。
- **E 规则组加载与管理**：加载和管理风控规则，例如黑名单规则、信用评分规则等。
- **F 规则执行器**：执行风控规则，对用户行为进行评估。
- **G 风险评分计算**：根据规则执行结果，计算用户的风险评分。
- **H 决策结果输出**：输出风控决策结果，例如拦截或放行。
- **I 策略编排**：根据业务需求，编排不同的风控策略。
- **J 策略优先级排序**：对不同的风控策略进行优先级排序，确保高优先级策略优先执行。
- **K 策略执行**：执行风控策略，对用户行为进行干预。
- **L 风控拦截/放行**：根据策略执行结果，对用户行为进行拦截或放行。
- **M 生成事件报告**：生成风控事件报告，记录风控过程和结果。
- **N 实时监控指标**：实时监控风控指标，例如拦截率、通过率等。
- **O 模型效果评估**：评估风控模型的效果，例如准确率、召回率等。
- **P 规则优化与调整**：根据监控和评估结果，对风控规则进行优化和调整。
- **Q 人工审核**：对可疑交易进行人工审核，确保风控决策的准确性。
- **R 可疑交易检测**：检测可疑的交易行为，例如大额转账、异地登录等。
- **S 人工介入**：人工介入处理可疑交易，例如电话核实、冻结账户等。

## 连线、分支与汇聚关系
- A -> C：用户行为事件数据进入数据清洗与转换阶段。
- B -> C：外部数据源数据进入数据清洗与转换阶段。
- C -> D：清洗转换后的数据进入特征工程阶段。
- D -> E：特征工程后的数据用于规则组加载与管理。
- E -> F：加载的规则组传递给规则执行器。
- F -> G：规则执行器执行规则，计算风险评分。
- G -> H：风险评分计算结果输出决策结果。
- H -> I：决策结果用于策略编排。
- I -> J：策略编排后进行策略优先级排序。
- J -> K：排序后的策略被执行。
- K -> L：策略执行的结果是风控拦截或放行。
- K -> M：策略执行的结果同时生成事件报告。
- M -> N：生成的事件报告用于实时监控指标。
- L -> N：风控拦截/放行结果用于实时监控指标。
- N -> O：实时监控指标用于模型效果评估。
- O -> P：模型效果评估结果用于规则优化与调整。
- P -> E：规则优化与调整的结果反馈给规则组加载与管理。
- L -> Q：风控拦截/放行结果可能需要人工审核。
- Q -> P：人工审核的结果用于规则优化与调整。
- L -- 可疑 --> R：如果风控拦截/放行结果为可疑，则进入可疑交易检测。
- R -> S：可疑交易检测后可能需要人工介入。
- S -> Q：人工介入的结果用于人工审核。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **风控**：风险控制，指识别、评估和应对风险的过程。
- **规则引擎**：一种基于规则的决策系统，用于自动化决策过程。
- **策略编排**：将不同的风控策略组合在一起，形成一个完整的风控方案。
- **特征工程**：从原始数据中提取有用的特征，用于机器学习模型训练。
- **风险评分**：对用户或交易的风险程度进行量化评估。
- **拦截/放行**：根据风控策略，对用户行为进行阻止或允许。
- **人工审核**：由人工对可疑交易进行审查，以确保风控决策的准确性。

## 可作为 QA Ground Truth 的高信息密度摘要
风控系统从用户行为事件和外部数据源接入数据，经过数据清洗、转换和特征工程后，进入规则引擎。规则引擎加载规则组并执行，计算风险评分，输出决策结果。决策结果用于策略编排和优先级排序，最终执行策略进行风控拦截或放行，并生成事件报告。风控拦截/放行结果和事件报告用于实时监控指标，评估模型效果，并进行规则优化与调整。对于可疑交易，系统会进行检测并可能需要人工介入，人工审核结果也会用于规则优化。
