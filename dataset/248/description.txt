## 图类型与用途
这是一个架构图，展示了 Acontext 项目的整体架构，包括客户端层、后端服务和 Web Dashboard，以及它们之间的交互关系。Acontext 是一个用于构建 Agent Memory Stack 的工具或平台，该图旨在帮助理解其组件和数据流。

## 图的整体布局
图整体采用从上到下的分层布局。顶部是客户端层和 Dashboard，中间是 Acontext 后端，底部是基础设施层。数据流从客户端和 Dashboard 发起，经过后端处理，最终与基础设施交互。

## 分组/子图/阶段说明
图中包含三个显式子图：
- **Client Layer**：表示客户端层，包括 Python 和 TypeScript/JavaScript 客户端。
- **Acontext Backend**：表示 Acontext 后端服务，包含 API、Core 和 Infrastructures 三个部分。
- **Dashboard**：表示 Web Dashboard，用于管理和监控 Acontext 服务。

## 节点逐项说明
- **PY** (pip install acontext)：Python 客户端，可以通过 `pip install acontext` 安装。
- **TS** (npm i @acontext/acontext)：TypeScript/JavaScript 客户端，可以通过 `npm i @acontext/acontext` 安装。
- **API** (API localhost:8029)：后端 API 服务，监听在 `localhost:8029`。使用 FastAPI 和 RabbitMQ。
- **CORE** (Core)：Acontext 的核心逻辑组件。
- **Infrastructure** (Infrastructures)：基础设施层，包含 PostgreSQL 数据库、S3 对象存储、Redis 缓存和 RabbitMQ 消息队列。
- **PG** (PostgreSQL)：PostgreSQL 数据库，用于存储数据。
- **S3** (S3)：对象存储服务，用于存储文件或其他对象。
- **REDIS** (Redis)：Redis 缓存，用于缓存数据以提高性能。
- **MQ** (RabbitMQ)：RabbitMQ 消息队列，用于异步任务处理和组件间通信。
- **UI** (Web Dashboard localhost:3000)：Web 仪表盘，监听在 `localhost:3000`，用于管理和监控 Acontext 服务。

## 连线、分支与汇聚关系
- `PY -> API`：Python 客户端通过 RESTful API 与后端 API 服务交互。
- `TS -> API`：TypeScript/JavaScript 客户端通过 RESTful API 与后端 API 服务交互。
- `UI -> API`：Web 仪表盘通过 RESTful API 与后端 API 服务交互。
- `API -> CORE`：后端 API 服务通过 FastAPI 和 RabbitMQ 与核心逻辑组件交互。
- `API -> Infrastructure`：后端 API 服务与基础设施层交互。
- `CORE -> Infrastructure`：核心逻辑组件与基础设施层交互。
- `Infrastructure -> PG`：基础设施层连接到 PostgreSQL 数据库。
- `Infrastructure -> S3`：基础设施层连接到 S3 对象存储。
- `Infrastructure -> REDIS`：基础设施层连接到 Redis 缓存。
- `Infrastructure -> MQ`：基础设施层连接到 RabbitMQ 消息队列。

## 仓库语境与术语解释
- **Acontext**：一个开源 Agent Skills as a Memory Layer，自动捕获 agent 运行中的学习内容，并将知识存储为 Markdown 文件，如 README 所述。
- **Client Layer**：包含 Python 和 TypeScript/JavaScript 客户端，允许开发者与 Acontext 服务进行交互。
- **FastAPI**：一个现代、快速（高性能）的 Web 框架，用于构建 API。后端 API 服务使用 FastAPI 处理客户端请求。
- **RabbitMQ**：一个消息队列服务，用于异步任务处理和组件间通信。后端 API 服务和核心逻辑组件使用 RabbitMQ 进行通信。
- **Skill Memory**：Acontext 的核心概念，指自动捕获 agent 运行中的学习内容并存储为 Markdown 文件的能力，如 README 所述。
- **Infrastructure**：包括 PostgreSQL 数据库、S3 对象存储、Redis 缓存和 RabbitMQ 消息队列，为 Acontext 提供数据存储、缓存和异步消息处理等基础设施服务。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 Acontext 项目的分层结构，客户端层（Python 和 TypeScript/JavaScript 客户端以及 Web Dashboard）通过 RESTful API 与后端 API 服务交互。后端 API 服务使用 FastAPI 和 RabbitMQ 与核心逻辑组件交互，核心逻辑组件和 API 服务都与基础设施层（PostgreSQL、S3、Redis、RabbitMQ）交互。整体架构体现了客户端、后端服务和基础设施之间的清晰分离，以及 Acontext 作为 Agent Skills Memory Layer 的核心功能。
