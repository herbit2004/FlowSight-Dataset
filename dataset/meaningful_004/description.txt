## 图类型与用途
该图是一个流程图，描述了订单消息的生成和消费流程。它展示了用户服务如何产生订单事件，以及这些事件如何被路由到不同的队列，最终被不同的服务消费和处理。该图旨在说明订单消息处理的整体架构。

## 图的整体布局
该图采用从上到下的布局。整体上分为消息生成流程和消息消费流程两个主要部分。起点是用户服务，终点是通知服务。

## 分组/子图/阶段说明
图中包含两个子图：
- **消息生成流程**：描述了从用户服务产生订单事件到消息进入不同队列的过程。
- **消息消费流程**：描述了消息从队列被消费，经过处理和风控检查，最终更新数据或记录异常，并发送通知的过程。

## 节点逐项说明
- **用户服务**：产生订单创建事件的源头。
- **订单创建事件**：用户服务产生的事件，作为消息的起点。
- **消息路由规则**：根据订单类型将消息路由到不同的队列。
- **订单消息队列**：存储普通订单消息的队列。
- **特殊订单队列**：存储特殊订单消息的队列。
- **订单消息队列**：存储普通订单消息的队列，等待订单处理服务消费。
- **特殊订单队列**：存储特殊订单消息的队列，等待高优先级订单处理服务消费。
- **订单处理服务**：处理普通订单消息的服务。
- **高优先级订单处理服务**：处理特殊订单消息的服务。
- **风控检查**：对订单进行风险控制检查。
- **订单数据更新**：更新订单数据的服务。
- **异常订单记录**：记录异常订单的服务。
- **通知服务**：发送通知的服务。

## 连线、分支与汇聚关系
- 用户服务 -> 订单创建事件：产生订单事件。
- 订单创建事件 -> 消息路由规则：将订单事件传递给消息路由规则。
- 消息路由规则 -- 订单类型A --> 订单消息队列：根据订单类型A，将消息路由到订单消息队列。
- 消息路由规则 -- 订单类型B --> 特殊订单队列：根据订单类型B，将消息路由到特殊订单队列。
- 订单消息队列 -> 订单处理服务：订单消息队列中的消息被订单处理服务消费。
- 特殊订单队列 -> 高优先级订单处理服务：特殊订单队列中的消息被高优先级订单处理服务消费。
- 订单处理服务 -> 风控检查：订单处理服务将订单传递给风控检查。
- 高优先级订单处理服务 -> 风控检查：高优先级订单处理服务将订单传递给风控检查。
- 风控检查 -- 通过 --> 订单数据更新：如果风控检查通过，则更新订单数据。
- 风控检查 -- 拒绝 --> 异常订单记录：如果风控检查拒绝，则记录异常订单。
- 订单数据更新 -> 通知服务：订单数据更新后，发送通知。
- 异常订单记录 -> 通知服务：记录异常订单后，发送通知。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **用户服务**：提供用户相关功能的微服务。
- **订单创建事件**：用户下单时产生的事件消息。
- **消息队列**：用于存储和传递消息的中间件，例如 Kafka 或 RabbitMQ。
- **风控检查**：对订单进行风险控制的检查，例如欺诈检测。
- **通知服务**：用于发送通知的微服务，例如短信、邮件等。
- **订单处理服务**：负责处理订单相关业务逻辑的微服务。

## 可作为 QA Ground Truth 的高信息密度摘要
用户服务产生订单创建事件，消息路由规则根据订单类型将事件路由到订单消息队列或特殊订单队列。订单消息队列中的消息被订单处理服务消费，特殊订单队列中的消息被高优先级订单处理服务消费。订单经过风控检查，如果通过则更新订单数据，否则记录异常订单。最后，无论是订单数据更新还是异常订单记录，都会触发通知服务发送通知。
