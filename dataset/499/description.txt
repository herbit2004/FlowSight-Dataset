## Edges, Branches & Convergence
- `CloudFront CDN --> S3 (Frontend)`: Requests for static assets are routed to the S3 bucket.
- `CloudFront CDN --> API Gateway`: API requests are routed to the API Gateway.
- `API Gateway --> Lambda: Jobs Handler`: API Gateway routes job-related requests to the Jobs Handler Lambda function.
- `API Gateway --> Lambda: Repos Handler`: API Gateway routes repository-related requests to the Repos Handler Lambda function.
- `API Gateway --> Lambda: Authorizer`: API Gateway routes authentication requests to the Authorizer Lambda function.
- `Lambda: Jobs Handler --> Step Functions`: The Jobs Handler Lambda function triggers the Step Functions workflow.
- `Step Functions --> ECS Fargate (Processor)`: The Step Functions workflow triggers the ECS Fargate cluster to process the job.
- `ECS Fargate (Processor) --> DynamoDB`: The ECS Fargate cluster stores data in DynamoDB.
- `ECS Fargate (Processor) --> S3 (Artifacts)`: The ECS Fargate cluster stores artifacts in the S3 bucket.
- `ECS Fargate (Processor) --> Secrets Manager`: The ECS Fargate cluster retrieves secrets from Secrets Manager.

## Repository Context & Terminology
- **CloudFront CDN**: A content delivery network (CDN) service provided by AWS. It caches content at edge locations to reduce latency and improve performance.
- **S3 (Frontend)**: An Amazon S3 bucket used to host the static frontend application files (HTML, CSS, JavaScript).
- **API Gateway**: A fully managed service that makes it easy for developers to create, publish, maintain, monitor, and secure APIs at any scale.
- **Lambda**: A serverless compute service that lets you run code without provisioning or managing servers.
- **Step Functions**: A serverless orchestration service that lets you coordinate multiple AWS services into serverless workflows.
- **ECS Fargate**: A serverless compute engine for containers that works with Amazon Elastic Container Service (ECS).
- **DynamoDB**: A fully managed NoSQL database service that provides fast and predictable performance with seamless scalability.
- **Secrets Manager**: A service that helps you protect secrets needed to access your applications, services, and IT resources.

## High-Density QA Ground Truth Summary
The architecture begins with the CloudFront CDN, which serves as the entry point for all requests, handling both static assets and API calls. Static content requests are routed directly to S3 (Frontend), while API requests are forwarded to the API Gateway. The API Gateway then dispatches requests to different Lambda functions based on the endpoint: Lambda: Jobs Handler for job-related tasks, Lambda: Repos Handler for repository management, and Lambda: Authorizer for authentication. The Lambda: Jobs Handler triggers a Step Functions workflow to orchestrate complex job processing. This workflow then invokes an ECS Fargate cluster (Processor) to execute the core processing logic. The ECS Fargate cluster interacts with several backend services: it stores processed data in DynamoDB, saves generated artifacts in S3 (Artifacts), and retrieves sensitive information from Secrets Manager. The Lambda: Authorizer validates user credentials, ensuring secure access to the system. The system leverages serverless technologies like Lambda and Fargate to minimize operational overhead and scale efficiently. The use of CloudFront CDN ensures low latency and high availability for users accessing the application.
