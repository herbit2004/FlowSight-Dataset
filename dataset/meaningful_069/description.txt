## 图类型与用途
这是一个流程图，用于描述用户通过向导创建或加载草稿，并完成配置、关联数据、保存等步骤的流程。该图展示了用户与系统交互的各个阶段，以及验证和保存过程中的分支。

## 图的整体布局
该图采用从上到下的布局。流程从用户操作触发向导开始，经过一系列步骤和判断，最终完成草稿的保存。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. **草稿初始化阶段**：检查草稿是否存在，并创建或加载草稿。
2. **信息配置阶段**：配置基本信息和关联相关数据，并进行验证。
3. **保存阶段**：确认并保存草稿。

## 节点逐项说明
- **开始：用户操作触发向导**：流程的起始节点，表示用户开始使用向导。
- **检查草稿是否存在？**：判断是否存在已有草稿的决策节点。
- **加载已有草稿**：如果存在草稿，则加载已有草稿。
- **创建新草稿**：如果不存在草稿，则创建新草稿。
- **步骤一：配置基本信息**：配置草稿的基本信息。
- **验证基本信息？**：验证配置的基本信息是否正确。
- **步骤二：关联相关数据**：关联与草稿相关的其他数据。
- **验证关联数据？**：验证关联的数据是否正确。
- **步骤三：确认并保存**：确认草稿信息并进行保存。
- **保存草稿？**：判断草稿是否保存成功。
- **完成：草稿保存成功**：流程的结束节点，表示草稿保存成功。

## 连线、分支与汇聚关系
- A -> B：用户操作触发向导后，进入草稿检查环节。
- B -- 是 --> C：如果草稿存在，则加载已有草稿。
- B -- 否 --> D：如果草稿不存在，则创建新草稿。
- C -> E：加载已有草稿后，进入配置基本信息阶段。
- D -> E：创建新草稿后，进入配置基本信息阶段。
- E -> F：配置基本信息后，进行基本信息验证。
- F -- 失败 --> E：如果基本信息验证失败，则返回配置基本信息阶段。
- F -- 成功 --> G：如果基本信息验证成功，则进入关联相关数据阶段。
- G -> H：关联相关数据后，进行关联数据验证。
- H -- 失败 --> G：如果关联数据验证失败，则返回关联相关数据阶段。
- H -- 成功 --> I：如果关联数据验证成功，则进入确认并保存阶段。
- I -> J：确认并保存后，进行草稿保存。
- J -- 成功 --> K：如果草稿保存成功，则流程结束。
- J -- 失败 --> I：如果草稿保存失败，则返回确认并保存阶段。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **向导**：引导用户完成特定任务的交互式工具。
- **草稿**：未最终完成但已保存的部分数据或文档。
- **基本信息**：描述草稿主要内容的基础数据。
- **关联数据**：与草稿内容相关的其他数据或信息。
- **验证**：检查数据是否符合预定规则或标准的过程。
- **保存**：将数据存储到持久化存储介质中的操作。

## 可作为 QA Ground Truth 的高信息密度摘要
用户操作触发向导后，系统检查是否存在草稿。如果存在，则加载已有草稿；否则，创建新草稿。然后，用户配置基本信息并验证，成功后关联相关数据并验证。最后，用户确认并保存草稿，如果保存成功，则流程结束。如果验证或保存失败，则返回相应步骤重新操作。
