- `start --> setups`: Starts the process and moves to DI setups analysis.
- `setups -.-> failed`: If DI setups analysis has problems, the process goes to "Compilation failed".
- `setups --> types`: Proceeds to type analysis after DI setups analysis.

- `option -.-> failed`: If there are no other options when selecting a dependency set, the process goes to "Compilation failed".
- `creating --> verification`: Verifies the dependency graph variant after creating it.
- `verification --> option`: If verification has problems, the process loops back to selecting a next dependency set.
- `verification --> codeGeneration`: If verification is correct, the process proceeds to code generation.

- `compilation -.-> failed`: If compilation has problems, the process goes to "Compilation failed".

## Repository Context & Terminology
- **Dependency Injection (DI)**: A design pattern in which one or more dependencies (or services) are injected into a dependent object. This is a fundamental concept in modern software development, promoting loose coupling and testability.
- **Type Analysis**: The process of examining the types of variables, expressions, and functions in a program to ensure type safety and correctness.
- **Dependency Graph**: A directed graph representing dependencies between software components. Nodes represent components, and edges represent dependencies.
- **Code Generation**: The process of automatically generating source code from a higher-level description or model.
- **Compilation**: The process of translating source code into machine code or bytecode that can be executed by a computer.
