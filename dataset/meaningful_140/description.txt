## 图类型与用途
该图是一个流程图，描述了多租户应用中请求的路由和处理流程。它展示了来自不同租户的请求如何通过 API 网关，经过租户 ID 识别和路由规则，最终访问各自的计算资源和数据库。该图体现了多租户架构下资源隔离和请求分发的关键步骤。

## 图的整体布局
该图采用从上到下的布局。整体上分为两个租户的请求处理流程，每个流程都从租户的请求开始，最终到达租户的数据库。API Gateway 作为统一入口，租户 ID 识别是关键的分支点。

## 分组/子图/阶段说明
图中包含两个子图：Tenant A 和 Tenant B，分别代表两个不同的租户。每个租户的处理流程可以分为以下阶段：
1.  请求发起阶段：租户发起请求。
2.  统一接入阶段：请求到达 API Gateway。
3.  租户识别与路由阶段：识别租户 ID 并根据路由规则进行分发。
4.  资源访问阶段：访问租户专属的计算资源和数据库。

## 节点逐项说明
- **Tenant A 请求**：Tenant A 发起的请求。
- **API Gateway**：API 网关，作为所有请求的统一入口。
- **Tenant B 请求**：Tenant B 发起的请求。
- **租户 ID 识别**：根据请求中的信息识别租户 ID。
- **Tenant A 路由规则**：Tenant A 的路由规则，用于将请求路由到 Tenant A 的计算资源。
- **Tenant B 路由规则**：Tenant B 的路由规则，用于将请求路由到 Tenant B 的计算资源。
- **Tenant A 计算资源**：Tenant A 专属的计算资源。
- **Tenant B 计算资源**：Tenant B 专属的计算资源。
- **Tenant A 数据库**：Tenant A 专属的数据库。
- **Tenant B 数据库**：Tenant B 专属的数据库。

## 连线、分支与汇聚关系
- Tenant A 请求 -> API Gateway：Tenant A 的请求发送到 API Gateway。
- Tenant B 请求 -> API Gateway：Tenant B 的请求发送到 API Gateway。
- API Gateway -> 租户 ID 识别：API Gateway 将请求发送到租户 ID 识别模块。
- 租户 ID 识别 -- Tenant A --> Tenant A 路由规则：如果识别出是 Tenant A 的请求，则根据 Tenant A 的路由规则进行路由。
- 租户 ID 识别 -- Tenant B --> Tenant B 路由规则：如果识别出是 Tenant B 的请求，则根据 Tenant B 的路由规则进行路由。
- Tenant A 路由规则 -> Tenant A 计算资源：Tenant A 的请求被路由到 Tenant A 的计算资源。
- Tenant B 路由规则 -> Tenant B 计算资源：Tenant B 的请求被路由到 Tenant B 的计算资源。
- Tenant A 计算资源 -> Tenant A 数据库：Tenant A 的计算资源访问 Tenant A 的数据库。
- Tenant B 计算资源 -> Tenant B 数据库：Tenant B 的计算资源访问 Tenant B 的数据库。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **多租户**：一种软件架构，其中单个软件实例服务于多个租户（客户或组织）。
- **API Gateway**：API 网关，作为所有 API 请求的入口点，负责路由、认证、授权等功能。
- **租户 ID**：用于标识不同租户的唯一标识符。
- **路由规则**：根据租户 ID 将请求路由到相应计算资源的规则。
- **计算资源**：用于执行计算任务的服务器、虚拟机等资源。
- **数据库**：用于存储数据的系统。
