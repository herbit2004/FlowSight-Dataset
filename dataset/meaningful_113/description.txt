## 图类型与用途
该图是一个流程图，描述了用户支付请求从发起经过聚合支付平台、商户系统到清算系统的完整流程。它展示了支付、对账和清算之间的交互关系。该图可以帮助理解支付系统的整体架构和数据流。

## 图的整体布局
该图采用从上到下的布局方式。整体分为三个主要层次：聚合支付平台、商户系统和清算系统。流程从用户支付请求开始，最终生成清算报表。

## 分组/子图/阶段说明
图中包含三个子图，分别代表：
- **聚合支付平台**：处理用户支付请求，与第三方支付交互。
- **商户系统**：接收支付结果，更新订单状态，发起对账请求，处理对账文件。
- **清算系统**：接收对账数据，生成清算报表。

## 节点逐项说明
- **A (用户支付请求)**：用户发起的支付请求。
- **B (创建支付订单)**：聚合支付平台创建支付订单。
- **C (提交至第三方支付)**：将支付订单提交给第三方支付平台。
- **D (第三方支付处理)**：第三方支付平台处理支付请求。
- **E (第三方支付回调)**：第三方支付平台回调通知支付结果。
- **F (回调验签与状态更新)**：聚合支付平台验证回调签名并更新支付状态。
- **G (通知商户系统)**：聚合支付平台通知商户系统支付结果。
- **H (接收支付结果)**：商户系统接收支付结果。
- **I (更新用户订单状态)**：商户系统更新用户订单状态。
- **J (发起对账请求)**：商户系统发起对账请求。
- **K (接收对账文件)**：商户系统接收对账文件。
- **L (对账处理)**：商户系统进行对账处理。
- **M (生成对账差异报告)**：商户系统生成对账差异报告。
- **N (接收对账数据)**：清算系统接收对账数据。
- **O (生成清算报表)**：清算系统生成清算报表。

## 连线、分支与汇聚关系
- A -> B：用户支付请求触发创建支付订单。
- B -> C：创建支付订单后提交至第三方支付。
- C -> D：第三方支付平台处理支付请求。
- D -> E：第三方支付平台回调通知支付结果。
- E -> F：回调后进行验签和状态更新。
- F -> G：更新状态后通知商户系统。
- G -> H：商户系统接收支付结果。
- H -> I：商户系统更新用户订单状态。
- I -> J：更新订单状态后发起对账请求。
- J -> N：对账请求发送至清算系统。
- N -> O：清算系统生成清算报表。
- I -> L：更新订单状态后进行对账处理。
- K -> L：接收对账文件后进行对账处理。
- L -> M：对账处理后生成对账差异报告。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **聚合支付平台**：整合多种支付渠道，为商户提供统一支付接口的平台。
- **第三方支付**：独立的支付机构，提供支付结算服务。
- **商户系统**：商家的业务系统，用于管理订单、商品等。
- **清算系统**：负责资金清算和结算的系统。
- **对账**：核对交易数据，确保账务一致。
- **清算报表**：记录资金清算情况的报表。
- **回调**：第三方支付平台将支付结果通知给聚合支付平台或商户系统的机制。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起支付请求，聚合支付平台创建订单并提交至第三方支付处理，第三方支付回调后，聚合支付平台验签并通知商户系统。商户系统接收支付结果并更新订单状态，然后发起对账请求至清算系统，清算系统生成清算报表。同时，商户系统接收对账文件并进行对账处理，生成对账差异报告。
