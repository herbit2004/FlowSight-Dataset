## 图类型与用途
该图是一个流程图，描述了电商系统中库存扣减和回滚的完整流程。它展示了从订单服务发起请求到最终完成扣减或回滚的各个步骤，以及可能出现的异常情况处理。该图可以帮助理解库存管理的业务逻辑。

## 图的整体布局
该图采用从左到右的布局方式。流程从左侧的订单服务发起请求开始，经过一系列判断和操作，最终到达右侧的完成状态。整体上呈现出线性流程，包含分支和汇聚。

## 分组/子图/阶段说明
图中包含一个名为“库存扣减与回滚流程”的子图，该子图囊括了整个流程的所有节点。

## 节点逐项说明
- **A[请求到达: 订单服务]**: 订单服务接收到用户请求，开始库存扣减流程。
- **B[检查库存是否充足]**: 检查当前库存是否满足订单需求。
- **C{库存充足？}**: 判断库存是否充足的条件节点。
- **D[尝试扣减库存: 库存服务]**: 库存服务尝试扣减库存。
- **E{扣减成功？}**: 判断库存扣减是否成功的条件节点。
- **F[生成预扣减记录: Redis]**: 在Redis中生成预扣减记录，用于后续回滚操作。
- **G[发送消息: 扣减成功事件]**: 发送扣减成功的消息，通知其他服务。
- **H[订单服务: 继续后续流程]**: 订单服务继续处理后续流程。
- **I[库存不足: 返回错误]**: 库存不足，返回错误信息。
- **J[业务异常: 订单取消/支付失败]**: 发生业务异常，如订单取消或支付失败。
- **K[监听取消订单事件]**: 监听取消订单事件。
- **L[查询预扣减记录: Redis]**: 从Redis中查询预扣减记录。
- **M{存在预扣减记录？}**: 判断是否存在预扣减记录的条件节点。
- **N[回滚库存: 库存服务]**: 库存服务执行库存回滚操作。
- **O[删除预扣减记录: Redis]**: 从Redis中删除预扣减记录。
- **P[回滚成功: 发送回滚成功事件]**: 发送回滚成功的消息，通知其他服务。
- **Q[系统异常: 人工介入]**: 发生系统异常，需要人工介入处理。
- **R[订单服务: 关闭订单]**: 订单服务关闭订单。
- **S[通知用户]**: 通知用户订单状态。

## 连线、分支与汇聚关系
- A --> B：订单服务发起请求后，进入库存检查环节。
- B --> C：检查库存后，进入库存充足判断。
- C -- 是 --> D：库存充足，尝试扣减库存。
- C -- 否 --> I：库存不足，返回错误。
- D --> E：尝试扣减库存后，进入扣减成功判断。
- E -- 是 --> F：扣减成功，生成预扣减记录。
- E -- 否 --> J：扣减失败，发生业务异常。
- F --> G：生成预扣减记录后，发送扣减成功事件。
- G --> H：发送扣减成功事件后，订单服务继续后续流程。
- I --> R：库存不足，订单服务关闭订单。
- J --> K：发生业务异常，监听取消订单事件。
- K --> L：监听取消订单事件后，查询预扣减记录。
- L --> M：查询预扣减记录后，进入预扣减记录存在判断。
- M -- 是 --> N：存在预扣减记录，回滚库存。
- M -- 否 --> Q：不存在预扣减记录，发生系统异常。
- N --> O：回滚库存后，删除预扣减记录。
- O --> P：删除预扣减记录后，发送回滚成功事件。
- R --> S：订单服务关闭订单后，通知用户。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **订单服务**: 负责接收和处理用户订单的服务。
- **库存服务**: 负责管理商品库存的服务。
- **Redis**: 一种内存数据库，用于存储预扣减记录。
- **预扣减记录**: 记录已预先扣减的库存信息，用于回滚操作。
- **扣减成功事件**: 库存扣减成功的消息事件。
- **回滚成功事件**: 库存回滚成功的消息事件。
- **人工介入**: 当系统出现无法自动处理的异常时，需要人工干预。

## 可作为 QA Ground Truth 的高信息密度摘要
订单服务接收请求后，检查库存是否充足。若充足，则尝试扣减库存，成功后生成预扣减记录并发送扣减成功事件，订单服务继续后续流程；若扣减失败，则发生业务异常。若库存不足，则返回错误并关闭订单，通知用户。如果订单取消，则查询预扣减记录，若存在则回滚库存并删除预扣减记录，发送回滚成功事件；若不存在，则判定为系统异常，需要人工介入。
