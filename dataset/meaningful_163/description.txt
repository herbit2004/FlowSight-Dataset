## Edges, Branches & Convergence
- `User Action: Comment/Like --> API Gateway: /comments, /likes`: User action triggers a request to the API gateway.
- `API Gateway: /comments, /likes --> AuthN/AuthZ`: API gateway forwards the request to the authentication and authorization service.
- `AuthN/AuthZ -- Valid User --> Comment/Like Service`: If the user is valid, the request is forwarded to the comment/like service.
- `AuthN/AuthZ -- Invalid User --> Error: Authentication Required`: If the user is invalid, an authentication error is returned.
- `Comment/Like Service --> Data Store: Comment/Like DB`: The comment/like service attempts to write data to the database.
- `Data Store: Comment/Like DB -- Success --> Kafka Topic: user_activity`: If the database write is successful, a user activity event is published to Kafka.
- `Data Store: Comment/Like DB -- Failure --> Error: DB Write Failed`: If the database write fails, an error is returned.
- `Kafka Topic: user_activity --> Activity Processor`: User activity events are consumed by the activity processor.
- `Activity Processor --> Filter: Relevance Score > Threshold`: The activity processor filters events based on a relevance score.
- `Filter: Relevance Score > Threshold -- Relevant --> Feed Aggregator`: Relevant events are forwarded to the feed aggregator.
- `Filter: Relevance Score > Threshold -- Not Relevant --> Discard Event`: Irrelevant events are discarded.
- `Feed Aggregator --> Data Store: User Feed DB`: The feed aggregator attempts to write data to the user feed database.
- `Data Store: User Feed DB -- Success --> Cache Invalidator`: If the database write is successful, the cache is invalidated.
- `Data Store: User Feed DB -- Failure --> Error: Feed Update Failed`: If the database write fails, an error is returned.
- `Cache Invalidator --> Redis Cache: User Feeds`: The cache invalidator updates the Redis cache.
- `Redis Cache: User Feeds --> Feed Delivery Service`: User feeds are retrieved from the Redis cache by the feed delivery service.
- `Feed Delivery Service --> API Gateway: /user/feed`: The feed delivery service sends the user feeds to the API gateway.
- `API Gateway: /user/feed --> User Client`: The API gateway forwards the user feeds to the user client.
- `Kafka Topic: user_activity --> Analytics Pipeline`: User activity events are consumed by the analytics pipeline.
- `Analytics Pipeline --> Data Lake`: Analytics data is stored in the data lake.
- `Data Lake --> Reporting Dashboard`: Analytics data is used to generate reports on the reporting dashboard.
- `Comment/Like Service --> Metrics Service`: The comment/like service sends metrics to the metrics service.
- `Metrics Service --> Monitoring Dashboard`: System metrics are displayed on the monitoring dashboard.

The `Kafka Topic: user_activity` event triggers both the `Feed Aggregation Pipeline` and the `Analytics & Monitoring` subgraph. Relevant events are sent to the `Feed Aggregator`, while irrelevant events are discarded via `Discard Event`. The `Feed Aggregator` writes to the `Data Store: User Feed DB`. The `Redis Cache: User Feeds` then provides data to the `Feed Delivery Service`, which sends it to the `API Gateway: /user/feed`, and finally to the `User Client`. Simultaneously, the `Kafka Topic: user_activity` event triggers the `Analytics Pipeline`, which stores data in the `Data Lake` for the `Reporting Dashboard`, and the `Comment/Like Service` sends metrics to the `Metrics Service` for the `Monitoring Dashboard`. The API Gateway acts as a reverse proxy, routing requests to the appropriate backend services, while Kafka provides a distributed streaming platform for handling user activity events.
