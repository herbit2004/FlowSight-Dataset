## 图类型与用途
该图是一个流程图，用于描述结算系统的工作流程。它展示了从订单创建到工作流结束的各个环节，包括风控检查、预支付、扣款、结算和退款等。该图清晰地呈现了不同环节之间的依赖关系和可能的结果。

## 图的整体布局
该图采用从左到右的布局方式。整体流程从左侧的“订单创建”开始，经过一系列处理环节，最终到达右侧的“工作流结束”。该图具有明显的层次结构，各个环节依次展开。

## 分组/子图/阶段说明
图中包含一个名为“结算系统工作流”的子图，它概括了整个流程。子图内部可以逻辑上分为以下几个阶段：订单创建与风控阶段、预支付阶段、扣款与结算阶段、退款阶段。

## 节点逐项说明
- **订单创建**：流程的起始节点，表示用户创建了一个新的订单。
- **风控检查**：对订单进行风险控制检查，判断订单是否存在风险。
- **预支付**：在正式扣款前，先进行预支付操作。
- **预支付结果**：预支付操作的结果，可能成功或失败。
- **扣款**：从用户的支付账户中扣除订单金额。
- **扣款结果**：扣款操作的结果，可能成功或失败。
- **结算**：将订单金额结算到商户账户。
- **结算完成**：结算操作完成，订单进入已结算状态。
- **预支付失败处理**：当预支付失败时，需要进行相应的处理。
- **退款**：当扣款失败时，需要将预支付的金额退还给用户。
- **退款成功通知**：退款操作成功后，向用户发送退款成功的通知。
- **订单取消**：当风控检查不通过或预支付失败时，订单会被取消。
- **工作流结束**：流程的最终节点，表示订单的结算流程已经完成。

## 连线、分支与汇聚关系
- 订单创建 -> 风控检查：订单创建后，进入风控检查环节。
- 风控检查 -- 通过 --> 预支付：风控检查通过后，进行预支付操作。
- 风控检查 -- 驳回 --> 订单取消：风控检查不通过，订单被取消。
- 预支付 -> 预支付结果：预支付操作完成后，产生预支付结果。
- 预支付结果 -- 成功 --> 扣款：预支付成功后，进行扣款操作。
- 预支付结果 -- 失败 --> 预支付失败处理：预支付失败后，进行预支付失败处理。
- 预支付失败处理 -> 订单取消：预支付失败处理后，订单被取消。
- 扣款 -> 扣款结果：扣款操作完成后，产生扣款结果。
- 扣款结果 -- 成功 --> 结算：扣款成功后，进行结算操作。
- 扣款结果 -- 失败 --> 退款：扣款失败后，进行退款操作。
- 退款 -> 退款成功通知：退款操作完成后，发送退款成功通知。
- 结算 -> 结算完成：结算操作完成后，订单进入已结算状态。
- 结算完成 -> 工作流结束：结算完成后，工作流结束。
- 退款成功通知 -> 工作流结束：退款成功通知发送后，工作流结束。
- 订单取消 -> 工作流结束：订单取消后，工作流结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **风控检查**：对订单进行风险评估，判断是否存在欺诈、恶意行为等风险。
- **预支付**：在正式扣款前，先冻结用户账户中的资金，确保有足够的余额进行支付。
- **扣款**：从用户的支付账户中划转订单金额到商户账户。
- **结算**：将订单金额从支付平台结算到商户的银行账户。
- **退款**：将已经支付的订单金额退还给用户。
- **订单取消**：由于某种原因（如风控不通过、用户主动取消等），订单被终止。

## 可作为 QA Ground Truth 的高信息密度摘要
订单创建后，系统进行风控检查，若通过则进行预支付，否则订单取消并结束流程。预支付成功后进行扣款，否则进行预支付失败处理，订单取消并结束流程。扣款成功后进行结算，结算完成后流程结束；扣款失败则进行退款，退款成功通知用户后流程结束。
