## 图类型与用途
这是一个架构图，展示了一个企业级电子商务平台的 Active-Active 多区域部署架构，目标是实现高可用性和容错性。该图在仓库中用于概览系统的多区域架构和数据复制关系，体现了数字韧性的设计。

## 图的整体布局
图采用从上到下的布局，分为全局层、台湾区域和日本区域三个主要部分。流量从全局层的 DNS 服务开始，分别流向台湾和日本区域的 EKS 集群。

## 分组/子图/阶段说明
图中有三个显式子图，分别代表：
- **Global Layer (🌐 Global Layer)**：全局层，负责智能流量管理。
- **Taiwan Region (🇹🇼 Taiwan Region (ap-east-2))**：台湾区域，作为主区域，处理 60% 的流量。
- **Japan Region (🇯🇵 Japan Region (ap-northeast-1))**：日本区域，作为辅助区域，处理 40% 的流量。

## 节点逐项说明
- **Route 53 DNS (DNS)**：AWS 的 DNS 服务，用于智能流量管理，根据策略将用户请求路由到不同的区域。
- **EKS Cluster (TW_APP)**：台湾区域的 Kubernetes 集群，运行应用程序，由 5 个节点组成，分布在 3 个可用区 (AZ)。
- **Aurora Global DB (TW_DB)**：台湾区域的 Aurora 全局数据库，作为主写入数据库。
- **ElastiCache Global (TW_CACHE)**：台湾区域的 ElastiCache 全局缓存。
- **EKS Cluster (JP_APP)**：日本区域的 Kubernetes 集群，运行应用程序，由 5 个节点组成，分布在 3 个可用区 (AZ)。
- **Aurora Global DB (JP_DB)**：日本区域的 Aurora 全局数据库，配置为写入转发，数据从台湾区域同步过来。
- **ElastiCache Global (JP_CACHE)**：日本区域的 ElastiCache 全局缓存。

## 连线、分支与汇聚关系
- `DNS -> TW_APP`：Route 53 DNS 将一部分用户请求路由到台湾区域的 EKS 集群。
- `DNS -> JP_APP`：Route 53 DNS 将另一部分用户请求路由到日本区域的 EKS 集群。
- `TW_APP -> TW_DB`：台湾区域的 EKS 集群访问台湾区域的 Aurora 数据库。
- `TW_APP -> TW_CACHE`：台湾区域的 EKS 集群访问台湾区域的 ElastiCache 缓存。
- `JP_APP -> JP_DB`：日本区域的 EKS 集群访问日本区域的 Aurora 数据库。
- `JP_APP -> JP_CACHE`：日本区域的 EKS 集群访问日本区域的 ElastiCache 缓存。
- `TW_DB -.-> JP_DB`：台湾区域的 Aurora 数据库将数据复制到日本区域的 Aurora 数据库，复制延迟小于 1 秒。
- `TW_CACHE -.-> JP_CACHE`：台湾区域的 ElastiCache 缓存将数据复制到日本区域的 ElastiCache 缓存，复制延迟小于 1 秒。

## 仓库语境与术语解释
- **Active-Active Multi-Region Architecture**：一种高可用性架构，在多个地理区域同时运行相同的应用和服务，实现负载均衡和故障转移，如 README 所述。
- **Route 53 DNS**：AWS 的 DNS 服务，用于智能流量管理，根据配置的策略将用户请求路由到不同的区域。
- **EKS Cluster**：Kubernetes 集群，用于运行应用程序。
- **Aurora Global DB**：跨区域的数据库服务，提供低延迟的全局读取和快速故障转移能力。
- **ElastiCache Global**：跨区域的缓存服务，用于加速数据访问。
- **CrossRegionTracingService**：用于跨区域调用链路追踪的服务，如 `app/src/main/java/solid/humank/genaidemo/application/tracing/CrossRegionTracingService.java` 所示，用于性能跟踪和业务上下文传递。
- **Digital Resilience**：通过 Active-Active 多区域架构实现的系统韧性，目标是 99.99% 的可用性，如 README 所述。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个企业级电子商务平台的 Active-Active 多区域部署架构，从全局层的 Route 53 DNS 开始，流量被智能地路由到台湾和日本区域的 EKS 集群。台湾区域作为主区域，其 Aurora 数据库和 ElastiCache 缓存的数据会以小于 1 秒的延迟复制到日本区域。这种架构旨在提高系统的可用性和容错性，体现了 README 中强调的数字韧性设计。`CrossRegionTracingService` 负责跨区域调用链的追踪。
