## Repository Context & Terminology
- **GitLab/GitHub/Gitea**: These are popular web-based Git repository management and collaboration platforms.
- **Webhook API Call**: A webhook is a mechanism for one application to notify another application when an event occurs. In this context, it's used to trigger the workflow when an event happens in the Git repository.
- **Merge Request**: A request to merge code changes from one branch into another.
- **Push Request**: An event that occurs when code changes are pushed to a Git repository.
- **LLM Review**: Large Language Model review, which refers to using a large language model to automatically review code changes.
- **IM Message/Report**: Instant Messaging message or report, which is used to send notifications or summaries to users.

## High-Density QA Ground Truth Summary
The flowchart begins with an event originating from a Git repository (GitLab/GitHub/Gitea), triggering a Webhook API call. The system first identifies the platform and then the event type. If the event is a merge request, the system proceeds to `handle_merge_request`, checking if the action is either `open` or `update`. If the action is `open` or `update`, the system obtains code changes and performs an LLM review before sending a code review IM message. If the event is a push, the system proceeds to `handle_push_request` and logs the push event. The system then checks if push review is enabled. If push review is not enabled, an IM notice is sent; otherwise, an LLM review is performed, and a code review IM message is sent. A scheduled timer triggers the reading of logs, which are then summarized by an LLM, and an IM report is sent. The `log push` process also feeds into the `Read logs` process, indicating that logs are read from the push events. The final actions involve sending IM messages or reports, providing feedback or summaries to users based on the processed events.
