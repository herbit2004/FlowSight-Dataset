## 图类型与用途
这是一个分层架构图，用于展示 Wegent 系统的整体架构和数据/控制流。Wegent 是一个 AI 原生的操作系统，用于定义、组织和运行智能 Agent 团队。该图旨在概览 Wegent 的核心组件及其交互方式，在 README 中作为架构概览出现。

## 图的整体布局
图整体采用从上到下的布局，分为四个主要层次：入口层 (Access Layer)、功能层 (Feature Layer)、Agent 层 (Agent Layer) 和执行环境 (Execution Environment)。用户请求从顶部的入口层开始，逐层向下传递，最终在执行环境中运行。

## 分组/子图/阶段说明
图中有四个显式子图，分别对应 Wegent 系统的四个主要层次：
- **Entry Layer**：入口层，包含用户与 Wegent 系统交互的各种入口。
- **Feature Layer**：功能层，提供 Wegent 系统的核心功能。
- **Agent Layer**：Agent 层，包含各种智能 Agent。
- **Execution Environment**：执行环境，Agent 在其中运行。

## 节点逐项说明
- **Web**：通过 Web 浏览器访问 Wegent 系统的入口。
- **IM Tools**：通过即时通讯工具（如 Slack、Discord 等）访问 Wegent 系统的入口。
- **API**：通过应用程序编程接口访问 Wegent 系统的入口。
- **Chat**：聊天功能，允许用户与 Agent 进行交互。
- **Coding**：编码功能，允许 Agent 生成和执行代码。
- **Feed**：信息流功能，用于展示 Agent 的活动和输出。
- **Knowledge**：知识库功能，用于存储和检索 Agent 使用的知识。
- **Wegent Chat**：Wegent 系统的聊天 Agent，负责处理用户聊天请求。
- **Claude Code**：使用 Claude 模型进行代码生成的 Agent。
- **Agno**：图中可见，但仓库上下文未进一步说明。
- **Dify**：集成了 Dify 平台的 Agent。
- **Agent Sandbox**：使用 Docker 容器作为 Agent 的沙箱环境，提供隔离和安全性。
- **Cloud Device**：在云设备上运行 Agent。
- **Local Device**：在本地设备上运行 Agent。

## 连线、分支与汇聚关系
- `Access --> Features`：用户通过入口层访问 Wegent 系统，请求被传递到功能层。
- `Features --> Agents`：功能层根据用户请求调用相应的 Agent。
- `Agents --> Execution`：Agent 在执行环境中运行，完成用户请求。

## 仓库语境与术语解释
- **Wegent**：一个开源的 AI 原生操作系统，用于定义、组织和运行智能 Agent 团队。
- **Entry Layer**：用户与 Wegent 系统交互的入口，包括 Web、IM 工具和 API。
- **Feature Layer**：Wegent 系统的核心功能，包括聊天、编码、信息流和知识库。
- **Agent Layer**：包含各种智能 Agent，如 ChatShell、ClaudeCode、Agno 和 Dify。
- **Execution Environment**：Agent 在其中运行的环境，包括 Docker 容器、云设备和本地设备。
- **Claude**：一种大型语言模型，Wegent 支持 Claude 以及 OpenAI, Gemini 等多种模型。
- **Docker**：一种容器化技术，Wegent 使用 Docker 容器作为 Agent 的沙箱环境。
