## 图类型与用途
这是一个流程图/架构图，展示了 AI Agent 如何通过 Cheat Engine MCP Bridge 与 Cheat Engine 交互，最终实现对目标进程内存的分析和控制。它在仓库中的作用是解释 Cheat Engine MCP Bridge 的工作原理，以及各个组件之间的交互方式和数据流向。

## 图的整体布局
图整体采用从上到下的布局。顶部是 AI Agent，作为整个流程的起点，底部是 Target .exe，表示流程的终点，中间是 MCP Server、命名管道和 Cheat Engine 内部的 Lua 脚本。

## 分组/子图/阶段说明
图中包含一个子图 CE，代表 Cheat Engine，CE 内部又包含一个子图 LUA，代表在 Cheat Engine 中运行的 Lua 脚本。整个流程可以分为三个阶段：AI Agent 发起请求、MCP Server 协议转换和通信、Cheat Engine 实际的内存操作。

## 节点逐项说明
- **AI Agent: Claude/Cursor/Copilot**：代表使用 MCP 协议与 MCP Server 通信的 AI 代理，例如 Claude、Cursor 或 Copilot。它负责发出指令，请求对目标进程内存进行分析。
- **MCP (mcp_cheatengine.py - Python MCP Server)**：这是一个用 Python 编写的 MCP 服务器，负责接收来自 AI Agent 的请求，并将这些请求转换为 Cheat Engine 可以理解的指令。根据 `MCP_Server/mcp_cheatengine.py` 文件，该服务器还包含针对 Windows 平台 CRLF 问题的修复。
- **PIPE ("\\\\.\\pipe\\CE_MCP_Bridge_v99")**：这是一个命名管道，用于 MCP Server 和 Cheat Engine 之间的异步通信。该管道的名称在 `MCP_Server/ce_mcp_bridge.lua` 中被定义为 `PIPE_NAME = "CE_MCP_Bridge_v99"`。
- **CE (Cheat Engine - DBVM Mode)**：代表 Cheat Engine 软件，运行在 DBVM (Debug Virtual Machine) 模式下，允许对目标进程进行高级调试和内存操作。
- **LUA (ce_mcp_bridge.lua)**：这是一个在 Cheat Engine 中运行的 Lua 脚本，作为 MCP Bridge 的一部分，负责处理来自 MCP Server 的指令。
    - **WORKER (Worker Thread - Blocking I/O)**：Lua 脚本中负责执行阻塞 I/O 操作的 Worker 线程。
    - **MAIN (Main Thread - GUI + CE API)**：Cheat Engine 的主线程，负责 GUI 界面和 Cheat Engine API 的调用。
- **TARGET (Target .exe)**：代表需要被分析和修改内存的目标可执行程序。

## 连线、分支与汇聚关系
- `AI -> MCP`：AI Agent 通过 MCP 协议（JSON-RPC over stdio）与 MCP Server 通信，发送分析请求。
- `MCP <--> PIPE`：MCP Server 通过命名管道与 Cheat Engine 中的 Lua 脚本进行异步通信。
- `PIPE <--> CE`：命名管道与 Cheat Engine 之间进行双向通信。
- `WORKER <--> MAIN`：在 Cheat Engine 内部，Lua 脚本的 Worker 线程和 Main 线程通过同步机制进行协作。
- `MAIN -> TARGET`：Cheat Engine 的 Main 线程通过 Memory Access 方式与目标进程进行交互，读取和修改目标进程的内存。

## 仓库语境与术语解释
- **MCP (Model Context Protocol)**：一种允许 AI Agent 与程序进行交互的协议。根据 README，该桥接允许 AI 数据中心分析程序内存。
- **DBVM (Debug Virtual Machine)**：Cheat Engine 的一种运行模式，允许对目标进程进行高级调试和内存操作。
- **Named Pipe**：一种用于进程间通信的机制，在此用于 MCP Server 和 Cheat Engine 之间的异步通信。README 指出该桥仅支持 Windows，因为使用了 Named Pipes (`pywin32`)。
- **ce_mcp_bridge.lua**：在 Cheat Engine 中运行的 Lua 脚本，作为 MCP Bridge 的一部分，负责处理来自 MCP Server 的指令。该脚本的版本信息可在脚本文件的开头找到，例如 `v11.4.0`。
- **mcp_cheatengine.py**：用 Python 编写的 MCP 服务器，负责接收来自 AI Agent 的请求，并将这些请求转换为 Cheat Engine 可以理解的指令。
- **AI Agent**：使用 MCP 协议与 MCP Server 通信的 AI 代理，例如 Claude、Cursor 或 Copilot。
- **Memory Access**：Cheat Engine 通过内存访问的方式与目标进程进行交互，读取和修改目标进程的内存。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 AI Agent 通过 Cheat Engine MCP Bridge 与目标进程交互的架构。AI Agent 通过 MCP 协议与 Python MCP Server (`mcp_cheatengine.py`) 通信，MCP Server 通过命名管道与 Cheat Engine 中的 Lua 脚本 (`ce_mcp_bridge.lua`) 进行异步通信。在 Cheat Engine 内部，Lua 脚本的 Worker 线程和 Main 线程通过同步机制进行协作，最终 Cheat Engine 通过内存访问的方式与目标进程进行交互，实现 AI 驱动的内存分析和修改。该架构的核心在于利用 AI Agent 的强大分析能力，通过 MCP Bridge 将 AI 的指令传递给 Cheat Engine，从而实现对目标进程内存的自动化分析和控制。
