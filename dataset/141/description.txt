## 图类型与用途
这是一个架构图，展示了 Contoso Real Estate 公司的企业级 JavaScript 应用的参考架构，描述了前端和云原生应用组件的部署和交互方式。它在仓库中的作用是展示一个现代化的、可组合的前端架构，以及如何利用 Azure 云服务构建一个完整的应用生态系统。

## 图的整体布局
图整体采用从上到下的布局。顶部是 Internet 区域，往下依次是 Azure Container Apps、Azure Static Web Apps、Azure API Management、Azure Functions 和 Database/Storage。

## 分组/子图/阶段说明
图中包含 Internet、Azure API Management、Azure Static Web Apps、Azure Functions、Azure Container Apps 和 Database/Storage 六个子图。

## 节点逐项说明
- **Portal (https://portal.contoso.com)**：主门户网站，用户访问房产信息、进行用户认证和管理个人资料的主要入口。
- **Blog (https://blog.contoso.com)**：公司博客，用于发布新闻、文章等内容。
- **CMS (https://cms.contoso.com)**：内容管理系统，用于管理网站内容，特别是博客内容。
- **Stripe (https://stripe.contoso.com)**：第三方支付服务，用于处理支付相关事务。
- **API (https://api.contoso.com)**：应用程序编程接口，提供数据和服务给前端应用。
- **API Gateway**：Azure API 管理服务，作为 API 网关，负责管理、保护和监控 API。
- **Angular**：Azure 静态 Web 应用服务，用于托管 Angular 构建的前端应用。
- **Node.js**：Azure 函数服务，提供无服务器计算能力，用于处理后端逻辑和 API 请求。
- **Next.js**：使用 Next.js 构建的应用，很可能用于渲染博客前端。
- **Strapi**：使用 Strapi 构建的应用，作为内容管理系统 (CMS) 的后端。
- **Stripe**：用于处理 Stripe 支付相关逻辑的容器化应用。
- **PostgreSQL - Strapi**：PostgreSQL 数据库，用于存储 Strapi CMS 的数据。
- **MongoDB - Portal**：MongoDB 数据库，用于存储门户网站的数据。
- **Azure Blob Storage - CMS**：Azure Blob Storage，用于存储 CMS 上传的媒体文件。

## 连线、分支与汇聚关系
- `Portal -> Angular`: 用户通过 Portal 访问 Angular 前端应用。
- `Angular -- portal.contoso.com/api/** --> API Gateway`: Angular 前端应用通过 API 网关发送 API 请求。
- `API Gateway -- portal.contoso.com/api/** --> Node.js`: API 网关将 Portal 的 API 请求路由到 Azure Functions 处理。
- `Blog -- blog.contoso.com --> Next.js`: 用户通过 Blog 访问 Next.js 应用。
- `Next.js -. Strapi API .-> Strapi`: Next.js 应用通过 Strapi API 从 Strapi CMS 获取内容。
- `CMS -- cms.contoso.com --> Strapi`: 用户通过 CMS 访问 Strapi CMS 系统。
- `Strapi -- read/write ----> PostgreSQL - Strapi`: Strapi CMS 可以读写 PostgreSQL 数据库。
- `Strapi -- upload --> Azure Blob Storage - CMS`: Strapi CMS 上传媒体文件到 Azure Blob Storage。
- `API --> API Gateway -- api.contoso.com --> Node.js`: API 通过 API 网关访问 Azure Functions。
- `Node.js <-- read/write --> MongoDB - Portal`: Azure Functions 读写 MongoDB 数据库。
- `Stripe ---> API Gateway -- stripe.contoso.com --> Stripe`: Stripe 通过 API 网关访问 Stripe 容器应用。
- `Stripe <-. validate payment (through APIM) .-> Node.js`: Stripe 容器应用通过 API 网关验证支付，并将结果传递给 Azure Functions。

## 仓库语境与术语解释
- **Portal**: 使用 Angular 构建的门户应用，用于查看和预订房源。
- **Blog**: 使用 Next.js 构建的博客应用，用于查看和创建博客文章。
- **CMS**: 使用 Strapi 构建的内容管理系统，用于管理 Portal 和 Blog 应用的数据。
- **Azure Functions**: 用于与 Portal 应用通信的 API，使用 Node.js 编写，具体实现位于 `packages/api` 目录。
- **Azure API Management (APIM)**: 可以通过设置 `infra/main.bicep` 文件中的 `useAPIM` 参数为 true 来启用，用于管理 API 调用。
- **Stripe**: 用于处理支付的第三方服务，相关代码位于 `packages/stripe` 目录。
- **infra/main.bicep**: 仓库中的主要 Bicep 文件，用于配置和部署 Azure 资源。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 Contoso Real Estate 应用的前端和云原生组件的交互方式。用户通过 Portal 访问 Angular 应用，Angular 应用通过 API 网关与 Azure Functions 交互，Azure Functions 读写 MongoDB 数据库。用户通过 Blog 访问 Next.js 应用，Next.js 应用通过 Strapi API 从 Strapi CMS 获取内容，Strapi CMS 读写 PostgreSQL 数据库，并上传媒体文件到 Azure Blob Storage。Stripe 通过 API 网关与 Stripe 容器应用交互，并验证支付结果。其中，API Gateway 和 Azure Functions 是关键的中间组件，连接了前端应用和后端数据存储。
