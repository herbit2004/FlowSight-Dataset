## High-Density QA Ground Truth Summary
The diagram begins with the `server.ts` component of the MCP Server, which initiates the process by reading the `registry.json` file. The server then utilizes the `LocalBackend`, which in turn employs a `Connection Pool` to manage connections to KuzuDB instances. The `Connection Pool` lazily opens connections to `KuzuDB conn A` and `KuzuDB conn B`. These KuzuDB connections then query the `.gitnexus` directories within `repo A` and `repo B` respectively. Separately, the CLI commands interact with the system. The `gitnexus setup` command writes the global MCP configuration to the `~/.cursor/mcp.json` file. The `gitnexus analyze` command registers repositories in the `registry.json` and stores index data in the `.gitnexus` directory of a repository. The `gitnexus clean` command unregisters repositories from the `registry.json`. Finally, the `gitnexus list` command reads the `registry.json` file to list registered repositories. The `registry.json` file acts as a central registry, read by the server and CLI commands, and modified by the `analyze` and `clean` commands. The end nodes are the `.gitnexus` directories in the project repos and the `registry.json` file, representing the persistent storage of analysis results and repository metadata.
