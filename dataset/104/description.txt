## 图类型与用途
这是一个架构图，描述了 GitNexus 命令行工具、数据存储以及 MCP Server 之间的关系。它展示了 GitNexus 如何通过 CLI 与项目仓库交互，并将数据存储在本地注册表和项目仓库中，最终通过 MCP Server 提供服务，为 AI agent 提供代码上下文。

## 图的整体布局
图采用从左到右的布局。左侧是 CLI 命令，中间是注册表和项目仓库，右侧是 MCP Server。数据流从 CLI 命令开始，经过注册表和项目仓库，最终到达 MCP Server。

## 分组/子图/阶段说明
图中包含三个子图：
- **CLI Commands**：包含 GitNexus 提供的命令行工具。
- **~/.gitnexus/**：表示 GitNexus 的全局配置和已注册仓库的信息存储位置。
- **Project Repos**：表示项目仓库，存储项目代码和 GitNexus 创建的索引数据。
- **MCP Server**：表示 GitNexus 的核心服务，用于处理查询和提供代码上下文。

## 节点逐项说明
- **gitnexus setup**：用于设置 GitNexus 的环境。根据 `gitnexus/src/cli/setup.ts`，该命令用于自动检测编辑器并写入 MCP 配置。
- **gitnexus analyze**：用于分析项目代码并创建索引。根据 `gitnexus/src/cli/analyze.ts`，该命令会索引仓库并将知识图谱存储在 `.gitnexus/` 目录下。
- **gitnexus clean**：用于清理 GitNexus 创建的索引和注册信息。根据 `gitnexus/src/cli/clean.ts`，该命令用于移除 `.gitnexus` 索引并从全局注册表中取消注册。
- **gitnexus list**：用于列出已注册的项目仓库。根据 `gitnexus/src/cli/list.ts`，该命令显示来自全局注册表的所有索引仓库。
- **~/.gitnexus/registry.json**：存储已注册仓库的元数据。
- **.gitnexus/ in repo A**：仓库 A 中存储 GitNexus 索引数据的目录。
- **.gitnexus/ in repo B**：仓库 B 中存储 GitNexus 索引数据的目录。
- **MCP Server/server.ts**：MCP Server 的主程序文件。
- **MCP Server/LocalBackend**：MCP Server 使用的本地后端，负责数据存储和检索。
- **MCP Server/Connection Pool**：连接池，用于管理与 KuzuDB 的连接。
- **MCP Server/KuzuDB conn A**：与仓库 A 对应的 KuzuDB 连接。
- **MCP Server/KuzuDB conn B**：与仓库 B 对应的 KuzuDB 连接。
- **~/.cursor/mcp.json**：存储 Cursor 编辑器的 MCP 配置。

## 连线、分支与汇聚关系
- `gitnexus setup -> ~/.cursor/mcp.json`：`gitnexus setup` 命令将全局 MCP 配置写入 `~/.cursor/mcp.json` 文件。
- `gitnexus analyze -> ~/.gitnexus/registry.json`：`gitnexus analyze` 命令将项目仓库注册信息写入 `registry.json`。
- `gitnexus analyze -> .gitnexus/ in repo A`：`gitnexus analyze` 命令将索引数据存储在项目仓库的 `.gitnexus/` 目录中。
- `gitnexus clean -> ~/.gitnexus/registry.json`：`gitnexus clean` 命令从 `registry.json` 中删除项目仓库的注册信息。
- `gitnexus list -> ~/.gitnexus/registry.json`：`gitnexus list` 命令读取 `registry.json` 文件以列出已注册的仓库。
- `MCP Server/server.ts -> ~/.gitnexus/registry.json`：`MCP Server` 读取 `registry.json` 文件以获取已注册仓库的信息。
- `MCP Server/server.ts -> MCP Server/LocalBackend`：`MCP Server` 使用 `LocalBackend` 进行数据存储和检索。
- `MCP Server/LocalBackend -> MCP Server/Connection Pool`：`LocalBackend` 使用 `Connection Pool` 管理与 KuzuDB 的连接。
- `MCP Server/Connection Pool -> MCP Server/KuzuDB conn A`：`Connection Pool` 懒加载与仓库 A 对应的 KuzuDB 连接。
- `MCP Server/Connection Pool -> MCP Server/KuzuDB conn B`：`Connection Pool` 懒加载与仓库 B 对应的 KuzuDB 连接。
- `MCP Server/KuzuDB conn A -> .gitnexus/ in repo A`：`KuzuDB conn A` 查询仓库 A 的索引数据。
- `MCP Server/KuzuDB conn B -> .gitnexus/ in repo B`：`KuzuDB conn B` 查询仓库 B 的索引数据。

## 仓库语境与术语解释
- **CLI Commands**：GitNexus 提供的命令行接口，用于与 GitNexus 系统进行交互。
- **MCP Server**：Meta-Context Provider Server，GitNexus 的核心服务，用于处理查询和提供代码上下文。根据 `gitnexus/src/mcp/server.ts`，它通过标准输入/输出与外部 AI 工具通信。
- **KuzuDB**：GitNexus 使用的图数据库，用于存储代码知识图谱。
- **~/.gitnexus/**：GitNexus 的全局配置目录，包含 `registry.json` 文件，用于存储已注册仓库的信息。
- **~/.cursor/mcp.json**：Cursor 编辑器的 MCP 配置文件，用于配置 Cursor 如何与 MCP Server 通信。根据 `gitnexus/src/cli/setup.ts`，`gitnexus setup` 命令会自动配置该文件。
- **registry.json**：存储已注册仓库的元数据，包括仓库路径、索引时间、最后提交等信息。
- **LocalBackend**：MCP Server 的本地后端，负责数据存储和检索。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 GitNexus 的架构，从 CLI 命令开始，`gitnexus setup` 用于配置编辑器，`gitnexus analyze` 用于索引代码库并将信息存储在 `.gitnexus/` 目录和 `registry.json` 中。`MCP Server` 读取 `registry.json` 并通过 `LocalBackend` 和 `Connection Pool` 查询 `KuzuDB` 数据库，最终将结果返回给 AI agent。`gitnexus clean` 用于清理索引，而 `gitnexus list` 用于列出已索引的仓库。核心流程是“CLI 命令 -> 索引与注册 -> MCP Server 查询 -> 结果返回”。
