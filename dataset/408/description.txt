## Repository Context & Terminology
- **Requirements Gathering**: The process of identifying and documenting the needs and expectations of stakeholders for a software system.
- **Functional Requirements**: Define what the system should do, its features, and functionalities.
- **Non-Functional Requirements**: Define how the system should perform, including aspects like performance, security, scalability, and usability.
- **API Design**: The process of designing the interfaces through which different software components interact.
- **Scale Estimation**: Estimating the expected load and usage patterns of the system to ensure it can handle the anticipated traffic.
- **High-Level Design**: A broad overview of the system's architecture, including major components and their interactions.
- **Component Design**: Designing the individual modules or components that make up the system.
- **Database Design**: The process of structuring and organizing data within a database.
- **Caching Strategy**: A plan for storing frequently accessed data in a cache to improve performance.
- **Load Balancing**: Distributing network traffic across multiple servers to prevent overload and ensure high availability.
