## 图类型与用途
该图是一个流程图，描述了商品库存扣减的完整流程，包括同步扣减和异步补偿两个主要部分。它展示了库存服务如何处理扣减请求，以及在扣减失败时如何进行补偿。该图旨在清晰地呈现库存扣减的业务逻辑和异常处理机制。

## 图的整体布局
该图采用从上到下的布局，分为“库存服务”和“异步扣减补偿服务”两个主要部分。库存服务是主流程，从接收扣减请求开始，到返回成功或失败响应结束。异步扣减补偿服务处理扣减失败的情况。

## 分组/子图/阶段说明
图中包含两个显式子图：
- **库存服务**：处理同步扣减请求，包含请求校验、库存查询、事务处理、缓存更新等步骤。
- **事务管理器**：负责事务的提交和回滚，是库存服务的一部分。
- **异步扣减补偿服务**：处理异步扣减补偿，监听MQ消息，检查扣减凭证状态，释放锁定库存。

## 连线、分支与汇聚关系
- A -> B：接收到扣减请求后，进行参数校验。
- B -- 参数有效 --> C：参数有效时，查询商品库存。
- B -- 参数无效 --> E：参数无效时，返回错误响应。
- C -> D：查询库存后，判断库存是否充足。
- D -- 充足 --> F：库存充足时，创建扣减事务。
- D -- 不足 --> G：库存不足时，返回库存不足。
- F -> H：创建扣减事务后，锁定库存。
- H -> I：锁定库存后，生成扣减凭证。
- I -> J：生成扣减凭证后，发送MQ消息。
- J -> K：发送MQ消息后，等待事务提交/回滚。
- K -- 提交 --> L：事务提交时，提交库存扣减。
- K -- 回滚 --> M：事务回滚时，回滚库存扣减。
- L -> N：提交库存扣减后，更新Redis缓存。
- N -> O：更新Redis缓存后，删除扣减凭证。
- O -> P：删除扣减凭证后，返回成功响应。
- M -> Q：回滚库存扣减后，释放锁定库存。
- Q -> R：释放锁定库存后，删除扣减凭证。
- R -> S：删除扣减凭证后，返回回滚成功。
- E -> T：返回错误响应后，记录错误日志。
- G -> U：返回库存不足后，记录错误日志。
- S -> V：返回回滚成功后，记录回滚日志。
- P -> W：返回成功响应后，记录扣减日志。
- X -> Y：监听MQ消息后，检查扣减凭证状态。
- Y -- 有效，未处理 --> Z：凭证有效且未处理，查询库存锁定记录。
- Y -- 无效或已处理 --> AA：凭证无效或已处理，忽略消息。
- Z -> BB：查询库存锁定记录后，判断锁定记录是否存在。
- BB -- 存在 --> CC：锁定记录存在，释放锁定库存。
- BB -- 不存在 --> DD：锁定记录不存在，记录异常日志。
- CC -> EE：释放锁定库存后，删除扣减凭证。
- EE -> FF：删除扣减凭证后，记录补偿日志。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **API**：应用程序编程接口，用于不同系统之间进行通信和数据交换。
- **MQ消息**：消息队列，用于异步通信，解耦系统之间的依赖关系。
- **Redis缓存**：一种内存数据库，用于缓存热点数据，提高访问速度。
- **事务**：一组操作的集合，要么全部成功，要么全部失败，保证数据的一致性。
- **扣减凭证**：用于记录扣减操作的凭证，用于后续的事务处理和补偿。
- **锁定库存**：在扣减库存之前，先锁定库存，防止超卖。
- **回滚**：当事务失败时，将数据恢复到事务开始之前的状态。

## 可作为 QA Ground Truth 的高信息密度摘要
库存服务接收扣减请求，校验参数，查询库存。若参数无效则返回错误，若库存不足则返回库存不足。若参数有效且库存充足，则创建扣减事务，锁定库存，生成扣减凭证，发送MQ消息，等待事务提交或回滚。事务提交则提交库存扣减，更新Redis缓存，删除扣减凭证，返回成功响应；事务回滚则释放锁定库存，删除扣减凭证，返回回滚成功。异步扣减补偿服务监听MQ消息，检查扣减凭证状态，若凭证有效且未处理，则查询库存锁定记录，若锁定记录存在，则释放锁定库存，删除扣减凭证，记录补偿日志。
