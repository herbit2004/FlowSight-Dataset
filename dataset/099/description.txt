## 图类型与用途
这是一个流程图，用于展示 GNN 项目的架构和数据处理流程。它描述了基础设施层、核心处理层、代码生成层以及分析与输出层之间的关系，帮助理解项目的整体结构和流程。

## 图的整体布局
图采用从左到右的布局，分为四个主要层次，分别用 subgraph 标出。信息从基础设施层开始，经过核心处理层和代码生成层，最终到达分析与输出层。

## 分组/子图/阶段说明
- **Infrastructure Layer**：基础设施层，包含 `Utils` 和 `Pipeline` 模块，为其他模块提供基础支持和流程控制。
- **Core Processing**：核心处理层，包含 `GNN`、`TypeChecker`、`Validation` 和 `Export` 模块，负责处理 GNN 代码的核心逻辑，进行类型检查、验证和导出。
- **Code Generation**：代码生成层，包含 `Render` 和 `Execute` 模块，负责将 GNN 代码渲染成可执行的代码或文档，并执行渲染后的代码。
- **Analysis & Output**：分析与输出层，包含 `LLM`、`Analysis` 和 `Report` 模块，负责对执行结果进行分析，并生成最终的报告。

## 节点逐项说明
- **Utils[utils/]**：包含各种实用工具函数和模块，为其他模块提供基础支持。根据 README 和 `AGENTS.md`，该模块提供共享 utilities。
- **Pipeline[pipeline/]**：定义了数据处理的管道流程，负责协调各个模块的执行顺序。根据 README 和 `AGENTS.md`，该模块负责 pipeline orchestration。
- **GNN[gnn/]**：GNN 模块，是系统的核心，负责处理 GeneralizedNotationNotation 的逻辑。根据 README 和 `AGENTS.md`，该模块负责 GNN file discovery, parsing, and multi-format serialization。
- **TypeChecker[type_checker/]**：类型检查器，用于验证 GNN 代码的类型正确性。根据 README 和 `AGENTS.md`，该模块负责 GNN syntax validation, type checking, and resource estimation。
- **Validation[validation/]**：验证模块，用于验证 GNN 代码的有效性和一致性。根据 README 和 `AGENTS.md`，该模块负责 advanced validation and consistency checking。
- **Export[export/]**：导出模块，用于将 GNN 代码导出为其他格式。根据 README 和 `AGENTS.md`，该模块负责 multi-format export generation。
- **Render[render/]**：渲染模块，负责将 GNN 代码渲染成可执行的代码或文档。根据 README 和 `AGENTS.md`，该模块负责 code generation for simulation frameworks。
- **Execute[execute/]**：执行模块，负责执行渲染后的代码。根据 README 和 `AGENTS.md`，该模块负责 execute rendered simulation scripts。
- **LLM[llm/]**：大型语言模型模块，可能用于辅助分析或生成报告。根据 README 和 `AGENTS.md`，该模块负责 LLM-enhanced analysis and interpretation。
- **Analysis[analysis/]**：分析模块，负责对执行结果进行分析。根据 README 和 `AGENTS.md`，该模块负责 advanced statistical analysis。
- **Report[report/]**：报告模块，负责生成最终的报告。根据 README 和 `AGENTS.md`，该模块负责 comprehensive analysis report generation。

## 连线、分支与汇聚关系
- `Utils --> GNN`：`Utils` 模块为 `GNN` 模块提供支持。
- `Utils --> TypeChecker`：`Utils` 模块为 `TypeChecker` 模块提供支持。
- `Utils --> Render`：`Utils` 模块为 `Render` 模块提供支持。
- `Pipeline --> GNN`：`Pipeline` 模块协调 `GNN` 模块的执行。
- `Pipeline --> Render`：`Pipeline` 模块协调 `Render` 模块的执行。
- `GNN --> TypeChecker`：`GNN` 模块将数据传递给 `TypeChecker` 模块进行类型检查。
- `GNN --> Validation`：`GNN` 模块将数据传递给 `Validation` 模块进行验证。
- `GNN --> Export`：`GNN` 模块将数据传递给 `Export` 模块进行导出。
- `GNN --> Render`：`GNN` 模块将数据传递给 `Render` 模块进行渲染。
- `Render --> Execute`：`Render` 模块将渲染后的代码传递给 `Execute` 模块执行。
- `Execute --> Analysis`：`Execute` 模块的输出传递给 `Analysis` 模块进行分析。
- `LLM --> Analysis`：`LLM` 模块的输出传递给 `Analysis` 模块进行分析，形成汇聚关系。
- `Analysis --> Report`：`Analysis` 模块的结果最终生成 `Report`。

## 仓库语境与术语解释
- **GNN (Generalized Notation Notation)**：一种基于文本的语言，用于标准化 Active Inference 生成模型的表示和通信。
- **Active Inference**：一种认知科学理论，认为生物体通过最小化自由能来感知和行动。
- **Pipeline**：数据处理流程，负责协调各个模块的执行顺序。该流程由 `pipeline/` 目录下的模块实现。
- **Utils**：实用工具模块，提供各种辅助函数和工具，位于 `utils/` 目录下。
- **TypeChecker**：类型检查器，用于验证 GNN 代码的类型正确性，位于 `type_checker/` 目录下。
- **Validation**：验证模块，用于验证 GNN 代码的有效性和一致性，位于 `validation/` 目录下。
- **Render**：渲染模块，负责将 GNN 代码渲染成可执行的代码或文档，位于 `render/` 目录下。
