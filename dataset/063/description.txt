## 图类型与用途
这是一个流程图，描述了 Litho (deepwiki-rs) 的研究流程，展示了如何通过多个 Researcher 分析代码库并生成报告。该图在仓库中用于概括 Litho 的核心文档生成流程，特别是研究阶段。

## 图的整体布局
图采用从上到下的布局。顶部是 Research Orchestrator，中间是多个 Researcher 及其生成的 Report，底部是 Memory 节点，表示报告的最终存储位置。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：
1.  **研究协调阶段**：由 Research Orchestrator 负责协调和启动各个 Researcher。
2.  **研究分析阶段**：各个 Researcher 分析代码库并生成相应的报告。
3.  **报告存储阶段**：所有生成的报告最终都被存储到 Memory 中。

## 节点逐项说明
- **Research Orchestrator**：整个研究流程的中心，负责协调和启动各个 Researcher。根据 `src/generator/research/orchestrator.rs`，它负责执行 agent 分析 pipelines。
- **SystemContext Researcher**：负责分析整个系统的上下文信息，例如系统的目标、用户、与其他系统的交互等。
- **Domain Module Detector**：负责检测代码库中的领域模块，即根据业务逻辑划分的模块。
- **Architecture Researcher**：负责分析代码库的架构，例如模块之间的依赖关系、数据流等。
- **Workflow Researcher**：负责分析代码库中的工作流程，例如用户如何与系统交互，系统如何处理请求等。
- **Key Module Insights**：负责深入分析代码库中的关键模块，提取关键信息和设计决策。
- **System Context Report**：由 SystemContext Researcher 生成，包含系统的上下文信息。
- **Domain Module Report**：由 Domain Module Detector 生成，包含领域模块的信息。
- **Architecture Analysis Report**：由 Architecture Researcher 生成，包含代码库的架构分析结果。
- **Workflow Analysis Report**：由 Workflow Researcher 生成，包含代码库的工作流程分析结果。
- **Module Deep Insights**：由 Key Module Insights 生成，包含关键模块的深入分析结果。
- **Memory**：所有报告的最终存储位置。

## 连线、分支与汇聚关系
- `Research Orchestrator -> SystemContext Researcher`：研究协调器启动系统上下文研究器。
- `Research Orchestrator -> Domain Module Detector`：研究协调器启动领域模块检测器。
- `Research Orchestrator -> Architecture Researcher`：研究协调器启动架构研究器。
- `Research Orchestrator -> Workflow Researcher`：研究协调器启动工作流研究器。
- `Research Orchestrator -> Key Module Insights`：研究协调器启动关键模块洞察。
- `SystemContext Researcher -> System Context Report`：系统上下文研究器生成系统上下文报告。
- `Domain Module Detector -> Domain Module Report`：领域模块检测器生成领域模块报告。
- `Architecture Researcher -> Architecture Analysis Report`：架构研究器生成架构分析报告。
- `Workflow Researcher -> Workflow Analysis Report`：工作流研究器生成工作流分析报告。
- `Key Module Insights -> Module Deep Insights`：关键模块洞察生成模块深度洞察。
- `System Context Report -> Memory`：系统上下文报告存储到内存。
- `Domain Module Report -> Memory`：领域模块报告存储到内存。
- `Architecture Analysis Report -> Memory`：架构分析报告存储到内存。
- `Workflow Analysis Report -> Memory`：工作流分析报告存储到内存。
- `Module Deep Insights -> Memory`：模块深度洞察存储到内存。
- `System Context Report, Domain Module Report, Architecture Analysis Report, Workflow Analysis Report, Module Deep Insights -> Memory`：所有报告汇聚到 Memory 节点，形成汇聚关系。

## 仓库语境与术语解释
- **Litho (deepwiki-rs)**：一个 AI 驱动的文档生成引擎，能够自动分析源代码并生成架构文档，如 README 所述。
- **Researcher**：在 Litho 中，Researcher 是负责分析代码库特定方面的组件，例如系统上下文、领域模块、架构和工作流程。
- **Research Orchestrator**：根据 `src/generator/research/orchestrator.rs`，它负责协调和启动各个 Researcher，执行 agent 分析 pipelines。
- **SystemContextResearcher**：根据 `src/generator/research/agents/system_context_researcher.rs`，负责分析项目的核心目标、功能价值和系统边界。
- **DomainModulesDetector**：根据 `src/generator/research/agents/domain_modules_detector.rs`，负责识别项目中的领域架构和模块。
- **ArchitectureResearcher**：根据 `src/generator/research/agents/architecture_researcher.rs`，负责分析系统的整体架构。
- **WorkflowResearcher**：根据 `src/generator/research/agents/workflow_researcher.rs`，负责分析项目的核心功能工作流程。
- **KeyModulesInsight**：根据 `src/generator/research/agents/key_modules_insight.rs`，负责深入分析核心模块的技术细节。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 Litho 的研究流程，从 Research Orchestrator 开始，它协调多个 Researcher（SystemContext Researcher, Domain Module Detector, Architecture Researcher, Workflow Researcher, Key Module Insights）分析代码库的不同方面。每个 Researcher 生成相应的报告（System Context Report, Domain Module Report, Architecture Analysis Report, Workflow Analysis Report, Module Deep Insights），最终所有报告都被存储在 Memory 中。这个流程的目标是从代码库中提取各种信息，并以结构化的报告形式呈现出来，从而自动生成高质量的文档。其中，Research Orchestrator 是流程的起点和协调者，Memory 是所有报告的汇聚点。
