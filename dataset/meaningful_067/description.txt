## 图类型与用途
该图是一个流程图，具体来说是一个工作流状态机。它描述了财务报销的完整流程，包括申请、审批、审核、打款和归档等环节。该图清晰地展示了各个环节之间的流转关系和可能的状态变化。

## 图的整体布局
该图采用从左到右的布局方式。流程从“提交报销申请”开始，最终到达“归档完成”。整体流程呈现出线性结构，中间存在分支和循环。

## 分组/子图/阶段说明
图中包含一个名为“工作流状态机 - 财务报销”的子图，它概括了整个报销流程。子图内部可以细分为以下阶段：
1. 申请与审批阶段：包括提交报销申请和审批人审批。
2. 财务审核阶段：包括财务审核和财务修改。
3. 打款阶段：出纳打款。
4. 归档阶段：包括完成和归档。

## 节点逐项说明
- **A[提交报销申请]**: 报销流程的起始节点，表示申请人提交报销申请。
- **B{审批人审批}**: 审批人对报销申请进行审批，决定是否同意。
- **C[财务审核]**: 财务部门对报销申请进行审核，确认是否符合财务规定。
- **D[申请人修改]**: 申请人根据审批人的意见修改报销申请。
- **E[出纳打款]**: 出纳部门根据财务审核的结果进行打款。
- **F[财务修改]**: 财务部门根据审核结果修改报销申请。
- **G[完成]**: 表示报销流程的完成状态。
- **H{归档}**: 将报销单据进行归档。
- **I[归档完成]**: 报销流程的最终状态，表示归档完成。

## 连线、分支与汇聚关系
- A -> B：提交报销申请后，进入审批人审批环节。
- B -- 同意 --> C：审批人同意报销申请，进入财务审核环节。
- B -- 拒绝 --> D：审批人拒绝报销申请，需要申请人修改。
- C -- 通过 --> E：财务审核通过，进入出纳打款环节。
- C -- 驳回 --> F：财务审核驳回，需要财务修改。
- F -> C：财务修改后，重新进入财务审核环节。
- D -> B：申请人修改后，重新进入审批人审批环节。
- E -> G：出纳打款完成后，流程进入完成状态。
- G -> H：流程完成后，进入归档环节。
- H -- 自动归档 --> I：自动归档完成后，流程结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **报销申请**：员工因公务活动产生的费用，向公司申请报销的单据。
- **审批人**：负责审批报销申请的领导或主管。
- **财务审核**：财务部门对报销申请进行审核，确认其合规性。
- **出纳打款**：出纳部门根据审核结果，将报销款项支付给申请人。
- **归档**：将报销单据整理并保存，以便日后查阅。
- **自动归档**: 系统自动将电子单据进行归档。

## 可作为 QA Ground Truth 的高信息密度摘要
财务报销流程从提交报销申请开始，经过审批人审批，若同意则进入财务审核，否则申请人需修改后重新审批。财务审核通过后，出纳打款，流程完成并进入归档环节，最终归档完成。财务审核若驳回，则需要财务修改后重新审核。
