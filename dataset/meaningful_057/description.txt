## 图类型与用途
这是一个流程图，描述了系统配置变更与回滚的完整流程。该图展示了从配置变更请求发起，到最终变更完成或回滚完成的各个步骤，包括权限校验、人工审核、配置快照、变更验证等环节。流程中包含了正常变更和回滚两种分支。

## 图的整体布局
该图采用从左到右的布局方式。流程从左侧的“配置变更请求”开始，经过一系列处理步骤，最终到达右侧的“流程结束”。整个流程呈现出清晰的层次结构。

## 分组/子图/阶段说明
图中包含三个子图：
- **系统配置变更与回滚流程**：包含整个流程的主体部分。
- **回滚分支**：包含了回滚流程相关的节点。
- **正常变更分支**：包含了正常变更流程相关的节点。

## 节点逐项说明
- **A[配置变更请求]**: 流程的起始节点，表示发起配置变更的请求。
- **B{权限校验}**: 对配置变更请求进行权限校验，判断是否有权限进行变更。
- **C[生成变更工单]**: 根据配置变更请求生成相应的工单。
- **D[人工审核]**: 对变更工单进行人工审核，确认变更的合理性和必要性。
- **E[生成配置快照]**: 在应用配置变更前，生成当前配置的快照，用于后续的回滚操作。
- **F[锁定配置]**: 锁定配置，防止在变更过程中被其他操作修改。
- **G[应用配置变更]**: 将配置变更应用到系统中。
- **H{变更验证}**: 验证配置变更是否成功。
- **I[更新配置快照]**: 如果变更成功，则更新配置快照。
- **K[解锁配置]**: 解锁配置，允许其他操作修改。
- **L[变更完成]**: 变更流程完成。
- **J[启动回滚]**: 如果变更验证失败，则启动回滚流程。
- **M[恢复配置快照]**: 恢复之前生成的配置快照。
- **N{回滚验证}**: 验证回滚是否成功。
- **O[解锁配置]**: 回滚成功后，解锁配置。
- **Q[回滚完成]**: 回滚流程完成。
- **P[告警并停止回滚]**: 如果回滚验证失败，则发出告警并停止回滚。
- **Reject[拒绝请求]**: 拒绝配置变更请求。
- **End[流程结束]**: 流程的结束节点。

## 连线、分支与汇聚关系
- A -> B：配置变更请求需要进行权限校验。
- B -- 通过 --> C：权限校验通过后，生成变更工单。
- B -- 失败 --> Reject：权限校验失败后，拒绝请求。
- C -> D：生成变更工单后，需要进行人工审核。
- D -- 批准 --> E：人工审核批准后，生成配置快照。
- D -- 拒绝 --> Reject：人工审核拒绝后，拒绝请求。
- E -> F：生成配置快照后，锁定配置。
- F -> G：锁定配置后，应用配置变更。
- G -> H：应用配置变更后，进行变更验证。
- H -- 成功 --> I：变更验证成功后，更新配置快照。
- H -- 失败 --> J：变更验证失败后，启动回滚。
- I -> K：更新配置快照后，解锁配置。
- K -> L：解锁配置后，变更完成。
- J -> M：启动回滚后，恢复配置快照。
- M -> N：恢复配置快照后，进行回滚验证。
- N -- 成功 --> O：回滚验证成功后，解锁配置。
- N -- 失败 --> P：回滚验证失败后，告警并停止回滚。
- O -> Q：解锁配置后，回滚完成。
- Q -> End：回滚完成后，流程结束。
- P -> End：告警并停止回滚后，流程结束。
- L -> End：变更完成后，流程结束。
- Reject -> End：拒绝请求后，流程结束。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **配置变更请求**: 提出对系统配置进行修改的申请。
- **权限校验**: 验证用户是否有权限进行配置变更操作。
- **配置快照**: 系统配置在特定时间点的备份，用于回滚操作。
- **锁定配置**: 防止在配置变更过程中，其他操作修改配置。
- **回滚**: 将系统配置恢复到之前的状态。
- **告警**: 系统检测到异常情况时发出的通知。

## 可作为 QA Ground Truth 的高信息密度摘要
系统配置变更流程开始于配置变更请求，首先进行权限校验，校验通过后生成变更工单，并进行人工审核。审核通过后，生成配置快照并锁定配置，然后应用配置变更。应用后进行变更验证，若验证成功，则更新配置快照并解锁配置，流程结束；若验证失败，则启动回滚流程，恢复配置快照并进行回滚验证。回滚验证成功则解锁配置，流程结束；回滚验证失败则告警并停止回滚，流程结束。权限校验或人工审核不通过，则拒绝请求，流程结束。
