## Diagram Type & Purpose
This is an architecture diagram depicting the structure and data flow within a Lightning Web Component (LWC) application. It illustrates the interaction between different layers, including the UI, controller, core engine, and data layers. The diagram provides a high-level overview of the system's components and their relationships.

## Overall Layout
The diagram is laid out in a top-down (TD) manner, with the UI Layer at the top and the Data Layer at the bottom. It shows a hierarchical structure, starting with the main orchestrator in the UI Layer and branching down to the data sources. The start node is `jtQueryViewer`, and the end nodes are `Custom Metadata` and `Salesforce DB`.

## Repository Context & Terminology
- **Lightning Web Components (LWC)**: A web standard-based programming model for building user interfaces on the Salesforce platform.
- **Apex**: A proprietary programming language developed by Salesforce, used to execute business logic on the Salesforce platform.
- **Singleton**: A design pattern that restricts the instantiation of a class to one object.
- **Caching**: A technique used to store frequently accessed data in a temporary storage location to improve performance.
- **Custom Metadata**: Customizable, deployable, packageable, and upgradeable metadata. It allows developers to create custom application configurations.
- **Salesforce DB**: The database used by the Salesforce platform to store data.

## High-Density QA Ground Truth Summary
The architecture begins with the `jtQueryViewer` component in the UI Layer, acting as the main orchestrator. It initiates interactions with `jtSearchableCombobox`, `jtExecuteButton`, `jtQueryResults`, and `jtCacheModal` components. The `jtSearchableCombobox` and `jtExecuteButton` components trigger the `JT_QueryViewerController` in the Controller Layer, which is responsible for query execution. The `jtCacheModal` also interacts with the `JT_QueryViewerController`. The `JT_QueryViewerController` then utilizes the `JT_DataSelector` in the Core Engine, which implements a singleton pattern and caching mechanisms. The `JT_DataSelector` interacts with both the `Salesforce DB` and `Custom Metadata` in the Data Layer. Separately, the `JT_MetadataCreator` manages configurations in `Custom Metadata`, and the `JT_UsageFinder` searches for usage data in the `Salesforce DB`. The data flow culminates in the `Salesforce DB` and `Custom Metadata`, representing the data storage locations. The `JT_DataSelector` component, central to the Core Engine, exemplifies the use of caching to optimize data retrieval from both the `Salesforce DB` and `Custom Metadata`.
