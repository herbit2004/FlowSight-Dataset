## 节点逐项说明
- **A[接收事件]**: 接收外部事件作为流程的起点。
- **B[事件预处理]**: 对接收到的事件进行初步处理，例如数据清洗、格式转换等。
- **C{规则集检索}**: 根据事件的特征，检索匹配的规则集。
- **D[命中规则集]**: 成功检索到匹配的规则集。
- **E[加载规则集]**: 将命中的规则集加载到内存中，以便后续的规则判定。
- **F{规则判定}**: 根据加载的规则集，对事件进行规则判定。
- **G[规则匹配]**: 规则判定过程中，规则与事件匹配。
- **H{全部规则匹配?}**: 判断是否所有规则都已匹配。
- **I[执行动作编排]**: 根据匹配的规则，执行相应的动作编排。
- **J[动作执行器]**: 负责执行编排好的动作。
- **K[输出执行结果]**: 输出动作执行的结果。
- **L[默认动作]**: 当没有命中任何规则集时，执行的默认动作。
- **M[事件后处理]**: 对执行结果进行后处理。
- **N[推送结果通知]**: 将最终结果推送给相关方。

## 连线、分支与汇聚关系
- A -> B：接收事件后进行事件预处理。
- B -> C：事件预处理后进行规则集检索。
- C -- 未命中 --> L：规则集检索未命中，执行默认动作。
- C -- 命中 --> D：规则集检索命中，加载规则集。
- D -> E：命中规则集后加载规则集。
- E -> F：加载规则集后进行规则判定。
- F -> G：规则判定过程中进行规则匹配。
- G -- 匹配 --> H：规则匹配后判断是否全部规则匹配。
- H -- Yes --> I：全部规则匹配，执行动作编排。
- H -- No --> F：未全部规则匹配，返回规则判定。
- I -> J：执行动作编排后，交给动作执行器执行。
- J -> K：动作执行器执行后，输出执行结果。
- L -> J：默认动作执行后，交给动作执行器执行。
- K -> M：输出执行结果后进行事件后处理。
- M -> N：事件后处理后推送结果通知。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **规则引擎**: 一种用于自动化决策的软件系统，它根据预定义的规则对输入数据进行评估，并执行相应的动作。
- **规则集**: 一组相关的规则，用于描述特定场景下的决策逻辑。
- **事件**: 触发规则引擎执行的数据输入。
- **动作编排**: 根据匹配的规则，将多个动作组合成一个执行序列。
- **动作执行器**: 负责执行编排好的动作序列。
- **事件后处理**: 对动作执行的结果进行进一步处理，例如数据转换、格式化等。

## 可作为 QA Ground Truth 的高信息密度摘要
规则引擎流程从接收事件开始，进行事件预处理后检索规则集。若未命中规则集，则执行默认动作；若命中，则加载规则集并进行规则判定。规则判定过程中，若全部规则匹配，则执行动作编排，否则继续规则判定。动作编排完成后，由动作执行器执行，输出执行结果，最后进行事件后处理并推送结果通知。
