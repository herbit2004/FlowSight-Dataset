## Diagram Type & Purpose

## Repository Context & Terminology
- **User Registration**: The process of creating a new account in the system.
- **Login**: The process of accessing an existing account in the system.
- **Email Verification**: Confirming the validity of a user's email address.
- **Temporary Token**: A short-lived security token used for email verification.
- **MFA (Multi-Factor Authentication)**: An authentication method that requires multiple verification factors.
- **Session Token**: A token that represents an authenticated user session.
- **User Dashboard**: The main interface for a logged-in user.

## High-Density QA Ground Truth Summary
The user registration and login flow begins with either "User initiates registration" or "User initiates login." For registration, the system first checks the email address format. If invalid, it displays an error. If valid, it checks if the email already exists. If so, an error is shown; otherwise, a temporary token is generated and sent via email. The user clicks the link, and the system validates the token. If valid, a user account is created, activated, and a welcome email is sent, completing registration. If the token is invalid, an error is displayed. For login, the system validates the username and password. Invalid credentials trigger an error. If valid, the system checks if the account is active. Inactive accounts result in an error. Active accounts generate a session token, and the system checks if MFA is enabled. If MFA is enabled, a code is sent, and its validity is checked. Invalid codes display an error. Valid codes, or disabled MFA, result in establishing a session and redirecting the user to their dashboard. The "Session Token" is a crucial element, representing an authenticated user session and enabling access to protected resources. The flow ensures secure user authentication and account management.
