## 图类型与用途
这是一个流程图，描述了 YouTube 频道成功预测的机器学习平台的整体流程，包括数据处理、模型训练、评估和部署。它在仓库中的作用是展示数据如何从原始数据集流向最终的 Next.js 仪表盘。

## 图的整体布局
图整体采用从左到右的布局。起点是原始 CSV 数据集，终点是 Next.js 仪表盘。数据经过一系列处理和模型训练步骤，最终用于推理并展示在仪表盘上。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：数据准备与特征工程、模型训练与评估、推理与结果展示。

## 节点逐项说明
- **Raw CSV Dataset**：原始 CSV 格式的数据集，包含 YouTube 频道的相关信息。根据 README，该数据集来源于 Kaggle，文件名为 `data/Global YouTube Statistics.csv`。
- **Load and Normalize Schema**：加载原始数据并标准化数据模式，例如统一数据类型、处理缺失值等。
- **Feature Engineering**：特征工程，从原始数据中提取有用的特征，为后续的模型训练做准备。
- **Train Supervised Models**：训练监督学习模型，用于预测 YouTube 频道的成功指标。
- **Train Clustering Models**：训练聚类模型，用于发现 YouTube 频道的不同类型或原型。
- **Generate Map and Country Analytics**：生成地图和国家/地区分析报告，提供全局的 YouTube 频道数据洞察。
- **Model Artifacts**：模型工件，包括训练好的监督学习模型和聚类模型。
- **Metrics Report**：指标报告，评估监督学习模型和聚类模型的性能指标。
- **Data Quality Report**：数据质量报告，评估原始数据的质量，例如完整性、准确性等。
- **Manifest and Registry**：清单和注册表，用于管理模型工件、指标报告和数据质量报告的版本和元数据。
- **FastAPI and Flask Inference**：使用 FastAPI 和 Flask 框架构建的推理服务，用于在线预测 YouTube 频道的成功指标。根据 `src/youtube_success_ml/api/fastapi_app.py`，项目主要使用 FastAPI 构建 API。
- **Next.js Dashboard**：使用 Next.js 框架构建的仪表盘，用于展示预测结果和分析报告。根据 `FRONTEND.md`，该仪表盘是 Next.js 应用的一部分。

## 连线、分支与汇聚关系
- `Raw CSV Dataset -> Load and Normalize Schema`：加载原始 CSV 数据集后，进行数据模式的标准化。
- `Load and Normalize Schema -> Feature Engineering`：标准化后的数据进入特征工程阶段。
- `Feature Engineering -> Train Supervised Models`：特征工程后的数据用于训练监督学习模型。
- `Feature Engineering -> Train Clustering Models`：特征工程后的数据也用于训练聚类模型。
- `Feature Engineering -> Generate Map and Country Analytics`：特征工程后的数据还用于生成地图和国家/地区分析报告。
- `Train Supervised Models -> Model Artifacts`：训练好的监督学习模型生成模型工件。
- `Train Clustering Models -> Model Artifacts`：训练好的聚类模型也生成模型工件，形成汇聚关系。
- `Train Supervised Models -> Metrics Report`：训练好的监督学习模型生成指标报告。
- `Train Clustering Models -> Metrics Report`：训练好的聚类模型也生成指标报告，形成汇聚关系。
- `Feature Engineering -> Data Quality Report`：特征工程后的数据用于生成数据质量报告。
- `Model Artifacts -> Manifest and Registry`：模型工件被存储在清单和注册表中。
- `Metrics Report -> Manifest and Registry`：指标报告也被存储在清单和注册表中，形成汇聚关系。
- `Data Quality Report -> Manifest and Registry`：数据质量报告也被存储在清单和注册表中，形成汇聚关系。
- `Manifest and Registry -> FastAPI and Flask Inference`：清单和注册表中的模型工件被用于 FastAPI 和 Flask 构建的推理服务。
- `FastAPI and Flask Inference -> Next.js Dashboard`：推理服务的预测结果被展示在 Next.js 仪表盘上。

## 仓库语境与术语解释
- **Raw CSV Dataset**：原始数据集，存储在 `data/Global YouTube Statistics.csv`，包含 YouTube 频道统计信息。
- **Feature Engineering**：根据 `src/youtube_success_ml/data/loader.py`，特征工程包括标准化列名、处理缺失值、数据类型转换等。
- **Supervised Models**：根据 `src/youtube_success_ml/models/supervised.py`，项目使用 RandomForestRegressor 作为监督学习模型。
- **Clustering Models**：根据 `src/youtube_success_ml/models/clustering.py`，项目使用 KMeans 和 DBSCAN 作为聚类模型。
- **FastAPI**：用于构建 API 的 Python 框架，参见 `src/youtube_success_ml/api/fastapi_app.py`。
- **Flask**: 另一个用于构建 API 的 Python 框架，与 FastAPI 一起用于推理服务。
- **Next.js Dashboard**：使用 Next.js 构建的前端仪表盘，用于展示预测结果，参见 `FRONTEND.md`。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 YouTube 频道成功预测机器学习平台的完整流程。从原始 CSV 数据集开始，数据经过加载、标准化和特征工程处理后，分别用于训练监督学习模型和聚类模型，并生成地图分析报告。训练好的模型工件、指标报告和数据质量报告被存储在清单和注册表中，最终通过 FastAPI 和 Flask 构建的推理服务将预测结果展示在 Next.js 仪表盘上。其中，特征工程、模型训练和 API 服务是关键环节。
