## 图类型与用途
这是一个流程图，描述了 EstateWise 聊天机器人的 AI 架构流程。它展示了用户消息如何被处理，经过一系列步骤，最终生成并展示给用户响应，以及用户反馈如何影响系统。该图在 README.md 中被提及，用于展示 AI 架构流程。

## 图的整体布局
图整体采用从上到下的布局。顶部是用户消息的输入，经过一系列处理和判断，最终在用户界面上显示响应。流程中包含条件分支和反馈循环。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为以下阶段：
1.  消息接收与预处理
2.  用户认证与历史加载
3.  AI 代理输入准备与工具编排
4.  Pinecone 数据使用判断与查询
5.  混合专家 API 请求与响应生成
6.  结果展示与用户反馈

## 节点逐项说明
- **UM (User Message)**：用户输入的消息，作为整个流程的起点。
- **API (RESTful APIs)**：后端提供的 RESTful API 接口，用于接收用户消息。
- **RME (Receive Message Event)**：接收到消息事件。
- **BP (Backend Processing)**：后端处理流程的起始点。
- **Auth (Is User Authenticated?)**：判断用户是否已认证的节点。
- **LMDB (Load Conversation History from MongoDB)**：从 MongoDB 数据库加载对话历史记录。
- **LBrowser (Load Conversation History from Local Browser Storage)**：从本地浏览器存储加载对话历史记录。
- **Prep (Prepare AI Agent Input)**：准备 AI 代理的输入，包括用户消息、系统历史记录和系统提示。
- **AInput (AI Agent Input)**：准备好的 AI 代理输入。
- **Orchestration (Agent Tool Orchestration)**：代理工具编排，负责协调不同的 AI 工具。根据 README，EstateWise 利用 Agentic AI Pipeline 来编排整个 AI 工作流。
- **UsePinecone (Use Data from Pinecone?)**：判断是否使用来自 Pinecone 的数据的节点。Pinecone 是一个向量数据库，用于存储房产信息的向量化表示。
- **QueryPinecone (Queries Vectorized Properties Data from Pinecone)**：从 Pinecone 查询向量化的房产数据。
- **NoPinecone (Proceed without RAG data from Pinecone)**：不使用 Pinecone 数据，直接进入下一步。
- **MOE (Mixture-of-Experts API Request Pipeline)**：混合专家 API 请求管道，包含 6 个专业 AI 专家和一个 AI 合并器。根据 README，EstateWise 使用 Mixture of Experts (MoE) 动态路由每个查询通过一个主模型来选择专门的子模型。
- **Generate (Generate Final Response)**：生成最终响应，包括文本和图表。
- **APIResp (API Request Response)**：API 请求的响应。
- **Display (Display Response)**：在用户界面上显示响应。
- **Rate (User Rates Response?)**：用户是否对响应进行评分的判断节点。
- **Update (User Gives Thumbs Down)**：用户给出差评，需要更新专家权重，并重新进行 API 请求。
- **End (User Gives Thumbs Up)**：用户给出好评，无需更新。

## 连线、分支与汇聚关系
- `UM -> API`：用户消息通过 RESTful API 发送到后端。
- `API -> RME`：API 接收到消息事件。
- `RME -> BP`：接收到消息事件后，开始后端处理。
- `BP -> Auth`：后端处理后进行用户认证。
- `Auth -- Yes --> LMDB`：如果用户已认证，则从 MongoDB 加载对话历史。
- `Auth -- No --> LBrowser`：如果用户未认证，则从本地浏览器存储加载对话历史。
- `LMDB -> Prep`：从 MongoDB 加载对话历史后，准备 AI 代理的输入。
- `LBrowser -> Prep`：从本地浏览器存储加载对话历史后，准备 AI 代理的输入。
- `Prep -> AInput`：准备 AI 代理的输入。
- `AInput -> Orchestration`：准备好的 AI 代理输入进入代理工具编排。
- `Orchestration -> UsePinecone`：代理工具编排后，判断是否使用 Pinecone 数据。
- `UsePinecone -- Yes --> QueryPinecone`：如果使用 Pinecone 数据，则从 Pinecone 查询向量化的房产数据。
- `UsePinecone -- No --> NoPinecone`：如果不使用 Pinecone 数据，则直接进入下一步。
- `QueryPinecone -> MOE`：从 Pinecone 查询向量化的房产数据后，进入混合专家 API 请求管道。
- `NoPinecone -> MOE`：不使用 Pinecone 数据，直接进入混合专家 API 请求管道，形成汇聚关系。
- `MOE -> Generate`：混合专家 API 请求管道生成最终响应。
- `Generate -> APIResp`：生成最终响应后，得到 API 请求的响应。
- `APIResp -> Display`：API 请求的响应在用户界面上显示。
- `Display -> Rate`：在用户界面上显示响应后，用户对响应进行评分。
- `Rate -- Thumbs Down --> Update`：如果用户给出差评，需要更新专家权重，并重新进行 API 请求。
- `Update -> MOE`：更新专家权重后，重新进入混合专家 API 请求管道。
- `Rate -- Thumbs Up --> End`：如果用户给出好评，无需更新。

## 仓库语境与术语解释
- **RESTful APIs**：后端提供的 RESTful API 接口，用于接收用户消息。
- **MongoDB**：用于存储用户认证后的对话历史记录。
- **Pinecone**：一个向量数据库，用于存储房产信息的向量化表示，用于 RAG (Retrieval Augmented Generation) 流程。backend/src/pineconeClient.ts 定义了 Pinecone 客户端。
- **RAG (Retrieval Augmented Generation)**：一种结合检索和生成模型的 AI 技术，用于生成更准确和相关的响应。README 提到 EstateWise 使用 Hybrid RAG (Vector + Graph)。
- **Mixture of Experts (MoE)**：一种机器学习技术，使用多个专家模型来处理不同的输入。
- **Agentic AI Pipeline**：EstateWise 使用 Agentic AI Pipeline 来编排整个 AI 工作流，管理数据检索、专家路由、响应生成和反馈集成。
- **Expert Weights**：用于调整混合专家系统中各个专家的权重，根据用户反馈进行更新。backend/src/controllers/chat.controller.ts 中使用了 expertWeights。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 EstateWise 聊天机器人的 AI 架构流程。用户消息通过 RESTful API 发送到后端，经过用户认证后，从 MongoDB 或本地浏览器存储加载对话历史。然后，准备 AI 代理的输入，并进行代理工具编排。根据是否使用 Pinecone 数据，选择从 Pinecone 查询向量化的房产数据或直接进入混合专家 API 请求管道。最终生成响应并显示在用户界面上，用户可以对响应进行评分，给出好评或差评，差评会触发专家权重的更新和重新请求。核心流程包括用户认证、数据检索、专家模型选择和反馈循环。
