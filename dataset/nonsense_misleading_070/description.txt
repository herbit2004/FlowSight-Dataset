## High-Density QA Ground Truth Summary
The flowchart begins with a user placing an order (A), which immediately proceeds to a payment success check (B). If payment is successful (B -- Yes --> C), an inventory check is performed. If the items are in stock (C -- In Stock --> D), the order is packaged. If the items are out of stock (C -- Out of Stock --> E), the customer is notified of the delay, and then an order confirmation email is sent (E --> F). If payment is not successful (B -- No --> F), an order confirmation email is also sent, skipping the inventory check. After sending the order confirmation email (F), the order is packaged (D). The packaged order then undergoes a shipping address validation (G). If the address is valid (G -- Yes --> I), a shipping label is generated. If the address is invalid (G -- No --> H), the order is cancelled. However, regardless of address validity, the order is then marked as shipped (I --> J, H --> J). After shipping, the inventory is updated (J --> K), and a shipping notification is sent (K --> L). Finally, the order is delivered (L --> M), and the process loops back to the beginning, with the user placing another order (M --> A). The intentional errors in this diagram include sending the order confirmation email before successful payment in one branch, shipping cancelled orders, and updating inventory after shipping.
