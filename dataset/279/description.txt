## 图类型与用途
这是一个架构图，展示了 AWS 云服务中监控和告警的架构。它描述了如何使用 CloudWatch 监控 API Gateway、Lambda 函数和 DynamoDB，并在出现问题时通过 SNS 主题发送通知。该图在仓库中的作用是展示 Serverless 服务的监控设计。

## 图的整体布局
图整体采用从上到下的布局。顶部是被监控的资源，中间是 CloudWatch 监控部分，底部是通知部分。数据流从上到下，表示监控数据的流向和告警通知的发送。

## 分组/子图/阶段说明
图中包含三个子图：
- **Monitored Resources**：表示被监控的 AWS 资源，包括 API Gateway、Lambda 函数和 DynamoDB 表。
- **CloudWatch Monitoring**：表示 CloudWatch 监控服务，包含仪表盘和告警。
- **Notification**：表示通知服务，使用 SNS 主题发送告警通知。

## 节点逐项说明
- **APIGW (API Gateway)**：API 网关，负责接收和路由 API 请求。该组件是 Serverless 服务的入口。
- **LAMBDA (Lambda Function)**：Lambda 函数，执行具体的业务逻辑。该函数是 Serverless 服务的计算单元。
- **DDB (DynamoDB Tables)**：DynamoDB 表，用于存储数据。该表是 Serverless 服务的数据存储。
- **HL (High-Level Dashboard)**：高级仪表盘，展示 API Gateway 的指标和业务关键绩效指标 (KPIs)。
- **LL (Low-Level Dashboard)**：低级仪表盘，展示 Lambda 函数和 DynamoDB 的指标。
- **API_ALARM (API Gateway Alarms)**：API Gateway 的告警，例如 5XX 错误和延迟。
- **LAMBDA_ALARM (Lambda Alarms)**：Lambda 函数的告警，例如错误和 P90 延迟。
- **DDB_ALARM (DynamoDB Alarms)**：DynamoDB 的告警，例如限制和错误。
- **SNS (SNS Topic)**：SNS 主题，用于发送告警通知，并使用 KMS 加密。

## 连线、分支与汇聚关系
- `APIGW -> API_ALARM`：API Gateway 的指标被 API Gateway 告警监控。
- `LAMBDA -> LAMBDA_ALARM`：Lambda 函数的指标被 Lambda 函数告警监控。
- `DDB -> DDB_ALARM`：DynamoDB 的指标被 DynamoDB 告警监控。
- `API_ALARM -> SNS`：API Gateway 告警触发时，向 SNS 主题发送通知。
- `LAMBDA_ALARM -> SNS`：Lambda 函数告警触发时，向 SNS 主题发送通知。
- `DDB_ALARM -> SNS`：DynamoDB 告警触发时，向 SNS 主题发送通知。
- `API_ALARM -> HL`：API Gateway 告警数据发送到高级仪表盘。
- `LAMBDA_ALARM -> LL`：Lambda 函数告警数据发送到低级仪表盘。
- `DDB_ALARM -> LL`：DynamoDB 告警数据发送到低级仪表盘。
- `LAMBDA_ALARM -> LL` 和 `DDB_ALARM -> LL` 形成汇聚关系，低级仪表盘汇聚了 Lambda 函数和 DynamoDB 的告警数据。

## 仓库语境与术语解释
- **API Gateway**：根据 README，该项目部署了一个 API GW，路径为 `/api/orders`，用于接收 POST 请求。
- **Lambda Function**：根据 README，该项目使用 Lambda 函数执行业务逻辑，并使用 AWS Lambda Powertools。
- **DynamoDB Tables**：根据 README，该项目使用 DynamoDB 表存储数据。
- **CloudWatch**：AWS 的监控服务，用于收集和跟踪指标、日志和事件，并设置告警。
- **SNS Topic**：AWS 的消息通知服务，用于发送告警通知。
- **KMS Encryption**：AWS Key Management Service，用于加密 SNS 主题，保护通知内容。
- **AWS Lambda Powertools**: README 中提到，AWS Lambda handler 使用 AWS Lambda Powertools。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Serverless 服务的监控架构，从 API Gateway、Lambda 函数和 DynamoDB 开始，它们的指标分别被 API Gateway Alarms、Lambda Alarms 和 DynamoDB Alarms 监控。当告警被触发时，会通过 SNS Topic 发送通知。API Gateway Alarms 的数据会发送到 High-Level Dashboard，而 Lambda Alarms 和 DynamoDB Alarms 的数据会汇聚到 Low-Level Dashboard。该架构利用 CloudWatch 监控关键资源，并通过 SNS 实现告警通知。README 提到该项目使用 CDK 部署，并使用 AWS Lambda Powertools。
