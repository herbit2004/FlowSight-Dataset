## 图类型与用途
这是一个分层架构图，展示了 Audio2Text 项目的 Clean Architecture 设计。该项目旨在将音频内容转录为文本，并遵循 Clean Architecture 原则，以确保代码库的可扩展性和可维护性。该图在 README.md 中用于可视化项目结构。

## 图的整体布局
图采用从上到下的分层布局，从 Infrastructure 层开始，依次是 Adapters 层、Use Cases 层和 Entities 层。每一层都依赖于其内部的下一层，最外层的 Infrastructure 层不依赖任何其他层。

## 分组/子图/阶段说明
图中包含四个显式子图，分别代表 Clean Architecture 的四个主要层：
- **Infrastructure**：基础设施层，包含 Web & Devices, User Interface (UI), Databases & External Integrations 等组件，负责与外部系统和用户交互。
- **Adapters**：适配器层，包含 Controllers, Presenters, Gateways 等组件，负责将 Infrastructure 层的请求转换为 Use Cases 层可以理解的格式，并将 Use Cases 层的响应转换为 Infrastructure 层可以使用的格式。
- **Use Cases**：用例层，包含 Use Cases 组件，包含系统的业务逻辑，负责处理来自 Controllers 层的请求，并与 Entities 层进行交互。
- **Entities**：实体层，包含 Learning Objects (LOs), Metadata, Gateway Interfaces, External Integrations 等组件，代表系统中的核心数据实体和接口。

## 节点逐项说明
- **Web & Devices**：代表 Web 界面和设备，是用户与系统交互的入口。
- **User Interface (UI)**：用户界面，负责展示信息和接收用户输入。
- **Databases & External Integrations**：数据库和外部集成，负责数据存储和与其他系统的交互。
- **Controllers**：控制器，负责接收来自 Web 层的请求，并将其传递给 Use Cases 层。根据 `src/main/java/com/falvojr/audio2text/domain/transcribedaudio/adapter/controller/CreateTranscribedAudioController.java`，Controller 负责将 HTTP 请求映射到用例的输入。
- **Presenters**：呈现器，负责将 Use Cases 层返回的数据格式化为 UI 层可以使用的格式。
- **Gateways**：网关，负责与 Infrastructure 层的数据库和外部系统进行交互。
- **Use Cases**：用例，包含系统的业务逻辑，负责处理来自 Controllers 层的请求，并与 Entities 层进行交互。根据 `src/main/java/com/falvojr/audio2text/domain/transcribedaudio/usecase/CreateTranscribedAudioUC.java`，Use Case 编排音频转录和持久化过程。
- **Learning Objects (LOs)**：学习对象，代表系统中的核心数据实体。
- **Metadata**：学习对象的元数据，包括转录文本、语言、修订版本、许可证等信息。
- **Gateway Interfaces**：网关接口，定义了 Gateways 层必须实现的接口，用于与 Infrastructure 层进行交互。
- **External Integrations**：外部集成接口，代表与外部系统（如数据库、WebClient、消息队列等）的集成接口。

## 连线、分支与汇聚关系
- `Web & Devices <--> Controllers`：Web 层与 Controllers 层双向交互，用户请求到达 Controllers，Controllers 将结果返回给 Web 层。
- `User Interface (UI) <--> Presenters`：UI 层与 Presenters 层双向交互，Presenters 将数据格式化后传递给 UI 层显示。
- `Databases & External Integrations <--> Gateways`：数据库和外部集成与 Gateways 层双向交互，Gateways 负责数据的读取和写入。
- `Controllers <--> Use Cases`：Controllers 层调用 Use Cases 层处理业务逻辑。
- `Presenters <--> Use Cases`：Use Cases 层将处理结果传递给 Presenters 层进行格式化。
- `Gateways -..-> Gateway Interfaces`：Gateways 层实现了 Gateway Interfaces。
- `Use Cases <--> Learning Objects (LOs)`：Use Cases 层与 Learning Objects 交互。
- `Use Cases <--> Gateway Interfaces`：Use Cases 层与 Gateway Interfaces 交互。
- `Learning Objects (LOs) -.- Metadata`：Learning Objects 包含 Metadata。
- `Gateway Interfaces -.- External Integrations`：Gateway Interfaces 代表 External Integrations。

## 仓库语境与术语解释
- **Clean Architecture**：一种软件设计原则，旨在通过将系统划分为不同的层，并将依赖关系限制在内部层，从而实现代码的可维护性、可测试性和可扩展性。
- **Audio2Text**：该项目的名称，旨在将音频内容转录为文本格式。
- **Infrastructure Layer**：Clean Architecture 的最外层，包含与外部系统交互的组件，例如 Web 界面、数据库和外部 API。
- **Adapters Layer**：Clean Architecture 的中间层，负责将 Infrastructure 层的请求转换为 Use Cases 层可以理解的格式，并将 Use Cases 层的响应转换为 Infrastructure 层可以使用的格式。
- **Use Cases Layer**：Clean Architecture 的核心层，包含系统的业务逻辑。根据 `src/main/java/com/falvojr/audio2text/config/usecase/TranscribedAudioUCsConfig.java`，该层定义了应用程序的行为。
- **Entities Layer**：Clean Architecture 的最内层，包含系统中的核心数据实体。
- **TranscribedAudio**: 表示转录后的音频数据，相关的 Controller, UseCase, Repository 都在 `src/main/java/com/falvojr/audio2text/domain/transcribedaudio/` 目录下。
- **application.yml**: 配置文件，包含 MongoDB 的 URI 和 OpenAI API Key 等配置信息。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Audio2Text 项目的 Clean Architecture 设计，从 Infrastructure 层（Web & Devices, User Interface, Databases & External Integrations）开始，通过 Adapters 层（Controllers, Presenters, Gateways）与 Use Cases 层交互，最终操作 Entities 层（Learning Objects, Metadata, Gateway Interfaces, External Integrations）。Controllers 接收 Web 层的请求并传递给 Use Cases，Presenters 格式化 Use Cases 的结果以供 UI 使用，Gateways 负责与数据库和外部系统交互。该架构旨在实现代码的可维护性和可扩展性，其中 OpenAI API 用于实现音频转录功能。
