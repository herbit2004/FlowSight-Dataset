## Diagram Type & Purpose
This is a flowchart diagram illustrating the authentication flow of a user accessing an application that uses Single Sign-On (SSO) with SAML (Security Assertion Markup Language). The diagram outlines the steps involved in checking for an existing session, authenticating the user via the SSO provider if necessary, validating the SAML assertion, and establishing a new session if authentication is successful. This flowchart serves as a visual representation of the authentication process, aiding in understanding and troubleshooting the system.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It starts with the user accessing the application and ends with returning a page to the user. The flow branches based on whether a session cookie is present and whether authentication is successful.

## Repository Context & Terminology
- **SSO (Single Sign-On)**: An authentication scheme that allows a user to log in with a single ID to multiple related, yet independent, software systems.
- **SAML (Security Assertion Markup Language)**: An open standard XML-based data format for exchanging authentication and authorization data between parties, in particular, between an identity provider and a service provider.
- **SAML Assertion**: A package of information that supplies statements about a subject, such as a user. It is issued by an SAML authority (the identity provider) and consumed by a SAML relying party (the service provider).
- **Session Cookie**: A small piece of data stored on the user's computer by the web browser while browsing a website. It is used to maintain session state.
- **Session Store**: A storage mechanism (e.g., database, cache) used to persist session data on the server-side.
- **Identity Provider (IdP)**: A system entity that creates, maintains, and manages identity information for principals while providing authentication services to relying applications within a federation or distributed network.
- **Service Provider (SP)**: A system entity that provides services to principals and relies on an identity provider to authenticate those principals.

## High-Density QA Ground Truth Summary
The authentication flow begins when a user accesses the application. The first step is to check for the presence of a session cookie. If a session cookie exists, the session ID is validated against the session store. If the session ID is valid, the user context is retrieved, application logic is executed, and the page is returned. If no session cookie is present, the user is redirected to the SSO provider for authentication. Upon successful authentication at the SSO provider, a SAML assertion is generated and posted to the application. The application then validates the SAML assertion. If the assertion is valid, a new session is created in the session store, a session cookie is generated and set in the user's browser, and the user context is retrieved. If either authentication at the SSO provider fails or the SAML assertion is invalid, an error message is displayed, and the user is prompted to retry authentication, returning to the SSO provider. The process concludes with the retrieval of user context, execution of application logic, and the return of the requested page. SAML assertions are crucial for securely transmitting user authentication and authorization information between the identity provider (SSO provider) and the service provider (application).
