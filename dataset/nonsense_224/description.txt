## 图类型与用途
该图是一个流程图，描述了用户请求处理的流程。该流程包括支付验证、风控、鉴权等环节。

## 图的整体布局
该图从上到下布局，整体呈现一个环状流程。流程从用户请求开始，最终返回响应。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1.  支付验证阶段
2.  风控阶段
3.  鉴权认证阶段

## 节点逐项说明
- **A[用户请求]**: 流程的起始节点，表示用户发起请求。
- **B{支付成功?}**: 判断节点，判断支付是否成功。
- **C[更新缓存]**: 支付成功后，更新缓存。
- **D[调用支付网关]**: 支付不成功时，调用支付网关。
- **E[订单服务]**: 调用订单服务。
- **F[写用户数据库]**: 将数据写入用户数据库。
- **G[发送消息到消息队列]**: 发送消息到消息队列。
- **H[风控系统]**: 进行风控检查。
- **I{风险等级高?}**: 判断节点，判断风险等级是否高。
- **J[人工审核]**: 风险等级高时，进行人工审核。
- **K[生成用户Token]**: 风险等级不高时，生成用户Token。
- **L[鉴权]**: 进行鉴权。
- **M[认证]**: 进行认证。
- **N[返回响应]**: 流程的结束节点，返回响应。

## 连线、分支与汇聚关系
- A -> B：用户请求进入支付成功判断。
- B -- Yes --> C：支付成功，更新缓存。
- B -- No --> D：支付不成功，调用支付网关。
- D -> E：调用支付网关后，进入订单服务。
- E -> F：订单服务写入用户数据库。
- F -> A：写入用户数据库后，回到用户请求。
- C -> G：更新缓存后，发送消息到消息队列。
- G -> H：发送消息到消息队列后，进入风控系统。
- H -> I：风控系统进行风险等级判断。
- I -- Yes --> J：风险等级高，进行人工审核。
- I -- No --> K：风险等级不高，生成用户Token。
- K -> L：生成用户Token后，进行鉴权。
- L -> M：鉴权后，进行认证。
- M -> N：认证后，返回响应。
- J -> N：人工审核后，返回响应。

## 仓库语境与术语解释
- **用户请求**: 用户发起的访问或操作请求。
- **支付网关**: 处理支付请求的接口或服务。
- **订单服务**: 处理订单相关业务的服务。
- **用户数据库**: 存储用户数据的数据库。
- **消息队列**: 用于异步消息传递的组件。
- **风控系统**: 用于识别和控制风险的系统。
- **鉴权**: 验证用户是否有权限访问资源。
- **认证**: 验证用户身份的过程。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先进入支付成功判断，若支付成功则更新缓存并发送消息到消息队列，进入风控系统进行风险等级判断；若支付不成功则调用支付网关，进入订单服务并写入用户数据库后回到用户请求。风控系统判断风险等级高则进行人工审核，否则生成用户Token，进行鉴权和认证后返回响应；人工审核后也返回响应。
