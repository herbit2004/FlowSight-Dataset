## 图类型与用途
这是一个流程图，描述了 Ruflo 平台的信息检索架构，展示了从输入到最终检索结果的整个过程。它在仓库中的作用是概括 Ruflo 平台如何处理信息检索请求，并展示各个组件之间的交互关系。

## 图的整体布局
图整体采用从左到右的布局。从左侧的“Input”子图开始，依次经过“Processing”、“Storage”，最终到达右侧的“Retrieval”子图。

## 分组/子图/阶段说明
图中包含四个显式子图：
- **Input**：表示信息检索的输入阶段，包含用户查询和新的洞察。
- **Processing**：表示对输入信息进行处理的阶段，包含嵌入、归一化和学习等操作。
- **Storage**：表示存储处理后的信息的阶段，包含 HNSW 索引、SQLite 缓存、AgentDB 和内存图数据库。
- **Retrieval**：表示从存储的信息中检索结果的阶段，包含向量搜索、语义匹配和图感知的排序。

## 节点逐项说明
- **Query[Query/Pattern]**：用户输入的查询语句或模式，作为信息检索的起点。
- **Insight[New Insight]**：新的洞察或知识，可能来自其他系统或用户的反馈。
- **Embed[ONNX Embeddings]**：使用 ONNX 模型将文本转换为向量嵌入，用于语义表示。
- **Normalize[Normalization]**：对嵌入向量进行归一化处理，使其具有统一的尺度。
- **Learn[LearningBridge<br/>SONA + ReasoningBank]**：学习桥梁，包含 SONA（Self-Optimizing Neural Architecture）和 ReasoningBank（推理库），用于增强知识表示和推理能力。根据 README，SONA 学习最优路由。
- **HNSW[(HNSW Index<br/>150x faster)]**：使用 HNSW（Hierarchical Navigable Small World）索引来加速向量搜索，速度提升 150 倍。根据 README，HNSW 提供亚毫秒级的检索速度。
- **SQLite[(SQLite Cache)]**：使用 SQLite 数据库作为缓存，存储中间结果，提高性能。
- **AgentDB[(AgentDB)]**：AgentDB，用于存储智能体相关的数据，例如智能体的状态、知识和交互历史。
- **Graph[MemoryGraph<br/>PageRank + Communities]**：内存图数据库，使用 PageRank 算法和社区发现算法来分析和组织知识图谱。
- **Vector[Vector Search]**：基于向量相似度的搜索，用于找到与查询向量最相似的向量。
- **Semantic[Semantic Match]**：语义匹配，基于 AgentDB 中的信息进行语义层面的匹配。
- **Rank[Graph-Aware Ranking]**：图感知的排序，利用图数据库中的信息对检索结果进行排序，提高相关性。
- **Results[Top-K Results]**：返回排序后的前 K 个结果，作为信息检索的终点。

## 连线、分支与汇聚关系
- `Query -> Embed`：用户查询被转换为向量嵌入。
- `Embed -> Normalize`：嵌入向量被归一化。
- `Normalize -> HNSW`：归一化后的向量被存储到 HNSW 索引中。
- `Normalize -> SQLite`：归一化后的向量被存储到 SQLite 缓存中。
- `Insight -> Learn`：新的洞察被用于学习和知识更新。
- `Learn -> AgentDB`：学习到的知识被存储到 AgentDB 中。
- `AgentDB -> Graph`：AgentDB 中的数据被用于构建内存图数据库。
- `HNSW -> Vector`：HNSW 索引用于加速向量搜索。
- `SQLite -> Vector`：SQLite 缓存中的向量被用于向量搜索。
- `AgentDB -> Semantic`：AgentDB 中的信息被用于语义匹配。
- `Vector -> Rank`：向量搜索的结果被用于图感知的排序。
- `Semantic -> Rank`：语义匹配的结果被用于图感知的排序。
- `Graph -> Rank`：内存图数据库的信息被用于图感知的排序。
- `Vector, Semantic, Graph -> Rank`：形成汇聚关系，多个来源的信息汇聚到排序阶段。
- `Rank -> Results`：排序后的结果作为最终的检索结果输出。

## 仓库语境与术语解释
- **RuFlo**：企业 AI 编排平台，用于部署和协调多个 AI 智能体。该图展示了 RuFlo 平台信息检索架构。
- **ONNX Embeddings**：使用 ONNX 运行时将文本转换为向量嵌入，无需 API 调用，速度更快。
- **SONA (Self-Optimizing Neural Architecture)**：自优化神经网络架构，用于学习最优路由。
- **ReasoningBank**：模式存储，用于轨迹学习。
- **HNSW (Hierarchical Navigable Small World)**：一种高效的向量索引技术，用于加速相似性搜索。
- **AgentDB**：用于存储智能体相关数据的数据库。
- **PageRank**：一种图算法，用于评估节点在图中的重要性。
- **Top-K Results**：返回排序后的前 K 个结果。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Ruflo 平台的信息检索架构。用户查询和新的洞察作为输入，经过 ONNX 嵌入和归一化处理后，存储到 HNSW 索引和 SQLite 缓存中。同时，新的洞察被用于学习并存储到 AgentDB 中，AgentDB 数据用于构建内存图数据库。向量搜索和语义匹配利用存储的信息进行检索，最后通过图感知的排序返回 Top-K 结果。其中，HNSW 索引加速向量搜索，AgentDB 存储智能体数据，图感知的排序提高相关性。
