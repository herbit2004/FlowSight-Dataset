## Diagram Type & Purpose
This is a flowchart diagram. It depicts the process of order fulfillment, from the initial submission of an order by a user to its completion or termination. The diagram outlines the steps involved in checking inventory, processing payment, shipping the order, confirming delivery, and handling order completion.

## Overall Layout
The diagram's layout is top-down (TD). It starts with the "User Submits Order" node at the top and flows downwards through a series of processes and decision points, eventually leading to the "End" node. There is no explicit hierarchy, but the flow progresses linearly with branching based on decision outcomes.

## Subgraphs / Stages
No explicit subgraphs; logically divided into 7 stages: order submission, inventory check, payment processing, shipping, delivery confirmation, order confirmation, and completion/termination.

## Edges, Branches & Convergence
- `A --> B`: User submits an order, initiating the process.
- `B -- No --> C`: If inventory is not available, notify the user.
- `B -- Yes --> D`: If inventory is available, process the payment.
- `D --> E`: Payment is processed.
- `E -- No --> G`: If payment is not successful, acknowledge the order.
- `E -- Yes --> H`: If payment is successful, ship the order.
- `H --> I`: Order is shipped.
- `I -- No --> J`: If delivery is not confirmed, investigate the delivery.
- `J --> H`: After investigating delivery, re-ship the order.

- `L -- Yes --> M`: If the order is completed, release hold on funds.
- `L -- No --> D`: If the order is not completed, re-process payment.
- `C --> F`: Notifying user of out-of-stock leads to the end.
- `G --> F`: Acknowledging the order leads to the end.
- `M --> F`: Releasing hold on funds leads to the end.
