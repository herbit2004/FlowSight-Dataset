## High-Density QA Ground Truth Summary
The prompt engineering system begins by ingesting data from external sources such as Google Sheets (`ext_sheet`), external Markdown files (`ext_md`), and potentially other APIs (`ext_api`), facilitated by community contributions (`ext_contrib`). This raw data, in the form of `prompt_excel/*.xlsx` and `prompt_docs/外部MD输入`, is then converted using `library/scripts/excel_to_docs.py` and `library/scripts/docs_to_excel.py` respectively, resulting in a standardized data frame (`ingest_bus`). The core processing is orchestrated by `scripts/start_convert.py`, which triggers data validation and normalization (`validate`) followed by format mapping and transformation (`transform`). The transformed data is then output as standardized Markdown documentation (`prompt_docs/规范MD`) and Excel data (`prompt_excel/导出XLSX`). The Markdown documentation is consumed by various prompt catalogs, including `i18n/zh/prompts/coding_prompts`, `i18n/zh/prompts/system_prompts`, `i18n/zh/prompts/assistant_prompts`, and `i18n/zh/prompts/user_prompts`, as well as the documentation repository (`i18n/zh/documents/*`) and potentially other downstream channels. The `main.py` script serves as the command-line interface, triggered by a `Makefile` and guided by the `README.md` file. The system relies on `scripts/requirements.txt` for dependencies and `library/scripts/config.yaml` for configuration. The final outputs include project context, plans, and code generated from the AI pair programming flow (`deliverables`).
