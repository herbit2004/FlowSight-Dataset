## 图类型与用途
这是一个分层架构图，展示了 Vibe Coding 项目的数据流和架构，用于将想法通过 AI 结对编程转化为现实。它描述了从外部数据源到最终代码产出的整个流程，并概括了数据处理和流程执行的整体架构。

## 图的整体布局
图采用从上到下的分层布局，将系统划分为外部系统与数据源层、数据接入与采集层、数据处理与智能决策层、执行与消费层、用户交互与接口层以及基础设施与横切能力层。数据从顶部的外部系统流入，经过中间层的处理，最终在底部的执行与消费层产出。

## 分组/子图/阶段说明
图中有多个显式子图，分别代表不同的逻辑层：
- **ext_layer (外部系统与数据源层)**：表示外部数据来源，包括社区贡献、Google 表格、外部 Markdown 提示词和其他数据源/API。
- **ingest_layer (数据接入与采集层)**：负责将外部数据接入系统，包括原始 Excel 文件、Markdown 文件，以及用于格式转换的 Python 脚本。
- **core_layer (数据处理与智能决策层 / 核心)**：负责对数据进行校验、转换和规范化，是整个流程的核心。
- **consume_layer (执行与消费层)**：表示最终的输出和消费，包括用于编码、系统设置、辅助等的提示词目录，以及最终的项目上下文和代码产出。
- **ux_layer (用户交互与接口层)**：提供用户与系统交互的接口，包括命令行界面（CLI）和 Makefile 任务封装。
- **infra_layer (基础设施与横切能力层)**：提供基础设施支持，包括 Git 版本控制、备份、依赖管理和配置。

## 连线、分支与汇聚关系
- `ext_contrib -> ext_sheet`：社区贡献者向外部表格贡献数据。
- `ext_contrib -> ext_md`：社区贡献者向外部 Markdown 提示词贡献数据。
- `ext_api -> ext_sheet`：其他数据源/API 向外部表格贡献数据。
- `ext_sheet -> excel_raw`：外部表格数据流入原始 Excel 文件。
- `ext_md -> md_raw`：外部 Markdown 提示词流入原始 Markdown 文件。
- `excel_raw -> excel_to_docs`：原始 Excel 文件通过 `excel_to_docs.py` 脚本转换为 Markdown 文件。
- `md_raw -> docs_to_excel`：原始 Markdown 文件通过 `docs_to_excel.py` 脚本转换为 Excel 文件。
- `excel_to_docs -> ingest_bus`：转换后的 Markdown 文件数据流入标准化数据帧。
- `docs_to_excel -> ingest_bus`：转换后的 Excel 文件数据流入标准化数据帧。
- `ingest_bus -> validate`：标准化数据帧进入字段校验与规范化阶段。
- `validate -> transform`：校验后的数据进入格式映射转换阶段。
- `transform -> artifacts_md`：转换后的数据输出为规范化的 Markdown 格式提示词文件。
- `transform -> artifacts_xlsx`：转换后的数据输出为导出的 Excel 格式提示词文件。
- `orchestrator -> validate`：协调器调用字段校验与规范化组件。
- `orchestrator -> transform`：协调器调用格式映射转换组件。
- `artifacts_md -> catalog_coding`：规范化的 Markdown 提示词文件流入编码提示词目录。
- `artifacts_md -> catalog_system`：规范化的 Markdown 提示词文件流入系统设置提示词目录。
- `artifacts_md -> catalog_assist`：规范化的 Markdown 提示词文件流入辅助提示词目录。
- `artifacts_md -> catalog_user`：规范化的 Markdown 提示词文件流入用户提示词目录。
- `artifacts_md -> docs_repo`：规范化的 Markdown 提示词文件流入文档仓库。
- `artifacts_md -> new_consumer`：规范化的 Markdown 提示词文件流入其他下游渠道。
- `catalog_coding -> ai_flow`：编码提示词目录驱动 AI 结对编程流程。
- `ai_flow -> deliverables`：AI 结对编程流程产出项目上下文、计划和代码。
- `cli -> orchestrator`：命令行界面调用协调器。
- `makefile -> cli`：Makefile 任务封装调用命令行界面。
- `readme -> cli`：README 文件提供使用指南，引导用户使用命令行界面。
- `git -> orchestrator`：Git 版本控制系统支持协调器。
- `backups -> artifacts_md`：备份脚本备份规范化的 Markdown 提示词文件。
- `deps -> orchestrator`：依赖文件支持协调器。
- `config -> orchestrator`：配置文件配置协调器。
- `monitor -> orchestrator`：日志与监控系统支持协调器。

## 仓库语境与术语解释
- **Vibe Coding**：该项目旨在通过与 AI 结对编程，将想法变为现实，提供一个终极工作站。
- **prompts-library**：该目录包含用于管理和转换提示词的脚本和数据，例如 `excel_to_docs.py` 和 `docs_to_excel.py`，以及配置文件 `config.yaml`。
