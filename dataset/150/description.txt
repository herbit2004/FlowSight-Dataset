## 图类型与用途
这是一个流程图，用于指导开发者在 Java Stream API 中选择合适的 `ParallelCollectors` 方法，以实现并行集合处理。它在仓库中的作用是帮助开发者根据不同的需求场景，选择最佳的并行处理策略。

## 图的整体布局
图整体采用从上到下的布局。顶部是起始判断节点，根据不同条件向下分叉，最终到达不同的建议节点。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为两个阶段：阻塞判断阶段和顺序判断阶段。

## 节点逐项说明
- **A[Are you ok blocking the caller thread while waiting for processing to finish?]**: 这是一个判断节点，询问开发者是否可以阻塞调用线程，直到所有并行处理完成。
- **B[Use ParallelCollectors.parallel]**: 这是一个建议节点，建议开发者使用 `ParallelCollectors.parallel` 方法。根据 README，该方法返回 `CompletableFuture`。
- **C{Does the order of elements matter?}**: 这是一个判断节点，询问开发者处理后的元素顺序是否重要。
- **D["Use ParallelCollectors.parallelToStream with c -> c.ordered()"]**: 这是一个建议节点，建议开发者使用 `ParallelCollectors.parallelToStream` 方法，并使用 `c -> c.ordered()` 来保持元素顺序。根据 README，`parallelToStream` 返回 `Stream`。
- **E[Use ParallelCollectors.parallelToStream]**: 这是一个建议节点，建议开发者使用 `ParallelCollectors.parallelToStream` 方法。

## 连线、分支与汇聚关系
- `A -- No --> B`：如果开发者**不可以**阻塞调用线程，则流程到达节点 B，建议使用 `ParallelCollectors.parallel` 方法。
- `A -- Yes --> C`：如果开发者**可以**阻塞调用线程，则流程到达节点 C，询问元素顺序是否重要。
- `C -- Yes --> D`：如果元素顺序**重要**，则流程到达节点 D，建议使用 `ParallelCollectors.parallelToStream` 方法，并使用 `c -> c.ordered()` 来保持元素顺序。
- `C -- No --> E`：如果元素顺序**不重要**，则流程到达节点 E，建议使用 `ParallelCollectors.parallelToStream` 方法。

## 仓库语境与术语解释
- **ParallelCollectors**：根据 README，这是一个工具包，旨在简化 Java 中使用 Stream API 进行并行集合处理的过程，克服标准并行流的限制。
- **ParallelCollectors.parallel**: 根据 `src/main/java/com/pivovarit/collectors/ParallelCollectors.java`，该方法使用 Virtual Threads 执行并行计算，并返回一个包含用户提供的 Collector 结果的 CompletableFuture。
- **ParallelCollectors.parallelToStream**: 根据 `src/main/java/com/pivovarit/collectors/ParallelCollectors.java`，该方法与 `parallel` 类似，但返回一个 Stream。
- **Virtual Threads**: 根据 README，Parallel Collectors 默认使用 Virtual Threads，这是一种比 Project Reactor 更轻量级的解决方案。
- **CompletableFuture**: 根据 README，Parallel Collectors 结合了 Stream API 和 CompletableFuture 的强大功能，允许指定超时、与其他 CompletableFuture 组合以及异步处理。
- **Stream**: 根据 README，`ParallelCollectors.parallelToStream` 返回 `Stream`。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图旨在帮助开发者根据是否允许阻塞调用线程以及是否需要保持元素顺序这两个关键因素，选择合适的 `ParallelCollectors` 方法。流程从判断是否可以阻塞调用线程开始，如果可以，则进一步判断元素顺序是否重要，从而选择是否需要使用 `c -> c.ordered()` 来保持顺序，并使用 `ParallelCollectors.parallelToStream`。如果不能阻塞调用线程，则直接建议使用 `ParallelCollectors.parallel` 方法。`ParallelCollectors.parallel` 返回 `CompletableFuture`，而 `ParallelCollectors.parallelToStream` 返回 `Stream`。该图提供了一个简单的决策树，帮助开发者快速选择适合自己场景的并行处理方法。
