## 图类型与用途
这是一个流程图/架构图，展示了 DeepCode 项目通过 nanobot Gateway 连接不同聊天平台，并利用 DeepCode 引擎进行代码生成和任务跟踪的整体架构。它描述了消息如何在不同组件之间流动，以及 DeepCode 如何与外部 LLM 提供商集成。

## 图的整体布局
图采用从左到右的布局。最左侧是客户端（聊天平台），中间是 nanobot Gateway，右侧是 DeepCode Engine 和 LLM 提供商。

## 分组/子图/阶段说明
图中包含三个子图：
- **Clients (💬 Chat Platforms)**：包含 Feishu, Telegram, Discord 三个聊天平台。
- **Gateway (🐈 nanobot Gateway)**：包含 Agent Loop 组件，负责处理消息和调用 LLM。
- **Engine (🧠 DeepCode Engine)**：包含 Paper → Code, Chat → Code, Task Tracking 三个功能模块。

## 节点逐项说明
- **Clients (💬 Chat Platforms)**：代表不同的聊天平台，作为用户与 DeepCode 交互的入口。
    - **Feishu**：使用 WebSocket 协议进行通信。`nanobot/nanobot/channels/feishu.py` 实现了 Feishu 频道。
    - **Telegram**：使用 Polling 方式进行通信。`nanobot/nanobot/channels/telegram.py` 实现了 Telegram 频道。
    - **Discord**：使用 Gateway 协议进行通信。`nanobot/nanobot/channels/discord.py` 实现了 Discord 频道。
- **Gateway (🐈 nanobot Gateway)**：作为不同聊天平台和 DeepCode 引擎之间的桥梁。
    - **Agent Loop**：核心组件，负责处理来自聊天平台的消息，调用 LLM 和工具，并将结果返回。`nanobot/nanobot/agent/loop.py` 定义了 AgentLoop 类。
- **Engine (🧠 DeepCode Engine)**：DeepCode 的核心引擎，负责代码生成和任务跟踪。
    - **Paper → Code**：将论文转化为代码的功能。
    - **Chat → Code**：根据聊天内容生成代码的功能。
    - **Task Tracking**：负责跟踪和管理任务。
- **LLM (☁️ OpenRouter)**：代表大型语言模型，用于代码生成和理解自然语言。这里使用 OpenRouter 作为 LLM API 的提供者。`nanobot/nanobot/providers/litellm_provider.py` 实现了 LiteLLMProvider，支持 OpenRouter 等多个 LLM 提供商。

## 连线、分支与汇聚关系
- `F & T & D <--> A`：三种聊天平台 (Feishu, Telegram, Discord) 通过各自的协议与 nanobot Gateway 中的 Agent Loop 进行双向通信，传递消息。
- `A --> P2C & C2C & TRK`：Agent Loop 通过 HTTP API 调用 DeepCode 引擎的 Paper → Code, Chat → Code 和 Task Tracking 功能。
- `A -.-> LLM`：Agent Loop 通过 LLM API 与 OpenRouter 提供的 LLM 进行通信。虚线箭头表示 Agent Loop 依赖于 LLM API。

## 仓库语境与术语解释
- **nanobot Gateway**：作为不同聊天平台和 DeepCode 引擎之间的桥梁，负责消息路由和协议转换。
- **Agent Loop**：是 nanobot Gateway 的核心组件，负责接收消息、构建上下文、调用 LLM 和工具、执行工具调用，并将响应发送回去。
- **DeepCode Engine**：是 DeepCode 项目的核心引擎，负责代码生成和任务跟踪等核心功能。
- **OpenRouter**：是一个 LLM API 提供商，DeepCode 使用它来访问大型语言模型。`nanobot/nanobot/providers/litellm_provider.py` 实现了对 OpenRouter 的支持。
- **WebSocket, Polling, Gateway**：分别代表 Feishu, Telegram, Discord 使用的不同通信协议。
- **HTTP API, LLM API**：分别表示 Agent Loop 与 DeepCode Engine 以及 LLM 之间的通信方式。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 DeepCode 项目的整体架构，用户通过 Feishu, Telegram, Discord 等聊天平台与系统交互，消息首先到达 nanobot Gateway，Gateway 中的 Agent Loop 负责处理消息，调用 DeepCode Engine 进行代码生成和任务跟踪，并利用 OpenRouter 提供的 LLM API。Agent Loop 通过 HTTP API 与 DeepCode Engine 通信，通过 LLM API 与 OpenRouter 通信。
