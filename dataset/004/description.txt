## Diagram Type & Purpose
This is an architecture diagram illustrating the flow of observability data within a system. It depicts how different components of a system generate traces, metrics, and logs, and how these are aggregated and used for analysis. The diagram serves to visualize the observability pipeline and its role in providing insights into system health and performance.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It features a "System" subgraph at the top, containing application services and infrastructure. Observability data flows from these components down to traces, metrics, and logs, which are then processed to provide insights.

## Repository Context & Terminology
- **Traces**: Distributed tracing provides insights into request flows across services, helping identify bottlenecks and latency issues.
- **Metrics**: Metrics are numerical measurements collected at regular intervals, providing insights into system performance and resource utilization.
- **Logs**: Logs are records of events that occur within the system, providing detailed context for debugging and troubleshooting.
- **Spans**: A span represents a single unit of work within a trace, such as a function call or a network request. Spans are the building blocks of distributed traces.
- **Observability**: The ability to understand the internal state of a system by examining its outputs, such as traces, metrics, and logs.
