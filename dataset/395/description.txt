## Diagram Type & Purpose
This is a flowchart diagram illustrating the architecture and process flow of a route planning system. It depicts the various layers involved in processing a user query, incorporating real-time traffic data, and generating a final route. The diagram serves as a high-level overview of the system's components and their interactions.

## Overall Layout
The diagram is laid out from left to right, with the Preprocessing Layer on the right, followed by the Query Processing Layer, Fallback Layer, Real-time Layer, and Post-processing Layer. The flow starts with map data preprocessing and a user query, and ends with the generation of a final route.

## Subgraphs / Stages
The diagram is divided into five distinct layers:
- **Preprocessing Layer**: Handles the initial processing of map data.
- **Query Processing Layer**: Processes the user's route query.
- **Real-time Layer**: Incorporates live traffic data into the route planning process.
- **Fallback Layer**: Provides alternative routing strategies in case of timeouts or failures.
- **Post-processing Layer**: Performs final adjustments and calculations to generate the final route.

## Edges, Branches & Convergence
- `MAP_DATA --> GRAPH_BUILD`: Map data is used to construct the graph.
- `GRAPH_BUILD --> CH_PREP`: The constructed graph is preprocessed using Contraction Hierarchies.
- `GRAPH_BUILD --> ARCFLAGS`: Arc flags are computed based on the constructed graph.
- `USER_QUERY --> REGION_CHECK`: A user query is submitted for route planning.
- `REGION_CHECK -- Yes --> LOCAL_ALG`: If the start and end points are in the same region, the Local Dijkstra algorithm is used.
- `REGION_CHECK -- No --> CH_QUERY`: If the start and end points are not in the same region, the CH Query algorithm is used.
- `CH_QUERY --> CH_PATH`: A path is found in the Contraction Hierarchies graph.
- `CH_PATH --> UNPACK`: Shortcuts in the path are unpacked.
- `TRAFFIC_DATA --> ML_MODEL`: Live traffic data is fed into a machine learning model for traffic prediction.
- `ML_MODEL --> WEIGHT_UPDATE`: Edge weights are updated based on traffic predictions.
- `WEIGHT_UPDATE --> RECOMPUTE`: A check is performed to see if there is a significant change in traffic conditions.
- `RECOMPUTE -- Yes --> REROUTE`: If there is a significant change, the route is recomputed using SPFA.
- `RECOMPUTE -- No --> KEEP`: If there is no significant change, the current route is kept.
- `LOCAL_ALG --> TIMEOUT`: The Local Dijkstra algorithm may time out.
- `TIMEOUT -- Yes --> GREEDY`: If the Local Dijkstra algorithm times out, a greedy algorithm is used.
- `TIMEOUT -- No --> SUCCESS`: If the Local Dijkstra algorithm finds a route, the route is considered successful.
- `CH_QUERY --> FAIL`: The CH Query algorithm may fail.
- `FAIL -- Yes --> STANDARD_DIJ`: If the CH Query algorithm fails, the standard Dijkstra algorithm is used.
- `FAIL -- No --> CH_PATH`: If the CH Query algorithm succeeds, a path is found in the CH graph.
- `UNPACK --> TURN_COST`: Unpacked shortcuts are used for turn restriction cost adjustment.
- `TURN_COST --> LANE_GUIDE`: Turn restriction cost adjustments are used for lane guidance generation.
- `LANE_GUIDE --> ETA`: Lane guidance is used for ETA calculation.
- `ETA --> FINAL`: The ETA calculation leads to the final route.
- `REROUTE --> FINAL`: The recomputed route becomes the final route.
- `KEEP --> FINAL`: The kept current route becomes the final route.
- `SUCCESS --> TURN_COST`: A successful route is used for turn restriction cost adjustment.
- `GREEDY --> TURN_COST`: The greedy route is used for turn restriction cost adjustment.

## Repository Context & Terminology
- **OSM (OpenStreetMap)**: A collaborative project to create a free editable map of the world. It is often used as a source of map data for route planning applications.
- **Contraction Hierarchies (CH)**: A speed-up technique for route planning algorithms. It preprocesses the road network to create a hierarchy of nodes, allowing for faster route calculations.
- **Dijkstra's Algorithm**: A classic algorithm for finding the shortest path between two nodes in a graph.
- **SPFA (Shortest Path Faster Algorithm)**: An improvement of the Bellman-Ford algorithm for computing single-source shortest paths in a directed graph. It is often used for incremental route updates.
- **ETA (Estimated Time of Arrival)**: The predicted time at which a vehicle or person is expected to arrive at a particular destination.
- **Arc Flags**: A technique used to precompute information about the reachability of nodes in a graph, which can then be used to speed up route planning queries.

## High-Density QA Ground Truth Summary
The route planning process begins with `USER_QUERY`, specifying start and end points. The system first checks `REGION_CHECK` whether these points are within the same region. If `Yes`, `LOCAL_ALG` (Dijkstra) is employed; if `No`, a `CH_QUERY` (Contraction Hierarchies) is initiated. The CH query can `FAIL`, triggering a fallback to `STANDARD_DIJ` (Dijkstra), or proceed to find a `CH_PATH`, which is then `UNPACK`ed. Simultaneously, `TRAFFIC_DATA` from sensors and crowdsourcing feeds into an `ML_MODEL` for traffic prediction, leading to `WEIGHT_UPDATE`s. A `RECOMPUTE` check determines if traffic changes are `Significant`. If `Yes`, `REROUTE` (SPFA) is performed; otherwise, the system `KEEP`s the current route. The `LOCAL_ALG` can `TIMEOUT`, defaulting to a `GREEDY` closest-next approach. All paths converge in the `Post-processing Layer`, starting with `TURN_COST` adjustments, followed by `LANE_GUIDE` generation, and `ETA` calculation using historical data. Finally, the `FINAL` route is generated. The use of Contraction Hierarchies (`CH_QUERY`) aims to accelerate route calculations compared to standard Dijkstra, especially for long-distance routes.
