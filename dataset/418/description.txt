## 图类型与用途
这是一个架构图，展示了 `arolariu.ro` 项目的整体架构，包括前端站点、后端 API、文档站点、组件库以及它们在 Azure 云上的部署和依赖关系。该图用于概览项目的技术栈和组件间的关系，体现了云原生应用的架构模式。

## 图的整体布局
图采用从左到右的布局，主要分为三个部分：Packages、Sites 和 Azure Cloud。数据流从左侧的 Packages 开始，经过中间的 Sites，最终到达右侧的 Azure Cloud。

## 分组/子图/阶段说明
图中包含三个子图：
- **Packages**：包含组件库 `@arolariu/components`，使用了 Radix UI 和 shadcn/ui。
- **Sites**：包含主网站 `arolariu.ro`、后端 API `api.arolariu.ro`、简历站点 `cv.arolariu.ro` 和文档站点 `docs.arolariu.ro`。
- **Azure Cloud**：包含 Azure Front Door、Data Layer 和 Azure OpenAI。

## 节点逐项说明
- **COMP (🧩 @arolariu/components)**：这是一个组件库，使用了 Radix UI 和 shadcn/ui。
- **WEB (🎨 arolariu.ro)**：这是主网站，使用 Next.js 16 和 React 19 构建。
- **API (⚙️ api.arolariu.ro)**：这是后端 API，使用 .NET 10 和领域驱动设计 (DDD)。
- **CV (📄 cv.arolariu.ro)**：这是一个简历站点，使用 SvelteKit 2 构建。
- **DOCS (📚 docs.arolariu.ro)**：这是文档站点，使用 DocFX 构建。
- **AFD (🌐 Azure Front Door)**：使用 Azure Front Door 作为内容分发网络 (CDN) 和 Web 应用防火墙 (WAF)。
- **DATA (📦 Data Layer)**：数据层，使用 SQL、Cosmos DB 和 Blob 存储。
- **AI (🤖 Azure OpenAI)**：使用 Azure OpenAI 的 GPT-4o 模型。根据 `infra/Azure/Bicep/ai/openai.bicep`，Azure OpenAI 用于发票分析、自然语言理解和内容生成。

## 连线、分支与汇聚关系
- `COMP --> WEB`：组件库 `@arolariu/components` 被主网站 `arolariu.ro` 导入使用。
- `WEB --> API`：主网站 `arolariu.ro` 通过 API 调用与后端 API `api.arolariu.ro` 进行交互。
- `API --> DATA`：后端 API 与数据层进行交互，进行数据存储。
- `API --> AI`：后端 API 与 Azure OpenAI 进行交互，进行 AI 功能调用。
- `AFD --> WEB`：Azure Front Door 将流量分发到主网站 `arolariu.ro`。
- `AFD --> API`：Azure Front Door 将流量分发到后端 API `api.arolariu.ro`。
- `AFD --> CV`：Azure Front Door 将流量分发到简历站点 `cv.arolariu.ro`。
- `AFD --> DOCS`：Azure Front Door 将流量分发到文档站点 `docs.arolariu.ro`。

## 仓库语境与术语解释
- **Monorepo**：`arolariu.ro` 项目采用 Monorepo 架构，将多个相关的项目或模块放在同一个代码仓库中进行管理。
- **DDD (Domain-Driven Design)**：后端 API 使用领域驱动设计，参见 `docs/rfc/2001-domain-driven-design-architecture.md`。
- **Azure Front Door**：根据 `infra/Azure/Bicep/network/azureFrontDoor.bicep`，Azure Front Door 作为全局 CDN、WAF 和负载均衡器。
- **Next.js**：主网站使用 Next.js 16 构建，这是一个 React 框架，用于构建高性能的 Web 应用程序。
- **SvelteKit**：简历站点使用 SvelteKit 2 构建，这是一个用于构建快速 Web 应用程序的框架。
- **DocFX**：文档站点使用 DocFX 构建，这是一个用于生成技术文档的工具。
- **Azure OpenAI**：根据 `infra/Azure/Bicep/ai/openai.bicep`，Azure OpenAI 用于发票分析、自然语言理解和内容生成。

## 可作为 QA Ground Truth 的高信息密度摘要
该架构图展示了 `arolariu.ro` 项目的整体架构，从组件库 `@arolariu/components` 到主网站 `arolariu.ro`，再到后端 API `api.arolariu.ro`，最终通过 Azure Front Door 分发到各个站点。后端 API 与数据层和 Azure OpenAI 进行交互，实现数据存储和 AI 功能调用。Azure Front Door 作为入口，将流量分发到主网站、后端 API、简历站点和文档站点，形成一个完整的云原生应用架构。该架构体现了“组件库 -> 前端站点 -> 后端 API -> 云服务”的主线，其中 Azure Front Door 和 Azure OpenAI 是两个关键的云服务组件。
