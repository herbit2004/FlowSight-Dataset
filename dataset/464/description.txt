## 图类型与用途
这是一个流程图，描述了 EstateWise 智能房地产助手平台中，用户查询如何通过一系列步骤转化为增强型提示（Augmented Prompt）的过程。该流程是数据检索增强生成（RAG）架构的一部分，旨在提高 LLM 生成结果的准确性和相关性。

## 图的整体布局
图采用从左到右的布局。起点是用户查询，终点是增强型提示，中间经过嵌入、向量搜索、图增强、合并去重等处理。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为四个阶段：查询预处理、信息检索、信息融合、提示生成。

## 节点逐项说明
- **Q[User Query]**：用户提出的关于房地产的需求或问题，作为整个流程的起点。
- **E[Embed Query]**：将用户查询进行嵌入（Embedding）处理，转换为向量表示，以便计算机可以理解和比较文本的语义相似度。
- **V[Pinecone Vector Search]**：使用 Pinecone 向量数据库进行向量搜索，找到与用户查询最相关的房地产信息。根据 `backend/src/pineconeClient.ts`，该服务使用了环境变量 `PINECONE_API_KEY` 和 `PINECONE_INDEX`。
- **K[Top-K Results]**：从 Pinecone 向量搜索中获取最相关的 K 个结果，K 是一个数字，代表返回结果的数量。
- **G[Neo4j Graph Enrichment]**：使用 Neo4j 图数据库对检索到的结果进行图增强，找到与检索到的房地产相关的其他房地产信息。根据 `backend/src/graph/graph.service.ts`，Neo4j 用于存储房地产之间的关系，例如邻近关系、相似房型关系等。
- **M[Merge + Dedupe]**：将从 Pinecone 和 Neo4j 获取的结果进行合并和去重处理，确保信息的完整性和准确性。
- **LLM[Augmented Prompt]**：将合并和去重后的信息添加到原始用户查询中，形成一个增强型提示（Augmented Prompt），然后将其输入到大型语言模型（LLM）中。

## 连线、分支与汇聚关系
- `Q -> E`：用户查询首先被嵌入成向量。
- `E -> V`：嵌入后的查询向量被用于在 Pinecone 向量数据库中进行搜索。
- `V -> K`：Pinecone 返回最相关的 K 个结果。
- `K -> G`：这 K 个结果被用于在 Neo4j 图数据库中进行图增强。
- `G -> M`：来自 Neo4j 的结果被合并和去重。
- `M -> LLM`：合并和去重后的信息被添加到原始查询中，形成增强型提示。

## 仓库语境与术语解释
- **RAG (Retrieval-Augmented Generation)**：一种通过检索外部知识来增强 LLM 生成结果的技术，EstateWise 使用混合 RAG 架构，结合向量数据库和图数据库。
- **Pinecone**：一个向量数据库，用于存储房地产信息的向量表示，支持快速的语义相似度搜索。
- **Neo4j**：一个图数据库，用于存储房地产之间的关系，例如邻近关系、相似房型关系等。根据 `backend/src/graph/neo4j.client.ts`，该服务使用了环境变量 `NEO4J_URI`，`NEO4J_USERNAME` 和 `NEO4J_PASSWORD`。
- **Embedding**：将文本转换为向量的过程，以便计算机可以理解和比较文本的语义相似度。
- **Augmented Prompt**：将检索到的相关信息添加到原始用户查询中，形成一个增强型提示，提供给 LLM 更丰富的上下文。
- **LLM (Large Language Model)**：大型语言模型，用于生成最终的房地产信息查询结果。
- **Hybrid RAG (Vector + Graph)**：根据 `README.md` 和 `RAG_SYSTEM.md`，EstateWise 使用混合 RAG 架构，结合 Pinecone 的 kNN 向量搜索和 Neo4j 的图增强。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 EstateWise 平台的 RAG 流程，从用户查询开始，经过嵌入处理后，利用 Pinecone 向量数据库进行相似房产检索，再通过 Neo4j 图数据库进行关系增强，最终将检索和增强的信息合并到用户查询中，形成增强型提示（Augmented Prompt）输入 LLM。其中，Pinecone 和 Neo4j 是该流程的关键组件，分别负责语义搜索和关系挖掘。
