## 图类型与用途
这是一个流程图，描述了基于LLM的数据分析智能体的工作流程。它展示了智能体如何接收用户需求，生成代码，执行分析，并最终生成报告的完整过程。该图在仓库中用于概括智能体的工作流程，方便用户理解其核心逻辑。

## 图的整体布局
图采用从上到下的布局。流程从顶部的用户输入开始，经过一系列处理和判断节点，最终到达底部的分析完成节点。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为四个阶段：需求接收与初始化、代码生成与执行、结果处理与迭代、报告生成与输出。

## 节点逐项说明
- **A (用户输入自然语言需求)**：流程的起点，表示用户以自然语言形式提出的数据分析需求。
- **B (初始化智能体)**：接收到用户需求后，智能体进行初始化设置，准备后续分析。
- **C (创建专用会话目录)**：为本次分析创建一个独立的目录，用于存放生成的文件、图表和报告，保证分析过程的隔离性和可追溯性。根据 `utils/create_session_dir.py`，该目录使用 UUID 生成，格式为 `session_[32位16进制UUID]`。
- **D (LLM理解需求并生成代码)**：大语言模型（LLM）负责理解用户的自然语言需求，并将其转化为可执行的数据分析代码（通常是Python代码）。`prompts.py` 中定义了系统提示词，指导 LLM 如何生成代码。
- **E (安全代码执行器执行)**：使用安全的代码执行器来执行LLM生成的代码。该执行器会限制代码的权限，以防止潜在的安全风险。`utils/code_executor.py` 实现了代码执行器，并限制了可导入的库。
- **F (执行是否成功?)**：一个判断节点，用于检查代码执行是否成功。
- **G (错误分析与修复)**：如果代码执行失败，则进入错误分析与修复阶段。智能体会尝试识别错误原因，并自动修复代码。
- **H (结果格式化与存储)**：如果代码执行成功，则将结果进行格式化，例如将数据转换为图表，并将图表和中间结果存储到会话目录中。`utils/format_execution_result.py` 负责格式化执行结果。
- **I (是否需要更多分析?)**：一个判断节点，用于确定是否需要进行进一步的分析。
- **J (基于当前结果继续分析)**：如果需要更多分析，则基于当前的结果和状态，继续进行下一轮的分析。
- **K (收集所有图表)**：如果不需要更多分析，则收集所有生成的图表，准备生成最终报告。
- **L (生成最终分析报告)**：基于收集到的图表和分析结果，生成最终的分析报告。
- **M (输出Markdown和Word报告)**：将分析报告输出为Markdown和Word两种格式，方便用户查看、编辑和分享。
- **N (分析完成)**：流程的终点，表示数据分析过程已经完成。

## 连线、分支与汇聚关系
- `A -> B`：用户输入需求后，智能体开始初始化。
- `B -> C`：智能体初始化后，创建专用会话目录。
- `C -> D`：创建会话目录后，LLM理解需求并生成代码。
- `D -> E`：LLM生成代码后，安全代码执行器执行代码。
- `E -> F`：代码执行后，判断执行是否成功。
- `F -- 失败 --> G`：如果执行失败，则进入错误分析与修复阶段。
- `G -> D`：错误分析与修复后，重新生成代码。
- `F -- 成功 --> H`：如果执行成功，则格式化结果并存储。
- `H -> I`：结果格式化与存储后，判断是否需要更多分析。
- `I -- 是 --> J`：如果需要更多分析，则基于当前结果继续分析。
- `J -> D`：基于当前结果继续分析后，重新生成代码。
- `I -- 否 --> K`：如果不需要更多分析，则收集所有图表。
- `K -> L`：收集所有图表后，生成最终分析报告。
- `L -> M`：生成最终分析报告后，输出Markdown和Word报告。
- `M -> N`：输出报告后，分析完成。

## 仓库语境与术语解释
- **LLM (Large Language Model)**：大型语言模型，用于理解用户需求并生成代码。本项目使用 OpenAI 的模型，相关配置在 `config/llm_config.py` 中。
- **安全代码执行器**：用于执行 LLM 生成的代码，限制了可导入的库，防止潜在的安全风险。`utils/code_executor.py` 实现了该执行器。
- **会话目录**：每次分析都会创建一个独立的目录，用于存放生成的文件、图表和报告，保证分析过程的隔离性和可追溯性。`utils/create_session_dir.py` 负责创建会话目录。
- **Markdown 和 Word 报告**：最终的分析报告会输出为 Markdown 和 Word 两种格式，方便用户查看、编辑和分享。
- **`prompts.py`**：该文件定义了系统提示词模板，用于指导 LLM 如何生成代码和报告。
- **`data_analysis_agent.py`**：该文件包含了 `DataAnalysisAgent` 类，是智能体的主体，负责接收用户需求、生成代码、执行分析和生成报告。
- **`utils/llm_helper.py`**：该文件包含了 `LLMHelper` 类，用于辅助调用 LLM，支持同步和异步调用。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了数据分析智能体的工作流程。流程从用户输入自然语言需求开始，智能体初始化并创建专用会话目录。LLM 理解需求并生成代码，代码通过安全执行器执行。如果执行失败，进行错误分析与修复，然后重新生成代码并执行；如果执行成功，格式化结果并存储。判断是否需要更多分析，如果需要，则基于当前结果继续分析；如果不需要，则收集图表并生成最终报告，最终报告以 Markdown 和 Word 格式输出，分析完成。其中，LLM 生成代码和安全代码执行器是关键环节，会话目录用于隔离每次分析的输出。
