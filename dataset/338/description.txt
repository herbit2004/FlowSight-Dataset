## 图类型与用途
这是一个流程图，展示了基于 Spring Cloud Stream 和 RabbitMQ 的事件驱动微服务架构。它描述了一个订单处理流程，涉及多个微服务之间的消息传递，用于概括微服务之间的交互方式。

## 图的整体布局
图整体采用从上到下的布局。顶部是订单服务（生产者），中间是消息代理和处理服务，底部是支付服务（消费者）。数据流从上到下流动。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：订单生成、订单处理（产品和运输）、订单支付。

## 节点逐项说明
- **order-service Producer Port: 2222**：订单服务，作为生产者，负责生成订单事件。根据 README，它使用 `Supplier<Order>` bean 自动生成订单。
- **RabbitMQ Broker**：RabbitMQ 消息代理，用于在各个微服务之间传递消息。
- **product-service Function Port: 2223**：产品服务，作为一个函数，接收订单事件，并执行与产品相关的操作。根据 README，它负责丰富订单信息，添加产品细节和价格。
- **shipment-service Function Port: 2224**：运输服务，也是一个函数，接收订单事件，并执行与运输相关的操作。根据 README，它负责丰富订单信息，添加运输细节和价格。
- **payment-service Consumer Port: 2225**：支付服务，作为消费者，接收事件，并执行支付相关的操作。根据 README，它聚合订单数据并计算最终总额。

## 连线、分支与汇聚关系
- `order-service Producer Port: 2222 -> RabbitMQ Broker`：订单服务通过 `ex.stream.out` 交换器将订单事件发送到 RabbitMQ Broker。
- `RabbitMQ Broker -> product-service Function Port: 2223`：RabbitMQ Broker 将 `ex.stream.out` 交换器上的消息路由到产品服务。
- `RabbitMQ Broker -> shipment-service Function Port: 2224`：RabbitMQ Broker 将 `ex.stream.out` 交换器上的消息路由到运输服务。
- `product-service Function Port: 2223 -> RabbitMQ Broker`：产品服务处理完消息后，通过 `ex.stream.out2` 交换器将消息发送到 RabbitMQ Broker。
- `shipment-service Function Port: 2224 -> RabbitMQ Broker`：运输服务处理完消息后，通过 `ex.stream.out2` 交换器将消息发送到 RabbitMQ Broker。
- `product-service Function Port: 2223` 和 `shipment-service Function Port: 2224` 都向同一个 `RabbitMQ Broker` 发送消息，形成汇聚关系。
- `RabbitMQ Broker -> payment-service Consumer Port: 2225`：RabbitMQ Broker 将 `ex.stream.out2` 交换器上的消息路由到支付服务。

## 仓库语境与术语解释
- **Spring Cloud Stream**：一个用于构建消息驱动的微服务应用程序的框架，简化了与消息中间件（如 RabbitMQ）的集成。
- **RabbitMQ Broker**：一个消息代理，用于在不同的微服务之间传递消息。
- **Producer**：在此架构中，指 `order-service`，负责生成并发送消息（订单事件）。
- **Function**：在此架构中，指 `product-service` 和 `shipment-service`，负责接收消息、处理消息，并将处理后的消息发送到下一个服务。
- **Consumer**：在此架构中，指 `payment-service`，负责接收并处理消息，完成最终的支付流程。
- **ex.stream.out**：主要的消息通道，用于初始订单的分发。
- **ex.stream.out2**：次要的消息通道，用于处理后的订单聚合。
- **Order**: `sample-common/src/main/java/pl/piomin/service/common/message/Order.java` 定义了订单的数据结构，包含订单ID、类型、创建时间、状态、产品和运输信息。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了一个基于 Spring Cloud Stream 和 RabbitMQ 的事件驱动微服务架构。订单服务（Producer）生成订单事件，通过 `ex.stream.out` 发送到 RabbitMQ Broker，然后分发给产品服务和运输服务（Function）进行处理。处理后的事件通过 `ex.stream.out2` 再次发送到 RabbitMQ Broker，最终到达支付服务（Consumer）完成支付流程。核心流程是“订单生成 -> 产品/运输信息丰富 -> 支付”，其中 RabbitMQ Broker 承担了消息路由的关键角色。`order-service` 使用 `Supplier<Order>` bean 自动生成订单。
