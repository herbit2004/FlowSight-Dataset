## 图类型与用途
该图是一个流程图，描述了用户请求处理的流程。流程从用户请求开始，经过支付网关、风控系统等环节，最终可能成功创建订单或进行退款。

## 图的整体布局
该图的布局是从上到下。流程的起点是“用户请求”，终点是“API 返回”或“用户请求”或“退款服务”。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1.  请求发起与支付：用户请求开始，经过支付网关。
2.  风控与数据处理：根据支付网关的结果，进入风控系统或缓存写入。
3.  订单处理：经过数据库写入、消息队列、订单服务，判断订单是否创建成功。
4.  结果反馈：根据订单创建结果，返回用户请求或进行退款服务。

## 节点逐项说明
- **A (用户请求)**：流程的起始节点，表示用户发起一个请求。
- **B (支付网关)**：判断节点，表示支付网关的处理结果。
- **C (风控系统)**：表示风控系统进行风险控制。
- **D (缓存写入)**：表示将数据写入缓存。
- **E (数据库写入)**：表示将数据写入数据库。
- **F (消息队列)**：表示将消息发送到消息队列。
- **G (订单服务)**：表示订单服务进行订单处理。
- **H (订单创建成功?)**：判断节点，表示订单是否创建成功。
- **I (用户请求)**：表示流程回到用户请求。
- **J (退款服务)**：表示进行退款服务。
- **K (API 返回)**：表示API返回。

## 连线、分支与汇聚关系
- A -> B：用户请求到达支付网关。
- B -- Yes --> C：支付网关处理成功，进入风控系统。
- B -- No --> D：支付网关处理失败，进入缓存写入。
- C -> E：风控系统处理后，进入数据库写入。
- E -> F：数据库写入后，进入消息队列。
- F -> G：消息队列处理后，进入订单服务。
- G -> H：订单服务处理后，判断订单是否创建成功。
- H -- Yes --> I：订单创建成功，流程回到用户请求。
- H -- No --> J：订单创建失败，进入退款服务。
- J -> E：退款服务后，进入数据库写入。
- D -> K：缓存写入后，API返回。

## 仓库语境与术语解释
- **支付网关**：处理支付请求的系统。
- **风控系统**：用于识别和控制风险的系统。
- **缓存写入**：将数据写入缓存，提高访问速度。
- **数据库写入**：将数据写入数据库，持久化存储。
- **消息队列**：用于异步处理消息的队列。
- **订单服务**：处理订单相关业务的服务。
- **退款服务**：处理退款相关业务的服务。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先进入支付网关，如果支付网关处理成功，则进入风控系统，然后进行数据库写入，接着进入消息队列，再到订单服务，判断订单是否创建成功，如果成功则流程回到用户请求，否则进入退款服务，再进行数据库写入。如果支付网关处理失败，则进入缓存写入，然后API返回。
