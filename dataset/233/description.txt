## 图类型与用途
这是一个流程图，描述了 Hive 自动化代理系统的工作流程，从定义目标开始，经过自动生成图、执行代理、监控观察、检查，最终交付结果或演化图。它在仓库中的作用是展示 Agent 如何通过迭代和演进实现预定义目标。

## 图的整体布局
图采用从左到右的布局。流程从左侧的“Define Goal”开始，经过一系列处理步骤，最终到达右侧的“Deliver Result”或返回中间步骤进行迭代。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为四个阶段：目标定义、图生成与执行、监控与检查、结果交付与演化。

## 节点逐项说明
- **GOAL (Define Goal)**：定义目标，是流程的起点。与 "Natural Language" 相关联，表示目标可以通过自然语言进行定义。
- **GEN (Auto-Generate Graph)**：自动生成图，根据定义的目标自动生成图结构，可能为任务分解图或代理之间的协作图。与 "Instant Architecture" 相关联，表明系统能够快速构建架构。
- **EXEC (Execute Agents)**：执行代理，系统执行生成的图中的各个代理，每个代理负责完成特定的任务。与 "Easy Integrations" 相关联，意味着代理之间易于集成。
- **MON (Monitor & Observe)**：监控和观察，系统监控代理的执行情况，并收集相关数据。与 "Full visibility" 相关联，强调系统具有全面的可见性。
- **CHECK (Pass?)**：检查，系统根据监控数据判断代理的执行结果是否符合预期目标。这是一个决策节点，有两个分支："Yes" 和 "No"。
- **DONE (Deliver Result)**：交付结果，如果检查结果为 "Yes"，表示系统已经成功实现了目标，将结果交付给用户。与 "Reliable outcomes" 相关联，表明系统能够产生可靠的结果。
- **EVOLVE (Evolve Graph)**：演化图，如果检查结果为 "No"，表示系统未能成功实现目标，需要对生成的图进行演化和改进。与 "Adaptability" 相关联，强调系统具有适应性。

## 连线、分支与汇聚关系
- `GOAL -> GEN`：定义目标后，系统自动生成图。
- `GEN -> EXEC`：生成图后，系统执行代理。
- `EXEC -> MON`：执行代理后，系统进行监控和观察。
- `MON -> CHECK`：监控和观察后，系统进行检查，判断执行结果是否符合预期。
- `CHECK -- Yes --> DONE`：如果检查结果为 "Yes"，流程进入交付结果阶段。
- `CHECK -- No --> EVOLVE`：如果检查结果为 "No"，流程进入演化图阶段。
- `EVOLVE -> EXEC`：演化图后，流程返回执行代理阶段，形成循环。

## 仓库语境与术语解释
- **Agent**：根据 README，Agent 是指 autonomous, reliable, self-improving AI agents，可以通过 Hive 构建。
- **Graph**：根据 `docs/key_concepts/graph.md`，Graph 是 Hive 用于建模业务流程的结构，由节点和边组成，可以包含循环、分支和决策点。
- **MCP (Meta-Config Protocol)**：图中未直接提及，但 README 中有 MCP badge，且仓库目录树中存在大量 `.mcp.json` 文件，推测 MCP 用于配置和管理 Agent。
- **Natural Language**：图中与 "Define Goal" 关联，表示可以使用自然语言定义 Agent 的目标。
- **Event Loop Node**：根据 `docs/key_concepts/graph.md`，是 Hive 中唯一的节点类型，用于执行多轮 LLM 循环，处理长期任务，管理上下文窗口，并从崩溃中恢复。
- **Tool**：根据 `docs/key_concepts/graph.md`，Tool 为 Event Loop Node 提供特定能力，例如 Web 搜索、API 调用、数据库查询等。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 Hive 自动化代理系统从定义目标到交付结果的完整流程。流程从“Define Goal”开始，自动生成图，然后执行代理并进行监控观察。根据检查结果，如果符合预期则交付结果，否则演化图并重新执行代理，形成迭代循环。该流程强调了系统通过监控、检查和演化来不断改进，最终达到可靠结果的能力。其中，图的自动生成和演化是关键环节。
