## Diagram Type & Purpose
This is a flowchart diagram illustrating a data quality assurance (QA) process for order management data. It outlines the steps involved in acquiring data, validating it, selecting samples for review, remediating errors, and reporting on data quality. The diagram serves as a visual representation of the QA workflow, providing a clear understanding of the process for stakeholders.

## Overall Layout
The diagram is laid out in a top-down (TD) direction. It is divided into three subgraphs representing different stages of the QA process. The process starts with "Source System: Order Management" and ends with "Development Team Backlog" and "Final Report: QA Summary & Metrics".

## Subgraphs / Stages
The diagram contains three explicit subgraphs:
- **Data Acquisition**: Focuses on extracting order data from the source system and performing initial validation.
- **Sample Selection & Review**: Describes the process of selecting data samples for manual review and assigning them to reviewers.
- **Remediation & Reporting**: Covers the steps taken to correct data errors, update sample statuses, and generate QA reports.

## Edges, Branches & Convergence
- `A --> B`: Data flows from the source system to the extraction process.
- `B --> C`: Extracted data is passed to the data validation rules.
- `C -- Pass --> D`: Data that passes validation is persisted to QA staging.
- `C -- Fail --> E`: Data that fails validation triggers an error log and alert.
- `D --> F`: Data in QA staging is subjected to a sampling algorithm.
- `E --> F`: Data that fails validation is subjected to a sampling algorithm.
- `F -- Selected --> G`: Selected samples are used to create a QA sample set.
- `F -- Rejected --> D`: Rejected samples are persisted to QA staging.
- `G --> H`: The QA sample set is assigned to reviewers.
- `H --> I`: Reviewers perform a manual data check.
- `I -- Pass --> J`: Samples that pass the manual check are approved.
- `I -- Fail --> K`: Samples that fail the manual check are rejected.
- `J --> O`: The sample status is updated to "Approved".
- `K --> P`: The sample status is updated to "Rejected".
- `K --> L`: Rejected samples trigger root cause analysis.
- `O --> Q`: Approved samples are evaluated against a sample accuracy threshold.
- `P --> Q`: Rejected samples are evaluated against a sample accuracy threshold.
- `Q -- Yes --> R`: If the threshold is met, a QA report is generated.
- `Q -- No --> S`: If the threshold is not met, the issue is escalated for further investigation.
- `S --> T`: Further investigation involves a deep dive analysis to determine the root cause.
- `T --> M`: The root cause analysis may lead to a data correction workflow.
- `T --> N`: The root cause analysis may lead to a bug report to development.
- `L -- Data Error --> M`: Data errors trigger the data correction workflow.
- `L -- System Defect --> N`: System defects trigger a bug report to development.
- `M --> D`: Data correction workflow leads back to persisting to QA staging.
- `N --> V`: Bug reports are added to the development team backlog.
- `R --> U`: A final QA report summarizing the QA process and metrics is generated.

## Repository Context & Terminology
- **Source System**: The original system of record where the data originates.
- **Order Management**: The process of managing customer orders from placement to fulfillment.
- **Data Validation Rules**: Predefined rules used to ensure data quality and consistency.
- **QA Staging**: A temporary storage area for data undergoing quality assurance.
- **Sampling Algorithm**: A method used to select a representative subset of data for review.
- **Stratified Random Sampling**: A sampling technique where the population is divided into subgroups (strata) and random samples are taken from each stratum.
- **Root Cause Analysis**: A systematic process for identifying the underlying causes of problems or events.
- **Data Correction Workflow**: A defined process for correcting data errors.
- **Bug Report**: A formal report documenting a software defect.
- **Development Team Backlog**: A list of tasks or issues that the development team needs to address.

## High-Density QA Ground Truth Summary
The QA process begins with data acquisition from the "Source System: Order Management," followed by extracting the "Order Data." This extracted data undergoes "Data Validation Rules," branching into two paths: if the data passes, it's persisted to "QA Staging"; if it fails, an "Error Log & Alert" is triggered. Both paths converge at the "Sampling Algorithm: Stratified Random," where data samples are selected. Rejected samples are persisted to QA Staging. A "QA Sample Set Creation" follows, with samples assigned to reviewers for a "Manual Data Check." This check results in either "Approve Sample" or "Reject Sample," updating the sample status accordingly. Both approved and rejected samples are then evaluated against a "Threshold Met: Sample Accuracy." If the threshold is met, a "Generate QA Report: Pass" is created, leading to a "Final Report: QA Summary & Metrics." If the threshold isn't met, the process escalates for "Further Investigation," involving a "Deep Dive Analysis: Root Cause." This analysis can lead to a "Data Correction Workflow" or a "Bug Report to Development," ultimately feeding into the "Development Team Backlog." The "Data Correction Workflow" loops back to "Persist to QA Staging," ensuring continuous improvement. The stratified random sampling algorithm ensures a representative sample for manual review, a key step in identifying and correcting data errors before they impact downstream processes.
