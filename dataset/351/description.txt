## Diagram Type & Purpose
This is a flowchart diagram illustrating the steps involved in generating a response to a user question. It outlines the process from receiving the initial query to streaming the final answer back to the user. The diagram serves as a high-level overview of the question answering pipeline.

## Overall Layout
The diagram has a top-down (TD) layout. It starts with the "User Question" node at the top and flows sequentially downwards to the "Stream to User" node at the bottom. There is no explicit hierarchy, but rather a linear progression of steps.

## Edges, Branches & Convergence
- `Q --> H`: The user question triggers the generation of a hypothetical answer.
- `H --> E`: The hypothetical answer is used to create an embedding.
- `E --> P`: The embedding is used to query Pinecone.
- `P --> C`: Pinecone returns relevant chunks.
- `C --> S`: The chunks are aggregated.
- `S --> O`: The aggregated sources are ordered by relevance.
- `O --> B`: A context is built from the ordered sources.
- `B --> R`: The context is used to generate a final response.
- `R --> U`: The final response is streamed to the user.

## Repository Context & Terminology
- **Embedding**: A vector representation of text or other data, used for similarity search.
- **Pinecone**: A vector database service used for storing and querying embeddings.
- **Chunks**: Segments of text or data that are indexed in the vector database.
- **Relevance**: A measure of how closely a chunk of information matches the user's question.
- **Context**: The information used to generate the final response.
