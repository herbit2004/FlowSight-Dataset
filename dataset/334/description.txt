## Diagram Type & Purpose
This is a flowchart diagram illustrating a software development process. It depicts the stages from user input to build verification, including planning, design, implementation, testing, code review, and QA feedback. The diagram serves as a visual representation of the workflow and the roles involved in each stage.

The diagram has a top-down (TD) layout. It starts with "사용자 입력" (User Input) at the top and progresses through various stages to "빌드 검증" (Build Verification) at the bottom. The flow includes a decision point based on QA feedback, creating a loop back to a previous stage if critical or high issues are found.

## Edges, Branches & Convergence
- `A --> B`: User input leads to the planning stage.
- `B --> C`: Planning leads to architecture design.
- `C --> D`: Architecture design leads to database design.
- `D --> E`: Database design leads to parallel implementation.
- `E --> E1`: Parallel implementation involves a frontend specialist.
- `E --> E2`: Parallel implementation involves a backend specialist.
- `E1 --> F`: Frontend implementation leads to test writing.
- `E2 --> F`: Backend implementation leads to test writing.
- `F --> G`: Test writing leads to code review.
- `G --> H`: Code review leads to QA feedback.
- `H --> H1`: QA feedback leads to a decision point.
- `H1 -- YES --> H2`: If there are critical/high issues, specialist modification is required.
- `H2 --> H3`: Specialist modification leads to build verification.
- `H3 --> H`: Build verification loops back to QA feedback.
- `H1 -- NO --> I`: If there are no critical/high issues, the process moves to completion.
- `I --> H3`: Completion leads to build verification.
- `E1` and `E2` converge at `F`.

## Repository Context & Terminology
- **사용자 입력 (User Input)**: The initial data or request provided by a user to start the process.
- **계획 수립 (Planning)**: The stage where the project's scope, goals, and resources are defined.
- **아키텍처 설계 (Architecture Design)**: The stage where the system's structure and components are designed.
- **DB 설계 (Database Design)**: The stage where the database schema and data models are designed.
- **병렬 구현 (Parallel Implementation)**: The stage where frontend and backend components are implemented concurrently.
- **테스트 작성 (Test Writing)**: The stage where tests are written to verify the functionality of the implemented components.
- **코드 리뷰 (Code Review)**: The stage where the code is reviewed by peers to identify potential issues.
- **QA 피드백 루프 (QA Feedback Loop)**: The stage where the quality assurance team provides feedback on the implemented components.
- **빌드 검증 (Build Verification)**: The stage where the final build is verified to ensure it meets the required standards.
- **CHANGELOG**: A file containing a curated, chronologically ordered list of notable changes for each version of a project.
- **git push**: A command used to upload local repository content to a remote repository.
- **telegram**: A cloud-based instant messaging and voice over IP service.
