## 图类型与用途
这是一个流程图，描述了使用 Markdown 编写微信公众号文章并发送到微信草稿箱的完整流程。它在仓库中的作用是展示如何使用 `md2wechat` 工具将 Markdown 文档转换为微信公众号文章。

## 图的整体布局
图整体采用从左到右的布局。流程从编写 Markdown 文章开始，经过模式选择、内容转换、效果预览等步骤，最终完成文章的发送。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：文章编写与模式选择、内容转换与排版、效果确认与发送。

## 节点逐项说明
- **A (用 Markdown 写文章)**：流程的起点，表示用户使用 Markdown 编写文章。
- **B (选择模式)**：一个决策节点，用户需要选择文章转换的模式，包括 API 模式和 AI 模式。
- **C (调用 md2wechat.cn API)**：API 模式下的步骤，调用 `md2wechat.cn` 提供的 API 将 Markdown 转换为 HTML。根据 README，使用 API 模式需要先获取 API Key。
- **D (获取 HTML)**：API 模式的输出，表示通过 API 获得了 HTML 格式的文章。
- **E (Claude AI 生成 HTML)**：AI 模式下的步骤，使用 Claude AI 将 Markdown 转换为 HTML。该节点被标记为“⭐”，表示推荐或重点功能。根据 README，AI 模式不需要 API Key。
- **F (精美排版)**：AI 模式的输出，表示通过 AI 生成的 HTML 具有精美的排版。
- **G (预览效果)**：用户预览转换后的文章效果。
- **H (满意吗)**：一个决策节点，用户判断预览效果是否满意。
- **I (上传图片)**：如果用户对预览效果满意，则上传文章中使用的图片。
- **J (发送到微信草稿箱)**：将文章发送到微信公众号的草稿箱。
- **K (完成)**：流程的终点，表示文章已成功发送到微信草稿箱。

## 连线、分支与汇聚关系
- `A -> B`：流程从编写 Markdown 文章开始，进入模式选择阶段。
- `B -- API 模式 --> C`：如果选择 API 模式，流程进入调用 API 阶段。
- `C -> D`：调用 API 后，获取 HTML 格式的文章。
- `B -- AI 模式 ⭐ --> E`：如果选择 AI 模式，流程进入 AI 生成 HTML 阶段。
- `E -> F`：AI 生成 HTML 后，得到精美排版的文章。
- `D -> G`：API 模式生成的 HTML 进入预览阶段。
- `F -> G`：AI 模式生成的 HTML 进入预览阶段，形成汇聚关系。
- `G -> H`：预览效果后，进入满意度判断阶段。
- `H -- 不满意 --> B`：如果不满意，流程返回模式选择阶段，重新选择模式或修改 Markdown 文档。
- `H -- 满意 --> I`：如果满意，流程进入上传图片阶段。
- `I -> J`：上传图片后，将文章发送到微信草稿箱。
- `J -> K`：文章发送到微信草稿箱后，流程完成。

## 仓库语境与术语解释
- **Markdown**：一种轻量级标记语言，用于编写结构化文档。
- **md2wechat**：该仓库提供的工具，用于将 Markdown 文档转换为微信公众号文章。
- **API 模式**：使用 `md2wechat.cn` API 进行转换的模式，需要 API Key。
- **AI 模式**：使用 Claude AI 进行转换的模式，无需 API Key，样式更丰富。
- **Claude AI**：一种人工智能模型，用于生成 HTML 代码和进行文章排版。
- **微信草稿箱**：微信公众号平台提供的草稿存储功能，用于保存待发布的文章。
- **writers/dan-koe.yaml**：仓库中定义的一种写作风格，用于辅助 AI 生成文章。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了使用 `md2wechat` 工具将 Markdown 文档转换为微信公众号文章的完整流程。用户首先编写 Markdown 文章，然后选择 API 模式或 AI 模式进行转换。API 模式调用 `md2wechat.cn` API，需要 API Key；AI 模式使用 Claude AI，无需 API Key 且排版更精美。用户可以预览转换后的效果，如果不满意可以返回重新选择模式或修改 Markdown 文档。如果用户满意，则上传图片并将文章发送到微信草稿箱，最终完成整个流程。其中，模式选择是关键分支，API Key 的获取是 API 模式的前提。
