## Diagram Type & Purpose
This is a flowchart diagram illustrating the data flow and user interaction within a customer data application. It depicts the process of fetching customer data, applying filters, and displaying customer details based on user actions. The diagram serves as a high-level overview of the application's architecture and user experience.

## Overall Layout
The diagram is laid out from left to right (LR). It is divided into three subgraphs: Data Source, Your Application, and User Experience. The flow starts at the Data Source, proceeds through the Application, and is influenced by the User Experience.

## Subgraphs / Stages
- **Data Source**: Represents the source of customer data, specifically a JSON API.
- **Your Application**: Encompasses the core logic of the application, including fetching data, filtering, and displaying customer details.
- **User Experience**: Illustrates the user interactions that influence the data displayed, such as searching, filtering by state, and pagination.

## Edges, Branches & Convergence
- `API --> FETCH`: Data flows from the JSON API to the Fetch Data process.
- `FETCH --> LIST`: Fetched data is passed to the Customer List and Filters component.
- `LIST --> DETAIL`: A selected customer from the list is displayed on the Customer Detail Page.
- `SEARCH --> LIST`: User search input influences the Customer List and Filters.
- `FILTER --> LIST`: User state filter selection influences the Customer List and Filters.
- `PAGINATE --> LIST`: User pagination actions influence the Customer List and Filters.

## Repository Context & Terminology
- **JSON API**: A data format commonly used for transmitting data between a server and a web application.
- **Customer Data**: The information related to customers, such as name, address, contact details, etc.
- **Fetch Data**: The process of retrieving data from a data source, typically an API or database.
- **Customer List**: A user interface component that displays a list of customers.
- **Filters**: Functionality that allows users to narrow down the displayed data based on specific criteria.
- **Pagination**: A technique used to divide a large dataset into smaller, more manageable pages.
- **Customer Detail Page**: A user interface component that displays detailed information about a specific customer.

## High-Density QA Ground Truth Summary
The diagram illustrates the flow of customer data from a JSON API to a user interface, mediated by application logic. The process begins with the `API` node, representing the JSON API from which customer data is sourced. The `FETCH` node then retrieves this data. The core of the application lies in the `LIST` node, which represents the customer list view, enhanced with filtering capabilities. Finally, the `DETAIL` node presents a detailed view of a selected customer. The data flow converges at the `LIST` node, where the fetched data is refined based on user-defined search, filter, and pagination criteria before being displayed or passed to the `DETAIL` page. The JSON API serves as the foundational data source, providing the raw customer information that drives the entire application.
