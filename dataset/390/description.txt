## Repository Context & Terminology

- **AF_INET6**: Address Family for IPv6. Used to specify the IPv6 protocol when creating sockets.
- **socket.gethostbyname**: A Python socket library function used to resolve a hostname to an IPv4 address.
- **socket.getaddrinfo**: A Python socket library function used to resolve a hostname to a list of address information, including IPv4 and IPv6 addresses.
- **socket.inet_pton**: A Python socket library function that converts an IPv6 address from its textual representation to a packed binary format.

## High-Density QA Ground Truth Summary
The flowchart begins with "User Input: Target", which is then cleaned to remove "http://" prefixes and brackets. The cleaned input is checked to determine if it's already an IP address. If it is, the IP format is validated, branching into IPv4 and IPv6 checks. For IPv4, the validation ensures four octets are within the range of 0-255. For IPv6, `socket.inet_pton` is used for format validation. Valid IPv4 addresses lead to `Return AF_INET` and the use of an `AF_INET` socket, while valid IPv6 addresses lead to `Return AF_INET6` and the use of an `AF_INET6` socket. If the initial input is not an IP address, the system attempts to resolve it as a hostname, first trying IPv4 resolution via `socket.gethostbyname`, and if that fails, IPv6 resolution via `socket.getaddrinfo`. Successful resolution for either protocol leads to the respective socket selection. Invalid IP formats or failed hostname resolutions result in an error message being displayed. Finally, both IPv4 and IPv6 socket paths converge at the "Perform Port Scan" node, initiating the network scan. The use of `socket.gethostbyname` and `socket.getaddrinfo` are key functions for DNS resolution, while `AF_INET` and `AF_INET6` specify the address families for IPv4 and IPv6 sockets respectively.
