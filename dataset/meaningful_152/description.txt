## 图类型与用途
该图是一个流程图，描述了从代码仓库变更到镜像发布的整个流程。它展示了镜像构建的各个阶段，包括触发构建、镜像构建、镜像扫描和镜像发布。该图可以帮助理解容器镜像构建和发布的自动化流程。

## 图的整体布局
该图采用从上到下的布局方式。流程从代码仓库变更开始，经过一系列步骤，最终到达镜像发布。整个流程可以分为构建触发、镜像构建和镜像发布三个主要阶段。

## 分组/子图/阶段说明
图中包含三个子图，分别代表不同的阶段：
- **构建触发**：描述了代码变更如何触发构建任务。
- **镜像构建**：描述了如何从 Dockerfile 构建镜像，包括缓存的使用和镜像层的合并。
- **镜像发布**：描述了如何将构建好的镜像推送到镜像仓库并更新元数据。

## 节点逐项说明
- **A[代码仓库变更]**：代码仓库发生变更，例如代码提交。
- **B{Webhook 触发}**：代码仓库变更触发 Webhook，通知构建系统。
- **C[构建任务队列]**：Webhook 将构建任务添加到队列中。
- **D[任务调度器]**：任务调度器从队列中取出任务并分配给构建节点。
- **E[选择构建节点]**：选择合适的构建节点来执行构建任务。
- **F[拉取构建上下文]**：构建节点拉取构建所需的上下文，例如代码和 Dockerfile。
- **G{Dockerfile 解析}**：解析 Dockerfile，确定构建步骤。
- **H[构建镜像层]**：根据 Dockerfile 中的指令构建新的镜像层。
- **I[复用缓存镜像层]**：如果存在缓存，则复用已有的镜像层。
- **J[合并镜像层]**：将所有镜像层合并成一个完整的镜像。
- **K[镜像扫描]**：对构建好的镜像进行安全扫描，查找潜在的安全漏洞。
- **L{扫描结果分析}**：分析镜像扫描的结果。
- **M[中断构建]**：如果扫描发现安全漏洞，则中断构建过程。
- **N[镜像推送]**：如果扫描通过，则将镜像推送到镜像仓库。
- **O[镜像仓库]**：存储构建好的镜像。
- **P[发布元数据更新]**：更新镜像仓库中的元数据，例如镜像标签。

## 连线、分支与汇聚关系
- A -> B：代码仓库变更触发 Webhook。
- B -> C：Webhook 触发后将构建任务添加到队列。
- C -> D：任务调度器从队列中获取任务。
- D -> E：任务调度器选择构建节点。
- E -> F：选择构建节点后拉取构建上下文。
- F -> G：拉取构建上下文后解析 Dockerfile。
- G -- 无缓存 --> H：Dockerfile 解析后，如果没有缓存，则构建新的镜像层。
- G -- 有缓存 --> I：Dockerfile 解析后，如果有缓存，则复用缓存镜像层。
- H -> J：构建镜像层后合并镜像层。
- I -> J：复用缓存镜像层后合并镜像层。
- J -> K：合并镜像层后进行镜像扫描。
- K -> L：镜像扫描后进行扫描结果分析。
- L -- 安全漏洞 --> M：扫描结果分析发现安全漏洞，中断构建。
- L -- 通过 --> N：扫描结果分析通过，推送镜像。
- N -> O：推送镜像到镜像仓库。
- O -> P：镜像推送到镜像仓库后更新元数据。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **Dockerfile**：一个文本文件，其中包含构建 Docker 镜像所需的所有指令。
- **镜像层**：Docker 镜像由多个只读层组成，每一层代表 Dockerfile 中的一条指令。
- **镜像仓库**：用于存储和分发 Docker 镜像的中心化存储库。
- **Webhook**：一种基于 HTTP 的回调机制，用于在特定事件发生时通知其他系统。
- **构建上下文**：构建镜像时需要的文件和目录的集合。
- **元数据**：描述镜像的信息，例如标签、创建时间等。

## 可作为 QA Ground Truth 的高信息密度摘要
代码仓库变更触发 Webhook，将构建任务添加到构建任务队列。任务调度器选择构建节点并拉取构建上下文。Dockerfile 被解析，如果没有缓存则构建新的镜像层，否则复用缓存镜像层。所有镜像层合并后进行镜像扫描，如果发现安全漏洞则中断构建，否则将镜像推送到镜像仓库并更新元数据。
