## 图类型与用途
这是一个流程图，描述了 XingRin 系统的整体扫描流程，用于自动化资产发现与漏洞扫描。该图在仓库中用于概括扫描流程的架构，展示了从扫描开始到完成的各个阶段和使用的工具。

## 图的整体布局
图采用从左到右的布局。流程从左侧的“开始扫描”节点开始，经过三个主要阶段，最终到达右侧的“扫描完成”节点。

## 分组/子图/阶段说明
图中包含三个显式子图，分别对应扫描的三个阶段：
- **阶段 1: 资产发现**：使用多种工具进行子域名枚举、端口扫描、站点识别和指纹识别，以发现目标系统的资产。
- **阶段 2: 深度分析**：对已发现的资产进行更深入的分析，包括URL收集、目录扫描和站点截图。
- **阶段 3: 漏洞检测**：利用漏洞扫描工具对已发现的资产进行漏洞扫描。

## 节点逐项说明
- **START (开始扫描)**：扫描流程的起始点。
- **STAGE1 (阶段 1: 资产发现)**：专注于发现目标系统的资产。
    - **SUB (子域名发现)**：使用 subfinder, amass, puredns 等工具进行子域名枚举。README 中提到，该阶段通过被动收集 + 主动爆破，聚合 50+ 数据源。
    - **PORT (端口扫描)**：使用 naabu 工具进行端口扫描。README 中提到，该阶段支持自定义端口范围。
    - **SITE (站点识别)**：使用 httpx 工具识别站点。README 中提到，该阶段可以进行 HTTP 探测，自动获取标题、状态码、技术栈。
    - **FINGER (指纹识别)**：使用 xingfinger 工具进行指纹识别。README 中提到，该阶段使用 2.7W+ 指纹规则，多源指纹库。
- **STAGE2 (阶段 2: 深度分析)**：对已发现的资产进行更深入的分析。
    - **URL (URL 收集)**：使用 waymore, katana 等工具收集 URL。README 中提到，该阶段通过历史数据 + 主动爬取来收集 URL。
    - **DIR (目录扫描)**：使用 ffuf 工具进行目录扫描。README 中提到，该阶段使用高速爆破和智能字典。
    - **SCREENSHOT (站点截图)**：使用 playwright 工具进行站点截图。README 中提到，该阶段使用 WebP 高压缩存储。
- **STAGE3 (阶段 3: 漏洞检测)**：对已发现的资产进行漏洞检测。
    - **VULN (漏洞扫描)**：使用 nuclei, dalfox 等工具进行漏洞扫描。README 中提到，该阶段使用 9000+ POC 模板，进行 XSS 检测。
- **FINISH (扫描完成)**：扫描流程的结束点。

## 连线、分支与汇聚关系
- `START -> STAGE1`：扫描流程从开始扫描进入资产发现阶段。
- `STAGE1: SUB -> STAGE1: PORT -> STAGE1: SITE -> STAGE1: FINGER`：在资产发现阶段，流程依次经过子域名发现、端口扫描、站点识别和指纹识别。
- `STAGE1: FINGER -> STAGE2`：完成资产发现后，流程进入深度分析阶段。
- `STAGE2 -> STAGE3`：完成深度分析后，流程进入漏洞检测阶段。
- `STAGE3 -> FINISH`：完成漏洞检测后，流程到达扫描完成。

## 仓库语境与术语解释
- **XingRin (星环)**：一个攻击面管理平台 (ASM) 和自动化资产发现与漏洞扫描系统，如 README 所示。
- **ASM (攻击面管理)**：用于发现、分析和管理组织暴露在外的攻击面，降低安全风险。
- **Subfinder, Amass, PureDNS, Naabu, HTTPX, XingFinger, Waymore, Katana, FFUF, Playwright, Nuclei, Dalfox**：用于执行不同扫描任务的工具，例如子域名枚举、端口扫描、站点识别、指纹识别、URL 收集、目录扫描、站点截图和漏洞扫描。
- **POC (Proof of Concept)**：用于验证漏洞是否存在的概念验证代码或方法。
- **docs/scan-flow-architecture.md**：该文档详细描述了完整的扫描流程，包括子域名发现、端口扫描、站点发现、指纹识别、URL 收集、目录扫描、漏洞扫描等阶段。
- **backend/apps/scan/flows**：该目录包含用于编排扫描流程的 Prefect Flows，例如 `subdomain_discovery_flow.py`、`port_scan_flow.py` 和 `site_scan_flow.py`。

## 可作为 QA Ground Truth 的高信息密度摘要
XingRin 系统的扫描流程从“开始扫描”节点启动，首先进入“阶段 1: 资产发现”，依次执行子域名发现（subfinder, amass, puredns）、端口扫描（naabu）、站点识别（httpx）和指纹识别（xingfinger）。然后进入“阶段 2: 深度分析”，执行 URL 收集（waymore, katana）、目录扫描（ffuf）和站点截图（playwright）。最后进入“阶段 3: 漏洞检测”，使用 nuclei 和 dalfox 进行漏洞扫描，最终到达“扫描完成”节点。该流程旨在全面、深入地评估目标系统的安全风险，其中资产发现是基础，深度分析提供更多信息，漏洞检测则直接发现安全问题。
