## 图类型与用途
该图是一个流程图，描述了一个推荐系统的整体架构和流程。它展示了从用户行为触发到最终展示的完整链路，包括召回、排序、AB实验等关键环节。该图可以帮助理解推荐系统的工作原理和数据流向。

## 图的整体布局
该图采用从左到右的布局，整体呈现出多层结构。流程从左侧的“用户触发”开始，经过一系列处理后，最终在右侧的“后处理与展示”结束。

## 分组/子图/阶段说明
图中包含多个子图，分别代表推荐系统的不同阶段：
- **用户触发**：模拟用户行为，为推荐系统提供输入。
- **召回服务**：从海量物品中筛选出用户可能感兴趣的候选集。
- **粗排与精排**：对候选集进行多轮排序，提高推荐的准确性。
- **后处理与展示**：对排序结果进行处理，并通过AB实验评估效果，最终展示给用户。
- **特征工程**：为排序模型提供特征支持。

## 节点逐项说明
- **A[用户行为日志]**：记录用户在平台上的各种行为数据，如浏览、点击、购买等。
- **B(实时行为提取与加工)**：对用户行为日志进行实时提取和加工，形成可用的特征。
- **C[历史行为特征库]**：存储用户的历史行为特征，用于个性化推荐。
- **D{触发条件判断}**：判断是否满足触发推荐的条件，例如用户是否登录、是否有新的行为等。
- **E(召回服务)**：根据用户特征和物品特征，从海量物品库中召回用户可能感兴趣的物品。
- **F[多路召回]**：采用多种召回策略，例如基于协同过滤、基于内容、基于热门等。
- **G(粗排模型)**：使用简单的模型对召回的物品进行初步排序，筛选出TopN的物品。
- **I{截断TopN}**：判断是否需要截断TopN的物品。
- **J(精排模型)**：使用复杂的模型对粗排筛选出的物品进行精细排序，提高推荐的准确性。
- **K(重排序)**：对精排后的物品进行重排序，例如根据多样性、新鲜度等因素。
- **L{流量分桶}**：将用户流量分配到不同的桶中，用于AB实验。
- **M[AB实验A]**：采用A方案进行推荐。
- **N[AB实验B]**：采用B方案进行推荐。
- **O(结果融合与过滤)**：将不同AB实验的结果进行融合，并进行过滤，例如去除重复的物品。
- **P[最终展示]**：将最终的推荐结果展示给用户。
- **X[用户画像特征]**：描述用户属性和偏好的特征。
- **Y(特征拼接)**：将用户画像特征、Item特征和上下文特征拼接在一起，形成完整的特征向量。
- **Z[Item特征]**：描述物品属性的特征。
- **W[上下文特征]**：描述用户所处环境的特征，例如时间、地点、设备等。
- **H[结束]**：流程结束。

## 连线、分支与汇聚关系
- A -> B：用户行为日志输入到实时行为提取与加工模块。
- C -> B：历史行为特征库输入到实时行为提取与加工模块。
- B -> D：实时行为提取与加工的结果输入到触发条件判断模块。
- D -- 满足条件 --> E：满足触发条件，进入召回服务。
- D -- 不满足条件 --> H：不满足触发条件，流程结束。
- E -> F：召回服务进入多路召回。
- F -> G：多路召回的结果输入到粗排模型。
- G -> I：粗排模型的结果输入到截断TopN判断模块。
- I -- 是 --> J：需要截断TopN，进入精排模型。
- I -- 否 --> H：不需要截断TopN，流程结束。
- J -> K：精排模型的结果输入到重排序模块。
- K -> L：重排序的结果输入到流量分桶模块。
- L -- 桶A --> M：流量分桶到A桶，进入AB实验A。
- L -- 桶B --> N：流量分桶到B桶，进入AB实验B。
- M -> O：AB实验A的结果输入到结果融合与过滤模块。
- N -> O：AB实验B的结果输入到结果融合与过滤模块。
- O -> P：结果融合与过滤的结果输入到最终展示模块。
- P -> H：最终展示后，流程结束。
- X -> Y：用户画像特征输入到特征拼接模块。
- Z -> Y：Item特征输入到特征拼接模块。
- W -> Y：上下文特征输入到特征拼接模块。
- Y -> G：特征拼接的结果输入到粗排模型。
- Y -> J：特征拼接的结果输入到精排模型。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **召回**：从海量物品库中筛选出用户可能感兴趣的候选物品集合的过程。
- **粗排**：使用简单的模型对召回的物品进行初步排序，筛选出TopN的物品。
- **精排**：使用复杂的模型对粗排筛选出的物品进行精细排序，提高推荐的准确性。
- **重排序**：对精排后的物品进行重排序，例如根据多样性、新鲜度等因素。
- **AB实验**：一种常用的评估推荐效果的方法，将用户流量分配到不同的桶中，采用不同的推荐策略，比较不同策略的效果。
- **用户画像**：对用户属性和偏好的描述，用于个性化推荐。
- **Item特征**：对物品属性的描述，用于推荐。
- **上下文特征**：描述用户所处环境的特征，例如时间、地点、设备等，用于推荐。

## 可作为 QA Ground Truth 的高信息密度摘要
用户行为日志和历史行为特征经过实时行为提取与加工后，进行触发条件判断。若满足条件，则进入召回服务，通过多路召回策略得到候选集，再经过粗排模型和截断TopN判断，进入精排模型进行精细排序，然后进行重排序。重排序结果经过流量分桶进入AB实验，最终结果经过融合与过滤后展示给用户。特征工程模块提供用户画像特征、Item特征和上下文特征，拼接后为粗排和精排模型提供特征支持。
