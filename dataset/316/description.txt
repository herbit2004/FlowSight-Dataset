## 图类型与用途
这是一个流程图，描述了 Gobii Platform 中 Agent 的架构和工作流程。它展示了 Agent 如何被触发、运行、与其他组件交互，以及如何产生输出，用于概括 Agent 的整体架构。

## 图的整体布局
图采用从左到右的布局。左侧是触发 Agent 的各种方式，中间是 Agent 的运行时环境和工具层，右侧是 Agent 的输出。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：触发阶段、运行阶段和输出阶段。

## 节点逐项说明
- **External Triggers SMS · Email · Webhook · API**：表示外部触发器，包括短信、电子邮件、Webhook 和 API 调用，用于启动 Agent。
- **Schedule / Cron**：表示定时任务调度器，允许 Agent 按照预定的时间表自动运行。`api/agent/core/schedule_parser.py` 文件负责解析 schedule 字符串。
- **Per-Agent Durable Queue**：表示每个 Agent 都有一个持久化的队列，用于存储触发 Agent 的事件或消息。这个队列保证了 Agent 的可靠性，即使 Agent 暂时不可用，事件也不会丢失。
- **Persistent Agent Runtime**：表示持久化的 Agent 运行时环境，是 Agent 实际运行的地方。它负责执行 Agent 的逻辑，并管理 Agent 的状态。
- **Tools Layer**：表示工具层，为 Agent 提供各种工具和能力，以便完成任务。
- **Browser Automation headed + profile-aware**：表示浏览器自动化工具，允许 Agent 模拟用户在浏览器中的操作，例如访问网页、填写表单等。`headed + profile-aware` 说明该自动化是可见的（有浏览器界面）并且能够识别用户配置。
- **SQLite State structured memory tables**：表示 SQLite 状态存储，为 Agent 提供结构化的内存表，用于存储和管理 Agent 的状态数据。
- **Outbound Integrations webhooks + HTTP**：表示出站集成，允许 Agent 通过 Webhook 和 HTTP 请求与其他系统进行交互。
- **Agent-to-Agent peer messaging**：表示 Agent 之间的通信机制，允许不同的 Agent 互相发送消息和协作。
- **Comms Replies SMS · Email · Web**：表示通信回复，Agent 可以通过短信、电子邮件或 Web 界面向外部发送回复消息。
- **Files + Reports + Artifacts**：表示文件、报告和工件，Agent 可以生成各种文件、报告和工件，例如日志文件、分析报告等。

## 连线、分支与汇聚关系
- `A -> B`：外部触发器将事件或消息发送到每个 Agent 对应的持久化队列。其中 A 代表 **External Triggers SMS · Email · Webhook · API**，B 代表 **Per-Agent Durable Queue**。
- `C -> B`：定时任务调度器将事件或消息发送到每个 Agent 对应的持久化队列。其中 C 代表 **Schedule / Cron**，B 代表 **Per-Agent Durable Queue**。
- `B -> D`：持久化队列将事件或消息传递给 Agent 的运行时环境。其中 B 代表 **Per-Agent Durable Queue**，D 代表 **Persistent Agent Runtime**。
- `D -> E`：Agent 运行时环境利用工具层中的各种工具来执行 Agent 的逻辑。其中 D 代表 **Persistent Agent Runtime**，E 代表 **Tools Layer**。
- `E -> E1`：工具层包含浏览器自动化工具。其中 E 代表 **Tools Layer**，E1 代表 **Browser Automation headed + profile-aware**。
- `E -> E2`：工具层包含 SQLite 状态存储。其中 E 代表 **Tools Layer**，E2 代表 **SQLite State structured memory tables**。
- `E -> E3`：工具层包含出站集成。其中 E 代表 **Tools Layer**，E3 代表 **Outbound Integrations webhooks + HTTP**。
- `E -> E4`：工具层包含 Agent 间通信机制。其中 E 代表 **Tools Layer**，E4 代表 **Agent-to-Agent peer messaging**。
- `D -> F`：Agent 运行时环境可以通过通信回复向外部发送消息。其中 D 代表 **Persistent Agent Runtime**，F 代表 **Comms Replies SMS · Email · Web**。
- `D -> G`：Agent 运行时环境可以生成文件、报告和工件。其中 D 代表 **Persistent Agent Runtime**，G 代表 **Files + Reports + Artifacts**。

## 仓库语境与术语解释
- **Agent**：Gobii 平台的核心组件，可以持续运行、响应事件、使用浏览器、调用外部系统和与其他 Agent 协作。
- **Persistent Agent**：一种特殊的 Agent，其运行时环境是持久化的，保证了 Agent 的可靠性和状态的持久性。
- **Browser Automation**：一种工具，允许 Agent 模拟用户在浏览器中的操作，例如访问网页、填写表单等。
- **SQLite State**：一种状态存储，为 Agent 提供结构化的内存表，用于存储和管理 Agent 的状态数据。
- **Outbound Integrations**：一种集成方式，允许 Agent 通过 Webhook 和 HTTP 请求与其他系统进行交互。
- **Agent-to-Agent Messaging**：一种通信机制，允许不同的 Agent 互相发送消息和协作。
- **Tools Layer**: 为 Agent 提供各种工具和能力，以便完成任务。`api/agent/tools/__init__.py` 定义了 agent 的工具。
- **Schedule / Cron**: 定时任务调度器，允许 Agent 按照预定的时间表自动运行。`api/agent/core/schedule_parser.py` 文件负责解析 schedule 字符串。

## 可作为 QA Ground Truth 的高信息密度摘要
Gobii Platform 的 Agent 架构允许 Agent 通过外部触发器或定时任务被触发，事件被发送到持久化队列，然后传递给 Agent 的运行时环境。Agent 运行时环境利用工具层中的各种工具来执行 Agent 的逻辑，包括浏览器自动化、SQLite 状态存储、出站集成和 Agent 间通信。Agent 可以通过通信回复向外部发送消息，也可以生成文件、报告和工件。`api/agent/core/schedule_parser.py` 负责解析定时任务的 schedule 字符串。
