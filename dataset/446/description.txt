## 图类型与用途
这是一个流程图，描述了当 Handler Function 需要加载模块时，系统尝试加载模块的逻辑和顺序。该图在仓库中用于解释模块加载机制，特别是如何解决跨上下文的模块加载问题，如 README 和 ARCHITECTURE.md 中所述。

## 图的整体布局
图采用从上到下的布局。顶部是流程的起点，中间是模块加载的尝试路径，底部是成功返回模块或抛出错误两种结果。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分为三个阶段：模块请求、路径尝试和结果处理。

## 节点逐项说明
- **Handler Function Needs Module**：表示处理函数需要加载一个模块，是整个流程的起点。
- **loadDocumentGenerator OR loadSpecGenerator**：表示实际执行加载模块的函数，可能是 `loadDocumentGenerator` 或 `loadSpecGenerator`。根据 ARCHITECTURE.md，这两个函数在 `src/index.ts` 中被调用。
- **Try Path 1 ./utils/*.js**：尝试从当前目录下的 `utils` 文件夹中加载 JavaScript 文件。
- **Try Path 2 ../utils/*.js**：尝试从父目录下的 `utils` 文件夹中加载 JavaScript 文件。
- **Try Path 3 ./*.js**：尝试从当前目录加载 JavaScript 文件。
- **Try Path 4 ../*.js**：尝试从父目录加载 JavaScript 文件。
- **Return Module**：表示成功加载模块，并返回该模块。
- **Throw Error with all attempted paths**：表示所有路径尝试都失败，抛出一个包含所有尝试路径的错误。
- **Log Success Path console.error SDD-DEBUG**：表示成功加载模块后，将成功加载的路径记录到控制台，方便调试。

## 连线、分支与汇聚关系
- `A -> B`：处理函数需要模块，调用加载函数。
- `B -> C`：开始尝试第一条路径。
- `C -- Success --> Z`：如果路径尝试成功，则返回模块。
- `C -- Fail --> D`：如果路径尝试失败，则尝试下一条路径。
- `D -- Success --> Z`：如果路径尝试成功，则返回模块。
- `D -- Fail --> E`：如果路径尝试失败，则尝试下一条路径。
- `E -- Success --> Z`：如果路径尝试成功，则返回模块。
- `E -- Fail --> F`：如果路径尝试失败，则尝试下一条路径。
- `F -- Success --> Z`：如果路径尝试成功，则返回模块。
- `F -- Fail --> G`：如果路径尝试失败，则抛出错误。
- `Z -> H`：成功返回模块后，记录成功路径。
- 节点 C、D、E、F 均可能汇聚到 Z，形成汇聚关系。

## 仓库语境与术语解释
- **moduleLoader.ts**：该文件实现了跨上下文兼容的模块加载机制，解决了在不同执行环境（如 npx, npm, node）下模块路径解析不同的问题，如 ARCHITECTURE.md 中所述。
- **documentGenerator.js**：该文件用于分析项目结构，生成项目信息，被 `specGenerator.js` 使用，如 ARCHITECTURE.md 中所述。
- **specGenerator.js**：该文件用于生成 requirements, design, tasks 等文档，如 ARCHITECTURE.md 中所述。
- **loadDocumentGenerator / loadSpecGenerator**：这两个函数用于加载 `documentGenerator.js` 和 `specGenerator.js` 模块，在 `src/index.ts` 中被调用。
- **SDD-DEBUG**：用于在控制台输出调试信息，帮助开发者了解模块加载的路径。
- **Handler Function**：指需要加载模块的函数，例如 `handleSteeringSimplified`、`handleRequirementsSimplified` 等，它们在 `src/index.ts` 中。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 MCP SDD Server 中模块加载的重试机制。流程从 Handler Function 需要模块开始，尝试按照预定义的路径顺序（./utils/*.js -> ../utils/*.js -> ./*.js -> ../*.js）加载模块。如果任何一条路径成功加载模块，则返回该模块并记录成功路径；否则，抛出包含所有尝试路径的错误。该机制提高了模块加载的可靠性，并方便了调试，解决了跨上下文模块加载的问题，`moduleLoader.ts` 是该机制的核心实现。`loadDocumentGenerator` 和 `loadSpecGenerator` 是加载的关键模块。
