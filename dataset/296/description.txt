## 图类型与用途
这是一个架构图，展示了 `osctrl` 系统的各个组件及其交互方式，描述了 `osquery` 代理的管理和监控流程。该图在仓库中用于概览 `osctrl` 的整体架构，帮助理解不同组件之间的关系和数据流。

## 图的整体布局
图采用从左到右的布局。左侧是入口节点，包括 `osquery Agents` 和 `Operators`，中间是 `osctrl` 的各个服务组件，右侧是数据存储和日志目的地。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：数据采集与接入、核心服务处理、数据存储与输出。

## 节点逐项说明
- **osquery Agents**：运行 `osquery` 的主机，是系统监控的目标。
- **osctrl-tls**：`osctrl` 的 TLS 终端，负责接收来自 `osquery` 代理的连接和数据，实现 `osquery` 的远程 API。
- **Operators**：操作员，即使用 `osctrl` 的用户。
- **osctrl-admin**：`osctrl` 的 Web UI，提供图形化界面供操作员使用。
- **osctrl-cli**：`osctrl` 的命令行界面，提供命令行方式供操作员使用。
- **osctrl-api**：`osctrl` 的 REST API，提供编程接口供其他系统或工具集成。
- **Shared Packages (pkg/*)**：共享包，包含 `osctrl` 各个组件共享的代码和功能模块。
- **PostgreSQL Backend**：PostgreSQL 数据库，用于存储 `osctrl` 的配置、状态和结果数据。
- **Redis Cache**：Redis 缓存，用于缓存数据以提高性能。
- **Log Destinations (DB, file, S3, Elastic, Splunk, Graylog, Kafka, Kinesis, Logstash)**：日志目的地，用于将 `osquery` 的日志数据发送到不同的存储和分析系统。
- **Carve Storage (DB, local, S3)**：文件雕刻存储，用于存储从主机上雕刻（提取）的文件和目录。

## 连线、分支与汇聚关系
- `osquery Agents -> osctrl-tls`：`osquery` 代理通过 TLS Remote API 连接到 `osctrl-tls`。
- `Operators -> osctrl-admin`：操作员通过 Web UI 与 `osctrl` 交互。
- `Operators -> osctrl-cli`：操作员通过 CLI 与 `osctrl` 交互。
- `Operators -> osctrl-api`：操作员通过 REST API 与 `osctrl` 交互。
- `osctrl-admin -> osctrl-api`：`osctrl-admin` 通过 HTTP API 与 `osctrl-api` 通信。
- `osctrl-cli -> osctrl-api`：`osctrl-cli` 通过 HTTP API 与 `osctrl-api` 通信。
- `osctrl-tls -> Shared Packages (pkg/*)`：`osctrl-tls` 使用 `Shared Packages`。
- `osctrl-admin -> Shared Packages (pkg/*)`：`osctrl-admin` 使用 `Shared Packages`。
- `osctrl-api -> Shared Packages (pkg/*)`：`osctrl-api` 使用 `Shared Packages`。
- `osctrl-cli -> Shared Packages (pkg/*)`：`osctrl-cli` 使用 `Shared Packages`。
- `osctrl-cli -.-> PostgreSQL Backend`：`osctrl-cli` 可以通过 Direct DB mode 直接访问 `PostgreSQL Backend`。
- `Shared Packages (pkg/*) -> PostgreSQL Backend`：`Shared Packages` 与 `PostgreSQL Backend` 交互。
- `Shared Packages (pkg/*) -> Redis Cache`：`Shared Packages` 与 `Redis Cache` 交互。
- `Shared Packages (pkg/*) -> Log Destinations (DB, file, S3, Elastic, Splunk, Graylog, Kafka, Kinesis, Logstash)`：`Shared Packages` 与 `Log Destinations` 交互。
- `Shared Packages (pkg/*) -> Carve Storage (DB, local, S3)`：`Shared Packages` 与 `Carve Storage` 交互。

## 仓库语境与术语解释
- **osquery**：一个开源的操作系统检测框架，允许使用 SQL 查询来监控系统状态。
- **osctrl-tls**：实现了 `osquery` 的远程 API，作为 TLS 终端接收来自 `osquery` 代理的连接和数据。参考 `cmd/tls/main.go`。
- **osctrl-admin**：`osctrl` 的 Web UI，允许操作员通过图形界面与系统交互。参考 `cmd/admin/main.go`。
- **osctrl-cli**：`osctrl` 的命令行界面，提供命令行方式与系统交互。参考 `cmd/cli/main.go`。
- **osctrl-api**：`osctrl` 的 REST API，提供编程接口供其他系统或工具集成。参考 `cmd/api/main.go`。
- **Shared Packages (pkg/*)**：包含 `osctrl` 各个组件共享的代码和功能模块，例如 `pkg/config/types.go` 定义了配置类型。
- **Log Destinations**：支持多种日志输出方式，例如 `pkg/logging/logging.go` 中定义了对 Splunk、Graylog 等的支持。
- **Carve Storage**：用于存储从主机提取的文件，支持本地、数据库和 S3 存储。参考 `pkg/config/types.go` 中 Carver 相关的定义。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 `osctrl` 的整体架构。`osquery Agents` 通过 `osctrl-tls` 接入，`Operators` 通过 `osctrl-admin`、`osctrl-cli` 或 `osctrl-api` 与系统交互。核心组件通过 `Shared Packages` 共享代码，数据存储在 `PostgreSQL Backend` 和 `Redis Cache` 中，日志可以输出到多种 `Log Destinations`，提取的文件存储在 `Carve Storage` 中。`osctrl-tls` 作为 `osquery` 远程 API 的实现，是数据接入的关键入口。
