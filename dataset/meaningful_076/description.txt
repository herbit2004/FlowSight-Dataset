## 图类型与用途
该图是一个流程图，描述了发票申请的完整流程。流程从申请人提交申请开始，经过审批、复核、开票等环节，最终完成发票的开具或驳回申请。图中还详细展示了自动开票系统的内部流程。

## 图的整体布局
该图采用从上到下的布局。整体流程分为发票申请流程和自动开票系统内部流程两个主要部分。起点是申请人提交发票申请，终点是结束（申请驳回）或更新发票状态。

## 分组/子图/阶段说明
图中包含两个子图：
- **发票申请流程**：描述了发票申请从提交到最终状态的完整流程。
- **自动开票系统**：描述了自动开票系统内部的处理流程。自动开票系统内部又包含一个子图 **自动开票系统内部**，更详细地描述了自动开票的步骤。

## 连线、分支与汇聚关系
- A -> B：申请人提交发票申请后，进入审批人审批环节。
- B -- 审批通过 --> C：审批通过后，进入财务复核环节。
- B -- 审批拒绝 --> Z：审批拒绝后，流程结束，申请驳回。
- C -- 复核通过 --> D：复核通过后，判断是否自动开票。
- C -- 复核拒绝 --> Z：复核拒绝后，流程结束，申请驳回。
- D -- 是 --> E：如果选择自动开票，则进入自动开票系统。
- D -- 否 --> F：如果选择人工开票，则进入人工开票流程。
- E -> G：自动开票系统生成电子发票。
- F -> G：人工开票生成电子发票。
- G -> H：生成电子发票后，判断是否需要邮寄。
- H -- 是 --> I：如果需要邮寄，则邮寄发票。
- H -- 否 --> J：如果不需要邮寄，则发送电子发票。
- I -> K：邮寄发票后，更新发票状态。
- J -> K：发送电子发票后，更新发票状态。
- K -> Z：更新发票状态后，流程结束。
- AA -> BB：接收开票请求后，校验开票信息。
- BB -- 信息正确 --> CC：信息正确，调用税务接口。
- BB -- 信息错误 --> DD：信息错误，记录错误日志。
- CC -> EE：调用税务接口后，接收税务响应。
- EE -- 开票成功 --> FF：开票成功，生成PDF发票。
- EE -- 开票失败 --> DD：开票失败，记录错误日志。
- FF -> GG：生成PDF发票后，保存发票数据。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **发票申请**：指向公司或组织提交的，请求开具发票的正式请求。
- **审批人**：负责审核发票申请是否符合规定的相关人员。
- **财务复核**：财务部门对发票申请的金额、抬头等信息进行再次审核。
- **自动开票系统**：通过系统自动完成发票开具的流程。
- **税务接口**：自动开票系统与税务部门系统进行数据交互的接口。
- **电子发票**：以电子方式存储的具有法律效力的发票。
- **PDF发票**：以PDF格式存储的电子发票。

## 可作为 QA Ground Truth 的高信息密度摘要
发票申请流程从申请人提交发票申请开始，经过审批人审批，若审批拒绝则流程结束。审批通过后进入财务复核，复核拒绝则流程结束。复核通过后，判断是否自动开票，若是则进入自动开票系统，否则进入人工开票流程。自动开票系统接收开票请求后，校验开票信息，信息错误则记录错误日志，信息正确则调用税务接口，接收税务响应，开票失败则记录错误日志，开票成功则生成PDF发票并保存发票数据。人工开票和自动开票都会生成电子发票，然后判断是否需要邮寄，若需要则邮寄发票，否则发送电子发票，最后更新发票状态，流程结束。
