## Repository Context & Terminology
- **React SPA**: Single Page Application built using React framework.
- **HTTP API**: An interface that allows different systems to communicate over the internet using HTTP protocol.
- **WebSocket RPC**: A communication protocol that provides full-duplex communication channels over a single TCP connection.
- **Message Bus**: A software architecture pattern used for inter-application communication.
- **Lane-based Scheduler**: A scheduler that organizes tasks into lanes for processing, potentially allowing for parallel or prioritized execution.
- **Agent Loop (think → act → observe)**: A control loop where an agent thinks, acts based on its thinking, and observes the result of its actions.
- **pgvector**: A PostgreSQL extension for vector similarity search.

## High-Density QA Ground Truth Summary
The system begins with various clients: Web Dashboard (React SPA), HTTP API, Telegram, Discord, Feishu/Lark, Zalo OA, and Zalo Personal. The Web Dashboard communicates via WebSocket RPC, while the HTTP API uses an HTTP Server. The other clients (Telegram, Discord, Feishu/Lark, Zalo OA, Zalo Personal) all connect to the Channel Manager. The WebSocket RPC, HTTP Server, and Channel Manager converge by sending messages to the Message Bus. The Message Bus then feeds into the Lane-based Scheduler, which organizes tasks, potentially using cron-based scheduling. The Agent Router receives scheduled tasks and routes them to the Agent Loop. The Agent Loop operates on a "think -> act -> observe" cycle, utilizing the Tool Registry for various tools (fs, exec, web, memory, delegate, team, mcp, custom) and LLM Providers such as Anthropic (with native and prompt caching) and OpenAI-compat (12+). Finally, the Agent Loop persists data to both a File-based (standalone) storage solution and a PostgreSQL 18 + pgvector (managed · multi-tenant) database, leveraging the pgvector extension for vector similarity searches.
