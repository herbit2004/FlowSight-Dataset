## 图类型与用途
这是一个流程图，描述了 Vibe Coder MCP Server 的启动和运行流程，包括首次运行检测、配置、参数解析、运行模式选择（REPL、CLI、MCP Server）以及不同模式下的具体流程。它在仓库中的作用是概括服务器的整体启动和运行逻辑。

## 图的整体布局
图整体采用从上到下的布局。顶部是启动节点，中间是配置和模式选择阶段，底部是不同模式下的执行流程。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可以分成四个阶段：启动与首次运行检测、配置与参数解析、运行模式选择、不同模式下的执行。

## 节点逐项说明
- **Start (vibe command)**：流程的起点，表示用户执行 `vibe` 命令。
- **Detect {First Run?}**：判断是否是首次运行的节点。
- **Setup [Setup Wizard]**：首次运行时执行的设置向导，用于配置服务器。README 表明该向导会配置 OpenRouter API key、项目目录、配置文件等。
- **Config [Save Configuration]**：保存配置信息的节点。
- **Parse [Parse Arguments]**：解析命令行参数的节点。
- **Mode {Mode?}**：根据解析的参数确定运行模式的判断节点。
- **REPL [Interactive REPL]**：交互式 REPL (Read-Eval-Print Loop) 模式。`src/cli/interactive/repl.ts` 定义了 REPL 的启动和运行逻辑。
- **CLI [CLI Execution]**：命令行执行模式。
- **MCP [MCP Server]**：MCP (Model Context Protocol) 服务器模式。`src/server.ts` 定义了 MCP Server 的创建和启动。
- **Session [Session Management]**：会话管理模块，用于维护用户会话。
- **Chat [Chat Interface]**：聊天界面，用于与用户交互。
- **Tools [Tool Execution]**：工具执行模块，执行各种软件开发工具。
- **Router [Hybrid Router]**：混合路由，用于将CLI命令路由到相应的工具。
- **Transport {Transport?}**：确定使用的传输协议的判断节点。
- **Stdio [Stdio Server]**：使用标准输入/输出流 (stdio) 作为传输协议的服务器。
- **SSE [SSE Server]**：使用服务器发送事件 (Server-Sent Events, SSE) 作为传输协议的服务器。

## 连线、分支与汇聚关系
- `Start -> Detect`：执行 `vibe` 命令后，检查是否是首次运行。
- `Detect -- Yes --> Setup`：如果是首次运行，则执行 `Setup` 向导。
- `Detect -- No --> Parse`：如果不是首次运行，则直接进入参数解析 `Parse`。
- `Setup -> Config`：执行 `Setup` 向导后，将配置保存到 `Config`。
- `Config -> Parse`：保存配置后，进入参数解析 `Parse`。
- `Parse -> Mode`：解析参数后，根据参数确定运行模式。
- `Mode -- --interactive --> REPL`：如果模式是 `--interactive`，则进入交互式 REPL 模式。
- `Mode -- "message" --> CLI`：如果模式是 `"message"`，则进入命令行执行模式。
- `Mode -- none --> MCP`：如果模式是 `none`，则进入 MCP 服务器模式。
- `Mode -- --setup --> Setup`：如果模式是 `--setup`，则重新执行 Setup Wizard。
- `REPL -> Session`：进入交互式 REPL 模式后，进行会话管理。
- `Session -> Chat`：会话管理后，通过聊天界面与用户交互。
- `Chat -> Tools`：通过聊天界面与用户交互后，执行工具。
- `CLI -> Router`：进入命令行执行模式后，通过混合路由将命令路由到相应的工具。
- `Router -> Tools`：混合路由将命令路由到相应的工具。
- `MCP -> Transport`：进入 MCP 服务器模式后，确定传输协议。
- `Transport -- stdio --> Stdio`：如果传输协议是 `stdio`，则使用 Stdio Server。
- `Transport -- sse --> SSE`：如果传输协议是 `sse`，则使用 SSE Server。
- `Stdio -> Tools`：Stdio Server 执行工具。图中可见，但仓库上下文未进一步说明。
- `SSE -> Tools`：SSE Server 执行工具。图中可见，但仓库上下文未进一步说明。
- `Chat -> Tools` 和 `Router -> Tools` 形成汇聚关系。

## 仓库语境与术语解释
- **Vibe Coder MCP Server**：一个 MCP (Model Context Protocol) 服务器，旨在增强 AI 助手（如 Cursor, Cline AI, 或 Claude Desktop）的软件开发能力。
- **MCP (Model Context Protocol)**：一种协议，用于 AI 助手与外部工具之间的通信。
- **REPL (Read-Eval-Print Loop)**：一种交互式编程环境，允许用户逐行输入和执行代码。`src/cli/interactive/repl.ts` 实现了交互式 REPL 模式。
- **CLI (Command Line Interface)**：一种通过命令行与计算机程序交互的方式。
- **Setup Wizard**：一个交互式配置工具，用于首次设置 Vibe Coder MCP Server。`src/setup-wizard.ts` 实现了 Setup Wizard。
- **OpenRouter API Key**：用于访问 OpenRouter 服务的 API 密钥。README 提到需要配置 OpenRouter API key。
- **Transport Protocol**：用于在客户端和服务器之间传输数据的协议，这里包括 `stdio` 和 `sse`。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了 Vibe Coder MCP Server 的启动流程，从执行 `vibe` 命令开始，首先检测是否是首次运行，如果是则执行 Setup Wizard 进行配置。然后解析命令行参数，根据参数选择不同的运行模式：交互式 REPL 模式、命令行执行模式或 MCP 服务器模式。在 REPL 模式下，通过聊天界面与用户交互并执行工具；在 CLI 模式下，通过混合路由将命令路由到工具；在 MCP 模式下，选择传输协议（stdio 或 SSE）并执行工具。其中 Setup Wizard 用于配置 OpenRouter API Key，`src/cli/interactive/repl.ts` 实现了交互式 REPL 模式。
