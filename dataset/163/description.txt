## 图类型与用途
这是一个流程图，描述了 `Compound Product` 如何通过分析每日报告、制定改进计划并自动执行这些计划，最终生成一个待审查的 Pull Request。它展示了一个自改进的产品系统，旨在自动化产品改进流程。

## 图的整体布局
图整体采用从上到下的布局。从顶部的“Your System”阶段开始，经过分析、计划和执行循环，最终在底部输出 Pull Request。

## 分组/子图/阶段说明
图中包含多个子图，分别代表不同的阶段：
- **Phase 0: Your System**：表示现有的产品系统，负责生成每日报告。
- **Phase 1: Analysis**：使用 LLM 分析报告的阶段，确定优先级和标准。
- **Phase 2: Planning**：基于分析结果制定改进计划的阶段，创建分支并生成产品需求文档和可执行的任务列表。
- **Phase 3: Execution Loop**：循环执行任务的阶段，直到所有任务完成或达到最大迭代次数。
- **Output**：表示最终结果，包括推送 Git 变更和生成 Pull Request。

## 节点逐项说明
- **GEN (Generate Daily Report)**：生成每日报告的组件，可以是代码、定时任务等。
- **R (📊 reports/\*.md)**：每日报告，包含指标、错误和反馈等信息。根据 README，报告可以是任何 markdown 文件。
- **A (analyze-report.sh)**：分析报告的脚本，使用 LLM API。点击该节点可跳转到 `scripts/analyze-report.sh` 文件查看具体实现。
- **J (analysis.json)**：分析结果，包含优先级和标准。
- **B (Create Branch)**：创建新的 Git 分支，例如 `compound/feature-name`。
- **PRD (AI Agent)**：AI 代理，加载 `prd` skill，用于生成产品需求文档。点击该节点可跳转到 `skills/prd/SKILL.md` 文件查看该 skill 的详细信息。
- **MD (tasks/prd-feature.md)**：产品需求文档，描述需要完成的任务。
- **TASKS (AI Agent)**：AI 代理，加载 `tasks` skill，用于将产品需求文档转化为可执行的任务列表。点击该节点可跳转到 `skills/tasks/SKILL.md` 文件查看该 skill 的详细信息。
- **JSON (prd.json)**：可执行的任务列表，JSON 格式。
- **LOOP (loop.sh)**：执行循环的脚本，限制最大迭代次数。点击该节点可跳转到 `scripts/loop.sh` 文件查看具体实现。
- **PICK (Pick next task)**：选择下一个未通过的任务。
- **IMPL (AI Agent)**：AI 代理，执行任务。
- **CHECK (Quality Checks?)**：质量检查，判断任务是否成功。
- **COMMIT (Git Commit)**：提交 Git 变更。
- **FIX (Fix & Retry)**：修复任务并重试。
- **UPDATE (Update prd.json)**：更新 `prd.json` 文件，标记已通过的任务。
- **DONE (All tasks done?)**：判断所有任务是否完成。
- **EXIT (Exit loop)**：退出执行循环。
- **PUSH (Git Push)**：推送 Git 变更。
- **PR (🎉 Pull Request)**：生成 Pull Request，等待审查。

## 连线、分支与汇聚关系
- `GEN -> R`：生成每日报告。
- `R -> A`：分析每日报告。
- `A -> J`：生成分析结果。
- `J -> B`：基于分析结果创建分支。
- `B -> PRD`：AI 代理加载 `prd` skill 生成产品需求文档。
- `PRD -> MD`：生成产品需求文档。
- `MD -> TASKS`：AI 代理加载 `tasks` skill 将产品需求文档转化为可执行的任务列表。
- `TASKS -> JSON`：生成可执行的任务列表。
- `JSON -> LOOP`：执行循环脚本。
- `LOOP -> PICK`：选择下一个未通过的任务。
- `PICK -> IMPL`：AI 代理执行任务。
- `IMPL -> CHECK`：进行质量检查。
- `CHECK -- Pass --> COMMIT`：如果质量检查通过，则提交 Git 变更。
- `CHECK -- Fail --> FIX`：如果质量检查失败，则修复任务并重试。
- `FIX -> CHECK`：修复后重新进行质量检查。
- `COMMIT -> UPDATE`：更新 `prd.json` 文件，标记已通过的任务。
- `UPDATE -> DONE`：判断所有任务是否完成。
- `DONE -- No --> PICK`：如果还有未完成的任务，则返回选择下一个任务。
- `DONE -- Yes --> EXIT`：如果所有任务都已完成，则退出执行循环。
- `EXIT -> PUSH`：推送 Git 变更。
- `PUSH -> PR`：生成 Pull Request。

## 仓库语境与术语解释
- **Compound Product**：一个自改进的产品系统，能够读取每日报告，识别最高优先级的可执行任务，并自动执行这些任务。
- **analyze-report.sh**：一个用于分析报告并选择最高优先级可执行任务的脚本。根据 `scripts/analyze-report.sh`，它支持多种 LLM 提供商，包括 Anthropic、OpenRouter 和 AI Gateway。
- **loop.sh**：一个执行循环的脚本，用于重复运行 AI 代理直到完成 `prd.json` 中的所有任务。根据 `scripts/loop.sh`，它使用 `amp` 或 `claude` 工具来执行任务。
- **prd.json**：一个包含可执行任务列表的 JSON 文件，由 `tasks` skill 生成。
- **prd skill**：一个用于生成产品需求文档的 AI 技能。根据 `skills/prd/SKILL.md`，它会根据给定的功能描述生成详细的 PRD。
- **tasks skill**：一个用于将 PRD markdown 文件转换为 `prd.json` 格式的 AI 技能。根据 `skills/tasks/SKILL.md`，它会将每个任务分解为细粒度的、机器可验证的子任务。
- **Quality Checks**：在执行循环中用于验证任务是否成功的检查。根据 README，这些检查是可配置的，可以在 `config.json` 文件中设置。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 `Compound Product` 的自动化改进流程。从生成每日报告开始，通过 `analyze-report.sh` 脚本使用 LLM API 分析报告，确定优先级和标准，然后创建 Git 分支，并由 AI 代理加载 `prd` 和 `tasks` skill 生成产品需求文档和可执行的任务列表。接着进入执行循环，选择下一个未通过的任务，由 AI 代理执行，进行质量检查，如果通过则提交 Git 变更，否则修复并重试，直到所有任务完成。最后推送 Git 变更并生成 Pull Request。`scripts/analyze-report.sh` 和 `scripts/loop.sh` 是该流程中的两个关键脚本，分别负责报告分析和任务执行。
