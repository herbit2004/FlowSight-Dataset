## Diagram Type & Purpose

The diagram serves as a visual representation of the upload process, aiding in understanding the system's architecture and data flow.

## Edges, Branches & Convergence
- `A --> B`: Client application initiates an upload request.
- `B -- Valid Token & Size < Limit --> C`: The upload request proceeds to the API Gateway if the token is valid and the size is within the limit.
- `B -- Invalid Token OR Size >= Limit --> Z`: An error response is sent to the client if the token is invalid or the size exceeds the limit.
- `C --> D`: The API Gateway forwards the request to the Authentication Service.
- `D -- Token Valid --> E`: The request is routed to the Request Router if the token is valid.
- `D -- Token Invalid --> Z`: An error response is sent to the client if the token is invalid.
- `E --> F`: The Request Router forwards the request to the Content Type Check.
- `F -- Accepted Type --> G`: The process continues to the Pre-Signed URL Generator if the content type is accepted.
- `F -- Rejected Type --> Z`: An error response is sent to the client if the content type is rejected.
- `G --> H`: The Pre-Signed URL Generator returns the pre-signed URL to the client.
- `H --> I`: The client uploads the object to object storage using the pre-signed URL.
- `I --> J`: The object storage service stores the uploaded object.
- `J --> K`: An event is added to the event queue when an object is uploaded.
- `K --> L`: The Metadata Service updates the metadata of the uploaded object.
- `L --> M`: The Cache Invalidator invalidates the CDN cache.
- `M --> N`: The Indexer updates the search index.

## Repository Context & Terminology
- **API Gateway**: A service that acts as a single entry point for client requests, handling authentication, authorization, and rate limiting.
- **Authentication Service**: A service responsible for verifying the identity of the client making the request.
- **Pre-Signed URL**: A URL that grants temporary access to a specific object in object storage, allowing clients to upload or download the object without requiring further authentication.
- **Object Storage**: A service for storing unstructured data, such as images, videos, and documents.
- **Event Queue**: A message queue used to decouple services and enable asynchronous communication.
- **Metadata Service**: A service responsible for managing metadata associated with objects stored in object storage.
- **Cache Invalidator**: A service responsible for invalidating cached content in a CDN (Content Delivery Network).
- **Indexer**: A service responsible for indexing data for search and retrieval.
- **CDN (Content Delivery Network)**: A distributed network of servers that caches content closer to users, improving performance and reducing latency.

## High-Density QA Ground Truth Summary
The upload process begins with a "Client Application" initiating an "Upload Request." This request is first intercepted by the "API Gateway," which performs initial validation, checking if the "Token Valid & Size < Limit." If either the token is invalid or the size exceeds the limit ("Invalid Token OR Size >= Limit"), an "Error Response to Client" is immediately triggered, terminating the successful flow. If the initial validation passes, the request proceeds to the "Authentication Service: Verify Token." A valid token ("Token Valid") leads to the "Request Router," while an invalid token ("Token Invalid") also results in an "Error Response to Client." The "Request Router" then directs the flow to "Content Type Check." If the content type is "Rejected Type," an error is returned; otherwise, if "Accepted Type," a "Pre-Signed URL Generator" creates a pre-signed URL. This URL is then returned to the client ("Return Pre-Signed URL to Client"), who uses it to upload the object to "Object Storage: Store Object." Upon successful storage, an "Event Queue: Object Uploaded" is triggered, leading to the "Metadata Service: Update Metadata," then the "Cache Invalidator: Invalidate CDN Cache," and finally, the "Indexer: Update Search Index," completing the upload workflow. The use of a pre-signed URL allows the client to directly upload to object storage without further server-side handling, improving scalability.
