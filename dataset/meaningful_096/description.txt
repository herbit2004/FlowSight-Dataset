## 图类型与用途
该图是一个流程图，描述了用户注册和登录的流程。它展示了用户如何通过不同的身份验证方式（手机验证码、邮箱验证、密码登录）进行身份验证，并最终生成会话令牌，重定向至主页。该图旨在清晰地呈现用户认证的各种路径和逻辑。

## 图的整体布局
该图采用从上到下的布局。流程从用户请求注册/登录页面开始，经过身份验证方式选择，最终到达用户重定向至主页。整体流程呈现出清晰的层次结构。

## 分组/子图/阶段说明
图中有一个名为“用户注册与登录”的子图，包含了整个用户注册和登录的流程。

## 节点逐项说明
- **A[用户请求: 注册/登录页面]**: 用户发起注册或登录请求的入口页面。
- **B{身份验证方式选择}**: 用户选择身份验证方式的决策点。
- **C[发送验证码至手机]**: 向用户手机发送验证码。
- **D[发送验证邮件]**: 向用户邮箱发送验证邮件。
- **E[密码验证]**: 验证用户输入的密码。
- **F[验证码校验]**: 校验用户输入的手机验证码是否正确。
- **G[邮箱Token校验]**: 校验邮箱中的Token是否有效。
- **H[数据库查找用户]**: 在数据库中查找用户信息。
- **I{验证码正确？}**: 判断验证码是否正确的决策点。
- **J{Token有效？}**: 判断Token是否有效的决策点。
- **K{用户存在？密码正确？}**: 判断用户是否存在且密码是否正确的决策点。
- **L[生成会话令牌]**: 生成用于跟踪用户会话的令牌。
- **N[写入Redis会话]**: 将会话信息写入Redis缓存。
- **O[返回会话令牌]**: 将会话令牌返回给用户。
- **P[用户重定向至主页]**: 将用户重定向到主页。
- **M[返回错误信息]**: 返回错误信息给用户。

## 连线、分支与汇聚关系
- A -> B：用户请求注册/登录页面，进入身份验证方式选择。
- B -- 手机验证码 --> C：选择手机验证码方式，发送验证码至手机。
- B -- 邮箱验证 --> D：选择邮箱验证方式，发送验证邮件。
- B -- 密码登录 --> E：选择密码登录方式，进行密码验证。
- C -> F：发送验证码至手机后，进行验证码校验。
- D -> G：发送验证邮件后，进行邮箱Token校验。
- E -> H：密码验证后，在数据库中查找用户。
- F -> I：验证码校验后，判断验证码是否正确。
- G -> J：邮箱Token校验后，判断Token是否有效。
- H -> K：数据库查找用户后，判断用户是否存在且密码是否正确。
- I -- 是 --> L：验证码正确，生成会话令牌。
- I -- 否 --> M：验证码错误，返回错误信息。
- J -- 是 --> L：Token有效，生成会话令牌。
- J -- 否 --> M：Token无效，返回错误信息。
- K -- 是 --> L：用户存在且密码正确，生成会话令牌。
- K -- 否 --> M：用户不存在或密码错误，返回错误信息。
- L -> N：生成会话令牌后，写入Redis会话。
- N -> O：写入Redis会话后，返回会话令牌。
- O -> P：返回会话令牌后，用户重定向至主页。
- M -> P：返回错误信息后，用户重定向至主页（可能重新尝试登录）。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **会话令牌**: 用于跟踪用户会话的唯一标识符。
- **Redis**: 一种内存数据存储，用于缓存会话信息。
- **Token**: 在邮箱验证中，用于验证用户邮箱所有权的字符串。
- **身份验证**: 验证用户身份的过程。
- **验证码**: 发送到用户手机或邮箱的一次性密码，用于验证用户身份。
- **数据库**: 存储用户信息的地方。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起注册/登录请求，选择身份验证方式（手机验证码、邮箱验证或密码登录）。若选择手机验证码，则发送验证码至手机，校验验证码是否正确；若选择邮箱验证，则发送验证邮件，校验Token是否有效；若选择密码登录，则在数据库中查找用户，验证用户是否存在且密码是否正确。若验证通过，则生成会话令牌，写入Redis会话，返回会话令牌，最终用户重定向至主页；否则，返回错误信息，用户重定向至主页（重新尝试）。
