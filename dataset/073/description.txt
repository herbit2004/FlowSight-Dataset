## 图类型与用途
这是一个流程图，描述了 Archive Agent 的文件摄取（Ingestion）和查询（Query）两个主要流程。它展示了如何将文件内容转化为向量嵌入并存储到数据库中，以及如何根据用户问题检索相关信息并生成答案。

## 图的整体布局
图采用从左到右的布局，分为上下两个子图，分别代表 Ingestion 和 Query 流程。Ingestion 流程从左上角开始，Query 流程从右上角开始，两个流程通过共享的 Qdrant 数据库连接。

## 分组/子图/阶段说明
- **Ingestion**：文件摄取流程，包括跟踪和提交文件、摄取文件、语义分块、嵌入块和存储块等步骤。
- **Query**：查询流程，包括用户提问、嵌入问题、检索最接近的块、重新排序、扩展上下文和生成答案等步骤。

## 节点逐项说明
- **Track and Commit Files**：跟踪文件变化并提交，支持不同的配置文件。
- **Ingest Files**：摄取文件，包括自动 OCR 策略和图像实体提取。
- **Semantic Chunking**：将文件分割成语义相关的块，并添加上下文头部信息。参数包括每块的行数（100）和每块的单词数（200）。
- **Embed Chunks**：使用 `text-embedding-3-large` 模型将每个块转换为向量嵌入，向量维度为 3072。
- **Store Chunks**：将向量嵌入存储在本地的 Qdrant 数据库中。
- **Ask Question**：用户提出问题。
- **Embed Question**：使用 `text-embedding-3-large` 模型将问题转换为向量嵌入。
- **Retrieve Nearest Chunks**：根据问题嵌入，从 Qdrant 数据库中检索最相关的块。参数包括最小分数（0.1）和最大块数（30）。
- **Rerank by Relevance**：对检索到的块进行重新排序，选择最相关的块。参数为最大块数（8）。
- **Expand Context**：扩展所选块的上下文，包括周围的块。参数为块半径（1）。
- **Generate Answer**：根据检索到的块和扩展的上下文，生成答案。
- **Get Answer**：通过命令行界面（CLI）、图形用户界面（GUI）或 MCP 接口将答案呈现给用户。

## 连线、分支与汇聚关系
- `A -> B`：跟踪并提交文件后，进行文件摄取。
- `B -> C`：文件摄取后，进行语义分块。
- `C -> D`：语义分块后，进行嵌入块。
- `D -> E`：嵌入块后，存储块到 Qdrant 数据库。
- `F -> G`：用户提问后，嵌入问题。
- `G -> H`：嵌入问题后，检索最接近的块。
- `E -> H`：Qdrant 数据库中的存储块数据被用于检索最接近的块，形成汇聚关系。
- `H -> I`：检索最接近的块后，按相关性重新排序。
- `I -> J`：按相关性重新排序后，扩展上下文。
- `J -> K`：扩展上下文后，生成答案。
- `K -> L`：生成答案后，获取答案。

## 仓库语境与术语解释
- **RAG (Retrieval Augmented Generation)**：一种将预先准备好的信息片段与查询相匹配的方法，用于增强生成答案的质量。
- **OCR (Optical Character Recognition)**：光学字符识别，用于将图像中的文字转换为机器可读的文本。
- **Qdrant**：一个向量数据库，用于存储和检索向量嵌入。在 `archive_agent/db/QdrantManager.py` 中定义了 Qdrant 的相关操作。
- **MCP (Model Context Protocol)**：一种用于集成 AI 模型的工作流协议。
- **text-embedding-3-large**：用于将文本转换为向量嵌入的模型。
- **Semantic Chunking**：根据语义将文件分割成块，在 `archive_agent/ai/chunk/AiChunk.py` 中定义了 chunk 的相关逻辑。
- **Profile**：在“Track and Commit Files”节点中提到，指的是不同的配置文件，用于控制文件跟踪和提交的行为。

## 可作为 QA Ground Truth 的高信息密度摘要
Archive Agent 的流程图展示了文件摄取和查询两个主要流程。文件摄取流程从跟踪和提交文件开始，经过文件摄取、语义分块和嵌入，最终将向量嵌入存储到 Qdrant 数据库。查询流程从用户提问开始，经过问题嵌入、检索最接近的块、重新排序和扩展上下文，最终生成答案并通过 CLI、GUI 或 MCP 接口呈现给用户。Qdrant 数据库是两个流程的关键连接点，其中 `text-embedding-3-large` 模型被用于嵌入块和问题。
