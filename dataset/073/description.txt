## Diagram Type & Purpose
This is a flowchart diagram illustrating the data flow and processing steps in a question-answering system. It depicts two main pipelines: an ingestion pipeline for processing and storing data, and a query pipeline for retrieving and generating answers based on user questions. The diagram serves as a high-level architecture overview, outlining the key components and their interactions within the system.

## Overall Layout
The diagram is laid out from left to right (LR). It consists of two main subgraphs: "Ingestion" and "Query". The "Ingestion" subgraph represents the data preparation process, starting with tracking files and ending with storing chunks in a database. The "Query" subgraph represents the question answering process, starting with asking a question and ending with getting an answer.

## Subgraphs / Stages
The diagram contains two explicit subgraphs:
- **Ingestion**: This subgraph describes the process of ingesting data, chunking it semantically, embedding the chunks, and storing them in a local Qdrant database.
- **Query**: This subgraph describes the process of taking a user question, embedding it, retrieving relevant chunks from the database, re-ranking them, expanding the context, generating an answer, and providing the answer to the user.

## Repository Context & Terminology
- **OCR (Optical Character Recognition)**: A technology that converts scanned or photographed images of text into machine-readable text.
- **Image Entity Extraction**: The process of identifying and extracting entities (e.g., people, organizations, locations) from images.
- **Semantic Chunking**: Dividing text into meaningful segments based on semantic content, often using context headers to maintain coherence.
- **text-embedding-3-large**: A specific text embedding model used to convert text into numerical vectors.
- **Qdrant**: A vector database used for storing and retrieving high-dimensional vectors, suitable for similarity search.
- **CLI (Command Line Interface)**: A text-based interface for interacting with a computer system.
- **GUI (Graphical User Interface)**: A visual interface for interacting with a computer system.
- **MCP**: visible in diagram; no further repository context available.

## High-Density QA Ground Truth Summary
The flowchart begins with the "Ingestion" subgraph, where the system "Tracks and Commits Files," supporting profiles, and then "Ingests Files" using an automatic OCR strategy and image entity extraction. The ingested files undergo "Semantic Chunking" with context headers, configured for 100 lines per block and 200 words per chunk. These chunks are then embedded using the "text-embedding-3-large" model, resulting in vectors of size 3072, and subsequently stored in a local Qdrant database. The "Query" subgraph starts with the user "Asking a Question," which is then embedded using the same "text-embedding-3-large" model. The system "Retrieves Nearest Chunks" from the Qdrant database, based on a minimum score of 0.1 and a maximum of 30 chunks. The retrieved chunks are then "Reranked by Relevance," limited to a maximum of 8 chunks, and the context is "Expanded" with a radius of 1 chunk. Finally, the system "Generates Answer" based on the expanded context and presents the "Get Answer" in CLI, GUI, or MCP. The Qdrant database serves as a central repository for the embedded chunks, enabling efficient similarity search during the question answering process.
