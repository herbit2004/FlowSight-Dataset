## Diagram Type & Purpose
This is an architecture diagram illustrating the high-level components and data flow within an agent orchestration system. It depicts the interaction between the frontend, API gateway, agent orchestration layer, tool ecosystem, storage layer, and external services. The diagram serves as a visual representation of the system's architecture, aiding in understanding the relationships and dependencies between different components.

## Overall Layout
The diagram has a top-to-bottom (TB) layout. It is hierarchically structured, with the Frontend at the top, followed by the API Gateway, Agent Orchestration, Tool Ecosystem, Storage Layer, and External Services at the bottom. The flow starts from the Frontend and progresses through the layers to the Storage Layer and External Services.

The diagram contains explicit subgraphs representing different layers of the system:
- **Frontend**: Represents the user interface layer.
- **API Gateway**: Handles API requests and manages authentication, CORS, and rate limiting.
- **Agent 编排层 Agent Orchestration**: Orchestrates the agent's behavior and routes requests to appropriate tools.

## Repository Context & Terminology
- **Next.js**: A React framework for building web applications.
- **FastAPI**: A modern, high-performance web framework for building APIs with Python.
- **CORS**: Cross-Origin Resource Sharing, a mechanism that allows restricted resources on a web page to be requested from another domain outside the domain from which the first resource was served.
- **LLM**: Large Language Model, a type of artificial intelligence model that can generate human-like text.
- **ASR**: Automatic Speech Recognition, the process of converting spoken language into text.
- **TTS**: Text-to-Speech, the process of converting text into spoken language.
- **E2B**: Likely refers to a sandboxing environment or service, possibly "Ephemeral Environments for Browser".
- **Playwright**: A Node.js library to automate Chromium, Firefox and WebKit with a single API.
- **Chrome DevTools**: A set of web developer tools built directly into the Google Chrome browser.

## High-Density QA Ground Truth Summary
The system architecture begins with the Next.js Web UI, which represents the frontend. The frontend communicates with the backend via the FastAPI Server, which acts as the API Gateway. The API Gateway handles authentication via the 认证中间件, CORS via the CORS 处理 component, and rate limiting via the 限流控制 component. The FastAPI Server then routes requests to the 智能路由器, which intelligently directs traffic based on the query type. The router can direct to 直接回答 for simple queries, 网页搜索 for web-based queries utilizing the Tavily 搜索 API, 工具调用 for agent-based queries, or 深度研究 for complex queries, also potentially using the Tavily 搜索 API. The 工具调用 node interacts with the 工具注册表 to discover and invoke various tools, including E2B 沙箱工具, 浏览器自动化 (using Playwright and Chrome DevTools), 桌面自动化, 搜索与爬虫, and MCP 工具桥. The E2B 沙箱工具 can perform 代码执行, 文件操作, and 文档生成. The API Gateway stores session data in PostgreSQL 会话存储 and uses Redis 缓存 for caching. The 工具调用 node utilizes Memo 长期记忆 for long-term memory. Browser automation stores screenshots and logs in 文件存储. The system leverages external services such as LLM 服务 (OpenAI/DeepSeek/Claude), Tavily 搜索 API, E2B 沙箱服务, and DashScope ASR/TTS. The architecture terminates with data being stored in the 存储层 Storage Layer, or by invoking external services.
