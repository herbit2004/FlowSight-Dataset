## 图类型与用途
该图是一个流程图，描述了支付流程、登录流程、数据同步流程和 API 调用流程。它展示了不同服务之间的交互以及可能的决策分支。

## 图的整体布局
该图从上到下布局，包含四个主要流程，支付流程位于主流程，登录流程、数据同步流程和 API 调用流程以子图形式存在。主流程从用户请求开始，最终返回订单成功或不足。

## 分组/子图/阶段说明
图中包含以下子图：
- **登录流程**：描述用户注册到生成Token或返回登录失败的流程。
- **数据同步**：描述数据库变更后通知缓存服务并进行数据同步的流程。
- **API 调用**：描述内部服务调用外部API并进行重试的流程。

## 连线、分支与汇聚关系
- A -> B：用户请求到达支付网关。
- B -- 支付成功 --> C：支付成功后进入风控系统。
- B -- 支付失败 --> D：支付失败后返回支付失败。
- C -- Yes --> E：风控系统判断为Yes，进入消息队列。
- C -- No --> F：风控系统判断为No，记录可疑交易。
- E -> G：消息队列到达订单服务。
- G -> H：订单服务进行写缓存操作。
- H -- Yes --> I：写缓存判断为Yes，进入数据库。
- H -- No --> J：写缓存判断为No，调用库存服务。
- I -> K：数据库操作后返回订单成功。
- J -> L：调用库存服务后进行扣减库存操作。
- L -- 库存足够 --> M：库存足够，返回库存成功。
- L -- 库存不足 --> N：库存不足，返回库存不足。
- M -> O：返回库存成功后，更新数据库库存。
- O -> H：更新数据库库存后，回到写缓存。
- P -> Q：用户注册到达认证服务。
- Q -> R：认证服务到达鉴权服务。
- R -- Yes --> S：鉴权服务判断为Yes，生成Token。
- R -- No --> T：鉴权服务判断为No，返回未授权。
- S -> Q：生成Token后，回到认证服务。
- T -> U：返回未授权后，返回登录失败。
- V -> W：数据库变更后，通知缓存服务。
- W -> X：通知缓存服务后，进行读缓存操作。
- X -- Yes --> Y：读缓存判断为Yes，更新数据库。
- X -- No --> Z：读缓存判断为No，删除缓存。
- Z -> AA：删除缓存后，返回同步成功。
- AB -> AC：内部服务 A 调用外部 API。
- AC -> AD：外部 API 调用后，进入重试机制。
- AD -- Yes --> AE：重试机制判断为Yes，返回 API 成功。
- AD -- No --> AF：重试机制判断为No，返回 API 失败。
- AE -> AB：返回 API 成功后，回到内部服务 A。

## 仓库语境与术语解释
- **支付网关**：处理支付请求的服务。
- **风控系统**：用于检测和预防欺诈交易的系统。
- **消息队列**：用于异步传递消息的组件。
- **订单服务**：处理订单相关业务的服务。
- **写缓存**：将数据写入缓存的操作。
- **数据库**：用于存储数据的系统。
- **库存服务**：管理库存的服务。
- **鉴权服务**：验证用户权限的服务。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求到达支付网关，支付成功后进入风控系统，根据风控结果进入消息队列或记录可疑交易。消息队列将请求传递给订单服务，订单服务进行写缓存操作，如果缓存未命中则调用库存服务进行扣减库存，根据库存是否足够返回库存成功或不足，库存足够则更新数据库库存，最终返回订单成功或不足。同时，存在登录流程、数据同步流程和 API 调用流程。
