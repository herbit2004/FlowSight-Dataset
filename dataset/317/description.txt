## 图类型与用途
这是一个流程图，描述了 AI Agent、Files、Gaze 和 Results 之间的循环关系，展示了 AI Agent 如何编辑文件，Gaze 如何监视文件变化并输出结果，以及 AI Agent 如何读取结果并继续循环。该图在仓库中用于说明 Gaze 如何与 AI Agent 协同工作，实现自动化开发流程。

## 图的整体布局
图采用从上到下的布局，节点之间形成一个循环。AI Agent 作为起点，通过编辑文件触发 Gaze 的监视，Gaze 输出结果后又反馈给 AI Agent。

## 分组/子图/阶段说明
图中包含一个名为 "cycle" 的 subgraph，表示整个流程是一个循环。

## 节点逐项说明
- **🤖 AI Agent**：表示 AI 代理，负责编辑文件。README 上下文表明，它可以是 Claude Code 这样的 AI 编码助手。
- **📁 Files**：表示被 AI Agent 编辑的文件。
- **👁️ Gaze**：表示 Gaze 工具，负责监视文件变化。
- **📊 Results\nTests • Lint • Output**：表示 Gaze 输出的结果，包括测试结果、代码检查结果和程序输出。

## 连线、分支与汇聚关系
- `A -> B`：AI Agent 编辑 Files。
- `B -> C`：Gaze 监视 Files 的变化。
- `C -> D`：Gaze 输出 Results。
- `D -> A`：AI Agent 读取 Results，形成循环关系。

## 仓库语境与术语解释
- **AI Agent**：指能够自动编辑代码文件的 AI 代理，例如 README 中提到的 Claude Code。
- **Gaze**：是一个文件监视工具，当文件发生变化时，可以自动运行预定义的命令。
- **Files**：指被 Gaze 监视的文件，可以是源代码文件、配置文件或数据文件。
- **Results**：指 Gaze 运行命令后产生的输出，例如测试结果、代码检查报告或程序运行结果。
- **Test-driven development**：一种开发模式，AI 编写代码的同时自动运行测试。
- **Build automation**：一种自动化流程，AI 修改源代码后自动构建项目。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 AI Agent、Files、Gaze 和 Results 之间的循环关系。AI Agent 编辑 Files，Gaze 监视 Files 的变化并输出 Results，AI Agent 读取 Results 并继续编辑 Files，形成一个闭环。这个流程体现了 Gaze 如何与 AI Agent 协同工作，实现自动化测试、构建和部署。Gaze 监视文件变化并自动运行命令是核心环节。
