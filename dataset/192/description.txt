## 图类型与用途
这是一个流程图，描述了 Agent Control Plane (ACP) 中 Agent 如何处理用户请求，并利用 LLM 和工具完成任务，最终生成 Assistant Message。该图旨在展示 Agent 与 LLM 提供商的交互，以及如何处理工具调用和响应。

## 图的整体布局
图整体采用从上到下的布局。顶部是 Task 下的 ContextWindow，包含 SystemMessage 和 UserMessage，底部是最终的 AssistantMessage。图中还包括 LLM 和 MCPServer 两个子图，分别表示 LLM 提供商和 MCP 服务器。

## 分组/子图/阶段说明
- **Task**：代表一个任务，包含上下文窗口和 Agent。
- **ContextWindow**：代表 LLM 的上下文窗口，包含一系列消息，包括 SystemMessage、UserMessage、ToolCall 和 ToolResponse。
- **LLM**：代表使用的 LLM，例如 OpenAI，包含 Provider 和 Credentials。
- **MCPServer**：代表 MCP (Management Control Plane) 服务器，负责工具的获取，包含 fetch 操作。

## 节点逐项说明
- **SystemMessage**：系统消息，用于指导 LLM 的行为。
- **UserMessage**：用户输入的消息。
- **Agent**：代表 ACP 中的 Agent，负责处理用户输入、调用 LLM 和处理工具调用。
- **LLM**：代表使用的 LLM，例如 OpenAI。
- **Provider**：LLM 的提供商，例如 OpenAI。
- **Secret**：存储敏感信息，例如 API 密钥。
- **Credentials**：用于访问 LLM 提供商的凭据。
- **OpenAI**：具体的 LLM 服务，例如 OpenAI 的 API。
- **ToolCall-1**：LLM 生成的工具调用请求，标签为 assistant:tool_calls。
- **Agent2**：可能是指同一个Agent，或者另一个Agent实例，用于处理工具调用后的结果。
- **MCPServer**：代表 MCP (Management Control Plane) 服务器，负责工具的获取。
- **fetch**：从 MCP 服务器获取工具信息的操作。
- **ToolResponse-1**：工具调用返回的结果，标签为 tool:result。
- **OpenAI2**：图中可见，但仓库上下文未进一步说明。
- **AssistantMessage**：LLM 生成的最终回复，标签为 assistant:content。

## 连线、分支与汇聚关系
- `SystemMessage -> UserMessage`：系统消息和用户消息按顺序进入上下文窗口。
- `UserMessage -> Agent -> LLM`：用户消息被 Agent 处理，然后传递给 LLM。
- `Provider -> OpenAI`：提供商信息指向具体的 LLM 服务。
- `Secret -> Credentials`：密钥用于获取凭据。
- `Credentials -> OpenAI`：凭据用于访问 OpenAI。
- `OpenAI -> ToolCall-1`：LLM 根据上下文生成工具调用请求。
- `ToolCall-1 -> Agent2 -> fetch`：Agent2 接收到工具调用请求，然后从 MCPServer 获取工具信息。
- `fetch -> ToolResponse-1`：MCPServer 返回工具调用的结果。
- `ToolResponse-1 -> OpenAI2 -> AssistantMessage`：工具调用的结果被传递给 LLM，LLM 生成最终的回复（AssistantMessage）。

## 仓库语境与术语解释
- **ACP (Agent Control Plane)**：一个云原生的 AI Agent 编排器，构建于 Kubernetes 之上。
- **LLM (Large Language Model)**：大型语言模型，例如 OpenAI 的 GPT-4。在 `acp/api/v1alpha1/llm_types.go` 中定义了 LLM 的配置，包括 Model、BaseURL、Temperature 等参数。
- **Agent**：ACP 中的核心组件，负责处理用户输入、调用 LLM 和处理工具调用。`acp/api/v1alpha1/agent_types.go` 中定义了 Agent 的 Spec，包括 LLMRef、MCPServers、System 等字段。
- **MCP (Management Control Plane) Server**：负责提供工具信息的服务器。`acp/api/v1alpha1/mcpserver_types.go` 中定义了 MCPServer 的 Spec，包括 Transport、Command、URL 等字段。
- **Task**：代表一个任务，包含 Agent、UserMessage 和 ContextWindow。`acp/api/v1alpha1/task_types.go` 中定义了 Task 的 Spec，包括 AgentRef、UserMessage、ContextWindow 等字段。
- **ContextWindow**：LLM 的上下文窗口，包含一系列消息，用于提供对话历史。
- **ToolCall**：LLM 生成的工具调用请求。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 Agent Control Plane 中 Agent 如何处理用户请求并利用 LLM 和工具完成任务的流程。流程从 SystemMessage 和 UserMessage 进入 ContextWindow 开始，Agent 处理 UserMessage 并传递给 LLM。LLM 根据上下文生成 ToolCall，Agent 从 MCPServer 获取工具信息并执行调用，ToolResponse 返回给 LLM，最终生成 AssistantMessage。其中，LLM、Agent、MCP Server 和 Task 是 ACP 的核心对象，ContextWindow 用于维护对话历史，ToolCall 用于请求外部工具。
