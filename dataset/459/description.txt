## Edges, Branches & Convergence
- `Start --> Init`: The Docker container starts and proceeds to the initialization stage.
- `Check -- Yes --> Mount`: If a configuration file exists at `/etc/tor/torrc`, the mounted configuration is used.
- `Check -- No --> Env`: If no configuration file is found, the process checks for environment variables.
- `Env -- Yes --> Generate`: If environment variables are set, a Tor configuration file is automatically generated.
- `Env -- No --> Error`: If environment variables are missing, an error occurs, and the container exits.
- `Mount --> Validate`: After using the mounted config, the configuration is validated.
- `Generate --> Validate`: After auto-generating the config, the configuration is validated.
- `Validate -- Yes --> ModeSelect`: If the configuration is valid, the process proceeds to relay mode selection.
- `Validate -- No --> Error`: If the configuration is invalid, an error occurs, and the container exits.
- `ModeSelect --> Guard`: If the Guard/Middle relay mode is selected, the process configures a Guard/Middle relay.
- `ModeSelect --> Exit`: If the Exit relay mode is selected, the process configures an Exit relay.
- `ModeSelect --> Bridge`: If the Bridge relay mode is selected, the process configures a Bridge relay.
- `Guard --> Running`: After configuring the Guard/Middle relay, the Tor relay starts running.
- `Exit --> Running`: After configuring the Exit relay, the Tor relay starts running.
- `Bridge --> Running`: After configuring the Bridge relay, the Tor relay starts running.
- `Running --> Ops`: Once the Tor relay is running, diagnostic operations are available.
- `Running --> Shutdown`: When the `docker stop SIGTERM` command is issued, the Tor relay initiates a graceful shutdown.
- `Shutdown --> End2`: After a graceful shutdown, the container stops cleanly.
- `Error --> End`: If an error occurs, the container exits.

## Repository Context & Terminology
- **/etc/tor/torrc**: The default location for the Tor configuration file.
- **NICKNAME**: An environment variable used to set the nickname of the Tor relay.
- **CONTACT_INFO**: An environment variable used to set the contact information for the Tor relay.
- **tor --verify-config**: A Tor command used to validate the configuration file.
- **obfs4**: A pluggable transport used to obfuscate Tor traffic, making it more resistant to censorship.
- **BridgeRelay**: A type of Tor relay that helps users bypass censorship.
- **ExitRelay**: A type of Tor relay that allows users to exit the Tor network and access the internet.
- **Guard/Middle Relay**: Tor relays that serve as entry points (Guards) or intermediate nodes (Middles) in the Tor network.
- **docker exec**: A Docker command used to run commands inside a running container.
- **SIGTERM**: A signal sent to a process to request its termination.

## High-Density QA Ground Truth Summary
The Tor relay Docker container starts with the `docker run` command, initiating the INITIALIZATION phase. The process first checks for a configuration file at `/etc/tor/torrc`. If found, the mounted configuration is used, providing full Tor control; otherwise, the process checks for environment variables like NICKNAME and CONTACT_INFO. If these are set, a `torrc` file is auto-generated; if not, the container exits with an error. After either using a mounted config or auto-generating one, the configuration is validated using `tor --verify-config`. An invalid configuration also leads to container exit. A valid configuration proceeds to RELAY MODE SELECTION, where the user chooses between Guard/Middle, Exit, or Bridge relay modes. Depending on the selection, the corresponding relay configuration is applied, and the Tor relay starts running. Diagnostic OPERATIONS are then available via `docker exec`. Finally, upon receiving a `docker stop SIGTERM` signal, the relay initiates a GRACEFUL SHUTDOWN, closing circuits, notifying directory authorities, and saving state before exiting cleanly. The `tor --verify-config` command ensures the Tor configuration is valid before the relay starts running, preventing errors and ensuring proper functionality.
