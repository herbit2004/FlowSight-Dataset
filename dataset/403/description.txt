## 图类型与用途
这是一个流程图，描述了代码从最初的最小实现草案，经过 AI 审查循环，最终达到发布准备完成状态的过程。该图在仓库中用于展示 AI 辅助的代码开发与质量保证流程，特别是 AI 代码审查的循环过程。

## 图的整体布局
图整体采用从上到下的布局。顶部是代码开发的起点“最小実装ドラフト”，经过 AI 审查和人工验证，最终到达底部的“リリース準備完了”状态。流程中包含一个循环审查的环节。

## 分组/子图/阶段说明
图中包含一个名为 "AIレビューサイクル詳細" 的子图，用于展示 AI 审查循环的详细过程。主流程和子图共同构成代码质量保证的各个阶段。

## 节点逐项说明
- **A (最小実装ドラフト)**：代码开发的起点，表示一个最小可运行的代码草案。
- **B (AIレビューサイクル)**：AI 审查循环，表示使用 AI 工具对代码进行审查的过程。
- **C (品質基準達成?)**：质量标准达成？这是一个决策节点，判断代码是否达到了预定的质量标准。
- **D (人間最終検証)**：人工最终验证，表示在 AI 审查通过后，由人工进行最终的验证。
- **E (リリース準備完了)**：发布准备完成，表示代码已经通过所有验证，可以准备发布。
- **F (🔴 セキュリティ HIGH)**：安全性（高），表示 AI 审查中对安全性方面的高优先级审查。对应 README 中 "Claude 4レビュー品質基準" 的 "🔴 HIGH セキュリティ" 部分。
- **G (🟡 アーキテクチャ MEDIUM)**：架构（中），表示 AI 审查中对架构方面的中等优先级审查。对应 README 中 "Claude 4レビュー品質基準" 的 "🟡 MEDIUM アーキテクチャ" 部分。
- **H (🟢 パフォーマンス LOW)**：性能（低），表示 AI 审查中对性能方面的低优先级审查。对应 README 中 "Claude 4レビュー品質基準" 的 "🟢 LOW パフォーマンス" 部分。
- **I (400文字要約)**：400字摘要，表示 AI 审查后生成一个 400 字的审查总结。

## 连线、分支与汇聚关系
- `A -> B`：从最小实现草案开始，代码进入 AI 审查循环。
- `B -> C`：AI 审查结束后，判断代码是否达到质量标准。
- `C -- No 3-4回まで --> B`：如果未达到质量标准，流程返回 AI 审查循环，进行最多 3-4 次的循环审查。
- `C -- Yes --> D`：如果达到质量标准，流程进入人工最终验证。
- `D -> E`：通过人工验证后，代码进入发布准备完成状态。
- `B -.-> F`：AI 审查循环会触发子图中的详细审查流程。

## 仓库语境与术语解释
- **AIレビューサイクル (AI Review Cycle)**：指使用 Claude Code 等 AI 工具对代码进行审查的流程，旨在提高代码质量和安全性。
- **品質基準 (Quality Standards)**：指代码需要达到的质量标准，包括安全性、架构和性能等方面。这些标准在 README 的 "Claude 4レビュー品質基準" 中有详细定义。
- **人間最終検証 (Human Final Verification)**：指在 AI 审查通过后，由人工进行的最终验证，确保代码质量。
- **リリース準備完了 (Release Ready)**：指代码已经通过所有验证，可以准备发布的状态。
- **Claude Code**: README 中提到 "CLAUDE.md と README.md の1:1対応による GitHub Issues 統合 AI支援開発プラットフォーム"，表明 Claude Code 在该项目中扮演重要角色。
- **GitHub Issues統合**: README 强调 "GitHub Issues統合AI開発プロセス"，说明该项目与 GitHub Issues 紧密集成。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图展示了一个迭代式的 AI 辅助代码开发流程。从“最小実装ドラフト”开始，代码进入“AIレビューサイクル”进行多方面的审查，包括安全性、架构和性能，并生成审查摘要。如果代码未达到“品質基準”，则重复进行 AI 审查，最多循环 3-4 次。当代码通过 AI 审查后，再由人工进行“人間最終検証”，最终达到“リリース準備完了”状态。该流程强调了 AI 在代码质量保证中的作用，通过循环审查和人工验证，确保代码质量，并与 GitHub Issues 紧密集成。
