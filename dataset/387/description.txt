## 图类型与用途
这是一个流程图，用于展示 Z-Image Turbo 2API 的架构，描述了系统如何接收不同格式的输入，经过转换处理，最终以不同的模式输出结果。该图在 README.md 中作为架构总览的一部分，帮助用户理解数据流向。

## 图的整体布局
图整体采用从左到右的布局。左侧是输入接口，中间是转换层，右侧是输出模式。数据流从左向右流动。

## 分组/子图/阶段说明
图中包含三个子图，分别代表不同的处理阶段：
- **输入接口 | Input Interfaces**：接收用户请求的入口。
- **转换层 | Transformation Layer**：负责将不同格式的输入转换为系统内部可以处理的格式。
- **输出模式 | Output Modes**：定义系统如何将处理后的结果返回给用户。

## 节点逐项说明
- **A1 (OpenAI 格式 Chat Completions)**：接收符合 OpenAI Chat Completions API 格式的请求，用于对话生成。
- **A2 (OpenAI 格式 Image Generations)**：接收符合 OpenAI Image Generations API 格式的请求，用于图像生成。
- **A3 (WebUI 驾驶舱 HTML5 界面)**：接收来自 WebUI 驾驶舱（HTML5界面）的请求，提供用户友好的交互方式。README.md 中提到 WebUI 驾驶舱是一个赛博朋克风格的 HTML5 控制面板，既是 API 也是创作工具。
- **B1 (协议适配)**：适配不同的输入协议，例如将 OpenAI Chat Completions 格式转换为内部格式。
- **B2 (参数映射)**：将输入参数映射到系统内部的参数，确保参数的正确传递。
- **B3 (会话伪装)**：对会话进行伪装或处理，可能用于身份验证、授权或会话管理。
- **C1 (实时流式响应 SSE)**：使用 Server-Sent Events (SSE) 技术，实时地将结果以流式方式返回给用户，提供更好的用户体验。README.md 中提到 Turbo 流式响应是其核心亮点之一。
- **C2 (同步等待 Blocking)**：同步等待结果生成，然后一次性返回给用户。
- **C3 (异步轮询 Polling)**：异步地处理请求，用户需要通过轮询的方式来检查结果是否生成。

## 连线、分支与汇聚关系
- `A1 -> B1`：来自 OpenAI Chat Completions 格式的请求，进入协议适配阶段。
- `B1 -> C1`：经过协议适配后，以实时流式响应的方式返回。
- `A2 -> B2`：来自 OpenAI Image Generations 格式的请求，进入参数映射阶段。
- `B2 -> C2`：经过参数映射后，以同步等待的方式返回。
- `A3 -> B3`：来自 WebUI 驾驶舱的请求，进入会话伪装阶段。
- `B3 -> C3`：经过会话伪装后，以异步轮询的方式返回。

## 仓库语境与术语解释
- **OpenAI 格式 Chat Completions/Image Generations**：指符合 OpenAI 官方 API 规范的请求格式，Z-Image Turbo 2API 旨在兼容这些格式。
- **WebUI 驾驶舱**：Z-Image Turbo 2API 内置的 HTML5 控制面板，允许用户通过 Web 界面与 API 交互。
- **协议适配/参数映射/会话伪装**：转换层中的三个关键步骤，用于将不同来源的请求转换为 Z-Image 内部可以处理的格式。
- **SSE (Server-Sent Events)**：一种服务器推送技术，允许服务器实时向客户端发送数据，用于实现实时流式响应。
- **Blocking/Polling**：两种不同的输出模式，Blocking 指同步等待，Polling 指异步轮询。
- **Cloudflare Workers**：Z-Image Turbo 2API 运行的平台，提供边缘计算能力。README.md 强调了零成本部署，利用 Cloudflare Workers 免费额度。
- **API_MASTER_KEY**：用于身份验证的 API 密钥，需要在 Cloudflare Worker 的环境变量中设置。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Z-Image Turbo 2API 的架构，从左到右依次为输入接口、转换层和输出模式。输入接口接收 OpenAI 格式的 Chat Completions 和 Image Generations 请求，以及来自 WebUI 驾驶舱的请求。这些请求经过协议适配、参数映射和会话伪装等转换处理后，最终以实时流式响应 (SSE)、同步等待 (Blocking) 或异步轮询 (Polling) 等不同的输出模式返回给用户。该架构运行在 Cloudflare Workers 上，旨在提供一个轻量级的 AI 图像生成 API。
