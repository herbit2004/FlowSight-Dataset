## 图类型与用途
这是一个流程图，描述了 MCP 客户端如何通过 API Gateway 与运行在 AWS Lambda 函数中的 MCP 服务器进行通信，并使用 OAuth 服务器进行授权。该图展示了将本地 MCP 服务器部署到云端并通过 HTTP 进行访问的架构。

## 图的整体布局
图采用从左到右的布局。MCP 客户端位于左侧，API Gateway 位于中间，MCP Server (Lambda function) 和 OAuth Server (Cognito or similar) 位于右侧，展示了请求处理和授权的流程。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：客户端请求发起、API Gateway 处理与路由、后端服务执行与授权。

## 节点逐项说明
- **MCP Client**：代表 MCP 客户端应用程序，例如 IDE 或 Claude Desktop。它负责发起 MCP 请求。
- **API Gateway**：AWS API Gateway，作为入口点，接收来自 MCP 客户端的 HTTP 请求，并负责路由、授权和调用 Lambda 函数。
- **MCP Server (Lambda function)**：代表运行在 AWS Lambda 函数中的 MCP 服务器。它负责处理接收到的 MCP 请求，并返回响应。根据 README，该 Lambda 函数会启动一个 stdio MCP server 作为子进程，初始化该服务器，并将请求转发到本地服务器。
- **OAuth Server (Cognito or similar)**：代表 OAuth 认证服务器，例如 AWS Cognito。它负责对来自 MCP 客户端的请求进行身份验证和授权。

## 连线、分支与汇聚关系
- `MCP Client -- MCP Streamable HTTP Transport --> API Gateway`：MCP 客户端通过 MCP Streamable HTTP Transport 发送 MCP 请求到 API Gateway。
- `API Gateway -- Invoke --> MCP Server (Lambda function)`：API Gateway 调用 Lambda 函数，将请求转发给运行在 Lambda 函数中的 MCP 服务器。
- `API Gateway -- Authorize --> OAuth Server (Cognito or similar)`：API Gateway 对请求进行授权，向 OAuth 服务器验证客户端的身份和权限。

## 仓库语境与术语解释
- **MCP (Model Context Protocol)**：一种协议，用于客户端和服务器之间的通信，尤其是在 IDE 和代码分析工具的上下文中。
- **MCP Streamable HTTP Transport**：一种 MCP 传输协议，通过 HTTP 流式传输数据。
- **AWS Lambda**：AWS 提供的无服务器计算服务，允许用户运行代码而无需管理服务器。
- **API Gateway**：AWS 提供的 API 管理服务，允许用户创建、发布、维护和保护 API。
- **OAuth Server**：用于身份验证和授权的服务器，例如 AWS Cognito。
- **StdioServerAdapterRequestHandler**：`src/python/src/mcp_lambda/server_adapter/stdio_server_adapter_request_handler.py` 中定义的类，用于处理 MCP stdio 服务器适配器的请求。
- **APIGatewayProxyEventHandler**：`src/python/src/mcp_lambda/handlers/api_gateway_proxy_event_handler.py` 中定义的类，用于处理 API Gateway V1 事件。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 MCP 客户端通过 MCP Streamable HTTP Transport 向 API Gateway 发送请求，API Gateway 将请求路由到运行在 AWS Lambda 函数中的 MCP 服务器，并使用 OAuth 服务器进行授权。核心流程是“客户端请求 -> API Gateway 路由与授权 -> Lambda 函数执行 MCP 服务器”，其中 API Gateway 负责请求的路由和授权，Lambda 函数负责运行 MCP 服务器。该架构允许将本地 MCP 服务器部署到云端，并通过 HTTP 进行访问。
