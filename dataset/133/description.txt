## 图类型与用途
这是一个流程图，描述 JoySafety 框架的配置时期流程，展示了管理后台如何配置和管理各种安全组件，以及这些组件如何与数据库和向量库交互。该图在仓库中的作用是清晰地展现 JoySafety 的配置管理流程和组件间的依赖关系。

## 图的整体布局
图整体采用从上到下的布局。顶部是快速启动脚本，中间是管理后台，两侧和底部是各个安全组件、数据库和向量库。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：初始化与注册、原子能力注册与配置、数据存储。

## 节点逐项说明
- **Quickstart (quickstart/脚本)**：快速启动脚本，用于初始化和注册系统。
- **Admin (safety-admin 后台管理)**：安全框架的管理后台，是整个系统的配置中心。
- **Bert (safety-bert 独立服务)**：基于 BERT 模型的独立安全服务，用于检测文本中的安全风险。
- **FastText (safety-fasttext 独立服务)**：基于 FastText 模型的独立安全服务，同样用于检测文本中的安全风险。
- **Keywords (safety-keywords 独立服务)**：基于关键词匹配的独立安全服务，用于检测文本中是否包含敏感词。
- **Knowledge (safety-knowledge 独立服务)**：基于知识库的独立安全服务，用于检测文本是否违反知识库中的规则。
- **DB (MySQL/Redis)**：数据库，用于存储配置信息、模型数据、敏感词数据和知识库数据。
- **Vearch (Vearch 向量库)**：向量数据库，用于存储知识库的向量表示，支持向量检索。
- **Strategy (防御策略编排)**：防御策略编排模块，用于定义不同安全组件的组合和执行顺序。
- **Business (业务场景配置)**：业务场景配置模块，用于针对不同的业务场景配置不同的安全策略。

## 连线、分支与汇聚关系
- `Quickstart --> Admin`：快速启动脚本用于初始化和注册管理后台。
- `Admin --> Bert`：管理后台负责注册 BERT 原子安全能力服务。
- `Admin --> FastText`：管理后台负责注册 FastText 原子安全能力服务。
- `Admin --> Keywords`：管理后台负责注册 Keywords 原子安全能力服务。
- `Admin --> Knowledge`：管理后台负责注册 Knowledge 原子安全能力服务。
- `Admin --> Keywords`：管理后台负责敏感词管理，配置敏感词数据。
- `Admin --> Knowledge`：管理后台负责知识库管理，配置知识库数据。
- `Admin --> DB`：管理后台将配置信息写入数据库。
- `Admin --> Strategy`：管理后台进行防御策略编排。
- `Admin --> Business`：管理后台进行业务场景配置。
- `Bert --> DB`：BERT 服务从数据库读取模型/配置。
- `FastText --> DB`：FastText 服务从数据库读取模型/配置。
- `Keywords --> DB`：Keywords 服务从数据库读取敏感词数据。
- `Knowledge --> DB`：Knowledge 服务从数据库读取知识/配置。
- `Knowledge --> Vearch`：Knowledge 服务使用向量库进行向量检索。

## 仓库语境与术语解释
- **safety-admin**：Java 模块，负责配置及数据管理，不参与用户请求链路，仅在配置时期写入数据。
- **safety-bert / safety-fasttext / safety-keywords / safety-knowledge**：Python 或 Java 模块，为独立服务，分别实现 BERT 分类模型服务、FastText 分类模型服务、敏感词检测服务和知识检索/RAG/多轮对话检测。
- **MySQL/Redis**：数据库，用于数据持久化。
- **Vearch**：向量数据库，用于知识的向量化及语义检索。
- **原子能力**：指 BERT、FastText、Keywords、Knowledge 等独立的安全能力模块，可以通过管理后台进行注册和配置，具体可参考 `safety/safety-admin/docs/api/function_api.md`。
- **防御策略编排 (Strategy)**：通过 DAG 编排，可以灵活配置不同原子能力的组合和执行顺序，具体可参考 `safety/safety-admin/docs/api/dag_api.md`。
- **业务场景配置 (Business)**：针对不同的业务场景配置不同的安全策略，具体可参考 `safety/safety-admin/docs/api/business_api.md`。

## 可作为 QA Ground Truth 的高信息密度摘要
该图描述了 JoySafety 框架的配置时期流程。流程从 Quickstart 脚本初始化 Admin 后台管理开始，Admin 负责注册和配置各种原子能力服务（Bert、FastText、Keywords、Knowledge），进行敏感词和知识库管理，编排防御策略，并针对不同的业务场景进行配置，最终将配置信息写入 MySQL/Redis 数据库，知识库服务使用 Vearch 向量库进行向量检索。Admin 后台管理是整个安全框架的核心，负责所有配置信息的管理。
