## 图类型与用途
该图是一个流程图，描述了用户请求处理的流程。该流程包括用户认证、权限校验、缓存处理、支付服务、消息队列、订单服务、日志记录、通知发送和错误处理等环节。

## 图的整体布局
该图从上到下布局，整体呈现一个环状流程。起点是“用户请求”，终点是“API 网关”，流程最终会回到“用户请求”节点。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. 用户认证与权限校验阶段 (A -> G)
2. 缓存处理阶段 (G -> I)
3. 支付与订单处理阶段 (I -> P)
4. 结果处理与通知阶段 (P -> L)
5. 循环回到用户请求阶段 (L -> A)

## 节点逐项说明
- **用户请求**：流程的起始节点，表示用户发起的请求。
- **数据库**：存储数据的节点。
- **用户认证?**：判断用户是否通过认证的决策节点。
- **生成JWT**：生成JSON Web Token的节点。
- **权限校验**：校验用户权限的节点。
- **权限足够?**：判断用户权限是否足够的决策节点。
- **返回错误**：返回错误的节点。
- **读缓存**：从缓存读取数据的节点。
- **缓存命中?**：判断缓存是否命中的决策节点。
- **支付服务**：处理支付服务的节点。
- **更新缓存**：更新缓存的节点。
- **API 网关**：API网关节点。
- **消息队列**：消息队列节点。
- **订单服务**：处理订单服务的节点。
- **写日志**：写入日志的节点。
- **支付成功?**：判断支付是否成功的决策节点。
- **发送通知**：发送通知的节点。
- **回滚订单**：回滚订单的节点。

## 连线、分支与汇聚关系
- 用户请求 -> 数据库：发起数据库请求。
- 数据库 -> 用户认证?：进行用户认证。
- 用户认证? -- Yes --> 生成JWT：用户认证通过，生成JWT。
- 用户认证? -- No --> 返回错误：用户认证失败，返回错误。
- 生成JWT -> 权限校验：进行权限校验。
- 权限校验 -> 权限足够?：判断权限是否足够。
- 权限足够? -- No --> 返回错误：权限不足，返回错误。
- 权限足够? -- Yes --> 读缓存：权限足够，读取缓存。
- 读缓存 -> 缓存命中?：判断缓存是否命中。
- 缓存命中? -- Yes --> 支付服务：缓存命中，调用支付服务。
- 缓存命中? -- No --> 更新缓存：缓存未命中，更新缓存。
- 更新缓存 -> API 网关：更新缓存后，到达API网关。
- API 网关 -> 用户请求：回到用户请求节点。
- 支付服务 -> 消息队列：调用消息队列。
- 消息队列 -> 订单服务：调用订单服务。
- 订单服务 -> 写日志：写入日志。
- 写日志 -> 支付成功?：判断支付是否成功。
- 支付成功? -- Yes --> 发送通知：支付成功，发送通知。
- 支付成功? -- No --> 回滚订单：支付失败，回滚订单。
- 回滚订单 -> 消息队列：回滚订单后，到达消息队列。
- 发送通知 -> API 网关：发送通知后，到达API网关。

## 仓库语境与术语解释
- **JWT (JSON Web Token)**：一种用于身份验证和授权的开放标准。
- **缓存**：一种临时存储数据的机制，用于提高访问速度。
- **API 网关**：系统的入口，负责请求路由、鉴权、限流等功能。
- **消息队列**：一种异步通信机制，用于解耦系统间的依赖。
- **订单服务**：处理订单相关业务的服务。
- **日志**：记录系统运行状态和事件的文件。
- **回滚**：撤销之前的操作，使系统回到之前的状态。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先经过数据库，进行用户认证，认证通过则生成 JWT 并进行权限校验。权限足够则读取缓存，若缓存命中则调用支付服务，否则更新缓存并回到 API 网关。支付服务调用消息队列和订单服务，写入日志后判断支付是否成功，成功则发送通知，失败则回滚订单，最终通知发送后回到 API 网关，API网关回到用户请求。
