## 图类型与用途
这是一个流程图，描述了用户请求在主备集群架构中的处理流程。该流程图展示了负载均衡、故障检测、流量切换以及数据校验等关键步骤，确保系统的高可用性和数据一致性。

## 图的整体布局
图的布局是从上到下，整体呈现分层结构。流程从“用户请求”开始，经过负载均衡，最终到达“用户”。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1. **请求接入与负载均衡阶段**：用户请求到达负载均衡器，根据主集群可用性进行路由。
2. **故障检测与切换阶段**：当主集群不可用时，进行故障检测和流量切换到备集群。
3. **数据处理与校验阶段**：主集群或备集群对数据进行处理，并进行数据校验。
4. **响应返回阶段**：处理后的数据返回给用户。

## 节点逐项说明
- **用户请求**：用户发起的请求。
- **负载均衡器**：负责将用户请求分发到主集群或备集群。
- **主集群入口**：主集群接收请求的入口。
- **故障检测**：检测主集群是否发生故障。
- **流量切换**：将流量从主集群切换到备集群。
- **备集群入口**：备集群接收请求的入口。
- **数据校验**：对数据进行校验，确保数据一致性。
- **主集群处理**：主集群对数据进行处理。
- **告警/数据修复**：当数据校验失败时，进行告警和数据修复。
- **备集群处理**：备集群对数据进行处理。
- **主集群数据库**：主集群的数据存储。
- **备集群数据库**：备集群的数据存储。
- **返回响应**：将处理结果返回给用户。
- **用户**：接收响应的用户。
- **配置中心更新**：更新配置中心，同步集群信息。

## 连线、分支与汇聚关系
- 用户请求 -> 负载均衡器：用户请求发送到负载均衡器。
- 负载均衡器 -- 主集群可用 --> 主集群入口：如果主集群可用，则将请求路由到主集群入口。
- 负载均衡器 -- 主集群不可用 --> 故障检测：如果主集群不可用，则进行故障检测。
- 故障检测 -- 确认故障 --> 流量切换：如果确认故障，则进行流量切换。
- 故障检测 -- 未确认故障 --> 负载均衡器：如果未确认故障，则返回负载均衡器重新检测。
- 流量切换 -> 备集群入口：将流量切换到备集群入口。
- 主集群入口 -> 数据校验：主集群入口将请求发送到数据校验。
- 备集群入口 -> 数据校验：备集群入口将请求发送到数据校验。
- 数据校验 -- 通过 --> 主集群处理：如果数据校验通过，则进行主集群处理。
- 数据校验 -- 失败 --> 告警/数据修复：如果数据校验失败，则进行告警/数据修复。
- 数据校验 -- 通过 --> 备集群处理：如果数据校验通过，则进行备集群处理。
- 数据校验 -- 失败 --> 告警/数据修复：如果数据校验失败，则进行告警/数据修复。
- 主集群处理 -> 主集群数据库：主集群处理将数据存储到主集群数据库。
- 备集群处理 -> 备集群数据库：备集群处理将数据存储到备集群数据库。
- 主集群数据库 -> 返回响应：主集群数据库将数据返回到返回响应。
- 备集群数据库 -> 返回响应：备集群数据库将数据返回到返回响应。
- 返回响应 -> 用户：将响应返回给用户。
- 流量切换 -> 配置中心更新：流量切换后更新配置中心。
- 配置中心更新 -> 负载均衡器：配置中心更新后通知负载均衡器。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **负载均衡器**：将网络流量分发到多个服务器，以提高性能和可靠性的设备或软件。
- **主集群**：主要提供服务的服务器集群。
- **备集群**：在主集群发生故障时，接替主集群提供服务的服务器集群。
- **故障检测**：自动检测系统中出现的故障。
- **流量切换**：将用户请求从一个集群切换到另一个集群。
- **数据校验**：验证数据的完整性和一致性的过程。
- **配置中心**：集中管理和维护系统配置信息的组件。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先到达负载均衡器，负载均衡器根据主集群的可用性进行路由。如果主集群可用，请求进入主集群入口，进行数据校验，校验通过后由主集群处理，数据存储到主集群数据库，最终返回响应给用户。如果主集群不可用，则进行故障检测，确认故障后进行流量切换到备集群入口，同样进行数据校验，校验通过后由备集群处理，数据存储到备集群数据库，最终返回响应给用户。数据校验失败时，会触发告警和数据修复流程。流量切换后，配置中心会进行更新，并将更新后的信息同步给负载均衡器。
