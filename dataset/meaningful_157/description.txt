## Diagram Type & Purpose
This is a flowchart diagram illustrating the archival and cleanup policy for a data lake. It outlines the steps involved in determining whether data needs to be archived, the process of archiving the data, and the actions taken based on the success or failure of the archival process. The diagram serves as a visual representation of the data lifecycle management within the data lake environment.

## Overall Layout
The diagram flows from top to bottom (TD). It is divided into several subgraphs representing different stages of the archival process. The start node is "Start: Policy Engine Triggered" and the end node is "End: Data Lake Inactive".

## Repository Context & Terminology
- **Data Lake**: A centralized repository that allows you to store all your structured and unstructured data at any scale.
- **Policy Engine**: A system that evaluates and enforces policies.
- **Compliance Scan**: A process to check if data and processes meet regulatory requirements.
- **Data Masking**: A technique to hide sensitive data by replacing it with modified or substitute data.
- **Metadata Enrichment**: The process of adding more information to existing metadata to improve its quality and usefulness.
- **DR Site**: Disaster Recovery site, a location for an organization to recover and continue operating its technology infrastructure when its primary location becomes unavailable.
- **Data Retention Policy**: A set of rules that define how long data should be kept and how it should be disposed of.
- **Nearline Archive**: A storage tier that provides relatively fast access to archived data.
- **Cold Storage Archive**: A storage tier for infrequently accessed data, typically with lower cost and slower access times.

If successful, the staging area is cleaned, archive data is indexed, and the data retention policy is updated, utilizing the 'Data Retention Policy Monitor'. Finally, an archival report is generated, and data is purged from the data lake based on the policy, leading to 'End: Archival Complete'.
