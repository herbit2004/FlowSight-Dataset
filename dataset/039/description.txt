## Diagram Type & Purpose
This is an architecture diagram depicting a layered software architecture. It illustrates the dependencies and flow of control between different layers of an application, from external infrastructure to the core domain logic. The diagram serves as a high-level overview of the system's structure and organization.

## Overall Layout
The diagram is laid out in a top-down (TD) direction, representing a layered architecture. The flow starts with the "Infrastructure (External)" layer at the top and proceeds downwards through "Interface Adapters," "Application (Use Cases)," and finally to the "Domain (Enterprise Rules)" layer at the bottom.

## Subgraphs / Stages
The diagram contains four explicit subgraphs, each representing a distinct layer in the architecture:
- **Infrastructure (External)**: Represents external dependencies like databases and UI.
- **Interface Adapters**: Acts as a bridge between the infrastructure and the application layer.
- **Application (Use Cases)**: Contains the application's use case logic.
- **Domain (Enterprise Rules)**: Represents the core business logic and data structures.

## Repository Context & Terminology
- **Layered Architecture**: A software design pattern where the application is divided into distinct layers, each with a specific responsibility.
- **Infrastructure Layer**: The outermost layer, responsible for interacting with external systems like databases and UI.
- **Interface Adapters Layer**: Translates data and requests between the infrastructure and application layers.
- **Application Layer**: Contains the application's use case logic and orchestrates the domain layer.
- **Domain Layer**: The innermost layer, containing the core business logic and data structures.
- **Entities**: Objects that have a distinct identity and lifecycle within the domain.
- **Value Objects**: Immutable objects that represent a specific value or concept within the domain.
