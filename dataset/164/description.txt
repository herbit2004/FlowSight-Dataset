## 图类型与用途
这是一个流程图，描述了客户端上传文件到 Web 应用后，Web 应用进行安全检查和处理的流程。它展示了一个安全的文件上传处理架构，旨在防止恶意文件上传。

## 图的整体布局
图采用从上到下的布局。流程从客户端上传文件开始，经过一系列检查和处理步骤，最终根据扫描结果返回相应的 HTTP 状态码。

## 分组/子图/阶段说明
图中没有显式子图/分组，但逻辑上可分为三个阶段：预处理与初步过滤、ZIP 文件特殊处理、字节扫描与结果判定。

## 节点逐项说明
- **Client uploads file(s)**：客户端上传文件，是整个流程的起点。
- **Web App Route**：Web 应用程序的路由，接收客户端上传的文件。
- **Pre-filters (ext, size, MIME)**：预过滤器，检查文件的扩展名、大小和 MIME 类型。
- **Is ZIP?**：判断文件是否为 ZIP 压缩包。
- **Iterate entries (limits & scan)**：如果是 ZIP 文件，则迭代 ZIP 文件中的每个条目，并进行限制检查和扫描。
- **Scan bytes**：扫描文件的字节内容，判断是否存在恶意代码。
- **HTTP 4xx**：如果预过滤器检查失败，返回 HTTP 4xx 错误，表示客户端错误。
- **HTTP 422 blocked**：如果文件被判断为恶意或可疑，返回 HTTP 422 错误，表示文件被阻止。
- **HTTP 200 ok + results**：如果文件通过所有安全检查，返回 HTTP 200 状态码，表示上传成功，并返回处理结果。

## 连线、分支与汇聚关系
- `Client uploads file(s) -> Web App Route`：客户端上传文件到 Web 应用程序的路由。
- `Web App Route -> Pre-filters (ext, size, MIME)`：Web 应用程序路由将文件传递给预过滤器。
- `Pre-filters (ext, size, MIME) -- fail --> HTTP 4xx`：如果预过滤器检查失败，则返回 HTTP 4xx 错误。
- `Pre-filters (ext, size, MIME) -- pass --> Is ZIP?`：如果预过滤器检查通过，则判断文件是否为 ZIP 文件。
- `Is ZIP? -- yes --> Iterate entries (limits & scan)`：如果文件是 ZIP 文件，则迭代 ZIP 文件中的每个条目，并进行限制检查和扫描。
- `Is ZIP? -- no --> Scan bytes`：如果文件不是 ZIP 文件，则直接扫描文件的字节。
- `Iterate entries (limits & scan) -> Scan bytes`：ZIP 文件迭代扫描后，进入字节扫描阶段。
- `Scan bytes -- malicious/suspicious --> HTTP 422 blocked`：如果文件被判断为恶意或可疑，则返回 HTTP 422 错误。
- `Scan bytes -- clean --> HTTP 200 ok + results`：如果文件通过所有安全检查，则返回 HTTP 200 状态码。

## 仓库语境与术语解释
- **Pre-filters (ext, size, MIME)**：对应于 `packages/pompelmi/src/scan.ts` 中的预处理逻辑，用于快速排除不符合要求的文件。
- **ZIP bomb**: 一种恶意档案，解压后会消耗大量资源。`packages/engine/src/scanner/zip-deep.ts` 实现了对 ZIP 文件的深度检查，以防止 ZIP 炸弹攻击。
- **YARA**: 一种模式匹配工具，用于识别恶意软件家族。`packages/engine-yara/src/index.ts` 提供了 YARA 规则引擎的集成。
- **Reason Codes**: `packages/pompelmi/src/reasonCodes.ts` 中定义了标准化的理由代码，用于描述扫描结果的原因，例如 `ARCHIVE_PATH_TRAVERSAL`。
- **Presets**: `packages/pompelmi/src/presets/production.ts` 和 `docs/PRESETS_AND_REASON_CODES.md` 中定义了预设的扫描策略，例如 `strict`、`balanced` 和 `fast`，用于快速配置扫描选项。
- **HTTP 4xx / HTTP 422 / HTTP 200**: 常见的 HTTP 状态码，用于表示客户端错误、请求被拒绝和请求成功。

## 可作为 QA Ground Truth 的高信息密度摘要
该流程图描述了文件上传的安全处理流程。客户端上传文件后，首先经过扩展名、大小和 MIME 类型的预过滤。如果通过预过滤，则判断是否为 ZIP 文件，如果是，则迭代扫描 ZIP 文件中的每个条目；否则，直接扫描文件字节。根据扫描结果，恶意或可疑文件返回 HTTP 422 错误，安全文件返回 HTTP 200 状态码。其中，预过滤和 ZIP 文件的特殊处理是关键分支，最终的字节扫描决定了文件的安全性。该流程旨在利用预设策略和 YARA 规则等技术，防止恶意文件上传到 Web 应用程序。
