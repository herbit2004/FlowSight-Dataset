## 图类型与用途
这是一个系统架构图，描述了 Project Cornelius 的多层架构，用于将 Claude Code 与 Obsidian 知识库连接起来，实现 AI 辅助的知识管理。该图在 README 中被用作“Layer Cake Architecture”的示意。

## 图的整体布局
图采用从上到下的布局，将系统划分为用户空间、Claude Code 层、Project Cornelius、Memory Engine 和 Knowledge Layer 五个层次。数据流从顶部的用户开始，经过各层处理，最终到达底部的知识库。

## 分组/子图/阶段说明
图中通过 subgraph 显式地划分了五个阶段：
- **User Space**：表示用户的交互界面。
- **Claude Code Layer**：表示 Claude Code 的集成开发环境和系统提示。
- **Project Cornelius**：表示 Project Cornelius 的核心组件，包括配置、子代理和技能。
- **Memory Engine**：表示记忆引擎，用于意图分类、扩散激活和学习。
- **Knowledge Layer**：表示知识层，包括 FAISS 索引、知识图谱和 Obsidian Vault。

## 节点逐项说明
- **User**：使用 Project Cornelius 的用户。
- **Claude Code IDE**：Claude Code 的集成开发环境，用户与系统交互的界面。
- **CLAUDE.md System Prompt**：包含 Claude 模型指令的系统提示文件，用于指导 Claude 的行为。
- **.claude Config**：系统的配置文件，包含各种参数和设置。
- **Sub-Agents**：专门用于不同知识任务的多个子代理，例如研究、写作等。README 中列出了 `vault-manager`、`connection-finder` 等子代理。
- **Skills**：系统具备的各种技能，例如洞察捕获、连接发现、研究和内容创建等。README 中列出了 `/recall`、`/search-vault` 等技能。
- **Local Brain Search**：在用户的知识库中进行搜索的功能。`.claude/agents/local-brain-search.md` 描述了其使用 FAISS 进行向量搜索和连接发现的功能。
- **Intent Classifier**：用于识别用户意图的组件。
- **Spreading Activation**：一种搜索算法，用于在知识图中找到相关的节点。
- **Q-Value Learning**：一种强化学习方法，用于优化搜索结果的排序。
- **Brain / Obsidian Vault**：用户的知识库，存储在 Obsidian Vault 中。
- **FAISS Index**：用于快速向量搜索的 FAISS 索引。
- **Knowledge Graph**：从用户的知识库中提取的知识图谱。

## 连线、分支与汇聚关系
- `User -> CC`：用户通过 Claude Code IDE 与系统交互。
- `CC -> CLAUDE`：Claude Code IDE 将用户输入传递给 CLAUDE.md System Prompt。
- `CLAUDE -> CONFIG`：CLAUDE.md System Prompt 根据 .claude Config 中的设置进行后续操作。
- `CONFIG -> AGENTS`：.claude Config 配置 Sub-Agents。
- `CONFIG -> SKILLS`：.claude Config 配置 Skills。
- `AGENTS -> SEARCH`：Sub-Agents 使用 Local Brain Search 在知识库中进行搜索。
- `SKILLS -> SEARCH`：Skills 也使用 Local Brain Search 在知识库中进行搜索。
- `SEARCH -> INTENT`：Local Brain Search 将搜索结果传递给 Intent Classifier。
- `INTENT -> SPREAD`：Intent Classifier 将用户意图传递给 Spreading Activation。
- `SPREAD -> FAISS`：Spreading Activation 使用 FAISS Index 在知识库中找到相关的节点。
- `SPREAD -> GRAPH`：Spreading Activation 也使用 Knowledge Graph 在知识库中找到相关的节点。
- `LEARN -> SPREAD`：Q-Value Learning 用于优化 Spreading Activation 的搜索结果。
- `FAISS -> BRAIN`：FAISS Index 从 Brain / Obsidian Vault 中获取数据。
- `GRAPH -> BRAIN`：Knowledge Graph 也从 Brain / Obsidian Vault 中获取数据。

## 仓库语境与术语解释
- **Claude Code**：一种集成开发环境，在此项目中作为用户与 AI 系统交互的界面。
- **Obsidian Vault**：用户的本地知识库，Project Cornelius 旨在增强其功能。
- **FAISS**：Facebook AI Similarity Search 的缩写，用于在知识库中进行快速向量搜索。
- **Spreading Activation**：一种受 SYNAPSE 启发的记忆检索方法，通过知识图谱传播激活，寻找相关节点。
- **Sub-Agents**：专门用于不同知识任务的 AI 代理，例如 `vault-manager` 用于管理 Obsidian Vault，`connection-finder` 用于发现笔记之间的连接。
- **Skills**：系统具备的各种技能，例如 `/recall` 用于知识检索，`/find-connections` 用于发现笔记之间的连接。
- **CLAUDE.md**：定义 Project Cornelius 行为的系统提示文件。`.claude/settings.json` 文件可以配置对该文件的读取权限。

## 可作为 QA Ground Truth 的高信息密度摘要
该图展示了 Project Cornelius 的多层架构，从用户通过 Claude Code IDE 发起请求开始，经过 CLAUDE.md 系统提示，配置 Sub-Agents 和 Skills，利用 Local Brain Search 在 Obsidian Vault 中进行搜索。搜索结果通过 Intent Classifier 和 Spreading Activation 进行处理，并使用 FAISS Index 和 Knowledge Graph 优化搜索结果。Q-Value Learning 用于改进搜索排序，最终结果从 Brain / Obsidian Vault 中获取。该架构的核心在于利用 AI 辅助用户进行知识管理，发现知识库中隐藏的连接。
