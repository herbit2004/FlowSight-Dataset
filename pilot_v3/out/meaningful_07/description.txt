## 图类型与用途
该图是一个流程图，描述了一个典型的微服务架构下的用户请求处理流程。它展示了用户请求如何经过 API 网关、鉴权路由，最终访问用户服务或订单服务，并返回响应。该图用于说明微服务架构中请求的处理过程。

## 图的整体布局
该图采用从上到下的布局。整体上分为“用户行为”和“系统内部”两个层次。流程从用户请求开始，最终返回响应。

## 分组/子图/阶段说明
图中包含两个子图：
- **用户行为**：模拟用户发起请求的场景。
- **系统内部**：描述系统内部处理用户请求的详细流程，包括鉴权、路由、服务调用、数据访问等。

## 节点逐项说明
- **A (用户请求)**：用户发起的请求。
- **B (API Gateway)**：API 网关，接收用户请求并进行初步处理。
- **C (鉴权 & 路由)**：鉴权和路由模块，负责验证用户身份并根据请求类型将请求路由到相应的服务。
- **D (用户服务 - 获取用户信息)**：用户服务，负责获取用户信息。
- **E (用户缓存命中?)**：判断用户缓存是否命中。
- **F (返回用户信息)**：返回用户信息给调用方。
- **G (用户数据库)**：用户数据库，存储用户信息。
- **H (返回用户信息)**：从数据库返回用户信息。
- **I (订单服务 - 创建订单)**：订单服务，负责创建订单。
- **J (库存服务 - 扣减库存)**：库存服务，负责扣减库存。
- **K (库存成功?)**：判断库存扣减是否成功。
- **L (订单服务 - 写入订单数据库)**：订单服务，负责将订单信息写入数据库。
- **M (订单服务 - 回滚订单)**：订单服务，负责回滚订单。
- **N (返回订单结果)**：返回订单结果给调用方。
- **O (返回响应)**：返回最终响应给用户。

## 连线、分支与汇聚关系
- A -> B：用户请求发送到 API 网关。
- B -> C：API 网关将请求发送到鉴权 & 路由模块。
- C -- 用户服务 --> D：鉴权 & 路由模块将用户服务请求路由到用户服务。
- D -> E：用户服务请求到达用户缓存判断。
- E -- 是 --> F：如果用户缓存命中，则直接返回用户信息。
- E -- 否 --> G：如果用户缓存未命中，则访问用户数据库。
- G -> H：从用户数据库获取用户信息。
- H -> F：将从数据库获取的用户信息返回。
- C -- 订单服务 --> I：鉴权 & 路由模块将订单服务请求路由到订单服务。
- I -> J：订单服务请求到达库存服务。
- J -> K：库存服务进行库存扣减。
- K -- 是 --> L：如果库存扣减成功，则将订单信息写入订单数据库。
- K -- 否 --> M：如果库存扣减失败，则回滚订单。
- L -> N：将订单结果返回。
- M -> N：将订单回滚结果返回。
- F -> N：将用户信息返回。
- N -> O：将最终响应返回给用户。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **API Gateway**：API 网关，是系统的入口，负责接收和路由外部请求。
- **鉴权**：验证用户身份的过程，确保用户有权限访问相应的资源。
- **路由**：根据请求的类型或内容，将请求转发到相应的服务或模块。
- **用户服务**：负责处理用户相关业务的服务，例如获取用户信息。
- **订单服务**：负责处理订单相关业务的服务，例如创建订单。
- **库存服务**：负责处理库存相关业务的服务，例如扣减库存。
- **缓存**：一种临时存储数据的机制，用于提高数据访问速度。

## 可作为 QA Ground Truth 的高信息密度摘要
用户发起请求，经过 API 网关到达鉴权 & 路由模块。如果是用户服务请求，则获取用户信息，如果缓存命中则直接返回，否则访问用户数据库获取并返回。如果是订单服务请求，则创建订单，扣减库存，如果库存扣减成功则写入订单数据库，否则回滚订单，最终返回订单结果。所有流程的最终结果都会返回响应给用户。
