# FlowSight 数据集增强与实验设计思路整理

本文档整理「四元组补齐 + 提升数据集价值 + 多实验组验证」的整体思路，便于落地实现与论文实验设计。

---

## 一、当前状态与目标

### 1.1 四元组定义

每条样本的完整形态（四元组）：

| 维度 | 内容 | 当前状态 |
|------|------|----------|
| **Mermaid** | `diagram.mmd` | ✅ 已有（500 条真实爬取） |
| **Image** | `diagram.png` | ✅ 已有（mermaid.ink 默认渲染） |
| **Description** | `description.txt`（7 节结构化） | ✅ 已有 |
| **QA** | 问答对，含题干 + 标准答案 | ❌ 待生成 |

**目标**：补齐 QA，并通过对「图像风格」「数据来源」「QA 设计」的扩展，让数据集不仅能评测「能不能答对」，还能支撑多组对照实验，得出可解释的结论。

### 1.2 价值主张（你希望证明/验证的）

- 真实数据比 LLM 合成数据更有评测价值。
- 多模态模型在答题时既依赖**图像理解**，也受**通用知识**影响；通过「无意义/反常识」数据可以分离这两种效应。
- 图像渲染风格会影响理解难度，可指导实践（如文档/工具选哪种风格）。
- QA 设计合理时，不同模型之间会拉开差距，且结论稳定、可复现。

## 二、三个增强方向与实验组设计

### 方向 1：多风格 PNG —— 「风格鲁棒性」实验组

**想法**：同一份 Mermaid 源码，生成多种渲染风格的 PNG，而非常年只用 mermaid.ink 默认样式。

**目的**：  
跑实验时固定题目（同一批 QA），只换图像风格，看**哪种风格下模型准确率更高/更低**，从而得到「什么风格更容易被理解」的结论。

**可选技术**（在「不微调、只评测」的前提下）：

- **Mermaid 自带**：  
  - [Mermaid 主题](https://mermaid.js.org/config/theming.html)（如 `default` / `forest` / `dark` / `neutral`）  
  - mermaid.ink 支持 `?theme=xxx` 等参数时可对同一 mmd 生成多张图。
- **其他开源渲染**：  
  - [Kroki](https://kroki.io/)：支持 Mermaid，可能有不同后端/样式。  
  - 自建 Mermaid CLI（`@mermaid-js/mermaid-cli`）渲染时传入不同 theme 或 config，得到多套 PNG。

**实验组设计**：

- **变量**：图像风格（如 default / dark / forest，至少 2–3 种）。  
- **固定**：同一批样本的 mmd、description、QA 不变，只替换 PNG。  
- **指标**：按风格汇总准确率；可做「风格 × 模型」交互分析。  
- **预期结论**：某些风格显著更好/更差 → 可作为「文档/工具应选用何种风格」的依据。

**实现要点**：

- 在现有 pipeline 里为每条样本增加「多风格渲染」步骤，输出如：  
  `diagram_default.png`、`diagram_dark.png`、`diagram_forest.png`。  
- metadata 或单独索引文件中标明每条样本有哪些风格，便于评测脚本按风格加载。

### 方向 2：合成数据 —— 「真实 vs 拟真 vs 无意义」实验组

**想法**：在 500 条真实数据之外，增加两类纯 LLM 生成的数据，用于对照。

| 类型 | 数量（建议） | 生成方式 | 用途 |
|------|--------------|----------|------|
| **真实** | 500（已有） | GitHub 爬取 + 多模态 description | 基线 |
| **拟真合成** | 250 | LLM 虚构「看起来像真实架构/流程」的 Mermaid，再生成 description + QA | 检验「真实 vs 拟真」的评测差异 |
| **无意义/反常识** | 250 | LLM 生成：无事实依据的图（无意义节点/边、自造词、或真实节点+错误逻辑） | 检验模型是「看图」还是「凭常识猜」 |

**拟真合成（250 条）**：

- **要求**：  
  - 完全由 LLM 生成 Mermaid，不抄真实仓库。  
  - 内容要「像」真实流程图/架构图：合理的技术名词、合理的流程步骤、有分支/汇聚等。  
- **Pipeline**：  
  - 用强模型（如 GPT-4 / Claude）生成 mmd → 用现有流程渲染 PNG → 用多模态模型根据 **PNG + mmd** 生成 description（可不用仓库上下文）→ 再生成 QA。  
- **实验假设**：  
  - 在「理解 / 生成」任务上，**拟真合成数据上的表现 ≥ 真实数据**（因为拟真更规整、更符合训练分布）。  
  - 若真实数据明显更难，则说明**真实数据的复杂度和噪音**具有独特评测价值。

**无意义/反常识（250 条）**：

- **要求**：  
  - 完全不模拟真实业务，例如：  
    - 无意义：随机节点 ID、无逻辑的边、无意义循环；或  
    - 自造词：虚构的技术名词、不存在的产品名；或  
    - 反常识：节点用真实概念（如「数据库」「缓存」），但边/分支关系故意错误（如「用户请求 → 数据库 → 用户请求」形成荒谬闭环）。  
- **目的**：  
  - 若模型主要「看图」：无意义/反常识题应明显更难，准确率更低。  
  - 若模型主要「凭常识」：可能在反常识题上错得更多（被常识带偏），而在纯无意义题上表现不一。  
- **预期排序**：  
  - **拟真合成 > 真实 > 无意义/反常识**。  
  - 可进一步比较：纯无意义 vs 反常识，不同模型是否表现不同（例如「常识强」的模型在反常识上更差）。

**实现要点**：

- metadata 中增加字段，如 `source: "real" | "synthetic_realistic" | "synthetic_nonsense"`。  
- 拟真/无意义两条 pipeline：  
  - 拟真：LLM 只生成 mmd（+ 可选简短场景描述）→ 统一走「渲染 → description → QA」。  
  - 无意义：LLM 按「无意义/自造词/反常识」三种子类型之一生成 mmd，并注明子类型 → 同样渲染 → description（描述中可标明「本题为无意义/反常识，答案仅以图为准」）→ QA。  
- 评测时可按 `source` 分层报告准确率，并做统计检验。

### 方向 3：QA 设计 —— 有 Ground Truth、可区分模型、可复现结论

**原则**（对应你提的几点）：

1. **有 ground truth**：每道题的答案在 description / 高信息密度摘要中有明确依据，理论上「认真看图+读描述」能答对。  
2. **有机会答对，但不会全对**：难度分布要合理，让强模型明显优于弱模型，而不是人人满分或人人零分。  
3. **在不同模型间体现差异**：题目类型要多样（见下），使得不同模型在不同维度上各有优劣。  
4. **引向标准结论**：QA 设计要服务上述实验假设（真实 vs 拟真 vs 无意义、风格差异等），便于写进论文。

**题目类型建议**（可组合使用）：

- **事实型**：图中明确信息（节点名、边方向、分支条件、起点/终点）。→ 测「是否真的看图」。  
- **推理型**：需要多步推理（如「A 失败后会走哪条路径」「哪些节点会汇聚到 X」）。→ 测结构理解与推理。  
- **摘要/复述型**：用 description 第 7 节作为答案，问「请简要概括该流程/架构」。→ 与现有高信息密度摘要对齐，便于自动评分（如与 reference 的相似度）。  
- **反常识/无意义专用**：在无意义数据上，答案必须严格以图为准（例如「图中从 A 到 B 的边写的是 X」），避免模型用常识「猜对」。  

**难度与区分度**：

- 每条样本可生成 2–5 个 QA，其中：  
  - 部分简单（单节点/单边），部分中等（多步），少量难（需要完整理解图+描述）。  
- 生成时可用「基于 description 的提纲」保证每道题都有对应段落作为 ground truth；  
- 可选：用一两个强模型做「预答」，过滤掉人人都对或人人都错的题，保留有区分度的题。

**实现要点**：

- 输出格式建议：每样本一个 `qa.json`（或合并进 metadata），包含 `question`、`answer`（标准答案）、`type`（factual / reasoning / summary / nonsense_only）、`ground_truth_section`（指向 description 的某一节或摘要）。  
- 评测脚本：按 `source`、`type`、可选 `style` 分层算准确率/相似度，便于画表和做统计检验。

## 三、整体实验矩阵（小结）

| 维度 | 取值 | 用途 |
|------|------|------|
| **数据来源** | 真实 / 拟真合成 / 无意义(含反常识) | 验证「真实数据价值」与「看图 vs 常识」 |
| **图像风格** | default / dark / forest / … | 验证「风格对理解难度的影响」 |
| **QA 类型** | 事实 / 推理 / 摘要 / 无意义专用 | 分析模型在不同能力上的差异 |
| **模型** | 多种 VLM / 多模态模型 | 区分度与排序 |

**预期可得到的结论**（示例）：

1. 真实数据在评测中比拟真合成更难，更能区分模型能力。  
2. 无意义/反常识数据上准确率显著低于真实/拟真，且反常识题上「常识强」的模型可能更易出错 → 说明多模态模型受通用知识影响，并非仅尊重图像。  
3. 某种/某几种图像风格下准确率系统性更高 → 可作为「推荐风格」的依据。  
4. 不同 QA 类型上模型排名可能不同 → 可讨论「理解 vs 推理 vs 摘要」的能力差异。

## 四、建议的落地顺序

1. **先做 QA 生成**  
   - 仅针对现有 500 条真实数据，基于 description（尤其第 7 节）生成 QA，定义好 `qa.json` 格式和题目类型。  
   - 跑一版基线评测，确认题目有区分度、有 ground truth。

2. **再加多风格 PNG**  
   - 选 2–3 种 Mermaid 主题，为现有 500 条（或子集）生成多风格图，扩展 metadata。  
   - 同一套 QA 下做「按风格」的准确率对比。

3. **再做合成数据**  
   - 先做 250 条拟真（仅 LLM 生成 mmd → 渲染 → description → QA）。  
   - 再做 250 条无意义/反常识，并细分子类型。  
   - 统一评测脚本，按 `source` 分层报告。

4. **最后做分析与写作**  
   - 用实验矩阵填表、做显著性检验，写出「真实 vs 拟真 vs 无意义」「风格」「QA 类型」的结论。
