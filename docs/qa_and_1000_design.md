# FlowSight：QA 设计依据与 1000 条数据方案

本文档记录：(1) Pilot V2 所用 QA 生成与评测流程；(2) 扩展到 1000 条时的数据划分设计及是否最优；(3) 题型（factual / reasoning / negation）与难度（easy / medium / hard）的划分理由与标准。

---

## 一、Pilot V2 的 QA 生成与评测流程（备忘）

### 1.1 QA 生成

- **输入**：每条的 `diagram.mmd` + `description.txt`（前约 7500 字）。
- **约束**：
  - 每样本固定题数（如 6 道），4 选项 A/B/C/D，单选，答案唯一。
  - 每题必须标注 `type` 与 `difficulty`（见第三节）。
  - 题目要能区分不同参数量与形态的模型（多跳、易混选项、长链、否定题）。
- **Prompt 要点**：要求包含多跳推理（从 X 到 Y 必经哪一节点）、易混选项（两选项均在图中出现或表述相近）、长链/远距离（起点到终点顺序、非相邻节点）、否定题（「以下哪个不是」且干扰项 plausible）。
- **输出**：`qa.json`，每项含 `question`, `options`, `correct_index`, `type`, `difficulty`。
- **覆盖生成**：`python pilot_v2/run.py qa_regen` 会先删已有 `qa.json` 再生成；`qa` 则不覆盖。

### 1.2 评测流程

- **预检 (probe)**：对每模型发一题「只回复 A」，确认能解析出字母，未通过则从评测中剔除。
- **答题**：每题对通过预检的模型并行请求；提示词强约束「只输出一个字母 A/B/C/D」，禁止解释；解析不到字母或请求失败时最多重试 3 次。
- **解析**：`_parse_message_to_letter()` 兼容 content 为 list、首行/末行首尾字、`\b(A-D)\b`、任意出现 A-D。
- **输出**：`eval_results.jsonl`（每题每模型一行），`report.txt` 按模型、类型、难度、模型×类型、模型×难度汇总准确率。

### 1.3 与 1000 条扩展的衔接

- 全量 1000 条：**先造数据（含 500 条新增合成），再统一为每条生成 QA**。
- QA 生成逻辑可复用 pilot_v2 的 prompt 与格式，仅需支持按 `source`（real / synthetic_realistic / synthetic_nonsense）选用不同 prompt 或同一 prompt 加说明（例如无意义数据注明「答案仅以图为准」）。

## 二、1000 条数据划分：有意义 vs 无意义，是否最优？还有哪些类型？

### 2.1 当前方案（与实验计划一致）

| 来源 | 数量 | 含义 | 实验作用 |
|------|------|------|----------|
| **真实 (real)** | 500 | GitHub 爬取，已有 | 基线；验证「真实数据是否更难、更有区分度」 |
| **拟真合成 (synthetic_realistic)** | **200** | LLM 生成「看起来像真实架构/流程」的 Mermaid，逻辑合理、术语正常 | 对照：拟真是否比真实更容易、是否更测不出模型能力 |
| **无意义 (synthetic_nonsense)** | **300** | 无事实依据，分三个子类型各 **100 条**（见 2.4） | 对照：无意义是否因无法用常识而表现更差；区分「看图」vs「凭常识」 |

结论：**500 真实 + 200 拟真 + 300 无意义 = 1000 条**。新增 500 条 = 200 拟真 + 300 无意义；无意义内**两种**子类型各 **150** 条（chaos / misleading）。

### 2.2 是否还有其它适合的数据类型？

在「不显著增加实现与实验复杂度」的前提下，可考虑的**补充类型**（非必须）：

- **对抗/边界 (adversarial / edge-case)**  
  - 含义：内容有意义，但故意难——歧义表述、长链、易混选项、多步否定。  
  - 作用：区分「难是因为无意义」还是「难是因为题目本身难」。  
  - 建议：**可不单独做一类**，而是在真实/拟真里通过 QA 难度（hard）和题型（reasoning / negation）来体现；若要做，可从小规模（如 50 条）先试。

- **无意义子类型（在无意义 300 条内细分）**  
  - 见下节 **2.4 无意义数据的两类子类型**：**两种**明确、互不重合的子类型，每类 **150 条**（chaos 完全混乱 / misleading 误导）；生成时打 `nonsense_subtype`，评测时按该字段聚合（实验 4）。  
  - 真实、拟真**暂不**做子类型划分。

### 2.3 推荐结论

- **主划分**：500 真实 + **200** 拟真 + **300** 无意义 = 1000 条。  
- **子类型**：仅对**无意义**数据做**两类**细分，每类 150 条（见 2.4）；真实与拟真暂不划子类型。

### 2.4 无意义数据的两类子类型（明确、互不重合）

**统一测试标准**：无意义图的评测标准与有意义图一致——**模型在多大程度上尊重原图作答**。即：答案应严格以图中内容为准；若模型按常识或“合理推测”作答而偏离原图，则判错。子类型只分两种，定义清晰：

| 子类型 (nonsense_subtype) | 中文名 | 定义 | 常识的角色 | 每类条数 |
|---------------------------|--------|------|------------|----------|
| **chaos** | 完全混乱 | 内容**完全混乱、无真实对应**，像“意大利面拌四十二号混凝土”——随机节点、自造词、荒谬组合、毫不相干的概念硬拼在一起，或整图无逻辑的连线与分支。不需要自洽，可以故意荒谬、无意义。 | 常识**用不上**，只能严格读图 | 150 |
| **misleading** | 误导 | 内容**有真实、有意义的对应**（真实世界概念：用户请求、数据库、API、缓存等），但以**不正确的方式组合**——错误的关系、颠倒的顺序、荒谬的因果，或表面正常却在一处故意改错（一条边反了、一个标签错一字、分支条件对调）。 | 常识会**误导**；测按常识还是按图答 | 150 |

**两类互不重合**：

- **chaos**：没有可依赖的常识对应，图本身即混乱/荒谬，只能看图。
- **misleading**：有常识对应，但组合方式错误或有一处陷阱，按常识答会错。

**实现**：生成无意义数据时，每条选定上述两类之一，在 metadata 中写入 `nonsense_subtype: "chaos" | "misleading"`。无意义共 300 条，每类 150 条。评测与报告按该字段分层准确率。

## 三、QA 题型（factual / reasoning / negation）为什么这么分？有更好分法吗？

### 3.0 理论依据：可引用的逻辑轴（直接依据）

当前三分法可以归结为一条**认知操作轴**：作答时模型需要做的**信息处理类型**不同，而不是“随便起的三个名字”。下面给出可直接写进论文、可引用的表述。

**轴心：理解层次（comprehension level）**

在阅读理解和图表 QA 里，常见把题目按“理解层次”分成几类（例如字面 / 推理 / 评价）。我们把**流程图单选题**的操作对应为三类：

| 题型 | 认知操作 | 与常见“理解层次”的对应 | 与 Bloom（松散） |
|------|----------|------------------------|------------------|
| **Factual** | **单步提取**：从图中直接定位一个实体、一条边或一个标签 | 字面理解（literal） | 偏 Remember / Understand |
| **Reasoning** | **多步推理**：沿路径、顺序、分支或并行关系做链式推断 | 推理理解（inferential） | 偏 Apply / Analyze |
| **Negation** | **排除判断**：在多个候选中找出“不符合题干描述”的一项，需理解“非”并抑制常识/关键词匹配 | 评价/排除（evaluative / exclusion） | Understand + Analyze（理解否定并排除） |

**直接逻辑依据**（可写进方法部分）：

- **Factual** 测的是**是否真的看图**：答案若不在图里就得不到，单步检索即可，对应“字面层”。
- **Reasoning** 测的是**结构理解与推理链**：必须整合多节点/多边关系才能作答，对应“推理层”。
- **Negation** 测的是**完整理解 + 抵抗干扰**：既要理解题干中的“不是/未出现”，又要在 plausible 干扰项下排除，对应“评价/排除层”。

因此，**分类的直接逻辑是“作答所需认知操作”**：单步提取 vs 多步推理 vs 排除性判断。  
与 Bloom 的对应是**松散的**（不追求一一对应）：Factual 偏识记/理解，Reasoning 偏应用/分析，Negation 偏理解+分析；若审稿人问，可说明“采用理解层次（literal / inferential / exclusion）的常见划分，与 Bloom 有大致对应但不做严格映射”。

**可引用方向**（供查文献）：  
- 阅读理解中的 literal vs inferential vs evaluative 分类；  
- 图表/Diagram QA 中 “location / relation / path / comparison” 等按所需信息类型的分类。  
- 若需要，可在文档中补一句“具体文献可参考 VQA / diagram comprehension 中按问题类型分层的评测设计”。

### 3.1 当前三分法的理由

- **Factual（事实题）**  
  - 定义：答案在图中**直接可见**（节点名、边标签、分支条件、起点/终点等），至多一步定位。  
  - 作用：测模型**是否真的看图**，而不是凭题干/选项猜。在无意义数据上，事实题必须严格以图为准。  
  - 典型问法：「图中包含以下哪个节点？」「从 A 到 B 的边上的标签是？」

- **Reasoning（推理题）**  
  - 定义：需要**多步推理**（路径、顺序、分支结果、并行关系、谁先谁后等），不能一眼从单点读出。  
  - 作用：测**结构理解与推理链**，能拉开不同模型（pilot 中 reasoning 上 thinking 明显优于 instruct）。  
  - 典型问法：「从 X 到 Y 必须经过哪一节点？」「若某分支选 No，最终会到达哪？」「哪两个步骤可以并行？」

- **Negation（否定题）**  
  - 定义：题干为「以下哪个**不是**……」「图中**未**出现的环节是」等，正确答案是「不符合题干描述」的那一项。  
  - 作用：迫使**完整理解题干+选项**并对照图，避免靠关键词或常识选「看起来对」的选项；在反常识/无意义数据上可检验是否被常识带偏。  
  - 典型问法：「以下哪个不是图中出现的步骤？」「图中没有出现的组件是？」

这样分的**核心理由**：  
(1) 对应三种不同的认知需求——**定位 vs 推理 vs 否定理解**；  
(2) 与实验假设一致（看图 vs 常识、模型区分度）；  
(3) 实现简单（生成时打 tag，评测按 type 分层），pilot 已验证有区分度。

### 3.2 与 Bloom 的对应（松散）、其它可能分法

- **Bloom（修订版）**：识记 → 理解 → 应用 → 分析 → 评价 → 创造。本三分法与 Bloom **无严格一一对应**：Factual 偏识记/理解，Reasoning 偏应用/分析，Negation 偏理解+分析（理解“非”并排除）。论文中若需提及，可写“题目类型按理解层次（literal / inferential / exclusion）划分，与 Bloom 认知层次有大致对应但不做严格映射”。
- **按所需范围**：单节点 / 多节点 / 全图。与当前 type 有交叉（factual 多单节点，reasoning 多多节点/全图），可作为**分析时的子维度**，不必改生成格式。  
- **按答案形式**：实体、关系、路径、计数。同样可作为分析时的补充视角，不必取代现有 type。

**结论**：当前三分法**足够好**，且已和 pilot 的 report 对齐；若审稿人问「为什么这样分」，可回答「按认知需求（直接事实 / 多步推理 / 否定理解）与实验目标（看图 vs 常识、模型区分度）设计」。不必为改而改。

## 四、QA 难度（easy / medium / hard）的划分标准

### 4.1 操作定义（生成时给模型看的标准）

- **Easy**  
  - 单步即可作答；答案在图中明显可见或仅需一次简单推断。  
  - 典型：某节点名、某条边标签、某个分支的两种结果之一。  
  - 预期：多数模型准确率较高，用于保证「不是全难、有基线」。

- **Medium**  
  - 需要看图并做**简单推理**（顺序、一个分支、相邻节点关系等）。  
  - 典型：「A 之后是哪一步？」「图中与 X 直接相连的节点是？」  
  - 预期：准确率略低于 easy，能区分「只看表面」和「会推一步」的模型。

- **Hard**  
  - **多步推理**、**长链**（非相邻节点）、**易混选项**（两个选项都在图中出现或表述相近）、或**否定题**且干扰项 plausible。  
  - 典型：「从起点到终点按顺序经过哪组节点？」「以下哪两个步骤可以并行？」「以下哪个不是……」（且错误选项都很像真的）。  
  - 预期：准确率明显低于 easy/medium，能拉开不同参数量与形态的模型（pilot 中 hard 上 thinking 优于 instruct 更明显）。

### 4.2 与题型的组合

- 一般不出现「factual + hard」很多（事实题天然偏简单），但可以有「factual + medium」（如「图中与 A 直接相连的节点有几个」需数一数）。  
- **Reasoning** 和 **Negation** 是拉高 hard 占比的主要来源；生成时可约束：easy 最多 1 道/样本，medium ≥ 2，hard ≥ 2。

### 4.3 小结

- **难度** = 作答所需步数 + 选项是否易混 + 是否否定题。  
- **Easy**：单步、明显；**Medium**：看图+简单推理；**Hard**：多步/长链/易混/否定。  
- 该标准已用于 pilot_v2 的 QA 生成与报告，全量 1000 条可沿用，并在无意义数据上注明「答案仅以图为准」即可。

## 五、落地顺序建议（与实验计划一致）

1. **造数据到 1000 条**  
   - 保留现有 500 条真实，在 metadata 中加 `source: "real"`（若尚未有）。**真实、拟真不做子类型**。  
   - 新增 **200** 条拟真：LLM 生成 Mermaid（不抄真实仓库）→ 渲染 PNG → 生成 description；metadata 中 `source: "synthetic_realistic"`。  
   - 新增 **300** 条无意义：LLM 按**两类子类型**（chaos / misleading）**各 150 条**生成 mmd → 渲染 → description；metadata 中 `source: "synthetic_nonsense"` 与 `nonsense_subtype`（见 2.4）。  
   - 目录与 metadata 统一：例如 id 500–699 拟真（200 条），700–999 无意义（300 条）；每条都有 `diagram.mmd`、`diagram.png`、`description.txt`。

2. **统一生成 QA**  
   - 对 1000 条统一跑 QA 生成（可复用 pilot_v2 的 prompt）；  
   - 对 `synthetic_nonsense` 可在 prompt 中加一句「本题为无意义/反常识图，答案严格以图为准，不要依赖常识」。  
   - 输出格式与 pilot_v2 一致：`qa.json` 含 `type`、`difficulty`。

3. **评测与报告**  
   - 按 `source`（real / synthetic_realistic / synthetic_nonsense）分层准确率；  
   - 按 **nonsense_subtype**（两类：chaos / misleading，各 150 条）对无意义数据再分层（实验 4）；  
   - 按 QA `type`、`difficulty` 分层（与实验 2 一致）。

这样，**数据划分、题型与难度标准、以及 QA 生成与评测流程**都有一份可复用的记录，便于实现 1000 条 pipeline 和写论文方法/实验部分。
