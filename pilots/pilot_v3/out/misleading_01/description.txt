## 图类型与用途
该图是一个流程图，描述了用户请求的支付处理流程。它展示了支付网关、风控系统、订单服务等组件之间的交互。该图用于说明支付流程中的各个步骤和决策点。

## 图的整体布局
该图从上到下布局，描述了一个支付流程。流程从“用户请求”开始，最终可能回到“用户请求”或“返回用户请求”。整体上呈现出一种循环和分支的结构。

## 分组/子图/阶段说明
图中没有显式子图，但逻辑上可分为以下阶段：
1.  **请求与风控阶段**：用户请求到达支付网关，经过风控系统判断。
2.  **订单处理与缓存查询阶段**：风控通过后，进入订单服务，查询缓存。
3.  **支付API调用与结果处理阶段**：缓存未命中，调用支付API，根据支付结果进行后续处理。
4.  **消息队列与异常处理阶段**：支付成功发送消息队列，支付失败则返回用户请求。

## 节点逐项说明
- **A[用户请求]**: 用户发起的支付请求。
- **B(支付网关)**: 接收用户请求，作为支付流程的入口。
- **C{风控系统}**: 对支付请求进行风险评估。
- **D[订单服务]**: 处理订单相关的业务逻辑。
- **E(直接返回成功)**: 风控系统判断为无风险，直接返回成功。
- **F{查询缓存}**: 查询订单信息是否已存在缓存中。
- **G[更新数据库]**: 将订单信息更新到数据库。
- **H(调用支付API)**: 调用第三方支付接口进行支付。
- **I{支付成功}**: 判断支付是否成功。
- **J[发送消息队列]**: 支付成功后，发送消息到消息队列。
- **K(订单服务)**: 订单服务节点，在支付失败时被调用。
- **L[返回用户请求]**: 将支付结果返回给用户。

## 连线、分支与汇聚关系
- A -> B: 用户请求到达支付网关。
- B -> C: 支付网关将请求发送到风控系统。
- C -- Yes --> D: 风控系统判断通过，进入订单服务。
- C -- No --> E: 风控系统判断不通过，直接返回成功。
- D -> F: 订单服务查询缓存。
- F -- Yes --> G: 缓存命中，更新数据库。
- F -- No --> H: 缓存未命中，调用支付API。
- H -> I: 调用支付API后，判断支付是否成功。
- I -- Yes --> J: 支付成功，发送消息队列。
- I -- No --> K: 支付失败，进入订单服务。
- K -> L: 订单服务返回用户请求。
- J -> A: 发送消息队列后，回到用户请求。

## 仓库语境与术语解释
- **支付网关**: 负责接收和转发支付请求的服务。
- **风控系统**: 用于评估支付风险的系统，防止欺诈行为。
- **订单服务**: 处理订单相关业务逻辑的服务。
- **支付API**: 第三方支付接口，用于实际的支付操作。
- **消息队列**: 用于异步处理消息的组件，例如支付结果通知。
- **缓存**: 用于存储常用数据，提高查询效率。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先到达支付网关，然后经过风控系统判断，如果风控通过，则进入订单服务，查询缓存；如果缓存命中，则更新数据库；如果缓存未命中，则调用支付API。支付API调用后，如果支付成功，则发送消息队列，并回到用户请求；如果支付失败，则进入订单服务，并返回用户请求。如果风控系统判断不通过，则直接返回成功。
