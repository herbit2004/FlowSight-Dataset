## 图类型与用途
该图是一个流程图，描述了灰度发布和流量切换的流程。它展示了用户请求如何根据灰度策略、特性开关以及监控评估，最终路由到灰度环境或正式环境，并根据评估结果进行流量调整或回滚。

## 图的整体布局
图的布局是从上到下，分为“初始状态”和“流量切换”两个子图。流程从“用户请求”开始，最终“响应用户”，并进入流量切换的循环。

## 分组/子图/阶段说明
图中包含两个子图：
- **初始状态**：描述用户请求进入系统的初始阶段。
- **流量切换**：描述根据监控评估结果，调整流量或回滚的阶段。

## 节点逐项说明
- **用户请求**：用户发起的请求。
- **流量入口**：接收用户请求的入口点。
- **灰度策略判断**：根据预设的灰度策略，判断请求是否满足灰度条件。
- **灰度环境服务**：处理满足灰度条件的请求的服务器。
- **正式环境服务**：处理不满足灰度条件的请求的服务器。
- **特性开关检查**：检查特定功能是否开启。
- **新特性处理**：处理开启的特性逻辑。
- **数据存储/更新**：存储或更新相关数据。
- **响应用户**：向用户返回响应。
- **监控与评估**：监控灰度环境的运行状况，并进行评估。
- **逐步增加灰度流量**：如果评估通过，则逐步增加灰度环境的流量。
- **回滚至正式环境**：如果评估不通过，则将流量回滚至正式环境。

## 连线、分支与汇聚关系
- 用户请求 -> 流量入口：用户请求进入流量入口。
- 流量入口 -> 灰度策略判断：流量入口将请求传递给灰度策略判断模块。
- 灰度策略判断 -- 满足灰度条件 --> 灰度环境服务：如果满足灰度条件，则将请求路由到灰度环境服务。
- 灰度策略判断 -- 不满足灰度条件 --> 正式环境服务：如果不满足灰度条件，则将请求路由到正式环境服务。
- 灰度环境服务 -> 特性开关检查：灰度环境服务进行特性开关检查。
- 特性开关检查 -- 特性开启 --> 新特性处理：如果特性开启，则进行新特性处理。
- 特性开关检查 -- 特性关闭 --> 正式环境服务：如果特性关闭，则将请求路由到正式环境服务。
- 新特性处理 -> 数据存储/更新：新特性处理后，进行数据存储或更新。
- 数据存储/更新 -> 响应用户：数据存储/更新后，响应用户。
- 正式环境服务 -> 响应用户：正式环境服务响应用户。
- 响应用户 -> 监控与评估：响应用户后，进入监控与评估阶段。
- 监控与评估 -- 评估通过 --> 逐步增加灰度流量：如果评估通过，则逐步增加灰度流量。
- 监控与评估 -- 评估不通过 --> 回滚至正式环境：如果评估不通过，则回滚至正式环境。
- 逐步增加灰度流量 -> 灰度策略判断：增加灰度流量后，重新进行灰度策略判断。
- 回滚至正式环境 -> 正式环境服务：回滚至正式环境后，请求由正式环境服务处理。

## 仓库语境与术语解释
本图为合成数据，无真实仓库。
- **灰度发布**：一种平滑过渡的发布方式，将新功能逐步开放给一部分用户，观察其表现，再决定是否全面推广。
- **灰度环境**：用于运行新功能或新版本的环境，只有部分用户可以访问。
- **正式环境**：稳定运行的生产环境，所有用户都可以访问。
- **特性开关**：一种控制功能是否开启的机制，可以在不重新部署的情况下启用或禁用某些功能。
- **流量切换**：根据监控和评估结果，调整灰度环境和正式环境之间的流量比例。
- **回滚**：当新功能出现问题时，将系统恢复到之前的稳定状态。
- **监控与评估**：对灰度环境的性能、错误率等指标进行监控，并评估其是否达到预期效果。

## 可作为 QA Ground Truth 的高信息密度摘要
用户请求首先进入流量入口，然后根据灰度策略判断是否进入灰度环境。如果满足灰度条件，则进入灰度环境，进行特性开关检查。如果特性开启，则进行新特性处理和数据存储/更新，最终响应用户。如果不满足灰度条件，则直接进入正式环境服务并响应用户。响应用户后，系统进行监控与评估，如果评估通过，则逐步增加灰度流量，重新进行灰度策略判断；如果评估不通过，则回滚至正式环境。
