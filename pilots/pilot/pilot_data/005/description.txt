## 图类型与用途
这是一个架构图，描述了 Kubernetes Pod 内部的 Sidecar 模式。它展示了主应用容器和 Sidecar 容器如何共享资源以及相互通信，用于解释 Kubernetes Pod 的内部架构。

## 图的整体布局
图采用从左到右的布局，主要展示了一个 Kubernetes Pod 及其内部组件。外部流量从左侧进入，Pod 内部的容器通过共享资源对外提供服务。

## 分组/子图/阶段说明
图中包含一个名为 "Kubernetes Pod" 的子图，以及一个名为 "Shared Resources" 的子图。
- **Kubernetes Pod**：表示 Kubernetes 的最小部署单元，包含一个或多个容器。
- **Shared Resources**：表示 Pod 中所有容器共享的资源，包括网络命名空间和存储卷。

## 节点逐项说明
- **Kubernetes Pod**：表示 Kubernetes 的最小部署单元，包含一个或多个容器。根据 README，Kubernetes 是一个容器编排系统。
- **AppContainer (Main Application Container)**：Pod 中的主要应用程序容器，运行核心业务逻辑。
- **SidecarContainer**：Pod 中的 Sidecar 容器，辅助主应用程序容器，提供诸如日志收集、监控等功能。
- **Network (Shared Network Namespace)**：Pod 中所有容器共享的网络命名空间，允许它们通过 `localhost` 相互通信。
- **Volumes (Shared Volumes)**：Pod 中所有容器共享的存储卷，允许它们共享数据。
- **ExternalTraffic**：表示来自 Pod 外部的流量。
- **ExternalServices**：表示 Pod 对外提供的服务。

## 连线、分支与汇聚关系
- `AppContainer -- localhost --> SidecarContainer`：主应用程序容器通过 `localhost` 与 Sidecar 容器通信。
- `SidecarContainer -- localhost --> AppContainer`：Sidecar 容器也通过 `localhost` 与主应用程序容器通信，实现双向通信。
- `AppContainer --> Network`：主应用程序容器使用共享的网络命名空间。
- `SidecarContainer --> Network`：Sidecar 容器也使用共享的网络命名空间。
- `AppContainer --> Volumes`：主应用程序容器使用共享的存储卷。
- `SidecarContainer --> Volumes`：Sidecar 容器也使用共享的存储卷。
- `ExternalTraffic --> Network`：外部流量进入共享的网络命名空间。
- `Network --> ExternalServices`：Pod 通过共享的网络命名空间对外提供服务。

## 仓库语境与术语解释
- **Kubernetes Pod**：Kubernetes 中最小的可部署单元，包含一个或多个容器。
- **Sidecar 模式**：一种容器设计模式，其中 Sidecar 容器与主应用程序容器一起部署在同一个 Pod 中，以提供辅助功能。
- **Network Namespace**：Linux 内核提供的网络隔离机制，Pod 中的容器共享同一个网络命名空间，可以像在同一台机器上一样通过 `localhost` 相互通信。
- **Volumes**：Kubernetes 中的存储卷，用于在 Pod 中的容器之间共享数据。
- **localhost**：表示同一台机器上的网络地址，由于 Pod 内的容器共享网络命名空间，因此可以通过 `localhost` 相互访问。
