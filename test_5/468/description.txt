## Repository Context & Terminology
- **CloudFront CDN**: A content delivery network (CDN) service from AWS that caches content at edge locations for faster delivery.
- **Application Load Balancer (ALB)**: An AWS load balancer that distributes incoming application traffic across multiple targets, such as EC2 instances, in multiple Availability Zones.
- **API Service**: A microservice responsible for handling API requests, likely implemented using a framework like Flask or Django.
- **User Service**: A microservice responsible for managing user accounts and profiles.
- **Order Service**: A microservice responsible for processing and managing customer orders.
- **SQS Event Queue**: AWS Simple Queue Service, a fully managed message queuing service that enables you to decouple and scale microservices, distributed systems, and serverless applications.
- **ElastiCache Redis**: A fully managed, in-memory data store service by AWS, often used for caching frequently accessed data.
- **RDS PostgreSQL**: A fully managed relational database service by AWS, using the PostgreSQL database engine.

## High-Density QA Ground Truth Summary
The architecture diagram illustrates a tiered application, beginning with the CloudFront CDN (Tier 0 - Edge) which routes HTTPS requests to the Application Load Balancer (Tier 1 - Ingress). The ALB then routes requests based on their path: `/api/*` to the API Service, `/users/*` to the User Service, and `/orders/*` to the Order Service (all Tier 2 - Compute). The RDS PostgreSQL and ElastiCache Redis form the data tier. The use of SQS Event Queue allows for decoupling of the Order Service and API Service, improving scalability and resilience.
