The diagram serves as a visual representation of the order fulfillment process, including payment verification, inventory checks, and shipping.

## Edges, Branches & Convergence
- `User Submits Order --> Payment Received?`: The order submission triggers the payment verification process.
- `Payment Received? -- Yes --> Inventory Check`: If payment is received, the system proceeds to check the inventory.
- `Payment Received? -- No --> Order Cancelled`: If payment is not received, the order is cancelled.
- `Inventory Check --> Inventory Available?`: The inventory check process leads to a decision based on availability.
- `Inventory Available? -- Yes --> Ship Order`: If inventory is available, the order is shipped.
- `Inventory Available? -- No --> Restock Inventory`: If inventory is not available, the system initiates the restocking process.
- `Restock Inventory --> Notify User of Delay`: After restocking, the user is notified of the delay.
- `Notify User of Delay --> Await User Confirmation`: The system waits for user confirmation after notifying them of the delay.
- `Await User Confirmation --> Inventory Check`: After user confirmation, the system loops back to the inventory check.
- `Ship Order --> Payment Received?`: After shipping the order, the system goes back to payment received.
- `Ship Order --> Order Cancelled`: After shipping the order, the system goes to order cancelled.
- `Order Cancelled --> Order Completed`: After the order is cancelled, the system goes to order completed.
